# 参悟

一个修仙题材的**养成挂机 + 小游戏**微信小程序：练功法、参悟小游戏、攒熟练度与战力、突破境界、论道打对手，顺手收集称号与成就。

> 原生微信小程序 + WorkBuddy 云服务：微信一键登录（邮箱验证码兜底），进度按账号存云端并做版本隔离，本机留同步缓存。
> 当前状态：原型可玩，**未发布上线**；真机登录、云端读写、头像与榜单链路尚未验证。

## 小游戏设计

**一门功法 = 一套玩法**。10 门功法对应 10 个互不复用的玩法模块，连同类功法也不共用内核；每套在盘面形态、交互方式、胜负规则、难度参数上都不同。`data/practice.js` 的 `game` 一一映射到 `minigames/`，`twist` 写清本门独有的规则花样：

| 功法（参悟方式） | 类别 | 专属玩法 | 盘面形态 | 独有的花样 |
| --- | --- | --- | --- | --- |
| 基础刀法（循光斩桩） | 刀法 | 顺光扫斩 | 3×3 刀路（可划） | 刀光沿 3–5 桩依次掠过，每桩一个 CSS 箭头指向下一桩、收势是靶心；必须顺箭头划，反向判劈空；光走完起寿命线；连击 5 / 10 / 20 记得分 ×1.5 / ×2 / ×3；每五道是更长的重斩 |
| 剑诀·断岳（辨锋截击） | 剑法 | 辨伪择真 | 4×3 方格 | 每轮数道剑光只一真招，截错倒扣分数与时辰，连截提速 |
| 心法·静心诀（背功法口诀） | 心法 | 记序复现 | 3×3 方格 | 复述有时限（题长 × 每字息数），点错罚一息半、三盏心神；连对每轮 +15%（封顶 +45%）；长按抢记按「少看几个字」给 ×1.2–1.9；大成逆诵、圆满叠印 |
| 丹道·凝露丹方（循纹采露） | 丹道 | 循纹递推 | 竖向河道（逐层） | 纹路 = 上层 +1 递推，水流打乱露石，三盏心神 |
| 吐纳诀（吸纳灵气） | 心法 | 节律判定 | 圆盘光环 | 判定窗更宽、收得更慢，比连拍稳定度 |
| 身法·踏云步（照卷踏位） | 身法 | 步法连环 | 卷轴 + 4 个步法键 | 一步不错：四段逐段变长，按序踏位，踏错重出并少一息 |
| 阵法入门（参悟阵眼） | 阵法 | 阵灯推演 | 3×3 方格 | 限时连解 36 秒，解亮一盘立刻换盘；难度只改「这盘最少几步」（2→6 步）；阵眼感应花 3 秒；大成开死门（点到整盘复位、罚 3 秒） |
| 阵法·小五行阵（排布阵灯） | 阵法 | 五行相生 | 五灯环 + 中央牌 | 按相生之位接龙，连生越长窗口越短 |
| 符箓·照影符（持符探禁） | 符箓 | 数格辨禁 | 6×6 方格 | 看数字推禁制、长按插旗，三盏心神、大成照见 3 处禁制 |
| 心法·太虚诀（内视观窍） | 心法 | 成对翻牌 | 4×3 方格 | 翻两处气窍配一对，记卦象；两次入定照见一对 |
| 境界突破 | — | 蓄力停区 | 蓄力条 | 长按蓄力、松手停在朱线区间，越近正中评级越高 |

举例说明「同族也不重样」：刀法顺着流动的刀路把刀扫到靶心（3×3），剑法在数道剑光里截真招（4×3 且截错倒扣）；两门阵法一个是静态翻转推演，一个是环形限时接龙。功法页每张卡片直接标出专属玩法名，开局准备页再写清本门规则。

**熟练度不只是解锁更难的同一件事**：`data/practice.js` 的 `STAGE_RULES` 给每门功法登记「到了某个阶段规则会变」，准备页的「本门新法」直接列出已得与待解锁。目前落地两门——静心诀大成「逆诵」（奇轮倒着点）、圆满「叠印」（题里出现重复格子）；阵法入门大成「死门」、圆满「双门」。机制写在各自的 `create()` 里，按 `ctx.perks.tier`（熟练度阶段 0–5）开关。

**首页回答一个问题：现在练哪门**。`engine.recommend(state)` 按「离下一个熟练度阶段最近」排序（按阶段跨度归一，衰减到三成的功法往后压），给出「差多少熟练度升哪一段」和「下一档难度还差多少」。洞府页顶部的「今日之课」卡片和吸底按钮都取这一条，不让玩家自己算倍率。

**三处压力是统一标准**：每一门都要有「会失败、有代价、有取舍」这三样。顺光扫斩、记序复现、阵灯推演三套已按这条标准重做完，其余 7 套仍是旧写法。

**顺光扫斩的循环**（其余 9 套照同一张清单排）：刀路逐桩亮起、箭头指明走向 → 手指顺箭头扫到靶心 → 白光掠过、下一道立刻换招。压力有三处：**反向划或跳桩一律判「劈空」**，罚一息（与剑诀·断岳同规矩）；寿命线走完没划中就是「漏」，刀势清零；乱划会把自己划死；连击 5 / 10 / 20 记后每一刀的得分抬到 ×1.5 / ×2 / ×3，一次失误全退回 ×1。每第五道换成重斩：刀路更长、分翻倍、寿命八折，接不住不罚、只是白过一手。五档难度改的是刀路长度与光掠过的速度，不是把数字拧小。

### 功法品阶与难度档

**一个维度只管一件事**：类型管玩什么，品阶管收益，熟练度管难度，境界管上限。调数值时互不牵扯。

**品阶（天地玄黄）只管收益，不管难度。** `data/skills.js` 每门功法挂 `tier`，`data/practice.js` 的 `TIERS` 定义倍率、属性系数与可修境界：

| 品阶 | 星级 | 功法 | 熟练度倍率 | 属性系数 | 可修境界 | 获取 |
| --- | --- | --- | --- | --- | --- | --- |
| 黄 | ★☆☆☆ | 基础刀法、阵法入门、吐纳诀 | ×1.00 | ×1.0 | 筑基 | 初始赠送 |
| 玄 | ★★☆☆ | 心法·静心诀、身法·踏云步 | ×1.50 | ×1.3 | 金丹 | 藏经阁 |
| 地 | ★★★☆ | 符箓·照影符、阵法·小五行阵、丹道·凝露丹方 | ×2.20 | ×1.7 | 元婴 | 藏经阁 / 论道首胜 |
| 天 | ★★★★ | 剑诀·断岳、心法·太虚诀 | ×3.20 | ×2.2 | 元婴以上 | 论道首胜 |

**难度档跟人走。** 五档全由「这门功法自己的熟练度」解锁，与品阶无关；档越高倍率越高，同时 `pace` 收紧、`goal` 抬高：

| 难度档 | 所需熟练度 | 倍率 | 节奏 | 目标 |
| --- | --- | --- | --- | --- |
| 简单 | 0 | ×1.0 | ×1.18（更缓） | ×0.85（更低） |
| 普通 | 400（小成） | ×1.3 | ×1.00 | ×1.00 |
| 困难 | 1000（大成） | ×1.7 | ×0.88 | ×1.12 |
| 极难 | 2500（圆满） | ×2.1 | ×0.78 | ×1.22 |
| 绝境 | 6000（大圆满） | ×2.6 | ×0.70 | ×1.32 |

**结算公式**（`applyPractice`）：

```
熟练度收益 = 基础值 × 品阶倍率 × 难度档倍率 × 评级倍率 × 境界衰减
```

- 评级倍率 S 1.5 / A 1.2 / B 1.0 / C 0.6 / F 0.2。S 刻意压低：它要与难度档连乘，过高会让总收益失控。
- 四个系数连乘后由 `MAX_MULTIPLIER = 8.0` 封顶，极端组合（天阶 3.2 × 绝境 2.6 × S 1.5 = 12.48 倍）只算 8 倍。
- 境界衰减 `REALM_DECAY = 0.3`：没到品阶门槛、或超过可修上限，收益只剩 30%。**不为 0** —— 还能练，但该换功法了。
- 越权选档（例如改页面参数）会被自动回落到已解锁的最高档并标注，不会白送倍率。
- 缩放的是节奏（`interval` / `flashMs` / `windowMs` / `shuffleMs` / `flipMs` / `window`）、收敛速度（`speed`）与目标数量（`chainGoal` / `maxRound` / `segments` / `beats` / `scramble` / `mines` / `pairs` / `decoys` / `startLen` / `baseLen`）。**刻意不改 `grid` / `cols` / `rows` / `size`**：盘面列数受限于 wxss 的 `.grid--c3/4/6`，改了会错位。各字段按玩法安全上限 clamp。
- 同一类型的功法共用一个**游戏族**（`data/practice.js` 的 `FAMILIES`），族内按品阶出变体（`data/skills.js` 的 `chainsOf()`）。功法页「功法谱系」把天地玄黄四档全列出来，**缺变体的档位显示空档**（如刀法的玄、地、天三阶），补齐只需加一门数据。
- 每门功法记一个局内最佳分数（`state.records`，存档版本 4，老档平滑迁移），结算显示得分与「破纪录」。**分数只作纪录，不加收益** —— 评级管收益，分数管追求。
- `scripts/simulate.js`（`npm run sim`）用固定种子的评级分布跑四组策略：黄阶只刷简单、黄阶逐档升、天阶逐档升、黄阶金丹后（看衰减），并就 9 条曲线结论做断言：「越高档期望收益越高」「逐档升明显优于只刷简单」「衰减确实疼」「极端组合被封顶」。改倍率后先跑它，再看真机手感。

- `minigames/theme.js` 给每门功法一套配色、格子符号、印章字与命中 / 失误 / 赞语文案；`pages/practice/` 通过根容器 CSS 变量下发到 wxss，并做了暗色覆盖。
- `minigames/common.js` 的 `vm` 统一带 HUD 字段（进度、实时评级、连击、目标、阶段横幅、浮字、心神、副指标）与 `stage` 舞台形态：`board` 方格、`lane` 河道、`ring` 节律盘、`orbit` 五行灯环、`scroll` 招式卷轴、`charge` 蓄力条。页面据此切换盘面渲染，玩法层只输出数据。
- 修掉过三个玩法漏洞：记忆序列闪烁时把序号写在格子上（等于直接给答案）、点击类点错毫无惩罚、数格辨禁误触一次即收功。
- 节律盘用 CSS `transform: scale()` 呈现，灯环与卷轴也都是纯 WXML/WXSS，不依赖 canvas 与触摸坐标；**真机上缩放、CSS 变量与动画效果仍需复核**。

## 角色资料与规则说明

- 道号 `roleName`、道相 `portrait`（0–5）、头像云存储路径 `avatar` 都是存档字段，随云端存档与 `CANWU1:` 存档码迁移；写入统一走 `engine.updateRole()`。
- 道相是 `components/portrait/` 里**纯 CSS** 绘制的角色形象，按编号换配色与法印、按境界增加光环层数，不需要图片资源也不需要授权。
- 微信登录只建立身份、不返回昵称头像。因此头像与昵称做成**主动选择式**：道牒编辑弹窗里 `chooseAvatar` 选微信头像、`type="nickname"` 输入框带出微信昵称，玩家自己决定用不用。不设头像就用道相。
- 头像上传到云存储 `users/<uid>/avatars/`，显示时用 1 小时签名 URL。**小程序 SDK 的 `storage.download` 不可用**，且签名 URL 由 `<image>` 加载还依赖 downloadFile 合法域名；拿不到 URL 会静默回退到 CSS 道相。这条链路需真机验证。
- `pages/guide/` 是集中式规则页，共 9 节，列出资源、挂机、熟练度、评级、小游戏、突破、论道、称号、存档、成就榜单与离线时间规则的全部数值；洞府页头与道牒各有入口。
- 面向玩家的页面文案不出现实现细节（数据化、换皮、SDK、RLS 等），这类说明只留在 README 与源码注释里。

## 登录与账号隔离

- 主入口 **微信一键登录**：`wx.login` 取 code + `wx.getAccountInfoSync().miniProgram.appId`（运行时真实 appid，不硬编码），调用 `cloud.auth.signInWithWechat(code, appid)`；后端换会话，前端不碰 AppSecret、不自存 openid。
- 兜底入口 **邮箱验证码**（发送 → 验证，无密码），默认折叠。两种方式共用 `app.js` 的 `afterLogin()`，身份隔离完全由会话 uid 决定。
- 冷启动 `app.js` 检查会话：**只有 `signed-out` 才跳登录页**；网络错误 / 云端读取失败一律保留本机进度离线可玩，显示提示并监听网络恢复自动重试。
- 云端表 `canwu_saves`：`owner_id TEXT NOT NULL DEFAULT auth.uid() UNIQUE`、`payload JSONB`、`version BIGINT DEFAULT 0`、`updated_at TIMESTAMPTZ`。归属由数据库填充，前端不传用户 ID。
- 已开启 RLS，SELECT / INSERT / UPDATE / DELETE 四条策略均限定 `owner_id = auth.uid()`；读写前先过 `cloud.auth.getSession()` 认证门。
- `version` 与 `updated_at` 由 **BEFORE UPDATE trigger 在服务端维护**（验证过前端伪造的 `updated_at` 会被 `now()` 覆盖），客户端不能改表刷时间或绕过版本。
- 榜单表 `canwu_scores`：`SELECT` 对所有人开放，`INSERT/UPDATE/DELETE` 仅本人；同样有服务端 `updated_at` trigger。写入时不传 `owner_id`。

## 存档可靠性

- 每次 `commit` **同步写本机** `canwu_save_v1` 并留下 `canwu_pending_v1` 标记；云端确认成功后才清除。切后台被冻结、断网、写失败都不会静默丢档——下次启动 `hydrate()` 先补写本地改动再读云端。
- 写云端带**乐观锁**：`.update(...).eq('id', rowId).eq('version', expectedVersion)`，0 行命中会再查一次区分「版本被别的设备推进」与「行被删」。冲突时不自动覆盖，弹窗让玩家选「用云端那份」或「用本机覆盖」。
- `rowId` 失效、插入撞唯一约束（23505）、行被移除等路径都有重新对齐 / 重建逻辑，不会卡在英文报错上。
- 关键操作（突破、结算、领奖、改名、买功法、导入、论道）走 `store.commitCritical()` 跳过 1.2 秒防抖立即回写；其余改动沿用防抖，并发 flush 复用同一个在途请求。
- 道牒页顶部与洞府页有**同步状态条**：已同步时间 / 待同步 / 失败原因 / 冲突，点一下可手动重试。
- 每日份例与离线收益使用单调时钟：时间回拨不会重开份例或倒着补收益。**彻底防作弊仍需服务端时间裁定，当前版本未接**。
- `SAVE_VERSION = 4`，`migrateState()` 是基于版本的迁移框架；v1 / v2 / v3 老档（含 `CANWU1:` 存档码导入）自动升级，补 `avatar`、`records` 并统一版本号。
- 云端无档时建新档，**本机旧进度不会自动上云**；要保留就先在道牒导出存档码，登录后导入。退出登录清本机缓存，云端保留。

## 音效

局内反馈全部由 `utils/sfx.js` 发声。音源是仓库里的 9 个 wav（`assets/sfx/`，16kHz 单声道，共约 92KB），由 `scripts/gen-sfx.js`（`npm run sfx`）合成——不引外部音频文件，改音色只改合成参数。

第一版反馈「太刺耳、脑子嗡嗡的」，第二版按四条改柔：**只用基频 + 极轻二次分音**（去掉金属泛音）、**全局一阶低通 + 14ms 软起音**（去掉「咔」的瞬态）、**每个音效只留单声部且衰减压到 0.1–0.2 秒**、**峰值 0.52 再乘播放音量 0.26–0.36**。

| 音效 | 触发时机 |
| --- | --- |
| `tap` | 落子、点空、撤销 |
| `hit` / `miss` / `gold` | 浮字 `vm.fx.tone` 的 good / bad / gold |
| `tick` | 倒数三声、用提示 |
| `go` | 起手 |
| `clear` / `settle` / `fail` | 结算 S·A / B·C / F（走火、收功） |

- **判定结果只认浮字**：`vm.fx` 是玩法层唯一统一的判定信号，页面 `render()` 里比对 `fx.key` 有没有变就发声，10 套玩法不用各写一遍；点空这类没有浮字的操作由页面补一声 `tap`。
- **绝不叠加**：判定 / 结算音共用一路声道（`VOICE`），新的一声会掐掉上一声；`pool` 一律为 1，另有同名 `gap`（85–400ms）与全局 `GLOBAL_GAP`（60ms）两层节流。第一版允许 3 路磬声并发，连击时叠成嗡鸣，这一条由 `tests/layout.test.js` 断言守住。
- **静音键不吃音效**：`obeyMuteSwitch = false`。否则 iOS 打开侧边静音开关就整局无声——「怎么没声音」最常见的来源。
- **三档音量**：道牒页「关于参悟」点一下弹出「轻 / 中 / 关」，默认「轻」（再乘 0.75）。落本地存储 `canwu.sfx.level`，兼容旧键 `canwu.sfx.on`；切档会同步改已创建音频实例的音量。页面 `onHide` / `onUnload` 收声，退出去不会接着响。
- 上下文在进参悟页时 `warm()` 预建，第一次落子不用等实例化。

## 输入形态：为什么基础刀法从「点」改成「划」

第一版「追光点击」是 3×3 静态格子里点亮的那一格，本质是打地鼠：手指不移动、没有方向与轨迹，调参数、加特效都改不掉这个体感。

参考过两条路：钢琴键 / 下落式音游的输入仍是「到点按一下」，手指还是点；水果忍者式的划线有轨迹感，且长扫轨迹、重斩后摇、一刀带走数个目标正好就是**刀**的手感。但抛物线飞入的目标 + 刀光拖尾要上 canvas，会在纯 view + setData 的架构里分叉出第二套渲染路径，真机性能与假时钟测试都得重来，所以只借「划」这个输入，不借它的渲染。

现在的「顺光扫斩」把「划」装进现有网格，**不引 canvas**，走的是刀该有的长折线扫掠（见下一节「兵器轴」）：

- 刀光沿 3×3 刀桩依次掠过 3–5 格，形成横劈 / 立劈 / 斜斩 / 游龙四种有方向的刀路；光走到收势桩才起寿命线，玩家可以追着最亮的光头一刀扫过去。
- 每桩一个纯 CSS 箭头指向下一桩（八方向），收势桩是靶心；**盘面没有任何汉字**，方向全靠形状表达，`dirAngle()` 用相邻两桩的行列差算角度。
- **方向只能顺着走**：判定 `matched()` 只认「起手 → 收势」这一个序列，反着划、跳桩、绕一大圈都判劈空；刀势允许多带两桩（刃扫过的面积），但绕盘面乱划一大圈不算。招式名「回锋」随之删掉，免得暗示可以反着来。
- 页面盖一层透明触摸层（`.swipe-layer`），开局量一次格子矩形，相邻 `touchmove` 之间按 10px 插值补全中间格。小程序的 touchmove 目标固定在起手元素，逐格绑事件收不到跨格轨迹；不做插值的话，划快了会漏桩、被误判成劈空。
- 玩法层只多收一个 `swipe(path)`，`vm.cells` 协议、判定浮字、音效、假时钟测试全部沿用，其余 10 套玩法一行未改。
- 五档难度第一次落在「刀路长度 + 光掠过速度」（`depth`）上，不再只是拧小寿命；重斩是每第 5 道的更长金桩长招，得分翻倍、漏了不断势。

## 兵器轴：为什么这一门是刀，以及剑法先不做

早期把这套长扫轨迹挂在「基础剑法」下，还写成平削 / 直刺 / 一剑中的 / 剑尖不许带桩——**那是剑的文案配了刀的手感**。手指「划」这个输入本身不分兵器（刀势、剑气都有轨迹），区别在于轨迹是什么：

| | 刀（当前启用） | 剑（预留，暂不挂功法） |
| --- | --- | --- |
| 轨迹 | 刃扫过的**面积**：长折线为主 | 光走的**点线**：短直线为主 |
| 招式 | 3–5 桩，折线多、允许大转弯 | 2–4 桩，折线少 |
| 判定 | 只认正向，容许多带 2 桩（刀势连贯） | 最多带 1 桩（抗抖） |
| 节奏 | 起手沉、后摇长、余势不断 | 光快、后摇短、点到靶心即收 |
| 称谓 | 横劈 / 立劈 / 斜斩 / 游龙、一刀斩中、劈空 | 平削 / 直刺 / 斜挑 / 绕指、一剑中的、刺偏 |

**这一版先只做刀法**：初始功法改名「基础刀法」，`weapon: 'dao'` 是唯一启用的 profile；`sword` profile 与「剑诀·断岳」仍留在数据里，但剑法不做点刺式输入、也不新增功法。长扫、重后摇、连扫数桩这套语汇本来就是刀，与其拿名字去补机制，不如让名实先对齐；将来真做剑法时补一个点刺输入适配器即可，共用同一套 `create(ctx)` 与结算。

`data/weapons.js` 是第五根轴（类型 → 玩什么、**兵器 → 怎么动**、品阶 → 收益、熟练度 → 难度、境界 → 上限）。两份 profile 管轨迹长度、折线概率、光速、判定容差、后摇、评级缩放、招式名与全部浮字称谓。`minigames/click.js` 只读 `ctx.params.weapon`，**不硬编码任何兵器称谓**；`buildParams` 原样透传，没标兵器时回落到当前启用的 `dao`。主题表只管配色与本门 banner，不再覆写命中 / 失手浮字——否则刀法沿用剑法主题时会说出「一剑中的」。

**再加一门刀法变体只要三步**：① `data/practice.js` 新增 method，`game: 'click'` + `params.weapon: 'dao'`；② `minigames/theme.js` 配一门刀主题；③ `data/guides.js` 补一份说明。玩法模块、页面、结算、音效、假时钟测试一行不用改。

`tests/minigames.test.js` 用 `weapon: 'sword'` 与 `weapon: 'dao'` 把同一套引擎各跑一局，断言招式明显更长、招式名与命中浮字全换、剑势槽变刀势槽；另有一条断言扫过刀法全部可见文案（招式名、浮字、说明、命名、主题）确保不混进剑字，反过来也守住预留的剑 profile 零刀字。`sword` profile 目前**未挂任何功法**——把「分得出来」变成可回归的事实，而不是提前做半套剑法。

## 视觉标准与沉浸舞台

方向：**国风修仙 + 2D 游戏场景 + 灵气特效 + 游戏化 HUD**。舞台固定深色（游戏该有固定氛围），外围页面仍走 `prefers-color-scheme` 双主题。原则是「一套骨架、十一种皮相」：统一字体阶梯、间距圆角、HUD 骨架、反馈时序、结算框架；各异的是场景母题、主辉光色、道具符文、招式动画与音色。

- **唯一真源** `data/visual.js`：五类主题色板（兵刃青蓝 / 心法青白 / 丹道赤金 / 符箓朱金 / 阵法青紫）、动效预算、结算分镜、样板开关。`styles/scene.wxss` 由 `app.wxss` 全局引入，只放表现；`minigames/` 下一行视觉字段都没有。
- **零图片资源**：山门、月轮、三层山脊、云雾、灵气点、法坛全是 CSS 色块与路径。全项目素材仅 124KB（音效 112K + 图标 12K），主包上限 2MB；十套场景若用位图会吃光包体，还要分包、CDN、加载白屏与深浅两套图。换主题只改几个色值，不用重出图。
- **三层场景**：远景静态（月轮 / 山门 / 星点 / 山脊）；中层 3 路常驻循环（月晕呼吸 8s、云雾漂移 18s、灵气上升 12s）；近层法坛与盘面恒为最高对比，特效不许压过判定信息。倒数三秒的深色遮罩顺带充当进场的明暗过渡。
- **游戏化 HUD**：息 → 香炷竖槽、心神 / 余息 → 命灯、连击 → 带 5 / 10 / 20 刻度的刀势槽、得分 → 灵石数字、评级 → 玉牌。
- **三档反馈**：命中 4 粒子 / 连击阶跃 6 粒子金色 / 重斩 8 粒子加金光闪；失手红光闪。视觉与音效共用 `vm.fx` 这一个判定信号。所有关键帧只动 `transform` / `opacity`，常驻循环 ≤3 路，粒子 ≤12 枚/次。
- **结算五段演出**：`0ms` 暗场收束 → `300ms` 评级落定（S 金光横扫 / F 裂纹）→ `700ms` 熟练度条 `scaleX` 涨满、数字浮现 → `1200ms` 奖励逐条 → `1800ms` 按钮淡入。S/A 满 1.8s，B/C/F 压到 900ms，任意处点击跳过，切后台回来直接给按钮。数字用 CSS 缩放浮现而不是逐帧 setData，守住「零高频 setData 动画」。
- **样板阶段**：`visual.ENABLED` 目前只有 `forge`（基础刀法·顺光扫斩），其余十套仍走原 HUD 与原结算卡。真机验过再逐个放开，避免方向没认就改十套。`tests/layout.test.js` 用 4 条断言守住色板、样板开关、演出时序与动效预算。

## 开发约定与工程命令

- **内容即数据**：新增功法、参悟方式、对手、称号、成就或调数值，只改 `data/`，不动业务代码。
- **一门功法一套玩法**：10 门功法各自对应 `minigames/` 里的一个模块，`data/practice.js` 的 `game` 一一映射、不复用内核；同类别的功法也必须有不同盘面与规则。新增玩法要实现模块 + 在注册表登记 + 挂到功法表，`tests/minigames.test.js` 会断言玩法唯一与同类不重样。
- **品阶管收益、难度跟人走**：品阶挂在 `data/skills.js` 的 `tier`（`TIERS`），难度档挂在 `data/practice.js` 的 `DIFFICULTIES`，`buildParams(method, diffKey)` 只按难度档缩放参数。新增功法必须指定品阶与分类，同类内变体不得重样，盘面尺寸字段不得缩放——`tests/rank.test.js` 断言这些约定。
- **难度只调参数，不再「gear 二次收紧」**：`buildParams` 输出 `depth`（0–4，第几档）与按档递增的 `steps`，玩法据此调整，而不是看 `gear`（只有 normal / hard 两个值，分不出困难与绝境，容易一档一个样、还叠成断崖）。顺光扫斩与阵灯推演已改完，其余 7 套仍是旧写法。
- **名字分四层，互不撞词**：功法名（典籍上的名字）、参悟方式（这门功课在做什么：斩桩 / 采露 / 观窍）、玩法名（盘面上的动作：顺光扫斩 / 循纹递推）、主题名（2 字意象：刀光 / 卦象）。前三层任意两层同名，准备页就会出现「步法连环 · 步法连环」这种叠字；**参悟方式不得与功法相斥**——刀法不练数格子、丹道不练渡河、符箓不练探雷。`tests/minigames.test.js` 断言三层不撞词。
- **小游戏统一接口**：`create(ctx) -> controller`，见 `minigames/common.js`，注册表在 `minigames/index.js`；控制器除 `tap(index)` 外可选实现 `swipe(path)`（手指经过的格子序列，目前只有顺光扫斩用）；`vm.stage` 决定页面用哪种舞台（`board` / `lane` / `ring` / `orbit` / `scroll` / `charge`），玩法层只输出数据。`ctx.theme` / `ctx.twist` 决定表现与本门规则。
- **单一状态源**：页面只读 `store.get()`，写走 `store.commit()` / `commitCritical()`，刷新靠 `store.subscribe()`；页面保持同步 API，云读写后台异步。
- **云客户端唯一**：`utils/cloud.js` 是全工程唯一初始化点；`store.setCloudAdapter()` 可替换存档实现。
- `'use strict'` + CommonJS，除云 SDK 与 ESLint 外无运行时依赖，不使用打包器。

```bash
npm ci            # 按 lock 还原依赖
npm run verify    # JSON / JS 语法 / 页面组件四件套 / 主题变量 / tabBar 图标 / 隐私清单格式 / 品阶与难度档约定
npm test          # 123 项常驻断言（内核 + 存档同步 + 小游戏假时钟整局 + 品阶难度 + 布局约定）
npm run sim       # 收益曲线模拟：验证高档期望更高、境界衰减生效、总倍率封顶
npm run lint      # ESLint 9（小程序全局对象与 CommonJS 已配置）
npm run check     # 上面四项一次跑完，CI 用这个
npm run icons     # 重新生成 tabBar 图标（零依赖）
```

`.github/workflows/ci.yml` 是可移植的 CI 模板（`npm ci` → `npm run check`）。仓库双托管：`origin` 指向 Gitee（主），同时配了两条 pushurl，`git push` 一次同时推 Gitee 与 GitHub 镜像，`fetch` 只走 Gitee；GitHub 侧可直接用这份 workflow，Gitee Go 需按其配置格式另配一份，命令相同。
