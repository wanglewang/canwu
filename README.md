# 参悟

一个修仙题材的**养成挂机 + 小游戏**微信小程序：练功法、参悟小游戏、攒熟练度与战力、突破境界、与人切磋，顺手收集称号与成就。

> 原生微信小程序 + WorkBuddy 云服务：微信一键登录（邮箱验证码兜底），进度按账号存云端并做版本隔离，本机留同步缓存。
> 当前状态：原型可玩，**未发布上线**；真机登录、云端读写、头像与榜单链路尚未验证。

## 小游戏设计

**一门功法 = 一套玩法**。19 门功法对应 19 个互不复用的玩法模块，连同类功法也不共用内核；每套在盘面形态、交互方式、胜负规则、难度参数上都不同。`data/practice.js` 的 `game` 一一映射到 `minigames/`，`twist` 写清本门独有的规则花样：

| 功法（参悟方式） | 类别 | 专属玩法 | 盘面形态 | 独有的花样 |
| --- | --- | --- | --- | --- |
| 刀法·开锋诀（循光斩桩） | 刀法 | 顺光扫斩 | 3×3 刀路（可划） | 刀光沿 3–5 桩依次掠过，每桩一个 CSS 箭头指向下一桩、收势是靶心；必须顺箭头划，反向判劈空；光走完起寿命线；连击基础 5 / 10 / 20 记给 ×1.5 / ×2 / ×3，档位越高门槛越高；重斩每 5 道（高档更密）；大成收势、圆满禁桩、大圆满双锋 |
| 剑法·断岳诀（辨锋截击） | 剑法 | 辨伪择真 | 4×3 方格 | 每轮数道剑光只一真招，截错倒扣分数与时辰，连截提速 |
| 心法·静心诀（背功法口诀） | 心法 | 记序复现 | 3×3 方格 | 复述有时限（题长 × 每字息数），点错罚一息半、三盏心神；连对每轮 +15%（封顶 +45%）；长按抢记按「少看几个字」给 ×1.2–1.9；大成逆诵、圆满叠印 |
| 水术·凝露诀（循纹采露） | 水术 | 循纹递推 | 竖向河道（逐层） | 纹路 = 上层 +1 递推，水流打乱露石，三盏心神 |
| 心法·吐纳诀（吸纳灵气） | 心法 | 节律判定 | 圆盘光环 | 判定窗更宽、收得更慢，比连拍稳定度 |
| 身法·踏云步（照卷踏位） | 身法 | 步法连环 | 卷轴步点 + 4 个方向键 | 卷轴画成一串步点、走过的描边、当前那颗实心起光；每颗步点与四个键都只用 CSS 图形指方向（↑ 前踏 / ↓ 后撤 / ↗ 斜踏 / ⟳ 旋身），盘面不写汉字；四段逐段变长，同一方向最多连出两个（三个就成了无脑连点），踏错重出并少一息；评级只看走完的段数 |
| 阵法·燃灯诀（参悟阵眼） | 阵法 | 阵灯推演 | 3×3 → 4×4 → 5×5 方格 | **一盘推演、步数预算**：点一格翻自身与四邻，预算内全亮即破阵；评级按「已走 / 最优步数」——正好最优 S、多两步内 A、两倍内 B、其余 C；阵溃（预算走完还没全亮）是走火 F；用感应或重置本盘最高 A。求解走 GF(2) 消元 + 零空间枚举（5×5 生成 40 局约 3ms），不再 2^n 穷举；盘面不写汉字，亮 `●` / 灭 `○` / 死门暗红 `✕`；大成开死门（点到整盘复位、罚 3 步）。难度档同时放大盘面与最优步数下限（2→3→4→5→5 步），预算 9→22 步；首次开局有盘上两步引导（可跳过，只出现一次） |
| 阵法·五行诀（排布阵灯） | 阵法 | 五行相生 | 五灯环 + 中央牌 | 按相生之位接龙，连生越长窗口越短 |
| 阵法·勘禁诀（勘位辨禁） | 阵法 | 数格辨禁 | 6×6 方格 | 经典扫雷：首点开出空白区、整盘无猜、钉阵钉后点数字格可连开；盘面只有数字与 ✕ / ⚑；三盏心神（高档两盏）、大成勘出 3 处 |
| 心法·太虚诀（内视观窍） | 心法 | 成对翻牌 | 4×3 方格 | 翻两处气窍配一对，记卦象；两次入定照见一对 |
| 术数·九宫诀（推填九宫） | 术数 | 九宫填数 | 4×4 / 6×6 / 9×9 方格 | 每行每列每宫各填一遍 1–N；挖洞时逐格验「解还唯一」，填错按格罚十息；点格选中、数字键落子、✕ 清格 |
| 合术·叠元诀（同数相合） | 合术 | 滑格相合 | 4×4 滑格 | 整行整列四向挤压，同数一撞翻倍；合出本档目标块即收功，盘满且相邻无同数判走火 |
| 目术·逐数诀（循数疾点） | 目术 | 顺序点格 | 4×4 → 5×5 → 6×6 方格 | 数散在盘上，从 1 顺次点到末数；点错只罚两息、不移位，考的是目光一路扫过去不乱 |
| 机巧·让路诀（挪块开路） | 机巧 | 滑块让路 | 4×4 滑块盘 | 整块滑一格，把 2×2 主块挪到底部出口；BFS 现算本盘最优步数，按「已走 / 最优」评级 |
| 挪移·入位诀（归箱入阵） | 挪移 | 推石入位 | 6×6 / 6×7 石图 | 人走石格、石箱只推不拉；每块推到阵位才算完，按推数评优 |
| 辨术·摘魁诀（择大辨微） | 辨术 | 数中取大 | 数阵 | 一批数只挑最大的那个，拣对换下一批；点错罚时不换批 |
| 境界突破 | — | 蓄力停区 | 蓄力条 | 长按蓄力、松手停在朱线区间，越近正中评级越高 |

举例说明「同族也不重样」：刀法顺着流动的刀路把刀扫到靶心（3×3），剑法在数道剑光里截真招（4×3 且截错倒扣）；两门阵法一个是静态翻转推演，一个是环形限时接龙。功法页每张卡片直接标出专属玩法名，开局前准备页只留一行「这一局做什么」，整篇规则在右上角「说明」里按节折叠。

**熟练度不只是解锁更难的同一件事**：`data/practice.js` 的 `STAGE_RULES` 给每门功法登记「到了某个阶段规则会变」，准备页的「本门新法」默认收成一行，点开才逐条列出已得与待解锁，改规矩的那几条能就地关。目前落地两门——静心诀大成「逆诵」（奇轮倒着点）、圆满「叠印」（题里出现重复格子）；燃灯诀大成「死门」、圆满「双门」。机制写在各自的 `create()` 里，按 `ctx.perks.tier`（熟练度阶段 0–5）开关。

**主页回答一个问题：现在练哪门**。`engine.recommend(state)` 按「离下一个熟练度阶段最近」排序（按阶段跨度归一，衰减到三成的功法往后压），给出「差多少熟练度升哪一段」和「下一档难度还差多少」。主页的一行提示与吸底按钮都取这一条，不让玩家自己算倍率；修炼页的默认选中功法也读它。

**三处压力是统一标准**：每一门都要有「会失败、有代价、有取舍」这三样。顺光扫斩、记序复现、阵灯推演、数格辨禁四套已按这条标准重做完，其余玩法仍是旧写法。

**顺光扫斩的循环**（其余 15 套照同一张清单排）：刀路逐桩亮起、箭头指明走向 → 手指顺箭头扫到靶心 → 白光掠过、下一道立刻换招。压力有三处：**反向划或跳桩一律判「劈空」**，罚一息（与剑法·断岳诀同规矩）；寿命线走完没划中就是「漏」，刀势清零；乱划会把自己划死；连击 5 / 10 / 20 记后每一刀的得分抬到 ×1.5 / ×2 / ×3，一次失误全退回 ×1。每第五道换成重斩：刀路更长、分翻倍、寿命八折，接不住不罚、只是白过一手。五档难度改的是刀路长度与光掠过的速度，不是把数字拧小。

### 功法品阶与难度档

**一个维度只管一件事**：类型管玩什么，品阶管收益，熟练度管难度，境界管上限。调数值时互不牵扯。

**品阶（天地玄黄）只管收益，不管难度。** `data/skills.js` 每门功法挂 `tier`，`data/practice.js` 的 `TIERS` 定义倍率、属性系数与可修境界：

| 品阶 | 星级 | 功法 | 熟练度倍率 | 属性系数 | 可修境界 | 获取 |
| --- | --- | --- | --- | --- | --- | --- |
| 黄 | ★☆☆☆ | 刀法·开锋诀、心法·吐纳诀、阵法·勘禁诀、御灵·并蒂引、土术·垒岳诀、灵植·三秀诀、术数·九宫诀、合术·叠元诀、目术·逐数诀、机巧·让路诀、挪移·入位诀、辨术·摘魁诀 | ×1.00 | ×1.0 | 筑基 | 初始赠送 / 藏经阁 |
| 玄 | ★★☆☆ | 心法·静心诀、身法·踏云步、阵法·五行诀 | ×1.50 | ×1.3 | 金丹 | 藏经阁 / 切磋首胜 |
| 地 | ★★★☆ | 阵法·燃灯诀、水术·凝露诀 | ×2.20 | ×1.7 | 元婴 | 初始赠送 / 切磋首胜 |
| 天 | ★★★★ | 剑法·断岳诀、心法·太虚诀 | ×3.20 | ×2.2 | 元婴以上 | 切磋首胜 |

**品阶按「这门功课有多难」定，不按「什么时候拿到」定。** 阵灯推演要在大盘上推演联动、还要把步数压到最优，是十九门里最费脑的一门，挂在黄阶等于「练得最苦、拿得最少」，所以提到地阶，名字也从「阵法入门」改成「阵法·燃灯诀」——地阶功法再叫入门，就是玩家一眼看得见的名实相斥。数格辨禁反过来：看懂数字规则之后基本是稳的，难度低于两门阵法，降到黄阶。阵法·五行诀偏反应、比阵灯推演轻，落玄阶，与燃灯诀排成「玄 → 地」两级。**一族一个品阶只放一门**，同阶撞车会让谱系按阶取槽时把后一门盖掉，`tests/rank.test.js` 有断言守这条。九套经典玩法（连连看 / 俄罗斯方块 / 消消乐 / 数独 / 2048 / 舒尔特方格 / 华容道 / 推箱子 / 找最大数）规则一看就懂、难度最低，也统一挂黄阶，价格与境界门槛都按黄阶走（见下节）。

代价要说清：燃灯诀是初始三门的其中之一，而地阶门槛是金丹——炼气到筑基这段它只有三成收益，属性加成则照拿 ×1.7。这是「品阶只管收益与可修境界、不管难度」的直接结果：高品阶天生要等境界，不然一门就通吃了。

**难度档跟人走。** 五档全由「这门功法自己的熟练度」解锁，与品阶无关；档越高倍率越高，同时 `pace` 收紧、`goal` 抬高：

| 难度档 | 所需熟练度 | 倍率 | 节奏 | 目标 |
| --- | --- | --- | --- | --- |
| 简单 | 0 | ×1.0 | ×1.18（更缓） | ×0.85（更低） |
| 普通 | 400（小成） | ×1.3 | ×1.00 | ×1.00 |
| 困难 | 1000（大成） | ×1.7 | ×0.88 | ×1.12 |
| 极难 | 2500（圆满） | ×2.1 | ×0.78 | ×1.22 |
| 绝境 | 6000（大圆满） | ×2.6 | ×0.70 | ×1.32 |

**默认档 = 本门最高已解锁的那一档**，每次进准备页按熟练度重算，不记忆手选：门槛到了就说明这一门的本事到了，还停在半年前那一档是漏设计。手选只记在内存（`diffOverride`），跨过新门槛就清掉、回到新档——想练手随时能点回低档。

**退回低档要付明码代价：熟练度 ×0.5，且该档的 S 不计连晋。** 两者共用 `belowCapOf()` 一个判定，玩家只需记一句「只有最高已解锁档才算真功夫」。折半后界线可以一句话讲：黄阶简单档拿 S 是 1.0 × 0.5 × 1.5 = 0.75，普通档拿 C 是 1.3 × 0.6 = 0.78，**普通档打个 C 也比简单档 S 多**。熟练度不到 400 时简单档就是最高档，本项不生效，新手不受罚；折减只动熟练度，不碰灵气与灵石。

**结算公式**（`applyPractice`）：

```
熟练度收益 = 基础值 × 品阶倍率 × 难度档倍率 × 评级倍率 × 境界衰减 × 换门加成
```

- **只奖不罚，但难度是事前承诺**：同一门连练不减收益，攒「连 3 局 S 直接晋级」本来就该连着练；换一门另有 `CROSS_BONUS = 1.15`「触类旁通」，是正激励、不是对专精的惩罚。旧的连练递减机制已废弃，准备页开局前就写明这一局吃不吃得到换门加成，结算只报实得倍率。低档折减不违背这条——它管的不是「练同一门」，而是「已经解锁更高档却退回低档」；退回本身不罚，只是那一局不算真功夫。
- 评级倍率 S 1.5 / A 1.2 / B 1.0 / C 0.6 / F 0.2。S 刻意压低：它要与难度档连乘，过高会让总收益失控。
- **C 与 F 是两个结论，不是两档分数**：C「粗浅」=这一局走完了但打得糙；F「走火」=这一局**没走完**（阵溃、心神耗尽、时辰到还没通完、还剩对子没接上）。有失败态的十二门（燃灯 / 勘禁 / 静心 / 太虚 / 凝露 / 并蒂引 / 九宫 / 叠元 / 逐数 / 让路 / 入位 / 摘魁）判负一律走 F，按 ×0.20 照常结算并断连；没有失败态、只看时限内产出的七门（刀法 / 剑法 / 身法 / 吐纳 / 灵植 / 土术 / 五行）最低只到 C——时间到就是那一局的终点，不是失手。**主动收功**是第三种：它根本不进结算（`applyPractice` 不调用），连 S 原样保留，所以结算卡上是「收」而不是「F」。
- **每门「C / B / A / S 各要什么」写在说明页里**：各玩法模块导出 `lines(params, gear)`，`minigames/index.js` 汇总成 `gradeLines()`，说明页「怎么评级」一节按当前难度档列出本档四条线（例：刀法困难档 `S ≥ 709 分 / A ≥ 507 / B ≥ 284 / 其余 C`；探禁 `S ≤ 25 秒 / A ≤ 45 / B ≤ 75`）。这份数与局内 HUD 的「再 N 分可入 S」、结算档位出自同一处算法，不存在第二套门槛。局内只报「下一条线还差多少」，看全四条要进说明页——一屏塞四条线会把第一局要读的东西挤掉。
- 四个系数连乘后由 `MAX_MULTIPLIER = 13.0` 封顶。正常组合最高就是天阶 3.2 × 绝境 2.6 × S 1.5 = 12.48 倍，**碰不到上限**——上限只防以后新增系数叠加。这里曾经取 8.0，结果把天阶的困难 / 极难 / 绝境三档压成同一个收益（8.16 / 10.08 / 12.48 全算 8.0），最高两档只剩挑战意义、没有收益意义，等于难度档白设；改成 13.0 后四品阶各自的五档 S 收益才重新严格递增。
- 境界衰减 `REALM_DECAY = 0.3`：没到品阶门槛、或超过可修上限，收益只剩 30%。**不为 0** —— 还能练，但该换功法了。
- 越权选档（例如改页面参数）会被自动回落到已解锁的最高档并标注，不会白送倍率。
- 缩放的是节奏（`interval` / `flashMs` / `windowMs` / `shuffleMs` / `flipMs` / `window`）、收敛速度（`speed`）与目标数量（`chainGoal` / `maxRound` / `segments` / `beats` / `scramble` / `mines` / `pairs` / `decoys` / `startLen` / `baseLen`）。**刻意不改 `grid` / `cols` / `rows` / `size`**：盘面列数受限于 wxss 的 `.grid--c3/4/6`，改了会错位。各字段按玩法安全上限 clamp。
- 同一类型的功法共用一个**游戏族**（`data/practice.js` 的 `FAMILIES`），族内按品阶出变体（`data/skills.js` 的 `chainsOf()`）。功法页「功法谱系」把天地玄黄四档全列出来，**缺变体的档位显示空档**（如刀法的玄、地、天三阶），补齐只需加一门数据。
- 每门功法记一个局内最佳分数（`state.records`，存档版本 4，老档平滑迁移），结算显示得分与「破纪录」。**分数只作纪录，不加收益** —— 评级管收益，分数管追求。
- `scripts/simulate.js`（`npm run sim`）用固定种子的评级分布跑五组策略：黄阶只刷简单、黄阶逐档升、黄阶退一档刷、天阶逐档升、黄阶金丹后（看衰减），把熟练度拆成「正常收益 / 三连 S 补额」两列，并做断言：「越高档期望收益越高」「逐档升明显优于只刷简单」「衰减确实疼」「天阶 120 局能到大圆满且数值不失控」「正常最高组合不被封顶压住」「四个品阶各自的五档 S 收益一档比一档高」「只刷简单不许反超逐档升」「退一档刷也不许反超」「折半后简单档 S 低于普通档 C」。最后几条是本轮修的：旧上限把高品阶高档压平，旧连 S 补额让刷简单反超逐档升——两者都曾被当成「正确」写在断言里。取消连练递减后曲线整体抬升，旧的 `30000` 护栏已按「6000 以上不再解锁段位 / 难度 / 属性」重标定为 `80000`。改倍率后先跑它，再看真机手感。

- `minigames/theme.js` 给每门功法一套配色、格子符号、印章字与命中 / 失误 / 赞语文案；`pages/practice/` 通过根容器 CSS 变量下发到 wxss，并做了暗色覆盖。
- `minigames/common.js` 的 `vm` 统一带 HUD 字段（进度、实时评级、连击、目标、阶段横幅、浮字、心神、副指标）与 `stage` 舞台形态：`board` 方格、`lane` 河道、`ring` 节律盘、`orbit` 五行灯环、`scroll` 步点卷轴、`charge` 蓄力条。页面据此切换盘面渲染，玩法层只输出数据。
- 修掉过三个玩法漏洞：记忆序列闪烁时把序号写在格子上（等于直接给答案）、点击类点错毫无惩罚、数格辨禁误触一次即收功。
- 节律盘用 CSS `transform: scale()` 呈现，灯环与卷轴也都是纯 WXML/WXSS，不依赖 canvas 与触摸坐标；**真机上缩放、CSS 变量与动画效果仍需复核**。

## 角色资料与规则说明

- 道号 `roleName`、道相 `portrait`（0–5）、头像云存储路径 `avatar` 都是存档字段，随云端存档与 `CANWU1:` 存档码迁移；写入统一走 `engine.updateRole()`。
- 道相是 `components/portrait/` 里**纯 CSS** 绘制的角色形象，按编号换配色与法印、按境界增加光环层数，不需要图片资源也不需要授权。
- 微信登录只建立身份、不返回昵称头像。因此头像与昵称做成**主动选择式**：人物页编辑弹窗里 `chooseAvatar` 选微信头像、`type="nickname"` 输入框带出微信昵称，玩家自己决定用不用。不设头像就用道相。
- 头像上传到云存储 `users/<uid>/avatars/`，显示时用 1 小时签名 URL。**小程序 SDK 的 `storage.download` 不可用**，且签名 URL 由 `<image>` 加载还依赖 downloadFile 合法域名；拿不到 URL 会静默回退到 CSS 道相。这条链路需真机验证。
- **战力 = 属性加权（体魄 1.0 / 灵力 1.2 / 悟性 0.8 / 身法 1.0）×（1 + 境界加成 + 功法特效）**。`getOverview` 把战力总数交给主页境界卡，公式与五条提升途径收进「说明 · 主页 · 战力怎么算」；`pages/guide/` 第二节把「练深一门 ×1→×5、多学一门最见效、突破 +6/+14/+24%、大成特效、换门加成」逐条写清。战力只影响切磋与突破门槛，不参与参悟收益。
- `pages/guide/` 是集中式规则页，共 12 节：目录 chip（点击滚动直达）+ 单节折叠 + 一键全展开，前 11 节列出资源、挂机、战力、熟练度、评级、小游戏、三连 S 晋级、突破、切磋、称号、存档、成就榜单与离线时间规则的全部数值，第十二节是由术语词典生成的「名词速查」。主页六宫格「玩法说明」、说明页页脚与人物页设置区都有入口。
- 面向玩家的页面文案不出现实现细节（数据化、换皮、SDK、RLS 等），这类说明只留在 README 与源码注释里。跨页复用的文案统一放 `data/copy.js`，术语解释统一放 `components/term/`（详见「文案规范与信息架构」）。

## 登录与账号隔离

- 主入口 **微信一键登录**：`wx.login` 取 code + `wx.getAccountInfoSync().miniProgram.appId`（运行时真实 appid，不硬编码），调用 `cloud.auth.signInWithWechat(code, appid)`；后端换会话，前端不碰 AppSecret、不自存 openid。
- 兜底入口 **邮箱验证码**（发送 → 验证，无密码），默认折叠。两种方式共用 `app.js` 的 `afterLogin()`，身份隔离完全由会话 uid 决定。
- 冷启动 `app.js` 检查会话：**只有 `signed-out` 才跳登录页**；网络错误 / 云端读取失败一律保留本机进度离线可玩，显示提示并监听网络恢复自动重试。
- 云端表 `canwu_saves`：`owner_id TEXT NOT NULL DEFAULT auth.uid() UNIQUE`、`payload JSONB`、`version BIGINT DEFAULT 0`、`updated_at TIMESTAMPTZ`。归属由数据库填充，前端不传用户 ID。
- 已开启 RLS，SELECT / INSERT / UPDATE / DELETE 四条策略均限定 `owner_id = auth.uid()`；读写前先过 `cloud.auth.getSession()` 认证门。
- `version` 与 `updated_at` 由 **BEFORE UPDATE trigger 在服务端维护**（验证过前端伪造的 `updated_at` 会被 `now()` 覆盖），客户端不能改表刷时间或绕过版本。
- 榜单表 `canwu_scores`：`SELECT` 对所有人开放，`INSERT/UPDATE/DELETE` 仅本人；同样有服务端 `updated_at` trigger。写入时不传 `owner_id`。

## 存档可靠性

- 每次 `commit` **同步写本机** `canwu_save_v1` 并留下 `canwu_pending_v1` 标记；云端确认成功后才清除。切后台被冻结、断网、写失败都不会静默丢档——下次启动 `hydrate()` 先补写本地改动再读云端。
- 写云端带**乐观锁**：`.update(...).eq('id', rowId).eq('version', expectedVersion)`，0 行命中会再查一次区分「版本被别的设备推进」与「行被删」。冲突时不自动覆盖，弹窗让玩家选「用云端那份」或「用本机覆盖」。
- `rowId` 失效、插入撞唯一约束（23505）、行被移除等路径都有重新对齐 / 重建逻辑，不会卡在英文报错上。
- 关键操作（突破、结算、领奖、改名、买功法、导入、切磋）走 `store.commitCritical()` 跳过 1.2 秒防抖立即回写；其余改动沿用防抖，并发 flush 复用同一个在途请求。
- 主页与人物页有**同步状态条**（只在异常时出现，正常状态不占文字）：待同步 / 失败原因 / 冲突，点一下可手动重试。
- 每日份例与离线收益使用单调时钟：时间回拨不会重开份例或倒着补收益。**彻底防作弊仍需服务端时间裁定，当前版本未接**。
- `SAVE_VERSION = 5`，`migrateState()` 是基于版本的迁移框架；v1–v4 老档（含 `CANWU1:` 存档码导入）自动升级，补 `avatar`、`records`、`sStreak`（每门功法的连 S 计数）并统一版本号。老档不补记历史连 S，一律从 0 重数。
- 云端无档时建新档，**本机旧进度不会自动上云**；要保留就先在人物页导出存档码，登录后导入。退出登录清本机缓存，云端保留。

## 四页信息架构与「说明」页

**为什么改。** 改版前的 tabBar 是「洞府 / 功法 / 论道 / 道牒」：把低频的**论道**放在黄金 tab 位，最高频的**修炼**却只藏在洞府页一个吸底按钮后面，主次是倒的；每个页面又都是「眉标 + 大标题 + 一句说明 + 多个区块小注 + 提示 + 页脚口号 + 术语角标」，洞府页一展开战力明细就是 6 行长文——等于把说明书印在脸上。参考的国风版式只留「标签 + 数值 + 按钮」，解释靠点进去展开，这才是主页面该有的信息密度。

**四个 tab 各管一件事**（`data/navigation.js` 的 `TAB_ORDER` 是唯一真源，`scripts/verify.js` 与 `app.json` 逐项核对）：

| tab | 页面 | 首屏只有 | 说明主题 |
| --- | --- | --- | --- |
| 主页 | `pages/index/` | 境界大卡（境界 / 进度 / 战力 / 称号）、一行提示、可领份例、六宫格、吸底「去修炼」 | `home` |
| 修炼 | `pages/cultivate/` | 练功台：上局战绩与道相、当前功法（名字 / 段位 / 熟练度）、`开始参悟`，换功法走「更换 ›」回功法页 | `cultivate` |
| 功法 | `pages/skills/` | 「已习得 / 未习得」两态、默认按「离下一段最近 + 能拿全额收益」三段排（与主页推荐同源）、紧凑三行卡片（三字正名 + 品阶 / 段位·属性一行 / 阶段色进度 / 定宽动作按钮），整行点开图鉴，玩法名与规则只在图鉴里 | `skills` |
| 人物 | `pages/profile/` | 身份卡、属性格、当前称号、境界突破条件清单、`突破境界` / `背包` | `profile` |

**主页只做导航中枢**：3×2 六宫格，**六格各进各的页面，不再借道别的 tab**——仙门切磋 → `battle`、藏经阁 → `shop`、战力仙榜 → `board`、称号簿 → `titles`、修行日志 → `log`、玩法说明 → `guide`。上一版图省事，藏经阁指向功法 tab、称号簿指向人物页折叠区、仙榜指向论道 `?focus=board`，玩家点进去看到的是另一页，等于「子页没做」。现在三张页面是真页面：`shop` 列身家与可换功法、`board` 列名次与前十、`titles` 列全部称号与佩戴；数据都由引擎给，**返回交给原生导航栏**。`data/navigation.js` 的 `TILES` 是唯一真源，`scripts/verify.js` 核对目标页存在，`tests/layout.test.js` 额外断言**六格不重复、且没有一格指向 tabBar 里的页面**。修炼页记住 `lastSkillId`，切 tab 回来不弹回第一门；仙门切磋从 tab 降为子页，全项目 `switchTab(battle)` 已改成 `navigateTo`。

**解释只有一个入口**：每页页尾一行「说明」→ `pages/help/help?topic=...`，内容全部取自 `data/help.js` 的 `TOPICS`，分节**默认全折叠**，点哪节展开哪节；底部「名词速查」由 `copy.TERMS` 同源生成，`修行指南` 是完整手册、`说明` 只讲这一页。搬走的文字有：战力公式与 6 行明细、份例 / 闭关 / 境界说明、品阶与藏经阁解释、称号与突破条件说明、日志与诸界的介绍、各页页头副标题与页脚口号、散落的术语角标（只保留局内准备页与人物设置等 7 处就地角标）。`pages/practice/` 更进一步：整篇规则搬去了「说明」的分类主题（`topic=practice`，按功法现拼），准备页只留一行「本局规则」+ 难度条，局内只留两行速记——规则分三层，每层只讲一次。

**视觉：墨底一支金。** `styles/immortal.wxss` 只有四条规则：一种底色（墨 `#0c1311`）、一种正文（暖白 `#ece5d8`）、**一种强调（旧金 `#cfae6d`）**、一种状态色（青玉，只标进度与「进行中」）。强调色只给数字、当前项和一处主操作；其余全部用 1rpx 描边与字重区分。
上一版是米金 + 薄荷青 + 荧光青 + 绿灰四支色相并发，次文字还偏绿，整页发浑发荧光。这一版把强调收到金色一支，青玉只留在进度条上；次文字从 `#9cc3b5` 换成中性 `#9daaa3`，注脚提到 `#7d8b84`——实测对比度正文 13.5:1、次文字 7.0:1、注脚 4.7:1、金色 8.0:1，全部在 AA 之上（`README` 里这组数字可直接复核）。
排版不再靠字距撑层级：页头去掉手写空格与衬线体，标题 30rpx/600、面板标签 22rpx 加 4rpx 字距、大数字交给 `--fs-h2`；宫格与属性格用整块细线格（一个外框 + 发丝分隔），不再是六个各带边框的小盒；卡片成组出现（`.imm-list` + `.imm-row`）。按钮只有两种：金色实心（一处主操作）与细描边（其余），高度锁 88 / 64rpx、`line-height: 1`——微信按钮默认行高 2.55 会把并排两枚撑成不一样高，这是上一版「按钮布局不对」的直接原因。禁用态改成细描边灰字，不再是一块发暗的金。实心按钮的底色一律写在 `background-color` 上，渐变只挂在 `background-image`：两者合并成 `background` 简写时，只要某个色标变量在该环境解析失败，整条声明就会被判无效，按钮退化成「一行没有底色的字」——这是登录页一度整页变纯文字的根因。同理，登录页的底色直接取 `--c-imm-*`，不取 `.pg--imm` 重定义过的 `--c-bg`，避免映射层没贴住时退回浅米底 + 深色字。
`.pg--imm` 局部重定义 `--c-*`（含 `--c-primary / --c-gold / --c-surface-ink`），让 `.card` / `.btn` / `.tag` 等旧基础层自动落到墨金体系，不必逐组件写暗色分支。`theme.json` 的导航栏与 tabBar 在明暗两套里都取同一组值，tabBar 图标重生成成灰青 / 金色，否则浅色系统下会拼出一条米白横条。
`scripts/verify.js` 1336 项里守着四页 IA、说明真源、默认折叠、六宫格目标存在与「解释不许回首页」；`tests/layout.test.js` 78 项里守着页面骨架（导航只留原生一层：不许页内返回箭头与第二个标题）、弹窗主次、禁用样式、六宫格独立性，以及**榜单只在战力仙榜页出现**——仙门切磋页不再复述前十，否则两处都能打、两处都要刷新。

## 功法命名规范

**问题不是「名字不好听」，是没有一条能执行的规则。** 改版前 13 门功法里 `刀法·开锋诀`（旧「基础刀法」）与 `心法·吐纳诀`（旧「吐纳诀」）没有前缀；带前缀的又各写各的：`剑法·断岳诀`（旧「剑诀·断岳」）前缀是「剑诀」而类别是「剑法」，`御灵·并蒂引`（旧「灵契·并蒂引」）前缀是「灵契」而类别是「御灵」；正名从 2 到 4 字不等，还混着「入门 / 小」这类等级词。列表扫过去像几套功法拼在一起。

**规则写进 `data/skills.js` 的 `NAME_RULE`，`validateNames()` 逐门校验**：前缀严格等于 `type`（不自造类别词）；分隔符全表只用间隔号 `·` 且只出现一次；正名一律 3 字，末字用体裁字（诀 / 步 / 引）且**同族必须同体裁字**；不写「入门 / 基础 / 初级 / 小 / 大」等品阶词，不与参悟方式名、玩法名重复。体裁字白名单只留在用的字——撤掉符箓一族、把「凝露方」改成「凝露诀」之后，「符 / 阵 / 方」三个字就没有任何功法在用了，`validateNames()` 会反向检查「白名单里有没有谁一整个字没人用」，逼着一起收窄，否则「XX·YY阵」这类名字会蒙混过关。三层命名各管一件事：功法名 = 类别·正名，参悟方式名 = 这一门具体在练什么（循光斩桩 / 勘位辨禁），玩法名 = 盘面上的动作（顺光扫斩 / 数格辨禁）。十九门正式名：`刀法·开锋诀`、`阵法·燃灯诀`、`心法·吐纳诀`、`心法·静心诀`、`身法·踏云步`、`阵法·勘禁诀`、`阵法·五行诀`、`水术·凝露诀`、`剑法·断岳诀`、`心法·太虚诀`、`御灵·并蒂引`、`土术·垒岳诀`、`灵植·三秀诀`、`术数·九宫诀`、`合术·叠元诀`、`目术·逐数诀`、`机巧·让路诀`、`挪移·入位诀`、`辨术·摘魁诀`。改名只动 `name`，`id` 全部不变，存档 / 纪录 / 连 S 计数 / 战力码不受影响；对白可用简称，正式名只认 `SKILLS[].name`。

## 功法图鉴：未习得也能查全本

**靠「看不了」吊胃口是错的。** 黑箱只给一个「未得」标签和一句「首胜 XX 掉落」，玩家连这一门是划刀、推阵还是数格子都不知道，既估不出值不值得练，也不知道该往哪使劲——悬念没有变成动力，变成了放弃。正确的留白是「看得见、练不了」：规则、盘面符号、阶段新法、练成收益、习得路径全部公开，只锁「开练」与熟练度收益。

引擎新增 `getSkillDetail(state, id)`，未习得同样返回完整内容：`guide`（目标 / 步骤 / 盘面术语 / 计分 / 要诀）、`gainLines`（属性 / 倍率 / 大成特效，并写明何时生效）、`stageRules`（本门新法与解锁阶段）、`unlockInfo()`（路径 + 进度 + 可执行动作：藏经阁给价格与资源差额、首胜给对手战力对比、机缘给下一步）。页面不自己拼文案，避免详情页与准备页各写一份。功法页卡片不再压灰，点开即图鉴弹窗；卡片右侧按钮按状态给「修炼 / 兑换 / 详情」，未习得也能一路读清楚再决定。

## 页面规范与设计令牌

**单一真源。** `styles/tokens.wxss` 定义全部语义色（`--c-*`）、字号阶梯（`--fs-*`）、4rpx 间距栅格（`--sp-*`）、圆角 / 阴影 / 层级 / 触控 / 动效 / 安全区；`app.wxss` 只写跨页面复用的类，页面 `.wxss` 只写布局。暗色在令牌表里重定义一次 `--c-*`，页面不再各写一遍 `@media` —— 改版前 5 个页面的私有样式写死浅色值，暗色下会出现浅底浅字（登录页 json 还写死了浅色导航栏，会变白条），现已全部消除。`--c-nav / --c-tab / --c-tab-text / --c-tab-active` 必须与 `theme.json` 的 `@` 变量同值，`scripts/verify.js` 逐项核对。

**页面骨架。** 四个 tab 与所有内容子页根节点统一 `.pg.pg--imm`（登录页是唯一品牌页例外 `.login-page`）；**导航只有原生一层**：返回箭头与页面标题都由小程序导航栏承担，页面里不再画 `‹` 与第二个标题；「说明」这类低频入口沉到页尾一行小字（`.pg__foot`），顶部不再为它单独占一行；区块用 `.imm-panel`（面板）、`.imm-list` + `.imm-row`（成组列表）、`.help-sec`（折叠分节）；页脚口号全部删除，只留指南页一行品牌字。**同一屏上页面名只出现一次**：tab 页的 `navigationBarTitleText` 一律留空（页名由底部 tabBar 承担，顶部再写一遍就是同一行字出现两次，`app.json` 的全局标题也留空以免漏写时回落），子页才写「仙门切磋 / 参悟 / 登录 / 修行指南 / 说明 / 修行日志 / 藏经阁 / 战力仙榜 / 称号簿」；参悟页的局内卡片同理不再重复「参 悟」，只报这一局玩的玩法名。配色交给主题变量（明暗同值）。旧骨架 `.pg__head`（眉标 + 标题 + 说明三行）是双层导航的来源，已随改版删除；`.pg__foot` 仍留给需要一行页脚文字的页面。

**尺度与反馈。** 页面左右留白 `--page-x`(28rpx)，卡片内距 28rpx、卡片间距 24rpx、区块间距 40rpx；正文 28rpx、辅助 24rpx、角标下限 22rpx；主操作热区 88rpx、次操作 76rpx、卡片内紧凑操作 68rpx；层级只用 0 / 40 / 80 / 90 / 100；所有吸底条与页面底部带 `env(safe-area-inset-bottom)`。加载 / 空 / 错误统一 `.state` 占位（主页、功法、仙门切磋、人物都接了），不再白屏或各用普通卡片；可点 `view` 统一 `class="… pressable" hover-class="pressable--on"`，危险操作只有一支 `.imm-btn--danger`。

**白名单例外。** `styles/scene.wxss` 与 `pages/practice/practice.wxss` 的**盘面**色板由 `minigames/theme.js` / `data/visual.js` 按功法注入（`--acc / --soft / --ink / --glow / --well / --deep`），必须固定、不随明暗漂移。参悟页的边界是「**纸张与墨**」：可以摸、可以划的那块（`.grid / .cell / .ring-area / .orbit / .scroll / .pad`）是纸，取注入色；其余全部（准备页、HUD、判定横幅、结算弹层、难度档）是墨，一律取 `--c-imm-*`。所以 `practice.wxss` 的 `.pg` 把整组 `--c-*` 映到 `--c-imm-*`（与 `.pg--imm` 同值），并无条件深色——本页已删掉 `@media (prefers-color-scheme)`，系统切深色时页面与盘面都不变色。`scripts/verify.js` 与 `tests/layout.test.js` 用 1336 项静态检查、78 项布局断言守住上述约定。

## 文案规范与信息架构

**文案单一真源。** `data/copy.js` 收拢跨页复用的玩家文案：加载与空态、通用按钮、区块标题，以及 22 条术语词典；`data/help.js` 收拢解释性长文；`data/navigation.js` 收拢导航标签。页面 WXML 一律写 `{{copy.xxx}}`，不许再抄字面量。改版前「打开一局小游戏」有「开始参悟 / 去参悟 / 就练这门 / 去练一局 / 回去修炼」五种写法，四个 tab 页的 loading 各拟一次人（推演气机 / 翻检藏经阁 / 整理论道台 / 展开道牒），品牌口号在 6 个页面重复。现在**同一动作一个说法、同一状态一句白话**；「参悟」与「修炼」也不再当同义词混用——修炼是去练功台，参悟是在练功台打一局；页面首屏只显示数据标签，解释一律进说明页。`scripts/verify.js` 有共享文案黑名单，并会拦截「解释性文字回到 tab 页首屏」。

**黑话首次出现即可查。** 新增 `components/term/`（虚线下划线 + 小圆问号，点击弹一句大白话），解释统一取 `copy.TERMS`，覆盖份例、闭关收获、蓄力停区、战力码、镜像、道号与道相、连 S 晋级、本门新法、功法图鉴、息等 22 个词；深色卡上用 `tone="ink"` 换配色。修行指南第十二节「名词速查」由同一份词典按「成长 / 页面 / 对战 / 玩法」分组生成 —— 解释只写一遍，页面弹层与指南不会各说各话。静态校验核对词典字段、`term-key` 引用以及用了 `<term>` 的页面是否注册了组件。

**信息架构按「先做一件事」排。** 主页首屏只留境界大卡、一行提示、六宫格与吸底主按钮（全页只留一个 `onQuickPractice`）；今日之课长卡、战力明细、快升段功法列表、境界突破长卡、日志与诸界全部撤走——分别去说明页、功法页、人物页、日志子页。功法页改成「已习得 / 未习得」两态，默认按「离下一段最近」排（与主页推荐同源），卡片只留玩法名 + 数值 + 一个动作，规则与收益进图鉴弹窗；人物页只留一行「称号簿 ›」通向独立页，成就、背包 / 战力码、设置、诸界收成 4 个默认折叠的分节；仙门切磋页的战力码仍折叠，日志与诸界另开子页。修行指南按**新手阅读流**排（怎么变强 → 离线挂机收益 → 灵气与灵石 → 战力从哪来 → 熟练度与境界 → 参悟与小游戏 → 三连 S → 切磋与战力码 → 称号与道牒 → 存档与换设备 → 成就与榜单 → 名词速查）：先搞懂挂机保底，再知道资源是什么，然后才学主动玩法。**目录 chip 直达 + 单节手风琴 + 一键全展开 / 全收起**，展开态只有 `sections[i].open` 一套状态——改版前全局展开与单节展开并存，全局展开着点某节标题会「点了没反应」。三节带「前去藏经阁 / 去修炼 / 去切磋」的下一步按钮，名词速查开头放一个真的「?」示范（`DEMO_TERM` 由校验守住），说明页则按主题分节折叠。区块标题一律说清里面是什么，不用「近况」「就差一点」这类含糊词。

品牌标语也只剩一份（`BRAND.slogan`）：人物页身份卡、分享文案与卡片图都取它；资源与收益的单位写法由 `formatCost / formatGain` 统一，两个函数都接进了真实页面，不是注释里的摆设；进度只有「X / Y」一种写法，直接写在 WXML 里由版式断言挡住无空格版本。

**可回归。** `scripts/verify.js` 1057 项里包含文案黑名单、术语词典完整性、`term-key` 引用与组件注册；顺手修了一个老漏洞：组件四件套检查原来只认绝对路径，页面 json 普遍写的 `../../components/...` 相对路径从未被验过。`tests/layout.test.js` 78 项里新增「文案真源」「术语同源」「信息架构主次」三组断言。

## 界面与按钮约定

- **主操作常驻拇指区**：主页底部有 `sticky-bar` 吸底主按钮「去修炼 · 推荐功法」，`.pg--with-bar` 预留底部空间；修炼页把「开始参悟」放在熟练度卡下方。**两处措辞分工明确：主页只负责把人送进练功台，不替人开局；难度档、规则速记、上一局评价都在修炼页。**四 tab 之外的入口全部走主页六宫格，页面底部不再堆与 tabBar 重复的跳转按钮。
- **弹窗统一「次操作在左、主操作在右」**：取消 / 关闭 / 次要动作一律 `btn--plain` 在左，`btn--primary` / `btn--gold` 在右（功法详情的主按钮由 `wx:if` / `wx:elif` 互斥渲染，也排在最右）。
- **危险操作降权但明示**：重置存档、退出登录用 `imm-btn--danger` 警示样式，与常规操作之间加分隔线与提示文字，均为 `wx.showModal` 二次确认。分享类次要动作降为 `.text-link` 文字链。
- **触控热区**：`.btn` / `.btn--small` / `.text-link` 分别取 `--touch`(88rpx) / `--touch-sm`(76rpx) / `--touch-xs`(68rpx)；纯文字点击入口一律补 `.text-link`。`.btn-row` 自带 20rpx 上边距会覆盖 `.mt12` / `.mt16`，需更紧时用 `.btn-row--tight`（`--mid` / `--flush` 无人使用，已删）。
- **减少重复整宽按钮**：仙门切磋页 10 个对手 / 秘境的挑战按钮改为行内小号按钮（`imm-btn--ghost imm-btn--sm`），不再各占一整行；诸界在日志页与人物页默认折叠，主页不再放这块。
- **局内操作分区**：参悟页「收功」是退出操作，放在局内 HUD 右上角 `.hud__quit`（屏幕上方、离拇指热区远）并加「这一局作废、连 S 原样保留」确认；撤销 / 提示留在底部 `sticky-bar--tools`。
- **吸底条只在有操作时出现**：`barMode` 只有 `start`（准备页：先不练了 + 开始参悟）和 `tools`（局内确实有撤销 / 提示时）两种；其余玩法不挂条、`.pg--with-bar` 也不加留白——否则多数玩法会白留一截底部空白，还把盘面挤出屏幕。
- **局内不重复功法头卡**：进入参悟后 `.pr-head`（标题 / 描述 / 熟练度条）不再渲染，技法名与难度压进 HUD 第一行小字，省下的近 380rpx 全部让给盘面。
- **HUD 每个数只说一遍**：`已探 X / Y` 与进度条已经在讲同一件事，目标句就不再写「还剩 N 格」；心神有独立的灯格行，目标句也不再复述。目标句只放「这一局在追什么」——例如探禁的「S 线 25 秒 · 已用 18 秒」。
- **局内评级徽章只在「档位会往上爬」的玩法里出现**：分数型玩法从 C 一路涨上去，摆着有意义；按用时反推档位的探禁，开局那一刻必是 S，摆出来等于告诉玩家「S 已到手」，之后只看它往下掉，所以 `extras.showGradeNow = false`，档位只在结算里给。
- **局内分数不叫「灵石」**：灵石是能换功法的资源，局内那个数是这一局的得分。场次 HUD 原来标「灵石 608」，同一页结算又写「灵石 +3」，两处当场打架；现在 HUD 与结算都叫「得分 / 局内得分」。
- **常驻速记只写恒久规则**：`guides.inline` 是所有阶段共用的那一行，写成「大成后到靶心停一拍」会让未入门的玩家以为每一刀都要停。阶段规则交给盘面上方那行按本局状态显示（`trail.rule`），大圆满同时开双锋与收势时两条一起给，不许只报一条。
- **新法生效范围写在标题右侧**：「本门新法 · 习得后每局生效」一句说透，条目里不再逐条重复；习得是永久的，每局重来的是效果。
- `tests/layout.test.js` 把以上约定固化为 78 项断言（含 WXML 标签配平、事件方法与 js 定义对应、弹窗顺序、热区尺寸、安全区留白、吸底条形态、音效资源齐备、箭头形态与禁反向、视觉标准与演出时序）。

## 音效

局内反馈全部由 `utils/sfx.js` 发声。音源是仓库里的 9 个 wav（`assets/sfx/`，16kHz 单声道，共约 92KB），由 `scripts/gen-sfx.js`（`npm run sfx`）合成——不引外部音频文件，改音色只改合成参数。

第一版反馈「太刺耳、脑子嗡嗡的」，第二版按四条改柔：**只用基频 + 极轻二次分音**（去掉金属泛音）、**全局一阶低通 + 14ms 软起音**（去掉「咔」的瞬态）、**每个音效只留单声部且衰减压到 0.1–0.2 秒**、**峰值 0.52 再乘播放音量 0.26–0.36**。

| 音效 | 触发时机 |
| --- | --- |
| `tap` | 落子、点空、撤销 |
| `hit` / `miss` / `gold` | 浮字 `vm.fx.tone` 的 good / bad / gold |
| `tick` | 倒数三声、用提示 |
| `go` | 起手 |
| `clear` / `settle` / `fail` | 结算 S·A / B·C / F（走火＝没走完；主动收功单独一种卡，不报字母） |

- **判定结果只认浮字**：`vm.fx` 是玩法层唯一统一的判定信号，页面 `render()` 里比对 `fx.key` 有没有变就发声，19 套玩法不用各写一遍；点空这类没有浮字的操作由页面补一声 `tap`。
- **绝不叠加**：判定 / 结算音共用一路声道（`VOICE`），新的一声会掐掉上一声；`pool` 一律为 1，另有同名 `gap`（85–400ms）与全局 `GLOBAL_GAP`（60ms）两层节流。第一版允许 3 路磬声并发，连击时叠成嗡鸣，这一条由 `tests/layout.test.js` 断言守住。
- **静音键不吃音效**：`obeyMuteSwitch = false`。否则 iOS 打开侧边静音开关就整局无声——「怎么没声音」最常见的来源。
- **三档音量**：人物页「设置」折叠区点一下弹出「轻 / 中 / 关」，默认「轻」（再乘 0.75）。落本地存储 `canwu.sfx.level`，兼容旧键 `canwu.sfx.on`；切档会同步改已创建音频实例的音量。页面 `onHide` / `onUnload` 收声，退出去不会接着响。
- 上下文在进参悟页时 `warm()` 预建，第一次落子不用等实例化。

## 玩法说明

20 套玩法（19 门功法 + 突破专用蓄力停区）各有一份「怎么玩」，数据集中在 `data/guides.js`：一句话目标、分步操作、**盘面术语表**、计分方式、诀窍，外加一行局内速记。

- **准备页**：头卡下面就是「怎么玩」卡，**默认收起**（先看功法与熟练度，要规则再点展开）；收起态那一行只写基础操作 + 本门**已解锁**的阶段新法（`STAGE_RULES[].short`），逆诵 / 死门这类还没解锁的不提前出现。
- **选档时说清代价**：难度档下面跟一行「这一档相对入门收紧了什么」（`diffDetail.brief`：`亮起时长 0.66 秒 → 0.49 秒 · 闪烁间隔 0.31 秒 → 0.23 秒`），而不是只给一个 ×1.70。毫秒一律折成秒，判定窗 / 气机收敛这类内部倍率不摆。
- **段位条下面写「下一段给什么」**：直接搬 `world.TIERS[].desc`（`到「小成」：解锁「普通」难度`）。只写「还差 114」等于只给一个数字，练到那步才发现没有好处。
- **局内代价句用阿拉伯数字**：`罚 1.5 息`、`折 1 盏心神`、`罚 3 秒`，与 HUD 的「余 12.3 息」同一套写法；中文数词要在脑子里换算，实时对局里读不起。`tests/layout.test.js` 扫全部 tip 与两处浮字挡住回退。
- **规则要变，在前一轮就说**：逆诵（第 3 轮起）、叠印（第 5 轮起）都是「打到这里突然换规矩」。等那一轮闪起来才提示，玩家第一下已经点下去了，只会觉得「好好记着顺序，凭什么让倒着点」。所以 `memory.js` 在**上一轮结算时**就把「下一轮起逆诵：从末字往前点」写进 `vm.status`，并把轮间停留从 640ms 拉到 1500ms——这句话得留得住人才有用。本轮生效的规则同时挂在 `vm.banner` 上，一直显示到输入结束。`tests/minigames.test.js` 用假时钟断言这句预告确实出现在第 3 轮之前。
- **阶段新法练到手就该能关**：逆诵、死门、收势、禁桩、双锋这些是**改规矩**（改点击方向、多一格不能碰的、要求停一拍），不是给便利，所以在 `STAGE_RULES` 里标 `hard: true`，准备页给一个开关（`state.twists[功法]`，缺省全开，不随存档版本走）。勘位 / 照纹 / 稳基是纯加成，关掉没有任何好处，不给开关——多一个开关只是多一处看不懂。三个玩法（`memory` / `lights` / `click`）都从 `perks.offTwists` 读，关掉就真的不触发；局内不给开关，改规则只能在开局前改。
- **战力是阶梯，别按线性报**：属性 = 功法条目 × 段位系数（0 / 1 / 1.8 / 2.8 / 4 / 5）× 品阶系数，段位不跳战力就一分不动。所以结算不写「本局战力 +N」（大多数局都是 0，等于每局告诉玩家白练），而是摆 `战力 112 · 跨段才涨` 加一行 `距离「金丹」还差 46 战力`；突破局的结算则明写 `战力 45 → 48（+3）`，主页提示也从「还差 46 战力」补成「· 突破后 +3」。`powerDetail(state, realmIndex)` 可指定境界重算，突破后的战力就是拿它算的，不另抄一遍公式。
- **局内**：HUD 的提示文字下面常驻一行术语速记（如刀法·开锋诀：`顺箭头扫到靶心 · 重斩翻倍 · 斜斩擦角不算 · 单点不判也不罚`），不占按钮、不用弹窗、也不会打断计时；划刀玩法盘面上方还会常驻当前招式名与桩数。**常驻行只写恒久规则**：大成才有的「到靶心停一拍」由盘面上方那一行按本局状态显示，写死在速记里会让未入门的玩家以为每一刀都要停。
- **三秀同收别让玩家多翻译一层**：简介改成「互换相邻两株 → 三株同色采收 → 新苗落下连锁」，仙味词（灵畦 / 采收 / 照畦）后面紧跟白话动作；有歧义的旧称一律改为「无效互换」，并在名词速查里定义清楚（换不出三连、原样换回、少 2 息；点错格、选中又取消都不算）。代价句 `换不出三连少 2 息` 原本从 `method.tip` 传进 `vm.hint`，却被 `syncHud()` 冲成纯计数，玩家整局看不到——现在 `costText` 常驻 hint 开头、计数跟在后面，`tests/layout.test.js` 守住「hint 必含代价句、全站无旧词」。S 线 `620 + 每档 150` 由 `data/practice.js` 的 `MATCH_S` 同源送进 params，准备页写出本档具体分数与「评级只看总分」的口径，玩法层不再自己算一份。反馈按调性分档：连锁 / 四株齐收走 `gold` 中量震动，无效互换只给 `light` 轻震，不跟着刀法猛震；提示按钮名统一收进 `HINT_LABELS`，三秀同收叫「照畦」。
- **盘面不放字**：早期起手桩挂一个「锋」字，既不指方向也不说明规则，已删掉。现在刀路每桩是一个纯 CSS 箭头（三角 + 短杆，按 `dirAngle` 旋转到八个方向之一），收势桩是圆环靶心；重斩从一格单字变成「更长的金色箭头刀路」，和寻常蓝色刀路一眼分得开。术语表把两者的桩数、分值、寿命、漏了会不会断连击都写清，还加了一条「带桩容差」讲明刀势可以多带两桩。
- **勘禁诀的术语也讲透**：`data/guides.js` 用具体例子说明「数字 1 的周围只剩一格没翻开 → 那格必是禁制」，并解释 ✕（禁制）/ ⚑（阵钉）/ 心神 / 不必猜 / 已探进度；局内速记常驻「数字＝周围八格禁制数 · 长按钉阵钉 · 钉数对上点数字格连开」。
- `tests/minigames.test.js` 断言 20 套玩法都有完整说明、术语不缺解释、局内速记不超长、刀法·开锋诀必须解释「箭头 / 刀路 / 重斩 / 扫到靶心」；另有断言逐桩核对箭头角度与相邻桩方向一致。

## 输入形态：为什么刀法·开锋诀从「点」改成「划」

第一版「追光点击」是 3×3 静态格子里点亮的那一格，本质是打地鼠：手指不移动、没有方向与轨迹，调参数、加特效都改不掉这个体感。

参考过两条路：钢琴键 / 下落式音游的输入仍是「到点按一下」，手指还是点；水果忍者式的划线有轨迹感，且长扫轨迹、重斩后摇、一刀带走数个目标正好就是**刀**的手感。但抛物线飞入的目标 + 刀光拖尾要上 canvas，会在纯 view + setData 的架构里分叉出第二套渲染路径，真机性能与假时钟测试都得重来，所以只借「划」这个输入，不借它的渲染。

现在的「顺光扫斩」把「划」装进现有网格，**不引 canvas**，走的是刀该有的长折线扫掠（见下一节「兵器轴」）：

- 刀光沿 3×3 刀桩依次掠过 3–5 格，形成横劈 / 立劈 / 斜斩 / 游龙四种有方向的刀路；光走到收势桩才起寿命线，玩家可以追着最亮的光头一刀扫过去。
- 每桩一个纯 CSS 箭头指向下一桩（八方向），收势桩是靶心；**盘面没有任何汉字**，方向全靠形状表达，`dirAngle()` 用相邻两桩的行列差算角度。
- **方向只能顺着走**：判定 `matched()` 只认「起手 → 收势」这一个序列，反着划、跳桩、绕一大圈都判劈空；刀势允许多带两桩（刃扫过的面积），但绕盘面乱划一大圈不算。招式名「回锋」随之删掉，免得暗示可以反着来。
- 页面盖一层透明触摸层（`.swipe-layer`），开局量一次格子矩形，相邻 `touchmove` 之间按 10px 插值补全中间格。小程序的 touchmove 目标固定在起手元素，逐格绑事件收不到跨格轨迹；不做插值的话，划快了会漏桩、被误判成劈空。
- **斜向两格只共一个顶点**：从 A 中心直划到 B 中心必然擦过旁边那格的角，整格命中会把「擦角格」补进轨迹，斜斩就被判成劈空。现在 `utils/swipe.js` 的插值只认格子中心内圈（半宽 0.42 格，擦角采样进不来），玩法层 `trimCorners()` 再把真机手抖 / 主动绕角多出的共边邻桩摘掉后判定——直划与绕角算同一刀，绕盘面乱划一大圈仍判劈空；禁桩与虚影不参与摘除，划到照判。起手 / 抬手是静止点，仍用整格命中，按在桩边上也能认出来。
- 玩法层只多收一个 `swipe(path, { hold })`，`vm.cells` 协议、判定浮字、音效、假时钟测试全部沿用，其余 12 套玩法一行未改。`hold` 是抬手前在最后一格停住的毫秒数，页面用「最后一次换格的时刻」算，收势靠它判定。
- **第一层难度只拧数值**（`depth`）：刀路 3→5 桩、光速 343→120ms、后摇 418→142ms、重斩每 5 道→每 3 道、连击门槛 5/10/20→9/18/32、劈空罚 1→2 息、S 门槛 507→912。后摇是唯一能压到高手的旋钮——会读图的人抢在光走完之前就划掉了，光速与寿命只卡新手。
- **第二层挂在熟练度阶段**：大成「收势」（到靶心停一拍再抬手，抢着抬只给半分）、圆满「禁桩」（红叉，划过就断势）、大圆满「双锋」（两条刀路，只有靶心在呼吸的那条是真招）。这三种都算「规则内看错」：断刀势、不罚息；反向 / 跳桩 / 绕圈这类违招才罚息。
- **生成层按 `params.grid / cols` 计算**，不再假设 3×3；默认仍是 9 格 3 列，4×4 在测试里跑通，作为以后扩盘的天花板。

## 兵器轴：为什么这一门是刀，以及剑法先不做

早期把这套长扫轨迹挂在「基础剑法」下，还写成平削 / 直刺 / 一剑中的 / 剑尖不许带桩——**那是剑的文案配了刀的手感**。手指「划」这个输入本身不分兵器（刀势、剑气都有轨迹），区别在于轨迹是什么：

| | 刀（当前启用） | 剑（预留，暂不挂功法） |
| --- | --- | --- |
| 轨迹 | 刃扫过的**面积**：长折线为主 | 光走的**点线**：短直线为主 |
| 招式 | 3–5 桩，折线多、允许大转弯 | 2–4 桩，折线少 |
| 判定 | 只认正向，容许多带 2 桩（刀势连贯） | 最多带 1 桩（抗抖） |
| 节奏 | 起手沉、后摇长、余势不断 | 光快、后摇短、点到靶心即收 |
| 称谓 | 横劈 / 立劈 / 斜斩 / 游龙、一刀斩中、劈空 | 平削 / 直刺 / 斜挑 / 绕指、一剑中的、刺偏 |

**这一版先只做刀法**：初始功法改名「刀法·开锋诀」，`weapon: 'dao'` 是唯一启用的 profile；`sword` profile 与「剑法·断岳诀」仍留在数据里，但剑法不做点刺式输入、也不新增功法。长扫、重后摇、连扫数桩这套语汇本来就是刀，与其拿名字去补机制，不如让名实先对齐；将来真做剑法时补一个点刺输入适配器即可，共用同一套 `create(ctx)` 与结算。

`data/weapons.js` 是第五根轴（类型 → 玩什么、**兵器 → 怎么动**、品阶 → 收益、熟练度 → 难度、境界 → 上限）。两份 profile 管轨迹长度、折线概率、光速、判定容差、后摇、评级缩放、招式名与全部浮字称谓。`minigames/click.js` 只读 `ctx.params.weapon`，**不硬编码任何兵器称谓**；`buildParams` 原样透传，没标兵器时回落到当前启用的 `dao`。主题表只管配色与本门 banner，不再覆写命中 / 失手浮字——否则刀法沿用剑法主题时会说出「一剑中的」。

**再加一门刀法变体只要三步**：① `data/practice.js` 新增 method，`game: 'click'` + `params.weapon: 'dao'`；② `minigames/theme.js` 配一门刀主题；③ `data/guides.js` 补一份说明。玩法模块、页面、结算、音效、假时钟测试一行不用改。

`tests/minigames.test.js` 用 `weapon: 'sword'` 与 `weapon: 'dao'` 把同一套引擎各跑一局，断言招式明显更长、招式名与命中浮字全换、剑势槽变刀势槽；另有一条断言扫过刀法全部可见文案（招式名、浮字、说明、命名、主题）确保不混进剑字，反过来也守住预留的剑 profile 零刀字。`sword` profile 目前**未挂任何功法**——把「分得出来」变成可回归的事实，而不是提前做半套剑法。

## 刀法的难度：数值挂档位，规则挂阶段

通用难度表走 `buildParams(method, diffKey)`：节奏类乘 `pace`、判定窗乘 `windowPace`、数量类乘 `goal`。但刀法的 `params` 里只有 `life` 落在这些键上，盘面尺寸是刻意不缩放的——所以五档真正发力的地方，是 `minigames/click.js` 读 `depth` 与 `perks.tier` 的那几行。

**第一层：档位只拧数值。**

| 档位 | 刀路 | 光速/桩 | 后摇 | 重斩 | 连击门槛 | 劈空 | S 门槛 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 简单 | 3 桩 | 343ms | 418ms | 每 5 道 | 5 / 10 / 20 | −1 息 | 507 |
| 普通 | 3 桩 | 217ms | 264ms | 每 5 道 | 6 / 12 / 24 | −1 息 | 608 |
| 困难 | 4 桩 | 150ms | 181ms | 每 4 道 | 7 / 14 / 28 | −1 息 | 709 |
| 极难 | 4 桩 | 132ms | 158ms | 每 4 道 | 8 / 16 / 30 | −2 息 | 810 |
| 绝境 | 5 桩 | 120ms | 142ms | 每 3 道 | 9 / 18 / 32 | −2 息 | 912 |

**低档缓入**：光速与后摇不是从档位线性起算，而是先乘一个随档位迅速收回的系数（`EASE_STEP = 2.2 / 1.45 / 1.08 / 1.02 / 1`、`EASE_GAP = 2.2 / 1.45 / 1.08 / 1.02 / 1`）。简单档的 156ms/桩直接抬到 **343ms**——3 桩要走 0.7 秒才亮完，每一步该往哪拐都看得清；后摇同步从 190ms 放到 418ms，斩完有一拍实打实的喘息。绝境档仍是 120ms / 142ms，一格未松。入门档是「教学」，高档才是「压力」，中间三档平滑过渡。

**评级门槛按实际得分重标**：旧门槛（155 / 68 / 22，即简单档 S 要 3139 分）是按「每秒划 4 刀」的机器人配的——15 息内要打 157 刀，人力根本不可能，正常速度玩下来永远停在 C，玩家只能靠抢在光头到达前盲划去刷分，这才是「明明调慢了还是觉得被催」的根源。新门槛按这一档真正打得出的分数反向推：简单档光走完 686ms、后摇 418ms，一局 12–14 刀，连击不断打下来 530 上下，所以 **S 507、A 385、B 203**——正常节奏就是 A，S 要的是连击不断、重斩全接。`tests/minigames.test.js` 里有一条断言整局不抢划跑完，确保简单档能拿到 A 以上。

后摇（`gap`）是这一门唯一能压到高手的旋钮。刀路在 `spawn()` 时就把整条路径和全部箭头画好了，`swipe()` 不检查光头位置——会读图的人可以抢在光走完之前划掉，所以光速与寿命线只对新手构成压力，接招间隔才决定高手的实际节奏。连击门槛同步上抬，是为了抵消「路更长、单招分更高」；不抬门槛，绝境档反而更容易拿 S。

**第二层：阶段换规则。** `STAGE_RULES.forge` 三条与 `perks.tier` 对齐，准备页的「本门新法」会逐条列出：

- 大成「收势」：划到靶心要停 70ms 再抬手，抢着抬算收势未成。
- 圆满「禁桩」：盘上出现红叉，禁桩一定不在刀路上；划过就断势。
- 大圆满「双锋」：同时亮两道刀路，两条都有靶心，只有会呼吸的那条是真的（`cell__end--live`）；虚招与真招不共用任何一格。

这三种都属于「规则内看错」：断刀势、不罚息。收势未成还留着半分，是因为它已经划完了整条刀路，只是没沉住；禁桩与虚影则整刀作废。反向 / 跳桩 / 绕圈才罚息——前者是没读清规则，后者是明知故犯，代价不该一样。

收势最初做成「未成则这一刀作废」，模拟下来玩家只要没注意到新提示就会整局 0 分——那不是难度，是事故。改成半分 + 断势后，同一节奏下从 0 分变成约正常得分的四分之一，落在 C 而不是归零：玩家还能继续练、还能拿到 60% 收益，同时「学会停顿」的回报是分数直接翻四倍。

**第三层：生成层不再假设 3×3。** `straightForms / neighbors / wanderPath / isBent / angleOf / dirAngle` 全部按 `shapeOf(grid, cols)` 算，`lineForms` 按形状缓存。默认仍是 9 格 3 列；`npm test` 里用 `grid: 16, cols: 4` 连跑 8 招，断言路径不越界、不重复、不跳格——把「以后能扩盘」变成可回归的事实，而不是先改盘面再发现生成层写死。

## 勘禁诀：把经典扫雷做扎实

「扫雷太经典了」正是它该挂在黄阶的理由：规则不用教，玩家看一眼数字就懂。所以这里的深耕**一条新规则都没加**，只把经典扫雷之所以好玩的三件事补齐（`minigames/mines.js`）：

- **首点必开出一片**：旧版在 `start()` 里就随机布好了禁制，`relocate()` 只在首点恰好踩雷时挪一枚，首点周围可能全是雷、开局就被一个数字堵死。现在改成**玩家点第一格才布雷**，那一格连同八邻一律无禁制；首点数字必为 0，一定展开一片空白。
- **整盘不用猜**：布完禁制用约束传播从首点模拟一遍最基础的推理（数字格周围「未探格数 == 剩余禁制数」→ 全是禁制；剩余 0 → 全安全），推得完才算合格，否则最多重布 64 次。刻意**不引入 1-2-1 / 两数相减**这类高阶技巧——黄阶入门功法的「无猜」就该是认得数字就能推完。6×6 五档实测 150 局全中，首点生成平均 0.2ms。`tests/minigames.test.js` 另有一个只读 `vm.cells` 的黑盒推理器，真的把整盘零失误翻完，不是玩法层自己说了算。
- **布镇符终于有用**：旧版那块记号只是给自己看的，胜利条件是「翻开所有安全格」，纯装饰。现在点已翻开的数字格，若周围符数（含已显形 / 已照见的禁制）对上数字，会一次连开其余邻格（chord）；压错位置照样踩禁制、按误触扣心神。不布符也能一格格点完，会用的人才快。

顺带修掉两处旧账：

- **破纪录方向是反的**：`finish.score` 以前传的是耗时秒数，而 `engine.applyPractice` 按 `score > prevBest` 记纪录——越磨洋工越容易「破纪录」。现在统一传「越大越好」的结算分（探明格数 ×10 − 用时 ×2 − 失误 ×60），与评级同向。
- **难度档挤成一团**：旧写法在 `buildParams` 已按 `goal` 缩放禁制数之后，又叠一次 `ctx.difficulty === 'hard' ? +3`，而 `gear` 只有 normal / hard 两值，困难 / 极难 / 绝境三档其实是一盘。现在禁制数全交给 `goal`，另让心神按 `depth` 从 3 盏收到 2 盏；盘面只有数字与 `✕`（禁制）/ `⚑`（旗）两个符号，不落汉字。

- **归类按玩法定，不按名字凑**：这门功课从头到尾是「看数字推禁制」，没有一处是画符——符是纸上画出来的东西，与格盘推理不相干。原来的「符箓·照影符」是类别与玩法相斥（项目自己的规矩就写着「符箓不练探雷」），已按「以游戏为准」改为**阵法·勘禁诀**，顺势补齐阵法族三档：黄阶勘禁（静态推理）→ 玄阶五行（动态连锁）→ 地阶燃灯（步数最省）。盘面术语同步从「镇符」改为「阵钉」，视觉色板从符箓朱金改为阵法青紫，`id` 仍是 `leifu` 不动存档。

阶段新法只给便利不添规则：大成「勘位」每局开局勘出 3 处禁位、大圆满「洞玄」5 处（**习得后每局生效**，不叠加，也不跨局留标记），已勘出的格子点了不再扣心神。三盏心神、长按钉阵钉、按用时评级（25 / 45 / 75 秒）这些老规矩原样保留；评级只看用时，心神折了只扣结算分。

## 视觉标准与沉浸舞台

方向：**国风修仙 + 2D 游戏场景 + 灵气特效 + 游戏化 HUD**。舞台固定深色（游戏该有固定氛围），页面也固定深色——四个主页面、子页、参悟页与登录页统一「墨底一支金」，不再跟 `prefers-color-scheme` 翻转。原则是「一套骨架、十一种皮相」：统一字体阶梯、间距圆角、HUD 骨架、反馈时序、结算框架；各异的是场景母题、主辉光色、道具符文、招式动画与音色。

- **唯一真源** `data/visual.js`：四类主题色板（兵刃青蓝 / 心法青白 / 丹道赤金 / 阵法青紫）、动效预算、结算分镜、样板开关。`styles/scene.wxss` 由 `app.wxss` 全局引入，只放表现；`minigames/` 下一行视觉字段都没有。
- **零图片资源**：山门、月轮、三层山脊、云雾、灵气点、法坛全是 CSS 色块与路径。全项目素材仅约 95KB（音效 92K + 图标 3K），主包上限 2MB；十套场景若用位图会吃光包体，还要分包、CDN、加载白屏与深浅两套图。换主题只改几个色值，不用重出图。
- **三层场景**：远景静态（月轮 / 山门 / 星点 / 山脊）；中层 3 路常驻循环（月晕呼吸 8s、云雾漂移 18s、灵气上升 12s）；近层法坛与盘面恒为最高对比，特效不许压过判定信息。倒数三秒的深色遮罩顺带充当进场的明暗过渡。
- **游戏化 HUD**：息 → 香炷竖槽、心神 / 余息 → 命灯、连击 → 带 5 / 10 / 20 刻度的刀势槽、得分 → 灵石数字、评级 → 玉牌。
- **三档反馈**：命中 4 粒子 / 连击阶跃 6 粒子金色 / 重斩 8 粒子加金光闪；失手红光闪。视觉与音效共用 `vm.fx` 这一个判定信号。所有关键帧只动 `transform` / `opacity`，常驻循环 ≤3 路，粒子 ≤12 枚/次。
- **结算五段演出**：`0ms` 暗场收束 → `300ms` 评级落定（S 金光横扫 / F 裂纹）→ `700ms` 熟练度条 `scaleX` 涨满、数字浮现 → `1200ms` 奖励逐条 → `1800ms` 按钮淡入。S/A 满 1.8s，B/C/F 压到 900ms，任意处点击跳过，切后台回来直接给按钮。数字用 CSS 缩放浮现而不是逐帧 setData，守住「零高频 setData 动画」。
- **样板阶段**：`visual.ENABLED` 目前只有 `forge`（刀法·开锋诀 / 顺光扫斩），其余十八套仍走原 HUD 与原结算卡。真机验过再逐个放开，避免方向没认就改十八套。`tests/layout.test.js` 用 4 条断言守住色板、样板开关、演出时序与动效预算。

## 开发约定与工程命令

- **设计先过清单**：新增一门玩法或改动已定规则，先照 `docs/checklist-puzzle.md` 逐条自检。它是交付门槛而不是灵感清单——十二个维度条条要有答案，能指到文件与断言；「二期」可以空着，但要明确知道自己空着。
- **内容即数据**：新增功法、参悟方式、对手、称号、成就或调数值，只改 `data/`，不动业务代码。
- **一门功法一套玩法**：19 门功法各自对应 `minigames/` 里的一个模块，`data/practice.js` 的 `game` 一一映射、不复用内核；同类别的功法也必须有不同盘面与规则。新增玩法要实现模块 + 在注册表登记 + 挂到功法表，`tests/minigames.test.js` 会断言玩法唯一与同类不重样。
- **品阶管收益、难度跟人走**：品阶挂在 `data/skills.js` 的 `tier`（`TIERS`），难度档挂在 `data/practice.js` 的 `DIFFICULTIES`，`buildParams(method, diffKey)` 只按难度档缩放参数。新增功法必须指定品阶与分类，同类内变体不得重样，盘面尺寸字段不得缩放——`tests/rank.test.js` 断言这些约定。
- **难度只调参数，不再「gear 二次收紧」**：`buildParams` 输出 `depth`（0–4，第几档）与按档递增的 `steps`，玩法据此调整，而不是看 `gear`（只有 normal / hard 两个值，分不出困难与绝境，容易一档一个样、还叠成断崖）。顺光扫斩、阵灯推演与数格辨禁已改完，其余玩法仍是旧写法。
- **名字分四层，互不撞词**：功法名（典籍上的名字）、参悟方式（这门功课在做什么：斩桩 / 采露 / 观窍）、玩法名（盘面上的动作：顺光扫斩 / 循纹递推）、主题名（2 字意象：刀光 / 卦象）。前三层任意两层同名，准备页就会出现「步法连环 · 步法连环」这种叠字；**参悟方式不得与功法相斥**——刀法不练数格子、丹道不练渡河、心法不练牵线（上一版反例就是「符箓」练扫雷，已改归阵法）。`tests/minigames.test.js` 断言三层不撞词。
- **小游戏统一接口**：`create(ctx) -> controller`，见 `minigames/common.js`，注册表在 `minigames/index.js`；控制器除 `tap(index)` 外可选实现 `swipe(path, { hold })`（手指经过的格子序列与收势停留，目前只有顺光扫斩用）；`vm.stage` 决定页面用哪种舞台（`board` / `lane` / `ring` / `orbit` / `scroll` / `charge`），玩法层只输出数据。`ctx.theme` / `ctx.twist` 决定表现与本门规则。
- **单一状态源**：页面只读 `store.get()`，写走 `store.commit()` / `commitCritical()`，刷新靠 `store.subscribe()`；页面保持同步 API，云读写后台异步。
- **云客户端唯一**：`utils/cloud.js` 是全工程唯一初始化点；`store.setCloudAdapter()` 可替换存档实现。
- `'use strict'` + CommonJS，除云 SDK 与 ESLint 外无运行时依赖，不使用打包器。

```bash
npm ci            # 按 lock 还原依赖
npm run verify    # JSON / JS 语法 / 页面组件四件套（含相对路径）/ 主题变量 / tabBar 图标 / 隐私清单 / 品阶难度 / 页面规范 / 文案术语
npm test          # 243 项常驻断言（内核 + 存档同步 + 小游戏假时钟整局 + 品阶难度 + 布局约定）
npm run sim       # 收益曲线模拟：验证高档期望更高、境界衰减生效、封顶不误伤、刷简单不反超
npm run lint      # ESLint 9（小程序全局对象与 CommonJS 已配置）
npm run check     # 上面四项一次跑完，CI 用这个
npm run icons     # 重新生成 tabBar 图标（零依赖）
```

`.github/workflows/ci.yml` 是可移植的 CI 模板（`npm ci` → `npm run check`）。仓库双托管：`origin` 指向 Gitee（主），同时配了两条 pushurl，`git push` 一次同时推 Gitee 与 GitHub 镜像，`fetch` 只走 Gitee；GitHub 侧可直接用这份 workflow，Gitee Go 需按其配置格式另配一份，命令相同。
