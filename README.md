# 参悟

一个修仙题材的**养成挂机 + 小游戏**微信小程序：练功法、参悟小游戏、攒熟练度与战力、突破境界、与人切磋，顺手收集称号与成就。

> 原生微信小程序 + WorkBuddy 云服务：微信一键登录（邮箱验证码兜底），进度按账号存云端并做版本隔离，本机留同步缓存。
> 当前状态：体验版可玩（已上真机试玩多局），**未正式发布**；真机登录、云端读写、榜单与隐私授权链路仍需逐条验收。

## 小游戏设计

**一门功法 = 一套玩法**。19 门功法对应 19 个互不复用的玩法模块，连同类功法也不共用内核；每套在盘面形态、交互方式、胜负规则、难度参数上都不同。`data/practice.js` 的 `game` 一一映射到 `minigames/`，`twist` 写清本门独有的规则花样：

| 功法（参悟方式） | 类别 | 专属玩法 | 盘面形态 | 独有的花样 |
| --- | --- | --- | --- | --- |
| 刀法·开锋斩桩诀（循光斩桩） | 刀法 | 顺光扫斩 | 3×3 刀路（可划） | 刀光沿 3–5 桩依次掠过，每桩一个 CSS 箭头指向下一桩、收势是靶心；必须顺箭头划，反向判劈空；光走完起寿命线；连击基础 5 / 10 / 20 记给 ×1.5 / ×2 / ×3，档位越高门槛越高；重斩每 5 道（高档更密）；大成收势、圆满禁桩、大圆满双锋 |
| 剑法·截锋断岳诀（辨锋截击） | 剑法 | 辨伪择真 | 4×3 方格 | 每轮数道剑光只一真招，截错倒扣分数与时辰，连截提速 |
| 心法·静心记诵诀（背功法口诀） | 心法 | 记序复现 | 3×3 方格 | 复述有时限（题长 × 每字息数），点错罚一息半、三盏心神；连对每轮 +15%（封顶 +45%）；长按抢记按「少看几个字」给 ×1.2–1.9；大成逆诵、圆满叠印 |
| 水术·叠纹凝露诀（循纹采露） | 水术 | 循纹递推 | 竖向河道（逐层） | 纹路 = 上层 +1 递推，水流打乱露石，三盏心神 |
| 心法·吐纳周天诀（吸纳灵力） | 心法 | 节律判定 | 一张谱：光环 + 朱色判定带（双手两环并排） | **按音乐写谱**：拍号定分组、速度（BPM）定心跳、音符时值定疏密，一格＝一个八分音符、音符落在整数格，环的周期就是到这个音符的间隔（长拍慢、短拍快），判定点落在 72.8%、点过之后仍收到底；五档各换一件事——每拍一下 → 长短交替 → 带休止 → **双手 1:2** → **双手 2:3 且提示全撤**；判定窗按「该手最短间隔的四成」封顶、下限 100ms；带内圆满、带边半拍（早 2.2 倍窗、晚 1.4 倍窗）、环收到底空拍；评级按「圆满当量」（合拍半分），分母是两手音符之和 |
| 身法·踏云连环步（照卷踏位） | 身法 | 步法连环 | 卷轴步点 + 4 个方向键 | 卷轴画成一串步点、走过的描边、当前那颗实心起光；每颗步点与四个键都只用 CSS 图形指方向（↑ 前踏 / ↓ 后撤 / ↗ 斜踏 / ⟳ 旋身），盘面不写汉字；四段逐段变长，同一方向最多连出两个（三个就成了无脑连点），踏错重出并少一息；评级只看走完的段数 |
| 阵法·点灯破阵诀（参悟阵眼） | 阵法 | 阵灯推演 | 3×3 → 4×4 → 5×5 方格 | **一盘推演、按冗余手数评级**：点一格翻自身与四邻，余量内全亮即破阵；评级只看「比最优多走了几步」——一步不多 S、多两步内 A、多五步内 B、其余 C；阵溃（余量走完还没全亮）是走火 F。**辅助一律有代价**：阵眼感应照一格算 2 步、折步数不封顶（走满最优也掉出 S）；复原本局每局只许一次，用过拿不到 S、最高 A。预算不写死，按本盘最优 +7 步余量现算，三档共用同一余量、难在盘面与最优步数。求解走 GF(2) 消元 + 零空间枚举（5×5 生成 40 局约 3ms），不再 2^n 穷举；盘面不写汉字，亮 `●` / 灭 `○` / 死门暗红 `✕`，**不显示「已亮几盏」**（正确一手常让亮灯变少，那个数会骗人）。大成开死门：误触后这一格点不动、罚 2 步，不复位整盘。难度档同时放大盘面与最优步数区间（3×3 2–3 步 → 3×3 4–5 → 4×4 4–5 → 5×5 6–7 → 5×5 8–9），同尺寸两档区间不重叠；首次开局有盘上两步引导（可跳过，只出现一次） |
| 阵法·五灯相生诀（排布阵灯） | 阵法 | 五行相生 | 五灯环 + 中央牌 | 按相生之位接龙，连生越长窗口越短 |
| 阵法·循数勘禁诀（勘位辨禁） | 阵法 | 数格辨禁 | 6×6 方格 | 经典扫雷：首点开出空白区、整盘无猜、钉阵钉后点数字格可连开；盘面只有数字与 ✕ / ⚑；三盏心神（高档两盏）、大成勘出 3 处 |
| 心法·太虚翻卦诀（内视观窍） | 心法 | 成对翻牌 | 4×3 方格 | 翻两处气窍配一对，记卦象；两次入定照见一对 |
| 术数·九宫排数诀（推填九宫） | 术数 | 九宫填数 | 4×4 / 6×6 / 9×9 方格 | 每行每列每宫各填一遍 1–N；挖洞时逐格验「解还唯一」，填错按格罚十息；点格选中、数字键落子、✕ 清格 |
| 合术·同数叠元诀（同数相合） | 合术 | 滑格相合 | 4×4 滑格 | 整行整列四向挤压，同数一撞翻倍；合出本档目标块即收功，盘满且相邻无同数判走火 |
| 目术·扫目逐数诀（循数疾点） | 目术 | 顺序点格 | 4×4 → 5×5 → 6×6 → 7×7 方格 | 数散在盘上，从 1 顺次点到末数；**盘上不标下一个在哪**，点错不移位、按档罚 2～6 秒，极难起点过的格不再退场，考的是目光一路扫过去不乱 |
| 机巧·让主出阵诀（挪块开路） | 机巧 | 滑块让路 | 4×4 滑块盘 | 整块滑一格，把 2×2 主块挪到底部出口；BFS 现算本盘最优步数，按「已走 / 最优」评级 |
| 挪移·石箱归位诀（归箱入阵） | 挪移 | 推石入位 | 6×6 / 6×7 石图 | 人走石格、石箱只推不拉；每块推到阵位才算完，按推数评优 |
| 辨术·一眼摘魁诀（择大辨微） | 辨术 | 数中取大 | 数阵 | 一批数只挑最大的那个，拣对换下一批；点错罚时不换批 |
| 境界突破 | — | 蓄力停区 | 蓄力条 | 长按蓄力、松手停在朱线区间，越近正中评级越高 |

举例说明「同族也不重样」：刀法顺着流动的刀路把刀扫到靶心（3×3），剑法在数道剑光里截真招（4×3 且截错倒扣）；两门阵法一个是静态翻转推演，一个是环形限时接龙。功法页每张卡片直接标出专属玩法名，开局前准备页只留一行「这一局做什么」，整篇规则在右上角「说明」里按节折叠。

**熟练度不只是解锁更难的同一件事**：`data/practice.js` 的 `STAGE_RULES` 给每门功法登记「到了某个阶段规则会变」，准备页的「本门新法」默认收成一行，点开才逐条列出已得与待解锁，改规矩的那几条能就地关。目前落地两门——静心记诵诀大成「逆诵」（奇轮倒着点）、圆满「叠印」（题里出现重复格子）；点灯破阵诀大成「死门」、圆满「双门」。机制写在各自的 `create()` 里，按 `ctx.perks.tier`（熟练度阶段 0–5）开关。

**主页回答一个问题：现在练哪门**。`engine.recommend(state)` 按「离下一个熟练度阶段最近」排序（按阶段跨度归一，衰减到三成的功法往后压），给出「差多少熟练度升哪一段」和「本档还剩几关、走通就开下一档」。主页的一行提示与吸底按钮都取这一条，不让玩家自己算倍率；功法页的把「离下一段最近」排在最前也读它。

**三处压力是统一标准**：每一门都要有「会失败、有代价、有取舍」这三样。顺光扫斩、记序复现、阵灯推演、数格辨禁四套已按这条标准重做完，其余玩法仍是旧写法。

**顺光扫斩的循环**（其余 15 套照同一张清单排）：刀路逐桩亮起、箭头指明走向 → 手指顺箭头扫到靶心 → 白光掠过、下一道立刻换招。压力有三处：**反向划或跳桩一律判「劈空」**，罚一息（与剑法·截锋断岳诀同规矩）；寿命线走完没划中就是「漏」，刀势清零；乱划会把自己划死；连击 5 / 10 / 20 记后每一刀的得分抬到 ×1.5 / ×2 / ×3，一次失误全退回 ×1。每第五道换成重斩：刀路更长、分翻倍、寿命八折，接不住不罚、只是白过一手。五档难度改的是刀路长度与光掠过的速度，不是把数字拧小。

### 功法品阶与难度档

**一个维度只管一件事**：类型管玩什么，品阶管「练得多贵、属性多厚」，难度管「打哪副盘」，熟练度管「练得多熟」，境界管上限。调数值时互不牵扯。

**品阶（天地玄黄）管耗气与属性，不管难度。** `data/skills.js` 每门功法挂 `tier`，`data/practice.js` 的 `TIERS` 定义耗气系数、属性系数与可修境界：

| 品阶 | 星级 | 功法 | 运功耗气 | 属性系数 | 可修境界 | 获取 |
| --- | --- | --- | --- | --- | --- | --- |
| 黄 | ★☆☆☆ | 刀法·开锋斩桩诀、心法·吐纳周天诀、阵法·循数勘禁诀、御灵·并蒂牵线引、土术·万石成岳诀、灵植·三秀连收诀、术数·九宫排数诀、合术·同数叠元诀、目术·扫目逐数诀、机巧·让主出阵诀、挪移·石箱归位诀、辨术·一眼摘魁诀 | ×1.00 | ×1.0 | 筑基 | 初始赠送 / 藏经阁 |
| 玄 | ★★☆☆ | 心法·静心记诵诀、身法·踏云连环步、阵法·五灯相生诀 | ×1.15 | ×1.3 | 金丹 | 藏经阁 / 切磋首胜 |
| 地 | ★★★☆ | 阵法·点灯破阵诀、水术·叠纹凝露诀 | ×1.30 | ×1.7 | 元婴 | 初始赠送 / 切磋首胜 |
| 天 | ★★★★ | 剑法·截锋断岳诀、心法·太虚翻卦诀 | ×1.45 | ×2.2 | 元婴以上 | 切磋首胜 |

**品阶按「这门功课有多难」定，不按「什么时候拿到」定。** 阵灯推演要在大盘上推演联动、还要把步数压到最优，是十九门里最费脑的一门，挂在黄阶等于「练得最苦、拿得最少」，所以提到地阶，名字也从「阵法入门」改成「阵法·点灯破阵诀」——地阶功法再叫入门，就是玩家一眼看得见的名实相斥。数格辨禁反过来：看懂数字规则之后基本是稳的，难度低于两门阵法，降到黄阶。阵法·五灯相生诀偏反应、比阵灯推演轻，落玄阶，与点灯破阵诀排成「玄 → 地」两级。**一族一个品阶只放一门**，同阶撞车会让谱系按阶取槽时把后一门盖掉，`tests/rank.test.js` 有断言守这条。九套经典玩法（连连看 / 俄罗斯方块 / 消消乐 / 数独 / 2048 / 舒尔特方格 / 华容道 / 推箱子 / 找最大数）规则一看就懂、难度最低，也统一挂黄阶，价格与境界门槛都按黄阶走（见下节）。

代价要说清：点灯破阵诀是初始三门的其中之一，而地阶门槛是金丹——炼气到筑基这段它运功贵一半（1.30 倍），属性加成则照拿 ×1.7。这是「品阶管耗气与可修境界、不管难度」的直接结果：高品阶天生要等境界，不然一门就通吃了。

**五档是五条并列的线，各 40 关。** 每门 200 关 = 5 档 × 40 关；走通本档 40 关才开下一档，与熟练度、品阶都无关。玩家界面只写档内 1–40，参数层仍吃全书 1–200（`levels.globalLevelOf()`），这样「第 41 关比第 40 关紧」跨档仍可比。档越往后一局越贵，同时 `pace` 收紧、`goal` 抬高：

| 档 | 全书关 | 开法 | 基础耗气 | 节奏 | 目标 |
| --- | --- | --- | --- | --- | --- |
| 简单 | 1–40 | 默认可选 | 7 | ×1.18（更缓） | ×0.85（更低） |
| 普通 | 41–80 | 走通「简单」40 关 | 11 | ×1.00 | ×1.00 |
| 困难 | 81–120 | 走通「普通」40 关 | 17 | ×0.88 | ×1.12 |
| 极难 | 121–160 | 走通「困难」40 关 | 24 | ×0.78 | ×1.22 |
| 绝境 | 161–200 | 走通「极难」40 关 | 32 | ×0.70 | ×1.32 |

**单价随章上升，单点灵力的熟练度反而下降——这是刻意的。** 标价 7 点的简单章（剑法实付约 6 点）首局 S 就换 34 点，绝境要 32 点（实付约 27 点）才换同样的 34 点。难盘该更贵，否则「又便宜又给得多」会让后段只剩挑战意义。往上走的回报不在单价，在**连 S 只在本档当前关叠、回关还要按「本关 ÷ 40」折减、降到低档再逐档对半**：同样 6000 点灵力，`npm run sim` 实测逐关进 5252 点熟练度、只刷简单档第 1 关 682 点，不到一成半。所以「哪档划算」其实没得选——停在第一关既叠不了连 S，又拿不满基础值。

**准备页有一排档位牌，五档并列。** 已开的档点一下就换，锁着的写「未开」、点了只说「先走通「普通」40 关」。档内第几关由「本档走通了几关」定（`levels = {easy: 12, …}`），**一局只推一关**，走通它下一关才开；往回翻可以退到第 1 关（`levelOverride`，只记内存）。想打本档还没走到的关会被夹回并如实报出（`levelFellBack`）。因为一局只动一格、换档那一刻玩家还亲手点过牌，`chapterSpec()` 的「本档换了哪一副盘」不会再被跳过；`levelDelta` 换档只报盘面规格，不报毫秒微调。

**回关只折熟练度，不折耗气。** 两种折减各管一层：档内 `practice.levelFactor(本关, 当前关) = 本关 ÷ 40`（分母是本档总关数，不是「离当前关多远」），再走 `profByLevel()` 四舍五入一次；降到已通关的低档则每低一档先对半一次、逐档取整，再叠档内那一刀。本档第 40 关时回打 40 / 30 / 20 / 10 / 1 关是 ×1.00 / ×0.75 / ×0.50 / ×0.25 / ×0.025；连降四档的 S 是 34 → 17 → 9 → 5 → 3。**「回头一步就掉下来，中间没有过渡」是故意的**——分母若改回「当前关」，停在第 1 关时第 1 关永远 ×1，「只刷第 1 关」就成了稳定正收益（实测 11551 vs 5252，反超逐关进）。耗气按所选档位的基数照算，与档内第几关无关。**连 S 与回关完全解耦**：回关局与降档局都不叠层、不砍连击收益、已有层数原样保留，回当前关照接第 3 连。

**结算公式**（`applyPractice`，一进一出两套账）：

```
熟练度 = 单局基础（S 34 / A 23 / B 15 / C 10 / F 0 点）
         S 连击：第 k 连 = round(34 × 1.5^(k-1))，k ≤ 10，之后锁死 1307 点/局
         回关：基础值 × (本关 ÷ 当前关)，四舍五入一次，且本局不参与连 S

耗灵力 = RUN_QI[档]（7/11/17/24/32） × methodQiFactor(本门时长基准 30–56 → 0.85–1.30)
         × TIER_QI[品阶]（1.00/1.15/1.30/1.45） × 境界超限 1.5
         × (1 − 心法省气，封顶 0.5) ÷ 悟性系数(1 + 悟性/200，≤ 1.6) × 触类旁通 0.92
         → round，最低 1 点；开局前先扣，走火与主动收功都不退
```

- **熟练度与功法品阶彻底解耦**：它只由「本局评级 + 连 S 层数」决定，不乘品阶、不乘难度、不乘境界、不乘属性；回关只折「基础值」，不碰连击收益。按当前关全 C 走，9999 局累计 99990 点，第 10000 局补满 **99999**（大圆满硬顶）；全程不断 S 且都打当前关，前 10 局 3853 点、之后每局 1307 点，**84 局**就到顶（理论最少局数，中途断一次连就更慢）。到顶后熟练度不再涨、属性也就不再涨，但**关卡照样往前走**——剩下那些关是盘面，不是熟练度，所以不能再说「该换门了」（全 S 84 局就到顶，那时大概才走到第二档）。
- **品阶的价值 = 战力 + 可修境界，代价 = 更费气**：`attr` 管属性，`qiCost` 抬高运功耗气（1.00 / 1.15 / 1.30 / 1.45），`needRealm / maxRealm` 管境界门槛与超限加价，都不加速熟练度。低阶功法省气、高阶功法厚属性，成长线上各有位置。
- **六段阈值 0 / 300 / 1500 / 6000 / 24000 / 99999**，段间跨度约 ×4；这六个数同时是本门 200 关的六个锚（`levels.levelFromProf()` 章内线性），一章一段：入门开第二章、小成开第三章、大成开第四章、圆满开第五章。最后 76000 点只能靠绝境一局局实打：连击封顶后每局固定 1307 点，也还要几十局——按 32 点一局算，那一段光灵力就要两千多。
- **只奖不罚，但难度是事前承诺**：同一门连练不减收益，攒「连 S 倍率」本来就该连着练；换一门另有 `CROSS_QI = 0.92`「触类旁通」，省 8% 灵力，是正激励、不是对专精的惩罚。旧的连练递减机制已废弃。回关折减不违背这条——它管的不是「练同一门」，而是「已经练到后面却回头打前面的关」。
- 评级 `GRADE_FACTOR` S 1.5 / A 1.2 / B 1.0 / C 0.6 / F 0 现在**只用于 buff 档位判定，既不进熟练度也不进资源**（资源产出已从参悟里整体撤出）。**F 是「整局作废」，不是「最低一档」**——熟练度为 0、连 S 归零、已经扣掉的灵力不退；C 才是「走完了但糙」的那一档。
- **C 与 F 是两个结论，不是两档分数**：C「粗浅」=这一局走完了但打得糙；F「走火」=这一局**没走完**（阵溃、心神耗尽、时辰到还没通完、还剩对子没接上）。有失败态的十二门（燃灯 / 勘禁 / 静心 / 太虚 / 凝露 / 并蒂牵线引 / 九宫 / 叠元 / 逐数 / 让路 / 入位 / 摘魁）判负一律走 F，零熟练度并断连；没有失败态、一局有自然终点的七门（刀法 / 剑法 / 身法 / 吐纳 / 灵植 / 土术 / 五行）最低只到 C——时辰到 / 拍数打满 / 段数走完就是这一局的终点，不是失手。吐纳周天诀走的是谱，没有时限，终点是「本局音符判完」。**主动收功**是第三种：它根本不进结算（`applyPractice` 不调用），由 `breakCombo()` 把连 S 归零，堵住「预感拿不到 S 就中途退出保连」，结算卡上是「收」而不是「F」；起手烧掉的灵力同样不退。
- **每门「C / B / A / S 各要什么」写在说明页里**：各玩法模块导出 `lines(params, gear)`，`minigames/index.js` 汇总成 `gradeLines()`，说明页「怎么评级」一节按当前难度档列出本档四条线（例：刀法困难档 `S ≥ 709 分 / A ≥ 507 / B ≥ 284 / 其余 C`；探禁 `S ≤ 25 秒 / A ≤ 45 / B ≤ 75`）。这份数与局内 HUD 的「再 N 分可入 S」、结算档位出自同一处算法，不存在第二套门槛。局内只报「下一条线还差多少」，看全四条要进说明页——一屏塞四条线会把第一局要读的东西挤掉。
- **耗气只有一个出处**：`data/economy.js` 的 `practiceQiCost(o)`。准备页调 `engine.practiceCostOf()` 预判并写在按钮上，`applyPractice` 内部再判一次（防改存档、防双页面同时开局），付不起直接拒绝开局并给出差多少。没有第二处算耗气。
- **境界超上限只加价，不禁练**：人物境界高于本门 `maxRealm` 时耗气 ×1.5（`REALM_OVER`），熟练度照给——原来砍产出，现在加消耗，是同一件事换了方向。
- 越权挑关（例如改页面参数）会被夹回本档当前关并标注（`levelFellBack`）；想打没开的档则夹回当前档，不会白送熟练度。
- 缩放的是节奏（`interval` / `flashMs` / `windowMs` / `shuffleMs` / `flipMs` / `window`）、收敛速度（`speed`）与目标数量（`chainGoal` / `maxRound` / `segments` / `beats` / `scramble` / `mines` / `pairs` / `decoys` / `startLen` / `baseLen`）。**`grid` / `cols` / `rows` / `size` 不交给通用缩放**：列数只认 wxss 的列规格白名单（`.grid--c3` 到 `.grid--c10`，6 列以上自动隐去角花），顺手被 pace 缩放改掉会错位。真要按档换盘面的门走各自的**显式规格表**（`LINK_LEVELS` / `MINES_LEVELS` / `CLICK_LEVELS` 等），玩法层真的读、准备页真的写「本档几乘几」——灵纹连线 6×4→8×4 就是这条，买的是搜索空间，不是缩场地逼手速。各字段按玩法安全上限 clamp。
- 同一类型的功法共用一个**游戏族**（`data/practice.js` 的 `FAMILIES`），族内按品阶出变体（`data/skills.js` 的 `chainsOf()`）。功法页「功法谱系」把天地玄黄四档全列出来，**缺变体的档位显示空档**（如刀法的玄、地、天三阶），补齐只需加一门数据。
- 每门功法记一个局内最佳分数（`state.records`，存档版本 4，老档平滑迁移），结算显示得分与「破纪录」。**分数只作纪录，不加收益** —— 评级管收益，分数管追求。
- `scripts/simulate.js`（`npm run sim`）是**收支曲线**：先打一份五档耗气表（基数 → 含时长系数与悟性的实价）与天阶对照，再跑**全 C** / **全程不断 S** 两条通关曲线（逐段记录局数与总耗气、折成「要闭关多少小时」），最后在**固定 6000 点灵力预算**下跑五种刷法（黄阶只刷第 1 关 / 逐关进 / 退一档刷 / 天阶逐关进 / 黄阶金丹后）。预算制而不是局数制，是因为灵力才是约束——同样的局数在低档烧的气少得多，拿局数比会让「刷简单」显得划算。断言分三层：**熟练度**（全 C 六段里程碑 30 / 150 / 600 / 2400 / 10000 局；全程不断 S 前 10 局 3853 点、84 局毕业；1～14 连逐局复算与第 11 连封顶；非 S / 走火 / 主动收功断连；回关与连 S 解耦；五章与四品阶在绝境章上 C 都是 10 点；回关折减对照表、低档逐档对半）、**耗气**（五档实价逐档递增、与 `practiceQiCost` 同源复算、准备页预判与结算扣除逐档相等、心法与悟性真的省气、堆满省气也压不穿 1 点、灵力不足直接拒绝开局且不扣任何东西）、**对战**（首胜另给 8 枚、重复打赢按当日场次衰减、每场先扣 5 点灵力、没钱直接拒绝）。另有两条策略护栏：「同样 6000 点灵力，只刷简单档第 1 关 682 点、退一章刷也不反超逐关进的 5252 点」。改数值后先跑它，再看真机手感。

- `minigames/theme.js` 给每门功法一套配色、格子符号、印章字与命中 / 失误 / 赞语文案；`pages/practice/` 通过根容器 CSS 变量下发到 wxss，并做了暗色覆盖。
- `minigames/common.js` 的 `vm` 统一带 HUD 字段（进度、实时评级、连击、目标、阶段横幅、浮字、心神、副指标）与 `stage` 舞台形态：`board` 方格、`lane` 河道、`ring` 节律盘、`orbit` 五行灯环、`scroll` 步点卷轴、`charge` 蓄力条。页面据此切换盘面渲染，玩法层只输出数据。
- 修掉过三个玩法漏洞：记忆序列闪烁时把序号写在格子上（等于直接给答案）、点击类点错毫无惩罚、数格辨禁误触一次即收功。
- 节律盘用 CSS `transform: scale()` 呈现，灯环与卷轴也都是纯 WXML/WXSS，不依赖 canvas 与触摸坐标；**真机上缩放、CSS 变量与动画效果仍需复核**。

## 双货币经济：灵力是油，灵石是钱

**两套货币各修一条线，只有一道单向的闸**（`data/economy.js` 是唯一真源）：

| | 灵力 | 灵石 |
| --- | --- | --- |
| 是什么 | 修士的「油」，日常节奏 | 修仙界的通货，长期目标 |
| 从哪来 | 闭关（0.5/分钟，一次最多算 8 小时，可随时「打坐」收）+ 每日份例 60 + **灵石兑换** | **只有两条**：切磋与秘境（当日第 n 场 `0.85^(n-1)`），首胜 / 首过另给 8 枚 |
| 装得下多少 | **有上限**：气海 =（境界基数 + 真元 × 2）×（1 + 心法扩池），炼气 174 / 筑基 284 / 金丹 444 / 元婴 644 起，满则不再生 | 无上限：灵石是长期目标，攒着不咬手 |
| 到哪去 | 参悟运功（7～32 × 各类系数）、切磋与秘境运功（每场 5） | 藏经阁买功法（12 门，16–70 枚）、布阵破境（60 / 120 / 240）、兑灵力（1 枚 = 100 点） |
| 设计意图 | 上限才是节奏：一趟能练几局由气海决定，想多练就去破境、去练真元 | 只有一次性大额支出，所以每一枚都要掂量；兑灵力是第三条支出，与买功法抢同一笔钱 |

**参悟从「产出」改成「消耗」是本轮的核心改动。** 旧版打一局既给灵力又给灵石，等于「花时间印钱」：灵力永远是过路财，灵石变成计件工资，玩家一直在攒钱却感觉不到钱有分量。现在单局只剩两个数——**熟练度多少、耗多少气**，一句话就能讲清；要灵石就得去打切磋，要灵力就得回去闭关，两件事第一次有了取舍。备份逻辑：`applyPractice` 的返回值里已没有 `qi / stone` 产出字段，只剩 `qiCost / qiBefore / qiAfter`。

**灵力有上限，叫气海。** 上限 =（境界基数 + 真元 × 2）×（1 + 心法扩池），境界基数写在 `world.realms[].qiCap`（炼气 150 → 元婴 620），扩池来自 `effect.type = 'qiCap'`（吐纳 +10% / 太虚 +15%，合计封顶 `QI_CAP_SKILL_MAX = 30%`）。没有上限时，挂机时长就是唯一的节奏，玩家只会「挂够再来」；有上限之后，境界多了一重每天摸得到的意义（一趟能练几局），闭关也变成「回来收」而不是「放着涨」。三条配套规则：①`idlePending` 把「坐出来的」与「装得下的」分成 `qiRaw / qi / overflow` 三个数，溢出当场散掉并在闭关回执里写明；②`meditate` 满池时不说「还没攒够」，而是直说「灵力已满」——它仍能收熟练度，所以满池不挡打坐；③`claimDaily` 在气海余位不足 60 时**拒绝领取**（份例是发放的，可以等人来取；打坐收的是坐出来的，满溢就散）。破境会拓深气海并**当场补满**（`applyBreakthrough`），这是突破的第二重回报。

**属性各有一件正事。** 体魄只进战力；**真元每点 +2 灵力上限**；悟性按 `1 + 悟性/200` 省灵力；身法每 30 点把切磋的波动下限抬 1%（封顶 10%，与 `variance` 特效共用 `rollBattle` 的 floor）。旧版四项属性都只进战力，练哪门都一样——「练功有什么用」因此答不上来。属性面板的 `role` 字段就是这个出口，人物页直接显示在数值下面。

**闭关可以随时「打坐」。** 灵力既然是参悟的油，油烧完了就得能补——如果只有冷启动那一次「闭关收获」，玩家在局内撞上「灵力不足」之后就无事可做（只能杀掉小程序再开，而且重开也只结算离开的那几分钟）。所以洞府首页多一行「闭关打坐」：攒够一点就能收，收多少由 `engine.idlePending()` 预演、`engine.meditate()` 结算，与冷启动那次共用同一套 accrual（`settleOffline` 已经改成调 `idlePending`）。它**不额外产任何东西**，只是把「离开期间攒的」变成「随时能收的」；顺带把两分钟以内的零头挡回去，免得「收下 = 灵力 +0」白扔时间。

**机缘只出残卷，不出资源。** 参悟里那点「偶得」现在只有一种结果：石阶上拾得《某诀》，概率 `FORTUNE_SCROLL_RATE = 1.2%`（约百局一册）。它曾经有 45% 的概率摸到 30–80 灵力、43% 摸到 15–40 灵石——那等于在「纯支出」的参悟里又开了一条细水长流，一晚上练三十局，摸到的灵石比打十场切磋还多。残卷这条路留着，是因为「不花灵石也能凑齐功法」得有条运气通道；资源那两条必须关掉，否则上面整张表就不成立了。

**对战也要运功。** 每场切磋与秘境先扣 5 点灵力（`BATTLE_QI`），胜负都扣；不够就直说「灵力不足」，不允许「没钱还打」。「赚灵石」和「练功」争同一池灵力，才不会出现「反正切磋不要钱，闲着就打」的空转。

**回合内的灵石产出有软顶。** 当日第 n 场战胜给 `0.85^(n-1)`（第 1 场全额、第 5 场 52%、第 10 场 23%），记账在 `state.daily.battleWins`，跨天由 `checkDaily` 清零。它不会归零，但打到第 15 场只剩一成，玩家自己就会停手——灵脉一天只吐那么多。首胜 / 首过那 8 枚是一次性奖励，不受衰减管。

**突破改为花灵石。** 筑基 60 / 金丹 120 / 元婴 240（`breakthroughStone(realmIndex)`），冲关不成退回一半（`BREAKTHROUGH_REFUND = 0.5`，「阵基还在，灵石散了些」）。原来拿灵力灵石各扣一点的做法会让「破境」在两种货币间含糊不清。

**心法与悟性换位到「省气」侧。** 六门心法（静心、勘禁等）原来的 `effect.type = 'practice'`（参悟收益 +X%）全部改成 `qiSave`（参悟耗气 −X%），累计封顶 50%（`PRACTICE_SAVE_MAX`）；悟性按 `1 + 悟性/200` 直接除，最多除到 1.6（省 37.5%）。熟练度不许有倍率，所以「练得省」这件事只能落在灵力上——这也是悟性唯一的用武之地。

**存档 v6 → v7，以及读档时夹平气海**：`migrateState` 把老档的 `resources.qi` 抬到至少 `START_QI = 160`（只补不削，否则更新后一局都开不了），并补 `daily.battleWins = 0`。开局身家 160 灵力 / 15 灵石：开局气海 174，一进来就接近满，第一件事是「去练」而不是「先等半小时」。旧版灵力没有上限，老档可能攒到几百点，所以 `normalizeState` 末尾会把余额夹到当前气海——只夹一次，不反复没收，之后由「溢出即散」接管。

## 角色资料与规则说明

- 道号 `roleName` 与道相编号 `portrait`（0–5）是仅有的两个角色字段，随云端存档与 `CANWU1:` 存档码迁移；写入统一走 `engine.updateRole()`。
- 道相是 `components/portrait/` 里**纯 CSS** 绘制的角色形象，按编号换配色与法印、按境界增加光环层数，不需要图片资源也不需要授权。
- 微信登录只建立身份、不返回昵称头像。名字是**主动选择式**：编辑弹窗里 `type="nickname"` 输入框可以带出微信昵称，也能纯手打道号，玩家自己决定。
- **微信头像能力已去掉**：形象只有一份——`components/portrait/` 的 CSS 道相。删它的理由是三份维护成本换一个小圆头像：`chooseAvatar` 要声明「用户信息」隐私项、头像进云存储要过内容安全检测、签名 URL 还得配 downloadFile 合法域名。删掉之后隐私清单只剩「昵称 / 剪贴板 / 发布内容」，头像这条从未真机验证过的链路也一并消失。存档里的 `avatar` 字段同步退役（`updateRole()` 忽略该键）；老档带来的这个键在 `normalizeState()` 里被丢弃。后续皮肤与形象走 `portrait` 的编号（0–5）扩展，不再接微信头像。
- **战力 = 属性加权（体魄 1.0 / 真元 1.2 / 悟性 0.8 / 身法 1.0）×（1 + 境界加成 + 功法特效）**。`getOverview` 把战力总数交给主页境界卡，公式与五条提升途径收进「说明 · 主页 · 战力怎么算」；`pages/guide/` 第二节把「练深一门 ×1→×5、多学一门最见效、突破 +6/+14/+24%、特效按段位兑现、换门加成」逐条写清。战力只影响切磋与突破门槛，不参与参悟熟练度，也不减耗气。

**功法特效按段位兑现，不再「练到大成才有」。** `EFFECT_TIER_SCALE = [0, 0.25, 0.5, 0.75, 1, 1]`：未入门 0、入门 1/4、小成 1/2、大成 3/4、圆满起满额。旧规则把 19 门功法的特效全部压在大成（6000 熟练度）之后，中前期练什么都像白练——那正是「练了感觉不到」的来源。图鉴的「练成之后」逐行写清属性、本门特效（当前几成）、代价与气海。
- `pages/guide/` 是集中式规则页，共 12 节：目录 chip（点击滚动直达）+ 单节折叠 + 一键全展开，前 11 节列出资源、挂机、战力、熟练度、评级、小游戏、连 S 叠倍率、突破、切磋、称号、存档、成就榜单与离线时间规则的全部数值，第十二节是由术语词典生成的「名词速查」。主页宫格「玩法说明」、说明页页脚与人物页设置区都有入口。
- 面向玩家的页面文案不出现实现细节（数据化、换皮、SDK、RLS 等），这类说明只留在 README 与源码注释里。跨页复用的文案统一放 `data/copy.js`，术语解释统一放 `components/term/`（详见「文案规范与信息架构」）。

## 登录与账号隔离

- 主入口 **微信一键登录**：`wx.login` 取 code + `wx.getAccountInfoSync().miniProgram.appId`（运行时真实 appid，不硬编码），调用 `cloud.auth.signInWithWechat(code, appid)`；后端换会话，前端不碰 AppSecret、不自存 openid。
- 兜底入口 **邮箱验证码**（发送 → 验证，无密码），默认折叠。两种方式共用 `app.js` 的 `afterLogin()`，身份隔离完全由会话 uid 决定。
- 冷启动 `app.js` 检查会话：**只有 `signed-out` 才跳登录页**；网络错误 / 云端读取失败一律保留本机进度离线可玩，显示提示并监听网络恢复自动重试。
- 云端表 `canwu_saves`：`owner_id TEXT NOT NULL DEFAULT auth.uid() UNIQUE`、`payload JSONB`、`version BIGINT DEFAULT 0`、`updated_at TIMESTAMPTZ`。归属由数据库填充，前端不传用户 ID。
- 已开启 RLS，SELECT / INSERT / UPDATE / DELETE 四条策略均限定 `owner_id = auth.uid()`；读写前先过 `cloud.auth.getSession()` 认证门。
- `version` 与 `updated_at` 由 **BEFORE UPDATE trigger 在服务端维护**（验证过前端伪造的 `updated_at` 会被 `now()` 覆盖），客户端不能改表刷时间或绕过版本。
- 榜单表 `canwu_scores`：`SELECT` 对所有人开放，`INSERT/UPDATE/DELETE` 仅本人；同样有服务端 `updated_at` trigger。写入时不传 `owner_id`。

## 发布前的合规件（代码层）

上线的门槛有一半不在玩法里。这一节记代码侧已经做完的合规件与兜底项，和它们各自守住的坑。前四件管「能不能过审」，后四件管「发出去之后还改得动、查得到」。

- **隐私授权**：`app.json` 打开 `__usePrivacyCheck__`，`utils/privacy.js` 是唯一入口（`requirePrivacyAuthorize` → 官方授权框）。约定是「**剪贴板与昵称输入一律先过 `privacy.guard`**」——未授权时 `wx.setClipboardData` / `input type="nickname"` 会静默失败（errno 112），症状与「页面漏注册」同款：按钮能点、什么都不发生。所以生命值最高的两页（人物页 4 处剪贴板、切磋页 2 处）逐处包了守卫，`verify` 按「调用数 ≤ 守卫数」核对，不靠人记。被拒时**存档码仍然显示出来**可长按手动复制，功能不因拒绝而丢。
- **游客态**：登录页多一颗「先不登录 · 本机玩」。实现在 `app.js` 的 `enterGuest()` / `leaveGuest()`，标记落盘（`canwu_guest_v1`），冷启动直接进主页——不落盘的话每次被杀进程都要重新点一遍，等于没有这个入口。`store.setGuest(true)` 会把云端这一层整体停用（不排期、不报错、清 pending），否则游客每改一次存档就发一次必然失败的请求，同步条会把「没登录」说成「连不上云端」。人物页在游客态显示「本机进度 · 未登录」+「登录以同步」。
- **隐私与协议**：`data/help.js` 的 `TOPICS.privacy`（5 节：拿到什么 / 用来做什么 / 存在哪里 / 你能怎么处理 / 用户协议），复用说明页容器，登录页底部与人物页设置区各一个入口。主题带 `navTitle`，导航标题就是「隐私与协议」，不拼「· 说明」后缀。条文只写代码里真做的事——微信登录不读头像昵称、剪贴板只在你点复制时读写、云端按账号隔离。
- **客服与版本号**：人物页设置区有 `open-type="contact"` 的「联络执事」（客服消息在后台开通即可用），并显示 `wx.getAccountInfoSync().miniProgram.version`（工具里为空则报「开发版」）。
- **更新提示**：`app.js` 的 `checkUpdate()` 走 `wx.getUpdateManager`，新版下载完弹一次「重开 / 稍后」，**不自动重启**——自动重启会打断正在打的一局。没有这段代码，审核通过后玩家可能长期停在旧版上，你还以为改生效了。
- **错误兜底**：`onError` / `onUnhandledRejection` / `onPageNotFound` 三处都收进 `recordError()`（`console.error` 带 `[参悟][kind]` 前缀 + 内存里留最近 20 条）。未捕获异常在小程序里不会崩进程，只会安静地少做一件事，症状和「点了没反应」一样；`onPageNotFound` 额外 `reLaunch` 回主页，专门兜旧版分享卡与改名的手滑链接——静态校验守的是「跳转目标必须是注册页」，这条守的是线上已经发生的。
- **打包排除**：`project.config.json` 的 `packOptions.ignore` 补掉 `docs/`、`*.md`、`eslint.config.js`、`package-lock.json`，`sitemap.json` 的 `desc` 从模板文案换成《参悟》自己的。文档与工具链不该计入安装包体积。

**后台还要做**（代码改不了）：request 合法域名加 `https://mp-api.app.workbuddy.host`；《用户隐私保护指引》按上面四项声明；类目与「是否构成游戏」的判定。

## 存档可靠性

- 每次 `commit` **同步写本机** `canwu_save_v1` 并留下 `canwu_pending_v1` 标记；云端确认成功后才清除。切后台被冻结、断网、写失败都不会静默丢档——下次启动 `hydrate()` 先补写本地改动再读云端。
- 写云端带**乐观锁**：`.update(...).eq('id', rowId).eq('version', expectedVersion)`，0 行命中会再查一次区分「版本被别的设备推进」与「行被删」。冲突时不自动覆盖，弹窗让玩家选「用云端那份」或「用本机覆盖」。
- `rowId` 失效、插入撞唯一约束（23505）、行被移除等路径都有重新对齐 / 重建逻辑，不会卡在英文报错上。
- 关键操作（突破、结算、领奖、改名、买功法、导入、切磋）走 `store.commitCritical()` 跳过 1.2 秒防抖立即回写；其余改动沿用防抖，并发 flush 复用同一个在途请求。
- 主页与人物页有**同步状态条**（只在异常时出现，正常状态不占文字）：待同步 / 失败原因 / 冲突，点一下可手动重试。
- 每日份例与离线收益使用单调时钟：时间回拨不会重开份例或倒着补收益。**彻底防作弊仍需服务端时间裁定，当前版本未接**。
- `SAVE_VERSION = 6`，`migrateState()` 是基于版本的迁移框架；v1–v5 老档（含 `CANWU1:` 存档码导入）自动升级，补 `records`、`sCombo`（每门功法的连 S 层数）并统一版本号（v1→v2 当年只为补头像路径，该字段已退役，这一步不再占版本号）。v5 的 `sStreak` 是旧三连晋级的计数，与连击层数含义不同：不换算、直接摘掉，一律从 0 重数。
- 云端无档时建新档，**本机旧进度不会自动上云**；要保留就先在人物页导出存档码，登录后导入。退出登录清本机缓存，云端保留。

## 页面信息架构与「说明」页

**为什么改。** 改版前的 tabBar 是「洞府 / 功法 / 论道 / 道牒」：把低频的**论道**放在黄金 tab 位，最高频的**修炼**却只藏在洞府页一个吸底按钮后面，主次是倒的；每个页面又都是「眉标 + 大标题 + 一句说明 + 多个区块小注 + 提示 + 页脚口号 + 术语角标」，洞府页一展开战力明细就是 6 行长文——等于把说明书印在脸上。参考的国风版式只留「标签 + 数值 + 按钮」，解释靠点进去展开，这才是主页面该有的信息密度。

**三个 tab，功法是唯一入口**（`data/navigation.js` 的 `TAB_ORDER` 是唯一真源，`scripts/verify.js` 与 `app.json` 逐项核对）：

| tab | 页面 | 首屏只有 | 说明主题 |
| --- | --- | --- | --- |
| 主页 | `pages/index/` | 境界大卡（境界 / 进度 / 战力 / 称号）、一行提示、可领份例、六宫格、吸底「参悟 · 某门」 | `home` |
| 功法 | `pages/skills/` | 「已持玉简 / 藏经阁」两分区。已持按「离下一段最近 + 能拿全额收益」三段排（与主页推荐同源），紧凑三行卡片（五字正名 + 品阶 / 段位·属性一行 / 阶段色进度 / 定宽动作按钮）；藏经阁装**全部未习得**功法，卡片第三行写代价或获取途径 | `skills` |
| 人物 | `pages/profile/` | 身份卡、属性格、当前称号、境界突破条件清单、`突破境界` / `背包` | `profile` |

**一趟参悟只有两屏：参悟页 → 局内**。曾经中间还夹着一层「功法详情」子页（`pages/cultivate/`），从功法卡片或主页吸底进去，看清这一门、点「开始参悟」，才到参悟准备屏——三屏才开一局，而两屏里装的是同一批东西：印、品阶、修为、上一局、规则、难度。详情页独有的只有「来历 + 风味 + 练成之后」三段正文，为这三段多按一次屏幕不划算。

合并的做法是**把详情页那几段搬进参悟准备屏，成为开局卡最后一块默认折起的「本门要略」**（`onToggleArchive`），换门也留在页内（`onToggleSwap` 弹一层已持功法，选完 `redirectTo` 整页重开——难度、规则、盘面全都跟着功法走，原地改一半只会留下半套状态）。于是：

- 主页吸底「参悟 · 某门」与功法页的卡片、卡片右侧「参悟」按钮，三处都直达 `pages/practice?skillId=`；
- 参悟页认 `?skillId`：点哪一门就是哪一门，未习得就在 `onLoad` 里说一句并退回，不留空页；
- 导航标题固定「参悟」（`PAGE_TITLES`），功法名交给卡片里的 h1——冲关局没有功法，标题写功法名反而错；
- 「本门要略」折起只占一行（`来历与所得 ›`），不点开时首屏仍是「一行规则 + 难度档 + 本门新法」；
- 说明只剩一本：这一门的盘面规则（`topic=practice`，按功法现拼），页尾的「本页说明」也在同一套里。

**主页只做导航中枢**：3 列六宫格（3 × 2 排满，不再有半行），**六格各进各的页面，不再借道别的 tab**——仙门切磋 → `battle`、秘境探索 → `secret`、战力仙榜 → `board`、称号簿 → `titles`、修行日志 → `log`、玩法说明 → `guide`。上一版图省事，藏经阁指向功法 tab、称号簿指向人物页折叠区、仙榜指向论道 `?focus=board`，玩家点进去看到的是另一页，等于「子页没做」。现在这六张都是真页面，数据由引擎给，**返回交给原生导航栏**。**秘境探索原本是切磋页里的第二段列表**：同一屏两段、两套按钮、两套结算，首屏得先分清「哪一段是同门」才点得对，而这两件事的目的根本不同——切磋为的是掉功法，秘境为的是攒灵力与灵石。拆页后两边谁也不复制对方的列表，**也不再在页尾互开一个门**——六宫格就是唯一入口，回上一页交给原生返回箭头；页尾只留「本页说明 / 完整规则」。结算卡抽成 `components/duel-result` 一份。`data/navigation.js` 的 `TILES` 是唯一真源，`scripts/verify.js` 核对目标页存在，`tests/layout.test.js` 额外断言**六格不重复、且没有一格指向 tabBar 里的页面**。仙门切磋与藏经阁都曾从 tab 降下来，全项目 `switchTab(battle)` / `switchTab(shop)` 已改成 `navigateTo`。

**藏经阁为什么不再是独立页**：它和功法页的「未习得」装的是同一批数据。两页都列没拿到的功法，玩家在两边找同一门；而功法页那一栏点开还有全本图鉴，弹窗底下又挂一个「去藏经阁」跳走——看起来是两个页面，实际是一次查询拆成了两跳。合并时没有「搬页面」，而是把功法页的第二个分区直接升级：它现在装**全部**未习得功法（12 门可换 + 4 门切磋首胜/机缘，19 门里 shop 来源 12、battle 来源 4、初始 3），可换的给「换取」按钮、就地扣资源，不可换的写获取途径。**如果只放可兑换的 12 门，那 4 门的图鉴与路径就没有别处可看了**——这是合并时最容易漏的一刀。

**解释只有一个入口**：每页页尾一行「说明」→ `pages/help/help?topic=...`，内容全部取自 `data/help.js` 的 `TOPICS`，分节**默认全折叠**，点哪节展开哪节；底部「名词速查」由 `copy.TERMS` 同源生成，`修行指南` 是完整手册、`说明` 只讲这一页。搬走的文字有：战力公式与 6 行明细、份例 / 闭关 / 境界说明、品阶与藏经阁解释、称号与突破条件说明、日志与诸界的介绍、各页页头副标题与页脚口号、散落的术语角标（只保留局内准备页与人物设置等 7 处就地角标）。`pages/practice/` 更进一步：整篇规则搬去了「说明」的分类主题（`topic=practice`，按功法现拼），准备页只留一行「本局规则」+ 难度条，局内只留两行速记——规则分三层，每层只讲一次。

**视觉：墨底一支金。** `styles/immortal.wxss` 只有四条规则：一种底色（墨 `#0c1311`）、一种正文（暖白 `#ece5d8`）、**一种强调（旧金 `#cfae6d`）**、一种状态色（青玉，只标进度与「进行中」）。强调色只给数字、当前项和一处主操作；其余全部用 1rpx 描边与字重区分。

排版不再靠字距撑层级：页头去掉手写空格与衬线体，标题 30rpx/600、面板标签 22rpx 加 4rpx 字距、大数字交给 `--fs-h2`；宫格与属性格用整块细线格（一个外框 + 发丝分隔），不再是六个各带边框的小盒；卡片成组出现（`.imm-list` + `.imm-row`）。按钮只有两种：金色实心（一处主操作）与细描边（其余），高度锁 88 / 64rpx、`line-height: 1`——微信按钮默认行高 2.55 会把并排两枚撑成不一样高，这是上一版「按钮布局不对」的直接原因。禁用态改成细描边灰字，不再是一块发暗的金。实心按钮的底色一律写在 `background-color` 上，渐变只挂在 `background-image`：两者合并成 `background` 简写时，只要某个色标变量在该环境解析失败，整条声明就会被判无效，按钮退化成「一行没有底色的字」——这是登录页一度整页变纯文字的根因。同理，登录页的底色直接取 `--c-imm-*`，不取 `.pg--imm` 重定义过的 `--c-bg`，避免映射层没贴住时退回浅米底 + 深色字。
`.pg--imm` 局部重定义 `--c-*`（含 `--c-primary / --c-gold / --c-surface-ink`），让 `.card` / `.btn` / `.tag` 等旧基础层自动落到墨金体系，不必逐组件写暗色分支。`theme.json` 的导航栏与 tabBar 在明暗两套里都取同一组值，tabBar 图标重生成成灰青 / 金色，否则浅色系统下会拼出一条米白横条。
`scripts/verify.js` 1338 项里守着三页 IA、**`pages/` 目录与 `app.json.pages` 双向一致**（只查「注册了但文件缺失」会漏掉「文件都在但忘了注册」——点了静默失败）、以及「代码里写死的每个跳转目标都是注册页面」、说明真源、默认折叠、六宫格目标存在与「解释不许回首页」；`tests/layout.test.js` 84 项里守着页面骨架（导航只留原生一层：不许页内返回箭头与第二个标题）、弹窗主次、禁用样式、六宫格独立性，以及**榜单只在战力仙榜页出现**——仙门切磋页不再复述前十，否则两处都能打、两处都要刷新。

## 功法命名规范

**问题不是「名字不好听」，是没有一条能执行的规则。** 改版前 13 门功法里 `刀法·开锋斩桩诀`（旧「基础刀法」）与 `心法·吐纳周天诀`（旧「吐纳诀」）没有前缀；带前缀的又各写各的：`剑法·截锋断岳诀`（旧「剑诀·断岳」）前缀是「剑诀」而类别是「剑法」，`御灵·并蒂牵线引`（旧「灵契·并蒂引」）前缀是「灵契」而类别是「御灵」；正名从 2 到 4 字不等，还混着「入门 / 小」这类等级词。

**第二轮（2026-11）：三字正名整批退役。** 前缀统一之后还剩一个更硬的问题——三个字说不清盘上做什么。「三秀诀」「叠元诀」「摘魁诀」都是查不到出处的生词，列表扫过去只看得见「这也是一门功课」。十九门于是统一改成五字，走「**物件 + 动作 + 体裁字**」：三秀连收诀＝三株灵苗连成一线收取，同数叠元诀＝两枚同数相叠成更高一元，一眼摘魁诀＝一批数里一眼挑出最大的那个。原先「三字」的唯一理由是卡片宽度，实测五字仍是一行（`.sk-name` 单行截断，320px 上也放得下），字数就让给了可读性。`NAME_RULE.titleMin` 抬到 4、`titleMax` 6：四字是下限（再少就只剩一个生词），六字是卡片一行的上限。旧三字名全部进 `scripts/verify.js` 的 `LEGACY_SKILL_NAMES`；三字还有第二道闸——`validateNames()` 逐门读 `SKILLS`，短于 `titleMin` 直接红，新门即便不撞旧名也带不回「看不懂」这个问题。

**规则写进 `data/skills.js` 的 `NAME_RULE`，`validateNames()` 逐门校验**：前缀严格等于 `type`（不自造类别词）；分隔符全表只用间隔号 `·` 且只出现一次；正名四到六字（现全表五字），末字用体裁字（诀 / 步 / 引）且**同族必须同体裁字**；不写「入门 / 基础 / 初级 / 小 / 大」等品阶词，不与参悟方式名、玩法名重复。体裁字白名单只留在用的字——撤掉符箓一族、把「凝露方」改成「叠纹凝露诀」之后，「符 / 阵 / 方」三个字就没有任何功法在用了，`validateNames()` 会反向检查「白名单里有没有谁一整个字没人用」，逼着一起收窄，否则「XX·YY阵」这类名字会蒙混过关。改名最容易漏的不是 `name` 而是 `effect.text` 的门面词（「叠元：对战战力 +5%」），`verify` 8b-2 因此改成硬规则：**门面词必须出现在这一门的正名里**，只留「刀意」「灯势」两个意象词例外（它们说的是这一门的气，不是动作），白名单同样反向自检。三层命名各管一件事：功法名 = 类别·正名（这一门叫什么），参悟方式名 = 这一门具体在练什么（循光斩桩 / 勘位辨禁），玩法名 = 盘面上的动作（顺光扫斩 / 数格辨禁）。十九门正式名：`刀法·开锋斩桩诀`、`阵法·点灯破阵诀`、`心法·吐纳周天诀`、`心法·静心记诵诀`、`身法·踏云连环步`、`阵法·循数勘禁诀`、`阵法·五灯相生诀`、`水术·叠纹凝露诀`、`剑法·截锋断岳诀`、`心法·太虚翻卦诀`、`御灵·并蒂牵线引`、`土术·万石成岳诀`、`灵植·三秀连收诀`、`术数·九宫排数诀`、`合术·同数叠元诀`、`目术·扫目逐数诀`、`机巧·让主出阵诀`、`挪移·石箱归位诀`、`辨术·一眼摘魁诀`。改名只动 `name`，`id` 全部不变，存档 / 纪录 / 连 S 计数 / 战力码不受影响；对白可用简称，正式名只认 `SKILLS[].name`。

## 功法图鉴：未习得也能查全本

**靠「看不了」吊胃口是错的。** 黑箱只给一个「未得」标签和一句「首胜 XX 掉落」，玩家连这一门是划刀、推阵还是数格子都不知道，既估不出值不值得练，也不知道该往哪使劲——悬念没有变成动力，变成了放弃。正确的留白是「看得见、练不了」：规则、盘面符号、阶段新法、练成收益、习得路径全部公开，只锁「开练」与熟练度收益。

引擎新增 `getSkillDetail(state, id)`，未习得同样返回完整内容：`guide`（目标 / 步骤 / 盘面术语 / 计分 / 要诀）、`gainLines`（属性 / 倍率 / 大成特效，并写明何时生效）、`stageRules`（本门新法与解锁阶段）、`unlockInfo()`（路径 + 进度 + 可执行动作：藏经阁给价格与资源差额、首胜给对手战力对比、机缘给下一步）。页面不自己拼文案，避免参悟页与功法页各写一份。功法页卡片不再压灰，点开即图鉴弹窗；卡片右侧按钮按状态给「修炼 / 兑换 / 详情」，未习得也能一路读清楚再决定。

## 页面规范与设计令牌

**单一真源。** `styles/tokens.wxss` 定义全部语义色（`--c-*`）、字号阶梯（`--fs-*`）、4rpx 间距栅格（`--sp-*`）、圆角 / 阴影 / 层级 / 触控 / 动效 / 安全区；`app.wxss` 只写跨页面复用的类，页面 `.wxss` 只写布局。暗色在令牌表里重定义一次 `--c-*`，页面不再各写一遍 `@media` —— 改版前 5 个页面的私有样式写死浅色值，暗色下会出现浅底浅字（登录页 json 还写死了浅色导航栏，会变白条），现已全部消除。`--c-nav / --c-tab / --c-tab-text / --c-tab-active` 必须与 `theme.json` 的 `@` 变量同值，`scripts/verify.js` 逐项核对。

**页面骨架。** 四个 tab 与所有内容子页根节点统一 `.pg.pg--imm`（登录页是唯一品牌页例外 `.login-page`）；**导航只有原生一层**：返回箭头与页面标题都由小程序导航栏承担，页面里不再画 `‹` 与第二个标题；「说明」这类低频入口沉到页尾一行小字（`.pg__foot`），顶部不再为它单独占一行；区块用 `.imm-panel`（面板）、`.imm-list` + `.imm-row`（成组列表）、`.help-sec`（折叠分节）；页脚口号全部删除，只留指南页一行品牌字。**同一屏上页面名只出现一次**：tab 页的 `navigationBarTitleText` 一律留空（页名由底部 tabBar 承担，顶部再写一遍就是同一行字出现两次，`app.json` 的全局标题也留空以免漏写时回落），子页才写「仙门切磋 / 参悟 / 登录 / 修行指南 / 说明 / 修行日志 / 藏经阁 / 战力仙榜 / 称号簿」；参悟页的局内卡片同理不再重复「参 悟」，只报这一局玩的玩法名。配色交给主题变量（明暗同值）。旧骨架 `.pg__head`（眉标 + 标题 + 说明三行）是双层导航的来源，已随改版删除；`.pg__foot` 仍留给需要一行页脚文字的页面。

**尺度与反馈。** 页面左右留白 `--page-x`(28rpx)，卡片内距 28rpx、卡片间距 24rpx、区块间距 40rpx；正文 28rpx、辅助 24rpx、角标下限 22rpx；主操作热区 88rpx、次操作 76rpx、卡片内紧凑操作 68rpx；层级只用 0 / 40 / 80 / 90 / 100；所有吸底条与页面底部带 `env(safe-area-inset-bottom)`。加载 / 空 / 错误统一 `.state` 占位（主页、功法、仙门切磋、人物都接了），不再白屏或各用普通卡片；可点 `view` 统一 `class="… pressable" hover-class="pressable--on"`，危险操作只有一支 `.imm-btn--danger`。

**白名单例外。** `styles/scene.wxss` 与 `pages/practice/practice.wxss` 的**盘面**色板由 `minigames/theme.js` / `data/visual.js` 按功法注入（`--acc / --soft / --ink / --glow / --well / --deep`），必须固定、不随明暗漂移。参悟页的边界是「**墨玉台、暖玉牌**」：可以摸、可以划的那块（`.grid / .klotski / .ring-area / .orbit / .scroll / .pad`）是一方玉局 —— 台取按功法族注入的 `--well`，牌取 19 门共用的 `--jade` 一副；其余全部（准备页、HUD、判定横幅、结算弹层、难度档）是墨，一律取 `--c-imm-*`。所以 `practice.wxss` 的 `.pg` 把整组 `--c-*` 映到 `--c-imm-*`（与 `.pg--imm` 同值），并无条件深色——本页已删掉 `@media (prefers-color-scheme)`，系统切深色时页面与盘面都不变色。`scripts/verify.js` 与 `tests/layout.test.js` 用 1392 项静态检查、84 项布局断言守住上述约定。

## 文案规范与信息架构

**文案单一真源。** `data/copy.js` 收拢跨页复用的玩家文案：加载与空态、通用按钮、区块标题，以及 22 条术语词典；`data/help.js` 收拢解释性长文；`data/navigation.js` 收拢导航标签。页面 WXML 一律写 `{{copy.xxx}}`，不许再抄字面量。改版前「打开一局小游戏」有「开始参悟 / 去参悟 / 就练这门 / 去练一局 / 回去修炼」五种写法，四个 tab 页的 loading 各拟一次人（推演气机 / 翻检藏经阁 / 整理论道台 / 展开道牒），品牌口号在 6 个页面重复。现在**同一动作一个说法、同一状态一句白话**；「参悟」与「修炼」也不再当同义词混用——修炼是去练功台，参悟是在练功台打一局；页面首屏只显示数据标签，解释一律进说明页。`scripts/verify.js` 有共享文案黑名单，并会拦截「解释性文字回到 tab 页首屏」。

**黑话首次出现即可查。** 新增 `components/term/`（虚线下划线 + 小圆问号，点击弹一句大白话），解释统一取 `copy.TERMS`，覆盖份例、闭关收获、蓄力停区、战力码、镜像、道号与道相、连 S 倍率、本门新法、功法图鉴、息等 22 个词；深色卡上用 `tone="ink"` 换配色。修行指南第十二节「名词速查」由同一份词典按「成长 / 页面 / 对战 / 玩法」分组生成 —— 解释只写一遍，页面弹层与指南不会各说各话。静态校验核对词典字段、`term-key` 引用以及用了 `<term>` 的页面是否注册了组件。

**信息架构按「先做一件事」排。** 主页首屏只留境界大卡、一行提示、六宫格与吸底主按钮（全页只留一个 `onQuickPractice`）；今日之课长卡、战力明细、快升段功法列表、境界突破长卡、日志与诸界全部撤走——分别去说明页、功法页、人物页、日志子页。功法页改成「已持玉简 / 藏经阁」两分区（后者并掉了原来的独立藏经阁页），已持按「离下一段最近」排（与主页推荐同源）、藏经阁按「换得起优先」排（兑换顺序，不是推荐顺序），卡片只留名字 + 数值 + 一个动作，规则与收益进图鉴弹窗；人物页只留一行「称号簿 ›」通向独立页，成就、背包 / 战力码、设置、诸界收成 4 个默认折叠的分节；仙门切磋页的战力码仍折叠，秘境探索单独一页，日志与诸界另开子页。修行指南按**新手阅读流**排（怎么变强 → 离线吐纳之规 → 灵力与灵石 → 战力从哪来 → 熟练度与境界 → 参悟与盘面 → 连 S 叠倍率 → 切磋与战力码 → 称号与道牒 → 存档与换设备 → 成就与榜单 → 名词速查）：先搞懂挂机保底，再知道资源是什么，然后才学主动玩法。**目录 chip 直达 + 单节手风琴 + 一键全展开 / 全收起**，展开态只有 `sections[i].open` 一套状态——改版前全局展开与单节展开并存，全局展开着点某节标题会「点了没反应」。三节带「去功法页 / 去切磋」的下一步按钮（`tabSkills` 会顺带指定落在哪个分区），名词速查开头放一个真的「?」示范（`DEMO_TERM` 由校验守住），说明页则按主题分节折叠。区块标题一律说清里面是什么，不用「近况」「就差一点」这类含糊词。

品牌标语也只剩一份（`BRAND.slogan`）：人物页身份卡、分享文案与卡片图都取它；资源与收益的单位写法由 `formatCost / formatGain` 统一，两个函数都接进了真实页面，不是注释里的摆设；进度只有「X / Y」一种写法，直接写在 WXML 里由版式断言挡住无空格版本。

**可回归。** `scripts/verify.js` 1338 项里包含文案黑名单、术语词典完整性、`term-key` 引用与组件注册；顺手修了一个老漏洞：组件四件套检查原来只认绝对路径，页面 json 普遍写的 `../../components/...` 相对路径从未被验过。`tests/layout.test.js` 84 项里新增「文案真源」「术语同源」「信息架构主次」三组断言。

## 界面与按钮约定

- **主操作常驻拇指区**：主页底部有 `sticky-bar` 吸底主按钮「参悟 · 推荐功法」，`.pg--with-bar` 预留底部空间；参悟页把「开始参悟」放在准备屏底部的吸底条上。**两处措辞分工明确：主页只负责把人送到那一门的参悟页，不替人开局；难度档、规则速记、上一局评价、这一门的来历都在那一屏。**子页入口全部走主页六宫格，页面底部不再堆与 tabBar 重复的跳转按钮。
- **弹窗统一「次操作在左、主操作在右」**：取消 / 关闭 / 次要动作一律 `btn--plain` 在左，`btn--primary` / `btn--gold` 在右（参悟页与图鉴的主按钮由 `wx:if` / `wx:elif` 互斥渲染，也排在最右）。
- **危险操作降权但明示**：重置存档、退出登录用 `imm-btn--danger` 警示样式，与常规操作之间加分隔线与提示文字，均为 `wx.showModal` 二次确认。分享类次要动作降为 `.text-link` 文字链。
- **触控热区**：`.btn` / `.btn--small` / `.text-link` 分别取 `--touch`(88rpx) / `--touch-sm`(76rpx) / `--touch-xs`(68rpx)；纯文字点击入口一律补 `.text-link`。`.btn-row` 自带 20rpx 上边距会覆盖 `.mt12` / `.mt16`，需更紧时用 `.btn-row--tight`（`--mid` / `--flush` 无人使用，已删）。
- **减少重复整宽按钮**：切磋与秘境的挑战按钮改为行内小号按钮（`imm-btn--ghost imm-btn--sm`），不再各占一整行；诸界在日志页与人物页默认折叠，主页不再放这块。
- **局内操作分区**：参悟页「收功」是退出操作，放在局内 HUD 右上角 `.hud__quit`（屏幕上方、离拇指热区远）并加「这一局作废、连 S 归零」确认；撤销 / 提示留在底部 `sticky-bar--tools`。
- **吸底条只在有操作时出现**：`barMode` 三种——`start`（准备页：暂且退去 + 开始参悟）、`tools`（局内确实有撤销 / 提示时）、`done`（本局已终、盘面还留在屏上：上局战绩 / 返回功法 / 再参一局）；其余玩法不挂条、`.pg--with-bar` 也不加留白——否则多数玩法会白留一截底部空白，还把盘面挤出屏幕。
- **局内不重复功法头卡**：进入参悟后 `.pr-head`（标题 / 描述 / 熟练度条）不再渲染，技法名与难度压进 HUD 第一行小字，省下的近 380rpx 全部让给盘面。
- **HUD 每个数只说一遍**：`已探 X / Y` 与进度条已经在讲同一件事，目标句就不再写「还剩 N 格」；心神有独立的灯格行，目标句也不再复述。目标句只放「这一局在追什么」——例如探禁的「S 线 25 秒 · 已用 18 秒」。
- **局内评级徽章只在「档位会往上爬」的玩法里出现**：分数型玩法从 C 一路涨上去，摆着有意义；按用时反推档位的探禁，开局那一刻必是 S，摆出来等于告诉玩家「S 已到手」，之后只看它往下掉，所以 `extras.showGradeNow = false`，档位只在结算里给。
- **局内分数不叫「灵石」**：灵石是能换功法的资源，局内那个数是这一局的得分。场次 HUD 原来标「灵石 608」，同一页结算又写「灵石 +3」，两处当场打架；现在 HUD 与结算都叫「得分 / 局内得分」。
- **常驻速记只写恒久规则**：`guides.inline` 是所有阶段共用的那一行，写成「大成后到靶心停一拍」会让未入门的玩家以为每一刀都要停。阶段规则交给盘面上方那行按本局状态显示（`trail.rule`），大圆满同时开双锋与收势时两条一起给，不许只报一条。
- **新法生效范围写在标题右侧**：「本门新法 · 习得后每局生效」一句说透，条目里不再逐条重复；习得是永久的，每局重来的是效果。
- `tests/layout.test.js` 把以上约定固化为 84 项断言（含 WXML 标签配平、事件方法与 js 定义对应、弹窗顺序、热区尺寸、安全区留白、吸底条形态、音效资源齐备、箭头形态与禁反向、视觉标准与演出时序）。

## 音效

局内反馈全部由 `utils/sfx.js` 发声。音源是仓库里的 9 个 wav（`assets/sfx/`，16kHz 单声道，共约 92KB），由 `scripts/gen-sfx.js`（`npm run sfx`）合成——不引外部音频文件，改音色只改合成参数。

第一版反馈「太刺耳、脑子嗡嗡的」，第二版按四条改柔：**只用基频 + 极轻二次分音**（去掉金属泛音）、**全局一阶低通 + 14ms 软起音**（去掉「咔」的瞬态）、**每个音效只留单声部且衰减压到 0.1–0.2 秒**、**峰值 0.52 再乘播放音量 0.26–0.36**。

| 音效 | 触发时机 |
| --- | --- |
| `tap` | 落子、点空、撤销 |
| `hit` / `miss` / `gold` | 浮字 `vm.fx.tone` 的 good / bad / gold |
| `tick` | 倒数三声、用提示 |
| `go` | 起手 |
| `clear` / `settle` / `fail` | 结算 S·A / B·C / F（走火＝没走完；主动收功单独一种卡，不报字母） |

- **判定结果只认浮字**：`vm.fx` 是玩法层唯一统一的判定信号，页面 `render()` 里比对 `fx.key` 有没有变就发声，19 套玩法不用各写一遍；点空这类没有浮字的操作由页面补一声 `tap`。
- **绝不叠加**：判定 / 结算音共用一路声道（`VOICE`），新的一声会掐掉上一声；`pool` 一律为 1，另有同名 `gap`（85–400ms）与全局 `GLOBAL_GAP`（60ms）两层节流。第一版允许 3 路磬声并发，连击时叠成嗡鸣，这一条由 `tests/layout.test.js` 断言守住。
- **静音键不吃音效**：`obeyMuteSwitch = false`。否则 iOS 打开侧边静音开关就整局无声——「怎么没声音」最常见的来源。
- **三档音量**：人物页「设置」折叠区点一下弹出「轻 / 中 / 关」，默认「轻」（再乘 0.75）。落本地存储 `canwu.sfx.level`，兼容旧键 `canwu.sfx.on`；切档会同步改已创建音频实例的音量。页面 `onHide` / `onUnload` 收声，退出去不会接着响。
- 上下文在进参悟页时 `warm()` 预建，第一次落子不用等实例化。

## 玩法说明

20 套玩法（19 门功法 + 突破专用蓄力停区）各有一份「怎么玩」，数据集中在 `data/guides.js`：一句话目标、分步操作、**盘面术语表**、计分方式、诀窍，外加一行局内速记。

- **准备页**：头卡下面就是「怎么玩」卡，**默认收起**（先看功法与熟练度，要规则再点展开）；收起态那一行只写基础操作 + 本门**已解锁**的阶段新法（`STAGE_RULES[].short`），逆诵 / 死门这类还没解锁的不提前出现。
- **选档时说清代价**：难度档下面跟一行「这一档相对入门收紧了什么」（`diffDetail.brief`：`亮起时长 0.66 秒 → 0.49 秒 · 闪烁间隔 0.31 秒 → 0.23 秒`），而不是只给一个 ×1.70。毫秒一律折成秒，判定窗 / 气机收敛这类内部倍率不摆。
- **段位条下面写「下一段给什么」**：直接搬 `world.TIERS[].desc`（`到「小成」：解锁「普通」难度`）。只写「还差 114」等于只给一个数字，练到那步才发现没有好处。
- **局内代价句用阿拉伯数字**：`罚 1.5 息`、`折 1 盏心神`、`罚 3 秒`，与 HUD 的「余 12.3 息」同一套写法；中文数词要在脑子里换算，实时对局里读不起。`tests/layout.test.js` 扫全部 tip 与两处浮字挡住回退。
- **规则要变，在前一轮就说**：逆诵（第 3 轮起）、叠印（第 5 轮起）都是「打到这里突然换规矩」。等那一轮闪起来才提示，玩家第一下已经点下去了，只会觉得「好好记着顺序，凭什么让倒着点」。所以 `memory.js` 在**上一轮结算时**就把「下一轮起逆诵：从末字往前点」写进 `vm.status`，并把轮间停留从 640ms 拉到 1500ms——这句话得留得住人才有用。本轮生效的规则同时挂在 `vm.banner` 上，一直显示到输入结束。`tests/minigames.test.js` 用假时钟断言这句预告确实出现在第 3 轮之前。
- **阶段新法练到手就该能关**：逆诵、死门、收势、禁桩、双锋这些是**改规矩**（改点击方向、多一格不能碰的、要求停一拍），不是给便利，所以在 `STAGE_RULES` 里标 `hard: true`，准备页给一个开关（`state.twists[功法]`，缺省全开，不随存档版本走）。勘位 / 照纹 / 稳基是纯加成，关掉没有任何好处，不给开关——多一个开关只是多一处看不懂。三个玩法（`memory` / `lights` / `click`）都从 `perks.offTwists` 读，关掉就真的不触发；局内不给开关，改规则只能在开局前改。
- **战力是阶梯，别按线性报**：属性 = 功法条目 × 段位系数（0 / 1 / 1.8 / 2.8 / 4 / 5）× 品阶系数，段位不跳战力就一分不动。所以结算不写「本局战力 +N」（大多数局都是 0，等于每局告诉玩家白练），而是摆 `战力 112 · 跨段才涨` 加一行 `距离「金丹」还差 46 战力`；突破局的结算则明写 `战力 45 → 48（+3）`，主页提示也从「还差 46 战力」补成「· 突破后 +3」。`powerDetail(state, realmIndex)` 可指定境界重算，突破后的战力就是拿它算的，不另抄一遍公式。
- **局内**：HUD 的提示文字下面常驻一行术语速记（如刀法·开锋斩桩诀：`顺箭头扫到靶心 · 重斩翻倍 · 斜斩擦角不算 · 单点不判也不罚`），不占按钮、不用弹窗、也不会打断计时；划刀玩法盘面上方还会常驻当前招式名与桩数。**常驻行只写恒久规则**：大成才有的「到靶心停一拍」由盘面上方那一行按本局状态显示，写死在速记里会让未入门的玩家以为每一刀都要停。
- **三秀同收别让玩家多翻译一层**：简介改成「互换相邻两株 → 三株同色采收 → 新苗落下连锁」，仙味词（灵畦 / 采收 / 照畦）后面紧跟白话动作；有歧义的旧称一律改为「无效互换」，并在名词速查里定义清楚（换不出三连、原样换回、少本档罚息；点错格、选中又取消都不算）。代价句原本从 `method.tip` 传进 `vm.hint`，却被 `syncHud()` 冲成纯计数，玩家整局看不到——现在 `costText` 常驻 hint 开头、计数跟在后面，**罚息按本档变**，由 `practiceData.tipFor()` 生成并送进局内与准备页（`method.tip` 只留简单档的兜底值，`tests/rank.test.js` 守着两者相等）。S 线不再写 `620 + 每档 150`，改由 `MATCH_LEVELS` 按本档实测可得分标定为 `1900 / 1750 / 1400 / 1301 / 950`：盘面越难，同样分数越难得，准备页与说明页都明写这句口径，玩法层只读 `p.sLine`。反馈按调性分档：连锁 / 四株齐收走 `gold` 中量震动，无效互换只给 `light` 轻震，不跟着刀法猛震；提示按钮名统一收进 `HINT_LABELS`，三秀同收叫「照畦」。
- **盘面不放字**：早期起手桩挂一个「锋」字，既不指方向也不说明规则，已删掉。现在刀路每桩是一个纯 CSS 箭头（三角 + 短杆，按 `dirAngle` 旋转到八个方向之一），收势桩是圆环靶心；重斩从一格单字变成「更长的金色箭头刀路」，和寻常蓝色刀路一眼分得开。术语表把两者的桩数、分值、寿命、漏了会不会断连击都写清，还加了一条「带桩容差」讲明刀势可以多带两桩。
- **循数勘禁诀的术语也讲透**：`data/guides.js` 用具体例子说明「数字 1 的周围只剩一格没翻开 → 那格必是禁制」，并解释 ✕（禁制）/ ⚑（阵钉）/ 心神 / 不必猜 / 已探进度；局内速记常驻「数字＝周围八格禁制数 · 长按钉阵钉 · 钉数对上点数字格连开」。
- `tests/minigames.test.js` 断言 20 套玩法都有完整说明、术语不缺解释、局内速记不超长、刀法·开锋斩桩诀必须解释「箭头 / 刀路 / 重斩 / 扫到靶心」；另有断言逐桩核对箭头角度与相邻桩方向一致。

**丹道这一门暂时空着。** 「丹道·凝露方」练的是一条竖向河道上采露，一颗丹也没炼——和之前「符箓·照影符」练数格辨禁是同一类错：类别写的是题材，玩法在做另一件事。按「以游戏为准」改归**水术·叠纹凝露诀**（`id` 仍是 `dan`，存档与纪录不动）。丹道留在 `FAMILIES` 里空着，等真有一门「配药、控火、守炉」的功课再填，不为了凑满门类把别人的玩法硬塞给它。

**所有小游戏共用「连 S 叠倍率」。** 单局基础 C 10 / B 15 / A 23 / S 34 点（A 的 22.5、S 的 33.75 都四舍五入进位），走火 F 是 0。只有连续的 S 才叠倍率：第 k 连 S（1 ≤ k ≤ 10）本局 = `round(34 × 1.5^(k-1))`，即 `34 / 51 / 77 / 115 / 172 / 258 / 387 / 581 / 871 / 1307` 点，一轮十连 3853 点；第 11 连起倍率锁死，每局固定 1307。**每局独立从 34 起算一次取整**，不拿上一局的整数接着乘（第 4 连是 115，不是 77 × 1.5 = 116），也不是最后总和再取整；`.5` 一律进位，所以第 3 连 76.5 取 77、A 的 22.5 取 23。全程不断 S 且都打当前关，**84 局**到 99999；全 C 是 10000 局，中途断一次连就得重新叠。

连 S 每门各算各的（`state.sCombo[skillId]`，存档 v6，旧 `sStreak` 不换算、一律从 0 重数）。C / B / A、走火 F、主动收功都把层数归零，下一局 S 重新从 34 点起；收功不进结算但走 `breakCombo()`，堵住「预感拿不到 S 就中途退出保连」。**低档局与连 S 完全解耦**：不叠层、不砍连击收益、已有层数原样保留，回去练手不会清掉高档攒的层数；连击曲线只在「本门最高已解锁档」生效。突破境界的「蓄力停区」不计数，大圆满后熟练度封顶但层数照常累计。准备页是十格小圆点 +「下一局 S 值多少点」，结算页给本局层数、算式与下一局点数，修行指南第七节专讲这套规则。`tests/game.test.js` 守 1～14 连逐局复算、断连与收功、跨功法、低档解耦、84 局毕业与存档迁移；`tests/rank.test.js` 守曲线常量、封顶与逐档折减表。

## 输入形态：为什么刀法·开锋斩桩诀从「点」改成「划」

第一版「追光点击」是 3×3 静态格子里点亮的那一格，本质是打地鼠：手指不移动、没有方向与轨迹，调参数、加特效都改不掉这个体感。

参考过两条路：钢琴键 / 下落式音游的输入仍是「到点按一下」，手指还是点；水果忍者式的划线有轨迹感，且长扫轨迹、重斩后摇、一刀带走数个目标正好就是**刀**的手感。但抛物线飞入的目标 + 刀光拖尾要上 canvas，会在纯 view + setData 的架构里分叉出第二套渲染路径，真机性能与假时钟测试都得重来，所以只借「划」这个输入，不借它的渲染。

现在的「顺光扫斩」把「划」装进现有网格，**不引 canvas**，走的是刀该有的长折线扫掠（见下一节「兵器轴」）：

- 刀光沿 3×3 刀桩依次掠过 3–5 格，形成横劈 / 立劈 / 斜斩 / 游龙四种有方向的刀路；光走到收势桩才起寿命线，玩家可以追着最亮的光头一刀扫过去。
- 每桩一个纯 CSS 箭头指向下一桩（八方向），收势桩是靶心；**盘面没有任何汉字**，方向全靠形状表达，`dirAngle()` 用相邻两桩的行列差算角度。
- **方向只能顺着走**：判定 `matched()` 只认「起手 → 收势」这一个序列，反着划、跳桩、绕一大圈都判劈空；刀势允许多带两桩（刃扫过的面积），但绕盘面乱划一大圈不算。招式名「回锋」随之删掉，免得暗示可以反着来。
- 页面盖一层透明触摸层（`.swipe-layer`），开局量一次格子矩形，相邻 `touchmove` 之间按 10px 插值补全中间格。小程序的 touchmove 目标固定在起手元素，逐格绑事件收不到跨格轨迹；不做插值的话，划快了会漏桩、被误判成劈空。
- **斜向两格只共一个顶点**：从 A 中心直划到 B 中心必然擦过旁边那格的角，整格命中会把「擦角格」补进轨迹，斜斩就被判成劈空。现在 `utils/swipe.js` 的插值只认格子中心内圈（半宽 0.42 格，擦角采样进不来），玩法层 `trimCorners()` 再把真机手抖 / 主动绕角多出的共边邻桩摘掉后判定——直划与绕角算同一刀，绕盘面乱划一大圈仍判劈空；禁桩与虚影不参与摘除，划到照判。起手 / 抬手是静止点，仍用整格命中，按在桩边上也能认出来。
- 玩法层只多收一个 `swipe(path, { hold })`，`vm.cells` 协议、判定浮字、音效、假时钟测试全部沿用，其余 12 套玩法一行未改。`hold` 是抬手前在最后一格停住的毫秒数，页面用「最后一次换格的时刻」算，收势靠它判定。
- **第一层难度只拧数值**（`depth`）：刀路 3→5 桩、光速 343→120ms、后摇 418→142ms、重斩每 5 道→每 3 道、连击门槛 5/10/20→9/18/32、劈空罚 1→2 息、S 门槛 507→912。后摇是唯一能压到高手的旋钮——会读图的人抢在光走完之前就划掉了，光速与寿命只卡新手。
- **第二层挂在熟练度阶段**：大成「收势」（到靶心停一拍再抬手，抢着抬只给半分）、圆满「禁桩」（红叉，划过就断势）、大圆满「双锋」（两条刀路，只有靶心在呼吸的那条是真招）。这三种都算「规则内看错」：断刀势、不罚息；反向 / 跳桩 / 绕圈这类违招才罚息。
- **生成层按 `params.grid / cols` 计算**，不再假设 3×3；默认仍是 9 格 3 列，4×4 在测试里跑通，作为以后扩盘的天花板。

## 兵器轴：为什么这一门是刀，以及剑法先不做

早期把这套长扫轨迹挂在「基础剑法」下，还写成平削 / 直刺 / 一剑中的 / 剑尖不许带桩——**那是剑的文案配了刀的手感**。手指「划」这个输入本身不分兵器（刀势、剑气都有轨迹），区别在于轨迹是什么：

| | 刀（当前启用） | 剑（预留，暂不挂功法） |
| --- | --- | --- |
| 轨迹 | 刃扫过的**面积**：长折线为主 | 光走的**点线**：短直线为主 |
| 招式 | 3–5 桩，折线多、允许大转弯 | 2–4 桩，折线少 |
| 判定 | 只认正向，容许多带 2 桩（刀势连贯） | 最多带 1 桩（抗抖） |
| 节奏 | 起手沉、后摇长、余势不断 | 光快、后摇短、点到靶心即收 |
| 称谓 | 横劈 / 立劈 / 斜斩 / 游龙、一刀斩中、劈空 | 平削 / 直刺 / 斜挑 / 绕指、一剑中的、刺偏 |

**这一版先只做刀法**：初始功法改名「刀法·开锋斩桩诀」，`weapon: 'dao'` 是唯一启用的 profile；`sword` profile 与「剑法·截锋断岳诀」仍留在数据里，但剑法不做点刺式输入、也不新增功法。长扫、重后摇、连扫数桩这套语汇本来就是刀，与其拿名字去补机制，不如让名实先对齐；将来真做剑法时补一个点刺输入适配器即可，共用同一套 `create(ctx)` 与结算。

`data/weapons.js` 是第五根轴（类型 → 玩什么、**兵器 → 怎么动**、品阶 → 收益、熟练度 → 难度、境界 → 上限）。两份 profile 管轨迹长度、折线概率、光速、判定容差、后摇、评级缩放、招式名与全部浮字称谓。`minigames/click.js` 只读 `ctx.params.weapon`，**不硬编码任何兵器称谓**；`buildParams` 原样透传，没标兵器时回落到当前启用的 `dao`。主题表只管配色与本门 banner，不再覆写命中 / 失手浮字——否则刀法沿用剑法主题时会说出「一剑中的」。

**再加一门刀法变体只要三步**：① `data/practice.js` 新增 method，`game: 'click'` + `params.weapon: 'dao'`；② `minigames/theme.js` 配一门刀主题；③ `data/guides.js` 补一份说明。玩法模块、页面、结算、音效、假时钟测试一行不用改。

`tests/minigames.test.js` 用 `weapon: 'sword'` 与 `weapon: 'dao'` 把同一套引擎各跑一局，断言招式明显更长、招式名与命中浮字全换、剑势槽变刀势槽；另有一条断言扫过刀法全部可见文案（招式名、浮字、说明、命名、主题）确保不混进剑字，反过来也守住预留的剑 profile 零刀字。`sword` profile 目前**未挂任何功法**——把「分得出来」变成可回归的事实，而不是提前做半套剑法。

## 刀法的难度：数值挂档位，规则挂阶段

通用难度表走 `buildParams(method, diffKey)`：节奏类（含判定窗 `window` 与刀光寿命 `life`）乘 `pace`、数量类乘 `goal`、时限乘 `TIME_LEVELS`；`speed` 方向相反，除以 `pace`。曾经另有一根 `windowPace`（2.34 倍）只管 `life`，已并回 `pace`（1.69 倍）——「窗口每短一成，容错掉的不是一成」，那一档把扫斩变成了纯手速活；那个字段与空数组都删掉了，不许留一列没人读的数。但刀法的 `params` 里只有 `life` 落在这些键上，盘面尺寸是刻意不缩放的——所以五档真正发力的地方，是 `minigames/click.js` 读 `depth` 与 `perks.tier` 的那几行。

**第一层：档位只拧数值。**

| 档位 | 刀路 | 光速/桩 | 后摇 | 重斩 | 连击门槛 | 劈空 | S 门槛 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 简单 | 3 桩 | 343ms | 418ms | 每 5 道 | 5 / 10 / 20 | −1 息 | 507 |
| 普通 | 3 桩 | 217ms | 264ms | 每 5 道 | 6 / 12 / 24 | −1 息 | 608 |
| 困难 | 4 桩 | 150ms | 181ms | 每 4 道 | 7 / 14 / 28 | −1 息 | 709 |
| 极难 | 4 桩 | 132ms | 158ms | 每 4 道 | 8 / 16 / 30 | −2 息 | 810 |
| 绝境 | 5 桩 | 120ms | 142ms | 每 3 道 | 9 / 18 / 32 | −2 息 | 912 |

**低档缓入**：光速与后摇不是从档位线性起算，而是先乘一个随档位迅速收回的系数（`EASE_STEP = 2.2 / 1.45 / 1.08 / 1.02 / 1`、`EASE_GAP = 2.2 / 1.45 / 1.08 / 1.02 / 1`）。简单档的 156ms/桩直接抬到 **343ms**——3 桩要走 0.7 秒才亮完，每一步该往哪拐都看得清；后摇同步从 190ms 放到 418ms，斩完有一拍实打实的喘息。绝境档仍是 120ms / 142ms，一格未松。入门档是「教学」，高档才是「压力」，中间三档平滑过渡。

**评级门槛按实际得分重标**：旧门槛（155 / 68 / 22，即简单档 S 要 3139 分）是按「每秒划 4 刀」的机器人配的——15 息内要打 157 刀，人力根本不可能，正常速度玩下来永远停在 C，玩家只能靠抢在光头到达前盲划去刷分，这才是「明明调慢了还是觉得被催」的根源。新门槛按这一档真正打得出的分数反向推：简单档光走完 686ms、后摇 418ms，一局 12–14 刀，连击不断打下来 530 上下，所以 **S 507、A 385、B 203**——正常节奏就是 A，S 要的是连击不断、重斩全接。`tests/minigames.test.js` 里有一条断言整局不抢划跑完，确保简单档能拿到 A 以上。

后摇（`gap`）是这一门唯一能压到高手的旋钮。刀路在 `spawn()` 时就把整条路径和全部箭头画好了，`swipe()` 不检查光头位置——会读图的人可以抢在光走完之前划掉，所以光速与寿命线只对新手构成压力，接招间隔才决定高手的实际节奏。连击门槛同步上抬，是为了抵消「路更长、单招分更高」；不抬门槛，绝境档反而更容易拿 S。

**第二层：阶段换规则。** `STAGE_RULES.forge` 三条与 `perks.tier` 对齐，准备页的「本门新法」会逐条列出：

- 大成「收势」：划到靶心要停 70ms 再抬手，抢着抬算收势未成。
- 圆满「禁桩」：盘上出现红叉，禁桩一定不在刀路上；划过就断势。
- 大圆满「双锋」：同时亮两道刀路，两条都有靶心，只有会呼吸的那条是真的（`cell__end--live`）；虚招与真招不共用任何一格。

这三种都属于「规则内看错」：断刀势、不罚息。收势未成还留着半分，是因为它已经划完了整条刀路，只是没沉住；禁桩与虚影则整刀作废。反向 / 跳桩 / 绕圈才罚息——前者是没读清规则，后者是明知故犯，代价不该一样。

收势最初做成「未成则这一刀作废」，模拟下来玩家只要没注意到新提示就会整局 0 分——那不是难度，是事故。改成半分 + 断势后，同一节奏下从 0 分变成约正常得分的四分之一，落在 C 而不是归零：玩家还能继续练、还能拿到 60% 收益，同时「学会停顿」的回报是分数直接翻四倍。

**第三层：生成层不再假设 3×3。** `straightForms / neighbors / wanderPath / isBent / angleOf / dirAngle` 全部按 `shapeOf(grid, cols)` 算，`lineForms` 按形状缓存。默认仍是 9 格 3 列；`npm test` 里用 `grid: 16, cols: 4` 连跑 8 招，断言路径不越界、不重复、不跳格——把「以后能扩盘」变成可回归的事实，而不是先改盘面再发现生成层写死。

## 循数勘禁诀：把经典扫雷做扎实

「扫雷太经典了」正是它该挂在黄阶的理由：规则不用教，玩家看一眼数字就懂。所以这里的深耕**一条新规则都没加**，只把经典扫雷之所以好玩的三件事补齐（`minigames/mines.js`）：

- **首点必开出一片**：旧版在 `start()` 里就随机布好了禁制，`relocate()` 只在首点恰好踩雷时挪一枚，首点周围可能全是雷、开局就被一个数字堵死。现在改成**玩家点第一格才布雷**，那一格连同八邻一律无禁制；首点数字必为 0，一定展开一片空白。
- **整盘不用猜**：布完禁制用约束传播从首点模拟一遍最基础的推理（数字格周围「未探格数 == 剩余禁制数」→ 全是禁制；剩余 0 → 全安全），推得完才算合格，否则最多重布 64 次。刻意**不引入 1-2-1 / 两数相减**这类高阶技巧——黄阶入门功法的「无猜」就该是认得数字就能推完。6×6 五档实测 150 局全中，首点生成平均 0.2ms。`tests/minigames.test.js` 另有一个只读 `vm.cells` 的黑盒推理器，真的把整盘零失误翻完，不是玩法层自己说了算。
- **布镇符终于有用**：旧版那块记号只是给自己看的，胜利条件是「翻开所有安全格」，纯装饰。现在点已翻开的数字格，若周围符数（含已显形 / 已照见的禁制）对上数字，会一次连开其余邻格（chord）；压错位置照样踩禁制、按误触扣心神。不布符也能一格格点完，会用的人才快。

顺带修掉两处旧账：

- **破纪录方向是反的**：`finish.score` 以前传的是耗时秒数，而 `engine.applyPractice` 按 `score > prevBest` 记纪录——越磨洋工越容易「破纪录」。现在统一传「越大越好」的结算分（探明格数 ×10 − 用时 ×2 − 失误 ×60），与评级同向。
- **难度档挤成一团**：旧写法在 `buildParams` 已按 `goal` 缩放禁制数之后，又叠一次 `ctx.difficulty === 'hard' ? +3`，而 `gear` 只有 normal / hard 两值，困难 / 极难 / 绝境三档其实是一盘。现在禁制数全交给 `goal`，另让心神按 `depth` 从 3 盏收到 2 盏；盘面只有数字与 `✕`（禁制）/ `⚑`（旗）两个符号，不落汉字。

- **归类按玩法定，不按名字凑**：这门功课从头到尾是「看数字推禁制」，没有一处是画符——符是纸上画出来的东西，与格盘推理不相干。原来的「符箓·照影符」是类别与玩法相斥（项目自己的规矩就写着「符箓不练探雷」），已按「以游戏为准」改为**阵法·循数勘禁诀**，顺势补齐阵法族三档：黄阶勘禁（静态推理）→ 玄阶五行（动态连锁）→ 地阶燃灯（步数最省）。盘面术语同步从「镇符」改为「阵钉」，视觉色板从符箓朱金改为阵法青紫，`id` 仍是 `leifu` 不动存档。

阶段新法只给便利不添规则：大成「勘位」每局开局勘出 3 处禁位、大圆满「洞玄」5 处（**习得后每局生效**，不叠加，也不跨局留标记），已勘出的格子点了不再扣心神。三盏心神、长按钉阵钉、按用时评级（25 / 45 / 75 秒）这些老规矩原样保留；评级只看用时，心神折了只扣结算分。

## 视觉标准与沉浸舞台

方向：**国风修仙 + 2D 游戏场景 + 灵力特效 + 游戏化 HUD**。舞台固定深色（游戏该有固定氛围），页面也固定深色——四个主页面、子页、参悟页与登录页统一「墨底一支金」，不再跟 `prefers-color-scheme` 翻转。原则是「一套骨架、十一种皮相」：统一字体阶梯、间距圆角、HUD 骨架、反馈时序、结算框架；各异的是场景母题、主辉光色、道具符文、招式动画与音色。

- **唯一真源** `data/visual.js`：四类主题色板（兵刃青蓝 / 心法青白 / 丹道赤金 / 阵法青紫）、动效预算、结算分镜、样板开关。`styles/scene.wxss` 由 `app.wxss` 全局引入，只放表现；`minigames/` 下一行视觉字段都没有。
- **几乎零图片资源**：山门、月轮、三层山脊、云雾、灵力点、法坛全是 CSS 色块与路径。位图源文件三张：tabBar 图标 3KB、果器纹 sprite 28KB、器纹 sprite 35KB（两张 sprite 只作源文件，运行时用的是 `crest.wxss` / `emblems.wxss` 里各内联一次的 base64，合计约 90KB），加音效 112KB，全项目素材约 200KB，主包上限 2MB；十套场景若用位图会吃光包体，还要分包、CDN、加载白屏与深浅两套图。换主题只改几个色值，不用重出图。
- **三层场景**：远景静态（月轮 / 山门 / 星点 / 山脊）；中层 3 路常驻循环（月晕呼吸 8s、云雾漂移 18s、灵力上升 12s）；近层法坛与盘面恒为最高对比，特效不许压过判定信息。倒数三秒的深色遮罩顺带充当进场的明暗过渡。

## 开发约定与工程命令

- **设计先过清单**：新增一门玩法或改动已定规则，先照 `docs/checklist-puzzle.md` 逐条自检。它是交付门槛而不是灵感清单——十二个维度条条要有答案，能指到文件与断言；「二期」可以空着，但要明确知道自己空着。
- **内容即数据**：新增功法、参悟方式、对手、称号、成就或调数值，只改 `data/`，不动业务代码。
- **一门功法一套玩法**：19 门功法各自对应 `minigames/` 里的一个模块，`data/practice.js` 的 `game` 一一映射、不复用内核；同类别的功法也必须有不同盘面与规则。新增玩法要实现模块 + 在注册表登记 + 挂到功法表，`tests/minigames.test.js` 会断言玩法唯一与同类不重样。
- **品阶管收益、难度跟人走**：品阶挂在 `data/skills.js` 的 `tier`（`TIERS`），难度档挂在 `data/practice.js` 的 `DIFFICULTIES`，`buildParams(method, diffKey)` 只按难度档缩放参数。新增功法必须指定品阶与分类，同类内变体不得重样，盘面尺寸字段不得缩放——`tests/rank.test.js` 断言这些约定。
- **难度只调参数，不再「gear 二次收紧」**：`buildParams` 输出 `depth`（0–4，第几档）与按档递增的 `steps`，玩法据此调整，而不是看 `gear`（只有 normal / hard 两个值，分不出困难与绝境，容易一档一个样、还叠成断崖）。19 门全部按 `depth` 取数；新增玩法若只有一个可见参数会变，`npm run audit:diff` 与 `tests/rank.test.js` 会同时报欠账——补参数必须让玩法层真的读，不许只写在 `params` 里。
- **名字分四层，互不撞词**：功法名（典籍上的名字）、参悟方式（这门功课在做什么：斩桩 / 采露 / 观窍）、玩法名（盘面上的动作：顺光扫斩 / 循纹递推）、主题名（2 字意象：刀光 / 卦象）。前三层任意两层同名，准备页就会出现「步法连环 · 步法连环」这种叠字；**参悟方式不得与功法相斥**——刀法不练数格子、丹道不练渡河、心法不练牵线（上一版反例就是「符箓」练扫雷，已改归阵法）。`tests/minigames.test.js` 断言三层不撞词。
- **小游戏统一接口**：`create(ctx) -> controller`，见 `minigames/common.js`，注册表在 `minigames/index.js`；控制器除 `tap(index)` 外可选实现 `swipe(path, { hold })`（手指经过的格子序列与收势停留，目前只有顺光扫斩用）；`vm.stage` 决定页面用哪种舞台（`board` / `lane` / `ring` / `orbit` / `scroll` / `charge`），玩法层只输出数据。`ctx.theme` / `ctx.twist` 决定表现与本门规则。
- **单一状态源**：页面只读 `store.get()`，写走 `store.commit()` / `commitCritical()`，刷新靠 `store.subscribe()`；页面保持同步 API，云读写后台异步。
- **云客户端唯一**：`utils/cloud.js` 是全工程唯一初始化点；`store.setCloudAdapter()` 可替换存档实现。
- `'use strict'` + CommonJS，除云 SDK 与 ESLint 外无运行时依赖，不使用打包器。

```bash
npm ci            # 按 lock 还原依赖
npm run verify    # JSON / JS 语法 / 页面组件四件套（含相对路径）/ 主题变量 / tabBar 图标 / 隐私清单 / 品阶难度 / 页面规范 / 文案术语
npm test          # 270 项常驻断言（内核 + 存档同步 + 小游戏假时钟整局 + 品阶难度 + 布局约定）
npm run sim       # 收益曲线模拟：验证高档期望更高、境界衰减生效、封顶不误伤、刷简单不反超
npm run audit:diff # 五档难度区分度审计：逐门列出会变的可见参数与评级线种类（只读报告，断言在 rank.test.js）
npm run lint      # ESLint 9（小程序全局对象与 CommonJS 已配置）
npm run check     # 上面四项一次跑完，CI 用这个
npm run icons     # 重新生成 tabBar 图标（零依赖）
```

`.github/workflows/ci.yml` 是可移植的 CI 模板（`npm ci` → `npm run check`）。仓库双托管：`origin` 指向 Gitee（主），同时配了两条 pushurl，`git push` 一次同时推 Gitee 与 GitHub 镜像，`fetch` 只走 Gitee；GitHub 侧可直接用这份 workflow，Gitee Go 需按其配置格式另配一份，命令相同。

- **文案真源只覆盖了一半**：`copy.js` 是「状态 / 通用按钮 / 区块标题 / 术语 / 单位」的唯一真源，但 WXML 里仍有一批写死的短句——profile 32 处、battle 21 处、practice 16 处，合计约 105 处（多为区块标题与按钮文字，没有指向已删功能的旧文案）。这是架构欠账不是 bug：文案改一次要翻 5 个文件，术语一旦改名就会漏。下一轮按「区块标题 → 按钮 → 说明句」的顺序搬进 `UI.sections` / `UI.actions`，每搬一页补一条断言。
- 发布上线。
