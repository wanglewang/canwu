## 绑定

关联本体：`specs/S.md`（系统规格）。提取日期：2026-11-22。

## 1. 身份

模块名《参悟》参悟系统；归属微信小程序；用途是十五门功法的一趟参悟——选门、判定、评级、推进、存档。

## 2. 核心意图

让修士每一局的钱花得明白、努力有可见回报，不被回访焦虑驱动；系统承诺的行为写死在规格里，不随实现漂移。

## 3. 不变量（最高优先级）

- 熟练度不为负、不越硬顶；到顶后不再增长，但纪录照记、灵力照扣。
- 段位只由走通关数决定，与熟练度、品阶无关；关数与火候两套名字不混用。
- 灵力只许灵石单向兑换，反向不开；参悟不产灵石；灵力最低 1 点，不许扣成负数。
- 一局只推一关；对局退出连击清零；主动结束与失败是两个结论。
- 「全部 / 集齐」门槛读 `SKILLS.length`；评级线唯一出处 `lines()`；有失败态必须给 `fail`。
- 每页同步皮肤；符号一律 CSS 画；用色只认令牌真源。
- 以上不变量的数值与断言落点见 `S.md` 各契约末尾的「守卫」。

## 4. 合法输入范围

节拍 / 盘面时刻的有效操作；当前关号（一局一关）；灵力余额充足时才开局；合法功法 id（未知 id 不许静默回落）。

## 5. 输出 / 反馈定义

评级（C/B/A/S + F 失败）、熟练度增量、段位推进、耗气数、结算结论；开局前报代价，结算写明扣多少。

## 6. 禁止行为清单

不做签到 / 连续登录 / 体力 / 回访焦虑；不做排行榜与多人；不做内购；不把长规则铺到首屏；
不自动帮玩家判定、不后台偷偷叠熟练度、不跨局保留连击；AI 不自己定规格又自己验收。

## 7. 外部依赖

本地存档与云端同步；`data/*.js` 数值真源；`scripts/verify.js` 断言；系统主题（跟随 / 白天 / 夜晚）。
