# T · 测试规格（Tests）

> 这份文档回答：**S 承诺的每条契约，用哪些场景去校验。**
> 它从 `S.md` 派生——S 有一条行为契约，这里就有一个或多个测试场景去验它。
> 只做「契约 → 测试文件/场景组」的映射导航，不复制断言代码；具体断言在 `tests/`。

## 一、派生关系

`tests/` 五个文件，各管一摊。下面是 S 的六组契约分别落到哪些测试场景：

| S 的契约组 | 校验它的测试文件 | 覆盖的场景组 |
| --- | --- | --- |
| 3.1 一局参悟 | `tests/game.test.js`、`tests/minigames.test.js` | 开局校验、一局一关、扣气与余额、连击清零、失败结论 |
| 3.2 熟练度与段位 | `tests/rank.test.js`、`tests/game.test.js` | 熟练度硬顶、段位只认关数、评级口径、连 S 上限、回关折减 |
| 3.3 灵力经济 | `tests/game.test.js`、`tests/rank.test.js` | 兑换单向、耗气定价、气海上限、参悟不产资源 |
| 3.4 存档与异常 | `tests/store.test.js`、`tests/game.test.js` | 存读往返、老档补值、上限夹平、读档不发钱 |
| 3.5 页面与视觉 | `tests/layout.test.js` | 首屏黑名单、按钮层级、折叠开关、返回路径 |
| 3.6 教学与说明 | `tests/layout.test.js`、`scripts/verify.js` | 教学盘五段、输入接管、说明术语扫描 |

静态契约（结构、命名、术语、数值同步）由 `scripts/verify.js` 的断言守，不属于这五个测试文件。
完整的机器校验链见 `docs/40-engineering/03-verification-chain.md`。

## 二、场景分层（按 09 §2.2 的口径）

**正向主场景**：走通一局的完整流程、评级到熟练度的换算、段位推进、灵力兑换、存读往返。

**边界场景**：熟练度到硬顶、连击叠满、气海上限、老档升级、首屏字数上限。

**异常 / 坏路径**：灵力不足开局、局中退出作废、读档不发钱、重复领取、非法 id 取法门。
其中「`getMethod` 对未知 id 静默回落」这条是踩过的坑——测试取法门时必须当场验 `game`，否则拿错参数照样全绿。

## 三、未覆盖风险（强制写，不许隐瞒）

这几项当前没有机器断言，靠真机或人判断——人做风险取舍，先得知道风险在哪：

- **真机手感**：点击判定在移动端低帧率下的误差、盘面符号在部分安卓机上的显示。静态断言测不了。
- **覆盖度集合与差集告警**：场景 ID 表、三份覆盖度自动比对、保真度校验都还没建（见 `coverage/` 与 09「待验」）。
- **全方法效果**：RDD/SDD 这套流程是否真的减少审查量、有没有漏掉真实缺陷，没在全项目实测过。
- **人的三个点头点**：规格认领、盲区接受、差异裁定，目前靠对话确认，没有固化成记录。

## 四、验收通过标准

`npm run check` 四段全绿（静态校验、常驻测试、收支曲线、lint）。通过项不逐一人工复核，
人只看红的那几行。测试数量不等于质量——判据是「有没有验到 S 的关键规则」，不是断言条数。
