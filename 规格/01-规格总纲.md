# S · 规格总纲

> 这份文档回答：**整个系统共同的底线、边界、未定问题是什么。**
> 六份行为契约（对局 / 成长 / 经济 / 存档 / 界面 / 教学）各自成文，但都受这份总纲约束。
> 只写「做什么」和「不许做什么」，不写「怎么做」；数值一律指真源，这里不另存一份。

## 一、这份文档的位置

规格驱动开发（Spec-Driven Development，SDD）把规格当作唯一真相源：代码和测试从它派生，
改行为先改这里，再让实现跟上。它与 RDD 的关系见 `docs/40-engineering/09-review-driven-development.md`——
RDD 管需求还在探索的那段，需求稳定后收敛到这里。

**这条链是有向的**：`S → T → D`，三层各派生一层覆盖度 R<sub>S</sub> / R<sub>T</sub> / R<sub>D</sub>。
S 是起点，由**人提出意图、AI 起草成文、人再纠正确认**——AI 不能自己定规格然后自己验收。
T 从 S 派生，D 从 T 派生；链条方向与审核反馈规则见 `规格/00-总览.md`。

三样东西不要混：

| 文档 | 回答什么 |
| --- | --- |
| `01-product-vision.md` | 为什么做这个游戏、给谁玩、体验目标是什么 |
| **本目录的规格**（总纲 + 六契约） | 系统承诺的行为、不变量、禁止项、边界——可测的契约 |
| `data/*.js` 与 `scripts/verify.js` | 数值的唯一出处，以及守住这些契约的断言 |

**规则**：规格里出现数值的地方只写「见真源」，不写具体数字。谁抄了一个数，
下次改 `data/*.js` 时它就过期，规格反而成了误导。唯一例外是纯结构性事实（比如「五段」「十五门」），
因为它们本身写在真源常量里，且由断言钉住。

## 二、范围与非目标

**范围内**：一门功法从开局到走通的一整趟参悟——选门、扣灵力、盘面判定、评级、熟练度与段位推进、
结算、存档、教学、皮肤、说明。六份契约把这六件事分开写。

**明确不做**（Non-goals，写在这里防止实现者好心多做）：

- 不做签到、连续登录、体力恢复和任何制造回访焦虑的机制。
- 不做排行榜、社交与多人实时对战。
- 不做内购；灵石只能从玩法获得，兑换只开「灵石→灵力」一向。
- 不把长篇规则铺到主页面首屏；解释只在点进去之后。

非目标不是物理定律，是当前的默认取舍。翻案要走人审，判据见 `01-product-vision.md` §5 的约束分层框架。

## 三、不变量（无论怎么改都必须成立）

这些约束横切六份契约，任何一份契约改动都不许突破它们：

- 熟练度不为负、不越过硬顶；连击有层数上限；对局退出则连击清零。
- 段位只由走通关数决定；十五门功法各有独立的内核，不做通用特效层（判重见 `tests/minigames.test.js`）。
- 灵力不能反向兑成灵石；参悟不产灵石；灵力最低 1 点，不许扣成负数。
- 「全部 / 集齐」的门槛读 `SKILLS.length`，不写字面量。
- 评级线只有一个出处 `lines()`；有失败态必须给 `fail` 结论。
- 符号一律 CSS 画，不许用会变彩色 emoji 的字符；用色只认令牌真源。
- 每页同步皮肤；新页面必须注册进 `app.json`；判定改一处要同时改所有消费端。

每条不变量的守卫写在对应契约里（`02`~`07`），不在这里重复——这里只列约束本身。

## 四、开放问题（未定，不许实现者替玩家决定）

这些是悬而未决的取舍，实现时**不得自行选一个做掉**，要以人为准。完整清单与背景在
`docs/50-balance/04-open-issues.md` 的 D 类；此处只列会造成行为分叉的几条：

- 后三段的关卡密度是否撑得住（D11）——直接决定「熟练度先毕业还是关卡先毕业」。
- 身法属性在中前期是否生效（D1）——决定要不要改属性出口。
- 熟练度封顶后仍要烧气继续练，这条是否保留——决定 `03-成长契约.md`「到顶后照扣」是否翻案。

## 五、维护纪律（防规格漂移）

SDD 最大的失败模式不是没写规格，是规格和代码悄悄脱节，然后 AI 照着过期规格自信地改错。
因此：

- **改行为先改对应契约**：实现与规格冲突时，先判断是规格错了还是实现错了；改契约要连同守卫一起改，并按 `00-总览.md` §三 走反馈回溯。
- **每条契约都要有会红的守卫**：写一条行为，就问「哪条断言会在它被破坏时报红」；答不出就补断言。
- **写完断言要反证**：故意把实现改坏一次，确认断言真的红；不红说明断言空转（项目铁律）。
- **数值只指真源**：规格不存第二套数字；改数值看 `docs/50-balance/02-numbers-reference.md` 与根 README 三处同步。
- **翻案走人审**：非目标和开放问题的改动要人点头，不能因为「实现起来更顺」就悄悄改口径。
