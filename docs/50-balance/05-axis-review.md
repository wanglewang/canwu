# 外来「精微层」方案评审

## 核心前提：一份外来方案，照见了我们自己的三件事

有人递来一份很完整的方案：一条可上下浮动的「精微层」轴控压力，沿途摆锚点解锁变体。我认真对着本作的数值逐项算了，结论是——它要的三样东西本作都已经有了，而它真正错在**把四个数焊成了一个数**：难度旋钮和进度刻度用同一根轴，于是失败必须回退难度，回退难度就等于回退进度。

这篇是对那份方案的评审记录，所以我保留原样、不改写历史——改了就失去对照价值。它的价值有两层：一层是「为什么拒」，把那几处硬伤（熟练度乘层数导致前 10 局白打、F 掉层让锚点卡死、奖励发的是出厂标配）讲成决策故事——当时为什么否、诱因是什么；另一层是「它说对了什么」，照出了本作真实存在的缺口——玩家感知不到「自己在第几站」、9 门没有阶段新法。拒绝一份方案不算完成，把它指对的那件事补进本作才算。

读这篇要注意：开头引文下方的 ⚠️ 注记标了哪些结论已被 v8/v9 推翻。这是评审当时的快照，不是现行设计。

> 收到一份「1 功法 = 1 小游戏 + 1~999 可锯齿浮动精微层 + 锚点解锁变体」的完整方案。
> 它要的三样东西本作都已经有了，它要错的是把四个数焊成一个数。本篇记下采纳了什么、拒了什么、为什么，并据此把本作缺的一处补上。

## 1. 概述

方案提出的「连续压力轴 / 玩家感知的关卡 / 悟道所得的新解法」三件事，本作分别由「999 关」「段内 40 段」「阶段新法」承担；
真正的分歧只有一条：**它让「难度旋钮」也承担「进度」，于是失败必须回退难度，而回退难度等于回退进度。**

那根「焊死的轴」为什么会崩，画出来是这样——一个环，越努力越往回走：

```text
        层数升高
           │
           ▼
      打不动了 → F 变多
           ▲          │
           │          ▼
      又打得动 ← 层数下降
           │
     （停在这里反复震荡 = 玩家的能力上限）

   本作把三件事分开，各管各的：
   ┌────────┬────────┬────────┐
   │ cleared│ 熟练度  │ 关 / 段 │
   │ 管进度 │ 管能力  │ 管参数  │
   └────────┴────────┴────────┘
      只增      不系数     不回退
```
*（结构示意，非实测截图；环形是「焊成一个数」的后果，方框是本作的拆法。）*

## 2. 目标与非目标

**目标**：判断这份方案哪几条能接进本作，哪几条必须拒；把「它说对了的那件事」补进本作。

**非目标**：本篇不动任何已有数值（评级、熟练度、五段、耗气）。要动数值的结论一律标「待拍板」。

## 3. 它在说什么

三条主张，加一条原则：

1. **一条 1~999 的轴控制单局压力**：S / A 精微层 +1，B / C 不变，F 掉 3~8 层。
2. **轴上摆 33 个小锚点（30、60、…、990）与 5 个境界大锚点**：抵达层数且评级达标 = 闯关成功，永久解锁一条变体。
3. **变体是「悟道所得」**：只给新策略 / 新视角 / 取舍型技能，「不降低系统压力」。
4. 熟练度 = 基础 ×（当前精微层 ÷ 1000）× 连 S 倍率。

它的基础数值直接取自本作：`S 34 / A 22.5 / B 15 / C 10 / F 0`、连 S ×1.5 叠 10 次、熟练度上限 99999。
所以这不是「另一套设计」，是**把本作的数值换一条轴重新包装**——评审可以逐项对着算。

## 4. 三处硬伤

### 4.1 熟练度乘 `层/1000`：前 10 局白打，全 C 永久零收益

本作前 10 局全 S 的熟练度是 `34+51+76+114+171+257+385+578+867+1307 = 3840`。
他的公式下，第 n 局的层数 ≈ n（每局 S 涨一层），代入 `34 × 1.5^(k-1) × n/1000`：

| 第 n 局 | 连 S 层 | 他的熟练度 | 本作 |
| --- | --- | --- | --- |
| 1 | 1 | `34 × 0.001 = 0.034 → 0` | 34 |
| 3 | 3 | `76 × 0.003 = 0.228 → 0` | 76 |
| 5 | 5 | `171 × 0.005 = 0.855 → 1` | 171 |
| 8 | 8 | `578 × 0.008 = 4.6 → 5` | 578 |
| 10 | 10 | `1307 × 0.010 = 13` | 1307 |
| **合计前 10 局** | | **32** | **3840** |

**前 10 局差 120 倍**，而且第 1~4 局取整后是**整整 0 点**。玩家开局连打四局满分，结算卡上写「熟练度 +0」——这是最容易被判定成 bug 的读数。

更硬的一处：**全 C 玩家永远出不了第 1 层**。
B / C 不改层，所以层恒为 1；`10 × 1/1000 = 0.01 → round = 0`。
本作全 C 打满 99999 要 10000 局，**他的方案下是无限局**。这不是「慢」，是这条路径不存在。

根因：`层/1000` 的系数上界是 1（第 999 层），而门槛 `0/300/1500/6000/24000` 是按「系数为 1」标定的。
**乘一个 ≤1 的系数、门槛一个不降，等于把所有玩家的解锁速度按层数打折**。要让这套成立，门槛必须同步除以同一个系数，
但层数是浮动的，门槛没法跟着浮动——所以这条路在他自己的规则里走不通。

全 S 毕业从 84 局变成 **391 局**（`Σ 1.307n = 99999` 解出的 n）。全 A 更慢，全 B 不动层，全 C 不存在。

### 4.2 F 掉层把「进度」变成「能力评估」，锚点必然卡死

本作「第 166 关」的判据是 `levelBest ≥ 166`——**只增不减**，全 C 打 166 局也能到。
他的「166 层」判据是评级净和：S/A 各 +1，F 扣 3~8。两者在高水平下同速，在中低水平下分叉：

| 评级分布（S/A/B/C/F） | 每局 Δ层 | 到 166 层 |
| --- | --- | --- |
| 20 / 30 / 30 / 15 / 5 | `0.5 − 0.275 = +0.225` | **738 局** |
| 10 / 20 / 25 / 30 / 15 | `0.3 − 0.825 = −0.525` | 永远到不了 |
| 0 / 0 / 40 / 55 / 5 | `0 − 0.275 = −0.275` | 永远到不了 |

第二行是这套轴的真正形状：**层数升高 → 打不动 → F 变多 → 层数下降 → 又打得动**。
它会自动停在「Δ = 0」那一层反复震荡，那一层就是玩家的能力上限。
这是动态难度平衡（DDA）的行为，不是进度轴的行为。

而锚点要求「抵达 166 层**且**评级 ≥ B」。震荡区间一旦落在 160 附近，**这个锚点永远拿不到**：
不是他打不到 B，是他打不到「166 层上的 B」。他越努力，F 越多；F 越多，离锚点越远。

第三条边界约束「所有变体永久绑定功法，掉层也不收回」把这事固定下来：
一位在 900 层解锁全部变体的玩家掉到 1 层，手里握着 33 条减负规则打第 1 层的盘——**层数彻底失真**。
他把这一条写成优点，但它恰好是这套轴的崩坏点。

### 4.3 锚点发的是「出厂标配」

凝方块劲的 7 条小锚点变体里：

- 【存块】= 储物槽 = 落石垒基已有的 Hold
- 【劲眼】= 多一个预览 = 已有三块预告再加一块
- 【延锁】/【轻落】= 锁定延迟相关 = 已有 500ms + 15 次重置
- 【余滑】= 落定前左右平移 = 已有的落定宽限
- 【逆旋】= 多一次逆时针 = 已有 SRS 双向旋转

**7 条里 5 条是本作品类的行业标配**（`docs/20-minigames/12` 记着九样机制逐条有出处：10×20 场地、7-bag、三块预告、Hold、
重力表、500ms 落定 + 15 次重置、SRS 踢墙、阶梯计分、盒内旋转）。

照这套做，等于**开局先把这五样拆掉**（没有 Hold、只有一块预告、落地即锁），再在第 30 / 60 / 90 层一件件当奖励发回来。
这不是设计，是「先把地基挖了再按块卖砖」。玩家到第 300 层才发现「原来这游戏本来就该能存块」，那一刻他学到的不是「我悟了」，
是「被耍了」。

**奖励不能发给「本来该有」的东西。** 这条比数值更能判死一套方案。

## 5. 另外四处

| 处 | 问题 |
| --- | --- |
| 原则自相矛盾 | 「压力随层数单调递增，没有反向」与「F 掉 3~8 层」放在一起就是矛盾的：层掉了，压力必然降 |
| 「不减负」的清单在减负 | 总说明写「不降低对局压力」，7 条变体里 5 条在降低压力（见 4.3） |
| 数字对不上 | 「6 个大锚点」表里只有 5 行（6 个境界 = 5 次跃迁）；33 小 + 5 大 = 38 个关卡，面板写「第 X/33 关」 |
| 没接经济 | 通篇无灵力 / 灵石。本作一局烧 7~32 点，F 掉 3~8 层 = 重爬 3~8 局 = 3~8 份灵力，**惩罚落在钱包上，不是技术上** |
| 休闲开关没代价 | 「可选：F 不掉层」= 免费无痛模式，且一开锯齿轴就没了。给这个开关等于承认轴不成立，却没敢删 |
| 规则爆炸 | 33 条变体同时在场上，他自己也写了「后续改强化版」——强化版仍是新规则。本作单门至多 3 式（`FOCUS = 2`）是刻意压住的 |

## 6. 它说对的三件事

1. **「变体是学会新解法，不是题目变简单」**——这条判断完全正确，而且比本作现在的 `hard: true` 标记说得更清楚。
   本作的十二原则第十一节写的是同一句话（「阶段新法要加规则，不是减难度」），但只有 8 门真的这么做了（见 §8）。
2. **「锚点 = 玩家感知的关卡」**——999 关是连续刻度，玩家不知道「我到哪一站了」。本作的「段」（5 关）负责参数微变，
   颗粒太细，不适合当叙事节点。这个缺口是真的。
3. **「评级权重在表达什么」**——它给每门写了「权重优先级：台面高度 > 消行效率 > 失败惩罚」。
   本作各门 `lines()` 是分项加权，但没有一处写清「这套权重表达的是什么取舍」。这一条可以借成文档要求。

## 8. 采纳：把关卡改成「熟练度的刻度」

它说对的那件事是「玩家要感知到自己在第几站」。但本篇第一版给的是「40 站」——那个方案是错的，
因为它承认了「999 关是路」，再在路上加里程碑。真正的解法是把「关」本身重定义。

**落在 `07-difficulty.md`，本节记决策**：

| 旧 | 新 | 理由 |
| --- | --- | --- |
| 999 关 | **200 关**（五段 × 40） | 999 关的真实分辨率就是 200（每 5 关一段），对外标 999 是虚标 |
| 关卡 = 打过的最高关（`levelBest + 1`） | **关卡 = `levelFromProf(熟练度)`** | 熟练度是唯一只增的数，关卡当它的另一个刻度，于是没有「跳关」，也没有「点高关号」的博弈 |
| 段内随便挑关 | **只能回关，不能往上挑** | 「挑」让进度变成手的动作；且第 1 关与第 40 关收益曾完全一样 |
| 每 5 关一段 | **一段一关** | 段内五关逐位相同等于「四关白过」 |
| 每低一段折半（`profBelowCap`） | **按「本关 ÷ 当前关 × 段基数比」连续折**（`profByLevel`） | 段位只有五段，段内第 1 关与末关系数都是 1——**段内折减是空的**，那正是「刷第 1 关」的入口 |

**这一步同时否掉了本篇第一版的「站」**：既然关由熟练度算出、一局动几关，关号本身就是「站」，
再加一层 25 关一站的刻度，只是把「第 47 关」翻译成「第 2 站第 22 关」——多一层换算，不多一分信息。

**量化后的代价（`npm run sim`，6000 点灵力）**：

| 刷法 | 局数 | 熟练度 | 相对逐关进 |
| --- | --- | --- | --- |
| 逐关进（一直打当前关） | 413 | 7290 | 100% |
| 只刷第 1 关 | 1000 | 598 | **8%** |
| 退一段 | 1000 | 598 | 8% |

旧版「只刷简单」还有 88%（6392 vs 7290）——**按关折才真正把它堵死**。

## 9. 不采纳

| 它的方案 | 为什么拒 |
| --- | --- |
| 精微层（可浮动、F 掉 3~8 层） | 一个数同时当难度旋钮与进度刻度，必须回退，回退即进度倒退。本作已分家：`cleared` 管进度、熟练度管能力、关与段管参数 |
| 熟练度 ×（层 / 1000） | 系数上界 1、门槛不降 = 全员打折。前 10 局差 120 倍，全 C 永久 0 点（§4.1） |
| 锚点给「变体池」 | 发的是出厂标配（§4.3），且 33 条规则同时在场无法验收 |
| 「可选：F 不掉层」 | 无代价的难度回退开关，与本作「阶段便利必须有明码代价」直接冲突 |
| 熟练度上限 99999 的连 S 复利 | 数值与本作一致，但叠上 `层/1000` 后变成双重复利：打得好 → 层高 → 熟练度高 → 更快解锁 → 更容易打得好 |
| 「6 个大锚点」 | 6 个境界 = 5 次跃迁，本作 `08-realm` 的口径是一次跃迁一次突破，不需要 6 个 |

## 10. 顺带查出的真缺口：9 门没有阶段新法

`STAGE_RULES` 现在有 10 门：`forge` / `recite` / `arrayEye` / `tanlei` / `linkpair` / `stackstone` / `harvest` / `shudu` / `tuisuo` / `seal`。
**余下 9 门练到 99999 熟练度也不会学到任何新东西**——这正是「变体」方案想解决的问题，它指对了，只是解法错。

补法分两类（沿用 `data/practice.js` 已有的两条口径）：

**A. 原创 6 门——加规则（`hard: true`）**

| 门 | at 3 | at 4 |
| --- | --- | --- |
| 02 辨伪择真 | 乱锋：真招中途会换到另一道光上 | 连截：每轮要连截两道真招才算数 |
| 04 循纹递推 | 暗纹：每层有两道纹看着都对，只有一道真对 | 回流：采对后石位倒换一层，要重新对 |
| 05 节律判定 | 双环：两个光环交替收进，只认外圈 | 逆拍：每第 3 拍反过来——红圈消失后才点 |
| 06 步法连环 | 逆卷：卷轴从右往左铺，要反着读 | 暗步：卷轴只亮前三步，后面边踏边看 |
| 08 五行相生 | 逆生：奇轮按相克次序接 | 双生：同时两灯可接，只有一灯接得下去 |
| 19 数中取大 | 近数：盘上出现 87 与 78 这类近值 | 倒数：每第 4 轮要挑最小的 |

**B. 经典 6 门——只给「看得更清」（不带 `hard`）**

`data/practice.js` 里 `STAGE_RULES` 上方那段注释的原则：九套经典玩法是入门功课，不往经典规则里塞新花样。

| 门 | at 3 | at 5 |
| --- | --- | --- |
| 10 成对翻牌 ✅**已落地** | 留影：照见的那一对留到点下一处才收（次数照扣） | 记印：翻错的两处阖上后牌背留一道极淡的卦象 |
| 14 九宫填数 ✅**已落地** | 密勘：某行列宫只剩一个空位时，那一格描一圈 | 唯余：选中空格时唯一候选的键描金 |
| 15 滑格相合 | 残影：新块生成前 0.3 秒淡显位置 | 预览：滑动前显示这一滑会发生几次合并 ⚠️ 不可行，见下 |
| 16 顺序点格 | 导引：下一个该点的数有极淡呼吸光 ⚠️ 与模块自身的设计相反，见下 | 残位：点错时那一格留 0.8 秒红痕 |
| 17 滑块让路 | 推演：按住一块时显示它能挪的位置 | 回步：每局可撤一步（只退位置，不抵步数） |
| 18 推箱入位 ✅**已落地** | 死位：推到就再也推不出来的格子压斜纹 | 临渊：石箱离死位只差一推时，那个死格描红 |

**⚠️ 上面两条是写这一节时没核对模块才写出来的，补之前必须改：**

- **16 的「导引」与 `minigames/schulte.js` 开头那段设计说明直接相反**：那里明写「盘面上**不标下一个在哪**……
  一旦替玩家把目标格圈亮，就只剩点发亮的格子，与舒尔特方格本身无关了」。所以这一门能给的只有「残位」（点错留痕），
  以及「点错之后给行 / 列、不给格」这类方向性提示——补的时候按这个尺度设计，不能照抄上表。
- **15 的「预览」在滑动手感下没有落点**：这一门没有「选方向 → 确认」两步，四向滑动就是立即执行，
  不存在「滑动之前」这个时刻。要预览只能改成「常驻显示四个方向各能合几次」——那等于把每一步的最优解摆出来，
  这一门就不成立了。所以 15 得另想办法（候选：新块落地位置的残影、或「离满盘还剩几格」这类不碰决策的显示）。

两条硬约束（补的时候必须守住）：

1. **便利也要有代价——但只对「交出资源」的那一类收。** 判据是这条便利有没有替玩家省下一次**已经数得清的次数**：
   - 省次数（多一次撤销、多一次照见、提示少扣一息）→ 必须明码标价。`harvest` 的做法是「少扣 1 息，但仍要付」；
     `tanlei` 的「开局标 3 处禁位」之所以不收费，是因为它标的是**这一局已经确定的东西**，多标一处并不让玩家少算一步。
   - 只改显示（暗纹、描红、压暗、描圈）→ 不收费。这类东西不动判定、不省次数，收费反而只能收在「看得更清」上，
     那等于说「想看清楚要交钱」，与「阶段新法」这四个字相反。
   按这条，上表已经落地的 `14 九宫填数`（密勘 / 唯余）与 `18 推箱入位`（死位 / 临渊）都不收费；
   还没落地的 `10 复观`（白看全部牌一次）、`17 回步`（每局多一次撤销）**属于省次数那一类，必须定价**。
2. **每补一门，同批补三处**：玩法模块读 `perks.tier`、`tests/*` 断言这一段真的生效、`docs/20-minigames/NN` 的「界面与反馈」节。

**账面结论**：十五门里只有换苗引秀（三秀同收）达标（**9 类全开 / 7 内容轴，段界一次开 5 条**）。牵灵引线（并蒂连枝引）4 类 / 3 内容轴，但段界仍只开 1 条；其余十三门只有 2–3 类、段界普遍 1 条。

**两整列是空的**：

- **本局变数**：只有换苗引秀有——圆满段开局从固定两条里选一条，一紧一松配对，S 线按改后的时辰现算。其余十四门全无；每局盘按规格现抽 ≠ 本局二选一，前者是随机化布局，后者把随机变成决策。

**地形障碍**只有换苗引秀的石皮一种，且石皮只是「不能换」，不是「要先用别的手段破」；**目标类型**有七门有——换苗引秀按段走「收灵草 / 收色 / 连锁 / 破皮 / 引苗落底」，而且这是唯一一门**目标就是终点**的（做成即收工，时辰尽未做成不算走通）；其中「引苗落底」是唯一的位置类目标（问「先清哪一列」，而不是「收够几个」）；其余六门多是攒分/攒数。

**段界仍是普遍短板**：展示层按轴去重补报预算轴之后，归箱入阵（3 条 / 2 内容轴）、挪块开路（2 条 / 1 内容轴）四道段界已真开两条，但两门类数不足 5，整门仍未达标；其余十二门段界仍只开 1 条（有的内容轴为 0，只报时辰或毫秒）。这不是段宽问题——把段宽改成 200 也一样，段界那一关还是没有第二条可报的轴。要补的是「段界同时上什么新规则」，不是「段界落在第几关」：展示层能补的（同轴去重 + 预算轴）已经补完，剩下十二门的第二根轴要么落在段内而非段界，要么根本是毫秒/时辰放大器（换章不许报），得改关卡段表让内容参数在段界那步长一格——那是动数值难度，见 D17 顺序②/③。

**换苗引秀已是样板门**：九类全开的做法是「四连/五连/交叉出符 → 目标换种类 → 石皮压换位数 → 挪苗买操作 → 二选一劫变买变数」，S 线与 `perMove` 按新机制重标。其余十四门照它补；补法顺序见 `docs/50-balance/04-open-issues.md` D17。
