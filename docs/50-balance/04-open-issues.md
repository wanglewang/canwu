# 已知问题、待验收与待拍板

## 一句话

把散在各篇设计文档里的「待验」收成一份清单，并分成**必修（代码写错了）/ 该修（代码里躺着的死东西）/ 缺口（断言没守住）/ 待拍板（要人决定）/ 待验收（要真机证据）** 五类——因为这五类的处理方式完全不同。

## 口径

| 类别 | 判据 | 谁来处理 | 能不能在 `npm run check` 里发现 |
| --- | --- | --- | --- |
| **A 必修** | 代码/文案与设计真源不一致，玩家能看见 | 下一步就改 | ❌ 现在发现不了 |
| **B 该修** | 死代码、遗留方法、名不副实 | 找时间改 | ❌ |
| **C 缺口** | 断言存在但门槛过低，或该守的没守 | 补断言 | ❌（它本身就是断言的事） |
| **D 待拍板** | 两种做法都成立，需要人决定 | 决策 | ❌ |
| **E 待验收** | 只能靠真机 / 真人数据 | 真机跑一遍 | ❌ |

**这五类全都不在 `check` 里。** 这是当前的实际情况：`verify` 11 段 135 处断言守的是「结构完整、公式复算、文案不退化」，守不了「这句话说反了」「这个方法没人调」「这个阈值太松」。所以才有这篇文档——它是 `check` 绿了但项目仍然有欠账的那部分。

## A. 必修：玩家能看见的错

### A1. 指南把身法的换算写大了 10 倍 —— **已修**

| 位置 | 说的是什么 |
| --- | --- |
| `pages/guide/guide.js` 第 55 行 | 「身法**每 30 点**把切磋波动下限抬 1%（封顶 10%）」 |
| `utils/game/profs.js` 注释 | 「身法给的切磋波动下限：**每 30 点** +1%，封顶 +10%」 |
| `utils/game/profs.js` 代码 | 曾是 `const SHEN_FLOOR_PER = 1 / 300;` → 现为 `1 / 3000` |

`1/300` 是 **每 3 点 +1%**：身法 30 点就吃满 10% 封顶，练两门之后这项属性再堆零收益。「每 30 点 +1%」需要 `1/3000`。

**修法（已落地）**：代码改成 `1/3000`，让两处文案成真。实测：开局 11 点 0.37%、练深几门 90 点 3.0%、十五门全大圆满 151 点 5.03%；封顶 10% 需 300 点，当前不可达，是留给以后扩属性的边界。

`tests/game.test.js` 补了一条断言，用没封顶的存档反算「每点系数 = 1/3000」。原来的断言只守「涨了、不超顶」——两个口径都满足，漂 10 倍也发现不了。**「有条断言」不等于「断言守的是那个数」**。

> **这条欠账自己写错了两处，一并记下**：① 原文说「实际是每 300 点 +1%、30 点只抬 0.1%」——`1/300` 算出来是 10%，方向反了；② 原文给的修法是「改成 `1/30`」，那是每 30 点 +100%、身法 3 点就封顶，比原实现更错。两份文档对同一行代码给出两个相反的读数，说明**欠账清单里的数字也要核算，不能照抄代码旁边的注释**。

### A2. 推石入位说「推不回来」，其实撤销得回来 —— **已修**

| 位置 | 修前 | 修后 |
| --- | --- | --- |

**顺带清掉一处自相矛盾**：`guides.js` 的步骤列表原来第 2 步说「只能复位重来」、第 4 步说「可以撤销」——同一份说明里两句话打架。

### A4. 说明页分享丢参数，转出去的是一份泛稿 —— **已修**

`pages/help/help.js:22` 读三个参数：

```js
const topic = q.topic === 'practice'
    ? helpData.practiceTopic({ method: q.method, game: q.game, diff: q.diff })
    : helpData.topicOf(q.topic);
```

但 `onShareAppMessage` / `onShareTimeline` 只拼了 `?topic=`：

```js
const q = this.topicKey ? '?topic=' + this.topicKey : '';
```

后果：`topic=practice` 的分享点开后，`method` / `game` / `diff` 全是 `undefined`，`practiceTopic` 退化成一份不带功法名、不带本段 S/A/B 门槛的通用说明。而 `30-ui/06-page-skills-practice.md` 承诺的正是「说明页按链接带的 `diff` 列出本段 S/A/B/C 门槛」。

**修法（已落地）**：`onLoad` 里把三个参数记到 `this.topicQuery`，新增模块级 `shareQuery(page)` 统一拼串，两个分享钩子都走它。`onShareTimeline` 的 query 不带 `?`，所以函数只拼 `k=v&k=v`、由调用方决定要不要前缀。

**守卫**：`scripts/verify.js` 的 1d 段新增一条——`pages/help/help.js` 里必须同时出现 `method=` / `game=` / `diff=`，否则红。这条能拦住「以后又只拼 topic」，但拦不住「拼了却拼错值」，那一层只能靠真机点一次。

### A6. 闭关报「灵力 +90」，账上一分没有 —— **已修**

真机上报的原话：「挂机了一阵子，来收灵力没有，看到没有增长，肯定有 bug，提示我增长了，但是没有增长。」

复现脚本（内存 wx 存储 + 假云端，跑真实的 `store.init()` / `store.hydrate()`）：

```
本机 qi=0、lastSeen 三小时前；云端那份是同一份旧档
init 之后      qi = 90    ← 弹窗会显示 +90
hydrate 之后   qi = 0     ← 玩家看到的就是这个数
```

**两个根因叠在一起：**

| 位置 | 错在哪 |
| --- | --- |
| `utils/store.js` 的 `init()` | 先 `settleOffline()` 结算、再由 `hydrate()` 用云端档整个覆盖 `state`——这一笔算完就扔了。而且 `init()` 里那句 `game.save()` 不给云端留 pending 标记，`hydrate()` 就当作「本机没改过」，直接拉云端 |
| `utils/game/state.js` 的 `save()` | 里面写着 `state.lastSeen = Date.now()`。存档远比结算频繁（领份例、换门、参悟结算…），每存一次就把闭关起点推到现在，攒下的时长一次次被抹掉 |

两条合起来正好是玩家看到的循环：**每次冷启动都弹「+90」，每次都是一分不到账**（云端那份 `lastSeen` 也是旧的，所以下次还能再算一遍）。

**修法（已落地）**：

- `save()` 不再碰 `lastSeen`，它只在 `settleOffline()` 里推进——注释写在函数头上，别让下一个人再顺手加回去；
- `store.init()` 只读档不结算，闭关统一由 `app.bootstrap()` 在 `hydrate()` 之后调 `store.settle()`；
- 主页弹窗改成两个触发点（`onShow` + `refresh()` 末尾）：冷启动那次结算发生在 `hydrate()` 回来之后，只在 `onShow` 看一眼会漏掉。

**守卫**：`tests/store.test.js`「冷启动：闭关灵力在 hydrate 之后才结算，不会被云端档吃掉」按真实时序跑一遍（init → hydrate → settle），断言「报告了 +N，账上就是 N」且同一段不许结算两次；`tests/game.test.js`「存档不推进闭关起点」守 `save()`。

### A7. 挂机在涨熟练度，等于挂着就能推关卡 —— **已修**

`world.idle.profPerHour = 2.5`（8 小时 20 点），是 999 关时代的遗物——那时关卡由「打过多少关」累加，挂机给的熟练度只是给功法加成。

关卡改成 `levelFromProf(熟练度)` 之后，这条产出变成了**第二条进度轴**：挂着不玩，关卡自己往前爬，「练到哪就在哪」成了假话。玩家算得比设计者清楚——最优解会变成「挂着不回」。

**修法（已落地）**：整条删掉。

| 删了什么 | 连带改动 |
| --- | --- |
| `world.idle.profPerHour` | 留一句注释说明「这里没有这个键」，见 `13-idle.md` 第 7 节 |
| `pickIdleSkill()`（挂机喂哪一门） | 没有熟练度就没有「喂给谁」，整段删掉 |
| `idlePending()` 的 `prof / skillId / skillName` | 预演对象只剩灵力五件套 |
| `settleOffline()` 的 `prof` 入账与日志尾巴 | 日志改成「闭关 5 时 48 分，灵力 +174（气海已满，散去 66）」 |
| `meditate()` 的「只涨熟练度」分支 | 满池现在**挡回并说明**（没有第二条产出可收了），主页也不再摆一个收不到的入口 |
| 主页闭关弹窗的「熟练度」行 | `pages/index/index.wxml` |
| 词典 / 说明 / 指南各一句 | 「闭关只养灵力，熟练度只在参悟里得」 |

**判据**：熟练度是「练出来的」，闭关只提供练的燃料。油和里程不能互换——与「灵力买不回灵石」是同一条。

**守卫**：`tests/game.test.js`「正常离线 1 小时只结算灵力，不涨熟练度」（报告里不许有 `prof`，每门功法的熟练度一字不变）。

### A8. 阵灯推演的评级阶梯实际只有两段，预算永不咬人 —— **已修**

一次专门的复算（枚举 3×3 / 4×4 全部盘面 + 5×5 抽样 + 逐段跑控制器）查出六条，全部出在「难度」这一层，`npm run check` 一条都发现不了——断言只锁了「规格不放宽、预算递增」，没锁段位之间到底有没有区别。

| 位置 | 说的是什么 | 实际是什么 |
| --- | --- | --- |
| 评级「B = 2 倍最优」 | 五段阶梯 | 最优 2 步时 A 线（2+2）与 B 线（2×2）是同一条线，**未入门段 B 带不存在**；C 带宽度在 5–12 步之间随机浮动，同一份走法抽到 5 步解是 B、抽到 3 步解是 C |
| 阵眼感应 | 「用一次本盘最高只到 A」 | 免费、不限次、每次直接给出最优解的下一格。**连按到底正好走出最优步数**，拿 A；而诚实推演多走 3 步只能拿 B（×1.0）。辅助不是让出最后段，是比诚实犯错净赚 20% |
| 复原本局 | 容错 | 免费、不限次、步数清零。任何时候按一下就把步数抹平，**预算永不咬人**，阵溃只剩「第一次不知道有这个按钮」 |
| 段位表预算 9/12/16/18/22 | 「够 A，不够乱点」 | 是最优的 3–4.5 倍，C 线（2×）以下才算浪费。旧表里「简单 [2,4]」与「普通 [3,5]」有三分之二的盘重合，**极难与绝境的最优区间完全一样（5–7）**：五段实际只有三段 |
| HUD「已亮 N / M」+ 进度条 | 进度 | 实测 5×5 上 **37.6% 的正确一手会让已亮数变少**。一个会倒退的进度条是反向信息，且玩家会拿它当判据 |
| 死门「整盘复位 + 罚 3 步」 | 加规则 | 用手指精度否掉整盘推演（与「想得久不扣分」冲突）；与「复原本局」撞成两种价；开局第一手误触时盘面一格没变、只少了 3 步 |
| `LEVEL_TIME_KEYS` 里的 `minSteps` | 段内收紧 | 乘 0.7 = 段末要求**更短的解** = 更简单。段内方向是反的，台阶数却因此好看了 |

**修法（已落地）**：

1. 评级换成绝对冗余手数（已走 − 最优）：S 0 手、A ≤2、B ≤5、C 其余、F 满余量。五段宽窄固定为 0/2/3/2，不再随盘变形。
2. 预算按「本盘最优 + 余量」现算，余量 7（段内收到 5，下限 5——再低 A 线与 B 线就重合）。
3. 感应改成**每看一眼算 2 步**，与走错落在同一把尺子上；余量不足时直接挡回，不让玩家点一下就从「还能救」跳到阵溃。
4. 复原本局**每局一次**，仍封顶 A。
5. 死门改成「这一格点不动 + 误触罚 2 步」，不再复位整盘。
6. HUD 撤掉「已亮 N / M」与局内评级徽章，只留「最优 / 已走 / 多走 / 余」。
7. 段位表改成 `size / min / hi / slack`，同尺寸两段的最优区间不重叠；4×4 只保留一段（它是「行追法必成」的尺寸，放后段等于背口诀拿 S）。
8. `minSteps` / `capSteps` 移出 `LEVEL_TIME_KEYS`，段内只收 `budgetSlack`。

**守卫**（这一轮补的，都是原来没有的）：S/A/B/C/F 五段逐段可达（`minigames.test.js`）、相邻两段至少一条轴真动过、条内不许动最优步数、余量压不破 B 带（`rank.test.js`）、HUD 不许再出现「已亮」、感应折步与复位限次（`layout.test.js` / `minigames.test.js`）。

**教训**：这一条的六项没有一项是「某处写错了一个数」，全是**评级这把尺子的形状不对**。静态校验守的是「表里写的和代码里读的是同一个数」，守不了「这个数量出来的东西有没有意义」。判据要往前挪一步：不是「五段参数有没有区别」，而是「五段的结果分布有没有区别」。

| 文档 §2 / §6 | 照纹扣 1 息、死局重排没写代价、点空地视为错配 | 代码是 **−2 息**、重排 **−3 息**（比手滑还贵）、点空地直接 `return` 不罚。「为什么提示只收 1 息」那一整节论证白写了 |
| 盘面 | 6×4 / 6 种 / 12 对 | `makeBoard` 是 `1+(i%6)` 循环，24 格配 6 种 ⇒ 每种永远正好 4 枚，连同纹密度都是常量。可动的盘面尺寸、纹种、折数上限一根都没动 |
| 阶段新法 | 照纹 / 自移「不再扣息」 | 减难度不是加规则；且「重排不扣息」锁在实测 **0.10 次/局** 的事上，解锁了基本看不见 |

**修法（已落地）**：

1. `minigames/link.js` 评级改看**收干净那一刻的剩余息**（S ≥32% / A ≥16% / B ≥4% / C 其余 / 未收干净 F）；分数只记连收手感，不参与评级。关掉 `showGradeNow`，HUD 只报「还差 N 对，S 线要剩 X 息」。
2. `data/practice.js` 加 `LINK_LEVELS`（6×4/4 种 → 8×4/6 种）与 `LINK_BUDGET`（每对 5.50 → 2.75 息，沿 200 关连收），`duration = floor(每对预算 × 本段对数)`；`buildParamsAt` 对这一门跳过 `TIME_LEVELS` 那一刀，末尾统一 `linkDurationAt(关号)` 收口。段界实测每对只减不增（0 处往松走）。
3. `levelDelta` 这一门只报换段 / 换盘 / 换纹种 / 每对时辰，不报换段时变长的总时辰，也不报毫秒级假变化；准备页补一行常驻「本段规格」，免得一局跳四五关把换段跨过去。实测 **39 关真变、160 关沿用上一段**，与 39 关有东西可报对齐。
4. `flashMs` 退役为恒定的 `hintMs`（900ms），不进 `PACE_KEYS`、不进 `LEVEL_TIME_KEYS`；审计的 `boardChanged` 认 `cols / rows / kinds`，`BOARD_TABLE_GAMES` 收 `link`（显式规格表）。
5. 死局自移**不扣息**（罚运气），代价改成「连收断掉」；点空地不罚；照纹 2 息（大成 1 息仍要付），大圆满「双照」一次照见两对，代价当场走浮字不写进看不见的 `vm.status`。阶段新法换成加规则的两条。
6. 玩家文案（`data/guides.js`、`method.tip`）与设计文档、评级表、难度审计、逐门打磨进度全批对齐；旧口径「不再扣息 / 少 3 息 / 按已收对数结算 / 剩余息 ×4」清干净。

**守卫**（这一轮补的）：评级四线逐段可达且 C 带非空、HUD 不许出现「已入 S」、段界每对预算不许往松走、五段必须换规格、`levelDelta` 不许报 `hintMs` / `flashMs`、`hintMs` 必须有生成端与消费端、39 关台阶数下限（`minigames.test.js` / `rank.test.js` / `verify.js`）。

**教训**：与 A8 同源——**「参数在动」不等于「盘面在动」，更不等于「评级在量本事」**。这一门三个层次各坏一次：生成端给了个没人读的 `flashMs`，消费端把「收干净」当成「分数够高」，文档再把两件都不成立的事写成设计依据。修的时候要按「玩家在这一手做对之后该看见什么」倒着查，不能只对照参数表。

## B. 该修：代码里躺着的东西

### B1. 蓄力停区有两支永远走不到的分支 —— **已修**

```js
const width = (hard ? 11 : 16) + (perks.easy ? 6 : 0);
const start = 42 + randInt(30);
const end = Math.min(96, start + width);
```

| 分支 | 为什么走不到 |
| --- | --- |
| `hard ? 11 : 16` 的 `11` 那一支 | 突破局 `difficulty` 恒为 `easy`，`difficultyOf('easy').gear` 恒为 `'normal'`，`hard` 永远 false |
| `Math.min(96, ...)` 的上限 | `start` 最大 71，`width` 最大 22（16+6），`71 + 22 = 93 < 96` |

第二支留着无害（是保险），第一支是**误导**：读代码的人会以为「突破也有难段」，进而去找那个难段在哪，找不到。

修法：把 `hard ? 11 : 16` 简化成常量 `16`，并在注释里写明「突破局只有一段，`perks.easy`（元婴起）是唯一的宽度变化」。或者反过来——如果本意是「元婴之后要有难段」，那就该真的把 `gear` 传进去，这是设计决策，不是清理。

**已修（本轮）**：取前一种。`hard` 变量整个删掉，宽度写常量 `16`；`Math.min(96, …)` 保留但注明它是「留给以后改长度的保险，不是活的分支」（start 最大 71 + 宽 22 = 93 < 96）。

### B2. 滑块让路的复位可以无限次免费用 —— **已修**

`reset()` 原本只清 `moves`，既不清「本盘复位次数」，也不消耗任何预算。玩家可以每走一步就复位一次，慢慢试出通路，然后按一次最优走法拿 S。

`minigames/lights.js` 对同一件事早有处理：用过阵眼感应或重置本盘，**最高只到 A**。两门同类玩法两套规矩，是遗漏而非选择。

**修法（已落地）**：`reset()` 置 `resetUsed`，把原来散在 `syncHud` 与 `finishOnce` 调用处的三处评级表达式收成一个 `gradeOf()`，见 `resetUsed` 就把 S 压到 A；`lines().items` 补第五条「复位过本盘，最高只到 A」，说明页照抄。复位次数仍不限——不限对走死的人是必要的，封顶已经把「反复重来」与「一步没浪费」分开。

**同时修掉的同根问题**：推石入位的 `undo` 把 `pushes` 一起回退（见 A2）。同一漏洞的另一种表现，堵法是「撤销不退推数」。

**守卫**：`tests/minigames.test.js`「按最优步数评级的三门」把阵灯 / 让路 / 入位各跑两遍（干净局必 S、先复位必 A）。

倾向第 1 种：跨玩法行为一致，玩家不用学第二套规矩。

### B3. `index.js` 的 `onBreakthrough` 没有任何绑定 —— **已修**

`pages/index/index.js:196` 定义了 `onBreakthrough`，但 `index.wxml` 里搜不到 `onBreakthrough`。主页境界卡的突破行只显示文字与数值（`突破 战力 45 / 75`），点击不跳转——突破入口在人物页。

这是详情页时代留下来的方法（`pages/cultivate` 已删）。修法：删掉，或改成「点了跳人物页」。留着最差：下一个人会以为主页能突破。

**已修（本轮）**：删掉。主页境界卡只显示数值，突破入口在人物页——`verify` 会守着「事件方法与 js 定义一一对应」，删掉之后两边都干净。顺带说明静态项数从 1301 掉到 1300 就是这个方法少了一条配对检查。

### B4. 审计脚本的 `INTERNAL` 里有三个不存在的名字 —— **已修**

```js
const INTERNAL = new Set(['depth', 'gear', 'sBase', 'sStep']);
```

实测 15 门全部段位的参数键共 50 个，`gear` / `sBase` / `sStep` **一个都不在里面**，只有 `depth` 真的被过滤。`tests/rank.test.js:787` 抄了同一份名单。

修法：收成 `['depth']`，两处同步改。名字挂着会让人以为背后有机制。

**已修（本轮）**：名单收进 `data/practice.js` 的 `INTERNAL_PARAM_KEYS`，审计脚本与 `tests/rank.test.js` 都读这一份——不再两处各抄一遍。

### B5. `recordError('error', error)` 会记成 `[object Object]` —— **已修**

```js
this.recordError('error', error);                        // app.js:83
this.recordError('promise', reason && (reason.message || reason));  // app.js:90
```

`promise` 那支取了 `message`，`error` 那支直接传对象。`recordError` 内部若做字符串拼接，得到的是 `[参悟][error] [object Object]`——真机上排查时这条日志等于没有。

修法：改成 `error && (error.stack || error.message || String(error))`。

**已修（本轮）**：照此改，注释写在 `app.js` 的 `onError` 上（真机上排查全靠这一条，记成 `[object Object]` 等于没记）。

### B6. 界面上「息」与「秒」两个单位混用 —— **已修（改了落点，没改措辞）**

局内文案写「扣 1 息」「换不出少 2 息」，难度说明写「罚 10 秒」（九宫填数、顺序点格）。两者是同一个单位。

约定是「叙事用息、罚时用秒」（`00-foundation/04-voice-and-copy.md`），但玩家读不出这个区分，会觉得是两种计时。要么全用「息」，要么在术语表里明写「本门以息计时，一息为一秒」。后者更省事，也保住了门规口吻。

**已修（本轮）**：选后者，但落点从「术语文档」挪到了**玩家能看到的说明页**——术语表玩家不会去翻。`data/help.js` 的 `practiceTopic()` 新增一节「计时」：「本门以息计时，一息即一秒。罚时写「秒」，与息是同一个单位。」改一处覆盖十五门，比逐条改文案稳。

顺带在这节旁边把「关号往前一关，盘面就紧一分」改成实话：节奏与时辰每关都紧一点，盘面规格挂在本段上，阵灯 / 丹道 / 辨魁 / 阵法这几门隔几关才换一副盘（见 D7）。

### B7. `levels.js` 的 `mixParams` 没有任何调用者，头注释却把它写成段内递进的机制 —— **已修**

`data/levels.js` 里躺着 `mixParams(a, b, f)` + `MIX_KEYS` + `roundBy()`（约 40 行），
作用是把「本段参数」与「下一段参数」按关内进度混合。全项目**没有一处调用**——真正的段内递进在
`data/practice.js` 的 `buildParamsAt()`：本段基准 × 时间与预算收紧三成 + `tweakParams()` 专属旋钮。

比死代码更糟的是它被写进了头注释与两篇文档，读者（包括我）会顺着注释去找「1/8 步长跳规格」在哪，
找到的是一个没人调的纯函数，还顺手把这句话抄进了界面：

```js
if (!d.length) return '第 ' + level + ' 关与上一关规格相同（盘面规格只在关界上按 1/8 步长跳）';
```

**盘面规格不按 1/8 跳，它换段才换一副**（`rawParams(method, ch)` 的段表），段内一字不动。

**修法（已落地）**：删 `mixParams` / `MIX_KEYS` / `roundBy` 与两条导出；头注释改成三步实况
（本段基准 → `LEVEL_TIGHTEN` → `tweakParams`），并把「混合」作为**否决方案**留在
`07-difficulty.md` 第 10 节（离散规格混完取整又退回原值，是最坏的一种假变化）。

**教训**：删掉一个纯函数很容易，难的是删掉「它是机制」这个说法。这次两处都有——代码和界面文案。
所以修的时候不许只删函数：`data/practice.js` 的两条「五关一段」旧注释、`07-difficulty.md` 第 7 节标题、
`05-axis-review.md` 的代码指路一起改，否则下一个人还会照注释去找那台不存在的机器。

## C. 缺口：断言守不住的地方

### C1. 按压反馈的断言门槛是 5 处，实际有 54 处 —— **已修**

`tests/layout.test.js:842`：

```js
assert.ok(total >= 5, '按压反馈覆盖不足：' + total + ' 处');
```

这个断言原本的作用是「新增页面别忘了挂 `.pressable`」，门槛 5 意味着**删掉 49 处也不会红**。它守的是「样式类存在」，不是「覆盖完整」。

修法：改成按页面断言——每个 WXML 至少 N 处，或总数随页面数算（`>= WXML.length * 2`）。硬写一个更大的固定值（比如 40）只能拖时间，加页面时又要改。

**已修（本轮）**：三条一起：① 每个页面至少 1 处；② 四个主交互页各给下限（index 4 / practice 12 / profile 6 / skills 3，按现状留两成余量）；③ 总数 `>= 页数 × 3`（现 54 / 12 页）。

**顺带查出计数本身是错的**：原来用 `/<view[^>]*hover-class="pressable--on"[^>]*>/` 切标签，而 `practice.wxml` 里有 `wx:if="{{a > b}}"` 这种含 `>` 的标签，一漏就是 11 处（practice 报 7、实际 18）。现在按「出现次数」数，另配一条「class 里含 `pressable` 的处数 ≥ hover-class 的处数」。

### C2. 隐私守卫只数 `guard(`，不数 `ensure(`，且只覆盖两页

`verify` 的隐私段按「调用数 ≤ 守卫数」核对剪贴板调用，但：

- 只数 `wx.setClipboardData` / `wx.getClipboardData` 这类显式调用，`privacy.ensure()` 的调用点不在核对范围；
- 只扫 `pages/secret` 与 `pages/battle` 两页，其它页面若新增剪贴板调用不会被发现（`pages/profile` 的存档码、`pages/board` 的战力码都在别处）。

修法：改成扫全项目 `wx.setClipboardData|getClipboardData|chooseAvatar` 的出现，逐处要求同一函数体内有 `guard(` 或 `ensure(`。

### C3. 15 门功法的 id 在两张表里没有一一对应断言 —— **已修**

`data/skills.js` 的 `PRACTICE_METHODS`（功法）与 `data/practice.js` 的 `PRACTICE_METHODS`（玩法）是两份独立列表，靠 `skillId` 关联。没有断言检查「`skills.js` 的每个 `practiceId` 都能在 `practice.js` 里找到」，也没有反过来的检查。

漏一个的后果是：功法在谱系里显示「未习得」但点进去准备页拿不到参数，或者反过来——图鉴里有、参悟页白屏。这类错 `check` 全绿也拦不住。

修法：在 `verify` 里加一段双向核对（与页面注册那段同一个套路）。

**已修（本轮）**：`verify` 8b-8 段。字段名核对清楚了——关联键是 `skills.js` 的 `method`（不是虚构的 `practiceId`）。双向都查：每门功法的 `method` 必须能在 `PRACTICE_METHODS` 里找到，每种玩法也必须至少被一门功法引用（「做了没人用」）。共 38 项。

### C4. 审计不校验「参数被注入后有没有被玩法读走」

`buildParams` 注入 `hearts = 2`，`mines.js` 若不读，审计照样判「过」。目前靠 `tests/rank.test.js` 逐门复算兜——但那只验算参数值，不验「参数在盘上生效」。

这一条**短期内无法用静态断言解决**（要跑游戏、读 vm），记在这里是让下一个人别以为「审计过了就等于参数生效了」。

### C5. 裸色值白名单是手工维护的

`styles/tokens.wxss` 之外写裸色值要进白名单（12 个文件）。新增一个带盘面色板的玩法时，容易忘了把文件加进白名单——或者反过来，加了白名单却没人核对它是否真的需要例外。

修法：白名单条目加一句理由（`// 盘面色板由 minigames/theme.js 注入`），并在 `verify` 里要求每条白名单都有一行注释。弱约束，但能让人停下来想一秒。

## D. 待拍板：两种做法都成立

### D1. 身法这项属性要不要存在（见 A1）

改代码让 30 点 = 1%，还是承认它在中前期不生效、重新设计出口。**这是本文档里唯一需要先定方向再动代码的一条。**

### D2. 数格辨禁的评级时间线要不要随段收紧

### D3. 顺序点格的五段挤在同一个 6×6（已修）

~~困难 34 秒 > 极难 32 秒，是「盘面在小成段跳到 36 格后不再变」的副作用，是否压 `PER_CELL[2]`。~~

压在 `PER_CELL` 上只把反向差挪到别处——只要两段同盘面、只靠秒表，反向差必然复现。

见 `50-balance/03` 特例三与 `20-minigames/16-遍观毫厘诀/`。

### D4. 灵石缺口靠重复切磋补，要多少场

全盘一次性收入 466 枚 vs 需求 783 枚，缺口 317 枚靠切磋（首胜 8 枚 + 当日衰减）。衰减取的是「当日第几场**胜利**」，而文案例写「当日第 n 场」——连败不消耗衰减额度。这是有利的松绑还是文案该改，未定。见 `10-systems/01-currency.md` 待验第二条。

### D5. `GRADE_DIST` 从未用真机校准

所有成长曲线结论（10000 局 / 84 局 / 6000 点预算五个方案）都建立在 `GRADE_DIST` 这张假设的评级分布表上。真人打出来的 S 率若与假设差一倍，`84 局毕业` 就变成 `42 局` 或 `168 局`。

这一条不阻塞开发，但它决定了 `50-balance/01-progression-curve.md` 里**每一个数字的可信度**。校准方法：找 5–10 个人各打 20 局，记录评级，替换分布表，重跑 `npm run sim`。

### D6. 「套壳」：玩法与功法之间还没有必然联系

有人玩过之后的原话是「一堆小游戏套了个修仙壳」。这个判断可以用一条测试复现：

> **换皮测试**：把 15 门功法的名字全换成「第 1 关…第 19 关」，玩法体验会不会变？
> 变了 → 玩法与设定有必然联系；不变 → 换了皮也不影响，那就是壳。

现在这条测试**在盘面上仍然通过**，但切磋 / 秘境这一路已经不通了（见下方「已补的第二半」）。盘面上的三处证据：

| 位置 | 事实 |
| --- | --- |
| `pages/practice/practice.js` | `qi` 只在准备页扣一次、结算显示一次；局内的 `onHint / onUndo / onReset` 直接调 controller，一分气不花、次数不限 |
| `utils/game/realm.js` | 境界只进 `power / bonus / qiCap` 三个字段，筑基与元婴玩同一门功法，盘面规则一字不差 |
| `minigames/*.js` | 每门玩法都是完整信息的纯技巧游戏：三秀撷英诀想的是「哪三连」，洞微勘禁诀想的是「哪个有雷」——这些判断换到任何主题下都成立 |

**已经补上的那一半**（表现层，不改玩法）：练功 → 战力 → 破境 这条链原来只有系统知道，现在四处同源地说出来——功法页「再练到入门：战力 +4」、结算「战力 45 → 49（+4）」、主页「还差 30 · 星罗烛天诀到入门 +8」、人物页破境卡同一句。见 `10-systems/10-power.md` 第 4 节。

**已补的第二半**（机制层，2026-11-15）：**本场运功 —— 功法第一次真正出场**。

在此之前，功法对切磋的全部影响是 `effectValue('power')` 把所有 power 类特技加成一个百分比塞进 `rollBattle`：十五门全自动叠加，玩家看不见任何一门出场，十门「非战斗」功法（灵力上限 / 省气 / 回复）在切磋里彻底隐形。

现在：十五门各炼成一式（`data/moves.js`），一场至多运三式，**选中才生效**，结算卡上逐条落位并显示 `运功前 151 → 运功后 181`。三类对应三个出手时机——起手抬战力、守势抬波动下限、养息抵灵力（封顶 3 点，永远不能白打）。

这条改动让换皮测试在**对战这一侧失效**：现在得先想清楚带哪三式，而「带哪三门」正是「我练的是什么」的函数。但它**没有**动 15 门盘面本身 —— 所以下面那半仍然欠着。

**已补的第三小块**（盘面层的第一步，2026-11-15 第二轮）：**移石归阵诀的石图改成每局现抽**。

原来五张手排图按段分配，未入门段永远第一张——第三遍开始玩家记的是答案，不是走法。这不算「套壳」，但它让换皮测试更容易通过：一门玩法如果打到第三遍就只剩回忆，那它本来就只有一层壳。
现在段位只给规格（内盘 4×4→5×5、阵位 1/1/2/2/3 处、内墙 0/1/1/2/2 道、最优推数区间），图由生成器**从解反向拉**出来，所以每局都可解、每局都不同。十五门里只有它按段分配固定图（其余都是随机布盘），所以也只改了它。见 `20-minigames/18-移石归阵诀/`。

这一条**不解决** D6 本身（玩法规则仍不来自设定），但它补上了盘面层的第一块：**可重复挑战 ≠ 同一张盘重复**。

**仍欠的那一半**（盘面层，最硬的那一半）：让玩法规则本身由修仙设定决定。样板：

- 三秀撷英诀 → 加「灵田地力」：每格连收三次地力枯，继续收只给半分，三回合才回满。玩家于是会**不消最划算的那一处**——这个决策在任何非修仙主题下都荒谬。
- 洞微勘禁诀 → 加「神识」：标一处禁位扣 1 点神识，标错扣 3 点，神识尽了你还能翻格但不能再标。

代价：15 门都要重设计一条规则，且与「三套经典玩法是黄阶入门功课、看一眼就会玩」的定位有冲突（黄阶本来就不该有新花样）。

**未定**：做不做、做几门、还是接受「经典玩法 + 修仙语境」这个定位并把「套壳」当作已知取舍。这条不阻塞开发，但它决定了这个产品到底是「修仙题材的小游戏集」还是「修仙游戏」。

**当前判断**：盘面层暂不动。理由是「黄阶三套经典玩法看一眼就会玩」是刻意定位，往盘面上加第二条规则会同时破坏「一次参悟 3–10 分钟」的节奏与「黄阶没有新花样」的品阶语义。**如果将来要动，从三秀撷英诀（灵田地力）与洞微勘禁诀（神识）这两门起**，它们是「三消 / 扫雷」最容易被说成套壳的两门，做完拿真机手感说话，再决定铺不铺开。

那是 v9 之前按「段」而不是按「关」收紧时算的，已作废）。

| 162 / 161 | 太虚照见诀 / 移星换斗诀 |

并蒂连枝引已从 44 补到 59：段内加了「布纹」变体（每种纹各有几对随段内进度偏斜，每段 3 级），
盘面肉眼可辨，段首与段末不再是同一副牌阵。这是方向 1 的第一门落地，其余门仍按上表读。

两个口径的差就是「参数动了」与「玩家看得见」的差——后者才是玩家的实际体验，也是各门文档
「N 关真变」现在引用的那个数。**吐纳周天诀 1000 关里只有 5 关有东西可报**（四次换段 + 一次
手数变化），它的段内收紧全在毫秒上，而这一门刻意不报毫秒。这是 D11 里最刺眼的一行。

2026-11 退役四门（叠纹凝露 / 五灯相生 / 截锋断岳 / 踏云连环步）之后，这张表少了 300 / 245 / 124 / 35
四行；「十五门 × 三段 = 五十七处」相应变成「十五门 × 三段 = 四十五处」。

两个方向：

1. **加内容，不加数字**：每段新增一条规则或一副盘（已定的规矩是「阶段新法加规则，不是减难度」）。
   十五门 × 三段 = 四十五处，这是真工作量，但也是唯一能兑现「1000 关」的说法。
2. **把关数收回去**：按每门能真正做出多少级台阶，给每门不同的关数（例如 14 级的阵灯只有
   十几关的线）。代价是玩家看到「十三门 300 关、六门 1000 关」，且段界不再统一。

暂定方向 1，按门逐批补；在补完之前，`07-difficulty.md` §3 那张表就是官方口径，
不许在别处把它写成「每关都不一样」。

## D12. 回关折减改成两把尺子（已修）与它管不到的半截 —— **待拍板**

**已修：折减只有一把尺子时，回关同时省了段位的气。**
`levelFactor` 原来只算 `本关 ÷ 本门当前关`。这按「走通必推一关」推出「停在某一关反复刷不可能」——
但**打一条已走通的关也算走通**，`当前关` 就钉死不动了。于是折减一直停在 ×0.95 上下，
而耗气按本关所在段报（未入门 7 / 圆满 32，差四倍半）。实测 `scripts/simulate.js`：
同样 6000 点灵力、随机评级，停在低段反复刷 11551 点熟练度，一路推进只有 6399 点。
这条护栏从 v9 提交（`29e6273`）起就是空跑的——那次把 `runBudget` 的刷法名从 `easy/below`
改成 `first/half`，却只把策略表里的第一项改成了 `novice`，两个名字都落进 `else` 分支，
于是「只刷第 1 关」「退一章」两条曲线都被算成了「逐关进」，三条一模一样，断言永远成立。

现在 `levelFactor` 再乘一道 `本关所在段基数 ÷ 当前关所在段基数`。同段回关时这一项恒为 1
（段内手感不变），跨段才收第二刀。改动同批同步了 `tests/rank.test.js`、`scripts/simulate.js`、
根 README 与指南第六节。

**它管不到的半截：同一段内「停在原地刷上一关」仍然不亏。**
折减是**局部**保证：同一个当前关下，回打更低的关永远不比打当前关划算（`sim` 现在守的就是这条，
cur = 2 / 21 / 200 / 800 四档逐档复算）。但**全局**不保证——段位耗气涨 4.5 倍、熟练度基数一动不动，
所以任何「停在低段反复刷」都比一路推向圆满段更省（1.93 vs 1.07 点/灵力）。这不是折减漏了，
是段成本曲线的形状。三条出路：

1. **抬高连 S 的分量**（现成手段）：连 S 只在本门当前关叠、回关不叠，所以真会打的人推进收益远高于刷。
   可以把这条写得更显——准备页与回关提示各说一句「回关不叠连」。
2. **压平段成本曲线**（7 / 11 / 17 / 24 / 32 → 更缓）：这会让「难盘更贵」这条设计松动，
   且 D11 里「段越后越贵」的文案要跟着改。
3. **接受它**：把「只刷低关」当成一种慢速保底，反正刷不到大圆满（11551 离 99999 很远）。
   代价是「推进更优」这句话在随机评级下不成立，文案不许再这么写（指南第六节已据实改成
   「真正的回报在连 S」）。

暂定方向 1 + 3：先按现状把话说实，动数值等真机手感回来再定。

## D15. 三秀同收加了必需演出，66 息里少掉一块 —— **待真机标定**

2026-11-17 把一手拆成三拍（留空 170ms → 落下 120–250ms → 再查一轮），并锁输入到落定为止。
此前 `resolve()` 是一个同步 while，跑完才渲染一次——玩家可以在「牌还在动」的时候直接点下一手，
演出不占操作窗口；现在是占的，而且必须占（空格帧里盘面真的缺牌，点上去就是错手）。

估算：一手 290–420ms（取中 350ms），S 线 1750 分按一手三连 36 分算约需 49 手，
合计约 17 秒——66 息里的 26%。同样手速，`S` 会比以前难一档。

**没有擅自改 S 线。** `MATCH_LEVELS` 那五条线是按 v9 实测标的，改一条等于让那批实测作废。两条路：

1. 真机打 10 局，记每局分数分布，重标五条线（首选：顺便把这门从没做过的真机验收做掉）；
2. 把 `BEAT` 再压到单手 250ms 以内——空格帧 170ms 已经是「看得见」的下限，能压的只有落下，
   缺口从 26% 收到 18% 左右。

判据：跑完要能回答「这一段的常人还拿不拿得到 B」。拿不到就是改了手感没改线——
玩家会觉得「明明打得更准，反而降级了」。

同一条也适用于将来任何「把一帧的结算拆成分段演出」的改动：**限时玩法里，演出时间是玩家
的时间**。停表不成立（手快的人拿动画换时间，一局打不完，实测过），只能算进线里。
