# 产品定位与体验目标

> 一句话：**一个用「修行」包装的养成 + 小游戏微信小程序——你把灵力烧在一局一局的参悟里，换熟练度、换战力、换境界，顺手和人切磋。**

## 1. 它是什么

| 维度 | 取值 |
| --- | --- |
| 载体 | 原生微信小程序（非 H5、非 Unity） |
| 题材 | 修仙 · 青云界（单世界生效） |
| 核心动词 | **参悟**（打一局小游戏）、**闭关**（养灵力）、**切磋**（换灵石）、**破境**（抬上限） |
| 单局时长 | 30–90 秒（多数玩法 13–68 秒限时） |
| 单次会话 | 3–10 分钟（约 2–6 局 + 一次收菜） |
| 长线目标 | 把 19 门功法练到 99999 熟练度；境界推到元婴；19 门全收 |
| 商业化 | 无。没有内购、广告、体力售卖 |

**不是**「小游戏合集」。19 门玩法是同一套养成的输入端，不是 19 个独立小游戏拼在一个壳里——每局都扣同一池灵力、产出同一种熟练度、喂同一套境界与战力。

## 2. 目标玩家

**主画像：** 喜欢轻度策略与解谜、能接受「一天来两三次、每次几分钟」的碎片节奏，对修仙叙事有好感但不要求硬核文本量的玩家。

**适配的场景：** 通勤、睡前、等餐；有耐心看盘面、不追求手速极限。

**不适配的场景：** 想在地铁上打 15 分钟不间断操作的；想靠操作技巧压过数值的；期待实时对战的。

**这条画像决定了三件事：**

1. **盘面必须「看一眼就会玩」**。十九门里九门是经典盘面（连线、落石、消消乐、九宫、合数、顺序点、滑块、推箱、取大），规则一句话；其余十门也都能在十秒内看懂目标。规则复杂 ≠ 深度，深度应该来自「省步数」「不断连」这类可重复挑战。
2. **不能靠手速卡人**。限时是有的，但最短一档（绝境 13 秒的顺光扫斩）也是「够看清再动手」的量级；难度靠收紧判定窗与抬高评级线，不靠让人来不及反应。
3. **随时能走**。任何一局都能主动收功，不弹「确定放弃奖励吗」的挽留；闭关是「回来收」而不是「放着涨」，因为玩家不需要为了效率把小程序挂在后台。

## 3. 三层核心循环

### 微循环（一局，30–90 秒）

```
选门 → 选难度（默认本门最高已解锁） → 扣灵力开局 → 打一局 → 评级 S/A/B/C/F → 进熟练度
```

一局只回答一个问题：**这一局我打得怎么样。** 局内 HUD 只报「下一条线还差多少」，四条线全貌在说明页——一屏塞四条会挤掉第一局真正要读的东西。

### 中循环（10–30 分钟 / 一个段位）

```
熟练度累积 → 跨过 300 / 1500 / 6000 / 24000 → 解锁下一档难度 + 段位加成 + 阶段新法 + 特效兑现比例
```

关键设计：**升段不是「同一件事变难」，而是「这件事本身变了」**。静心记诵诀小成后可以「抢记」（长按少看几个字，赌记忆换倍率），大成后奇轮要倒着点；点灯破阵诀大成后盘上多一格不能碰的死门。`data/practice.js` 的 `STAGE_RULES` 是这份规则的登记处。

### 宏循环（天 / 周）

```
闭关养灵力（0.5/分，装进气海）→ 参悟烧灵力换熟练度 → 熟练度抬战力 → 切磋赢灵石
   → 灵石买功法 / 布阵破境 → 境界抬气海与战力 → 一趟能练更多局 → 回到闭关
```

这条环有一个**咬合点**：灵力和灵石都从「时间」来，但去向不交叉。参悟只烧灵力、不产任何资源；灵石只能从切磋与秘境挣。所以玩家的时间永远在两种用途之间做选择：**练功（消耗灵力换熟练度）还是挣盘缠（消耗灵力换灵石）**。两条路都消耗同一池灵力，这就是这个游戏唯一的资源决策。

## 4. 体验目标

按优先级排序，冲突时上位压倒下位。

| 优先级 | 目标 | 具体含义 | 反例（明确不要） |
| --- | --- | --- | --- |
| 1 | **一眼看懂现在该做什么** | 主页首屏只有「境界卡 + 六宫格 + 一行提示 + 一个主按钮」，提示永远是「去练哪门」这一句 | 首屏出现眉标、说明句、页脚口号、公式 |
| 2 | **国风沉浸，不像小程序** | 恒定深色墨底 + 一支旧金；文案是门规口吻（「另择一门」「暂且退去」） | 出现「小游戏」「页面」「资源」「收益」「通关」等产品词 |
| 3 | **每一局的钱都花得明白** | 开局前就在按钮上写清耗多少灵力、余多少；结算写明扣了多少、不退 | 打完才告诉玩家「其实你没钱」 |
| 4 | **努力有可见回报** | 特效按段位兑现（入门 25% → 圆满 100%），每升一段面板上都有变化 | 「练到大成才有特效」——中前期等于白练 |
| 5 | **不惩罚离开** | 无日常任务链、无连续登录奖励、无「体力不足请明天再来」；闭关回来后一键收 | 用 FOMO 制造回访 |
| 6 | **解释放在点进去之后** | 首屏只留标签 + 数值 + 按钮；长解释在右上角「说明」按节折叠 | 一屏铺满规则 |

第 2 条是本项目最容易被破坏的一条。判据只有一句：**「这个词会不会让玩家意识到自己在用一个小程序」**。「这一局」可以留（棋局），「这一门」必须改（口语省略），「小游戏」必须改成「盘面」。

## 5. 明确不做（以及为什么）

| 不做 | 原因 | 曾经想做的诱因 |
| --- | --- | --- |
| 实时 PVP | 小程序端做同步对战要长连接 + 房间服务，成本远超收益；现方案是「上传战力 + 镜像对战」（`data/opponents.js` 的 7 位预设 + 战力码） | 「切磋」听起来该是真人对打 |
| 付费 / 内购 / 广告 | 未发布、无版号、无支付资质；且一旦有内购，「灵力上限」这类设计会立刻变成付费点，整套节奏会被污染 | 挂机游戏通常靠加速道具变现 |
| 多世界 | 科幻 / 都市两套只有元数据；每套要 19 门功法 + 19 套玩法，是重做而不是扩展 | 世界观切换听起来很有想象力 |
| 微信头像 | `chooseAvatar` + 云存储 + 签名 URL + 内容安全检测 + downloadFile 域名，五份成本换一个小圆头像；形象已由 `components/portrait` 的 CSS 道相承担（6 个编号） | 社交产品默认都要头像 |
| 浅色主题 | 恒定深色是沉浸的前提；两套主题会让每次改样式都翻倍，且盘面「纸」的对比关系会被打破 | 系统深色模式该被尊重 |
| 无代价的辅助 | 用了提示还宣称 S 不公平。要么不给，要么把代价写在按钮上（点灯破阵诀「阵眼感应」封顶 A） | 新手需要帮助 |
| 首屏说明书 | 与第 6 条体验目标直接冲突 | 「规则这么复杂，不解释玩家怎么懂」 |
| 攻略式长文 | 解释性内容一律进 `data/help.js` 的折叠节与 `pages/guide/`，不进主页面 | 设计者总想解释自己的设计 |

## 6. 成功判据

不写「留存 40%」这类拿不到的数。以下是**在仓库内可验证**的判据：

| 判据 | 门槛 | 验证方式 |
| --- | --- | --- |
| 一门功法从开局到入门 | ≤ 3 局（S 34/局，300 需 9 局；全 C 需 30 局） | `npm run sim` |
| 从零到 99999 的极端路径 | 全 C 10000 局 / 全程不断 S 且都打最高档 84 局 | `npm run sim` 两条曲线 |
| 一局的实际代价 | 6–27 点灵力（剑法五档实价） | `simulate.js` 耗气表 |
| 灵力自给能力 | 炼气气海 174 点 ≈ 困难档 12 局；气海 5.8 小时坐满 | `game.qiCap` + `idle.qiPerMinute` |
| 首屏字数 | 主页面首屏不出现说明句（黑名单断言） | `tests/layout.test.js` |
| 十九门玩法不重复 | 玩法内核、盘面、交互、胜负规则四者至少三项不同 | `tests/minigames.test.js` |
| 每条硬约束有守卫 | 1290 项静态 + 288 项 Node 断言 | `npm run check` |

## 代码指路

- `app.json` —— 页面注册、tabBar（三个 tab：主页 / 功法 / 人物）
- `data/navigation.js` —— `TAB_ORDER` / `TILES` / `PAGE_TITLES` / `HELP_TOPICS`，信息架构真源
- `data/world.js` —— `intro`（开场一句）、世界元数据、境界与属性
- `data/copy.js` —— `SHARE`（分享一句）、`TERMS`（术语词典）
- `README.md` 的「当前边界」—— 已验证 / 未验证的真实清单，比任何宣称都可靠

## 待验

- 「一屏放得下」在 4.7 寸屏是否成立：主页境界卡 + 六宫格 + 吸底条、参悟准备屏（印 + 修为 + 一行规则 + 难度条 + 折叠新法）。所有「一屏」结论目前只有静态断言（元素存在与顺序），没有真机截图证据。
