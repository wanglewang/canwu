# 文案口吻规范

> 判据有两句，先过后一句再看前一句：
>
> 1. **今天会不会有人这么说？** 不会 → 换掉。
> 2. **这个词会不会让玩家意识到自己在用一个小程序？** 会 → 换掉。
>
> 第 1 条是 2026-11 补的。此前只守第 2 条，于是把「暂且退去」「留于此处」「容再思量」「另择一门」当成门规口吻写了进去——它们确实不像小程序，但也不像今人说话。**本作是现代背景的修仙，不是古代修仙**：设定名词可以古，句子不行。

---

## 一、口吻：现代汉语，修仙名词

**说话的人是这座山门，但用的是今天的白话。** 分界线只有一条：

- **设定名词照旧**：功法、境界、灵力、灵石、气海、火候、段位、盘面、玉简——它们是这个世界的东西，换了就出戏。
- **评级与退出不用设定词**：F 写「失败」，不写「走火」；中途退出写「结束」，不写「收功」；合出目标块写「完成」。玩家要的是结论，不是一记需要查词典的暗号（2026-11 定）。
- **句子、动词、按钮、状态一律白话**：不写「方可」「方能」「尚未」「无从」「且去」「便」，不写倒装与省略主语的仿古句。

| 场景 | 写（现代汉语） | 不写（仿古） |
| --- | --- | --- |
| 换一门练 | 换一门 / 换一门功法 | 另择 / 另择一门 |
| 退出当前局 | 退出 | 暂且退去 |
| 打完一局还想打 | 再来一局 | 再参一局 |
| 结算后停在原屏 | 留在本页 | 留于此处 |
| 关掉开局倒计时 | 暂不开始 | 容再思量 |
| 跳过教学 | 跳过指引 | 略过指引 |
| 境界不够 | 要「金丹」境界才能修炼 | 需「金丹」境界方能修习 |
| 榜单无数据 | 暂未上榜 | 尚未上榜 |
| 空记录 | 暂无记录，可先参悟一局 | 尚无动静，且去参一局 |
| 空榜单 | 榜单暂无记录，参悟一局就能上榜 | 榜单尚空，斗一场便留名 |
| 冲关失败 | 突破失败，布阵的灵石散了 N 枚 | 气机一乱，未能突破 |
| 一局没走完 | 失败（F） | 走火（F） |
| 中途退出本局 | 结束 / 中途结束 | 收功 / 中途收功 |
| 合出目标块 | 完成 | 收功 |

**代词用「本门 / 本局 / 本页」。** 不写「你这一门」「玩家」「用户」。「本页」只在真的指这一屏时说（「留在本页」「本页说明」），不拿它指代功能或模块。

例外：「这一局」可以留。它是「棋局」的量词，不是口语省略——「这一局打得不错」在今天也成立。但「这一门」不行，它把「功法」省略成了量词短语，读起来像产品在说「这个功能」。

**「古风」不是护身符。** 写「道友请留步」也算古风，但很土；写「暂且退去」也算古风，但今天没人这么说话。这两句都不许进按钮。

**「口语」也不是解法。** 按钮与状态词取中性书面语，不取聊天口吻：「暂不开始」不写「再想想」，「暂未上榜」不写「还没上榜」，「暂无记录，可先参悟一局」不写「还没有记录，先去打一把」。判据是：**这句话贴到别人的 App 里也成立吗**——成立就对了。

## 二、四族必改词

### 第一族：口语代词与省略

| 旧 | 新 |
| --- | --- |
| 这一门 | 本门 / 本门简介 |
| 这一门的新法 | 本门新法 |
| 页面 / 界面的功能名 | 去处 / 这一屏（说位置时才用「本页」） |

### 第二族：产品与技术词

| 旧 | 新 | 为什么 |
| --- | --- | --- |
| 资源 | 灵力 / 灵石（分开写） | 「资源」是策划词，玩家不这么说话 |
| 手感 | 火候 | 「手感」是体验设计词 |
| 小游戏 | 盘面 | 玩家在「参悟」，不在「玩小游戏」 |
| 卡片 | 玉简 | 界面物件要用世界观里的东西命名 |
| 个人页 | 道牒 | 同上 |
| 燃料 | 运功的根本 | 「燃料」是引擎词 |
| 技能特效 | 功法特效 | 「技能」是游戏系统词 |
| 通关 | 走通 | 「通关」是关卡制游戏词 |
| 点一下 | 轻点 | 「点一下」是操作说明，不是门规 |

**「收益」与「所得」并用，不作禁用**：结算、份例等按评级给东西的地方用「所得」（走 `copy.formatGain`，先气后石、为 0 不写）；玩法失败提示沿用各 `minigames/*.js` 的 `fail` 文案「本局没有收益」。两句都是门规能说的话，不必强行统一——约定只禁会让人意识到「在用小程序」的词，「收益」不在其列。

### 第三族：现实游戏名（正名自造，文案可提）

俄罗斯方块、2048、消消乐、数独、华容道、推箱子、连连看、舒尔特方格、扫雷、找最大数……

**分两层看，别一刀切。反对它们的理由从来不是「违法」**——这类词大多已是通用品类名，
拿它描述玩法谁也拦不住你（《商标法》第 49 条：注册商标成为核定商品的通用名称可被申请撤销）；
真要踩线的是照抄某一款的美术、界面、关卡数据与音乐，跟说出这四个字无关。
理由是**调性**：满屏「数独 / 扫雷 / 消消乐」会把修仙打回小游戏合集，玩家一进门就认定这是搬运来的合集。

| 层 | 规矩 | 例子 |
| --- | --- | --- |
| **正名层**：功法名、玩法名、说明页标题、准备页与结算的系统标签 | **一律自造**，一个品类词都不许有 | 「并蒂连枝引」不是「连连看」，`gameName` 是「灵纹连线」 |
| **口语层**：人物口吻的句子（`flavor`、对白、玩家心里话） | **可以点出来**，但一门最多一句，且必须是在认梗、不是在命名 | 「师父说这叫并蒂，你觉得这叫连连看。」（`data/skills.js` 的 `lingqi`） |

口语层那句不违规也不伤人——它把玩家心里的话说了出来，反而比假装这个品类不存在更可信。
两条约束：① 只能出现在人物口吻里，**系统播报与按钮上不许有**；② 一门最多一句，
不许拿它当「替这门的玩法做说明」的捷径，玩法怎么玩归 `data/guides.js` 与说明页。

正名对照（旧表沿用，只是「不许出现」的范围收到正名层）：

| 现实名 | 本门正名 |
| --- | --- |
| 扫雷 | 数格辨禁 |
| 消消乐 | 三秀同收 |
| 数独 | 九宫填数 |
| 2048 | 滑格相合 |
| 俄罗斯方块 | 落石垒基 |
| 连连看 | 灵纹连线 |
| 华容道 | 滑块让路 |
| 推箱子 | 推石入位 |
| 舒尔特方格 | 顺序点格 |
| 找最大数 | 数中取大 |

技术注释、文档、代码注释里随便写（方便维护者理解），**玩家可见的正名与系统标签里一个都不许有**。


### 第四族：与既有真源冲突的表述

| 旧 | 新 | 原因 |
| --- | --- | --- |
| 神品 | 绝佳 | 与 `GRADE_TITLE` 的 S = 绝佳冲突 |
| 一局 3.2 倍熟练度 | （删除） | 品阶不加速熟练度，这是错的口径 |
| 大成起才有特效 | 按段位兑现（入门 25% → 圆满 100%） | 旧规则已退役 |
| 三连 S 晋级 | 连 S 叠倍率 | 旧机制已退役 |

## 三、三处真源与各自边界

文案不许「想到哪写哪」，因为改一次要翻五个文件、术语一改就漏。三层分工：

| 真源 | 管什么 | 形态 | 谁取用 |
| --- | --- | --- | --- |
| `data/copy.js` | 状态、通用按钮、区块标题、术语、品牌标语、单位格式化 | `UI.actions` / `UI.sections` / `TERMS` / `GRADE_TITLE` / `SHARE` | 所有 WXML 的 `{{copy.xxx}}` |
| `data/help.js` | 解释性长文（说明页 7 个主题，分节折叠） | `HELP_TOPICS` + `practiceTopic()` 现拼 | `pages/help/` |
| `data/guides.js` | 玩法规则（目标、步骤、术语、评级口径） | 按 `methodId` 索引 | 准备页一行规则 + 说明页 |

**边界不许越**：

- WXML 里不许抄字面量（现有欠账约 105 处，主要在 profile / battle / practice 的区块标题与按钮，见 `50-balance/04-open-issues.md`）。
- 玩法规则不许写进 `copy.js`（它属于 `guides.js`）。
- `pages/practice` 的说明 topic 不许塞进静态 `HELP_TOPICS`——它必须由 `practiceTopic()` 按功法现拼，`verify` 守着。

## 四、格式约定

### 数字

- **局内代价句用阿拉伯数字**（「扣 1 息」），不写「扣一息」。断言守着。
- 数值表与文档里的数值必须可复算：写 `7 / 11 / 17 / 24 / 32`，不写「七到三十二」。
- 百分比统一带 `%`；倍率统一带 `×`，最多两位小数（`×0.50`、`×2.60`）。
- 折减系数要能显示 `×0.0625` 这类四位小数——`toFixed(2)` 会把它写成 `×0.06` 骗人，所以用 `factorText()`。

### 单位

- 时间在局内叙事里叫「息」（一息即一秒）；具体罚时写「秒」（「罚 10 秒」）。两种写法同义，说明页的「计时」一节会明写一次（改之前只有文档知道，玩家读不出来）。
- 灵力、灵石的单位是「点」与「枚」：灵力论「点」，灵石论「枚」。
- 熟练度不带单位，直接写数。

### 组合句式

- 所得用 `copy.formatGain(qi, stone)`：**先气后石，为 0 不写**。不许各页面自己拼「+60 灵力 +8 灵石」。
- 消耗用 `copy.formatCost()`，同理。
- 衰减用 `copy.decayText()`（当日第 n 场 ×0.85…），不许各页面自己算。

## 五、分享文案

`copy.SHARE` 一句一页，前缀由 `utils/share.PREFIX` 加：

| key | 文案 |
| --- | --- |
| `skills` | 十五门功法，每一门都是一路修法 |
| `board` | 战力仙榜，来看看你排第几 |
| `titles` | 称号簿：修行路上攒下的名号 |
| `log` | 修行日志，一局一记 |
| `help` | 修行指南：规则与术语都写在这一页 |
| `practice` | 我在参悟《{skill}》，所修的是「{game}」 |

三条硬规则：

1. **除登录页外每一页都要接 `onShareAppMessage` / `onShareTimeline`，且落在自己那一页**。子页分享不许送回首页——那等于把刚看的东西丢了。
2. 参悟页分享必须带 `?skillId=`，说明页必须带 `?topic=`。`verify 1d` 逐页守这两支方法与参数。
3. 分享卡标题不写「快来玩」这类招揽语。

## 六、写新文案的流程

按顺序做，不许跳步：

1. **先判断归属**：状态/按钮/标题 → `copy.js`；长解释 → `help.js`；玩法规则 → `guides.js`。三处都不合适，说明这条文案不该存在。
2. **过判据**：读一遍，先问「今天有人这么说吗」，再问「这会不会让玩家意识到自己在用小程序」。任一为否 / 是就重写。
3. **查旧词**：对照 `03-glossary.md` 第七节的禁用表，以及 `tests/layout.test.js` 的黑名单数组。
4. **补断言**：新增或改动的关键文案，在 `tests/layout.test.js` 里加一条断言。**没有断言的文案等于没有规范**——下一次改动必然漏。
5. **同步 README**：`README.md` 里「当前事实」型的引用（按钮名、章节名、术语分组）要跟着改；历史叙述保留原文。
6. **跑校验**：`npm run check`。文案改动最容易连带打挂布局断言。

## 七、反面清单（写文案时逐条对照）

- ❌ 「这一门功法很有趣，快来试试吧！」——两个破绽：这一门、招揽语。
- ❌ 「点击开始按钮开始游戏」——技术说明口吻。
- ❌ 「小游戏加载中」——「小游戏」。
- ❌ 「你已解锁困难难度，可以挑战更高难度的俄罗斯方块了」——系统播报里拿现实名当正名 + 第二人称。
- ❌ 「温馨提示：灵力不足时可以去闭关恢复哦～」——「温馨提示」「哦～」。
- ❌ 「暂且退去，容再思量」——今天没人这么说，换成「退出 / 再想想」。
- ✅ 「灵力不足：本局要 14 点，还差 6 点。回洞府闭关一会儿就能补上。」——说清差多少、去哪补，不加语气词。
- ✅ 「本局作废，不计所得；连 S 归零，起手耗去的灵力不退。」——代价写在玩家付出之后、下一次付出之前。

## 代码指路

- `data/copy.js` —— `UI` / `TERMS` / `GRADE_TITLE` / `SHARE` / `formatGain` / `formatCost` / `decayText`
- `data/help.js` —— `HELP_TOPICS` 与 `practiceTopic()`
- `data/guides.js` —— 每门玩法的 `goal` / `steps` / `terms` / `scoring`
- `tests/layout.test.js` —— 文案断言与黑名单（搜 `黑名单` / `旧词`）
- `scripts/verify.js` —— 页面分享方法与 `?skillId=` / `?topic=` 的静态核对

## 待验

- 「息 / 秒」的口径已在说明页明写（`practiceTopic` 的「计时」节）；待验的是玩家会不会读到。
