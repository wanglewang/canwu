# 功法分类、命名与品阶

> 类别按**玩法动作**定，不按名字凑。判据一句话：**刀法不练数格子，丹道不练渡河，心法不练牵线。**

---

## 1. 一句话

19 门功法分布在 15 个类别里；名字的结构是「类别·四到六字正名」（现在全表五字），品阶（天地玄黄）决定耗气、属性与可修境界。

## 2. 十五个类别与各自的玩法内核

| 类别 | 门数 | 玩法内核 | 说明 |
| --- | --- | --- | --- |
| **刀法** | 1 | 顺光成路 | 顺着箭头把刀扫到靶心，招长而折，容许多带两桩 |
| **剑法** | 1 | 辨光取真 | 在数道剑光里截真招 |
| **阵法** | 3 | 盘上推演 | 同族都在方盘上推演：勘禁位、排五行、点阵灯 |
| **心法** | 3 | 记忆与节律 | 三门主修各考一样：节拍、记性、配对 |
| **水术** | 1 | 循纹递推 | 看河石上的水纹递推 |
| **身法** | 1 | 步法连环 | 照卷轴踏位 |
| **御灵** | 1 | 灵纹连线 | 牵两枚同纹灵石，找一条不超过两折的通路 |
| **土术** | 1 | 落石垒基 | 挪石转石垒满一层，唯一持续下落的盘面 |
| **灵植** | 1 | 三秀同收 | 互换相邻两株凑三连，新苗落下还能连锁 |
| **术数** | 1 | 填数推演 | 九宫盘上补数，行、列、宫各要一遍 |
| **合术** | 1 | 同数相叠 | 四向推盘，同数相撞就合上去 |
| **目术** | 1 | 按序扫盘 | 目光按序把整盘点一遍，考的是扫而不是记 |
| **机巧** | 1 | 滑块让路 | 一块一格地滑，给主块腾出底部出口 |
| **挪移** | 1 | 推石入位 | 人走箱推、只推不拉，每箱对上自己的阵位 |
| **辨术** | 1 | 择大辨微 | 一堆数里挑最大的那个，考比较不考记性 |
| **丹道** | 0 | **待补** | 暂空缺：留给真正炼丹的功课 |

`data/practice.js` 的 `FAMILIES` 是这张表的真源（`core` 内核 + `note` 一句话 + `kind`）。

**「丹道」空着是有意的**：宁可空一格，也不要拿「凑数」的玩法填进去。判据同上——丹道该练「配比与火候」，不是换个皮的三消。

## 3. 命名规则

`data/skills.js` 的 `NAME_RULE`（可执行，`validateNames()` 校验）：

```js
{
  sep: '·',          // 唯一分隔符
  titleMin: 4,       // 正名最少四个字
  titleMax: 6,       // 最多六个字（卡片一行的上限）
  suffixes: ['诀', '步', '引'],   // 末字必须是体裁字
}
```

**五条规则：**

| 规则 | 例 | 反例 |
| --- | --- | --- |
| 前缀严格等于类别 | `刀法·开锋斩桩诀` | `剑·断岳`（缺类别）、`刀法剑诀`（类别混用） |
| `·` 是唯一分隔符 | `心法·太虚翻卦诀` | `心法-太虚翻卦诀`、`心法 太虚翻卦诀` |
| 正名四到六字 | `阵法·点灯破阵诀` | `阵法·燃灯诀`（三字，已退役）、`阵法·燃灯破阵大法`（七字，卡片放不下） |
| 末字用体裁字（同族同字） | 诀 / 步 / 引 | `刀法·开锋斩`（同族里混了「斩」） |
| 不写等级词 | — | `高级刀法`、`入门剑诀`、`上品心法` |

**为什么同族同字**：`心法·吐纳周天诀` / `心法·静心记诵诀` / `心法·太虚翻卦诀` 都用「诀」，一眼看出同族。混用会让「谱系」这个概念散掉。

**为什么是五字（三字为什么退役）**：三个字装不下一件东西加一个动作。旧表里「三秀诀」「叠元诀」「摘魁诀」都是查不到出处的生词——玩家读到的不是「换苗凑三连」「同数相撞」「挑最大的数」，而是一串看不出指涉的音节；名字越短越像代号，越像代号越像小游戏。现在一律走「**物件 + 动作 + 体裁字**」：

| 正名 | 拆开 |
| --- | --- |
| `灵植·三秀连收诀` | 三秀（三株灵苗）· 连收（连成一线收取）· 诀 |
| `合术·同数叠元诀` | 同数（两枚一样大）· 叠元（相叠成更高一元）· 诀 |
| `辨术·一眼摘魁诀` | 一眼（不逐个比）· 摘魁（取最大的那个）· 诀 |
| `机巧·让主出阵诀` | 让主（给主块腾路）· 出阵（送到阵底出口）· 诀 |
| `挪移·石箱归位诀` | 石箱（只推不拉的箱子）· 归位（对上自己的阵位）· 诀 |

原先「三字」的唯一理由是卡片宽度（4.7 寸屏一行放得下三字），本轮实测五字仍是一行：`pages/skills/skills.wxss` 的 `.sk-name` 是 `nowrap + ellipsis`，五字在 320px 宽度下也不截断，于是把字数让给了可读性。四字是下限（再少就只剩一个生词），六字是上限（再长要挤掉品阶 chip）。**这条前提写在 `README` 的真机待验里**：卡片宽度一旦变化，先看五字名有没有被截。

**门面词必须回到正名里**：`effect.text` 的前缀（`叠元：对战战力 +5%`）是玩家在属性面板上看到的第二处名字。改名时最容易漏它，于是 `verify` 8b-2 把它变成硬规则——门面词必须是正名的一部分，只有「刀意」（`刀法·开锋斩桩诀`）、「灯势」（`阵法·点灯破阵诀`）两个意象词例外，它们说的是这一门的气，不是动作；白名单本身也反向自检，有词没人用就报错。

**id 不随改名变动**：`jian` / `zhen` / `tuna` 这些短 id 是存档键，改名只改 `name`，永不改 `id`。这条有断言守着。

**旧名黑名单**：`verify` 的 `LEGACY_SKILL_NAMES` 里存着两批旧名——无前缀 / 类别错置的一批（`基础刀法`、`剑诀·断岳`、`灵契·并蒂引`、`丹道·凝露方`），以及三字正名整批退役的 19 个。三字的闸还有一道：`validateNames()` 逐门读 `SKILLS`，正名短于 `titleMin` 直接红——新门即便不撞旧名，也带不回「看不懂」这个问题。（不做全项目形状扫描的原因：带 `·` 的 `name` 还有对手「妖兽·青鳞狸」，扫形状只会误伤。）

## 4. 品阶（天地玄黄）

`data/practice.js` 的 `TIERS`：

| 品阶 | 星级 | 耗气系数 | 属性系数 | 学习门槛 | 可修上限 | 获取 |
| --- | --- | --- | --- | --- | --- | --- |
| 黄 | ★☆☆☆ | ×1.00 | ×1.0 | 炼气 | 筑基 | 初始赠送 / 藏经阁 |
| 玄 | ★★☆☆ | ×1.15 | ×1.3 | 筑基 | 金丹 | 藏经阁 / 切磋首胜 |
| 地 | ★★★☆ | ×1.30 | ×1.7 | 金丹 | 元婴 | 初始赠送 / 切磋首胜 |
| 天 | ★★★★ | ×1.45 | ×2.2 | 元婴 | 元婴以上 | 切磋首胜 |

**品阶只管三件事**：耗气、属性、可修境界。**不管难度**（难度跟熟练度走）、**不管熟练度速度**（那是「投入刻度」，见 `04-proficiency.md`）。

### 品阶按「这门功课有多难」定，不按获取时间定

- **点灯破阵诀**（阵灯推演）要在 4×4 / 5×5 上推演联动、还要把步数压到最优，是十九门里最费脑的一门，挂黄阶等于「练得最苦、拿得最少」——所以提到**地阶**。
- **循数勘禁诀**（数格辨禁）反过来：看懂数字规则之后基本是稳的，难度低于两门阵法——降到**黄阶**。
- **五灯相生诀**偏反应，比阵灯轻，落**玄阶**，与点灯破阵诀排成「玄 → 地」两级。

**一族一个品阶只放一门**：同阶撞车会让谱系按阶取槽时把后一门盖掉。`tests/rank.test.js` 有断言守这条。

> 注：这条规则在「阵法」族上被打破过一次（点灯破阵地阶、循数勘禁黄阶、五灯相生玄阶——三阶各一门，符合规则）。真正需要守的是「同族同阶不重」。

### 九套经典玩法统一挂黄阶

连线、落石、三秀、九宫、合数、顺序点格、滑块、推箱、取大——规则一看就懂、难度最低，价格与境界门槛都按黄阶走。**这九门是「入门功课」的位置**，不因为「经典」就给高品阶。

## 5. 谱系与空档

`skills.chainsOf(state)` 把同族功法按天地玄黄排列，功法页的「功法谱系」据此显示：

| 族 | 黄 | 玄 | 地 | 天 |
| --- | --- | --- | --- | --- |
| 刀法 | ✓ 开锋斩桩诀 | ·空· | ·空· | ·空· |
| 心法 | ✓ 吐纳周天诀 | ✓ 静心记诵诀 | ·空· | ✓ 太虚翻卦诀 |
| 阵法 | ✓ 循数勘禁诀 | ✓ 五灯相生诀 | ✓ 点灯破阵诀 | ·空· |

**缺变体的档位显示空档，不隐藏**。用意：让玩家看见「这一族还有位置」，也为以后加功法留出可视化入口。补齐只需加一门数据（加玩法是另一回事）。

## 6. 未习得也能查全本

`getSkillDetail(state, id)` 对**未习得的功法**返回完整内容：玩法规则、练成所得、习得路径。

**锁的只有「能不能开练」**，不是「能不能看」。理由：功法是玩家做选择的信息，藏起来只会让人不知道自己在选什么。图鉴弹窗里给「怎么拿到」（藏经阁价格 / 哪场切磋首胜掉落）。

## 7. 早已撤销的一族：符箓

历史上有一族「符箓」，装的是扫雷玩法（原叫「符箓·镇符诀」）。撤销原因：**类别与玩法动作对不上**——扫雷是「按数字推断埋点」，属于盘上推演，不是「画符」。

处理：

- 类别改「阵法」，名字改「阵法·循数勘禁诀」，盘面术语从「镇符」改成「阵钉」；
- `visual.FAMILIES` 由五类收成四类（兵刃 / 心法 / 丹道 / 阵法）；
- `id` **不动**（`leifu`），存档不受影响。

这条是「类别以玩法动作为准」的最佳反例：如果当时按「符箓」这个好听的名字继续加，扫雷就永远解释不清它和画符有什么关系。

## 8. 被否决的方案

| 方案 | 为什么否掉 |
| --- | --- |
| 类别按获取途径分（初始 / 藏经阁 / 掉落） | 获取途径会变，玩法不会。分类应当稳定 |
| 类别按品阶分 | 品阶已经是独立维度，再按它分类等于取消分类 |
| 名字带等级词（初阶 / 高阶） | 等级由品阶与段位表达，名字里再写一遍会互相矛盾 |
| 三字正名 | 三个字装不下一件东西加一个动作，列表扫过去全是生词（2026-11 整批退役，见 §3） |
| 七字以上正名 | 卡片一行放不下，会挤掉品阶 chip |
| 同族不同体裁字 | 谱系会散 |
| 丹道用「换个皮的三消」填上 | 判据不过：丹道不练数格子 |
| 隐藏未习得功法的详情 | 玩家不知道自己在选什么 |

## 代码指路

- `data/skills.js` —— `SKILLS`（19 门）、`NAME_RULE`、`validateNames()`、`chainsOf()`
- `data/practice.js` —— `TIERS`、`FAMILIES`、`familyOf()`
- `data/visual.js` —— `FAMILIES`（四类视觉族）
- `pages/skills/` —— 功法页两分区、谱系、图鉴弹窗
- `scripts/verify.js` —— 命名规则、id 不变、旧名黑名单、一族一阶不重
- `tests/layout.test.js` —— 卡片三行、名字单行、品阶 chip

## 待验

- 九个黄阶经典玩法集中在同一品阶，谱系上会不会显得「黄阶拥挤、高阶空」。目前靠「空档也要显示」来表达这是待补，不是缺陷。
