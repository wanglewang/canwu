# 功法分类、命名与品阶

> 类别按**修士靠什么手段修行**定，不按「玩家在屏幕上做什么」定。判据一句话：**刀法不练数格子，丹道不练渡河，心法不练牵线。**

---

## 1. 一句话

15 门功法分布在 **9 个类别**里（`FAMILIES` 留 12 族，剑法 / 水术 / 身法三族自 2026-11 起暂无功法）；名字的结构是「类别·四到六字正名」（现在全表五字），品阶（天地玄黄）决定耗气、属性与可修境界。

## 2. 九个类别与各自的玩法内核

| 类别 | 门数 | 功法（品阶） | 玩法内核 | 说明 |
| --- | --- | --- | --- | --- |
| **心法** | 3 | 吐纳周天诀（黄）· 太虚照见诀（黄）· 澄心默诵诀（玄） | 记忆与节律 | 主修各考一样：节拍、配对、记性 |
| **阵法** | 3 | 循数勘禁诀（黄）· 九宫补缺诀（黄）· 星罗点灯诀（地） | 盘上推演 | 同族都在方盘上推演：勘禁位、补九宫、点阵灯 |
| **神识** | 2 | 遍观毫厘诀（黄）· 摘星辨魁诀（黄） | 神念览物 | 神念扫过全域：按序点格、辨气机强弱 |
| **机关** | 2 | 移山开路诀（黄）· 移石归阵诀（黄） | 移位让路 | 挪块让路、推石归阵，考的是腾挪次序 |
| **刀法** | 1 | 开锋破军诀（黄） | 顺光成路 | 顺着箭头把刀扫到靶心，招长而折 |
| **丹道** | 1 | 同源叠元诀（黄） | 同级合炼 | 同级相合，合出更高一阶——炼丹的路子 |
| **御灵** | 1 | 并蒂连枝引（黄） | 灵纹连线 | 牵两枚同纹灵石，找一条不超过两折的通路 |
| **灵植** | 1 | 三秀连收诀（黄） | 三秀同收 | 互换相邻两株凑三连，新苗落下还能连锁 |
| **土行** | 1 | 万石成岳诀（黄） | 落石垒基 | 挪石转石垒满一层，唯一持续下落的盘面 |

空族三个：**剑法 / 水术 / 身法**（2026-11 删门留下的坑，族定义留在 `FAMILIES`，`chainsOf()` 不分组，谱系里不显示）。`data/practice.js` 的 `FAMILIES` 是这张表的真源（`core` 内核 + `note` 一句话 + `kind`）。

### 2.1 为什么是这九类

**类别说的是「修士靠什么修行」，不是「玩家在屏幕上做什么」。** 这条一开始是错的，2026-11 整批重归过：

| 旧类别 | 它其实在说 | 现类别 | 归并理由 |
| --- | --- | --- | --- |
| 土术 | 俄罗斯方块 | 土行 | 五行之一是修行门类 |
| 术数 | 数独 | 阵法 | 填数推演就是布阵推演，与勘禁同源 |
| 合术 | 2048 | 丹道 | 同级相合、合出更高一阶，就是炼丹的路子 |
| 目术 | 舒尔特方格 | 神识 | 神念扫过全域 |
| 辨术 | 找最大的数 | 神识 | 神识辨气机强弱 |
| 机巧 | 华容道 | 机关 | 挪块让路是机关术 |
| 挪移 | 推箱子 | 机关 | 推石归阵同上 |

旧的那套读起来像《封神演义》里的左道旁门（术数 / 目术 / 辨术），跟现代玄幻修仙的门类对不上——**现代玄幻按手段分**：丹师炼丹、阵师布阵、剑修用剑、体修练肉身、炼神靠神识。十二类里十个只有一门，九类里五个只有一门，但留下那五个都是玩家认得的门类。

**「丹道」曾经空着是有意的**：宁可空一格，也不要拿凑数的玩法填进去。2026-11 叠元归入丹道后它为「同级合炼」，是名副其实的一格。

## 3. 命名规则

`data/skills.js` 的 `NAME_RULE`（可执行，`validateNames()` 校验）：

```js
{
  sep: '·',          // 唯一分隔符
  titleMin: 4,       // 正名最少四个字
  titleMax: 6,       // 最多六个字（卡片一行的上限）
  suffixes: ['诀', '引'],   // 末字必须是体裁字
}
```

**五条规则：**

| 规则 | 例 | 反例 |
| --- | --- | --- |
| 前缀严格等于类别 | `刀法·开锋破军诀` | `刀·开锋破军诀`（缺类别）、`刀法剑诀`（类别混用） |
| `·` 是唯一分隔符 | `心法·太虚照见诀` | `心法-太虚照见诀`、`心法 太虚照见诀` |
| 正名四到六字 | `阵法·星罗点灯诀` | `阵法·点灯诀`（三字，已退役）、`阵法·点灯破阵大法`（七字，卡片放不下） |
| 末字用体裁字（同族同字） | 诀 / 引 | `刀法·开锋斩`（同族里混了「斩」） |
| 不写等级词 | — | `高级刀法`、`入门剑诀`、`上品心法` |

### 3.1 正名走「意象 + 体裁字」，不走「物件 + 动作」

这是 2026-11 改的第二条。原先的规则是「前两字说盘上有什么，中间两字说手上做什么」，结果是名字变成了**关卡目标**：

| 旧正名 | 它其实是 | 现正名 |
| --- | --- | --- |
| 让主出阵诀 | 华容道的胜利条件 | 移山开路诀 |
| 石箱归位诀 | 推箱子的胜利条件 | 移石归阵诀 |
| 一眼辨魁诀 | 操作提示（一眼看出最大的） | 摘星辨魁诀 |
| 扫目遍观毫厘诀 | 「扫目」生造、「毫厘」在解释玩法 | 遍观毫厘诀 |
| 开锋斩桩诀 | 武馆训练科目（新刀开刃、砍木桩） | 开锋破军诀 |
| 并蒂牵线引 | 「牵线」就是连线玩法 | 并蒂连枝引 |

**判据**：名字读完**不应该知道怎么玩**，只应该知道它出自哪一脉、什么分量——怎么玩写在方法页与说明页。名字写得越准确，越像帮助页的标题，越不像功法。反过来说，「大衍诀」「长春功」这类小说里的名字，读者恰恰不知道它具体干什么。

四门没动：**循数勘禁诀、吐纳周天诀、三秀连收诀、万石成岳诀**——这四个放进小说不违和。

### 3.2 为什么是五字

三字装不下一个意象加一个体裁字。旧表里「三秀诀」「叠元诀」「辨魁诀」都是查不到出处的生词，列表扫过去只看得见「这也是一门功课」。四字是下限，六字是上限（再长要挤掉品阶 chip）。实测五字仍是一行：`pages/skills/skills.wxss` 的 `.sk-name` 是 `nowrap + ellipsis`，五字在 320px 下不截断。**卡片宽度一旦变化，先看五字名有没有被截。**

### 3.3 门面词必须回到正名里

`effect.text` 的前缀（`辨魁：灵力恢复 +10%`）是玩家在属性面板上看到的第二处名字。改名时最容易漏它，于是 `verify` 8b-2 把它变成硬规则——门面词必须是正名的一部分，只有「刀意」（`刀法·开锋破军诀`）、「灯势」（`阵法·星罗点灯诀`）两个意象词例外，它们说的是这一门的气，不是动作；白名单本身也反向自检，有词没人用就报错。

**`id` 不随改名变动**：`jian` / `zhen` / `tuna` 这些短 id 是存档键，改名只改 `name`，永不改 `id`。

**旧名黑名单**：`verify` 的 `LEGACY_SKILL_NAMES` 里存着三批旧名——无前缀 / 类别错置的一批（`基础刀法`、`吐纳诀`、`灵契·并蒂引` 等）、三字正名整批退役的十九个、以及 2026-11 第二次整批退役的十二个（旧类别 + 操作式正名）。回退即报错。

## 4. 品阶（天地玄黄）

`data/practice.js` 的 `TIERS`：

| 品阶 | 星级 | 耗气系数 | 属性系数 | 学习门槛 | 可修上限 | 获取 |
| --- | --- | --- | --- | --- | --- | --- |
| 黄 | ★☆☆☆ | ×1.00 | ×1.0 | 炼气 | 筑基 | 初始赠送 / 藏经阁 |
| 玄 | ★★☆☆ | ×1.15 | ×1.3 | 筑基 | 金丹 | 藏经阁 / 切磋首胜 |
| 地 | ★★★☆ | ×1.30 | ×1.7 | 金丹 | 元婴 | 初始赠送 / 切磋首胜 |
| 天 | ★★★★ | ×1.45 | ×2.2 | 元婴 | 元婴以上 | 切磋首胜（2026-11 起暂无功法） |

**品阶只管三件事**：耗气、属性、可修境界。**不管难度**（难度靠一关一关走通 1000 关，见 `07-difficulty.md`）、**不管熟练度速度**（那是「投入刻度」，见 `04-proficiency.md`）。

### 品阶按「这门功课有多难」定，不按获取时间定

- **星罗点灯诀**（阵灯推演）要在 4×4 / 5×5 上推演联动、还要把步数压到最优，是十五门里最费脑的一门，挂黄阶等于「练得最苦、拿得最少」——所以提到**地阶**。
- **循数勘禁诀**（数格辨禁）反过来：看懂数字规则之后基本是稳的，难度低于同族的另外两门——降到**黄阶**。

**同族同阶可以并列，但不许被盖掉**：谱系每族四个槽（黄 / 玄 / 地 / 天），一个槽里可以并排多门。心法、阵法、神识、机关四族都有同阶并列，谱系必须全显示——`tests/rank.test.js` 断言「每门功法都能落进某个槽的 items，显示数与实际相符」。

### 九套经典玩法统一挂黄阶

连线、落石、三秀、九宫、叠元、顺序点格、滑块、推箱、取大——规则一看就懂、难度最低，价格与境界门槛都按黄阶走。**这九门是「入门功课」的位置**，不因为「经典」就给高品阶。

## 6. 未习得也能查全本

`getSkillDetail(state, id)` 对**未习得的功法**返回完整内容：玩法规则、练成所得、习得路径。

**锁的只有「能不能开练」**，不是「能不能看」。理由：功法是玩家做选择的信息，藏起来只会让人不知道自己在选什么。图鉴弹窗里给「怎么拿到」（藏经阁价格 / 哪场切磋首胜掉落）。

## 7. 早已撤销的一族：符箓

历史上有一族「符箓」，装的是扫雷玩法（原叫「符箓·镇符诀」）。撤销原因：**类别与玩法动作对不上**——扫雷是「按数字推断埋点」，属于盘上推演，不是「画符」。

处理：类别改「阵法」，名字改「阵法·循数勘禁诀」，盘面术语从「镇符」改成「阵钉」；`visual.FAMILIES` 由五类收成四类；`id` **不动**（`leifu`）。

这条与 2026-11 的整批重归是同一个病：**先给玩法起一个好听的类别名，再倒过来解释它为什么属于这一类**。符箓只是因为「符是画出来的、扫雷不是」而在当时被抓住；术数 / 目术 / 辨术一路蒙混到第二次重归才被拆掉。

**符箓要立起来，得先有一个真画符的盘面**，光起名不算。

## 8. 被否决的方案

| 方案 | 为什么否掉 |
| --- | --- |
| 类别按获取途径分（初始 / 藏经阁 / 掉落） | 获取途径会变，玩法不会。分类应当稳定 |
| 类别按品阶分 | 品阶已经是独立维度，再按它分类等于取消分类 |
| 类别按玩家操作分（扫视 / 比较 / 合并 / 推箱） | 2026-11 整批退役：那是 App 的功能目录，不是修士世界的门类（见 §2.1） |
| 名字带等级词（初阶 / 高阶） | 等级由品阶与段位表达，名字里再写一遍会互相矛盾 |
| 三字正名 | 三个字装不下一个意象加一个体裁字，列表扫过去全是生词（2026-11 整批退役，见 §3.2） |
| 正名写「物件 + 动作」 | 名字变成关卡目标，读完就知道怎么玩，反而不像功法（见 §3.1） |
| 七字以上正名 | 卡片一行放不下，会挤掉品阶 chip |
| 同族不同体裁字 | 谱系会散 |
| 去掉「类别·」前缀 | 最像小说，但丢掉家族信息，玩家一眼看不出这一门属于哪一脉 |
| 丹道用「换个皮的三消」填上 | 判据不过：丹道不练数格子 |
| 隐藏未习得功法的详情 | 玩家不知道自己在选什么 |

## 代码指路

- `data/skills.js` —— `SKILLS`（15 门）、`NAME_RULE`、`validateNames()`、`chainsOf()`
- `data/practice.js` —— `TIERS`、`FAMILIES`、`familyOf()`
- `data/visual.js` —— `FAMILIES`（四类视觉族，按玩法 key 映射，与类别无关）
- `pages/skills/` —— 功法页两分区、谱系、图鉴弹窗
- `scripts/verify.js` —— 命名规则、id 不变、旧名黑名单、门面词
- `tests/layout.test.js` —— 卡片三行、名字单行、品阶 chip

## 待验

- 九个类别、五个独苗族在真机上谱系是否显得零散（每族一格一门，空档很多）。
- 九个黄阶经典玩法集中在同一品阶，谱系上会不会显得「黄阶拥挤、高阶空」。目前靠「空档也要显示」来表达这是待补，不是缺陷。
- 「机关」「神识」这两个新类别名，玩家第一眼认不认（「神识」是网文通用词，「机关」是否够修仙味未验）。
