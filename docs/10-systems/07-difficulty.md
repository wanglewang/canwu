# 关卡制、难度五档与回关折减

> 难度档跟**人**走，不跟功法走。它由这门功法自己的熟练度算出——这是「一个维度只管一件事」的第三条。
>
> 关卡不是玩家走出来的路，是熟练度的另一个刻度：练到哪，就在哪。

---

## 1. 一句话

200 关（五章 × 40 关），**当前关由本门熟练度算出**（`levels.levelFromProf()`），只增不减；
五档难度降级成章节名，玩家看到与操作的是「第几关」；回关练手时，熟练度按「本关 ÷ 当前关」连续折减。

## 2. 为什么是 200 关，不是 999

旧版 999 关的真实分辨率是 **200**：每 5 关一段、一章 40 段，同段五关参数逐位相同。
玩家看到「第 437 关」，实际是「第三章第 37 段第 2 关」，第 436 关与第 440 关完全一样。
对外标 999、对内只有 200 种盘面，是虚标；而且一局 S 能跨四五关，关号一直在跳，玩家反而没有「我到了」的实感。

现在一段一关：**200 关就是 200 种盘面**，关号一局动一格到几格，看得见，也认得下。

## 3. 关卡由熟练度算出

```js
levels.levelFromProf(prof)      // 0 → 第 1 关；300 → 第 41 关；99999 → 第 200 关
```

六个锚与 `world.TIERS` 的 threshold 同源（0 / 300 / 1500 / 6000 / 24000 / 99999），章内线性铺满 40 关：

| 熟练度 | 关 | 章 | 一局 S 前进 |
| --- | --- | --- | --- |
| 0 → 300 | 1 → 40 | 一 · 简单 | 约 4 关 |
| 300 → 1500 | 41 → 80 | 二 · 普通 | 约 1.3 关 |
| 1500 → 6000 | 81 → 120 | 三 · 困难 | 约 0.35 关 |
| 6000 → 24000 | 121 → 160 | 四 · 极难 | 约 0.09 关 |
| 24000 → 99999 | 161 → 200 | 五 · 绝境 | 约 0.02 关 |

前段快得看得见，后段慢到「这一关要磨」——两头都对。全 S 84 局走完 200 关，全 C 10000 局。

**关卡只由熟练度决定，熟练度只增不减，所以关卡也只增不减。**
「打不过就掉关」在这套结构里不存在：惩罚落在这一局（F = 本局作废），不落在长期进度上。

## 4. 三条硬规则

| 规则 | 内容 |
| --- | --- |
| 不能往上挑 | 关卡由熟练度算出，玩家只能打「当前关」或更低的关。越权（改页面参数）一律回落到当前关 |
| 可以回关 | 想找手感可以退到任意低关，代价是熟练度折减（见 §5） |
| 不设关卡锁 | 章内没有「必须先过第 N 关」的限制——关卡本来就只有一个 |

旧版「章内随便挑」这条被取消了：它让「进度」变成玩家自己点的动作，而第 1 关与第 200 关的收益曾经完全一样——**那正是「刷第 1 关」这条最优解的入口**。

## 5. 回关折减

**熟练度 = 基础值 ×（本关 ÷ 当前关），四舍五入一次。**

| 当前第 40 关 | 系数 | S | B |
| --- | --- | --- | --- |
| 打 40 关 | ×1.000 | 34 | 15 |
| 打 30 关 | ×0.750 | 26 | 11 |
| 打 20 关 | ×0.500 | 17 | 8 |
| 打 10 关 | ×0.250 | 9 | 4 |
| 打 1 关 | ×0.025 | 1 | 0 |

为什么不用「每低一档折半」：档只有五级，**同一章内第 1 关与第 40 关的折减系数都是 1**，
而第 1 关的 S 率远高于第 40 关——档内折减是空的。按关折是连续的，退一关只掉不到 1%，
不存在「退一档砍一半」那种断崖。

### 5.1 只折熟练度，不折耗气

耗气按回关所在章的基数算。回关本来就便宜（7 点起），再折会让「回关刷分」变成省气的聪明选择。

### 5.2 与连 S 完全解耦

回关局：不叠层、不砍已有层数、不砍连击收益（本局给的是折减后的基础值）。回当前关照接上一层 +1。

### 5.3 新手不受罚

熟练度 < 300 时当前关落在第 1～40 关，此时「当前关」就是他自己，回关只发生在主动往下退。

### 5.4 判定只有一个函数

`practice.levelFactor(level, curLevel)`。所有「折到几成」的判断都调它，不许在页面里再算一遍。

## 6. 五档表

档位不再是「解锁范围」，而是**关卡的命名分区**：第几章 = 第几档，档由关号反推。

| 档 | 关 | 耗气基数 | pace（节奏） | windowPace（判定窗） | goal（目标） | gear | depth |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 简单 | 1–40 | 7 | ×1.18（更缓） | ×1.50 | ×0.85 | normal | 0 |
| 普通 | 41–80 | 11 | ×1.00 | ×1.21 | ×1.00 | normal | 1 |
| 困难 | 81–120 | 17 | ×0.88 | ×1.00 | ×1.12 | hard | 2 |
| 极难 | 121–160 | 24 | ×0.78 | ×0.83 | ×1.22 | hard | 3 |
| 绝境 | 161–200 | 32 | ×0.70 | ×0.64 | ×1.32 | hard | 4 |

`gear` 只分 normal / hard 两值——玩法拿它分不出困难与绝境，所以**一档一细变必须靠 `depth`**，不能靠 gear。

## 7. 章内递进：本章基准 + 关内收紧，不朝下一章混合

`buildParamsAt(method, level)` 三步：`rawParams(method, 本章)` 取本章基准 → 时间与预算按
`progressOf(level) = (关内序号 + 1) / 40` 收紧最多三成（`LEVEL_TIGHTEN`）→ `tweakParams()` 叠一门自己的连续旋钮。

下面这张表说的是**本章基准**怎么来的（`rawParams` 里的 `d` 是本档）：

| 组 | 键 | 作用 | 缩放 |
| --- | --- | --- | --- |
| `PACE_KEYS` | `interval` / `flashMs` / `gapMs` / `windowMs` / `shuffleMs` / `flipMs` / `dropMs` / `window` / `msPerNote` | 节奏变快 | × `pace` |
| `WINDOW_KEYS` | `life` | 判定窗变窄 | × `windowPace`（比 pace 更陡） |
| `GOAL_KEYS` | `chainGoal` / `maxRound` / `segments` / `beats` / `scramble` / `mines` / `pairs` / `decoys` / `startLen` / `baseLen` | 目标变高 | × `goal`，并按 `capFor()` 夹到安全上限 |
| 时辰 | `duration` / `timeLimit` | 时限收紧 | × `TIME_LEVELS` = 1 / 0.97 / 0.94 / 0.91 / 0.88 |
| 收敛 | `speed` | 光环收缩更快 | ÷ `pace`（方向相反） |

**盘面尺寸只在「规格类玩法」里放大**：阵灯 3×3 → 5×5、九宫 4 → 6 → 9、顺序点格 4×4 → 5×5 → 6×6。
其余十八门盘面固定，靠参数变难。`verify` 守着「调难度不许顺手改盘面」。

### 7.1 「每关都变」在规格类玩法上做不到

相邻两关参数真的不同的关，叫**规格台阶**。一关一段之后本该每关都是台阶，实测十九门分成三组：

| 台阶数 | 门 | 可动的量 |
| --- | --- | --- |
| 199（每关都变） | 十三门 | 毫秒类节奏 + 连续预算，一格 1ms，两百关够动 |
| 123 | 节律·息鼓合拍诀 | 拍间隔与判定窗，但小节数是整数 |
| 108 | 落石垒基 | 起始级每 20 关一级、每级层数每 10 关一层 |
| 52 | 数术·逐数排布诀 | 盘面 4→6→9 与罚时，两样都是整数 |
| 37 | 辨术·一眼摘魁诀 | 一批几样、几批、整秒时辰 |
| 36 | 合术·同数契合诀 | 段数 / 刀路长度 / 时辰，全在档表里 |
| 31 | 阵灯·点灯破阵诀 | 盘子 3×3→5×5 与步数，档表里只有这几级 |

所以**规格类玩法的关卡刻度本来就比 200 关粗六七倍**：阵灯每四关里有三关与上一关一字不差。
界面据实报「第 N 关与上一关规格相同（章内只收紧时辰与预算，盘面规格换章才换一副）」，
不假装有变化——把 20 秒写成 19.5 秒玩家也看不出来，那是后台偷偷动参数，
与 `verify` 8b-5d 守的「生成了但玩家看不见」是同一类错。

`tests/rank.test.js` 守的是**台阶数不许再掉**（每门 ≥ 30）与**方向只许变难**，不是「每关都不同」。
要不要给这几门加一条毫秒级副轴，见 `04-open-issues.md` D7。

## 8. 越权与回落

```js
const curLevel = levelData.levelFromProf(rec.prof);
const playedLevel = Math.min(curLevel, wantLevel);   // 往上挑一律夹回
const fellBack = wantLevel > curLevel;               // 结算如实报出
```

存档层（`applyPractice`）再判一次，防改存档与双页面同时开局。

## 9. 「本关变在哪」要说清

两个函数各管一层，别混：

| 函数 | 粒度 | 说什么 |
| --- | --- | --- |
| `diffDetail(method, diffKey)` | 一档 | 这一档相对基准收紧了哪几处（`brief`，准备页用） |
| `levelDelta(method, level)` | 一关 | 这一关相对上一关实际变了哪几处（最多 2 条，逐项格式化后同值就不报） |

特例：阵灯 / 三秀 / 九宫 / 让路 / 合数 / 逐数 / 入位 / 摘魁 有自己的 `brief` 句式，
因为它们的难度不是「快慢」，按时间字段拼只会拼出「入门基准」这句废话。

## 10. 被否决的方案

| 方案 | 为什么否掉 |
| --- | --- |
| 999 关（旧版） | 真实分辨率 200，对外标 999 是虚标；一局跨 5 关，关号在跳，没有「到达」感 |
| 关卡由「打过 +1」累加（旧版） | 200 关要 200 局才走得完，而熟练度 84 局就毕业——两者永远对不上，只能靠「章内随便挑」补，于是第 1 关成了最优 |
| 章内随便挑关（旧版） | 让进度变成手点的动作，且第 1 关与第 200 关收益相同，刷低关是全局最优 |
| 「每低一档折半」（旧版） | 档只有五级，章内第 1 关与第 40 关系数都是 1，档内折减是空的 |
| 另造一条「精微层」当难度轴 | 熟练度已经是那条只增的轴，再造一个是两个只增的数打架；且它要承担「难度回退」，只能让 F 掉层，于是进度会倒退（见 `50-balance/05-axis-review.md`） |
| 难度跟品阶走 | 「高级功法更难」会让没练熟的玩家被迫打难盘；且与「熟练度管难度」冲突 |
| 记忆手选档位 | 关卡本来就只有一个，多记一个手选等于多一处能漂的状态 |
| 用 gear 区分五档 | gear 只有两值，一档一细变会变成「三档一样」 |
| 关内混合下一章参数（`mixParams`，已删） | 离散规格混完取整退回原值：6 列混 7 列得 6.4、取整还是 6 列，参数看着动了、盘面没动。真变化只有时间与预算，而那是 `LEVEL_TIGHTEN` 已经在做的事 |

## 代码指路

- `data/levels.js` —— `LEVEL_MAX` / `CHAPTERS` / `LEVEL_PROF_STEPS` / `levelFromProf()` / `stageOf()` / `progressOf()` / `tweakParams()`
- `data/practice.js` —— `DIFFICULTIES`、`buildParamsAt()`、`levelDelta()`、`diffDetail()`、`levelFactor()`、`profByLevel()`、`retreatText()`、五张整表
- `utils/game.js` —— `applyPractice()` 里的 `curLevel` / 回关折减 / 越权夹回；`practiceCostOf()` 按关报价
- `pages/practice/practice.js` —— 关卡步进、回关提示、结算说明
- `scripts/difficulty-audit.js` —— 区分度审计（`npm run audit:diff`）
- `scripts/simulate.js` —— 三种刷法的预算对照（只刷第 1 关 / 逐档升 / 退一章）
- `tests/rank.test.js` —— 六个锚、单调性、规格台阶、回关系数与连续性

## 待验

- 一章 40 关、一局动 4 关（第一章）会不会让「关」显得太轻；第五章一局约 0.7 关会不会显得不动。
- 四门规格台阶只有 31–52 级的玩法（阵灯 / 合术 / 摘魁 / 数术），连着三关看到「与上一关规格相同」时，玩家会不会以为关卡坏了。
- 回关提示用 `warn-note`（红边），会不会被读成报错。
- 规格台阶只有 30–40 级的六门（阵灯 / 步法 / 扫目 / 摘魁 / 垒基 / 节律），玩家会不会觉得「关号在走、盘面没变」。
- 84 局走完 200 关是不是太快——熟练度曲线是假设分布算出来的，真机数据回来后要重算。
