# 仙门切磋

> 切磋是「赚灵石」的唯一稳定来源，也是唯一有「对手」这个概念的玩法。它不生产熟练度，但消耗同一池灵力——所以「今天练功还是挣钱」这个决策，落点就在这一页。

---

## 1. 一句话

选一位对手（或粘贴战友力码），先运功扣 5 点灵力，双方各摇一次战力，赢则按当日第 n 场衰减给灵石，首胜另有 8 枚与功法掉落。

> 战力公式与摇点细节见 `10-power.md`，本篇只讲这一页的流程与体验。

## 2. 页面结构

```
┌ 境界 · 灵力 96 / 174 ────────────────┐
│ 仙门切磋                              │
│ 一张列表：7 位对手                     │
│   名 / 头衔 / 战力 / 胜后得多少灵石     │
│   首胜标记（已胜过的显示「已胜」）      │
│ 战力码：输入框 + 「应战」              │
│ 仙榜推荐：「挑一位最接近的道友」        │
└──────────────────────────────────────┘
```

首屏显示灵力余量的理由很直接：每场扣 5 点，玩家要一眼看出「还能打几场」。

## 3. 一场切磋的完整流程

1. **点一位对手** → `battle(state, id)`；
2. **检查灵力**：不足 5 点直接拒绝，提示「先回洞府打坐」，不扣任何东西；
3. **扣 5 点**（胜负都扣，见代码里 `state.resources.qi -= BATTLE_QI` 在判定之后、发奖之前）；
4. **摇点**：`playerRoll` vs `enemyRoll`；
5. **发奖**：赢了给灵石（衰减后），首胜再加 8 与掉落；
6. **出结算卡**：胜负、双方点数、生效的特效、灵力 −5、灵石 +N（标明第几场 ×系数）、掉落、对手的一句台词。

**没有战斗过程动画**。这是一个「算一下、看一眼」的动作，不是一局小游戏——它不该占用玩家 30 秒。

## 4. 结算卡

`components/duel-result`，与秘境共用（`styleIsolation: apply-shared`，否则全局类不生效）。

| 行 | 例 |
| --- | --- |
| 标题 | `胜` / `负` / `首胜` / `首过` |
| 点数 | `战力 46 : 39` |
| 生效特效 | `刀意：对战战力 +3%`（已生效的才列） |
| 灵力 | `−5 · 余 91 / 174` |
| 灵石 | `+12（第 1 场 ×1.000）` |
| 掉落 | `得《阵法·五行诀》` |
| 台词 | `赵砚收剑，盯着你的手腕看了半天，没说话。` |

**台词不是装饰**。七个对手各有 `winLine` / `loseLine`，这是这套系统里唯一的叙事投入——切磋要是只报数字，就退化成一台老虎机。

## 5. 灵石衰减的可见性

| 场次 | 系数 | 玄真（120）实得 |
| --- | --- | --- |
| 1 | 1.000 | 120 |
| 2 | 0.850 | 102 |
| 3 | 0.722 | 87 |
| 5 | 0.522 | 63 |
| 10 | 0.232 | 28 |
| 15 | 0.103 | 12 |

结算卡必须写明「第 n 场 ×系数」，否则玩家会以为「怎么这次给少了」是 bug。

**衰减按当日已胜场数计**：输了不消耗额度。连败已经罚了灵力（5 点/场），再罚额度就是双重惩罚。

## 6. 首胜与掉落

- 首胜：另给 **8** 枚（不在衰减内），并解锁对手的 `drop` 功法（若有）；
- 已胜过的对手显示「已胜」，但**仍可重复打**——这是灵石的主要来源；
- 掉落在首胜时判定：若该功法已习得，则只给 8 枚，不掉第二本。

四门只能靠掉落的功法：五行诀（柳含烟）、凝露诀（护山傀儡）、断岳诀（魔修·血手）、太虚诀（峰主·玄真）。

## 7. 战力码与镜像

- 「复制战力码」→ `CW1-` 开头的短码（含校验位）；
- 对方粘贴 → 还原战力 → 打一场镜像；
- 不用同时在线，也不需要服务器。

**只有战力进码**：不含灵力、灵石、功法、称号。分享一个码不会泄露进度。

保存码到剪贴板必须过 `utils/privacy.js` 的守卫——未同意隐私指引时剪贴板接口会静默失败，症状是「点了没反应」。

## 8. 仙榜联动

仙榜（`pages/board/`）显示战力前 10 的真实玩家，并自动挑一位战力最接近的供切磋。

- 来源是云数据库的战绩上传，不是实时同步；
- **榜上有人的时候，切磋页会出现「挑一位最接近的道友」**，点击直接打镜像；
- 榜为空（未登录 / 无数据）时这一行不出现。

## 9. 被否决的方案

| 方案 | 为什么否掉 |
| --- | --- |
| 实时 PVP | 要长连接与房间服务，成本远超收益 |
| 打一场小游戏决定胜负 | 切磋的定位是「算一下」，插一局玩法会让「练功」与「挣钱」两个循环混在一起 |
| 输也扣灵石 | 会让玩家只挑稳赢的打，切磋失去「挑战」意义 |
| 首胜走衰减 | 会让玩家不敢打首胜（怕浪费额度） |
| 灵力不足时「先欠着」 | 让「运功」这个成本失效 |
| 战力码带完整存档 | 泄露进度，且码会长到无法分享 |
| 每场都重播战斗动画 | 与「3–10 分钟一次会话」的节奏冲突 |

## 10. 界面约束

- 首屏一行「境界 · 灵力 96 / 174」——不能用 `roleName`（那是人物页的东西）；
- 对手行的灵石数要写「胜后得 N」，不是「N」——否则会被读成「入场费」；
- 结算卡的主按钮走 `--c-imm-gold`，不许写死蓝色（历史上有过 `#2a87ab`）；
- 子页之间不开「去秘境那页」的入口行——指向由「此处说明」承担，返回交给原生导航栏。

## 待验

- 「没有战斗过程」是否让玩家觉得「太随意」——目前靠台词与结算卡撑仪式感，未做真人反馈。
- 战力码在真机上的复制/粘贴链路（含隐私授权三处行为）。
- 仙榜的真实数据与「挑一位最接近的」推荐质量。
