# 熟练度体系

> 熟练度是「这一门练得多熟」的刻度，不是功法身价。整站只有两个东西决定它：**本局评级**与**连 S 层数**。
> 玩家面上它叫**火候**：生涩 → 初窥 → 渐熟 → 精纯 → 通玄 → 化境。

---

## 1. 一句话

每门功法各自累计 0–99999 的熟练度，跨过六级阈值时抬属性加成、逐步开本门新法、提高特效兑现比例。
**关卡不在这张表里**：一门一条 1–1000 的线、五段，走通一关推一关，与熟练度无关
（见 `07-difficulty.md`）。

## 2. 六级阈值与解锁内容

| 火候 | 阈值 | 属性倍率 | 这一段给什么 |
| --- | --- | --- | --- |
| 生涩 | 0 | ×0 | 尚无加成 |
| 初窥 | 300 | ×1 | 属性加成 ×1 |
| 渐熟 | 1500 | ×1.8 | 属性加成 ×1.8 |
| 精纯 | 6000 | ×2.8 | 属性加成 ×2.8、本门新法自此逐条开、特效 75% |
| 通玄 | 24000 | ×4 | 属性加成 ×4、特效兑现满 |
| 化境 | 99999 | ×5 | 属性加成 ×5、本门新法开到最后一条（硬顶） |

级间跨度：300 → 1500（×5）→ 6000（×4）→ 24000（×4）→ 99999（×4.17）。**约 ×4 一级**，这是 `02-design-principles.md` 第三节「递增曲线平缓」的直接落实。

**这套名字里不许出现段名。** 关卡那边叫未入门 / 入门 / 小成 / 大成 / 圆满 / 大圆满，
这里叫生涩 / 初窥 / 渐熟 / 精纯 / 通玄 / 化境。两套都叫过「小成」一次，
玩家分不清「我练到哪一段」和「我练得多熟」——那一次是改版时被真机反馈逼着拆开的。

**也不许同音。** 2026-11 之前是「生涩 / 初熟 / 精熟 / 纯熟 / 通玄 / 化境」：
三个「熟」摆在一列本来就挤，更要命的是「初熟」与「纯熟」念出来一样（chū shú / chún shú），
隔着屏幕看不出区别；「初熟」本身也不像等级名——初熟是「刚熟」，那精熟、纯熟又各是什么度？
换成「初窥（初窥门径）→ 渐熟 → 精纯」之后六个字互不重复、读音全不撞，递进还是「生→熟→化」那一路。
阈值与加成一点没动，`world.js` 的 `key` 也没动——改的只是玩家看见的那三个词。

旧版把五段难度的门槛取前五段（0/300/1500/6000/24000），于是一段一段、看似优雅；代价是「解锁难度」其实是「刷够分」。
中间那一版又把难度改成「五段各 40 关、走通开下一段」，仍然要玩家在五条平行线上各刷一遍。
现在关卡收成一条 1–1000 的线，熟练度只留属性与新法。两条线各自单调，互不代偿。

## 3. 单局熟练度：四种情况

`applyPractice()` 里的顺序是**先判作废，再判回打，再判 S，最后是普通评级**。顺序不能换。

### 情况 A：失败（F）→ 0 点，断连

```js
const rawFactor = worldData.GRADE_FACTOR[grade];
const factor = typeof rawFactor === 'number' ? rawFactor : 0.6;
const wiped = factor === 0;
```

- 熟练度 **0**，连 S **归零**；
- 灵力**不退**（起手就烧了）；
- 不立纪录（`grade !== 'F'` 才写 `state.records`）；
- 日志写「参悟 X 失败，本局无所得」，**不写「熟练度 +0」**——那读起来像 bug。

> `GRADE_FACTOR.F = 0` 是唯一的 0，所以不能用 `||` 兜底（`0 || 0.6` 会静默变成 0.6）。这行注释在代码里留了三年。

### 情况 B：回打 → 基础值按「本关 ÷ 当前关 × 段基数比」折一次，不叠连 S

```js
// belowCap = playedNo < curNo（打的不是本门当前关）
rawGain = practiceData.profByLevel(worldData.PROF_BASE[grade] || 0, playedNo, curNo);
// profByLevel = Math.round(base × Math.min(1, 本关 / 当前关))
```

- 本门走到第 800 关时：S 回打 400 关是 17、100 关是 4、第 1 关是 0；
- 本门走到第 21 关时：S 回打 10 关是 34 × 10/21 → 16；
- **只有一道折减**：关卡只剩一条线，没有「打前段」这个动作了，
  所以上一版那道「每低一段再对半」的刀被整段删掉（同一件事不许收两遍钱）；
- 只折熟练度，不折耗气——耗气只看这一关落在哪一段，与段内第几关无关；
- 本局**不参与连 S**，但**已有层数原样保留**（回当前关照接下一层）；
- 层数不涨也不清零——这是「与回打完全解耦」的具体含义。

### 情况 C：S 且在本门当前关 → 叠层

```js
comboNow = Math.min(worldData.COMBO_MAX, comboBefore + 1);
comboGainNow = worldData.comboGain(comboNow);   // round(34 × 1.5^(k-1))
rawGain = comboGainNow;
```

第 1–10 连：`34 / 51 / 77 / 115 / 172 / 258 / 387 / 581 / 871 / 1307`。第 11 连起锁死 1307。详见 `06-combo.md`。

### 情况 D：C / B / A → 固定基础值，断连

| 评级 | 基础值 |
| --- | --- |
| S | 34 |
| A | 23 |
| B | 15 |
| C | 10 |
| F | 0 |

C/B/A **不叠层且断连**。注意这不是惩罚「打得不够好」——连 S 的语义就是「连续」，断在第 4 局 A 是规则，不是失败。

### 封顶

```js
const gain = Math.min(rawGain, Math.max(0, worldData.PROF_MAX - rec.prof));
```

到 99999 后 `gain = 0`，但：
- 层数照常叠、纪录照常记；
- **灵力照扣**；
- 日志写「熟练度已圆满，本局只记战绩」，不写「+0」。

熟练度到顶后属性也就不再涨，但**关卡照样往前走**——剩下那些关是盘面，不是熟练度。
所以文案不能说「该换门了」：全 S 84 局就火候封顶，此时才走到第 84 关（还在入门段），
后面还有九百多关没打。（要不要因此抬高 `PROF_MAX`，见 `07-difficulty.md` 待验。）

## 4. 评级对挂机的影响（唯一的「倍率」出口）

`applyPractice` 在非失败时设一个 30 分钟的 buff：

| 评级 | buff 倍率 |
| --- | --- |
| S | ×1.8 |
| A | ×1.5 |
| B | ×1.25 |
| C | ×1.1 |
| F | 不设 |

这个倍率**只作用于闭关时长折算**（`idlePending` 里 `buffMinutes * multiplier`），不进熟练度、不进资源。语义是「刚练完，气机还热着，坐一会儿更有效率」。

`GRADE_FACTOR`（S 1.5 / A 1.2 / B 1.0 / C 0.6 / F 0）与这个 buff 倍率是两套数，不要混。`GRADE_FACTOR` 现在**只用来判 `wiped`**（是否等于 0），其余值不参与任何计算——这是历史遗留，保留是因为称号与成就还在读它。

## 5. 分数与纪录

每门功法记一个「本门最佳」（`state.records[skillId]`）：

- 只在**分数更高**且**不是失败**时更新；
- 失败不立纪录——第一局崩掉就在准备页留下「本局最佳 0 分 · 失败」，玩家会以为那就是自己的水平；
- **分数不加任何收益**。评级管收益，分数管追求。

## 6. 被否决的方案

| 方案 | 为什么否掉 |
| --- | --- |
| 熟练度 × 品阶系数 | 天阶是黄阶 3.2 倍，低阶功法在成长线上被直接淘汰，黄阶十一门成装饰 |
| 熟练度 × 难度倍率 | 与「回打折减」重复计一次，且会让「越难越划算」压过「按承诺打」 |
| 熟练度 × 境界 / 属性 | 熟练度就不再是「你练了多少」，而变成「你有多富」。`resMult / MAX_MULTIPLIER` 那套已整条退役 |
| 熟练度解锁关卡（旧版） | 与火候阈值同源，于是「解锁难度」= 「刷够分」；玩家要么刷最浅一段刷到吐，要么以为难度是个能挑却点不动的按钮。关卡已改成「一门一条 1–1000 的线、走通一关推一关」，与熟练度彻底脱钩 |
| 三连 S 直接晋级（补额到下一门槛） | 补额不看关卡，而回关 S 概率更高，于是「只刷第 1 关」能反超「逐关进」。这条在模拟里被抓到过，机制已整体退役 |
| 连练递减（练同一门收益递减） | 攒连 S 本来就要连练同一门，在最该上瘾的地方反着来。已废弃，换门改为正激励（省 8% 灵力） |
| 圆满后归零 | 等于这门功法死了，玩家只能换门 |
| 熟练度也给灵石/灵力 | 参悟变成印钞线，两种货币的分工塌掉 |

## 7. 数值推导：为什么每局给这些点

**S 34 点**的来历：旧版 S 是 40 点，乘 0.85 的「难度系数」后是 34。改用「只由评级与连 S 决定」之后，直接取 34 作为 S 的基准——保留手感，去掉系数。

**A 23 / B 15 / C 10**：与 S 的比值是 0.68 / 0.44 / 0.29，接近 `GRADE_FACTOR` 的 1.2/1.0/0.6 在 S=1.5 下的相对位置。取整后 A 是 22.5 进位成 23（`.5` 进位），S 是 33.75 进位成 34——两者都往上，不往下。

**为什么 C 是 10 而不是 8**：全 C 走完六段是 10000 局（见 `03-economy-flow.md`）。若 C 给 8，需要 12500 局。10000 与 12500 的差别不在「能不能走完」，而在「每局是否还能看见进度」——C 给 10 时，30 局到入门，这个数还算「一天十局、三天入门」。

**为什么硬顶是 99999 而不是 100000**：99999 读起来是「差一点」的极限，100000 是整数关卡。前者更像「练到极处」。

## 8. 日志的三条分支

结算写日志时不许含糊：

| 情况 | 日志 |
| --- | --- |
| 正常 | `参悟 刀法·开锋破军诀，熟练度 +34（灵力 −6）` |
| 升火候 | `刀法·开锋破军诀 参悟至「渐熟」` |
| 失败 | `参悟 刀法·开锋破军诀 失败，本局无所得` |
| 到顶 | `参悟 刀法·开锋破军诀，熟练度已圆满，本局只记战绩` |

「+0」不出现在日志里，任何一条分支都不写它。

## 代码指路

- `utils/game.js` —— `applyPractice()`（四种情况的判定顺序、`advanced` 推进关卡）、`tierIndex()`、`breakCombo()`
- `data/world.js` —— `TIERS`（`desc` 只说属性与新法，不提难度）、`PROF_BASE`、`PROF_MAX`、`GRADE_FACTOR`、`comboGain()`
- `data/practice.js` —— `levelFactor()` / `profByLevel()`（按 本关÷当前关 折）、`clearedOf()` / `curLevelOf()`
- `tests/game.test.js` —— 1–14 连逐局入账、非 S / 结束 / 失败断连、跨功法、回关解耦、大圆满后层数照常、v7→v8 迁移
- `tests/rank.test.js` —— 回关系数对照表与单调性、回打不再叠第二刀、四品阶同值

## 待验

- 「全 C 一万局」是数学下界，不是设计目标。真有人走这条路时，前 30 局（到入门）的体验是否还撑得住，未做真人观察。
- **熟练度与关卡谁先毕业**：全 S 84 局到 99999，此时才走到第 84 关（还在入门段）；全 C 一万局则刚好走完 1000 关。
  属性先满、内容后满的那一大段，玩家会不会觉得「练了也没用」——`PROF_MAX` 是否该抬到 1000 关的量级，待真机判断。
  这是拆掉互锁之后冒出来的新问题，已记进 `04-open-issues.md` D 类。
- 大圆满后「灵力照扣」是否会让玩家觉得被罚。目前只有文案提示「本局只记战绩」，没有更强的引导。
