# 评级体系：S / A / B / C / F

> 五档，不是六档。**S 与 F 不是「最高」与「最低」，是两个特殊结论**：S 是「打得极好」，F 是「这一局没走完」。

---

## 1. 一句话

每局只有一个评级，决定这一局换多少熟练度；判定的**指标**可以因门而异，五档名与系数全站统一。

## 2. 五档的语义

| 代号 | 名 | 语义 | 熟练度基础 |
| --- | --- | --- | --- |
| **S** | 绝佳 | 打得极好 | 34（连 S 按倍率叠） |
| **A** | 上乘 | 打得好 | 23 |
| **B** | 中平 | 打得稳 | 15 |
| **C** | 粗浅 | **走完了，但糙** | 10 |
| **F** | 走火 | **没走完**，整局作废 | 0 |

名称真源：`copy.GRADE_TITLE`。结算、称号、成就、连 S 全站共用一份，不许在各页面写「S 级」。

> 通用模板常见的 `C/B/A/S/SS/SSS` 六档不能照抄：多两档要改结算、称号、成就、连 S 四处，改动面比做一个新玩法还大；而这两档能表达的东西（「更好」）已经被连 S 表达了。

## 3. C 与 F 是两个结论

这是这套评级最重要的一条，也是最容易被写错的一条。

| | C 粗浅 | F 走火 |
| --- | --- | --- |
| 这一局走完了吗 | 走完了 | **没走完** |
| 熟练度 | 10（回关折减） | 0 |
| 连 S | 归零 | 归零 |
| 灵力 | 不退 | 不退 |
| 纪录 | 照记 | **不记**（没走完的成绩不算本门最佳） |
| 日志 | 「熟练度 +10」 | 「走火，本局无所得」 |

**判据：这门玩法有没有「达成即结束」的事件？**

- **有** → 时间或命数先到就是 F。**十二门**：燃灯、勘禁、静心、太虚、凝露、并蒂牵线引、九宫、叠元、逐数、让路、入位、摘魁。
- **没有**（只看时限内产出）→ 最低只到 C。**七门**：刀法、剑法、身法、吐纳、灵植、土术、五行。

**为什么七门没有 F**：这些门里「时间到」是那一局的终点，不是失手。给它们判 F 等于说「你没打完」，但它们本来就没有「打完」这个状态——顺光扫斩打 15 秒，时间到就是打完了。

**第三种结局：主动收功**。它根本不进结算（`applyPractice` 不调用），由 `breakCombo()` 把连 S 归零，结算卡报「收」不报 F，靠页面的 `aborting` 标记区分——**不许让玩法层猜**。

## 4. 判定指标：三族

统一的是五档名与系数，**不统一指标**。指标必须一句话讲清、写进 `guides.scoring`，并与局内 HUD、结算同源。

| 族 | 指标 | 代表 | 为什么适合它 |
| --- | --- | --- | --- |
| **分数族** | 本局总得分 | 刀法 608 / 剑法 13 道 / 静心 363 / 并蒂 1176 / 垒岳 520 / 三秀 1750 | 玩法本身有「越打越高」的累积，分数是自然产物 |
| **比值族** | 已走步数 ÷ 最优步数 | 燃灯（正好最优 S）、让路（正好最优 S）、入位（正好 3 推 S） | 玩法有「唯一最优解」，比时间更能衡量「想得对不对」 |
| **用时族** | 完成用时（含罚时） | 勘禁 25 秒 / 凝露 14 秒 / 太虚 18 秒 / 九宫 80 秒 / 逐数 26 秒 / 摘魁 21 秒 | 玩法有明确的「清盘」状态，快慢即水平 |
| **进度族** | 走完的段数 / 轮数 / 拍数 | 踏云连环步 4 段全成 / 吐纳 7 拍圆满 | 玩法是逐段推进，段数就是成绩 |

## 6. 评级线只有一个出处

```
minigames/*.js  导出 lines(params, gear)
        ↓
minigames/index.js  gradeLines(gameId, params, gear)
        ↓
   ┌────┴─────────────────────┐
说明页「怎么评级」      局内 HUD「再 N 分可入 S」      结算档位
```

**不许在别处再算一遍。** 说明页按链接带的 `diff` 列出本档四条线，与局内 HUD、结算同源；这条由 `verify` 与 `tests/minigames.test.js` 守着（新增玩法必须导出 `lines`）。

**局内只报下一条线**，不列四条：一屏塞四条会把第一局真正要读的东西挤掉。想看全貌进说明页。

## 7. 辅助与评级

用了辅助就不能拿 S——这条不是惩罚，是公平：

| 玩法 | 辅助 | 评级影响 |
| --- | --- | --- |
| 阵灯推演 | 阵眼感应 / 重置本盘 | 本盘最高只到 A |
| 灵纹连线 | 照纹 | 扣息（不封顶评级，但少的时间会反映在分数/用时上） |
| 三秀同收 | 照畦 / 重排 | 扣息 |

点灯破阵诀是最明确的例子：它按步数评级，「感应」直接告诉你该点哪一格，那就不再是推演。所以封顶 A 是唯一诚实的选择。

## 8. 评级线的标定方法（不是「越难越高」）

三秀同收是反直觉的样本：

| 档 | 花色 | 时辰 | S 线 |
| --- | --- | --- | --- |
| 简单 | 5 | 68 息 | 1900 |
| 普通 | 5 | 60 | 1750 |
| 困难 | 6 | 58 | 1400 |
| 极难 | 6 | 55 | 1300 |
| 绝境 | 7 | 52 | 950 |

**盘面越难，S 线越低。** 因为 7 色盘面上随机凑出三连的概率远低于 5 色，同样的分数含金量不同。标定目标是「高手约 75–95% 拿得到、常人 5–25%」，由 `npm run audit:diff` 与 `tests/rank.test.js` 一起守。

准备页与说明页必须明写这句（「盘面越难，同样分数越难得」），否则玩家会以为算错了。

## 9. 被否决的方案

| 方案 | 为什么否掉 |
| --- | --- |
| SSS / SS 两档 | 见第 2 节 |
| 全站统一指标（都用分数） | 点灯破阵诀与让主出阵诀没有「分数」，硬造一个只会变成「步数 × 系数」的伪分数 |
| 全站统一为用时 | 步数类玩法「想得久不扣」是刻意的（推演不该被手速惩罚） |
| F 当最低一档（给 5 点） | 「走火」就不再是走火。零收益才能让玩家真正怕它 |
| 局内列出四条线 | 挤掉第一局要读的东西 |
| 评级线写死在页面里 | 改一次要改三处，必漏 |
| 走火也立纪录 | 第一局崩掉就在准备页写「本局最佳 0 分 · 走火」，玩家以为那就是水平 |

## 代码指路

- `minigames/*.js` —— 各门 `lines(params, gear)`
- `minigames/index.js` —— `gradeLines()`
- `data/copy.js` —— `GRADE_TITLE`
- `data/guides.js` —— `goal`（准备页一行）与 `scoring`（说明页）
- `utils/game.js` —— `applyPractice` 里 `wiped` 的判定
- `tests/minigames.test.js` —— 逐门整局驱动、`lines` 存在性
- `tests/layout.test.js` —— 局内只报下一条线、评级名真源

## 待验

- 点灯破阵诀「正好最优步数才 S」对刚上手的人是否过于苛刻（一步不浪费是高手标准，不是入门标准）。目前靠「预算留三档余量」缓解。
- 太虚翻卦诀的 S 要求「≤18 秒且 ≤24 翻」是双条件，玩家可能只知道其中一个。局内 HUD 只报下一条线时，双条件如何呈现未验证。
- 三秀同收绝境 S 线 950 是否真的比 5 色 68 息的 1900 难：模拟用的是随机可行换位策略，真人偏好找底部连锁，实际 S 率可能更高。
