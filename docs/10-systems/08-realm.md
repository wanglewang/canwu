# 境界与突破

> 境界回答两个问题：**战力乘多少**，以及**气海有多深**。前者是传统做法，后者是这个项目补上去的——因为只抬战力的话，破境就只是一个数字变大。

---

## 核心前提：破境是一天里记得住的那一下

境界平时是隐形的。你练功、攒灵石，直到某天人物页告诉你「战力够了，阵材也齐了」——这时你才第一次真正去「冲关」。我想让破境有别于「点一下数字变大」：它是一局有失败可能的小游戏，失败只散一半灵石。这样你日后想起来的不是「我战力涨了」，而是「那次我屏住呼吸，看指针停在红线上」。境界还顺手把气海挖深一层——这是它比战力更贴日常的一面。

## 1. 一句话

四境（炼气 → 筑基 → 金丹 → 元婴）；达到战力门槛并备齐灵石后，完成一次「蓄力停区」试炼即可突破，失败退一半灵石。

这张表在回答：四个境界各要多少战力才够格，进去之后战力和气海又各涨多少。

```text
   战力够 ─┐
          ├─► 蓄力停区 ─► 成：扣石·进境·气海满
   灵石够 ─┘        │
                    └─► 败：气机一乱，退半石
```

## 2. 四境表

| 境界 | 战力门槛 | 境界加成 | 气海基数 | 描述 |
| --- | --- | --- | --- | --- |
| 炼气 | 0 | ×1.00 | 150 | 引气入体，方入门径 |
| 筑基 | 75 | ×1.06 | 260 | 气沉丹田，根基初成 |
| 金丹 | 170 | ×1.14 | 420 | 一颗金丹，从此不问外物 |
| 元婴 | 300 | ×1.24 | 620 | 元婴既出，青云可期 |

- **战力门槛**是「够不够格冲关」，只看战力。
- **境界加成**是乘数，进 `powerDetail` 的 `(1 + realmBonus + effectBonus)`。
- **气海基数**决定灵力上限，见 `02-qihai.md`。

三个数一起涨，但**门槛涨得最快**（75 → 170 → 300，约 ×2.2 与 ×1.8），加成涨得最慢（+6% → +14% → +24%）。用意：境界不是「肝到就能上」，而是「战力得先到」。

## 3. 突破的两道门

`breakthroughInfo()` 故意把两件事分成两个布尔：

| 字段 | 含义 | 用在哪 |
| --- | --- | --- |
| `available` | 战力 ≥ 下一境门槛 | 决定「能不能冲关」 |
| `stoneReady` | 灵石 ≥ 布阵价目 | 决定「备不备得起阵材」 |

**不合成一个 `ok`**：合了就会出现「战力够了却说不能突破」的糊涂提示。页面把两条分开列，缺哪条说哪条。

布阵价目：筑基 **60** / 金丹 **120** / 元婴 **240**（逐境翻倍）。

### 还差几点时，该练哪门

`breakthroughInfo()` 另给两个字段，专治「战力 45 / 75」后面没话可说：

| 字段 | 含义 |
| --- | --- |
| `lack` | `need - power` |
| `fastest` | `{ id, name, nextName, gain, gap }`，取「离下一段熟练度最近」的那门 |

排序键是 `gap`，不是 `gain`：加成最大的往往是「大成 → 圆满」（差 18000 熟练度），那条路走不完。玩家要的是今天再打几局就能动的那一步。主页与人物页破境卡都拿它拼一句话（「还差 30 · 星罗烛天诀到入门 +8」），公式见 `10-power.md` 第 4 节。

## 4. 蓄力停区（突破玩法）

`minigames/charge.js`，**只用于突破，不在十五门参悟里出现**。

| 项 | 规则 |
| --- | --- |
| 操作 | 长按蓄力，松手停住 |
| 目标 | 红线之间（起点 42% + 随机 0–30%，宽度 11–16，`perks.easy` 时 +6） |
| 指针 | 4%/tick 往返扫动，0↔100 |
| 区间外 | **F（气机一乱）** |
| 区间内 | 距正中 ≤3 → S；≤7 → A；≤12 → B；其余 → C |

**为什么突破是一局小游戏而不是一次点击**：突破是这套系统里唯一「有失败可能」的成长动作。若只要战力够就必成，那灵石只是一个过路门槛，玩家不会记得自己曾经「冲关」过。

**为什么失败只退一半**：全退等于失败无代价（可以无限重试到成功），不退会让一次失手掏空积蓄。退一半的语义是「阵基还在，灵石散了些」。

## 5. 成功之后：三件事同时发生

`applyBreakthrough()`：

1. 扣灵石（不退）；
2. `realmIndex += 1`；
3. **气海当场补满**（`state.resources.qi = qiCap(state)`）。

第 3 条是「突破的第二重回报」。结算卡上单独两行：

```
灵力上限  174 → 284（+110）
灵力      已补满 284 / 284
战力      45 → 48（+3）
```

顺序是**先气海，后战力**：气海是每天都能摸到的差别（一趟多练 8 局），战力是长期值。把更贴日常的那条放前面。

失败的回执只报损失：

```
气机一乱，未能突破。布阵的灵石散了 30 枚，余下的还在。
```

## 6. 境界与功法的交叉：两道不同的门

这里有一个容易混的地方——境界对功法有**两个**作用，语义完全不同：

| 概念 | 字段 | 含义 | 效果 |
| --- | --- | --- | --- |
| **学习门槛** | `tier.needRealm` | 没到这个境界就修不动 | **禁练**，入口直接挡掉 |
| **可修上限** | `tier.maxRealm` | 超过这个境界，这门功法「练到顶了」 | **只加价 ×1.5**，不禁练，熟练度照给 |

品阶对应的两道门：

| 品阶 | 学习门槛 | 可修上限 |
| --- | --- | --- |
| 黄 | 炼气 | 筑基 |
| 玄 | 筑基 | 金丹 |
| 地 | 金丹 | 元婴 |
| 天 | 元婴 | 元婴以上（不设） |

**为什么不能合成一个布尔**：金丹期（境界 3）练黄阶功法（上限 2）是**正常且鼓励**的——黄阶便宜、够用，只是「练到头了，该换更高阶」。若合成 `realmOk`，就会误判成「金丹期练不了黄阶」，把玩家的老功法全锁掉。

这条在代码里留了注释（`utils/game/` 里的 `realmReady` / `realmAbove`：`settle.js` 与 `view.js` 各算一次），`tests/game.test.js` 有断言守着「超上限只加价不禁练」。

## 7. 界面表达

| 位置 | 内容 |
| --- | --- |
| 主页境界卡 | 境界名 + 战力 + 灵力 `160 / 174` |
| 人物页突破区 | 清单：战力（够/差多少）、灵石（够/差多少）、气海预告（`174 → 284`）、通关后的加成（`×1.06 → ×1.14`） |
| 突破前 | 「冲关」按钮，缺哪条说哪条 |
| 突破中 | 蓄力条 + 红线之间 + 当前蓄力 % |
| 突破后 | 结算卡三行（气海 / 灵力 / 战力） |

**气海预告用中性点标**（`imm-check__mark--ref`），不参与「够不够格」的判断——气海是所得，不是条件。

## 8. 被否决的方案

这些不是拍脑袋否的——每一条都曾是「这样应该也行」的那一刻。我把诱因一并记下来，是因为知道「当时为什么想这么做」，比记住「结论是不做」更有用。

| 方案 | 为什么否掉 |
| --- | --- |
| 只抬战力 | 破境变成一个纯数字，玩家感觉不到「境界高了之后日子好过了」 |
| 突破自动成功（只看战力） | 灵石变过路门槛，没有仪式感 |
| 突破失败全额退灵石 | 可无限重试到成功，等于没有失败 |
| 突破失败不退 | 一次失手掏空积蓄，玩家会不敢冲 |
| 突破后不补满灵力 | 「攒够战力却灵力见底」的玩家会先被迫闭关，体验断裂 |
| 学习门槛与可修上限合成一个判断 | 见第 6 节，会锁掉老功法 |
| 境界加成给 20% 以上 | 会让「先堆战力再一次性破境」成为唯一策略，中间过程失去意义 |

## 9. 数值推导

**为什么门槛是 75 / 170 / 300**：开局战力 45。练到第一门入门（300 熟练度）约 +10 战力，练满一门（黄阶、大圆满）约 +26。要到 75 大约需要 2–3 门入门，这是「一两小时的量」。170 与 300 同理，各需要更多门与更高段位。

**为什么加成是 6% / 14% / 24%**：逐境 +8 / +8 / +10 个百分点，接近线性。若按倍数（×1.06 / ×1.12 / ×1.25），元婴会一步跳太多，而元婴本该是「长线目标」。

**为什么气海基数 150 / 260 / 420 / 620**：段差 110 / 160 / 200 逐境变大——越往后单局越贵（绝境 27 点），一池要多撑几局就得涨得更快。

**为什么布阵 60 / 120 / 240**：逐境翻倍，与「一次破境 ≈ 一门玄阶功法（55–70）」对齐。

## 代码指路

- `data/world.js` —— `realms[]`（power / bonus / qiCap / desc）
- `utils/game/` —— `breakthroughInfo()`（两个布尔）、`applyBreakthrough()`（扣灵石、进境、补满气海）、`powerDetail(state, realmIndex)`（可预告下一境战力）
- `minigames/charge.js` —— 蓄力停区的评级
- `pages/profile/` —— 突破清单与结算卡
- `tests/game.test.js` —— 气海随境界单调、突破补满、结算与预告一致、失败退一半

## 待验

- 蓄力条在 4.7 寸屏上的操作精度：4%/tick 的速度下，S 区（距正中 3% 内）是否可稳定命中。
- 突破价目 240 灵石在元婴前的可承受性：灵石一次性收入 466 枚，扣掉功法与两次破境后剩余有限，第三次破境可能要刷几天切磋。这是设计意图还是过紧，需要真人数据。
- 突破失败（气机一乱）的文案「灵石散了 30 枚」是否会被读成「还要再交 30」。
