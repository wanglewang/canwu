# 每日份例、连练与机缘

> 三件「日循环」里的事，放在一篇，因为它们都在回答同一个问题：**今天练过之后，还有什么可拿。**

**核心前提：我不想做「今天没来就亏了」那种游戏，但又想让「多回来几次」有一点甜头。** 这三件事都不强制——不领份例照样玩，不换门照样练——它们只是悄悄奖励「今天又回来了」这个动作。这一点很重要，因为它是我后面所有取舍的标尺：凡是长出「断签清零」「连续登录奖励」的提议，到这里就该被挡回去。

---

## 1. 每日份例

这张表在回答：今天练满三次之后，系统给什么、给多少，以及什么时候给不了。

| 项 | 值 |
| --- | --- |
| 条件 | 当日参悟满 **3** 次 |
| 所得 | 灵力 **+60**，灵石 **0** |
| 上限 | 每日一次 |
| 气海不足时 | **按空位领**：装多少给多少，余下的当场散去，回执写明「+21（余下 39 散去）」 |

**为什么只给灵力、一分灵石不给**：份例是「今天练过了」的补给，不是工钱。灵石只能靠切磋与秘境挣——两种货币的分工从第一笔收入就要成立。旧版份例给灵石，结果「不打切磋也能买功法」，切磋这个系统直接变成可选项。

**为什么按空位领，而不是整份装不下就拒领**：

旧版是拒领，理由写在注释里——「份例是发放的，可以等人来取」。听起来讲究，实际上把这件事变成一道算术题：气海 174、份例 60，玩家练满三次时灵力往往还剩 130 以上，空位不足 60。**也就是解锁的那一刻正好领不到。**

玩家点了「领取」，灵力一点没动，看到的长句是「灵力 153 / 174，气海只余 21 点空位（份例是 60 点）」。他能得出的结论只有一个：这是坏的。

现在改成装多少领多少，并且照实报散掉多少：「+21 / 60，余下 39 散去」。数字难看一点，但它是真的，而且当场的动作就清楚了——**先练一局，腾出空位再来**。

打坐与份例仍然有一处不同：打坐的溢出是「坐出来的」，不收就当场散；份例一点空位都没有时仍然拒领（领 0 点没有意义），回执写「先练一局腾出空位，份例在这等你」。两条都在 `tests/game.test.js` 里有断言。

## 2. 单调日历

```js
function checkDaily(state) {
  const key = todayKey(Date.now());
  if (key <= state.daily.date) return;   // 不是「!=」，是「<=」
  ...reset
}
```

这行代码看着只是在挑个比较符，其实是我专门留给「改设备时间」这类小动作的锁。

**用 `<=` 而不是 `!=`**：设备时间被调回过去时，`key < date` 成立，若写成 `!=` 就会「重置一天」，让玩家把已领的份例再领一次。

同样，`battleWins`（切磋灵石衰减的计数）也在这里跨天归零——「灵脉第二天又满了」。

## 3. 连练：只奖不罚

| 行为 | 效果 |
| --- | --- |
| 连续练同一门 | **无衰减**（旧版有「连练递减」，已整条废弃） |
| 换一门练 | `CROSS_QI = 0.92`，本局耗气省 8%（触类旁通） |
| 回关 | 熟练度 × 本关 ÷ 当前关 × 段基数比、不叠连 S（见 `07-difficulty.md` §5） |

**连练递减为什么该废**：攒「连 S 倍率」本来就要连练同一门。若同时扣收益，等于在最该上瘾的临门一脚反着来。

**换门为什么要给正激励**：多样化靠奖励实现，不靠惩罚专精。8% 是个「值得顺手换一次」的量——不够大到让人放弃连 S，但足够成为「练满了换一门」的理由。

> 注意`cross` 的判定：`state.lastPractice.skillId !== skillId`。所以**隔了几局再回来练同一门，不算换门**——「换门」指的是「上一局练的是别的」。

## 4. 机缘：只出残卷

| 项 | 值 |
| --- | --- |
| 概率 | **1.2%**（每局参悟结算时判定） |
| 条件 | 还有未习得的功法，且本局**不是失败** |
| 所得 | 随机解锁一门未习得功法（残卷） |
| 不给 | 灵力、灵石、熟练度加成 |

**为什么只给残卷**：这是「不花灵石拿功法」的第三条路（另两条：入门即持的十三门、切磋首胜掉落）。它必须与两种货币都有明确分工——**不产灵力、不产灵石**。否则参悟就又变成印钞线。

**为什么 1.2%**：约「一百局摸到一册」。开局即持十三门，锁着的只剩澄心默诵诀（藏经阁 70 枚）与太虚照见诀（峰主·玄真首胜）两门——机缘是「偶得一门」的第三条窄路，不是主路。

**失败不触发**：整局作废还能拾到残卷，等于「零收益」只是句空话。

**概率是每次结算独立判定，没有保底**。这是刻意的：保底会让「刷局数」成为拿功法的策略，而这条路本该是「偶得」。

## 5. 三者与「日循环」的关系

把它们画在一起，你会看到三件事其实指向同一个动作——「今天多回来几次」：

```text
  ┌─ 日循环：三件事，一个方向 ────────────────────────┐
  │ 今天练 3 局 ──→ 可领份例（+60 灵力）              │
  │      │                 │                          │
  │      │                 └─→ 继续练 / 去打切磋换灵石 │
  │      ↓                                            │
  │ 每局 1.2% 可能拾到残卷                             │
  │      │                                            │
  │      ↓                                            │
  │ 换门练一局可省 8% 灵力                             │
  └──────────────────────────────────────────────────┘
```

三件事都不强制（不领份例也能玩，不换门也能练），但都指向同一个行为：**今天多回来几次**。这与「不惩罚离开」的原则不冲突——没有连续登录奖励，没有「断签清零」。

## 6. 被否决的方案

下面每一条都曾经是「看起来挺合理」的提议。我把它留在这里，不是给否决盖章，是记下当时的诱因——下次谁再提，至少知道它当初为什么被放下。

| 方案 | 为什么否掉 |
| --- | --- |
| 份例给灵石 | 「不打切磋也能买功法」，切磋变可选项 |
| 份例满池自动转灵石 | 破坏两条货币线 |
| 份例满池照发、溢出丢弃 | 与打坐相反的处理会造成困惑；份例本可等人来取 |
| `checkDaily` 用 `!=` 判日期 | 改时间可重复领（见第 2 节） |
| 连练递减 | 见第 3 节 |
| 换门给大额奖励（如 +20%） | 会让「每局都换门」成为最优策略，专精失去意义 |
| 机缘有保底（如 100 局必出） | 会让「刷局数」成为拿功法的策略 |
| 机缘也失败触发 | 见第 4 节 |
| 连续登录奖励 | 与「不惩罚离开」直接冲突 |

## 7. 数值推导

**为什么是 3 次参悟**：约 10–15 分钟的游戏量。够形成「今天来过了」的感觉，又不至于要求长时间在线。

**为什么 +60 灵力**：约三局小成段（14/局 = 42）或四局入门段。补的是「今天练过了」，不是白送一笔钱。

**为什么机缘是 1.2% 而不是 5%**：5% 意味着 20 局一册，锁着的两门几乎必掉——那藏经阁（70 枚）与峰主·玄真首胜就都没有存在意义了。1.2% 让藏经阁与切磋仍是主路。

**为什么换门省 8% 而不是 15%**：15% 接近「换门一定比连练划算」，会打断连 S 的连续性（连 S 的十连价值远大于 15% 省气）。8% 是「顺手」的量级。

## 代码指路

- `data/world.js` —— `daily`（target 3 / qi 60 / stone 0）
- `data/economy.js` —— `DAILY_QI` / `CROSS_QI` / `FORTUNE_SCROLL_RATE`
- `utils/game/` —— `checkDaily()`（单调日历）、`claimDaily()`（按空位领 / 零空位拒领）、`applyPractice` 的 `cross` 判定与机缘分支
- `pages/index/` —— 份例入口与「今日之课」
- `tests/game.test.js` —— 份例仅灵力、按空位领且报出散了多少、零空位拒领、改时间不重复领、机缘不给资源

## 待验

- 份例按空位领之后，「+21（余下 39 散去）」这句在 toast 里够不够看清：微信的 toast 两行就截，真机要试。
- 主页份例行在空位不足时会写成「灵力 +21（气海只余 21）」，这个括号会不会被当成错误提示。
- 「今日之课」推荐 3 局的具体呈现（进度点 / 文案）未在真机验证。
- 机缘 1.2% 的「盼头感」是否足够：一百局才可能见到一次，玩家可能根本不知道有这条路。目前靠说明页与日志弥补。
