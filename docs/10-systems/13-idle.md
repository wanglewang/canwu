# 闭关与打坐

> 闭关与打坐是**同一套算法、两种触发**。区别只在：冷启动回来时弹给你，还是你当场点一下收走。
>
> 灵力是参悟的油。油烧完了不该逼玩家杀掉小程序再开一遍——这就是「打坐」存在的全部理由。

---

## 1. 一句话

离开期间按 0.5 灵力/分累积，一次最多算 8 小时；装满气海的部分不收，回来第一件事是收它。**闭关只养油，不涨功力。**

## 2. 参数

| 参数 | 值 | 出处 |
| --- | --- | --- |
| `qiPerMinute` | 0.5 | `world.idle` |
| `capHours` | 8 | `world.idle` |

8 小时产能 = 240 灵力。**但炼气气海只装 174**（5.8 小时即满）——所以炼气期先到的是气海，不是时长。筑基之后（284）才轮到 8 小时这个上限。

没有 `profPerHour` 这个键：闭关一分熟练度都不产，理由见第 7 节。

## 3. 一次结算的完整过程

```js
idlePending(state)          // 只算不写：页面据此显示「已坐 N 分 · 灵力 +M」
  ├─ 时钟倒退？→ 全 0
  ├─ 时长 = min(now − lastSeen, 8h)
  ├─ buff 折算（见第 4 节）
  ├─ qiRaw  = floor(有效分钟 × 0.5 × (1 + offline 特效))
  ├─ qiRoom = max(0, 气海 − 当前灵力)
  ├─ qi     = min(qiRaw, qiRoom)
  └─ overflow = qiRaw − qi

settleOffline(state)        // 写入：qi / lastSeen / 日志
meditate(state)             // 打坐 = 当场调一次 settleOffline
```

`idlePending` 是**预演**，`settleOffline` 是**结算**，`meditate` 调的是同一个 `settleOffline`。三处不许各算一遍——这是「一个数只有一个出处」的具体执行。

**`lastSeen` 只在 `settleOffline` 里推进**（结算即归零），`game.save()` 绝不碰它。这一条是踩出来的：存档每改一次都发生（领份例、换门、参悟结算…），`save()` 里写一句 `lastSeen = now` 就等于把攒下的闭关时长一次次抹掉。真机上的症状是——冷启动弹「闭关收获 灵力 +90」，关掉弹窗灵力还是 0，下次进来又弹 +90。

## 4. buff：刚练完，气机还热着

`applyPractice` 在非失败时设一个 30 分钟的 buff：

| 上一局评级 | buff 倍率 |
| --- | --- |
| S | ×1.8 |
| A | ×1.5 |
| B | ×1.25 |
| C | ×1.1 |
| F | 不设（失败没有加成） |

计算方式：落在 `buff.until` 之后的分钟按 ×multiplier 折算，其余按 1 折算。

```
有效分钟 = buff 覆盖分钟 × 倍率 + 其余分钟
```

**这个倍率只作用于闭关折算**，不进熟练度、不进资源产出。语义是「刚练完，坐一会儿更有效率」——它同时让「先打两局再挂着」变成有意义的顺序。

## 5. 气海：三个数必须分开报

| 字段 | 含义 |
| --- | --- |
| `qiRaw` | 这一趟坐出来的总量 |
| `qi` | 实际收下的（受气海空位限制） |
| `overflow` | 装不下、当场散掉的 |
| `full` | 空位是否为 0 |
| `qiRoom` | 空位数 |

恒等式 `qi + overflow = qiRaw` 被断言守着。日志写：

```
闭关 5 时 48 分，灵力 +174（气海已满，散去 66）
```

**「散去多少」必须写出来**。静默吞掉会让玩家以为离线收益坏了；只写「气海已满」又不够——玩家想知道自己损失了多少。

## 6. 打坐的三条回执

| 情况 | 回执 | 为什么 |
| --- | --- | --- |
| 有灵力可收 | `打坐 12 分：灵力 +6（174 满）` | 报清时长、所得、上限 |
| 灵力已满 | `灵力已满（174 / 174）：再坐也装不下，去参一局，或破境、练真元拓气海。` | 满池**没有第二条产出**可收（闭关不产熟练度），所以这里要说「满了」并指出路 |
| 不足 1 点 | `还没攒够一点。再坐两分钟，回来就能收。` | **明确回一句**，不静默吞掉。「点了没反应」是这类按钮最容易挨骂的毛病 |

**满池时绝不能说「还没攒够」。** 那句话在满池情形下是错的——玩家坐了很久，只是装不下。所以 `meditate` 先判 `full`，返回 `{ ok: false, full: true }` 而不是笼统的失败。

满池时主页**不摆**「闭关打坐」这一行：没有可收的东西就不给一个收不到的入口。满池这件事由主页那行提示说（「灵力已满 N / M · 去参一局」）。

## 7. 为什么不产熟练度

旧版闭关每小时给 2.5 点熟练度（8 小时 20 点，约半局）。现在**一分不给**，原因是关卡制：

- 当年关卡由熟练度算出（`levelFromProf`），而熟练度是那套系统里唯一只增的数；
- 挂机能涨熟练度，就是**挂着不玩也在推关卡**——「练到哪就在哪」变成「挂了多久就在哪」；
- 于是「参悟才是提速」是假话，而且玩家会发现最优解是「挂着不回、回来一次跨好几关」。
  （v9 起关卡只由「走通」推进，这条成因已不存在；但「闭关不产熟练度」的结论照旧成立——
  熟练度是练出来的，油和里程不能互相兑换。）

一句话：**熟练度是「练出来的」，闭关只提供练的燃料。** 油和里程不能互相兑换，这条与「灵力买不回灵石」是同一条判据。

代价：气海满时挂机零收获。这是有意的——满池还挂着有收益，等于鼓励挂着不回来。

## 8. 边界情况

| 情况 | 处理 | 理由 |
| --- | --- | --- |
| 时钟倒退 | 不结算，也不把回拨值写进存档 | 改系统时间不能刷灵力 |
| 云端存档来自时间超前的设备 | 同上（`last > now` 直接返回 null） | 两台设备时间不同步是常态 |
| 不是同一分钟 | `< 1 分钟` 不结算 | 一分钟只有 0.5 点，取整为 0 |
| 闭关期间 buff 过期 | 只按覆盖的分钟折算 | 见第 4 节 |
| 气海满时打坐 | 挡回并说明「满了」 | 见第 6 节 |
| 冷启动先 hydrate 再结算 | `store.init()` 不结算，`app.bootstrap()` 在 `hydrate()` 之后调 `store.settle()` | 先结算会被云端档整个覆盖，玩家看到 +90 而账上没有 |

## 9. 界面

| 位置 | 内容 |
| --- | --- |
| 主页 | 坐满 1 分钟、且气海有空位，出现一行「已坐 12 分 · 灵力 +6 / 上限 174」，可点 |
| 主页（满池） | 不出这一行；由提示行说「灵力已满 N / M · 去参一局」 |
| 冷启动 | 弹窗：「闭关 5 时 48 分」+ 灵力行 + 溢出提示 |
| 洞府（主页） | 打坐按钮，随时可点 |

**「已坐 N 分」这一行要自己走起来**（定时刷新），否则玩家会以为那是静态文案。

弹窗的触发点有两个：`onShow` 一次、`refresh()` 末尾一次——冷启动的结算发生在 `hydrate()` 回来之后，早于页面 `onShow` 也早于第一次 `refresh`，只在 `onShow` 里看一眼会漏掉。

## 10. 被否决的方案

| 方案 | 为什么否掉 |
| --- | --- |
| 只有冷启动才结算 | 想收灵力就必须杀进程重开，荒诞 |
| 打坐与闭关两套算法 | 两个数会对不上（「弹窗说 +6，点打坐给 +5」） |
| 离线无上限 | 挂 24 小时和挂 8 小时一样，时长失去意义 |
| 上限只由时长（8h），无气海 | 见 `02-qihai.md` |
| 满池时禁止打坐（旧版） | 那时打坐还产熟练度，禁掉等于废了按钮。现在不产了，满池就该挡回并说明 |
| 溢出静默丢弃 | 玩家会以为离线收益坏了 |
| **挂机给熟练度**（旧版，已删） | 关卡由熟练度算出，挂着就能推关卡；「参悟才是提速」变假话。见第 7 节 |
| 挂机喂「战力最高的门」 | 那条分支随熟练度产出一起删了；现在闭关没有「喂给哪一门」这件事 |
| 挂机也给灵石 | 破坏两条货币线 |
| `game.save()` 顺手推进 `lastSeen` | 存档远比结算频繁，等于每次存档都把闭关时长抹掉（真机丢过一整晚的收益） |

## 11. 数值推导

**为什么 0.5/分**：一天 10–15 局的量级。小成段 14 点/局，一天要 140–210 点，8 小时 240 点正好覆盖。旧版是 1.2/分——那是「参悟产灵力、挂机只是贴补」时代的数，那时攒的灵力根本没处花。

**为什么一分熟练度都不给**：关卡只由走通推进，熟练度不推关（v9 起如此；旧版熟练度兼作关卡刻度，那条成因已不存在）。但闭关若给熟练度，就等于开了一条「不玩也涨」的只增轴——熟练度本是火候与属性的刻度，不该被挂机冲淡。而慢车道一旦存在，玩家算得比设计者清楚。

**为什么 buff 最高 ×1.8**：S 打完接着挂机，20 分钟能多收 16 点（约一局困难）。够让人愿意「先打再挂」，但不足以让玩家为了 buff 而刻意刷 S。

**为什么上限是 8 小时**：一个整夜 + 一个白天。超过 8 小时的部分对「日循环」没有意义，只会让「隔一天回来」和「隔三天回来」收益一样。

## 代码指路

- `data/world.js` —— `idle`（0.5 / 8）
- `utils/game/` —— `idlePending()`、`settleOffline()`、`meditate()`、`buffInfo()`；`save()` 里有「不许写 lastSeen」的注释
- `utils/store.js` —— `init()` 只读档不结算、`settle()` 才是结算入口
- `app.js` —— `bootstrap()` 在 `hydrate()` 之后调 `store.settle()`
- `pages/index/index.js` —— `refreshIdle()`（定时刷新那一行）、`maybeShowOffline()`（弹窗两个触发点）
- `tests/game.test.js` —— 溢出三数、满池打坐不静默、时钟倒退、`save()` 不动 `lastSeen`、闭关不涨熟练度
- `tests/store.test.js` —— 「冷启动：闭关灵力在 hydrate 之后才结算，不会被云端档吃掉」

## 待验（必须真机）

- 「闭关打坐」按钮要**在洞府里坐满一分钟后才出现**。这个延迟是否会被误认为「没有这个功能」。
- 连点打坐是否会出现「0 点」的残影提示。
- 冷启动弹窗里「散去 66 点」是否会被读到（玩家注意力通常在「收了多少」）。
- 挂机不再涨熟练度之后，玩家会不会觉得「挂着白挂」——这句话正是要传达的，但语气上是否太冷。
