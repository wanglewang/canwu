# 闭关与打坐

> 闭关与打坐是**同一套算法、两种触发**。区别只在：冷启动回来时弹给你，还是你当场点一下收走。
>
> 灵力是参悟的油。油烧完了不该逼玩家杀掉小程序再开一遍——这就是「打坐」存在的全部理由。

---

## 1. 一句话

离开期间按 0.5 灵力/分、2.5 熟练度/时累积，一次最多算 8 小时；装满气海的部分不收，回来第一件事是收它。

## 2. 参数

| 参数 | 值 | 出处 |
| --- | --- | --- |
| `qiPerMinute` | 0.5 | `world.idle` |
| `profPerHour` | 2.5 | `world.idle` |
| `capHours` | 8 | `world.idle` |

8 小时产能 = 240 灵力 / 20 熟练度。**但炼气气海只装 174**（5.8 小时即满）——所以炼气期先到的是气海，不是时长。筑基之后（284）才轮到 8 小时这个上限。

> 20 熟练度 ≈ 半局（S 34 点）。挂机能练，但远不如真打。

## 3. 一次结算的完整过程

```js
idlePending(state)          // 只算不写：页面据此显示「已坐 N 分 · 灵力 +M」
  ├─ 时钟倒退？→ 全 0
  ├─ 时长 = min(now − lastSeen, 8h)
  ├─ buff 折算（见第 4 节）
  ├─ qiRaw  = floor(有效分钟 × 0.5 × (1 + offline 特效))
  ├─ qiRoom = max(0, 气海 − 当前灵力)
  ├─ qi     = min(qiRaw, qiRoom)
  └─ overflow = qiRaw − qi

settleOffline(state)        // 写入：qi / prof / lastSeen / 日志
meditate(state)             // 打坐 = 当场调一次 settleOffline
```

`idlePending` 是**预演**，`settleOffline` 是**结算**，`meditate` 调的是同一个 `settleOffline`。三处不许各算一遍——这是「一个数只有一个出处」的具体执行。

## 4. buff：刚练完，气机还热着

`applyPractice` 在非走火时设一个 30 分钟的 buff：

| 上一局评级 | buff 倍率 |
| --- | --- |
| S | ×1.8 |
| A | ×1.5 |
| B | ×1.25 |
| C | ×1.1 |
| F | 不设（走火没有加成） |

计算方式：落在 `buff.until` 之后的分钟按 ×multiplier 折算，其余按 1 折算。

```
有效分钟 = buff 覆盖分钟 × 倍率 + 其余分钟
```

**这个倍率只作用于闭关折算**，不进熟练度、不进资源产出。语义是「刚练完，坐一会儿更有效率」——它同时让「先打两局再挂着」变成有意义的顺序。

## 5. 气海：三个数必须分开报

| 字段 | 含义 |
| --- | --- |
| `qiRaw` | 这一趟坐出来的总量 |
| `qi` | 实际收下的（受气海空位限制） |
| `overflow` | 装不下、当场散掉的 |
| `full` | 空位是否为 0 |
| `qiRoom` | 空位数 |

恒等式 `qi + overflow = qiRaw` 被断言守着。日志写：

```
闭关 5 时 48 分，灵力 +174（气海已满，散去 66），刀法·开锋诀 +14
```

**「散去多少」必须写出来**。静默吞掉会让玩家以为离线收益坏了；只写「气海已满」又不够——玩家想知道自己损失了多少。

## 6. 打坐的三条回执

| 情况 | 回执 | 为什么 |
| --- | --- | --- |
| 有灵力可收 | `打坐 12 分：灵力 +6（174 满）· 刀法·开锋诀 +1` | 报清时长、所得、上限 |
| 灵力已满但熟练度可收 | `灵力已满（174），这一坐只涨熟练度` + 熟练度 | 打坐还产熟练度，那是另一条产出，不能因满池而废掉按钮 |
| 不足 1 点 | `还没攒够一点。再坐两分钟，回来就能收。` | **明确回一句**，不静默吞掉。「点了没反应」是这类按钮最容易挨骂的毛病 |

**满池时绝不能说「还没攒够」。** 那句话在满池情形下是错的——玩家坐了很久，只是装不下。所以 `meditate` 返回 `{ ok: false, full: true }` 而不是笼统的失败。

## 7. 挂机喂给哪一门

`pickIdleSkill(state)`：

1. 上一次参悟的那门，若未到圆满（< 24000）→ 继续喂它；
2. 否则按 `SKILLS` 顺序找第一门已习得且未到圆满的；
3. 都满了 → 第一门（熟练度不再涨，但日志仍记）。

**为什么以 24000（圆满）为界而不是 99999**：圆满之后每局要绝境难度才划算，挂机那 20 点熟练度对 76000 点的长尾毫无意义。让位给还没练满的门，收益更大。

## 8. 边界情况

| 情况 | 处理 | 理由 |
| --- | --- | --- |
| 时钟倒退 | 不结算，也不把回拨值写进存档 | 改系统时间不能刷灵力 |
| 云端存档来自时间超前的设备 | 同上（`last > now` 直接返回 null） | 两台设备时间不同步是常态 |
| 不是同一分钟 | `< 1 分钟` 不结算 | 一分钟只有 0.5 点，取整为 0 |
| 闭关期间 buff 过期 | 只按覆盖的分钟折算 | 见第 4 节 |
| 气海满时打坐 | 照收熟练度 | 见第 6 节 |

## 9. 界面

| 位置 | 内容 |
| --- | --- |
| 主页 | 坐满 1 分钟出现一行「已坐 12 分 · 灵力 +6 / 上限 174」，可点 |
| 主页（满池） | 「灵力已满 174 · 只涨熟练度」 |
| 冷启动 | 弹窗：「闭关 5 时 48 分」+ 灵力行 + 熟练度行 + 溢出提示 |
| 洞府（主页） | 打坐按钮，随时可点 |

**「已坐 N 分」这一行要自己走起来**（定时刷新），否则玩家会以为那是静态文案。

## 10. 被否决的方案

| 方案 | 为什么否掉 |
| --- | --- |
| 只有冷启动才结算 | 想收灵力就必须杀进程重开，荒诞 |
| 打坐与闭关两套算法 | 两个数会对不上（「弹窗说 +6，点打坐给 +5」） |
| 离线无上限 | 挂 24 小时和挂 8 小时一样，时长失去意义 |
| 上限只由时长（8h），无气海 | 见 `02-qihai.md` |
| 满池时禁止打坐 | 见第 6 节 |
| 溢出静默丢弃 | 玩家会以为离线收益坏了 |
| 挂机自动喂「战力最高的门」 | 与「上次练的那门」相比，玩家预期的连续性更重要 |
| 挂机也给灵石 | 破坏两条货币线 |

## 11. 数值推导

**为什么 0.5/分**：一天 10–15 局的量级。困难档 14 点/局，一天要 140–210 点，8 小时 240 点正好覆盖。旧版是 1.2/分——那是「参悟产灵力、挂机只是贴补」时代的数，那时攒的灵力根本没处花。

**为什么 2.5 熟练度/时**：8 小时 20 点 ≈ 半局。挂机是「不在时的补贴」，不是「主要玩法」。给多了会让「挂着」比「打着」划算。

**为什么 buff 最高 ×1.8**：S 打完接着挂机，20 分钟能多收 16 点（约一局困难）。够让人愿意「先打再挂」，但不足以让玩家为了 buff 而刻意刷 S。

**为什么上限是 8 小时**：一个整夜 + 一个白天。超过 8 小时的部分对「日循环」没有意义，只会让「隔一天回来」和「隔三天回来」收益一样。

## 待验（必须真机）

- 「闭关打坐」按钮要**在洞府里坐满一分钟后才出现**。这个延迟是否会被误认为「没有这个功能」。
- 连点打坐是否会出现「0 点」的残影提示。
- 冷启动弹窗里「散去 66 点」是否会被读到（玩家注意力通常在「收了多少」）。
