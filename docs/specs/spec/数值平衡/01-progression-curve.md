# 需求（Spec）· 进度曲线：一条 1000 关的线，与一个 6000 点预算实验

> 一门功法就是一条 1–1000 的长线。走通当前关 = +1 关，其余一律 +0。
> 所以「走完一门」恒为 **1000 局**——评级、品阶、境界都不改这个数。
> 真正的约束不是进度公式，而是灵力：全 C 走完要 22020 点（≈ 闭关 734 小时）。

## 核心前提：进度不再是「点数」，而是「走了多远」

2026-11 之前这里有一条「熟练度」曲线：评级决定基数、连 S 决定倍率，全 C 要 10000 局、全 S 只要 84 局，
中间 119 倍是整套设计的主角。那套机制已经整条删除，原因不是「数值不好看」，而是它和「第几关」并排显示时，
玩家永远不知道自己算几级——两个数都在回答同一个问题，答案却不一样。

现在是另一种难度来源：**没有公式可优化，只有内容要走完**。
一局一关意味着「进度」这件事不再有策略空间——你不能靠刷哪一关加速，只能一关一关走下去。
玩家要权衡的从「怎么刷最划算」变成了「这一池灵力先练哪一门、这一门走到哪一段」。

## 1. 概述

| 维度 | 回答 |
| --- | --- |
| 一局推几关 | 走通本门当前关 = 1，其余 = 0 |
| 走完一门要几局 | 恒为 1000 局 |
| 走完一门要多少灵力 | 黄阶全 C 22020 点（≈ 闭关 734 小时）；地阶更贵 |
| 评级影响什么 | 结算观感、30 分钟挂机 buff 档位、称号与成就 |
| 品阶影响什么 | 耗气、属性、可修境界 |
| 境界影响什么 | 能不能修这一门（门槛）、超上限后每局 ×1.5 耗气 |

## 2. 两段实测（`npm run sim`）

```
== 全 C 走完 1000 关：一路打本门当前关 ==
  段位        局数   门槛
  入门             10     10
  小成             50     50
  大成            200    200
  圆满            500    500
  大圆满          1000   1000
  共烧灵力 22020 点 ≈ 闭关 734 小时

== 全 S 走完 1000 关：对照「评级不换进度」==
  局数 1000（与全 C 相同）· 烧气 22020 点（与全 C 相同，耗气与评级无关）
```

| | 局数 | 灵力 | 闭关时长 |
| --- | --- | --- | --- |
| 全 C | 1000 | 22020 | 734 小时 |
| 全 S | 1000 | 22020 | 734 小时 |
| 差值 | **0** | **0** | **0** |

**这张表的意义是「没有差值」。** 它不是巧合，是 `advanced` 那一行代码的直接后果：
评级进不了进度，也进不了耗气。旧版那 119 倍曾经是设计的主角，现在它是 1 倍——
因为「打得好」的回报被搬到了别处（观感、挂机、称号），不再兑现成进度。

### 2.1 六档门槛

| 段位 | 门槛（已走通几关） | 全 C 局数 | 全 S 局数 |
| --- | --- | --- | --- |
| 未入门 | 0 | — | — |
| 入门 | 10 | 10 | 10 |
| 小成 | 50 | 50 | 50 |
| 大成 | 200 | 200 | 200 |
| 圆满 | 500 | 500 | 500 |
| 大圆满 | 1000（硬顶） | 1000 | 1000 |

**门槛就是段界关**（`data/levels.js` 的 `STAGE_GATES`），这是刻意的：
段位不该是另一把尺子，它就是「你走到第几关」的别名。写成「段界关 +1」会让段位与「下一关在哪一段」差一档，
准备页与功法页立刻对不上（这次改版第一版就踩过，见 `tasks/07` 的对应条目）。

## 3. 耗气曲线：往后每一步都更贵

```
== 五段耗气（黄阶 · 悟性 10 · 不换门 · 未超上限 · 各段首关）==
  未入门  基数   7 → 实价   6 点 · 每点灵力推 0.167 关
  入门    基数  11 → 实价   9 点 · 每点灵力推 0.111 关
  小成    基数  17 → 实价  14 点 · 每点灵力推 0.071 关
  大成    基数  24 → 实价  20 点 · 每点灵力推 0.050 关
  圆满    基数  32 → 实价  27 点 · 每点灵力推 0.037 关
```

实价 = 基数 × 本门时长系数 ÷ 悟性系数，唯一真源 `economy.practiceQiCost()`。

**这一段承担了旧版「连 S 曲线」的角色**：关卡越往后越贵，所以「往后走」本身就是一种投入。
旧版靠「连 S 只在当前关叠」逼玩家往前走；现在不需要那道闸——回关不推进度，往回走的收益恒为 0。

### 3.1 地阶对照

```
  未入门   黄阶  6 → 地阶 10（×1.67）
  入门     黄阶  9 → 地阶 16（×1.78）
  小成     黄阶 14 → 地阶 25（×1.79）
  大成     黄阶 20 → 地阶 35（×1.75）
  圆满     黄阶 27 → 地阶 46（×1.70）
```

品阶只抬价，不改进度：地阶同预算推得少，是因为每一关都更贵。

### 3.2 一池灵力能打几局

闭关 0.5 点/分，8 小时产能 240 点，但炼气气海只装 **174** 点（5.8 小时即满，溢出 66 点收不到）。

| 段位 | 一池（174 点）能打 |
| --- | --- |
| 未入门 | 29 局 |
| 小成 | 12 局 |
| 圆满 | 6 局 |

想把一池练大，靠破境（气海 150 → 620）与真元（每点 +2）。
「一次只能打几局」是这套经济真正的节奏闸。

## 4. 6000 点预算实验

固定 6000 点灵力（≈ 闭关 200 小时），五种刷法：

| 刷法 | 局数 | 推了几关 | 每关灵力 |
| --- | --- | --- | --- |
| 黄阶 · 只刷第 1 关 | 1000 | **1** | 6000 |
| 黄阶 · 逐关进 | 376 | 355 | 17 |
| 黄阶 · 退一章 | 1000 | **1** | 6000 |
| 地阶 · 逐关进 | 251 | 239 | 25 |
| 黄阶 · 金丹后 | 270 | 258 | 23 |

### 4.1 结论

1. **「往回刷」推不动进度**：只刷第 1 关与退一章都只推得动第 1 关——第 2 局起就是回关，进度恒 +0。
   这是结构性的，不是靠折减系数压出来的：旧版为堵这个洞打了四道补丁（回关折减 / 连 S 只在当前关叠 / 断连 / 主动结束归零），
   现在只需要一句「回关不推进度」。
2. **逐关进是唯一能走远的路**：同样的 6000 点，逐关进推 355 关，两条往回刷的路各推 1 关。
3. **品阶加价是真的**（地阶 239 vs 黄阶 355 关）：地阶耗气更贵，同样的气走得更短。天阶功法已于 2026-11 退役，
   拿天阶做对照的旧句一并作废。
4. **金丹后练黄阶更慢**（258 vs 355 关）：境界超过 `maxRealm` 时耗气 ×1.5。
   这是「往上走之后该换功法」的硬约束。

## 5. 三条守恒关系

| 关系 | 内容 |
| --- | --- |
| 进度 ↔ 灵力 | 进度只吃灵力，不吃灵石 |
| 灵石 ↔ 战力 | 灵石只买功法与布阵，不买进度 |
| 参悟只耗不产 | 参悟**不产任何资源**，1.2% 的机缘只出残卷 |

**「参悟不产资源」是这套经济的地基**。它一旦松动，玩家就会找到「用参悟刷灵石」的路，两条货币线当场糊掉。

## 6. 为什么不做成像样的「加速曲线」

旧版那条 1 : 5 : 20 : 80 : 333 的门槛比例，本质是在对抗「多花时间就够」。
那条曲线之所以必须存在，是因为进度是**点数**——点数可以被「多刷」买到，所以要让它加速扩张。

进度改成「关卡」之后，这个问题消失了：一门只有 1000 关，走完就是走完。
1000 局是不是太长，这个问题只能靠留存回答，不能靠调公式解决
（真要缩短，应该减内容或降耗气，而不是给进度乘个系数）。

## 7. 被否决的方案

| 方案 | 为什么否掉 |
| --- | --- |
| 进度乘评级系数 | 会让「S 一局顶 C 三局」，玩家立刻开始找「哪一段最容易拿 S」。这是旧版所有刷法漏洞的总根 |
| 连 S 叠倍率 | 它奖励的是「一直打同一门」，而换门已经有省气的正激励。保留它就得同时保留层数存档、断连规则、「回关不叠层」的例外——四套东西只服务一个已经不存在的数 |
| 进度乘品阶倍率 | 会让「练天阶」变成唯一正确选择，黄阶功法失去存在意义 |
| 进度乘境界倍率 | 与「境界是上限而非收益」冲突 |
| 进度乘属性（悟性） | 悟性已经负责「省灵力」，再让它加进度就是双重收益 |
| 回关折减 | 折减是「回关也有收益」时才需要的护栏。回关收益恒为 0 之后，折减成了给 0 打折 |
| 回关也推进度（每次只推半关） | 半关要落成整数就得有「余数记账」，于是又出现「停在某处攒余数」的最优解 |
| 线性门槛 / 加速门槛 | 门槛不再是可调的旋钮：它就是关号 |
| 参悟产灵石 | 两条货币线当场糊掉 |

## 8. 代码指路

- `scripts/simulate.js` —— `GRADE_DIST`、`walkAll()`（全 C / 全 S 两条曲线）、`runBudget()`（五种刷法）
- `data/world.js` —— `TIERS`（六档门槛 = 段界关）
- `data/levels.js` —— `STAGES` / `STAGE_GATES` / `LEVEL_MAX`
- `data/economy.js` —— `RUN_QI`（五段基数）、`practiceQiCost()`、`qiCapOf()`
- `data/practice.js` —— `retreatText()`（回关只说「不推进度」，不再算折减）
- `utils/game/settle.js` —— `applyPractice()` 的 `advanced` 一行
- `tests/game.test.js` —— 「一局只推一关」「一门 1000 关就是 1000 局」
- `tests/rank.test.js` —— 六档门槛 = 段界关、回关不推进度

## 9. 待验

- **`GRADE_DIST` 从未用真机数据校准**。它现在还留在 sim 里，但只影响「随机评级下推多少关」的次要读数，
  已不影响进度曲线（进度与评级无关）。真机数据回来后这一篇的主表不会变，这是删掉点数曲线的额外收益。
- **1000 局是不是太长**：全 C 走完 1000 关要 22020 点灵力、≈ 734 小时闭关，实际是一年量级。
  这是刻意的（一门一条线、慢慢走），但「走得完吗」只能靠留存回答。
- **一池 6 局（圆满段）** 是否太紧：每次进游戏只能打几局，可能让「今天练一门」变成「今天打两把」。
  要不要抬气海或降圆满段耗气，待真机。
- 地阶比黄阶贵 1.7 倍左右，但进度一样快（都是一局一关）——品阶的价值全在属性与可修境界上。
  「贵 70% 值不值」要靠玩家选门的数据看，未验。
