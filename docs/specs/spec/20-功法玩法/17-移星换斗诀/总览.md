# 需求（Spec）· 机关·移星换斗诀 → 滑块让路（总）

## 玩法概述

一张 4×4 的小盘上卡着六块石头，中间那块 2×2 的主块要一路挪到盘底的出口。你一次平移一整块，给主块让出一条路。我想做的不是「找最短路线」，而是「腾位置」——关键判断永远是「先挪开谁、才轮得到主块过去」。走的路越省越算功夫：正好等于本盘最优步数才拿 S。

这里有个别处没有的规矩：压力不来自时辰，只来自步数预算——走完预算还没脱身就「困住了」。预算按本盘最优步数算比值，所以同一玩家在不同盘面上拿 S 的难度一致。五段盘面始终是 4×4 六块，变的是「这一局有多绕」（最优 2–4 步一路涨到 6–12 步）和「走错几步还救得回来」（预算系数一路收）。

```text
  ┌───┬───┬───┬───┐
  │   │横 │   │   │
  ├───┼───┼───┼───┤
  │竖 │主 │主 │散 │  ← 主块 2×2，要挪到底部出口
  │   │主 │主 │   │    先挪开挡路的横块 / 竖块
  ├───┼───┼───┼───┤
  │   │散 │   │   │
  ├───┼═══╪═══┼───┤  ← 盘底正中：出口 + 向下箭头
  └───┴───┴───┴───┘
  点选一块 → 方向键平移 → 步数预算内让主块脱身
```

## 1. 盘面介绍

固定 4×4，六块：

| 块 | 尺寸 | 数量 | 用途 |
| --- | --- | --- | --- |
| 主块 | 2×2 | 1 | 要挪到盘底出口的那一块（挂纹样 20 号） |
| 横块 | 2×1 | 1 | 挡路的主要障碍 |
| 竖块 | 1×2 | 1 | 同上，方向不同 |
| 散块 | 1×1 | 2 | 灵活，用来「让位」 |

**空格六格**。每局盘面随机生成，生成后由 BFS 现算最优步数，只接受落在 `[minOpt, maxOpt]` 区间里的盘面；
40 次抽样都失败时退回一张「主块就在出口上方」的保底盘。**绝不给玩家无解盘**。

块是整块滑的，用绝对定位按百分比摆（`left / top / width / height`），不用格子拼——格子拼出来的块会被缝线切碎，
看不出「这是一整块」。台面下压着一层 4×4 的暗格线，只做参照：块挪动时玩家需要一个「格」来量距离，否则只看见几片色块在飘。

盘底正中两格是出口：虚线缺口 + 一个向下的箭头（箭头用两条边画，字符箭头在部分安卓机上会被换成彩色 emoji）。

## 2. 规则说明

| 项 | 规则 |
| --- | --- |
| 移动 | 先点一块选中，再按方向键，该块整体平移一格 |
| 阻挡 | 挪过去会重叠或出界就是「挪不动」，不扣步数 |
| 脱身 | 主块落到盘底出口（第 2–3 列最下一行）即完成 |
| 预算 | `capSteps = max(最优 + 2, ceil(最优 × 本段系数))` |
| 系数 | 五段 3.20 / 2.90 / 2.70 / 2.50 / 2.20，段内再按进度收 18%，**封底 2.05** |
| 失败（F） | 预算走完主块还没脱身 → 「困住了」，F |
| 复位 | 「盘面复位」把块搬回开局位置、步数清零，**最优步数不变**，但**本盘最高只判 A** |
| 得分 | `(预算 − 已走) × 10`，只用于破纪录 |

**没有时限**。压力只来自步数预算。

`max(最优 + 2, …)` 是硬底线：预算永远不会小于最优步数，不会出现「明明能解却判 F」。

### 操作：两段式

两段式：先点选块（`tap`），再按四向键（`move`）。

- 方向键四向齐全，图标由 CSS 画（`pad.keys[].icon`）；
- **选中一块后，它挪不过去的方向在键上先压暗**（`shut`）。压暗不是禁用——按下去照样给「挪不动」的回话，规则一个字没改；压掉的只是「先按一下试试能不能过」这件试错；
- **四面都堵的块**：四个键一起压暗，选中时直接浮字「这块四面都堵着 · 换一块」。4×4 上这种情况不罕见（横石被主块与散石夹在角上），不说一句就得四个方向各试一遍；
- 挪不动时**指名道姓**：撞盘沿说「那边是盘沿」，被块挡住说「横石挡着」，同时把挡路的那一块描红 460ms。盘沿与被占是两件事，玩家下一步要做的动作完全不同；
- 复位键（`showReset`）随时可用，代价是本盘最高只判 A。

两段式而不是「点块直接拖」：拖动在 4×4 小盘上极易误判方向（尤其竖块与横块相邻时），点选 + 按键是确定的。

### 评级

| 评 | 判据 |
| --- | --- |
| S | 已走步数 = 本盘最优步数 |
| A | 多 2 步以内 |
| B | 不超过最优的两倍 |
| C | 超过两倍才脱身 |
| F | 预算走完还没脱身 |
| — | **复位过本盘，S 一律降到 A**（其余段不受影响） |

这是**比值族**评级：分母是本盘最优步数，不是固定门槛。同一个玩家在不同盘面上拿 S 的难度一致，这就是「用比值而不用绝对步数」的理由。

最后一行是补的一条限制：它不属于「五段」，而是叠加在五段之上。A / B / C 本来就够不到 S，封顶对它们没有影响；只有「本来能拿 S」的那条路径被压下来。`lines().items` 里因此有第五条，说明页照抄。

## 4. 设计依据

### 4.1 预算系数为什么随段收紧

以前系数固定 2.4，段越高最优步数越长、预算也跟着变宽——「越难容错越大」，方向是反的。圆满段最优 12 步配 29 步预算，`困住了` 几乎不会发生，C 带满地走。

现在系数随段从 3.20 收到 2.20，再按段内进度收 18%，末段封底 2.05。方向是「越往后余量比例越小」，而不是「预算绝对步数变小」——后者会把一切都压成 F。

### 4.2 为什么封底 2.05

C 线是「超过最优两倍才脱身」。预算一旦压到两倍最优以下，玩家还没走到两倍就先判「困住了」——
**C 这一段永远拿不到**，评级表里那行评语等于删掉。那不是变难，是断层。所以系数有硬下限，`tests/rank.test.js` 逐段守着。

同理，段内收紧不能按全书进度做。`buildParamsAt` 已经对 `capFactor` 按时间键收过一次（`1 − 0.30f`），若 `tweakParams` 再按全书进度叠一刀，第一段末（第 10 关）的预算会被整段的进度吃掉，而下一段开头（第 11 关）按段位本该回升——两刀叠出来的曲线会在段界处倒挂。现在先把前一刀除掉，再按一段 18% 重收：段内一路更紧，换段回一口气。

### 4.3 与落石垒基、推石入位三方对比

| | 落石垒基 | 滑块让路 | 推石入位 |
| --- | --- | --- | --- |
| 谁动 | 块自己往下落 | 整块滑，能左右挪 | 人走，箱子只推不拉 |
| 目标 | 填满整层消除 | 主块到出口 | 每块推到自己的阵位 |
| 压力 | 实时下落 | 回合制、步数预算 | 回合制、推数预算 |
| 不可逆 | 堆到顶 | 可以复位 | 推错只能重来 |

三者都是「格子 + 移动」，但动作与不可逆性完全不同。移星换斗诀是**唯一允许整块平移**的一门——这决定了它的核心不是「路线规划」而是「腾位置」。

### 4.4 为什么用 BFS 现算最优，而不是手写最优步数

手写的最优步数一旦与盘面不符，S 线就变成「猜出来的」。BFS 现算几毫秒一次，且**保证下限成立**：只要 solvable 就一定有解，最优值也一定对。

实测：4×4 六块的随机盘，最优步数分布是双峰的——1 步占 10%（主块就在出口上方），3–9 步各占 4–7%，10–14 步回升到 7–9%，16 步是上界。所以 `[minOpt, maxOpt]` 区间在任一段都能抽到足够样本，40 次抽样的失败率可以忽略。

代价是每局开局有一小段计算（40 次抽样 × 每次 BFS），在低端机上首次进入会感觉「卡一下」。这是用 CPU 换正确性的取舍。

### 4.5 为什么没有时限

这一门考「想清楚再动」，加时限就变成手速游戏，且与「点选 + 按键」的两段式操作天然冲突（光是选块就要花时间）。

全站 16 套盘面里（十五门功法 + 突破的蓄力停区），压力的来源只有四类：**时钟**（多数）、**步数 / 推数预算**（移星换斗诀、推石入位）、**盘面空间**（滑格相合，盘满即死）、**精度**（终局蓄力，一按定生死）。移星换斗诀属于第二类。

### 4.6 为什么保留「盘面复位」

挪错一步就退不回去——没有撤销会让人卡在死局里反复确认「是不是无解」。复位提供一条明确的逃生口：**重来一遍，同一张盘**。

但逃生口不能变成免费重抽。盘面固定 + 复位清零是一对危险组合：「挪一步 → 复位 → 再挪」可以把最优路径整个试出来，S 就变成「肯反复重来」的奖励，而不是「一步没浪费」的结果。所以复位**记一次痕，本盘封顶 A**，并把这句话同时写在按钮反馈、局内浮字与说明页的四条线之后。这与阵灯推演的复位、推石入位的复位是同一条规矩，不另立一套（阵灯的阵眼感应不走封顶，它直接折步数：每看一眼算 2 步）。

推石入位用的不是封顶，而是「撤销只退位置、不退推数」——因为它的推数是唯一记账口径，而移星换斗诀的步数会因为复位直接清零。同一个漏洞，两种堵法，判据见 `docs/specs/constitution/02-十三条设计原则` 第九节 9.3。

### 4.7 被否决的方案

这张表是当时否掉的念头，每一行都留着诱因和收手的理由。头三条都围着「复位 / 撤销」打转——这是这一类滑块谜题最容易漏的漏洞，值得连起来读。

| 方案 | 为什么否掉 |
| --- | --- |
| 单步撤销 | 会让「最优步数」失去意义：撤销到完美即 S，等于没有难度。推石入位的做法（撤销不退推数）在移星换斗诀上不成立——这里只有「步数」一个计数，退了就真没了，所以改为给复位封顶 |
| 复位不封顶 | 等于承认「反复重来也算一步没浪费」，`docs/specs/spec/checklist-puzzle.md` 第二节「反悔必须留痕」直接失效 |
| 复位扣预算 | 会让走死的玩家在「剩余预算已经很少」时复位到几乎必败的局，逃生口变成陷阱 |
| 加时限 | 见 §4.5，与两段式操作冲突 |
| 盘面放大到 5×5 | 最优步数会暴涨到 30+，一局在手机上要几分钟；而且空格变多，块反而更好让开 |
| 手写最优步数表 | 一改盘面就失真，且无法覆盖随机生成 |
| 拖动操作 | 4×4 小盘上误判率高，尤其横块竖块相邻时 |
| 加「提示下一步」 | 直接给出答案是取消这一门，只给「多 2 步」这种段位反馈 |
| 预算系数固定 2.4 | 段越高最优步数越长、预算也越宽，「越难容错越大」，绝境里 `困住了` 几乎不会发生 |
| 预算系数压到 2.0 以下 | C 线是「超过最优两倍才脱身」，压到两倍以下 C 这一段直接不存在——变难不能靠删掉一段评语 |
| 用方向键直接挪选中的块（不做压暗） | 玩家四个方向各按一次才知道哪边能过，把「给谁让路」的判断换成了试错 |

## 5. 界面与反馈

1. **判据**：主块与出口同列时缺口亮起（`aligned`），脱身那一手出口同帧变成开着的门（`open`）、主块沉进出口；浮字「脱身 · N 步」。
2. **代价**：挪不动指名道姓（盘沿 / 横石挡着）并把挡路块描红 460ms；复位按钮反馈与浮字都写「本盘最高 A」。
3. **操作**：两段式——先点选（选中块金环箍住），四向键图标由 CSS 画、挪不过去的方向先压暗；四面都堵时浮字提示换一块。
4. **进度**：HUD 常驻「已走 N 步 · 最优 M 步 · 预算 K 步」，余量写「余 K−N 步」。
5. **收束**：预算走完主块没脱身 → `C.flash`「步数用尽 · 困住了」，F；脱身按已走步数 / 最优步数结算。

挪对了不给浮字：块已经滑过去了，再报一句「挪了一格」是噪音。这一门唯一该主动说话的时刻是「挪不动」和「四面都堵」。

| 项 | 落点 |
| --- | --- |
| 难度 | 两条轴——最优步数（2–4 → 6–12）与预算系数（3.20 → 2.20）。`audit:diff` 3 参数 / 5 种线 / 3.00× `minOpt` |
| 显示 | ① 选中块挪不过去的方向在键上压暗；② 出口带向下箭头，主块与出口同列时缺口亮起；③ HUD 常驻「已走 N 步 · 最优 M 步 · 预算 K 步」；④ 挪不动时说清是盘沿还是谁挡着 |
| 特效 | ① 块挪动走 `transition: left/top 0.14s`——这一门的手感就是「滑过去」，不是瞬移；② 挡路的块描红 460ms 后自己撤；③ 脱身时主块沉进出口（`translateY(16%) scale(0.9)`），出口同帧从缺口变成开着的门 |
| 引导 | `guides.goal` 一句 + 首条讲压暗；术语补「压暗的方向键」「步数预算」「出口同列会亮」；整篇在 `topic=practice` |
| 关卡 | 段内 `capFactor` 按 18% 单调收紧，换段回升（段位重设），与「不朝下一段插值」同一条。**1000 关里 161 关的预算真的变了**，其余与上一关相同（撞上 2.05 封底后整数取整，或 0.01 的精度吃掉了），界面据实报「与上一关规格相同」 |

## 7. 待验

- ~~复位可以无限次~~ **已修**：`reset()` 置 `resetUsed`，`gradeOf()` 见它就把 S 压到 A，按钮反馈与 flash 都写「本盘最高 A」。
- **封顶之后会不会反而没人敢复位**：硬顶到「困住了」是 F，复位是 A。理论上复位严格优于硬顶，但玩家可能读不出这个比较，卡在死局里反复确认。文案层的观察项，不是机制问题。
- 40 次抽样 + BFS 在低端机首帧的耗时（尤其圆满段 `maxOpt = 12`，BFS 上限 `maxOpt + 6 = 18` 层）。本机实测 4000 盘抽样 15.8 秒（约 4ms/盘），低端机按 3 倍估算仍是十几毫秒一抽、最坏情况近半秒——**若真机首帧卡顿，把抽样次数降到 24 并放宽兜底盘**。
- 「点选 + 方向键」两段式在 4.7 寸屏上，拇指是否能同时够到盘面与方向键。
- 方向键压暗的明度差（`--jade-dim` 底 + 图标 45% 透明）在强光下够不够一眼；四键全压暗时会不会看着像「按键坏了」。
- 挡路块描红 460ms：够不够看清是哪一块；连着按两次挪不动时会不会闪烁。
- 脱身时主块沉进出口的幅度（`translateY(16%) scale(0.9)`）会不会让它看着像「掉出屏幕」而不是「进去了」。
