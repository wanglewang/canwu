## 破境这一步

先把一件事说在前头：这不是一门功法，不进参悟序列，只在境界突破时出现。突破是全流程唯一的不可逆节点——成功进一境、战力跳一段、气海拓宽；失败散一半灵石。前面几十局攒战力都是渐进、可预期的，最后一步如果只是点一下「确定」，破境就变成了勾清单。所以我给了它一个「手要稳」的动作。

按住按钮，蓄力值在 0 到 100 之间来回往复；松手那一刻定生死——停在红线之间就过，越靠正中评级越高；停在区间外就是「气机偏离」，这一次冲关作废，只有一次机会。我想立起来的就是这「临门一脚」：全站唯一考「手」不考「脑」的盘面，也是唯一一处窗口只有几十毫秒的地方。

## 1. 盘面介绍

没有格子，只有一条**蓄力条**：

- 蓄力值在 **0 → 100 → 0** 之间往复，每次 tick +4，**55ms 一跳**；
- 条上有一条「红线之间」，位置每局随机：`起点 = 42 + randInt(30)`（即 42%–71%），`终点 = min(96, 起点 + 区间宽)`；
- 区间宽：常局 **16**，`realmIndex ≥ 2`（金丹起）**22**；
- HUD 实时报「距正中 N% · X 评」，松手前就能看到当下是什么评级。

满程 100 分需要 25 跳 ≈ **1.375 秒**；一次完整往返 ≈ **2.75 秒**。蓄力值是 4 的倍数，一共 **26 个落点**。

因为落点只有 26 个（4 的倍数）、区间只有 16 宽，**实际落在区间内的落点只有 5 个左右**：

| 位置 | 举例（区间 42–58，正中 50） | 评 | 窗口时长 |
| --- | --- | --- | --- |
| 正中 ± 1 格 | 50 | S | 55–110ms（1–2 个落点） |
| 正中 ± 4 | 46 / 54 | A | 约 220ms |
| 正中 ± 8 | 42 / 58 | B | 约 220ms |
| 区间外 | ≤38 或 ≥62 | F | — |

**这是全站唯一一处「窗口只有几十毫秒」的地方**，理由见 §4.2。

## 2. 规则说明

| 项 | 规则 |
| --- | --- |
| 开始 | 按住按钮即开始蓄力，HUD 从「还没进红线」逐跳变化 |
| 结束 | 松手那一刻定生死，**只有一次机会** |
| 成功 | 停在红线之间（C / B / A / S 皆算成功） |
| 失败 | 停在区间外 → F「气机偏离」，「气机一乱」，这一次冲关作废 |
| 蓄力时长 | **不限**。0 ↔ 100 一直往复，可以看几个来回再松手 |
| 中途结束 | 也是 F，同样算失败 |

**判定（`gradeAt`）**

```js
if (v < start || v > end) return 'F';          // 区间外：气机偏离
dist = |v − center|;
return dist <= 3 ? 'S' : dist <= 7 ? 'A' : dist <= 12 ? 'B' : 'C';
```

评级与结果：

| 评 | 结果 |
| --- | --- |
| S | 突破成功，结算卡标「破关」 |
| A | 突破成功 |
| B | 突破成功 |
| C | 突破成功 |
| F | **失败**，退一半灵石，境界不变 |

关键判断：**只有 F 是失败，C 起步全算过。** 见 `applyBreakthrough()` 里那一句 `if (grade === 'F')`——C/B/A/S 走同一条成功分支。

评级在这个玩法里**不换收益**，只换结算卡上的一个字母与一句 banner（S 才有 `theme.praise` 那句「破关」）。
这是刻意的：破境是「成 / 不成」的二元事件，把收益做成连续梯度会让玩家反复刷同一道关。

### 2.1 操作

只有两个动作：**按下**（`press`）与 **松开**（`release`）。

- 触屏走 `bindtouchstart` / `bindtouchend`；
- 桌面预览里鼠标可能只触发 tap，所以留了一支兜底：点一下自动按 520ms 再松开（`tapFallback`，500ms 内不重复触发）；
- 蓄力中状态栏写「气机正盛…松手定生死」，banner 写「一线之间」。

## 4. 设计依据

### 4.1 为什么突破要有一个「手要稳」的动作

突破是全流程唯一的**不可逆节点**：成功进一境、战力跳一段、气海拓宽并补满；失败散一半灵石。
前面几十局参悟攒战力的过程全是渐进、可预期的，最后一步如果只是点一下「确定」，整个破境就变成了「检查清单勾完了」。
加一个要求精度的手部动作，是把「临门一脚」立起来。

这也是这一门**唯一一个考「手」而非考「脑」**的盘面。十五门功法都在考眼、考规划、考记忆；突破考的是手感。

### 4.2 为什么 S 窗只有 1–2 个落点、几十毫秒

这是「有实时读数」之后反推出来的：

- HUD 每一跳都在报「距正中 N% · X 评」，玩家可以看着读数瞄；
- 若 S 窗也做得宽（比如 ±10），那么「看着 HUD 等它跳到 S 再松手」就是无脑操作，S 失去分量；
- 所以 S 窗必须窄到「看得见但不容易停准」，把**手眼协同**而不是**读数字**变成真正的门槛。

S 不换收益，所以这个严苛只影响结算卡上那一个字母，不影响玩家能不能过。**这是它敢做这么窄的前提**。

### 4.3 为什么区间是往复的、而且不限时

单向蓄力（0 → 100 一次过）会让失误完全取决于第一次的反应速度，而反应速度是不可训练的。
往复则把「一次判断」变成「节奏学习」：玩家看一两个来回就能摸出周期，第二次经过区间的命中率远高于第一次。

**不限时**是同一个理由的延伸：既然要学节奏，就不能催。

### 4.4 为什么不给第二次机会

「松手定生死」是这个动作的全部张力。若允许「停错了再按一次」，它就退化成「一直按到满意为止」，与「临门一脚」的定位正好相反。

代价是：一次手抖就散一半灵石（筑基 30 枚、金丹 60 枚、元婴 120 枚）。

### 4.5 失败只退一半，不退完也不全扣

- 全退 → 失败没有代价，等于「无限试到过为止」；
- 全扣 → 一次失手掏空积蓄，玩家会不敢冲关，境界体系就卡住。

一半是**能感觉到疼、但不至于不敢再来**的位置。这一条与「本门只奖不罚」的整体调性不同，因为突破是花费而非产出。

### 4.6 被否决的方案

这张表是被我否掉的念头，每一行都留着诱因和收手的理由。头一条「点一下确定直接突破」和末一条「把 charge 也放进参悟列表」划出了这一门的两条边界——它既不能是个 checkbox，也不能混进功法序列。

| 方案 | 为什么否掉 |
| --- | --- |
| 点一下「确定」直接突破 | 破境变成勾清单，没有临门一脚 |
| 单向蓄力、只有一次 | 纯考反应速度，不可训练 |
| 允许重复尝试 | 张力消失，退化成「按到满意」 |
| S 窗放宽到 ±10 | 看着 HUD 等 S 即无脑成功 |
| 按评给不同突破收益（S 多给属性） | 玩家会反复刷同一道关，破境从「事件」变「刷子」 |
| 失败全扣灵石 | 会让人不敢冲关，境界体系卡住 |
| 失败全退 | 失败无代价，等于无限重试 |
| 把 charge 也放进参悟列表 | 它没有熟练度、没有段位、没有连 S，进参悟会破坏整套数值假设 |

## 5. 界面与反馈

1. **判据**：松手时 HUD 报当下评级（`vm.gradeNow` / `vm.goal`「距正中 N% · X 评」），红线区间写在 goal 上。
2. **代价**：区间外 F「气机偏离」→「气机一乱，未能突破。布阵的灵石散了 N 枚，余下的还在。」；中途结束也是 F。
3. **操作**：按下 / 松开两个动作；蓄力中状态栏「气机正盛…松手定生死」，banner「一线之间」。
4. **进度**：蓄力条 0 ↔ 100 往复，不限时、不看秒表，看的是当下落点离正中多远。
5. **收束**：松手定生死，只有一次机会；C 起步全算成功，F 退一半灵石、境界不变；S 才在结算卡标「破关」。
