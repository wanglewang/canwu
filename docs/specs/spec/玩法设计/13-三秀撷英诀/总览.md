# 需求（Spec）· 灵植·三秀撷英诀 → 三连互换（总）

## 玩法概述

一片灵畦种满灵植，你互换相邻两株，凑齐三株同色就采收；收走之后上面的苗落下来补空，补下来的新苗又可能再凑成一线——这就是连锁，一层比一层值钱。我想做一门「看一眼就懂、想拿高分却要算三步」的三消：规则一句话，深度全藏在「换哪两株能引出下一波连锁」里。

盘面五段一路从 6×6 长到 10×10，花色从 5 增到 7（第三段到顶，七是本门纹样的族数上限）。**从第二段起**，盘上就开始出现**石皮封住的苗**——它不能换，只能靠落到它头上的三连把它收走解封，格数逐段加密（2 / 5 / 9 / 14）；第四段起**重排开始计次**——前 3 次按原价降 4 手当量，之后每次翻倍（降档不花手数）。前 10 关靠眼准，之后还得绕开石皮、算着降档打。

另有一条不用读字的台阶：**每换一段，盘上整副图案一起换掉**。第一段是果器（灵植），之后依次是甜点、海洋、灵兽，圆满段把四套各请一族凑成「荟萃」。二十六格图按剪影族排（圆润 / 方框 / 伞锥 / 竖长 / 成簇 / 带尖，多出来的第七色借一枚形状独占的「异纹」），不按序号取前 N 格——前八格里五个是果子，取前五就是一盘圆，去色后分不开。图案只换皮不换骨架：玩家学的是「第几族长什么样」，不是「这一格画的是什么东西」，所以换段只重置一次认图，判断不用重建。真源在 `minigames/crest.js`，图与切位由 `scripts/gen-crest.js` 同一次出；主题按段由 `data/levels.js` 注入，段内恒定。

**它不占一条变化方向**：换皮不增加候选、不改判定、不动代价，只是把「一眼看出换段了」这件事从提示文字搬到盘面上。方向账仍按 `levelDelta` 的结构键算，九类 / 七内容轴 / 段界五条的口径不变；段界那句常驻规格会写出本段纹样名，让看得见的变化也有文字落点。

评级不按「时限内攒了多少分」，而是按「**用掉几成手数就做成目标**」：做成即收工，没打掉的手数按固定汇率折成分数，再扣掉失误攒下的降档分；三条线分别对应四成 / 六成半 / 九成手数（见 §4.2）。分数的绝对值仍随本关手数与每手产出现算（`gradeLinesOf()`），所以段与段之间会「抬高」：新一段的起手手数比上一段末关更宽，同样的用手比例就对应更高的分数当量。这是口径，不是算错。玩家在准备页与评级卡上读到的是手数口径，不是这个分数。

```text
  ┌──┬──┬──┬──┬──┬──┐
  │花│叶│花│果│叶│花│
  ├──┼──┼──┼──┼──┼──┤
  │果│花│果│叶│果│叶│
  ├──┼──┼──┼──┼──┼──┤
  │叶│果│花│花⇄花│果│  ← 换位凑三连
  ├──┼──┼──┼──┼──┼──┤
  │花│叶│果│叶│花│叶│
  └──┴──┴──┴──┴──┴──┘
 三株同色成线 → 收走留空 → 落下补苗 → 再查连锁
```

> 这张示意是设计意图，不是实测截图；花色用汉字代指 sprite 图案，盘面按段为 6×6 到 10×10。

> 在灵畦里互换相邻两株，凑齐三株同色即采收；新苗落下还能再连锁。换不出三连就降 1 手当量（不扣手数）。
>
> 五段六篇：本篇放五段共用的骨架（盘面 / 规则 / 依据 / 界面 / 代码），

> 这一门是唯一「一张表管全」的玩法（`MATCH_LEVELS`），整表按段逐段展开到各段篇 §1。

- 功法：灵植·三秀撷英诀（黄阶，offline +12%）｜玩法 id：`harvest`｜阶段新法：照畦 / 连收
- 时长基准 `base = 34`

换盘、换花色、收手数、收降档、加石皮、限重排，再加上四连/五连的符、本局目标、挪苗与二选一劫变——五段每一样都往前推了一点，推完 S 线落到哪，表中可查。共用骨架写在本篇，每段的整表行与手感另有专篇。

**这一门是九类方向的样板**：盘面几何、元素种类、玩法结构（符）、地形障碍（石皮）、目标类型、信息可见度、代价节奏、本局变数（劫变）、主动手段（挪苗）九类全开，内容轴 7 类，段界一次开 5 条。规矩见 `docs/specs/constitution/02-十三条设计原则` §13，逐门账见 `spec/数值平衡/05-axis-review` §13。

手数预算与降档权重按原表逐关现算：段一 55 → 40 手、段二 53 → 37、段三 48 → 34、段四 43 → 30、段五 38 → 27（段表基准 57 / 53 / 48 / 43 / 38，段内收紧 30%）；各段段首 S 线分别是 6897 / 6243 / 4378 / 4085 / 3827，第 1000 关 2719。重排前四段不限次，后两段前 3 次原价、之后翻倍；失误 / 照畦 / 挪苗 / 重排都不扣手数，只累计降档权重（单位「手当量」）。三条评级线由 `gradeLinesOf()` 按本关手数与每手产出现算，圆满段劫变改手数后再算一次。

跨段看：盘面 6×6 → 10×10（每换一段就换一副盘）、花色 5 → 7（第三段封顶）、
手数 55 → 27 手（−51%）、降档 −1→−3 手当量、石皮 0 → 14 格。
**盘面变大不是难度**：消消乐里盘越大同色越多，一手能成的换位从 8.9 处涨到 17.8 处（模拟 400 局）。
真正拉开五段的是花色、石皮与手数——盘面那一格只负责「不用读字也知道换段了」（见 §4.4）。
**注意「段首 vs 段末」不是笔误**：每一段的起手手数都比上一段末关更宽（第 10 关 40 手 → 第 11 关 53 手），
所以评级线的分数当量在换段那一关会跟着抬回去一截。玩家进新段看到的数比上一关高，这是对的——
**它衡量的不是「这门有多难」，而是「这一关的手数里，四成手数做成目标能折算多少分」**（见 §4.2）。

## 1. 盘面介绍

五段各一副盘：6×6 / 7×7 / 8×8 / 9×9 / 10×10，铺满灵植。盘面列与行由 `MATCH_LEVELS`
注入（玩法层读 `p.cols / p.rows`），九 / 十列在 `practice.wxss` 走满宽的 `grid--compact`，
不是落石那套 408rpx 窄槽——否则十列每格只剩 20px，果器纹挤成一团。

- 花色数按段 5 → 7（`kinds`），第三段到顶：器纹只有 7 个能在 31–45px 的格子上分得开的剪影；
- **石皮封印格**（`seals`，逐段 0 / 2 / 5 / 9 / 14）：这些格子里的苗换不动，
  但照样能被三连一起收走——收走就解封，新落下来的苗是活的。判据是「看得见、算得清」：
  石头壳比暖玉牌压暗一档、边缘发钝（`.cell--sealed`，`scale(0.94)` + 7rpx 石壳 + 斜石纹），
  一眼扫过去就知道哪几格碰不得；
- **灵种**（`goalType 5`，圆满段 2 枚）：几格被一枚深色种子占着——它换不动、不参与三连，
  只会随着它那一列的塌陷往下沉（本列塌一格，它沉一格），沉到底行即收走
  （`.cell--seed`，褐圆偏上、底缘一道金弧）。它是这一门唯一**位置类**的目标：
  其余四种都在数「收了多少」，它问的是「先清哪一列」；
  **「本列塌一格它沉一格」是必须补的一条，不是优化**：只靠「下方空了才下压」时，
  盘面越往下越不参与消除（10×10 实测 1850 手，底行被消 **0** 次，行分布
  1216 / 1085 / 951 / 511 / 236 / 87 / 29 / 7 / 1 / 0），灵种会永远停在原格；
- 每次采收后上方落下、顶上补新苗，盘面**收场时永远是满的**。
  **「满」是收场，不是过程**：收走的三株会在盘上真空出 170ms（`cell--clear`，格子凹下去、
  牌撤掉），新苗再从上方按距离落下（`cell--fall`，掉几格就走几格）。这一段空是玩家
  唯一看得见「刚才收在哪儿」的窗口——前后两帧都是满的，中间不空一段，连锁三层和一层
  在屏幕上长得一模一样，只能靠浮字知道发生了事；
- 图案用 `crest` sprite（八张牌，绝境用到第 7 张）；
- **没有可行换位时自动重排**，绝不把玩家卡在死局里。前三段不限次、每次按 `shuffleCost` 记降档（不扣手数）；
  后两段每局只有前 3 次按原价记，用完还有死局就每次双倍降档（见 §2）。

## 2. 规则说明

| 项 | 规则 |
| --- | --- |
| 采收 | 点相邻两株换位，使三株同色连成一线（横或竖 ≥3）；换成功一次扣 1 手 |
| 无效互换 | 换不出三连 → 评级降 `missCost` 手当量（不扣手数） |
| 连锁 | 落下后再次凑成一线 → 连锁 +1 层，一层比一层值钱 |
| 每步思考 | 每步 30 秒（全局 `MATCH_STEP_SEC`）：落子后重新计满；一直不落子、30 秒走完才扣 1 手再计满。演出期间不扣思考秒，想多久都不掉预算，只要 30 秒内落子 |
| 石皮封印 | 封住的苗**不能换**（点了只震一下、不记降档），但能被三连收走，收走即解封 |
| 灵种（圆满段） | 占一格的深色种子：**不能换、不算三连**；它那一列塌一格，它沉一格，沉到底行即收走 |
| 本局目标 | 按段换：收灵草 / 收够指定色 / 做出连锁 / 破开石皮 / 引苗落底。**做成即收工**，没打掉的手数折成分数；手数用尽还没做成算未走通（`goalMissed`，不推进度） |
| 重排 | 降 `shuffleCost` 手当量（不扣手数），把全盘重排；每局前 `shuffleCap` 次按原价记，之后每次双倍降档 |
| 照畦（提示） | 降 `hintCost` 手当量（不扣手数），指出一步能三连的换位 |
| 结束 | 做成目标→立即结算；手数用尽还没做成→结算为未走通（`goalMissed`，不推进度） |

**没有 F，但有关卡结论**：石皮不判负、重排用尽不判负；但手数用尽还没做成目标，这一关**算未走通**——
不判负（练过的功夫不白练）、进度不推、重打同一关也不算回关，只是不报 F。
F 是「一局打崩」，没做完目标不是打崩，把两者合并会让玩家以为整局白打。理由见 §4.4。

## 3. 五段递进

每一步只收紧两到三个数，且三个方向（花色 / 石皮 / 手数）只往前走：

| 段 | 这一段新学的一件事 | 主轴 |
| --- | --- | --- |
| 一 · 未入门 | 找三连：相邻两株换位、横或竖 ≥3 即采收 | 复杂度（5 色 · 6×6 · 无石皮） |
| 二 · 入门 | 花色 +1、2 格石皮、**本局目标收够指定色**、挪苗 1 次 | 目标 + 主动手段 + 石皮上线 |
| 三 · 小成 | 花色到顶、**四连留直行/直列符**、目标改做出连锁 | 玩法结构（符）+ 目标换种类 |
| 四 · 大成 | **五连留同色符**、石皮 9 格、目标改破石皮、重排限 3 次 | 符升级 + 障碍 + 目标 |
| 五 · 圆满 | **交叉留四邻符且两符可相撞**、目标改**引苗落底**（盘上 2 枚灵种全落到底行）、**开局二选一劫变** | 本局变数 + 玩法结构封顶 + 位置类目标 |

**为什么石皮从第二段起、只给 2 格**：第一段要先立住「换两株凑三连」这一件事；
第二段只放 2 格，是「看得见但挡不死」——玩家第一眼就知道有些格子不让动，又不会被逼着绕。
往后每段加几格，是同一件事的加深，玩家不需要重新学规则。
（先试过把石皮整个留到第四段：实测段二反而比段一好打 22%，因为 7×7 / 5 色的同色密度更高。
盘面变大在消消乐里是容量，不是难度。）

### 3.1 阶段新法（大成 / 大圆满）

| 段位 | 名 | 规则 | 可关 |
| --- | --- | --- | --- |
| 大成 | 照畦 | 「照畦」**少降 1 手当量（仍要记）** | 否 |
| 大圆满 | 连收 | 连锁从第 3 层起额外加成；重排少降 1 手当量 | 否 |

**这两条是原则第十一节的标准写法**：便利可以有，但必须有明码代价——「少降 1 手当量」而不是「不降」。
而且加成从第 3 层才给，得先打出连锁才拿得到，不是白送。

## 4. 设计依据

### 4.1 为什么整表管理而不是公式缩放

旧版只有「S 线 620 + depth×150」在变，预算 / 5 色 / 罚则四段全写死——旧制按秒表计时，真人手速跟不上，所以改成手数预算。真控制器跑 12 局的结果：
高手五段 12/12 全 S、常人绝境 10/12 S——**等于同一局打五遍**。

现在每段收紧两到三个数，且方向一致：

- 未入门 → 入门：花色 +1、石皮上线（2 格）、收手数、收降档、收重排与照畦；
- 入门 → 小成：花色再 +1（到顶）、石皮 2 → 5、收手数；
- 小成 → 大成：盘面 +1 列、石皮 5 → 9、加封印以外的两条规则（照畦 / 重排计次）、收手数；
- 大成 → 圆满：盘面 +1 列、石皮 9 → 14、收手数。

每一步动的数不少，但**只有「花色 / 石皮 / 手数」三个方向**在推进，没有一件事是往回走的。
`npm run audit:gap` 会报出每一道段界换了哪些结构键。

### 4.2 评级为什么按「用掉几成手数」而不是按分数

旧版是五档手填的绝对分（1900 / 1750 / 1400 / 1300 / 950），后来改成「每手产出 × 可用手数 × 0.72 利用率」。
2026-11-20 又改一次，因为**终点换了**：目标做成即收工，玩家不必打满预算。
于是「时限内攒了多少分」这个问题本身就立不住——分的大半是剩余预算折出来的。
再往后从秒表改成步数制：旧制按秒表计时，真人手速跟不上；改成固定手数预算之后，
「四成手数内做成」才真正对应「几手能做成」，评级数学与旧制等价。现在：

```text
每手折分 = perMove × MATCH_MOVE_SEC(=1) × MATCH_CLEAR_K   （K = 2.5，即 perMove × 2.5）
总分     = 已收的分 + 达成时刻剩余手数 × 每手折分 − 累计降档手当量 × 每手折分
S 线     = perMove × floor(本关手数 / MATCH_MOVE_SEC=1) × (K − (K−1)·0.4)
         = perMove × 手数 × 1.9
三条线   = perMove × 手数 × (K − (K−1)·x)
           x = 0.40（S）/ 0.65（A）/ 0.90（B）
```

四个常数各自只答一件事：

- `MATCH_MOVE_SEC = 1` — 恒为 1：`duration` 本就是手数，不再做秒→手换算；保留这个名字只为断言结构不动。
- `MATCH_STEP_SEC = 30` — 每步思考限时（秒），落子后重新计满；只有一直不落子超时才扣 1 手。它只管节奏，不进评级，也不随段收紧。
- `MATCH_CLEAR_K = 2.5` — 省下一手值几手产出。**必须大于 1**：等于 1 时「早收工」与「打满」
  在数上完全等价，玩家没有任何理由为「早做完」改变打法，这个改动就等于没做。
- `MATCH_GRADE_X` — 三条线各自对应的「用掉几成手数」。**不能写成「A = S × 0.68」那种派生**：
  手数一收紧三条会一起漂，标定就对不上。

`perMove`（每手产出）仍是实测值：随机合法手跑满一手到无连锁为止、每档 400 局，总得分 ÷ 总手数，
再按第一段锚到 66 等比缩放，得到 66 / 62 / 48 / 50 / 53。
**它不随段单调下降**——10×10 一次能消更多株，最后一段反而比第四段高。这是实的，别拿它当难度看。

不按分数评的三条理由：

1. **分里有一大半不是打出来的**。达成即收工之后，总分 = 真收的分 + 剩余手数 × 汇率 − 降档手当量 × 汇率。
   按总分评等于按「你拖了多久」评，方向反了：拖到底的局分反而更低才对，但它会先拿到收株分。
2. **同一个分可以由两种相反的打法得到**：早做完、手一般；拖到底、手很快。
   评级却一样——那不是尺子，是两个量糊在一起。
3. **分数仍要留着**，但它只做即时反馈（三株齐收 +N、连锁 ×1.5），不参与评级。

实测标定（骨架模拟、每档 40 局、**不含符与石皮**，所以是偏保守的下限）：

| 段 | 目标 | 认真打｜达成 / S | 随手打｜达成 / S |
| --- | --- | --- | --- |
| 一 | 收 100 株 | 95% / 85% | 100% / 50% |
| 二 | 收色 18 株 | 98% / 45% | 98% / 25% |
| 三 | 连锁 5 次 | 80% / 20% | 78% / 18% |
| 四 | 破石皮 5 格 | 88% / 73% | 48% / 10% |
| 五 | 灵种 2 枚 | 93% / 83% | 73% / 38% |

判据是「**认真打八成以上做成、随手打一半左右**」——目标是终点，不是彩头。三条线的同源与
折算系数恒定由 `tests/rank.test.js` 与 `tests/layout.test.js` 一起守。

> **2026-11-21 更正段三那一行（旧数字留作历史，别照抄）**：原表写「80% / 20% vs 78% / 18%」
> 并据此判「段三不看打法」，是**标定口径错了**，不是玩法问题。旧脚本把 `findMove` 当「认真打」，
> 而 `findMove` 永远取左上第一个可行换位、不会去凑连锁，反而比随手随机更差（实测段三 200 关
> 达成仅 28%、S 仅 10%）。换成真正的认真打——在副本上把每个可行手推演一遍、挑连锁最深的那手——
> 段三反而是全门区分度最好的一档：

> | 关 | 随手 达成/S | 认真（挑连锁）达成/S |
> | --- | --- | --- |
> | 51 | 78% / 13% | 100% / 75% |
> | 125 | 75% / 10% | 98% / 50% |
> | 200 | 70% / 15% | 88% / 48% |

> 所以段三目标**不改口径**（不换成「连锁总层数」），`MATCH_GRADE_X` 也不动——
> 它本来就在量「你能不能看出该换哪一手」。真正改的是两处误导文案：局内仪表与评级卡都把
> 「做了 5 次连锁（每次至少 2 层）」写成了「5 层连锁」，会让玩家去凑一次五连（那是「连收」的事）。
> 已改为「次」并由 `tests/minigames.test.js` 钉住。**「认真打」的定义写在这里，避免下一个人再踩**：
> 三秀这类「连锁 count」门，`findMove` 只能当驱动跑流程，不能当手感基准；基准要在副本上推演
> 每个可行手、挑收益最高的那手，随手基准才是随机可行。

### 4.3 为什么无效互换要记降档

不记的话，玩家可以靠「狂换」试出三连——换位本身成了搜索工具。降档让「想好了再换」成为必要：
它不花手数，但会按每手当量从结算分里扣掉，影响评级。

### 4.4 被否决的方案

这张表记着我否掉的念头——每一条都留着当时的诱因。

| 方案 | 为什么否掉 |
| --- | --- |
| S 线按段写死绝对分 | 见 §4.2：与盘面脱钩，还把一个方向减了两遍 |
| S 线随段上升 | 同上：花色变多已经被 `perMove` 吃掉，再加一条上升曲线就是双重惩罚 |
| 无效互换不记降档 | 可以靠试（见 §4.3） |
| 死局不重排 | 卡死玩家 |
| 照畦免费 | 辅助必须有代价（原则第九条） |
| 「照畦不记降档」 | 原则第十一节：便利要有明码代价，改为「少降 1 手当量」 |
| **重排用尽即判负** | 死局是盘面自然长出来的，不是玩家打错的。实测 35 对那一档、60 局里平均 0.4 次自然死局、最多 2 次——按「2 次原价」定价合理，但「第 3 次就判负」等于把一手运气变成废局。改为「用尽翻倍 + 不判负」：还救得回来，只是很贵 |
| **封印格连三连也收不走** | 那样死格会永久占位，盘面越打越僵，且玩家没有手段。让它「能被三连收走」把石头变成了目标而不是障碍 |
| **封印格点了记降档** | 玩家分不清「我换错了」和「这块石头不让换」。点了只震一下、浮字说明、不记降档 |
| **石皮从第一段就出现** | 第一段要先立住「换两株凑三连」这一件事，盘上再加障碍会分不清「我换错了」和「这格不让动」。第二段起只给 2 格，是「看得见但挡不死」 |
| **只靠盘面变大做段差**（2026-11-19 推翻） | 模拟 400 局：7×7 / 5 色的每手均分比 6×6 / 5 色高 36%，9×9 / 6 色又比 8×8 / 6 色高 11%——盘大了同色更多、更好找手。段二、段四都出现过「换段反而更容易」。现在段差押在花色、石皮与手数上，盘面只负责「一眼可见换段」 |
| **花色加到 8** | `GLYPHS` 与器纹只有 7 个能在 31px 格子上分得开的剪影。第 8 色必然与某族撞形状，那不是「多一种花」，是「两族看着一样」——玩家的误判会被记到「难度」账上 |
| **目标只加分、不决定终点**（2026-11-20 两次推翻） | 第一版目标是旁挂的：达成只加分，玩家的最优解永远是「找收得最多的一手」。改成返还手数之后仍然不硬——手数用尽总能结算，目标只影响打多久。最后落到「**做成即收工 + 未做成不算走通**」：目标才真的成为这一局的终点。两次改动的代价都是同一个——评级线必须同批重标（见 §4.2） |
| **目标未达成报 F** | 没做完目标不是「打崩」：报 F 会让进度、挂机加成一起清零，玩家只是这一关没过，不是这一局白打。改成「不报 F、不推进度、不判负」——卡关的代价是重打的时间，不是清零的资源 |
| **灵种做成一格「不能消的障碍」** | 那它就只是第二个石皮。灵种必须是**目标**：会动、会走到底、会被收走。所以它不挡匹配，只挡换位，并且跟着 `collapse` 一起下落 |
| **灵种开局摆在底行 / 摆盘顶** | 摆底行等于目标白给。摆盘顶实测做不到：10×10 实测 1850 手底行被消 0 次，靠「下方清空自然下落」永远走不到底。现在固定在「距底 4 行」——段末只剩 27 手时，距底 7 格已经是做不到的数（实测只剩三成局做得完） |

## 5. 界面与反馈

原文 §6「界面」与 §6.5「界面与反馈」合列如下。

- 局内代价句按本段生成：「换不出三连 · 评级降 N 手当量」（`tipFor()` 现拼，不写死）；
- 准备页难度栏显示本段花色 / 手数 / 降档 / 石皮 / 目标类型（`stageDetail.brief`），关卡块另起一行写带数量的本局目标（如「本局目标：收灵草 100 株」，`matchGoalLine` 与局内 meter / 评级卡同源）；分数线不再上屏，报的是「四成手数内做成 S」；
- 换段那一关的常驻规格追加「石皮封住 N 格 · 重排原价 N 次（用尽翻倍）」——它不抢
  `levelDelta` 那三条额度，因为它不是「这一关比上一关变了什么」，而是「这一段一直是这样」；
- HUD 常驻「（原价 N）」与「· 石皮 N」，打到第 4 段以后一眼能查到还剩几次；
- 无效互换有轻震反馈，与连锁的中量震动区分开；点石皮是**另一种**震法（单次短震 + 浮字），要能与前者分开。

### 5.1 一手演三拍

一手不是一个瞬间。三件事压进同一次渲染，盘面就从满的跳到满的——人眼比两帧只能比出
「位置变了」，比不出「少了三株」，连锁叠三层和一层在屏幕上没有区别。

| 拍 | 时长 | 盘面上看见什么 | 为什么必须有这一段 |
| --- | --- | --- | --- |
| 收走 | 170ms（`BEAT.clear`） | 那三株撤掉、格子凹下去（`cell--clear`，静态凹槽，不是一次性动画）、原位迸一小把粒子、HUD 浮字 | 整手唯一「看得见少了东西」的锚点。凹槽写成静态状态：减少动效关掉动画时它还在，「这里刚收走三株」照样读得出来 |
| 落下 | 130–300ms（`BEAT.fallBase + 格数 × fallPer`，封顶 `fallMax`） | 牌从上方掉进格子（`cell--fall`），掉几格走几格；新苗从盘面外进来 | 一格和十格给同一个时长会读成瞬移。**同列必须同时落定**，否则同列两株会在半空互相穿插；列与列各按自己最远那株定时长 |
| 再查一轮 | 0ms | 还有三连 → 回到「收走」，层数 +1 | 连锁是「落下来的新苗又凑成一线」。看不到落下，连锁就像凭空发生 |

无效互换另算一条：两株各抖一下（横向 ±7rpx 三次回正）。只降 2 手当量、不抖，玩家会以为
「没点上」，接着再点一次。点石皮也有反馈，但**只有一下短震 + 一句浮字**——抖三下会被读成
「这次换位失败了、再试试」，而它其实是「这一格根本换不了」。

**演出期间不收输入，但每步思考限时照走。** 步数制下演出那几百毫秒不扣思考秒——它不是玩家在想的时间，
不进 30 秒倒计时；锁输入 + 落子后重新计满才是现在的口径。单手演出仍压在 0.5 秒以内
（三拍合计 300–470ms，三层连锁约 1.4 秒），只为手感，不为省预算。

抖动与下落都只动 `transform`；`cell--fall` 的 `0/1` 交替序号是为了让相邻两手各自重播一次
（同名类连挂两帧不播动画）。`cell--clear` 不需要交替——它是状态，不是一次性动作。

**被否决的方案**

- **整盘连锁脉冲**（每层连锁给全盘加一层光）：连锁本来就带金浮字与粒子，再加整盘光
  是三层叠加，玩家只看到「屏幕在闪」。
- **只给最上面八格挂落下动画**（v10 前的写法）：为了躲开「一二十格一起动等于整盘乱抖」，
  代价是玩家看不见真正移动的那些牌——他看到的「落下」全是新苗，老牌全是瞬移。
  正解是按列同步落定（同列同速，不会穿插），而不是砍掉一半的格子。
- **演出期间照扣思考秒**（旧制遗留）：节奏更紧，但演出不是玩家在想的时间；步数制下这段不扣，
  落子后重新计满 30 秒。这是改步数制时顺带修掉的。

## 7. 待验

以下为全门性待验；段相关的那几条落在各段篇 §6，本文件不重复。

- 6×6（约 50px/格）到 10×10（约 35px/格）相邻两株互换在大屏 / 4.7 寸小屏的误触率，重点看第九、十段的满宽样式有没有把果器纹挤糊。
- 长按选中与点击取消的容错。
- **石皮的可辨识度**：10×10 盘上 8 格石皮，扫一眼能不能立刻分出「这块不能动」；
  石皮与「已选中」的暖玉高亮会不会互相盖住（两者都在 `cell` 上做视觉）。
- **石皮的难度贡献**：加 4 格 / 8 格之后，五档的 `perMove` 实测值会不会掉出当前标定
  （66 / 66 / 56 / 56 / 50）。掉了就得同批重标 S 线——这是 §4.2 那个公式的唯一输入。
- **原价 3 次够不够**：`shuffleCap` 是按「自然死局平均 0.4 次 / 最多 2 次」定的，
  但那是并蒂连枝引（灵纹连线）35 对盘实测；三消的连锁会自己制造死局，得单独实测一轮。
- 「无效互换轻震」在 iOS / Android 上能否与连锁的中量震动、石皮的短震分得开，会不会反而打断观察节奏。
- **三拍的实际手感**：170ms 的空格帧在小屏上够不够看见（看不见就是白发一次渲染）；
  10×10 盘上「整列塌一截」会不会糊成一片；三层连锁连续演 1.4 秒，中间玩家是不是开始抢点。
  这三条只能真机看，代码里量不出来。
- 演出期间不收输入会不会被读成「点了没反应」——真机上抢点一次，看玩家会不会以为卡了。
- **灵种与石皮会不会混**：两者都是「不能换」，一个是深褐圆、一个是灰绿壳。10×10 盘上
  两枚灵种 + 14 格石皮，第一眼能不能分出「这枚会掉下去、那格只是钉住了」。
- **收工那一拍会不会读成卡住**：目标达成后计时冻住、停 900ms 再进结算。真机上抢点两下，
  看玩家会不会以为「计时停了是不是崩了」——报账那句浮字是唯一的解释，它必须够醒目。
- **未达成时玩家知不知道自己在哪**：手数尽、目标没做完，结算是 C + 「这一关还没通」。
  要看玩家会不会误以为掉档只是成绩差、下一关照常——结算 notes 那句是唯一的出口。
