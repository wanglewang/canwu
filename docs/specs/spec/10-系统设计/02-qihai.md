# 需求（Spec）· 气海：灵力上限

> 灵力是油，气海是油箱。**装满就不再进**——这一条把「挂机时长」从唯一节奏变成了「回来收」。
>
> 它同时是境界的第二重价值：破境不只抬战力，还让你一趟多练几局。

---

## 核心前提：先有油箱，才有「回来收」

把气海想成一只有刻度的油箱。你关掉小程序去上班，它慢慢往里灌油；等你下午回来，油已经到顶，多出来的会当场漏掉——不会堆成一个越来越大的数字等着你。

我为什么非要这只箱子？因为**没有它，「挂机时长」就是唯一的节奏**：玩家会发现最优解是「挂够再来」，而且是挂到第二天也没有新体验。有了它，闭关从「放着涨」变成「回来收」，境界也多了一重每天摸得到的意义——破境不只是战力变大，是这一趟能多练几局。

这一点很重要，因为下面五条边界——溢出当场散、满池不挡打坐、份例满池拒领——都不是在给那条乘法公式打补丁，而是在回答同一个问题：「玩家真的回来时，该看到什么、不该看到什么」。

## 1. 概述

**气海 =（境界基数 + 真元 × 2）×（1 + 心法扩池，封顶 30%）**，炼气期 174，元婴期 644。

## 2. 公式与三要素

`economy.qiCapOf(realmBase, ling, skillBonus)` 是唯一实现，`game.qiCap(state)` 是唯一的取数入口。

容量由三个数决定，各管一件事，谁也替不了谁：

| 要素 | 来源 | 作用 | 为什么是它 |
| --- | --- | --- | --- |
| **境界基数** | `world.realms[].qiCap`：炼气 150 / 筑基 260 / 金丹 420 / 元婴 620 | 主体的量 | 境界本来就该是「容量」的度量。只给战力的话，破境就只是一个数字变大 |
| **真元 × 2** | 属性面板的真元（`ling`） | 每点 +2 | 给「练真元类功法」一个独立出口。三项属性原本都只进战力，等于练哪门都一样 |
| **心法扩池 ≤ 30%** | `effect.type = 'qiCap'`：吐纳 +10%、太虚 +15% | 乘算 | **心法**的语义就是「养气」；把池子挖深，比给战力更贴题。封顶 30% 是防止以后加功法把池子撑穿 |

三个数各管一件事，互不顶替：**境界决定基数，真元决定微调，心法决定增幅。**

| 境界 | 基数 | 真元 12 时 | 一池能练（小成段 14/局） | 一池能练（绝境 27/局） |
| --- | --- | --- | --- | --- |
| 炼气 | 150 | **174** | 12 局 | 6 局 |
| 筑基 | 260 | 284 | 20 局 | 10 局 |
| 金丹 | 420 | 444 | 31 局 | 16 局 |
| 元婴 | 620 | 644 | 46 局 | 23 局 |

> 真元堆到 100 时，元婴气海约 820。心法满配再 ×1.25，约 1025。

## 3. 五条边界规则

这五条是这个系统真正的设计内容。上限本身只是个乘法，边界才是玩家能感知的部分。

### 3.1 满则不再生，溢出当场散

`idlePending()` 把一次闭关拆成三个数：

| 字段 | 含义 |
| --- | --- |
| `qiRaw` | 这一趟坐出来的总量（时长 × 0.5 × 闭关加成） |
| `qi` | 实际收下的（= min(qiRaw, 气海空位)） |
| `overflow` | 装不下、当场散掉的（= qiRaw − qi） |

回执里必须写明：「气海已满，散去 66 点未收」。**静默吞掉是最坏的处理**——玩家会以为离线收益坏了。

三个数满足 `qi + overflow = qiRaw`，这条等式被断言守着。把这一趟闭关画出来，就是一次注水——流进去的和留下的，永远对得上：

```text
          ┌───────────────────┐
          │  气海  174 / 174  │ ← 满则不再进
          │▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│
          │▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│
          └─────────┬─────────┘
   闭关产出 qiRaw ───┤
                   ├─→ qi（收下）= min(qiRaw, 空位)
                   └─→ overflow（散掉）= qiRaw − qi
                   qi + overflow = qiRaw
```

### 3.2 满池不挡打坐

打坐除了灵力还产熟练度（2.5/时）。所以满了之后仍要能打坐，只是回执改用另一句：

- 有灵力可收：「打坐 12 分：灵力 +6（174 满）· 刀法·开锋破军诀 +1」
- 灵力已满：「灵力已满（174），这一坐只涨熟练度」

`meditate()` 在满池时返回 `{ ok: false, full: true }`，**不是** `还没攒够`。这两句的区别是：前者是解释，后者是敷衍。

### 3.3 份例满池拒绝领取

余位不足 60 时 `claimDaily()` 直接拒绝。

**为什么与打坐相反**：份例是**发放**的，可以等人来取（玩家先用掉一些再来领，什么也没损失）；打坐收的是**坐出来**的，不收就当场散掉。同样的「满了」，一个可等、一个不可等。

### 3.4 破境拓深并当场补满

`applyBreakthrough()` 之后：

- 气海从 174 → 284（筑基）；
- 灵力**当场补满**到 284。

这是突破的第二重回报，而且**当天就能摸到**——比「战力 +46」更贴日常。结算卡里单独一行：`灵力上限 174 → 284（+110）· 灵力 已补满 284 / 284`。

准备页的突破预告里也有一行「气海 174 → 284（+110）· 破境即补满」，用中性点标（`imm-check__mark--ref`），不参与「够不够格」的判断——气海不是条件，是所得。

### 3.5 老档夹平一次

旧版灵力没有上限，老档可能攒到几百点。`normalizeState` 末尾把余额夹到当前气海：

```js
const cap = qiCap(base);
if (base.resources.qi > cap) base.resources.qi = cap;
```

**只夹一次，不反复没收**。之后由「溢出即散」接管。若不做这一步，主页会写出「660 / 174」——上限在那一天才出现，玩家只会以为算错了。

## 4. 界面上出现在哪

| 位置 | 写法 | 用意 |
| --- | --- | --- |
| 主页境界卡 | `灵力 160 / 174` | 分母小一号、压成灰（`.imm-stat__cap`），读起来是注脚不是第二个数 |
| 主页提示 | 满池时：「灵力已满 174 / 174 · 去参一局」 | 满着是最该被点出来的浪费：一分钟都不再生 |
| 参悟准备页 | `耗灵力 14 · 余 96 / 174` | 玩家要权衡的是「还能打几局」 |
| 切磋 / 秘境首屏 | `境界 · 灵力 96 / 174` | 每场都要运功（2–5 点），要能一眼看出还能打几场 |
| 人物页 | 属性格第三行「每点 +2 灵力上限」 | 说明这一项管什么 |
| 说明页 / 指南 | 各一节「气海」 | 长解释归这里 |

主页的满池提示排在「即将升段」之前——那是运营层面的损失，升段只是进度上的好消息。

## 5. 被否决的方案

每一条否决背后都是一次真实的诱惑：省事的、能讨好玩家的、看起来更「合理」的。我把它们连同被否的理由一起留在这里——**因为气海这个系统的价值，恰恰藏在那些「没做」里**。

| 方案 | 为什么否掉 |
| --- | --- |
| 不设上限（旧版） | 挂机时长成为唯一节奏；境界只剩战力一个卖点；「灵力够不够」永远不是问题，于是「回洞府打坐」这个动作也没有存在必要 |
| 上限只由境界决定 | 真元就只剩「战力加权 1.2」一个用途，与体魄重复 |
| 上限只由真元决定 | 破境失去第二重价值 |
| 上限 = 固定值（如 200） | 一万局的老玩家和新手同一个油箱，长线成长感消失 |
| 满池时禁止打坐 | 打坐还产熟练度，禁掉等于用「油箱满了」惩罚「练功」 |
| 份例满池自动转成灵石 | 破坏「两条线不交叉」；而且份例本可以等人来取，没有浪费 |
| 溢出直接折算成灵石 | 同上。且会让「故意溢出」成为刷钱路径 |
| 读档时把超上限部分折成灵石 | 老档一次性发财，破坏经济。夹平是最中性的处理 |

## 6. 数值取舍

**为什么炼气是 150 + 24 = 174**：

- 需要「一进来就接近满」（开局送 160），否则第一件事是等半小时；
- 需要「装得下一天的量」：一天 10–15 局小成段 ≈ 140–210 点，174 正好在区间下限；
- 需要「5–6 小时能坐满」：174 / 0.5 = 348 分钟 = 5.8 小时，短于 8 小时上限——**炼气期先到的是气海，不是时长**。这个梯度是刻意的：筑基之后（284）才轮到「8 小时装不下」。

**为什么境界基数差距越往后越大**（110 / 160 / 200）：越往后单局越贵（绝境 27 点），一池要多撑几局就得涨得更快；同时也是「越往后成长感越强」的表达。

**为什么扩池封顶 30%**：两门心法合计 25%，留 5% 余量。若以后加第三门心法，仍能塞进去而不撑穿。

## 代码指路

- `data/economy.js` —— `QI_CAP_PER_LING` / `QI_CAP_SKILL_MAX` / `qiCapOf()`
- `data/world.js` —— `realms[].qiCap`（150/260/420/620）
- `utils/game/` —— `qiCap(state)`、`idlePending()`（三分数）、`settleOffline()`、`meditate()`、`claimDaily()`、`applyBreakthrough()`、`normalizeState` 末尾夹平
- `data/skills.js` —— `effect.type === 'qiCap'`（吐纳 10% / 太虚 15%）
- `pages/index/index.js` —— `refreshIdle()` 的满池分支、`meditate` 回执文案
- `tests/game.test.js` —— 气海随境界单调、真元换算严格 ×2、溢出三数对得上、满池打坐不静默、破境补满
- `scripts/verify.js` —— `qiCap` 只能挂心法、扩池总和 ≤ 30%、气海基数随境界单调

## 待验（必须真机）

- 主页三格统计「160 / 174」在 4.7 寸屏会不会挤（`.imm-stat__cap` 是新加的小字）。
- 满池提示「灵力已满 · 去参一局」会不会把「今日之课」的推荐盖掉。
- 「气海已满，散去 N 点未收」这句在冷启动弹窗里是否显眼到会被读到——它出现时玩家通常刚回来，注意力在「收了多少」而不是「散了多少」。
