# 需求（Spec）· 进度与段位

> 一门功法只有**一条**进度线：这门走通了几关（`skills[id].cleared`，0–1000）。
> 段位（未入门 → 入门 → 小成 → 大成 → 圆满 → 大圆满）就是这条线上的位置，不是第二套刻度。
> 2026-11 之前这里摆着两条平行线（熟练度 + 关卡），两套名字、两处入账；那一整套已删，存档推到 v10。

---

## 核心前提：只剩一条线

想象你练了一阵刀法：从「一关没通」走到「走通第 50 关」，于是这门就是**小成**——属性 ×1.8、本门新法开始逐条开。
这中间没有第二个数字要你理解。**「这门小成了」与「这门走通到第 50 关」是同一句话。**

旧版是两条线：一条叫熟练度（玩家面上叫火候），按评级累加点数；一条叫关卡，由走通推进。
麻烦不在于多一个数，而在于两个数并排显示时，玩家永远分不清「我这门到底算几级」——
结算页写「熟练度 +34」、准备页写「小成」、功法页写「已走通 60 / 1000 关」，三处都在回答同一个问题，答案却不一样。
文档也在两套名字之间漂：一段写「第 84 关还在入门段」，另一段按火候说「已到小成」。

现在一局只做一件事：**走通本门当前关就 +1**，其余一律 +0。

## 1. 六档：门槛就是段界关

`data/world.js` 的 `TIERS` 与 `data/levels.js` 的 `STAGES` 是同一把尺子——
六档门槛 = 段界关 `0 / 10 / 50 / 200 / 500 / 1000`，`verify` 逐档断言这件事。

| 段位 | 门槛（已走通几关） | 属性倍率 | 这一段给什么 |
| --- | --- | --- | --- |
| 未入门 | 0 | ×0 | 尚无加成 |
| 入门 | 10 | ×1 | 属性加成 ×1、特效兑现 25% |
| 小成 | 50 | ×1.8 | 属性加成 ×1.8、特效 50% |
| 大成 | 200 | ×2.8 | 属性加成 ×2.8、本门新法自此逐条开、特效 75% |
| 圆满 | 500 | ×4 | 属性加成 ×4、特效兑现满 |
| 大圆满 | 1000 | ×5 | 属性加成 ×5、本门新法开到最后一条（硬顶） |

门槛是「已走通几关」，所以**走通第 50 关那一局**才是「入门 → 小成」的那一刻；
走到第 49 关还算入门。晋段当场报出来（日志 + 结算里程碑），因为它是玩家唯一看得见的成长刻度。

## 2. 关卡：一门 1–1000，一局一关

```text
   未入门      入门        小成          大成          圆满         大圆满
   1–10      11–50      51–200       201–500      501–1000        走完
   └── 段界关 10 ──┴── 50 ──┴── 200 ──┴── 500 ──┴── 1000 ──┘
```

- 当前关 = 已走通 + 1（走完 1000 关后停在 1000，重打不推进也不越界）；
- 只能往回翻，不能往上挑：越权的关号会被夹回本门当前关；
- 一局只推一关，**走通 1000 关恒为 1000 局**——评级再高也换不来第 2 关。

## 3. 单局进度的五种情况

`applyPractice()` 只回答一个问题：这一局推不推得动一关。

```js
const advanced = !wiped && !goalMissed && playedNo === curNo && cleared < levelData.LEVEL_MAX;
if (advanced) rec.cleared = cleared + 1;
```

| 情况 | 判据 | 进度 | 别的账 |
| --- | --- | --- | --- |
| 走通本门当前关 | `advanced` | **+1 关** | 记纪录、给 buff、晋段则写日志 |
| 回关（打更早的关） | `playedNo < curNo` | +0 | 耗气按本关所在段照收，不减免；只剩「找手感」 |
| 失败（F） | `GRADE_FACTOR[grade] === 0` | +0 | 灵力不退（起手就烧了）；不立纪录；不给 buff |
| 目标未达成 | `goalMissed` | +0 | 不算失败、不给 buff，单独一句「目标未达成」 |
| 已走完 1000 关 | `cleared === LEVEL_MAX` | +0 | 纪录照记，**灵力照扣**——此时再练就是纯烧气 |

只有第一个分支会写 `cleared`。这条「进度只有一处入口」是整套成长线的地基：
任何「顺手多给一关」的写法都必须先动这一行，而动它就会撞上 `tests/rank.test.js` 与 `simulate.js`。

## 4. 评级只剩两个出口

评级（S / A / B / C / F）**不再给任何进度点数**。它还剩两个出口：

1. **结算观感**：大字评级、颜色、称号与成就的触发条件；
2. **30 分钟挂机 buff**：非失败局设一个 `state.buff`，只作用于闭关时长折算。

| 评级 | buff 倍率 | `GRADE_FACTOR` |
| --- | --- | --- |
| S | ×1.8 | 1.5 |
| A | ×1.5 | 1.2 |
| B | ×1.25 | 1.0 |
| C | ×1.1 | 0.6 |
| F | 不设 | 0 |

`GRADE_FACTOR` 现在**只用来判 `wiped`**（是否等于 0），其余值不参与任何数值计算——
保留它是因为称号与成就还在读评级本身。两套数不要混：buff 倍率管挂机，`GRADE_FACTOR` 管判定。

## 5. 分数与纪录

每门功法记一个「本门最佳」（`state.records[skillId]`）：

- 只在**分数更高**且**不是失败**时更新；
- 失败不立纪录——第一局崩掉就在准备页留下「本门最佳 0 分 · 失败」，玩家会以为那就是自己的水平；
- **分数不加任何收益**。分数管追求，进度管成长。

## 6. 被否决的方案

这些方案大多不是偷懒，恰恰相反——每一条都能让「熟练度」多干一点活。否掉它们是因为
**一条刻度一旦同时管两件事，就不再是「你练到哪了」**。理由留在这里，供以后想给它加重时对照。

| 方案 | 为什么否掉 |
| --- | --- |
| 进度 × 品阶系数 | 天阶是黄阶 3.2 倍，低阶功法在成长线上被直接淘汰，黄阶十一门成装饰 |
| 进度 × 难度倍率 | 与「回关折减」重复计一次，且会让「越难越划算」压过「按承诺打」 |
| 进度 × 境界 / 属性 | 进度就不再是「你走到哪」，而变成「你有多富」。`resMult / MAX_MULTIPLIER` 那套已整条退役 |
| 进度解锁关卡（旧版） | 与段位门槛同源，于是「解锁难度」=「刷够分」；玩家要么刷最浅一段刷到吐，要么以为难度是个能挑却点不动的按钮 |
| 三连 S 直接晋级（补额到下一门槛） | 补额不看关卡，而回关 S 概率更高，于是「只刷第 1 关」能反超「逐关进」。这条在模拟里被抓到过 |
| 连 S 叠倍率（第 k 连给 round(34 × 1.5^(k-1))） | 它是「熟练度」这条线最后一块承重墙：留着它，就还得留一套层数存档、一套断连规则、一套「回关不叠层」的例外。而它奖励的其实是「一直打同一门」——换门已经有省气的正激励，不需要再来一条负激励 |
| 两套名字（火候：生涩 / 初窥 / 渐熟 / 精纯 / 通玄 / 化境） | 六档门槛本来只有一套，硬给它起两套名字，等于让玩家学两个词表去指一件事。已经删了——现在只有段位名 |
| 回关折减（本关 ÷ 当前关 × 段基数比） | 折减是在「回关也有收益」的前提下才需要的护栏。回关改成不推进度之后，往回刷的收益恒为 0，折减成了给 0 打折 |
| 连练递减（练同一门收益递减） | 与「只奖不罚」的基调冲突。换门改为正激励（省 8% 灵力） |
| 圆满后归零 | 等于这门功法死了，玩家只能换门 |
| 参悟也给灵石 / 灵力 | 参悟变成印钞线，两种货币的分工塌掉 |

## 7. 为什么是「一局一关」

**为什么不是按评级给点数：** 点数要落地成「段位」才有意义，于是必须有一条换算表；
换算表一旦存在，就必然出现「停在哪一关刷最划算」的最优化问题——这正是旧版反复修补的地方
（回关折减、连 S 只在当前关叠、断连、主动结束归零，四道补丁全是为了堵同一类漏洞）。
「一局一关」把这个问题从根上取消：进度的唯一来源是「走通了没有」，没有可优化的余地。

**为什么门槛取段界关而不是「段界关 +1」：** 段位是「你现在站在哪一段」。
走通 10 关的人下一局打第 11 关，那一关属于入门段，所以他已经是入门。
写成 +1 会让「段位」与「下一关在哪一段」差一档，准备页与功法页立刻对不上（这次改版第一版就踩了）。

**为什么走完 1000 关不再涨：** 到顶后进度封顶、纪录照记、灵力照扣。
这不是惩罚，是「这门已经到极处了，该换门」——与「只奖不罚」的基调一致：
没有任何一项既有收益被拿走，只是不再有新收益。

## 8. 日志的分支

结算写日志时不许含糊，每种结局一句，且「+0」不出现在任何一句里：

| 情况 | 日志 |
| --- | --- |
| 走通并晋段 | `刀法·开锋破军诀 走通第 50 关，入「小成」` |
| 走通未晋段 | `刀法·开锋破军诀 走通第 37 关（灵力 −14）` |
| 回关 | `参悟 刀法·开锋破军诀 第 12 关（回关，不推进度）` |
| 失败 | `参悟 刀法·开锋破军诀 失败，本局无所得` |
| 目标未达成 | `参悟 刀法·开锋破军诀，目标未达成，这一关还没通` |
| 已到顶 | `刀法·开锋破军诀 已走通全部 1000 关，本局只记战绩` |

## 代码指路

- `utils/game/settle.js` —— `applyPractice()`（`advanced` 的四个条件、五种日志分支、耗气与 buff）
- `utils/game/profs.js` —— `tierIndexOfCleared()` / `tierInfo()` / `effectScaleOf()` / `computeAttributes()`
- `data/world.js` —— `TIERS`（六档门槛、名称、属性系数、说明）、`GRADE_FACTOR`、`GRADE_COLOR`
- `data/levels.js` —— `STAGES` / `STAGE_GATES` / `stageIndexOfCleared()` / `curLevelOf()` / `legacyLevelFromProf()`
- `data/practice.js` —— `clearedOf()` / `curLevelOf()` / `stageIndexOfCleared()` / `retreatText()`
- `tests/game.test.js` —— 一局一关、失败 / 回关 / 目标未达成都不推、晋段、走完 1000 关、v5→v10 迁移
- `tests/rank.test.js` —— 六档门槛 = 段界关、段位取值边界、回关不推进度、段内台阶
- `scripts/simulate.js` —— 全 C 与全 S 都是 1000 局、两条往回刷曲线卡在第 1 关

## 待验

- **1000 局是不是太长**：全 C 走完 1000 关要烧 22020 点灵力（≈ 闭关 734 小时）。
  真实玩家一池灵力（炼气 174 点）只够打 6 局圆满段，所以「走完一门」实际上是一年量级的事。
  这是刻意的（一门一条线、慢慢走），但「走得完吗」只能靠留存数据回答，未做真人观察。
- **属性先满、内容后满**：大圆满要 1000 关，而属性倍率在 1000 关才到 ×5——两者现在同步了，
  旧版「84 局满属性、还剩 916 关」的错位已经消失。但「×5 是终点」这件事玩家多久能感觉到，未验。
- 大圆满后「灵力照扣」是否会让玩家觉得被罚。目前只有文案「本局只记战绩」，没有更强的引导。
