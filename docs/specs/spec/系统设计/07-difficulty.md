# 需求（Spec）· 关卡制：一门一条 1–1000 的线，分五段

> **没有段位，也没有段位选择器。** 一门功法从第 1 关走到第 1000 关，
> 沿途经过 未入门 → 入门 → 小成 → 大成 → 圆满 五段，走通第 1000 关叫「大圆满」。
>
> 段位不是一个可选项，只是「已走通几关」的另一个说法：`stageIndexOfCleared(cleared)`。
> 熟练度（火候）只管网属性加成与本门新法，**不换关号、不开段、不解锁任何东西**。

---

## 核心前提：关卡是里程，不是门槛

想象你第一次打开一门新功法。这里没有「选难度」这一步——按钮上写着一个关号，打完一局它就往前挪一格。你从来不用决定自己「该在第几关」，因为关卡不是挑的，是走出来的。我想让这件事简单到不需要解释：一个数字只往前走，走通就 +1，回打和失败都不动它。段位也不是另一样要争取的东西，它只是你回头看时给这段路起的名字。

## 1. 概述

`cleared` = 本门已走通的关数（0–1000）。当前关 = `min(1000, cleared + 1)`。
一局只推一关：只有「走通本门当前关」才 `cleared + 1`，回打与失败都不推。
段位由 `cleared` 落在哪一段决定，不需要玩家挑，也没有「未开」这个状态。

```text
   熟练度（火候）          关号（cleared）
   ──────────────          ───────────────
   属性加成 · 本门新法       走到第几关
        │                        │
        └── 两把尺子，不互换 ────┘
```

## 2. 五段

| 段 | 关 | 关数 | 耗气基数 | pace | goal | gear | 这一段教什么 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 未入门 | 1–10 | 10 | 7 | ×1.18（更缓） | ×0.85 | normal | 一关一条规矩，先把手上认熟 |
| 入门 | 11–50 | 40 | 11 | ×1.00 | ×1.00 | normal | 规矩齐了，第一副真盘面 |
| 小成 | 51–200 | 150 | 17 | ×0.88 | ×1.12 | hard | 盘面收紧、目标抬高，失误余地更小 |
| 大成 | 201–500 | 300 | 24 | ×0.78 | ×1.22 | hard | 几乎没有容错，一乱即落 |
| 圆满 | 501–1000 | 500 | 32 | ×0.70 | ×1.32 | hard | 练到极处：最快节奏、最高目标 |

- `STAGE_GATES = [10, 50, 200, 500, 1000]`，段界关**属于本段**：走通第 10 关，
  人站在第 11 关（入门）；走通第 1000 关，段号 5 = 大圆满（`FINAL_STAGE_NAME`）。
- `gear` 只分 normal / hard 两值，玩法拿它分不出小成与圆满——**一段一细变必须靠 `depth`**。
- 段名（未入门…大圆满）与火候名（生涩…化境）是两套词，**不许互相借用**：
  两套都叫过「小成」，玩家分不清「我练到哪一段」和「我练得多熟」。

## 3. 为什么是 1000 关，而不是 200 或 999

关卡的真实分辨率是「相邻两关参数真的不同的关数」，不是对外标的数字。
旧版 999 关的真实分辨率只有 200（同段五关逐位相同），所以那一版把对外数字改成了 200。
这一版反过来：**先按玩家的时间感受定 1000 关（一段要走很久），再承认末三段的密度不够**。

**这是明写的欠账（D11），不是假装没有。** 口径 = `levelDelta` 非空（准备页真报得出这一关变了什么），
1000 关逐门实测（`node` 直调 `practice.levelDelta`，与准备页、结算同源，2026-11 复算）：

| 真变关数 | 门 |
| --- | --- |
| 429 | 九宫补缺诀 |
| 232 | 洞微勘禁诀 |
| 210 | 移石归阵诀 |
| 162 / 161 | 太虚照见诀 / 移星换斗诀 |
| 156 / 143 | 遍观毫厘诀 / 三秀撷英诀 |
| 133 / 110 | 澄心默诵诀 / 万石成岳诀 |
| 97 | 开锋破军诀 |
| 59 / 46 / 29 | 并蒂连枝引 / 摘星辨魁诀 / 同源归一诀 |
| 14 / 5 | 星罗烛天诀 / 吐纳周天诀 |

宽口径（相邻两关任一键不同就算变）现传十五门全是 999/999，等于没有信息量；旧版那张
999/429/156 分层表是 v9 之前按段而非按关收紧时算的，**已作废**，别再照它读。完整口径说明见
`docs/specs/constitution/08-待拍板清单.md` 的 D11。

末三段的关数（150 / 300 / 500）远超多数玩法的可动旋钮数，所以：

- 段内据实报「与上一关规格相同」，不把 20 秒写成 19.5 秒假装有变化。
- 第 1 关与第 1000 关是例外：两关都没有「上一关」可比（末关与上一关常被整秒取整抹平），
  分别报「本门第一关：起手规格」与「本门最后一关 · 比起手关：累计变了什么」，真源在
  `data/practice.js` 的 `levelDelta`。
- 换段是长线里**唯一一次**玩家看得见的盘面变化，`levelDelta` 必须优先报结构键。
- 补密度的方向是「每段新加一条规则 / 一副盘」，不是把毫秒再切细——那是 D11 的正文。

## 4. 硬规则

| 规则 | 内容 |
| --- | --- |
| 一局只推一关 | 走通「本门当前关」才 +1；失败不加、回打不加 |
| 只回打已走通的关 | 往前只能打「已走通 + 1」，往回可以退到 1；越权（改页面参数）夹回当前关并如实报出 |
| 段不可挑 | 没有段位按钮、没有「未开」；`STAGES` 上没有 `need`、没有 `open` |
| 满关不越界 | 走通第 1000 关后停在 1000，重打不推进也不算出第 1001 关 |
| 不设关卡锁 | 段内没有「必须先过第 N 关」——只有一个当前关，回打不受限 |

存档：`state.skills[id].cleared`（0–1000）。旧档的 `levels{diff:0-40}` 与更旧的 `prof`
在 v9 迁移里折算一次，见 `spec/系统设计/18-save-migration.md`。

## 5. 折减：只有一种，给「回打」定价

**熟练度 = 基础值 ×（本关 ÷ 当前关）×（本关段基数 ÷ 当前关段基数），四舍五入一次。**
段基数 = 未入门 7 / 入门 11 / 小成 17 / 大成 24 / 圆满 32。

| 本门走到第 800 关（圆满段 32） | 系数 | S | B |
| --- | --- | --- | --- |
| 打 800 关（当前关） | ×1.000 | 34 | 15 |
| 打 700 关（同段） | ×0.875 | 30 | 13 |
| 打 400 关（大成 24） | ×0.375 | 13 | 6 |
| 打 100 关（小成 17） | ×0.066 | 2 | 1 |
| 打 1 关（未入门 7） | ×0.0003 | 0 | 0 |

### 5.1 为什么是两把尺子

**第一把（关号）** 是主刀：越往回退，折得越狠，连续、无断崖，玩家按「400 ÷ 800 = 0.5」就能自己复算。

**第二把（段基数比）** 是补 v9 漏掉的那半截。只按关号折时，回关**同时省了段位的气**：
未入门一局 6 点、圆满一局 27 点，差四倍半。于是「停在低段反复刷同一条已走通的关」永远比
推进更省——实测 6000 点灵力下只刷第 1 关 11551 点熟练度，一路推进只有 6399 点（1.8 倍）。

v9 当时以为这条路不存在，理由是「走通必推一关，想停在第 N 关只能每局失败」。
**这句话是错的**：打一条**已经走通**的关也算走通，`当前关` 就钉死不动了，折减一直停在 ×0.95 上下。
护栏也因此空跑了一整版——`scripts/simulate.js` 里刷法名从 `easy/below` 改成 `first/half` 时，
策略表只改了一项、还是改成了不认识的名字，两条曲线都落进 `else` 算成了逐关进。
2026-11 补上第二把尺子并把护栏改成「回关每点灵力收益 ≤ 打当前关」，见 `08-待拍板清单.md` D12。

**它管不到的半截也写在那里**：同段内「停在原地刷上一关」仍然不亏（段成本涨 4.5 倍、熟练度基数不动），
所以「推进永远更划算」这句话在随机评级下不成立；真正的回报是连 S（只在本门当前关叠，回关不叠）。

### 5.2 同段回关只折一道

第二项在同段回关时恒为 1，退化回「本关 ÷ 当前关」——所以段内退几关的手感与旧版完全一样，
只有跨段回关才收第二刀。这条被 `rank.test` 单独守着（「同段回关不该被第二把尺子再折一次」）。

### 5.3 只折熟练度，不折耗气

耗气看**这一关落在哪一段**（7 / 11 / 17 / 24 / 32），与段内第几关、是不是回打都无关。
`practiceCostOf(state, skillId, level)` 吃关号、自己解析段位。
回打本来就折得厉害，再折气会让「回打刷分」变成省气的聪明选择。

### 5.4 与连 S 完全解耦

只有「本门当前关」的 S 才叠层。回打局：不叠层、不砍已有层数、不砍连击收益
（本局给的是折减后的基础值）。回当前关照接上一层 +1。

### 5.5 判定只有两个函数

`practice.levelFactor(level, curLevel)` + `practice.profByLevel(base, level, curLevel)`。
所有「折到几成」的判断都调它们，不许在页面里再算一遍。

## 6. 段内递进：本段基准 + 关内收紧

`buildParamsAt(method, level)` 四步：`rawParams(method, 本段)` 取段基准 → 时间与预算按
`progressOf(level)`（段内进度，段首 1/n → 段界 1）收紧最多三成（`LEVEL_TIGHTEN`）→
`tweakParams()` 叠一门自己的连续旋钮 → **按生效下限夹一次**
（节律判定的判定窗按毫秒定，压到 200ms 下限就停，见 `TEMPO_FLOOR`）。
最后这一步不能省：只在玩法层用 `max()` 托底，参数会继续变小而盘面不动，`levelDelta` 就会报
「判定窗 5.5% → 5.4%」这种盘面上根本没有的变化。

| 组 | 键 | 作用 | 缩放 |
| --- | --- | --- | --- |
| `PACE_KEYS` | `interval` / `flashMs` / `gapMs` / `windowMs` / `shuffleMs` / `flipMs` / `dropMs` / `window` / `msPerNote` / `life` | 节奏变快 | × `pace` |
| `GOAL_KEYS` | `chainGoal` / `maxRound` / `segments` / `beats` / `scramble` / `mines` / `pairs` / `decoys` / `startLen` / `baseLen` | 目标变高 | × `goal`，并按 `capFor()` 夹到安全上限 |
| 时辰 | `duration` / `timeLimit` | 时限收紧 | × `TIME_LEVELS` = 1 / 0.97 / 0.94 / 0.91 / 0.88 |
| 收敛 | `speed` | 光环收缩更快 | ÷ `pace`（方向相反） |

**盘面尺寸只在「规格类玩法」里放大**：阵灯 3×3 → 5×5、九宫 4 → 6 → 9、顺序点格 4×4 → 7×7。
其余各门盘面固定，靠参数变难。`verify` 守着「调难度不许顺手改盘面」。

**两刀不许叠在同一根轴上。** 滑块让路的 `capFactor` 只吃 `tweakParams` 那一刀（18%），
`buildParamsAt` 的 30% 对它跳过（`capOwned`）——两刀叠加要「先除掉一刀再乘」，
除法的两次取整会在段内冒出「预算 ×2.66 → ×2.67」的反向回弹。

## 7. 越权与回落

```js
const cleared = practiceData.clearedOf(rec);         // 已走通几关
const curNo   = practiceData.curLevelOf(rec);        // min(1000, cleared + 1)
const wantNo  = Math.max(1, Math.round(opts.level));
const levelFellBack = wantNo > curNo;                // 结算如实报出
const playedNo = Math.min(curNo, wantNo);            // 往上挑一律夹回
```

想打**还没走到的关** → 夹回当前关，结算报「所选关超出本门当前进度」。
想打**更早的关** → 允许，按 §5.1 折，结算写明「回打第 N 关（本门已走到第 M 关，退 K 关）」。
存档层（`applyPractice`）再判一次，防改存档与双页面同时开局。

## 8. 「本关变在哪」要说清

| 函数 | 粒度 | 说什么 |
| --- | --- | --- |
| `stageDetail(method, stageIndex)` | 一段 | 这一段相对基准收紧了哪几处（`brief`，准备页用） |
| `levelDelta(method, level)` | 一关 | 这一关相对上一关实际变了哪几处（最多 2 条，逐项格式化后同值就不报） |
| `stageSpec(method, level)` | 一段 | 本段换的是哪一副盘，按任意关号常驻返回 |

特例：阵灯 / 三秀 / 九宫 / 让路 / 合数 / 毫厘 / 入位 / 辨魁 有自己的 `brief` 句式，
因为它们的难度不是「快慢」，按时间字段拼只会拼出「入门基准」这句废话。

**换段只报结构键，不报毫秒。** 换段那一刻盘面规格换一副，同时时辰 / 停留一律回弹给读盘；
照老顺序按 `PACE_KEYS` 报，玩家看到的是「翻牌停留 0.70 → 0.84 秒」——又细、又像变简单。
`levelDelta` 在段界关先给一条带 `chapter: true` 的「踏入第 X 段」，再报 `LEVEL_STRUCT_KEYS`
（盘面 / 对数 / 息数 / 段数 / 待填格…）；没有结构变化的门如实写「沿用同一副盘」。

**「一局跨四五关」的成因已经消失。** 关由熟练度算的时候，一局连 S 能往前跨四五关，
段首关常被整步跨过去，所以 `stageSpec()` 必须按任意关号常驻返回。
现在一局只推一关，换段只发生在「走通段界关」那一刻。`stageSpec()` 留着（零成本，
换段时那一行仍要说清盘面换了什么），但它不再是补丁。

## 9. 被否决的方案

下面这几条路我们都走过。每一条在当时都看着合理，否掉的理由也都不是空话——留在这里，是想让后来的人一眼看见「这里试过，别再踩」。

| 方案 | 为什么否掉 |
| --- | --- |
| 难度由熟练度解锁（旧版） | 门槛 0/300/1500/6000/24000 与段位同源，于是「解锁难度」其实是「刷够分」；玩家要么刷到吐，要么以为难度是个能挑却点不动的按钮 |
| 五段各 40 关、玩家挑段（上一版） | 关卡只有 200 格，走完就没内容；挑段把「往前打」拆成五条平行线，回打折减要在「段内 ÷ 40」与「降段再对半」之间叠两刀 |
| 关卡由熟练度算出（更旧版） | 一条轴同时管「打哪一段 / 第几关 / 段位加成」三件事，三者只能同进同退，熟练度一毕业就没内容可打 |
| 999 关，真实分辨率 200（更旧版） | 对外标 999、对内只有 200 种盘面，且一局跨四五关时玩家根本数不清自己走到哪 |
| 关卡由「打过 +1」累加（当年） | 单看这一条没错，错在当年它和熟练度曲线对不上（200 关要 200 局，熟练度 84 局就毕业）。解耦之后反而成了正解 |
| `levelFactor = lv / curLevel`（当年） | 当前关停在第 1 关时第 1 关永远 ×1，「只刷第 1 关」变正收益（6000 点灵力刷出 11551 点熟练度）。现在走通必推，这条路已不存在 |
| 1000 关平分（每段 200） | 前半段太稀、后半段更稀。玩家最先看到的前 10 关必须一关一条规矩，所以取 10/40/150/300/500 的前密后疏 |
