# 需求（Spec）· 称号与成就

> 两套「收集」系统，长得像，机制完全不同：**称号要落盘、可佩戴；成就不落盘、每次现算。**

**核心前提：这是两套收集，但它们满足的是两种不一样的心情。** 称号回答「你曾经是谁」——它挂在人物卡片上，是你选了要戴的身份；成就回答「你走到了哪」——它是一排进度条，告诉你离下一个还差多少。我想让「身份」和「进度」各占一处，所以一个要存下来、一个每次现算。这不是技术偏好，是两种心情本来就该放在两个地方。

---

## 1. 概述

14 个称号（解锁后存入存档，可佩戴一个），14 项成就（只存元数据，进度由存档实时算出）。

## 2. 称号：14 个，可佩戴

`data/titles.js`：

| id | 名 | 条件 | metric / target |
| --- | --- | --- | --- |
| t01 | 初入道途 | 完成第一次参悟 | `practiceCount` 1 |
| t02 | 略窥门径 | 任一门到入门 | `maxTier` 1 |
| t03 | 一技大成 | 任一门到大成 | `maxTier` 3 |
| t04 | 炉火纯青 | 任一门到圆满 | `maxTier` 4 |
| t05 | 初战告捷 | 第一次战胜 | `wins` 1 |
| t06 | 同门无敌 | 累计战胜 5 次 | `wins` 5 |
| t07 | 筑基修士 | 突破至筑基 | `realmIndex` 1 |
| t08 | 金丹修士 | 突破至金丹 | `realmIndex` 2 |
| t09 | 博闻强识 | 习得 5 门功法 | `unlockedCount` 5 |
| t10 | 万法归一 | 习得全部功法（门槛按 `SKILLS.length` 现算，现存 15 门） | `unlockedCount` 15 |
| t11 | 触类旁通 | 触发 10 次换门省气 | `comboCount` 10 |
| t12 | 日日精进 | 领取 1 次份例 | `dailyClaimed` 1 |
| t13 | 一击圆满 | 取得 10 次 S | `gradeS` 10 |
| t14 | 返璞归真 | 任一门练至大圆满 | `maxTier` 5 |

### 机制

- `checkTitles(state)` 在每次结算后调用（参悟 / 切磋 / 突破 / 份例），算出新解锁的加入 `state.titles`；
- **第一个解锁的称号自动佩戴**（`equippedTitle`）；
- 佩戴是唯一的：`equipTitle()` 换一个，再次点同一个则取消佩戴（`''`）；
- 佩戴的称号出现在人物卡片上。

### 为什么要落盘

称号是**玩家选择佩戴**的东西。若每次现算，玩家选的那个就得另存一个字段——那不如把「已解锁」也存下来。而且称号是「曾经达到过」的记录，即使后来换了门也不该消失。

## 3. 成就：14 项，实时计算

进度条铺在四处：修行、切磋、收藏、境界，四组各管一段路：

`data/achievements.js`：

| 分组 | 项 |
| --- | --- |
| 修行 | 初入道途（1 次参悟）/ 日日不辍（10）/ 百炼成钢（50）/ 一念通明（1 次 S）/ 触类旁通（1 次换门）/ 登堂入室（1 次升段）/ 晨课不缺（3 天份例） |
| 切磋 | 初战告捷（1 胜）/ 少有敌手（10 胜）/ 遍访高手（首胜 3 位） |
| 收藏 | 小有藏书（5 门）/ 名动一方（3 个称号） |
| 境界 | 筑基有成（筑基）/ 金丹之资（战力 170） |

### 机制

```js
getAchievements(state) → ACHIEVEMENTS.map(a => ({
  ...a,
  value: 实际值,
  done: 实际值 >= a.goal,
  progress: 百分比
}))
```

**不往 `state` 里塞已解锁列表**。好处有三：

1. 老存档立刻能算出进度（不需要回填）；
2. `CANWU1:` 存档码导入后同样立刻可算；
3. 改阈值或加成就时，玩家已有的进度会自动对齐，不会出现「存档里说已完成、但条件已经变了」。

代价是不能记录「第一次达成的时间」。对成就来说这不重要——它只是一个进度条。

## 4. 两者的分工

| | 称号 | 成就 |
| --- | --- | --- |
| 数量 | 14 | 14 |
| 存储 | `state.titles[]` | 不存在 |
| 可佩戴 | 是（唯一） | 否 |
| 展示位 | 人物卡片 | 成就页（分组 + 进度条） |
| 语义 | 「你曾经是谁」 | 「你走到了哪」 |

称号是身份，成就是进度。同一个条件可能两边都有（如「初战告捷」在称号 t05 与成就 `first_win` 里各一条），这不是重复——一个能戴，一个能看进度。

把这两套东西并排画出来，分工就一眼可辨（这张图是设计意图，不是截图）：

```text
┌─ 两套收集，两种心情 ───────────────────────────────┐
│                                                    │
│   称号 · 身份                 成就 · 进度             │
│   落盘 state.titles[]        不落盘 · 每次现算       │
│   可佩戴一个                  四组进度条              │
│        ▲                         ▲                  │
│        │                         │                  │
│   「你曾经是谁」              「你走到了哪」           │
│                                                    │
│   同一个条件可以两边各一条：一个能戴，一个能看。       │
└────────────────────────────────────────────────────┘
```

## 5. 度量口径

`computeMetrics(state)` 是唯一的度量来源：

```js
{
  practiceCount,   // state.stats.practiceCount
  wins,            // state.stats.wins
  comboCount,      // state.stats.comboCount  ← 换门省气次数
  gradeS,          // state.stats.gradeS
  dailyClaimed,    // state.stats.dailyClaimed
  realmIndex,      // 当前境界下标
  maxTier,         // 所有已习得功法里最高段位
  unlockedCount,   // 已习得门数
}
```

注意 **`maxTier` 是「最高的一门」不是「平均」**，所以「一技大成」只需要一门练到大成。这是刻意的：让「专精一门」也能拿到称号。

`comboCount` 记录的是**换门省气的次数**（`cross` 为真时 +1），不是连 S 层数。这个命名有历史遗留，容易误读——真正的连击层数在 `state.sCombo[skillId]`。

## 6. 界面

| 页 | 内容 |
| --- | --- |
| 称号簿（`pages/titles/`） | 已得 / 未得两段；已得的可点佩戴；顶部「当前所佩」 |
| 成就页 | 四组（修行 / 切磋 / 收藏 / 境界），每项一条进度 |
| 人物卡片 | 佩戴的称号 |
| 结算 | 新解锁的称号在结算卡里提示一次 |

**称号簿默认折叠**（低频内容），长文用目录 + 手风琴。

## 7. 被否决的方案

「两个系统长得像」这件事，诱使过不少人提议把它们合并。下面这些否决，记的是我当初为什么坚持把它们分开。

| 方案 | 为什么否掉 |
| --- | --- |
| 成就也落盘 | 老档与导入存档无法自动获得已有进度，要写回填逻辑 |
| 称号实时计算（不带佩戴） | 玩家就没有「身份」这个东西了 |
| 允许多个称号同时佩戴 | 人物卡片放不下；且「唯一」才让选择有意义 |
| 称号有属性加成 | 会变成「必须刷称号」，与「收集」的定位冲突 |
| `maxTier` 取平均 | 「一技大成」这种称号就没人能拿 |
| 成就只显示已完成的 | 进度条本身就是动力，藏起来等于没有 |

## 8. 数值

**为什么称号门槛取这些点**：与养成节奏对齐——1 次参悟（第一分钟）、入门 300（第一小时）、大成 6000（第一周）、圆满 24000（第一个月）、大圆满 99999（长线）。14 个称号分布在整条曲线上，每个阶段都有一个新的。

**为什么「万法归一」要求收满全部门**：这是最贵的一个（时间或灵石），放在最后一个位置作为「收集毕业」的标志。门槛已按 `SKILLS.length` 现算，删门后同步降到 15，不用改代码。

## 代码指路

- `data/titles.js` —— `TITLES`（14）
- `data/achievements.js` —— `ACHIEVEMENTS`（14）+ `getAchievement()`
- `utils/game/` —— `computeMetrics()`、`checkTitles()`、`equipTitle()`、`getAchievements()`、`achievementMetric()`
- `pages/titles/` —— 称号簿
- `pages/profile/` —— 成就区与人物卡片
- `tests/game.test.js` —— 称号解锁与自动佩戴、成就实时计算

## 待验

- 「触类旁通」这个称号名在称号簿与成就里各出现一次（t11 与 `combo`），条件相同（10 次 vs 1 次），玩家是否会觉得重复。
- `comboCount` 的字段名（实际是换门次数）在维护时容易被误读，是否要改名。
- 称号簿与成就页在长列表下的折叠交互未在真机验证。
