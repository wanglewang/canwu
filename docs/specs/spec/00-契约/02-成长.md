# 需求（Spec）· S · 成长契约

> 回答：**一门的进度怎么长、段位怎么读、底线是什么。**
> 2026-11 之前这里是全项目最容易写混的地方：进度与段位是两套独立系统、两套名字。
> 现在只有一条线——**这门走通了几关**。受 `constitution/README.md` 约束。

## 契约与守卫

- **只有一条进度线**：`skills[id].cleared`（0–1000）。走通本门当前关 = +1，其余一律 +0。
  评级（S/A/B/C）不改变推几关，品阶不改变推几关，境界不改变推几关。
  **守卫**：`utils/game/settle.js` 的 `advanced` + `tests/game.test.js`「一局只推一关」+ `scripts/simulate.js` 的「全 S 与全 C 都是 1000 局」。
- **回关不推进度**：往回翻只能翻到已走通的关，那一局只剩「找手感」，耗气按本关所在段照收、不减免。
  **守卫**：`tests/rank.test.js`「回关不推进度」+ `scripts/simulate.js` 的两条往回刷曲线都卡在第 1 关。
- **段位就是关号位置**：六档门槛 = 段界关 `0 / 10 / 50 / 200 / 500 / 1000`，
  段名 未入门 / 入门 / 小成 / 大成 / 圆满 / 大圆满，属性系数 `0 / 1 / 1.8 / 2.8 / 4 / 5`。
  走通段界关当场进下一段；走通第 1000 关即大圆满并到顶。
  **守卫**：`data/world.js` 的 `TIERS` + `scripts/verify.js` 的「逐档等于段界关」+ `tests/rank.test.js` 的段位边界断言。
- **不许再出现第二套名字**：进度（段位：未入门 / 入门 / 小成 / 大成 / 圆满 / 大圆满）那一整套已删。
  现在「这门小成了」与「这门走通到第 50 关」是同一句话，写文档时也只准用段位名。
  **守卫**：`scripts/verify.js` 禁 `PROF_*` / `COMBO_*` / `comboGain` / `profByLevel` / `sCombo` / `breakCombo`。
- **每一段都要换规则**：段界必须改变玩法本身，不能只换秒表或缩尺寸；段内变化要让玩家察觉得到。
  **守卫**：`npm run audit:gap` + `data/practice.js` 的 `AXIS_*` 九类方向账 + `verify` 的逐格断言。
- **评级线唯一出处**：每档评级对应的分数线只有一个来源，不许在别处另写一套。
  **守卫**：`lines()` + `tests/rank.test.js`。

## 外部依赖

`data/world.js`（六档门槛与属性系数）、`data/levels.js`（段界与 `stageIndexOfCleared`）、
`data/practice.js`（评级线、方向账）。
