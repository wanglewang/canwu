# 需求（Spec）· S · 成长契约

> 回答：**熟练度和段位怎么长、各自的底线是什么。**
> 这是全项目最容易被写混的地方：熟练度和段位是两套独立的系统。受 `constitution/README.md` 约束。

## 契约与守卫

- **熟练度有硬顶**：每门功法各自累计，到顶后不再增长，但纪录照记、灵力照扣。
  **守卫**：`data/world.js` 的 `PROF_MAX` + `tests/rank.test.js` + `scripts/simulate.js` 两条曲线断言。
- **段位只看关数**：走通第几关决定段位，与熟练度、品阶无关。
  **守卫**：`data/levels.js` 的 `stageIndexOfCleared` + `tests/rank.test.js` 的段位边界断言（走通 10 关入门）。
- **两个名字不许混用**：熟练度那套叫「火候」，段位那套叫「段位」，名字一个字都不能重合。
  一条判据里出现段位词，先问清这个数是关数算的还是熟练度算的（C6、C7 两次踩坑）。
  **守卫**：`scripts/verify.js` 的术语扫描 + `docs/specs/tasks/07-已修归档.md` C6/C7。
- **每一段都要换规则**：段界必须改变玩法本身，不能只换秒表或缩尺寸；段内变化要让玩家察觉得到。
  **守卫**：`npm run audit:gap` + `data/practice.js` 的 `AXIS_*` 九类方向账 + `verify` 的逐格断言。
- **评级线唯一出处**：每档评级对应的熟练度增量只有一个来源，不许在别处另写一套。
  **守卫**：`lines()` + `tests/rank.test.js`。

## 外部依赖

`data/world.js`（硬顶）、`data/levels.js`（段位）、`data/practice.js`（评级线、方向账）。
