# 需求（Spec）· 视觉语言：宣纸、五支颜料色与「墨玉台、暖玉牌」

> **两套皮肤，三档设置**：白天「宣纸彩墨」（纸做底、白纸做卡、墨褐做字），夜里「墨玉夜」（深青墨底、玉白字、颜料色各提一档）。默认**跟随系统**（手机开了深色就用夜里那套），也可以在道牒 → 设置 → 皮肤里手选「白天 / 夜晚」。两套是**同一套色相的明暗两面**，不是两份设计。五支颜料色各绑一个系统。参悟页的舞台固定深色——它用的正是「墨玉夜」那一支，所以夜里进局没有硬切。

## 核心前提：先想象你抬眼的那一秒

玩家不会读这篇文档，他只会看见一屏颜色。我想让那一屏自己把话说完：哪一块能点、哪一块是灵力、哪一块走到头了——不用读一个字。所以颜色在这里不是装饰，是**分工**：一支颜料只许对应一件有名字的东西，多一件都不许上场。

这很重要，因为我们已经在这上面翻过两次车：先是「黑黑灰不溜秋」，加了彩色后又「花里胡哨刺眼」。两头的病根都不是「有没有颜色」，而是**颜色有没有活儿可干**。这一篇讲的，就是怎么让每一支颜色都领到一份说得出口的活。

白天和夜里看到的是同一座山门，只是天色不同——底压深、字翻亮、颜料提一档，分工表一个字不改。这是我给换肤定的底线：换肤不能让同一种含义在两套皮肤里变成两种颜色。

## 1. 概述

这不是「一套深色皮肤加几个色块」，是**一条能执行到底的配色纪律**：底色与正文只有纸墨两档，彩色只给五件有名字的东西（朱砂 = 主操作 / 当前项，石青 = 灵力 / 信息，石绿 = 进度，藤黄 = 灵石 / 贵重，绛紫 = 稀有）。任何一个新页面、新组件，只能在这五支里挑一支，并且必须说得出它代表哪个系统。

**白天与夜里共用这一条纪律**，区别只在于底色压深、文字翻亮、颜料色提档——分工表一个字都不改。所以「换肤」不会让同一个含义在两套皮肤里变成两种颜色。

## 2. 目标与非目标

**目标**

- **彩色是信息，不是装饰**：扫一眼颜色就知道哪一格是灵力、哪一块是秘境，不用读字。这一条决定了分色只在「有语义」的地方出现；
- 底色与字保持低彩度：纸是米黄、字是墨褐。大面积彩色与「宣纸」会互相打架，也会让每一屏都在喊；
- 数字与主操作永远最醒目，其余退成描边与字重；
- 中文排版不靠字距、不靠衬线体、不靠装饰符号撑「国风」；
- 夜里打开时，看到的必须是**同一座山门，只是天黑了**：底压深、字翻亮、颜料色提档，色相分工一律不动。

**非目标**

- 不做「两套互相独立的设计」（只有一套骨架在明暗两面上的展开，见第 3 节）；
- 不做「每页各自一套皮肤」：档位是**全局设置**，哪一页改了就全站跟着变；
- 不做逐元素换肤（自定义色板 / 让玩家挑颜色）：再开一支色，五支颜料色的分工当场失效；
- 不做四角金饰、大圆角气泡、发光描边这类「仙侠 UI 皮肤包」元素；
- 不用 ✦ ✿ ◆ 这类 dingbat 当装饰（部分安卓会渲染成彩色 emoji）；
- 不做彩虹式撒彩：同一屏里同一个含义只出现一次颜色。

## 3. 五支颜料色的分工

色值只有一处真源（`styles/tokens.wxss`），这里只写「哪一支归谁」，不抄值——抄了就会过期。

| 色 | 令牌 | 归谁 |
| --- | --- | --- |
| 纸 | `--c-imm-bg` / `--c-imm-panel` | 页面底 / 卡片面。底比卡暗一档，靠「纸压纸」的明度差分层级 |
| 墨褐 | `--c-imm-text` | 正文、卡片标题、面板主文字。不用纯黑 |
| 朱砂 | `--c-imm-primary` | **主操作 / 当前项**：主按钮、选中行、可点的文字链 |
| 石青 | `--c-imm-azure` | **灵力 / 信息**：气海页的灵力条、可点的信息链接 |
| 石绿 | `--c-imm-jade` | **进度**：进度条填充、已走通、「进行中」标签 |
| 藤黄 | `--c-imm-gold` | **灵石 / 贵重**：兑换页的灵石数、称号、掉落。做文字必须走 `--c-imm-gold-text`（暗一档） |
| 绛紫 | `--c-imm-violet` | **稀有 / 特殊**：不常开的入口、限定掉落 |

这张分工表回答的问题是「一支颜色归谁」。把它画到一屏上，就是下面这个样子——注意彩色的位置有多克制：

```text
┌───────────────────────────────┐
│ 炼气 · 境界   ▓▓▓░░ 62%        │  纸 + 墨：只报状态
├──────────┬────────────────────┤
│  星罗烛天 │  灵力 ▓▓▓▓░  96/174│  石青：信息
│  洞微勘禁 │  灵石 23   [兑]    │  藤黄：贵重 + 可点
├──────────┴────────────────────┤
│ 进度 ▓▓▓▓▓▓░░░░                 │  石绿：进度
│        [ 入  参  悟 ]          │  朱砂：唯一主操作
└───────────────────────────────┘
  稀有入口 —— 绛紫，不常开，平时不上场
```
*（设计示意，非实测截图；只为说明颜色分工，不代表最终排版与数值。）*

**怎么判断该不该上色（这条比上面那张表更重要）。** 判据不是「这个数字有没有含义」，而是「**玩家需要它来做什么**」：

| 该上色 | 不该上色 |
| --- | --- |
| 要从一堆里**挑一个**（当前项、选中标签、可点的字） | **并排罗列的一组同类文字**（三个数值、六个宫格字、一列表的右值） |
| 要**看状态**（进度走到哪、是否已走通、是否危险） | 只是**换个说法**的同义标签 |
| 是**唯一的主操作** | 页面里同时有好几处「重要」 |

> 反例（两处都真机上翻过车）：主页三个数值分过三种色（战力墨 / 灵力石青 / 灵石藤黄），六个宫格汉字分过六种色。它们不是「没有含义」，而是**含义不需要颜色传递**——标签就写在旁边，玩家不看颜色也知道那格是「秘境探索」。结果是同一屏的彩点从 3 个抬到 10 个，眼睛一直在被色相提醒「这里有东西」，读完什么都记不住。玩家原话：「花里胡哨刺眼」。

> 现在的口径：**主页那一屏彩色文字为 0**，彩色只出现在两个带「可操作」语义的地方——主按钮的朱砂底、灵石那一格的按压反馈。彩色块（按钮底、进度条）不算文字，不受这条限制。

**五支颜料取「水彩」的浓度，不取「矿物颜料」的浓艳（2026-11 定调）。** 玩家先嫌过「黑黑灰不溜秋」，改彩色后又嫌「花里胡哨刺眼」——两头的病根不是「有没有颜色」，是**颜色的浓度**。现在的解法是色相分工一个字不动，把五支整体降饱和、提明度：朱砂→陶土红 `#b1503a`、石青→雾水蓝 `#3d6f88`、石绿→苔豆绿 `#6a9c78`、藤黄→麦芽黄 `#b8933f`、绛紫→藕荷紫 `#8a67a0`。观感是轻小说插画那种柔和彩色，不是国画笔矿的纯色。**降饱和不是退回灰**：每支仍保住自己的色相；真正承字的那几支另备深一档的 `-text`，压到 4.5:1 以上，柔版只做块色与描边。

对比度（WCAG，纸 `#fffcf2` 上）：正文 **14:1**、次文字 **6.8:1**、注脚 **5.3:1**、朱砂文字版 **5.7:1**、石青 **5.3:1**、石绿文字版 **4.9:1**、藤黄文字版 **4.8:1**，全部达 AA。**藤黄裸块在纸上只有 2.8:1，只许做底色与色块，不许做字；柔化后朱砂裸块承白字仍有 5.0:1。**

夜里的那套（深青墨 `#08131c` 上）：正文 **16.3:1**、次文字 **10.0:1**、注脚 **7.0:1**、朱砂 **7.6**、石青 **8.9**、石绿 **9.0**、藤黄 **10.5**、绛紫 **7.3**，同样全在 AA 之上。夜里不是把白天那套压暗，是**各提一档**——深底反而给了更大的余量，所以夜里的字比白天更容易读。

**两套皮肤怎么组织（只有一份色值）。** 全部写在 `styles/tokens.wxss`：

1. `page { }` 是白天那套，逐键给值；`--night-*` 是夜里的**原色板**，同段定义一次，共 42 个键（含后补的 5 个 `--night-mine-*`）；
2. `.pg--t-night { }` 把每个 `--c-*` / `--c-imm-*` 映到 `var(--night-*)`，挂在**页面根节点**上；
3. `styles/scene.wxss` 的 `.pg--scene`（参悟页舞台）映同一批 `var(--night-*)`。

第 2、3 步**只做引用，不写字面色值**——这样「夜里的页面」与「夜里的舞台」在结构上不可能漂开。唯一的例外是原生栏四个变量（`--c-nav` / `--c-tab` / `--c-tab-text` / `--c-tab-active`）：`verify` 拿它们与 `theme.json` 逐字比对，必须是字面量。

**为什么档位解析放在 JS，而不是 CSS 的 `prefers-color-scheme`。** 媒体查询只会问系统。玩家手选「白天」而手机开着深色时，没有任何选择器能盖住「系统说是夜」——只能再写一份白天值，于是同一件事有两份真源，谁赢取决于选择器权重，而权重是改样式的人看不见的。所以档位由 `utils/theme.js` 合成一个确定结果（`light` / `night`），页面根节点出类名，CSS 里只有一条路径。

**原生栏要跟着一起切，而且必须每页切一次。** `wx.setNavigationBarColor` 只作用于当前页面，页面栈里其他页仍停在旧色上；`wx.setBackgroundColor` 补的是 `page` 元素那层 CSS 背景（类选择器改不到它，只能运行时设）；`wx.setTabBarStyle` 在非 tab 页必然失败——那是正常路径，不许弹错。三处加上 tabBar 换图全收在 `theme.syncPage()`，每页 `onLoad` / `onShow` 第一行调用。

`scripts/verify.js` 钉着这个结构：① 令牌表里**不许再出现** `prefers-color-scheme`；② 每个页面根节点挂 `pg--t-{{themeTone}}`；③ 每个页面 js 调了 `pageTheme.syncPage(this)`；④ `theme.js` 的 `CHROME` 与 `theme.json` 两段逐字相同；⑤ 夜块除那四个变量外不许写字面色值、夜板每个键必须真被引用、`.pg--scene` 也必须走 `var(--night-*)`；⑥ **夜块的底色与正文色不许与白天同值**（上一版就是两段同值，`darkmode` 与 `theme.json` 全套就位却一点都没切）、夜版 tabBar 图标必须存在。

**为什么上一版的否决理由不成立了。** 上一版否掉双主题的理由是「两套都要维护，且所有对比度都是蒙的」。那条理由成立的前提是「夜里要另做一套设计」——另做就得重新标定全部对比度，而没有任何断言能证明它好看。现在夜里只是**同一套色相的提亮**：色值只有一份 `--night-*`，对比度标定一次，分工表一个字不动。所以否决的前提被消解了，不是被无视。

**为什么上一版否掉「站内开关」，现在又做了。** 原理由是「要给 12 个页面挂类名 + 加存档字段 + 写原生栏运行时换色，还要处理手动与系统谁赢，多出来的状态验不完」。落地后发现前两项被高估：类名是每页一行、同步调用每页一行（`verify` 逐页断言），而档位是**本机偏好**——不进存档、不跨设备同步，根本不需要「存档字段」。真正要设计的只有一条：**`auto` 才问系统，系统变化只在 `auto` 档生效**，手选的档位不被系统拽走。所以这条否决是「成本估高了」，不是「状态验不完」。

**为什么推翻上一版（墨底 + 旧金）**：更早那版是「米金 + 薄荷青 + 荧光青 + 绿灰」四处并发、字还偏绿，整页发浑——那个问题是真的。但它被过度修正成「只有一支低饱和旧金压在大面积墨底上」，结果整页只剩黑、灰、一点脏黄：页面层一支彩色都没有，而项目本来就有五行色板，却只注进了玩法盘面。用户的原话是「哪有这种黑黑灰不溜秋的」。

**这次的纪律不是放开撒彩**：旧版的问题是「颜色没有语义，纯当装饰」；新版把颜色绑到系统上，所以它既是彩色的，也仍然是可读的。

## 4. 层级靠字号、字重，颜色另有分工

**层级**用字号与字重（见 `--fs-*` 阶梯）。**颜色不参与层级**，它只回答「这是什么」。

| 层级 | 用什么 |
| --- | --- |
| 主标题 | `--fs-h1`（54rpx）+ 700 |
| 姓名 / 强调标题 | `--fs-lead`（40rpx）+ 700 |
| 卡片标题 / 数值 | `--fs-h3`（32rpx）+ 600 |
| 区块标题 | `--fs-subhead`（30rpx）+ 600 |
| 正文 | `--fs-body`（28rpx）+ 400 |
| 次要 / 密集文本 | `--fs-body-sm`（26rpx） |
| 注脚 / 角标 | `--fs-caption`（22rpx） |

**明确不做**：

- 标题不加字间空格（`letter-spacing` 只给角标，4rpx）；
- 不挂衬线体（`app.wxss` 里 `.serif` 类还在，但页面一律不用）；
- 标题前后不加 `✦`、不加 `·` 分隔装饰。

## 5. 「墨玉台、暖玉牌」——唯一的实物质感区

参悟页进局后，盘面是全站唯一的实物：一块深色台，上面摆一片浅色牌。

- **台（`.grid` / `.klotski` / `.scroll` / `.orbit` / `.ring-area`）取 `data/visual.js` 按功法族注入的 `--well`**：兵刃墨青、心法墨绿、丹道墨褐、阵法墨紫。同一个灰阶，四个色相。
- **牌取 `styles/tokens.wxss` 的 `--jade` 一副**（`--jade` 面 / `--jade-paper` 凹槽纸 / `--jade-dim` 暗玉）：15 门共用，换门不换棋子，像同一副棋换棋盘。
- 舞台内的 HUD、底栏、结算卡取 `--c-imm-*`，但由 `styles/scene.wxss` 的 `.pg--scene` 局部重映射到「夜里的那一支」——纸墨带进夜底会变成白底黑字的 HUD。**准备页不在舞台里**：白天它是宣纸，夜里它是墨玉夜（与舞台同一个色），所以夜里从准备屏进局没有任何明暗变化。

为什么台要深：格子里要写字、要放图案、要读颜色差异。**牌必须比台亮六七倍**，牌才立得起来。旧版是「纸白底上摆纸白牌」，两者只差 1.1:1，远看就是一整块发光的白板——那正是「加了花纹还是不好看」的根。

台深了以后，「凸 / 凹」这对物理隐喻才真的成立：

- 未翻开的格子是**玉牌**：顶缘 2rpx 高光、底缘 7rpx 赭色厚度、牌下一条落影，四周留 8rpx 台色沟槽（边框取 `--well`，格子仍按百分比铺满，不必算 `calc()`）；
- `.cell--open` 吃内阴影，变成**凹槽里的旧纸**（`--jade-paper`）。

**这条比配色更有效**：玩家分得清「能点」与「点过了」，不需要靠颜色区分。

**一处例外：探禁（扫雷）整盘落在低亮区，不做釉面、也不做「点亮」。** 教训是踩了三次才收住的：已探格只要做成全盘最亮的那一层，探开一片就是一片反光板，怎么调色都晃眼（数字落在亮格上才够对比，可亮格一片就刺眼；数字改深又掉到 2.8:1 以下）。参照图之所以「不用盯着看」，不是米色好看，是它整盘没有一处接近白。所以这一门的极性跟实体棋盘一致：**未探 = 还没翻的牌（浅一点、凸，暗在下缘），已探 = 挖开的地方（更暗、凹，暗在上缘）**，探得越多盘面越暗，亮的地方只剩数字那几点。数字反过来走浅色（青玉 / 暖陶 / 旧金，落在已探格上约 7.6 / 6.5 / 7.0）。**第四次返工的病根不在格子，在 `--well`**：格子之间那道沟槽取的就是 `--well`，它曾被压到近黑 `#241d15`，等于在暖赭格上罩了一张黑网，远看既灰又碎。第五次才听明白那句话：**网格线跟的是整页的背景色，不是盘面的颜色**。参照图里盘不是嵌在墨里的一块板，是若干暖玉牌摊在纸上——缝就是纸。所以 `.board--mines` 的 `--well` 直接取 `--c-imm-bg`：白天米色缝、夜里深青缝，盘与页面是一整块；外圈那道旧金细线与墨圈也撤了（那是「盘浮在纸上」才需要的边框）。通用盘那三道「上缘暖光 / 底部暗角 / 内圈压黑」在探禁上同样撤掉，明暗全交给格子自己。**手段从「凸 / 凹」换到「暗上沿 / 暗下沿 + 数字反白 + 纸色沟槽」，要达到的那件事没变**：一眼分得清「能点」与「点过了」，且整盘不属于灰或黑。作用域是 `practice.wxss` 的 `board--mines`，数独的已填格仍是旧纸凹槽。**第六次返工换的是色系，不是极性**：暖褐铺满一盘仍被判「土、脏、简陋」，夜里压在深青墨页上更是两块不相干的颜色；改成青灰石——白天像一方冷玉摊在宣纸上，夜里是同一方玉沉进墨里。色板收进 `styles/tokens.wxss` 的 `--mine-*`（夜色 `--night-mine-*` 由 `.pg--t-night` 转接），翻格涟漪 / 踩禁冲击环 / 连开扫光走 `mineFxList` 浮层，只挂这一门。特效时长收在翻片 420ms、踩禁 520ms、连开 360ms；环直径由玩法层按列数下发（`--fx-size` / `--fx-half`），6×6 到 12×12 都不跨格压住刚翻开的数字——通关那圈 240rpx 是唯一例外，那时已没有数字要读。

## 6. 按钮只有两支

| 支 | 类 | 高度 | 用在哪 |
| --- | --- | --- | --- |
| 朱砂实心（主操作） | `.imm-btn` | `--touch`（88rpx） | 一屏只能有一个：开始参悟 / 再来一局 / 微信登录 / 突破境界 |
| 细描边（次操作） | `.imm-btn--ghost` | 88rpx 或 `--sm` 64rpx | 返回、导出、撤销、复位…… |

两条硬规则：

1. **`line-height: 1`**。微信 `button` 默认行高 2.55，不锁死会让两枚并排按钮一高一低；
2. **实心按钮的底色写在 `background-color`、明暗层次单独挂 `background-image`**。写成 `background: linear-gradient(...)` 且色标是变量时，任何一次变量解析失败都会让整条 `background` 失效，按钮退化成「一行没有底色的字」——真机上极难排查。

`.imm-btn--danger` 不是第三支，它是 `.imm-btn--ghost` 的修饰：淡褐描边 + 警示红字，只用于「重置存档 / 退出登录」这类不可撤销操作。

## 7. 原生导航就是唯一导航

- 页面 `json` 的 `navigationBarTitleText` 与原生返回箭头承担全部导航；
- 页内**不画**标题、不画 `‹`、不画第二个返回；
- 「说明」这类低频入口沉到页尾 `.pg__foot` 一行小字；
- `navigationBarBackgroundColor`、tabBar 三色必须与令牌同值（`theme.json` 的 `light` / `dark` 两段分别对令牌的白天 / 夜块），`scripts/verify.js` 逐项核对；运行时再由 `utils/theme.js` 按玩家档位改一遍（`CHROME` 与 `theme.json` 同被断言钉住）；
- **tabBar 图标是纯色 png，不认 `theme.json` 的 `@变量`**。底色跟着主题换了、图标不会，白天的墨褐图标压在夜里的 `#0f2030` 上等于消失。所以图标出**昼夜两套共 12 张**（`scripts/gen-icons.js` 从 `theme.json` 读色值，链条是 tokens → theme.json → png），由 `theme.syncPage()` 用 `wx.setTabBarItem` 换。换失败**不记「已应用」**，下次进页面会重试——否则失败一次就永远停在错的那套图标上。

历史上曾有一个 `.imm-head`（右上角单字动作）和 `.pg__head`（眉标 + 标题 + 说明），两者都已删除——它们等于第二层导航。

## 8. 反例：被否决的具体做法

下面每一条都不是纸上推演出来的，是我们在真机上撞过、或者认真想过又主动放弃的路。我把它留在这里，是因为**记下「为什么不」比记下「是什么」更能防止下一个人重犯**。尤其头两条——它们曾经被翻过案，理由还留着，翻案的是那部分已经被现实消解的前提。

| 做法 | 为什么否掉 |
| --- | --- |
| 恒定深色 + 唯一旧金强调 | 2024 版就是它。低饱和金在墨底上读作「脏黄」，页面层一支彩色都没有，玩家判定为「丑」 |
| ~~浅色 / 深色双主题~~ **（已翻案）** | 原理由：「两套都要维护，且所有对比度都是蒙的」。**这条前提是「夜里另做一套设计」**——另做才需要重新标定全部对比度。现在的夜皮肤是同一套色相的提亮：色值只有一份 `--night-*`、对比度标定一次、分工表不动。前提消解，故改为跟随系统两套皮肤（见第 3 节） |
| ~~站内手动主题开关~~ **（已做）** | 原理由：要给 12 页挂类名 + 存档字段 + 原生栏运行时换色，状态验不完。**成本估高了**：类名与同步调用各一行（`verify` 逐页断言），档位是本机偏好、不进存档；「手动 vs 系统」只有一句——`auto` 才问系统。现为三档开关，默认跟随系统（见第 3 节） |
| 一屏撒五种彩色（彩虹式） | 颜色没有语义时只是噪音；彩色必须绑系统 |
| 紫色当主强调 | 绛紫已归「稀有」，主操作再抢它，玩家会以为每个按钮都是稀有物品 |
| 四角金饰 + 大圆角气泡 | 皮肤包审美，与「1rpx 细描边 + 大块留白」相反 |
| 标题加字距做「古典感」 | 中文加字距只显得松散，不显得古 |
| 用 dingbat 当分隔 | 部分安卓换成彩色 emoji，与纸墨撞色 |
| 盘面也做浅色 | 格子里读不出数字与图案差异；牌必须比台亮六七倍 |

## 9. 代码指路

- `styles/tokens.wxss` —— 全部颜色 / 字号 / 间距 / 圆角 / 阴影 / 层级 / 触控 / 动效令牌，**唯一真源**；白天段 = `page{}`，`--night-*` = 夜色原色板，末段 `.pg--t-night` = 逐键引用
- `utils/theme.js` —— 三档设置（`auto` / `light` / `night`）、档位解析、原生栏与 tabBar 换色；`CHROME` 与 `theme.json` 同值
- `styles/immortal.wxss:20` —— `.pg--imm` 把 `--c-*` 映射到 `--c-imm-*`（昼夜通用）
- `styles/scene.wxss:12` —— `.pg--scene` 把同一组 `--c-imm-*` 映到 `var(--night-*)`
- `data/navigation.js` —— 六宫格的字形与去向（字形一律墨褐，见第 3 节的上色判据）
- `app.wxss` —— 全局基础层（`.pg` / `.card` / `.btn` / `.state` / `.modal` / `.sticky-bar`）
- `app.js` 的 `theme.watch()` —— 系统切深浅时调一次（只有 `auto` 档跟），并把手选档位重新压回原生栏
- `pages/profile/profile.js` 的 `onPickTheme()` —— 道牒 → 设置 → 皮肤的三档开关
- `theme.json` —— 原生导航与 tabBar 的 `@变量`，`light` / `dark` 两段分别与令牌同值
- `scripts/gen-icons.js` —— tabBar 图标，色值从 `theme.json` 读，一次出昼夜两套
- `tests/layout.test.js` —— 守着「页面不许画第二个标题」「页面名必须等于宫格入口名」
- `scripts/verify.js` —— 核对 `theme.json` 与令牌同值、页面根节点挂 `.pg`、无裸色值、夜板单一真源、两套皮肤不许同值、夜版图标存在

## 10. 待验

- `.pg--imm` 是**类选择器**：一旦某页根节点漏挂它，页面会退回 `tokens.wxss` 的基础层。白天漏挂是「退成基础层」、夜里漏挂是「整页发暗」，两种症状不同但都能看出来；`verify` 仍逐页断言根节点挂 `.pg` / `.pg--scene`。
- **手选「白天 / 夜晚」与系统深色是否真的分得开**：系统切深浅时框架会按 `theme.json` 重设一次导航栏与 tabBar，`onThemeChange` 里已经把手选档位重压一遍，但时序未实测——切完那一帧会不会先闪旧色。
- **`wx.setTabBarItem` 换图有没有可见闪烁**，以及冷启动时 tabBar 未渲染那一次的失败是否被页面 `onShow` 补上。
- 手选「夜晚」后进参悟页，舞台与页面是同一个色（零切换）；手选「白天」时那一次「纸→夜」硬切仍在——两条路径都要复看。
- `page` 元素那层 CSS 背景由 `wx.setBackgroundColor` 补，iOS 上能不能盖住下拉回弹区未实测（`.pg` 已铺满 100vh，正常情况下看不到）。
- 宣纸底上反射式眩光（户外强光）未实测；浅底比深底更吃反光。
- 白天的「纸→夜」进局转场是否刺眼（夜里已无转场）。
- 五支颜料色在低色温屏（暖色模式）上的区分度未实测，尤其朱砂与绛紫在小面积图标上；夜里那套整体偏亮，需复看是否「发光发荧光」。
