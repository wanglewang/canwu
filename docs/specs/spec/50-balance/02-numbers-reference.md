# 数值总表（改数值前先看这一页）

> 全项目所有会影响玩家的常量都在这里。每一行都标了出处文件，改之前先去那个文件改，**不要在别处写第二份**。

## 核心前提：这是账本，不是说明书

我把这篇当成一本账，而不是一篇用来读的文章。它存在的理由只有一个：当有人想改一个数时，能在同一个地方查到「它现在是多少、在哪个文件、被谁引用」。所以它不追求好读，追求的是「全、准、能对上号」。

这也意味着你读它的时候要换个心态——不要从头读到尾，要带着一个问题来查：「灵力上限由哪几样决定？」「破境要几枚灵石？」查到那一行，顺着出处文件去改，改完按第 7 节的三问核对。

这篇和 `01-progression-curve.md` 是一对：那边讲「这些数凑出来的曲线长什么样、为什么这么设计」，这边讲「这些数本身是多少」。想知道为什么 → 去那边；想知道是多少 → 留这边。

带着问题来查时，先看清这本账分成几本分账——每个问题落在哪一本，就翻到哪一节：

### 1.2 耗气算法

```
qiCost = RUN_QI[段] × methodQiFactor × TIER_QI[品阶] × 1.5(超限)
         ÷ min(1.6, 1 + 悟性/200) × 0.92(换门)
         → round，最低 1
```

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `RUN_QI` | `[7, 11, 17, 24, 32]` | 五段基数 |
| `TIER_QI` | `{huang:1, xuan:1.15, di:1.3, tian:1.45}` | 品阶加价 |
| `BASE_QI_REF` | 36 | 时长系数的基准（`method.base / 36`） |
| `METHOD_QI_MIN` / `MAX` | 0.85 / 1.3 | 时长系数上下限 |
| `REALM_OVER` | 1.5 | 超 `maxRealm` 时 ×1.5 |
| `CROSS_QI` | 0.92 | 换门（上一局练的是别的） |
| `WU_SAVE_MAX` | 1.6 | 悟性省气的除数上限 |
| `PRACTICE_SAVE_MAX` | 0.5 | 心法 `qiSave` 合计封顶（省一半） |
| `QI_COST_MIN` | 1 | 最低 1 点 |

### 1.3 气海

```
qiCap = round((境界基数 + 真元 × 2) × (1 + min(0.3, 扩池)))
```

| 常量 | 值 |

| `QI_CAP_SKILL_MAX` | 0.3（心法扩池封顶 30%） |

## 4. 熟练度（`data/world.js` + `data/practice.js`）

| 常量 | 值 |
| --- | --- |
| `PROF_MAX` | 99999（硬顶） |
| `PROF_BASE` | `{S:34, A:23, B:15, C:10, F:0}` |
| `COMBO_STEP` | 1.5 |
| `COMBO_MAX` | 10 |
| `COMBO_TABLE` | `[34,51,77,115,172,258,387,581,871,1307]` |
| `COMBO_ROUND` | 3853（十连合计） |
| `COMBO_CAP_GAIN` | 1307（封顶值） |
| `PROF_C_RUNS` | 9999（全 C 局数） |
| `PROF_S_RUNS` | 84（全 S 局数） |

**六阶火候**：`0 / 300 / 1500 / 6000 / 24000 / 99999`（生涩 / 初窥 / 渐熟 / 精纯 / 通玄 / 化境）。

**关卡**：一门一条 1–1000 的线，`LEVEL_MAX = 1000`，五段 `10 / 40 / 150 / 300 / 500`
（`STAGE_GATES = [10, 50, 200, 500, 1000]`）。熟练度**不算关号、不决定段位**。

**回打折减**：系数 = （本关 ÷ 当前关）×（本关段基数 ÷ 当前关段基数），四舍五入一次；
段基数未入门 7 / 入门 11 / 小成 17 / 大成 24 / 圆满 32。本门走到第 800 关（圆满段）时，
S 的 34 点在 800 / 700 / 400 / 100 / 1 关为 `34 / 30 / 13 / 2 / 0`，
C 的 10 点为 `10 / 9 / 4 / 1 / 0`。
**只有这一道折减**——没有「前段再对半」；第二项是同一道折减里的第二个乘数，
管的是「回关同时省下的段位气价」，不是又一道刀（见 `spec/10-systems/07-difficulty.md` §5）。

`GRADE_FACTOR = {S:1.5, A:1.2, B:1.0, C:0.6, F:0}` —— **现仅用于判 `wiped`，不参与熟练度计算**（熟练度只用 `PROF_BASE` + 连 S）。

## 7. 一句核对口诀

改任何一个数之前，问三个问题：

1. **它在哪个文件？** 表里每一行都标了出处。
2. **有没有第二处在用它？** 用 `grep` 找引用，尤其注意「模块里的兜底值」与「`data/` 里的真源」必须相等（`verify` 有逐项比对）。
3. **改完之后跑 `npm run check` 与 `npm run sim`。**

## 8. 待验

- `GRADE_FACTOR` 现在只用于判 `wiped`，但它的值（1.5 / 1.2 / 1.0 / 0.6 / 0）仍在代码里，很容易被误认为「还参与熟练度」。建议改名或在注释里写死。
- `BASE_QI_REF = 36` 是「时长系数的基准」，15 门的 `base` 在 30–56 之间。**基准取 36 而不是中位数**，意味着偏长的门（56）耗气 ×1.56，偏短的（30）×0.83——这个选择的依据没有记录。
- 上表 15 门是 `data/skills.js` 的 `SKILLS` 数组，但 `data/practice.js` 的 `PRACTICE_METHODS` 是另一份（含 `base` / `params` / `tip`）。**两处必须一一对应**，`verify` 8b-8 双向核了这件事：功法指向的 `method` 必须在 `PRACTICE_METHODS` 里，反过来每个参悟方式也必须至少有一门功法能玩到——两头漏一头都会让图鉴点进去白屏，或者做了玩法没人用。
- `MINES_HEARTS = [3,3,2,1,1]` 已从早期的 `[3,3,3,2,2]` 收紧：心神不再只是区分度审计「第二个参数」的补丁，后两段零容错本身也是段差的一部分。
