# 秘境探索

> 秘境是「地方」，不是「对手」。它用同一套判定（`battle()`），但语义完全不同：你不是打赢了谁，而是**走通了一处**。

**核心前提：秘境是我留给「今天还想拿点灵石、但不想再跟人较劲」时去的地方。** 切磋要挑对手、要运功、赢了还有人对着你说话；秘境把这些全拿掉，只留一句环境话和一处你走过的地方。它们在引擎里其实是同一个 `battle()`——你照样运功、照样摇点——但屏幕上没有「对手」这个概念。我想让「去走一处」和「去打一场」在手感上就是两件事，哪怕底下算的是同一笔账。这个区别很重要，因为秘境存在的理由不是「又一处能刷钱的地方」，而是给「打不过某个对手」的你留一条仍走得通的路。

---

## 1. 概述

三处秘境，各有战力门槛与固定灵石收益；每场先运功 2–5 点灵力（随三式浮动），走通则得灵石，首次走通另加 8 枚。

**运哪三式与切磋共用同一套**：同一页上的「本场运功」面板，同一份 `moveBoard()`，同一个 `qiCost`。走秘境也要把功法运出去——这是秘境与切磋唯一完全一致的地方，因为「怎么走进去」和「跟谁打」在引擎里本来就是一回事（`battle()`）。见 `15-battle.md` §9。

## 2. 三处秘境

| 秘境 | 战力 | 灵石 | 描述 |
| --- | --- | --- | --- |
| 后山灵泉 | 60 | 8 | 灵力浓得有点呛人，适合闭关，也适合打盹 |
| 废弃丹房 | 160 | 16 | 炉火早熄了，架子上还剩几只没贴标签的瓶子 |
| 云海断崖 | 320 | 30 | 风大到说话得靠喊，据说有人在崖上悟过剑 |

三处合计一次性 54 枚；首次走通各另加 8 枚（共 24）。

我把这三处摆成一条往上走的山径——门槛越高，石越厚。这张图是设计意图，不是截图：它想让你一眼看见「总有一处在你能走的范围里」：

## 3. 与切磋的三处不同

同一套判定摆成两种玩法，差别就在玩家眼里「打人」和「走地方」的不同——也正是这几条，让秘境没有沦为切磋的换皮：

| | 切磋 | 秘境 |
| --- | --- | --- |
| 对象 | 7 位具体的人 / 妖 | 3 处地方 |
| 掉落 | 首胜可掉功法 | **不掉功法** |
| 台词 | 对手说一句 | 环境说一句（「泉水太凉，你决定改天再来」） |
| 定位 | 主要灵石来源 | 补充灵石 + 叙事点缀 |

**秘境不掉功法**是刻意的：功法的三条获取路径（初始三门 / 藏经阁 / 切磋首胜掉落）已经够，再加一条会让「打谁掉什么」这件事变模糊。

## 4. 判定

我没有为秘境另写一套判定——它直接复用 `battle(state, id)`。这点很重要：**「怎么走进去」和「跟谁打」在引擎里本来就是同一件事**，省下的不只是代码，还有玩家的理解成本（他会发现秘境和切磋共用同一套运功面板）。具体走一遍是这样：

- 扣 2–5 点灵力（不够直接拒绝）；
- 摇点：玩家 `power × [floor, 1.15]` vs 秘境 `power × [0.85, 1.15]`；
- 赢了按 `0.85^(当日已胜场数)` 给灵石；
- 首次走通：`+8` 枚 + 记入 `defeated`。

**「已胜场数」与切磋共用一个计数器**（`state.daily.battleWins`）。所以一天里打了 3 场切磋再进秘境，秘境也按第 4 场衰减。

我刻意让两条路共用一个计数器，这是「灵脉一天只吐那么多」的一致表达——如果各自计数，玩家会两边轮着刷，衰减就失去意义。读者可能会问：那进秘境是不是就亏了？不亏——秘境补的是「打不过某个对手」时仍有一处可去的缺口，不是另一条刷钱线。

## 5. 结算卡上的措辞

走通、没走通、第一次走通，三种情况下玩家各看到什么词——「首过」和「首胜」的分工就落在这里：

| 情况 | 标题 | 说明 |
| --- | --- | --- |
| 首次走通 | **首过** | `首过 后山灵泉，灵石 +16`（8 + 首过 8） |
| 重复走通 | **胜** | `+8（第 2 场 ×0.850）` |
| 未走通 | **负** | 环境台词，不给灵石 |

「首过」这个词只在秘境用，「首胜」只在切磋用——虽然底层是同一个 `firstClear` 标记。

## 6. 界面

- 首屏一行「境界 · 灵力 96 / 174」（与切磋同）；
- 三行秘境，每行：名 / 战力门槛 / 走通所得 / 是否已过；
- 结算卡与切磋共用 `components/duel-result`；
- **不在本页开「去切磋那页」的入口**——指向由「此处说明」承担，返回交给原生导航栏。

## 7. 被否决的方案

下面每一条，都是当时有人真的想过要那么做。我把它们留在这里，不是给否决盖章，是记下当时的诱因——下次谁再提，至少知道它当初为什么被放下。

| 方案 | 为什么否掉 |
| --- | --- |
| 秘境掉功法 | 与「打谁掉什么」的清晰性冲突 |
| 秘境只产灵力 | 与「灵力来自闭关与份例」冲突，两条线会混 |
| 秘境独立衰减计数 | 见第 4 节 |
| 秘境做成小游戏 | 「秘境」若也要打一局，它就和参悟没有区别；它该是「一次探索」，不是「一门功课」 |
| 秘境每日限次 | 衰减已经足够收敛，硬性限次只会让玩家觉得被卡 |

## 8. 数值推导

**为什么是 8 / 16 / 30**：约等于「同战力段位对手」奖励的 60–70%（如 60 战力对应赵砚 12 枚，秘境给 8 枚）。秘境该比切磋略差——切磋有对手叙事与掉落，秘境只有一次探索。

**为什么门槛是 60 / 160 / 320**：与七个对手的战力曲线错开（42 / 85 / 130 / 190 / 270 / 370 / 520），让「打不过某个对手」时总有一处秘境可以去。

**为什么首次只给 8**：与切磋首胜同额。都是「打通这条路」的奖励，不该因为内容是「地方」就更贵。

## 待验

- 三处秘境的数量是否够：走通后只剩「重复刷」，缺少新鲜感。这属于内容不足，不是设计问题。
- 「首过」与「首胜」两个词玩家是否分得清（同一底层，不同语境）。
- 秘境行的「战力门槛 / 走通所得」四行信息在 4.7 寸屏是否挤成两行。
