# 宪法（Constitution）· 十三条设计原则

> 一句话：这不是「好游戏都这么做」的抄录，是十三次取舍的记录——每条都写清了我守住什么、又为此放弃了什么。

## 先讲清楚：为什么要给每条原则配一个「代价」

我知道有人会问：写「要做什么」就够了，何必花篇幅写「不做什么」「代价是什么」「被否决的方案」。因为前者谁都写得出来，后者才是决策。一条原则若只写好处、不写代价，下一个人读到它只会当成口号；真碰到两个方案打架，他还是会拍脑袋——而拍脑袋的结果，往往就是把已经踩过的坑再踩一遍。

这十三条是判断依据，不是宣传语。每条都带着自己的代价；一条原则如果没有代价，它就只是偏好。把一条原则摊开，骨架大致长这样：

```text
       一条原则长什么样
   ┌──────────────────────────────┐
   │ 想守住的那条线  —— 原则       │
   │        │                      │
   │  不守会塌成什么 —— 为什么      │
   │        │                      │
   │  为此放弃的那一头 —— 代价  ★   │
   │        │                      │
   │  谁来盯住别滑坡 —— 守卫        │
   └──────────────────────────────┘
   ★ 没有这一格，剩下的就只是偏好
```

不是每一条都留了「被否决的方案」——只有当时确实有过另一条路时才留。那些地方是这份文档最值钱的段落：写清「为什么不是另一种」，才算把决策真的留了下来。

编号沿用设计期的「十二原则」，第十三条（变化方向）是 2026-11 新增的，见 `scripts/verify.js` 8b-6a-4 与 `08-待拍板清单.md` D17。代码注释里能找到对应的是第三节（递增曲线平缓）与第十一节（阶段新法加规则不减难度）；行号会随代码变动，这里只记节号，不写 `文件:行号`。

## 一、一门功法一套玩法，不换皮

**原则**：15 门功法 = 15 套互不复用的玩法内核。同族（三门阵法、三门心法）也不共用盘面与判定。

**为什么**：玩家分辨「这是另一门功课」的唯一依据是**动作**，不是名字。如果刀法和剑法都是点格子数数，那 15 门就只是 15 个数值段位。养成游戏里，「练哪门」本该是个有内容的选择。

**怎么判**：把这一门的文案全删掉，只看盘面与判定，还能不能分辨出是另一门。分不出就是换皮。

**代价**：新增一门功法的成本是「写一套玩法」，不是「加一行配置」。15 门意味着 15 份 `create()`，最长的一门（`click.js`）796 行。这个代价被接受，因为它是这个产品唯一的内容护城河。

**守卫**：`tests/minigames.test.js` 断言「15 门功法对应 15 套互不重复的玩法」「同类功法也各用各的玩法」「每门功法的独有机制互不重复」。

**曾经违反**：九套经典玩法最初是「同一门功法换难度就换盘面」，被判为换皮后改成九门独立功法（各挂黄阶、各有名字与属性加成）。

## 二、一个维度只管一件事

**原则**：类型管**玩什么**，品阶管**练得多贵、属性多厚**，进度管**能选多难**，境界管**上限**。调数值时互不牵扯。

**为什么**：四个维度如果都能影响同一件事（比如都能加速进度），那么「练哪门划算」就变成一个四元方程，玩家算不出，设计者也算不出——只能靠拍脑袋配平，然后被模拟推翻。

**代价**：品阶不能「越高级练得越快」，于是天阶功法的价值只能落在战力、属性与可修境界上；而高品阶又更费灵力，等于「贵且不加速」。这条代价由「灵力和灵石两条线不交叉」来补偿（见第六条）。

**守卫**：`tests/rank.test.js` 断言四品阶走通同一关都只 `+1`（品阶不换进度）、`scripts/verify.js` 断言 `qiCost` 随品阶单调、`attr` 随品阶单调——品阶只在「多贵、多厚」上说话。

**被否决的方案**：品阶 `reward` 直接乘进进度（天阶是黄阶 3.2 倍）。模拟显示低阶功法在成长线上被淘汰，玩家只会盯着天阶，黄阶的十一门等于装饰。

## 三、递增曲线平缓，无断崖

**原则**：任何随进度增长的量（段位、进度段、气海、耗气），相邻两段的差幅要接近，不做突变。

**为什么**：断崖会把「渐进练习」变成「卡关」。玩家看不到进步，只会觉得「我不行」，而不是「我再练练」。

**怎么落地**：

- 时辰：五段统一 ×1 / 0.97 / 0.94 / 0.91 / 0.88（`TIME_LEVELS`），每段收 3%，绝境累计只收 12%。
- 气海：炼气 150 → 筑基 260 → 金丹 420 → 元婴 620，段差 110 / 160 / 200（越往后越宽，不是越窄）。
- 关卡段：六档门槛 0 / 10 / 50 / 200 / 500 / 1000（= 五段的段界关），段内关数 10 / 40 / 150 / 300 / 500——每段都比上一段长，越往后越宽而不是越窄。段长是内容量，不是难度旋钮，见 `spec/数值平衡/01`。

**反例（已经修掉的）**：三连互换（2026-11-19 随功法正名三秀撷英诀一起定名）的旧版「S 线 620 + depth×150」，四段写死 60 息 / 5 色 / 罚 2 息——五段实际是同一局打五遍。现在五段由三个方向推进：花色 5→6→7（到顶）、石皮 0→2→5→9→14 格、手数预算 57→38 手（每步另有 30 秒思考限时，不随段收紧）；盘面 6×6→10×10 只负责「一眼看出换段」，不再当难度轴（消消乐里盘越大同色越多，实测换段那一关反而更好打）。

**代价**：段与段之间的「难度感」不如大步跳来得明显。补偿手段是让**评级线**跟着段位重标定，而不是靠参数暴涨制造压迫感。

**守卫**：`scripts/difficulty-audit.js` 逐门检查五段是否至少有两个玩家可见参数变化；`tests/rank.test.js` 逐门复算参数表与评级线。

## 四、只奖不罚，但难度是事前承诺

**原则**：连续练同一门不掉收益；「已经打到当前关却往回退」不推进度——这不是惩罚，是把承诺兑现。

**为什么**：这两句看似矛盾，其实分工不同。**「只奖不罚」管的是专精**：玩家不该因为反复练同一门而收益递减，那是旧版「连练递减」的毛病，已整条废弃。**「难度是事前承诺」管的是选关**：回打第 1 关等于想拿进度又躲开难盘。

**怎么落地**：

- 连续练同一门：无衰减；换门另有 `CROSS_QI = 0.92`（省 8% 灵力），是正激励。
- 回关：`advanced` 只在「打的是本门当前关」时为真，所以往回打**一关都不推**；耗气按那一关所在段照收、不减免，不能因为回关就变便宜。
- **没有折减曲线了**。旧版按「本关 ÷ 当前关 × 段基数比」折，退一关掉不到 1%、退到本段第 1 关只剩 1/40——连续量既不直观，又要玩家拿计算器。「0 就是 0」好讲得多，也更难绕。
- 当前关只由「已走通几关」决定（`cleared + 1`）：新手站在第 1 关，压根没有可退的关。回关是玩家的主动选择，不是系统扣他的。

**代价**：想「今天不想动脑，随便练练」的玩家，回关这一局一点进度都不涨。这个代价被接受：回关的目的本来是看盘、找手感、冲本门最佳成绩，不是拿进度；而且回关按早段计价，比打当前关便宜（耗气 7 对 32）。

**守卫**：`tests/rank.test.js` 的关号单调、越权夹回、回关 +0；`npm run sim` 断言「只刷第 1 关也只推 1 关」「退一章再进也只推 1 关」——两处预算与逐关进都是 1000 局，差值恒为 0。

## 五、一局一关，评级不改进度

**原则**：一局只推一关——走通本门当前关就是 `+1`；失败、回关、没做成目标、走完 1000 关，都是 `+0`。**评级不进这个判定**，品阶、境界、属性也不进。

**为什么**：进度只有一个语义——「这门走到第几关」，它是**位置**，不是分数。位置一旦被「打得多漂亮」乘一遍，就等于又开了一条刻度，玩家立刻分不清「我这门算几级」；被品阶乘一遍则会变成「你有多富」。所以这里只留一个布尔：走通了没有。

**代价**：S 与 C 推的是同一关，打得漂亮在进度上没有任何回报。回报被移到两处——结算演出（S/A 走满 1800ms 的五段动画，B/C/F 压到 900ms）与那 30 分钟挂机加成（S ×1.8 / A ×1.5 / B ×1.25 / C ×1.1）。高品阶功法在进度上同样没有优势，只能靠战力与境界门槛体现价值：**天阶练起来一样局数，只是每局更贵。**

**守卫**：`tests/rank.test.js` 断言评级不影响 `cleared`、四品阶同段同评级同值；`scripts/verify.js` 断言 `effectValue` 不进 `applyPractice`。历史欠账：`resMult / MAX_MULTIPLIER` 那一套资源倍率已整条退役，不许再写回来。

**被否决的方案**：① 品阶 / 境界 / 悟性倍率乘进进度——三者叠加后同一个 S 在满配手里是 3 倍以上，门槛必须为满配重标，新玩家永远追不上；② 评级积分制（S 34 点 / C 10 点累加到 99999）——同一件事有了两个数，且「一次 S 抵三次半 C」这种换算没人算得出来，见 `spec/系统设计/04-progress.md` 的「被否决的方案」。

## 六、参悟只耗不产，两条货币线只单向交叉

**原则**：灵力（油）从闭关、份例与灵石兑换来，只往运功去；灵石（钱）从切磋与秘境来，往功法、破境与兑灵力去。**只许灵石买灵力，灵力换不回灵石。**

**为什么**：如果参悟既产灵力又产灵石，参悟就变成「花时间印钱」。灵力会变成过路财（进来就出去，没有储备意义），灵石会变成计件工资（打得多自然多，不需要决策）。两种货币的分工当场糊掉，玩家一直在攒钱却感觉不到钱有分量。

**代价**：想买功法、想破境，就必须去打切磋——哪怕你今天只想练功。想白拿灵力就得等闭关或领份例；不想等，就掏灵石换。**这个「不得不」是设计，不是不便**：它让两种玩法都必须被玩到。

**为什么只开一个方向**：灵石买灵力，省掉的是「等」，代价是攒不下功法，取舍还在；灵力换灵石，换来的就是「挂机时长直接印钱」——气海一满就白坐着，最优解变成挂着不回来，灵石立刻退化成计件工资。两边后果不对称，所以闸只开一边。

**为什么兑换卡在气海上**：钱能买油，买不来更大的油箱。若兑换只看灵石够不够，练真元与破境拓池就能被钱绕过，气海这个上限也就守不住了。

**边界情况**：

- 参悟里的「机缘」（1.2%）只出残卷，不产任何资源。
- 秘境只产灵石，不产灵力。
- 份例只给灵力 60，灵石 0。
- 破境失败退一半灵石；成功不退（花了就是花了）。

**守卫**：`scripts/verify.js` 断言 `data/skills.js` 的 `source.cost` 只收灵石；`data/opponents.js` 奖励只有 `reward.stone`；`tests/game.test.js` 断言参悟回执里没有资源产出字段。

## 七、C 与 F 是两个结论，不是两段分数

**原则**：**C「粗浅」＝这一局走完了但打得糙；F「失败」＝这一局没走完。**

**为什么**：如果把 F 当成「最低一段」，玩家会以为「打崩了也有一点进度」。实际上 F 是整局作废——零进度、挂机加成不给、已经烧掉的灵力不退。这是「失败」这个词该有的分量。

**判据（怎么定谁有 F）**：这门玩法有没有「达成即结束」的事件。

- **有**（阵溃、心神耗尽、时辰到还没通完、还剩对子）→ 时间或命数先到就是 F。十一门：点灯 / 勘禁 / 澄心 / 太虚 / 并蒂连枝引 / 九宫 / 叠元 / 毫厘 / 让路 / 入位 / 辨魁。
- **没有**（一局有自然终点：时辰到 / 手数用尽（三秀，目标未达成不算走通但不判负）/ 拍数打满 / 段数走完）→ 最低只到 C。四门：刀法 / 吐纳 / 灵植 / 土行。

**第三种结局：主动结束**。它不进 `applyPractice`——「不进结算」本身就是作废，不靠清零某个连击计数来兜。三条出路（打完 / 主动结束 / 局中切页）都必须走同一个结账口 `closeAbandonedRound()`，结算卡上报「收」，不报 F，靠页面的 `aborting` 标记区分，**不许让玩法层猜**。

**代价**：十一门有「真会输」的压力，四门没有。这个不对称是刻意的：限时连打类玩法里，「时间到」是那一局的终点，不是失手；给它判 F 等于说「你没打完」，但它本来就没有「打完」这个状态。

**守卫**：`tests/minigames.test.js` 逐门驱动整局并断言结局落在合法集合；`tests/layout.test.js` 断言结束二次确认与「本局作废、灵力不退」文案。

## 八、规则分三层，每层只说一次

**原则**：**准备页一行**（这一局做什么 + 代价）、**局内两行**（tip 讲代价、inline 讲操作）、**整篇在说明页**（按节折叠）。同一句话不许在两处出现。

**为什么**：解谜类玩法最容易犯的错是「怕玩家不懂，于是到处解释」。结果首屏被文字占满，玩家反而不看。信息要在**需要它的那一刻**出现：开局前看目标，局内看代价，想深究了点进说明。

**怎么落地**：

- 准备页：一行 `ruleText`（取 `guides.goal`）+ 难度条 + 折叠的「本门新法」。**不许**铺 `guide.steps / guide.terms`。
- 局内：tip（代价句）与 inline（操作句）各一行，且**不许说同一件事**。
- 说明页：`topic=practice`，由 `help.practiceTopic()` 按功法现拼，六到七节。

**代价**：玩家第一次遇到不懂的机制，必须点进说明页。这个摩擦被接受，因为「点进去展开」本身就是沉浸的一部分（卷轴感），而滚动阅读的说明书会被直接略过。

**守卫**：`tests/layout.test.js` 断言准备页不出现 `guide.steps / guide.terms`、局内两行不说同一句话、代价句用阿拉伯数字、说明入口走 `nav.practiceHelpUrl`；`verify` 断言 `practice` 不许塞进静态 `HELP_TOPICS`（它必须现拼）。

**补充约束**：局中切页 = 本局作废，所以**说明入口只能在开局前**。

## 九、辅助必须有明码代价

**原则**：要么不给提示，要么把代价写在按钮上。不存在「用了提示还宣称 S」的公平。范围不止「提示」——**凡是不改变盘面、只抹掉玩家已经付出的东西的操作，都算辅助**：提示、重排、复位、撤销。

**为什么**：解谜玩法里，提示的价值极高——它直接把「想」变成「做」。如果免费，整门玩法的难度设计立刻失效；如果不给，卡住的玩家只能退出。唯一合理的位置是「给，但要付」。

### 9.1 三类辅助，三种代价形态

辅助分几种，各自的「代价」该落在什么量上。分类的依据不是它叫什么名字，而是它动了你已经付出的哪一样东西。

| 形态 | 例子 | 代价该怎么算 |
| --- | --- | --- |
| **告诉你答案** | 阵眼感应（阵灯）、照纹（灵纹） | 评级封顶，或扣局内资源 |
| **替你重排盘面** | 重排（三秀）、复位本盘 | 三秀不扣手、累计降档权重（手当量，结算扣分）；复位另加评级封顶 |
| **抹掉已付出的计数** | 撤销（推石）、复位（滑块） | 计数不许退，或评级封顶——**至少占一样** |

第三类是这一版补的。前两类一直有代价，第三类原来只在阵灯推演上做了，其余按「走步数 / 推数」评级的门是敞开的。

阵灯推演后来又从「封顶」改成了「折步数」：封顶只切掉最高那一段，而 A（×1.2）比「诚实推演但多走三步」的 B（×1.0）还高——辅助就成了比诚实犯错更划算的选项。判据是**辅助的代价必须落在评级真正评的那个量上**；落不上去的时候，让辅助去动那个量本身（这一门是步数余量）。

### 9.2 已落地的五处

三种代价形态落到具体玩法上，就是下面这些——每一行都是一个已经付了钱的辅助。

| 玩法 | 辅助 | 代价 |
| --- | --- | --- |
| 阵灯推演 | 阵眼感应 | 每看一眼算 2 步，直接吃掉余量（不再是「封顶」） |
| 阵灯推演 | 复原本局 | 本盘最高只判 A，且每局只许一次 |
| 滑块让路 | 复位本盘 | 本盘最高只判 A（步数清零，但清零后的 S 不算） |
| 推石入位 | 撤销一步 | 只退位置，**推数照算**（这一推已经发生） |
| 推石入位 | 复位本盘 | 推数清零，但本盘最高只判 A |
| 并蒂连枝引（灵纹连线） | 照纹 | 少 2 息；大成起 1 息（仍要付），大圆满一次照见两对仍是 1 息。死局自移前三段不扣息、只断连收；大成起按段给次数（2 次，每次 1 息；圆满每次 2 息），用尽后翻倍、**不判负** |
| 三秀撷英诀（三连互换） | 照畦 / 挪苗 / 重排 | 不扣手，累计降档权重（手当量，每手当量 `perMove × 2.5` 扣分）；阶段新法只把权重打薄（照畦大成起 −1、重排大圆满 −1），仍要付 |

### 9.3 为什么「复位」必须有代价，而「撤销」可以只退位置

这两者的漏洞不一样，堵法也不一样：

- **复位的漏洞是「重置计数」**。盘面是固定的（滑块让路 4×4 六块、推石入位复位回本局开局那一张），复位把计数清零又回到同一个开局——不封顶的话，「走一步 → 复位 → 再走」可以把最优解白试出来，S 就变成「肯反复重来」的奖励，而不是「一步没浪费」。所以复位必须封顶。
- **撤销的漏洞是「退还计数」**。推石入位的 `undo` 原来把 `pushes` 一起回退，等于推错了不用付账。堵法是**只退位置、不退推数**：人回到上一步站的地方，但这一推已经算进账里。这样撤销仍是逃生通道（不会卡死），但用它是要付钱的。

**被否决的方案**：给撤销也加评级封顶。否决理由——撤销在推箱子里是高频操作（走错一格就要用），一封顶等于把整局的 S 都封掉了，「随手撤一下」和「整盘重来」被压成同一件事，代价失去区分度。而「推数照算」既保留了 S 的可能性（只要还原后不再多推），也让每次撤销都真实付账。

### 9.4 代价本身也是可设计的

阶段新法可以「让代价变便宜」，但不能「让代价消失」——这两者在玩家感受上是「练到后面更划算」与「这条规则作废了」的区别。

**守卫**：`tests/minigames.test.js` 的「按最优步数评级的三门：反悔过就本盘封顶 A」逐门跑两遍（干净局必得 S、先复位必降 A）、「推石入位：撤销只退位置，不退推数」、「两门的评级说明都写清『反悔封顶』」；`tests/rank.test.js` 与 `data/practice.js` 的 `STAGE_RULES` 守着「仍要付」的文案。

## 十、盘面不写汉字，靠形状 / 颜色 / 图案

**原则**：方向用箭头，状态用形状与颜色，身份用图案。汉字只出现在 HUD、按钮与说明里。

**为什么**：盘面上出现汉字，等于把「游戏」变成「表格」。而且汉字在小格子里会挤成一团（4.7 寸屏上 6×6 的格子约 50px）。更实际的一条：**emoji 化陷阱**——`✦ ✿ ◆` 这类字形在部分安卓会被替换成彩色 emoji，同一盘面在两台手机上长得不一样。

**三支图案**：

1. `crest` —— 26 格灵纹牌纹（果器 8 格 + 甜点 / 海洋 / 灵兽 各 6 格，四套主题共用一副六族骨架；连线、消消乐）。配对类按**剪影族**取纹，不按 sprite 序号取前 N——前 N 格碰巧同族，一盘就成了一盘水果；
2. `emblem` —— 26 格卦象 / 器物纹（其余原本写汉字或用 dingbat 的玩法）；
3. 数字 / 形状盘 —— 保留数字，统一补四角纸纹 + 一次性命中金圈。

**代价**：图案的辨识度不如文字直接，需要真机验证（尤其同心圆类的 12 阵眼环 / 14 八角阵位、只差一条爻的八卦 3 震 / 7 艮）。

**守卫**：`tests/layout.test.js` 的运行时探针逐门扫开局那一帧，断言汉字 `label` 必须有 `emblem` 盖住；`verify` 断言 sprite 单份 base64、26 格齐、打包排除。

**例外**：五行图案按 `ELEMENT_EMBLEM = [23,25,26,22,24]` 映射——元素次序与 sprite 次序不同，不许写 `22 + i`。

## 十一、阶段新法要加规则，不是减难度

**原则**：练到某一段之后，这一门的**规则**会变——变复杂、变有趣，而不是「变得更容易」。

**为什么**：如果阶段新法只是「少扣几息」「多给点分」，那它就不是新法，是数值补丁。玩家练到圆满，感受应该是「这门功课的另一面打开了」，而不是「终于能躺着了」。

**代价**：改规则的阶段新法可能让已经习惯的人不适应（澄心默诵诀大成后奇轮要倒着点）。所以：**改规则的那几条必须能在准备页就地关掉**（`hard: true` 标记），纯加成的不给开关——多一个开关只是多一处看不懂。

**两条道，不是一条。** 已经落地的九门分得清清楚楚：哪几门改的是规则、哪几门只是让你看得更清，以及谁需要准备页开关。

| 类 | 门 | 给的是什么 | 准备页开关 |
| --- | --- | --- | --- |
| 改规则（带 `hard: true`） | 开锋破军诀（收势 / 禁桩 / 双锋）、澄心默诵诀（逆诵 / 叠印）、星罗烛天诀（死门 / 双门） | 规则真的变了：多一处禁桩、奇轮要倒着点、同时亮两道刀路 | 给 |
| 看得更清（不带 `hard`） | 洞微勘禁诀（勘位 / 洞玄）、并蒂连枝引（照纹 / 双照）、万石成岳诀（稳基 / 层叠）、三秀撷英诀（照畦 / 连收）、九宫补缺诀（密勘 / 唯余）、移石归阵诀（死位 / 临渊）、太虚照见诀（留影 / 记印） | 判定一个字没动，只是把「本来推得出来、但要花眼力与几次试错」的事摆到明处 | 不给 |

**为什么后一类也不违背这一条**：这七门的盘面都照抄行规（经典玩法「看一眼就会玩」才配叫简单）——其中六门是黄阶入门功课，
太虚照见诀虽是天阶心法主修，玩法内核仍是经典的翻牌配对，按同一条口径走。
往里塞新规则等于把这份「一眼就会玩」砸掉。它们能给的只有「看得更清」——而看得清不需要开关，
因为它没有作废任何规则；不给开关，也就不多一处看不懂。

**边界只有一条：这条便利有没有替玩家省下一次「已经数得清的次数」。**

- 省次数（多一次撤销、多一次照见、提示少扣一息）→ **必须定价，且不能把价定成零**。三秀撷英诀的「照畦大成起少 1 手当量，但仍要付」就是这条的样板：它不花手数，却照实扣分、把评级往下压。
- 只改显示（暗纹、描红、压暗、描圈）→ **不收费**。收在「想看清楚要交钱」上，与「阶段新法」四个字正好相反。

余下五门（吐纳周天 / 同源归一 / 遍观毫厘 / 移星换斗 / 择大辨微）暂时一条都没有，
（截锋断岳 / 叠纹凝露 / 踏云连环 / 五灯相生 四门 2026-11 已退役，不再计入。）
欠账与补法记在 `spec/数值平衡/05-axis-review.md` 第十节。

**守卫**：`tests/layout.test.js` 断言 `hard` 类才有开关、开关只在准备页、折叠态带一行速记。

## 十二、首屏只留标签 + 数值 + 按钮

**原则**：主页面第一屏不出现眉标、说明句、hints、页脚口号、大段公式。所有解释的入口是右上角一个「说明」。

**为什么**：玩家打开小程序的第一秒，问的是「我现在该点什么」，不是「这个系统怎么运作」。首屏每多一行字，主按钮就往下挤一行——在 4.7 寸屏上，这一行可能就是「要不要滚动才能开始」的差别。

**怎么落地**：

- 主页：境界卡（战力 / 境界 / 灵力 `160 / 174`）+ 六宫格 + 一行提示 + 吸底「参悟」。
- 参悟准备页：印 + 修为 + 一行规则 + 难度条 + 折叠的「本门新法」。
- 功法页：两分区（已持 / 藏经阁）+ 速览条 + 三行卡片。
- 人物页：身份卡 + 属性格 + 突破清单。

**代价**：设计意图必须靠「点进去」才被看到，因此**说明页与折叠区的质量直接决定体验上限**。这也是 `data/help.js`（7 个主题）与 `data/copy.js`（术语词典）投入很大的原因。

**守卫**：`tests/layout.test.js` 的「解释不许回 tab 页首屏」黑名单（页头副标题、页脚口号、hints、公式字样）。

## 十三、变化方向：一门 1000 关至少五类方向，段界同时开两条

**原则**：一门功法在 1 → 1000 的跨度里，玩家能说清的独立变化不得少于 **5 类**（其中至少 **3 类内容轴**）；每个段界必须同时开 **≥2 类方向、且 ≥1 类内容轴**。只把格子变大、时间变短、毫秒变少，不算换了东西。

**为什么**：第 1 关和第 1000 关摆在一起，玩家应该能一口气说出好几条不同——「盘形变了、多了一种牌、多了一种障碍、目标不再是攒分、开局还要二选一」。如果只有「大一点、紧一点」，那不叫 1000 关，叫一张表拉长。判定一律用一句话问：**这两关闭着眼睛能不能听出区别？** 听不出，中间那些关就只是刻度。

**九类模板（跨门通用，不按玩法私有命名）**：

| 类 | 回答的问题 | 在本作里的样子 |
| --- | --- | --- |
| 盘面几何 | 盘长什么样 | 行列、空位、墙、箱、雷、轨段 |
| 元素种类 | 盘上有什么 | 花色 / 纹种、主题、诱饵 |
| 玩法结构 | 那一手怎么算 | 折数、单 / 双手、谱型、连锁评级 |
| 地形障碍 | 哪些格子不好用 | 石皮（后续：薄冰 / 锁链 / 毒藤 / 多层叠加） |
| 目标类型 | 这一局要达成什么 | 攒分 / 收集 / 限步 / 指定连锁 |
| 信息可见度 | 玩家能看见多少 | 照纹、预演、迷雾、闪现毫秒 |
| 代价节奏 | 这一局有多紧 | 时辰、生命、步数、手数预算、罚息 / 降档手当量、每对预算 |
| 本局变数 | 开局抽到什么环境 | 二选一劫变（一紧一松配对，随机变成决策） |
| 主动手段 | 玩家手上多出什么 | 自移、照纹、重排、撤销 |

**内容轴与支撑轴**：盘面几何 / 元素种类 / 玩法结构 / 地形障碍 / 目标类型 / 本局变数 / 主动手段这七类是**内容轴**——它们改变「这一关在玩什么」。信息可见度与代价节奏是**支撑轴**：它们让已有方向更清楚或更紧，单独变化不算「玩法变了」。所以「闪现从 180ms 缩到 170ms」「时辰从 62 息缩到 60 息」既不入内容轴计数，也不该在准备页冒充「本关新变化」；真要报，就报它服务的是哪条内容轴。

**口径唯一**：`data/practice.js` 的 `AXIS_LABELS` / `AXIS_OF` / `AXIS_CONTENT` / `AXIS_KEY_OF` 是唯一真源。`levelDelta` 的每一个 key 都必须登记到九类之一；`chapter` / `start` / `final` / `sLine` 显式登记为 `_meta`（换段、首末关总结、评级线口径），不计方向。新增玩法参数时先在这里归类，再谈上报文案——反过来做就会出现「生成了没人读」和「读了没归类」两种假绿。

**怎么落地**：逐门方向账登记在 `docs/specs/spec/数值平衡/05-axis-review.md` §13，一行一门，九列打勾，与代码现算值逐格比对。段界那一关按「同时开了哪几条」单独计，不许用「整门累计出现过」冒充段界变化。

**代价**：按这个门槛，当前十五门里只有三秀撷英诀（三连互换）九类全开、7 内容轴、段界一次 5 条，其余十四门是欠账（逐门账见 `spec/数值平衡/05-axis-review.md` §13，欠账见 `08-待拍板清单.md` D17）。规矩先立，欠账逐门补——**不许因为现在不达标就把门槛降下来**；反过来也不许拿「九类全开」当目标硬铺，一门没有目标类型就说不出目标类型，那是编规则不是改玩法。

**守卫**：`scripts/verify.js` 8b-6a-4 逐门复算方向账，与 §13 登记表逐格比对；有 key 未归类、登记与代码不符、文档门槛数字被改，当场红。`npm run audit:gap` 量的是**段内冻结**（同一段里逐关有没有真变），§13 量的是**跨门方向数**（这一门有没有在玩新东西），两件事不能互相替代。

## 附：三条贯穿性的硬约束

这三条不属于「原则」，属于**底线**——违反就是 bug，不是取舍。

1. **昼夜两套皮肤，颜色绑系统，色值只有一份**。白天宣纸彩墨（纸 `#f2e9d6` / 白纸 `#fffcf2` / 墨褐 `#33291f`），夜里墨玉夜（深青墨 `#08131c` / `#0f2030` / 玉白 `#e3f1f8`），默认跟随系统、也可在道牒里手选（`utils/theme.js` 解析档位，页面根节点挂 `pg--t-night`，原生栏逐页重设）。五支颜料色各绑一个系统（朱砂 = 主操作、石青 = 灵力、石绿 = 进度、藤黄 = 灵石、绛紫 = 稀有），同一屏同一含义只出现一次颜色。页面挂 `.pg--imm`，颜色全取 `var(--*)`，页面 wxss 不写裸色值；夜里的原色只写在 `--night-*` 一处，夜块与舞台都只做 `var()` 引用。盘面是唯一例外（「墨玉台、暖玉牌、其余是墨」：台取功法族的 `--well`，牌取 15 门共用的 `--jade`），舞台恒深、不跟着翻。
2. **玩家文案只有一个真源**。`data/copy.js` 管状态 / 按钮 / 区块标题 / 术语；`data/help.js` 管解释长文；`data/guides.js` 管玩法规则。WXML 里不许抄字面量。
3. **每个页面目录必须注册进 `app.json.pages`**。漏注册时 `wx.navigateTo` 静默失败——页面文件齐全、旧断言全绿也拦不住。`verify` 双向核对。
