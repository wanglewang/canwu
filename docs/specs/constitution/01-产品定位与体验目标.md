# 宪法（Constitution）· 产品定位与体验目标

> 一句话：**一个用「修行」包装的养成 + 小游戏微信小程序——你把灵力烧在一局一局的参悟里，换熟练度、换战力、换境界，顺手和人切磋。**

## 核心前提：把它想象成一个具体的早晨

早上八点，地铁刚过两站。你打开小程序，没看任何说明——首屏只有一张境界卡、六个功法格子、一句「去练哪门」和一个大按钮。你点了「星罗烛天诀」，扣掉 6 点灵力，四十秒把阵灯逐一点亮，拿到一个 A，熟练度涨了。三分钟后你关掉它去上班，没有任何「今天还没签到」的提醒在等你。

**这就是我想做的东西**：一趟随时能上、随时能下的修行。它必须小到能塞进两站地铁，又密到让你明天还想打开。技术上我选原生微信小程序——不是因为时髦，是因为这个场景要求「点开即玩、关掉即走」，H5 和 Unity 都太重。

这一点很重要，因为后面每一条设计——首屏不放说明书、一局 30–90 秒、不惩罚离开——都是从这一个早晨推出来的，不是从「修仙游戏应该有什么功能」推出来的。

## 1. 它是什么

| 维度 | 取值 |
| --- | --- |
| 载体 | 原生微信小程序（非 H5、非 Unity） |
| 题材 | 修仙 · 青云界（单世界生效） |
| 核心动词 | **参悟**（打一局小游戏）、**闭关**（养灵力）、**切磋**（换灵石）、**破境**（抬上限） |
| 单局时长 | 30–90 秒（多数玩法 13–68 秒限时） |
| 单次会话 | 3–10 分钟（约 2–6 局 + 一次收菜） |
| 长线目标 | 把 15 门功法练到 99999 熟练度；境界推到元婴；15 门全收 |
| 商业化 | 无。没有内购、广告、体力售卖 |

**它不是「小游戏合集」。** 我刻意不做成 15 个独立小游戏拼在一个壳里——每一局都扣同一池灵力、产出同一种熟练度、喂同一套境界与战力。15 门玩法是同一套养成的输入端，玩家以为自己在挑游戏，其实一直在练同一门功课。

## 2. 目标玩家

**主画像：** 喜欢轻度策略与解谜、能接受「一天来两三次、每次几分钟」的碎片节奏，对修仙叙事有好感但不要求硬核文本量的玩家。

**适配的场景：** 通勤、睡前、等餐；有耐心看盘面、不追求手速极限。

**不适配的场景：** 想在地铁上打 15 分钟不间断操作的；想靠操作技巧压过数值的；期待实时对战的。

这张画像不是装饰，它直接定死了三件事：

1. **盘面必须「看一眼就会玩」**。十五门里九门是经典盘面（连线、落石、消消乐、九宫、合数、顺序点、滑块、推箱、取大），规则一句话；其余六门也都能在十秒内看懂目标。规则复杂 ≠ 深度，深度应该来自「省步数」「不断连」这类可重复挑战。
2. **不能靠手速卡人**。限时是有的，但最短一段（绝境 13 秒的顺光扫斩）也是「够看清再动手」的量级；难度靠收紧判定窗与抬高评级线，不靠让人来不及反应。
3. **随时能走**。任何一局都能主动结束，不弹「确定放弃奖励吗」的挽留；闭关是「回来收」而不是「放着涨」，因为玩家不需要为了效率把小程序挂在后台。

## 3. 三层核心循环

我把这个游戏想成三个套在一起的钟。一局是一秒、一个段位是一分钟、一天是一小时——它们咬合，但各有各的节奏。

```
   ┌─ 微循环：一局 30–90 秒 ────────────────────────┐
   │ 选门 → 当前关开局 → 扣灵力 → 打一局 → S/A/B/C/F │
   └──────────────────┬────────────────────────────┘
                      │ 熟练度累积
   ┌─ 中循环：10–30 分钟 / 一个段位 ─────────────────▼┐
   │ 跨阈值 300/1500/6000/24000 → 段位加成 + 阶段新法 │
   │ 走通本段全部关 → 站上下一段                      │
   └──────────────────┬────────────────────────────┘
                      │ 战力 / 感悟
   ┌─ 宏循环：天 / 周 ──────────────────────────────▼┐
   │ 闭关养气 → 参悟烧气 → 熟练度抬战力 → 切磋赢石     │
   │   → 买功法 / 布阵破境 → 境界抬上限 → 一趟练更多   │
   └──────────────────────────────────────────────┘
```

一局只回答一个问题：**这一局我打得怎么样。** 局内 HUD 只报「下一条线还差多少」，四条线全貌在说明页——一屏塞四条会挤掉第一局真正要读的东西。

中循环的关键设计：**升段不是「同一件事变难」，而是「这件事本身变了」**。澄心默诵诀小成后可以「抢记」（长按少看几个字，赌记忆换倍率），大成后奇轮要倒着点；星罗烛天诀大成后盘上多一格不能碰的死门。`data/practice.js` 的 `STAGE_RULES` 是这份规则的登记处。

走通本段全部关才站上下一段——五段各 10 / 40 / 150 / 300 / 500 关；**难度线另算，与熟练度无关**（展开见 `spec/系统设计/07-difficulty.md`）。这一分家是刻意的：熟练度是「练了多少」，关号是「走到哪」，两把尺子互不兑换。

宏循环里有一个**咬合点**，也是整个游戏唯一真正的资源决策：

```
   时间 ──┬──→ 灵力（0.5/分，装进气海）──┬──→ 参悟 ──→ 熟练度 ──→ 战力 ──┐
          │                              └──→ 切磋 ──→ 灵石 ──┐         │
          └── 两种用途抢同一池灵力                              │         │
                                          灵石 → 买功法/破境 → 境界 ─────┘
                                          （抬上限 → 一趟练更多局 → 回到闭关）
```

灵力和灵石都从「时间」来，但去向不交叉。参悟只烧灵力、不产任何资源；灵石只能从切磋与秘境挣。所以玩家的时间永远在两种用途之间做选择：**练功（消耗灵力换熟练度）还是挣盘缠（消耗灵力换灵石）**。

> **这是第三层默认值，不是硬约束**（判定见 §5）。松绑它——比如让参悟也产一点灵石——会让这里写的「唯一资源决策」不再成立，并且牵动守恒 3「灵石收入 < 需求」与重复切磋循环，必须连带重算。当时选它，是为了让「练功还是挣盘缠」成为每天都存在的取舍；若有了更能加厚修仙感的去处，可以改。

## 4. 体验目标

按优先级排序，冲突时上位压倒下位。这张表是我在做每一个具体界面时的裁判——两个方案吵起来，就看谁更符合上面那一条。

| 优先级 | 目标 | 具体含义 | 反例（明确不要） |
| --- | --- | --- | --- |
| 1 | **一眼看懂现在该做什么** | 主页首屏只有「境界卡 + 六宫格 + 一行提示 + 一个主按钮」，提示永远是「去练哪门」这一句 | 首屏出现眉标、说明句、页脚口号、公式 |
| 2 | **国风沉浸，不像小程序** | 昼夜两套皮肤，默认跟随系统、也可手选白天 / 夜晚（白天宣纸彩墨 / 夜里墨玉夜）；颜色绑系统而不是当装饰；名词用修仙设定（功法、境界、灵力），句子用现代白话（「换一门」「退出」） | 出现「小游戏」「资源」「通关」等产品词；或写成「另择一门」「暂且退去」这类仿古句 |
| 3 | **每一局的钱都花得明白** | 开局前就在按钮上写清耗多少灵力、余多少；结算写明扣了多少、不退 | 打完才告诉玩家「其实你没钱」 |
| 4 | **努力有可见回报** | 特效按段位兑现（入门 25% → 圆满 100%），每升一段面板上都有变化 | 「练到大成才有特效」——中前期等于白练 |
| 5 | **不惩罚离开** | 无日常任务链、无连续登录奖励、无「体力不足请明天再来」；闭关回来后一键收 | 用 FOMO 制造回访 |
| 6 | **解释放在点进去之后** | 首屏只留标签 + 数值 + 按钮；长解释在右上角「说明」按节折叠 | 一屏铺满规则 |

第 1 条画出来就是这个样子——首屏是一块「读数板」，不是一页宣传单：

```text
┌─────────────────────────┐
│  炼气 · 境界  ▓▓▓░░ 62%  │  ← 境界卡：只报状态
├──────────┬──────────────┤
│ 星罗烛天 │ 澄心默诵      │  ← 六宫格：选「练哪门」
│ 洞微勘禁 │ 太虚照见      │
│ 并蒂连枝 │ 万石成岳      │
├─────────────────────────┤
│ 去练星罗烛天诀 · 耗 6 灵力 │  ← 一行提示 + 一个按钮
│      [ 入  参 悟 ]        │
└─────────────────────────┘
```

> 第 5 条属于第三层默认值（判定见 §5），不是不可动的身份约束；松绑方向是「今日机缘」这类修仙事件，不是通用签到领奖，且要连带重看灵力恢复节奏。

第 2 条是本项目最容易被破坏的一条。判据有两句：**「今天有人这么说吗」**与**「这个词会不会让玩家意识到自己在用一个小程序」**。「这一局」可以留（棋局），「这一门」必须改（口语省略），「小游戏」必须改成「盘面」。注意别从「太像小程序」滑到另一头：**本作是现代背景的修仙，不是古代修仙**，按钮上不许出现「暂且退去」「容再思量」。详见 `04-文案口吻规范.md` §一。

## 5. 约束分层：哪层真不能动，哪层只是默认值

> 这一节回答一个反复踩的问题：**「文档写了不做」算不算硬约束？** 不算。文档记的是当时选的一条路，不是物理定律。约束分三层，判断权在「改它能不能同时加厚修仙感与让人进来」，不在「文档写没写过」。

| 层 | 是什么 | 本作里的具体内容 | 改动前要问什么 |
| --- | --- | --- | --- |
| **一 · 定义** | 换掉它就不是这个游戏 | 修仙题材；**功法即小游戏**（一门一套互不复用的玩法内核，门数 = 玩法数） | 「换掉之后还是修仙 + 功法吗？」不是，就别动 |
| **二 · 一致性** | 不是口味问题，动了会塌 | 三条守恒（`spec/系统设计/03-economy-flow.md` §6）；平台与资质现实（原生微信小程序、无版号无支付资质——是外部现实，不是口味）；评级线由各 `minigames/*.js` 的 `lines()` 实测标定 | 「改完 `npm run sim` / `npm run check` 还绿不绿？」要连带重算就不算默认值 |
| **三 · 默认值** | 当时记下的一条路，不是唯一的路 | 下面 §5.2 的整张「不做」清单；体验目标第 5 条「不惩罚离开」（§4）；宏循环的「参悟不产资源」咬合点（§3） | 「改它能同时加厚修仙感与让人进来吗？」能就改，再回头查第二层有没有被牵动 |

**第一、二层才是硬约束**，第三层是产品判断。§6 成功判据里的「每条硬约束有守卫」说的是前两层——校验脚本钉的是数值守恒和真源一致，不是在钉产品选择。

**怎么分二、三层**：看你要「加内容」还是要「换守恒」。加一条成长线、加一个回访事件、换一句分享文案，都只是加内容；让参悟也产灵石、让灵石收入超过需求、把评级线改成拍脑袋的数，是在换守恒——后者必须连带重算。默认值不是硬约束，但松绑时要把被牵动的守恒一起动。

**先例**：§5.2 表里「浅色主题」已经翻过一次案——前提消解后就地标注，理由留着，结论改掉。这一节就是给后来的翻案留位置，不是给「不做」二字盖章。

### 5.1 默认值松绑时要连带重算什么

| 默认值 | 松绑方向 | 必须连带处理的第二层 |
| --- | --- | --- |
| 参悟不产资源（§3 咬合点） | 让参悟也产灵石，每局有即时回报 | 守恒 3「灵石收入 < 需求」当场失效，重复切磋循环失去理由；收入/需求表与破境价目全部重算 |
| 不惩罚离开（§4 第 5 条） | 加轻量回访事件 / 机缘 | 闭关 0.5/分、炼气 5.8 小时坐满的节奏要重看，别让「怕漏」压过「想练」 |
| 首次必出稀有、前两次特效放大 | 只对不进数值系统的产物用（道相、称号、外观） | 一旦产物进评级或经济，各门 `lines()` 的实测线全部作废重标 |

### 5.2 明确不做（默认值清单，按需可调整）

> 下表整体属于第三层，**可以按需调整**。每行保留当时的理由与诱因，不抹历史；要翻案就照「浅色主题」那样就地标注，别删旧行。
>
> 唯一例外是「付费 / 内购 / 广告」：**没资质**是第二层的外部现实（现在做不了），**要不要真的做**是第三层判断（资质若解开，仍要重新决定）。表里把两层写在一行，是因为当时把它们一起否决了；翻案时只翻产品判断那一半，别把外部现实也划掉。

| 不做 | 原因 | 曾经想做的诱因 |
| --- | --- | --- |
| 实时 PVP | 小程序端做同步对战要长连接 + 房间服务，成本远超收益；现方案是「上传战力 + 镜像对战」（`data/opponents.js` 的 7 位预设 + 战力码） | 「切磋」听起来该是真人对打 |
| 付费 / 内购 / 广告 | 未发布、无版号、无支付资质；且一旦有内购，「灵力上限」这类设计会立刻变成付费点，整套节奏会被污染 | 挂机游戏通常靠加速道具变现 |
| 多世界 | 科幻 / 都市两套只有元数据；每套要 15 门功法 + 15 套玩法，是重做而不是扩展 | 世界观切换听起来很有想象力 |
| 微信头像 | `chooseAvatar` + 云存储 + 签名 URL + 内容安全检测 + downloadFile 域名，五份成本换一个小圆头像；形象已由 `components/portrait` 的 CSS 道相承担（6 个编号） | 社交产品默认都要头像 |
| ~~浅色主题~~ **（已翻案）** | 原理由两条：①「两套主题会让每次改样式都翻倍」；②「盘面「纸」的对比关系会被打破」。**②仍然成立**（舞台恒深、牌必须比台亮六七倍），所以盘面不跟着翻；**①已不成立**——夜皮肤不是另做一套设计，而是同一套色相的提亮，色值只有一份 `--night-*`，页面样式一行不改。「翻倍」实际只是多一份原色板。现改为两套皮肤 + 三档设置（跟随系统 / 白天 / 夜晚，默认跟随系统；见 `spec/界面设计/01-visual-language.md` 第 3 节） | 系统深色模式该被尊重 |
| 无代价的辅助 | 用了提示还宣称 S 不公平。要么不给，要么把代价写在按钮上，而且代价要落在评级评的那个量上（星罗烛天诀「阵眼感应」每看一眼算 2 步） | 新手需要帮助 |
| 首屏说明书 | 与第 6 条体验目标直接冲突 | 「规则这么复杂，不解释玩家怎么懂」 |
| 攻略式长文 | 解释性内容一律进 `data/help.js` 的折叠节与 `pages/guide/`，不进主页面 | 设计者总想解释自己的设计 |

## 6. 成功判据

不写「留存 40%」这类拿不到的数。以下是**在仓库内可验证**的判据——我要的不是「我觉得会成功」，是「任何人 clone 下来跑一遍就能复核」：

| 判据 | 门槛 | 验证方式 |
| --- | --- | --- |
| 一门功法从开局到入门 | 固定走通 10 关，即 10 局（一局推一关；段位只看关数，与熟练度无关） | `tests/rank.test.js` 的 `[10,1,'入门']` 断言 |
| 从零到 99999 的极端路径 | 全 C 10000 局 / 全程不断 S、每局打当前能打的最高关 84 局（不回头刷低关） | `npm run sim` 两条曲线 |
| 一局的实际代价 | 6–27 点灵力（吐纳五段实价） | `simulate.js` 耗气表 |
| 灵力自给能力 | 炼气气海 174 点 ≈ 小成段 12 局；气海 5.8 小时坐满 | `game.qiCap` + `idle.qiPerMinute` |
| 首屏字数 | 主页面首屏不出现说明句（黑名单断言） | `tests/layout.test.js` |
| 十五门玩法不重复 | 玩法内核、盘面、交互、胜负规则四者至少三项不同 | `tests/minigames.test.js` |
| 每条硬约束有守卫 | 1360 项静态 + 316 项 Node 断言 | `npm run check` |
