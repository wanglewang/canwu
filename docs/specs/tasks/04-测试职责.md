# 任务（Tasks）· 五个测试文件的职责边界

> 五个文件、363 个用例、没有测试框架。用 `assert` + 自己的 `check()`，因为小程序项目不想引构建链。

## 核心前提：把「设计规范」也写成会红的断言

我为什么愿意为这么小一个项目写五个测试文件？因为这个游戏有一条很硬的约束——**「一门功法一套互不复用的玩法内核」**，还有一堆页面规范（盘面不写汉字、提示只有一句、页面名等于入口名）。这些如果只写在文档里，迟早会被改代码的人无意破坏。

所以我把它们变成断言。「互不重复」「互不撞词」「各用各的」是那条硬约束的机器版本；`rank.test.js` 守五段真的分得开；`layout.test.js` 甚至起一局真盘去扫开局那一帧有没有汉字上屏。静态读代码看不出运行时填了什么——只有运行时探针能守住这条。

我没引测试框架，因为小程序项目不想为了测试背一条构建链。三行的 `check()` 就够，跑起来就是 `node tests/game.test.js`，失败输出就是那条 `assert` 的原始信息。少一层包装，少一层藏污纳垢的地方。

## 1. 概述

| 文件 | 用例 | 一句话职责 |
| --- | --- | --- |
| `game.test.js` | 48 | 引擎的**每个数都对**（一局一关是承重墙） |

| `layout.test.js` | 108 | 页面与样式的**规范没走样** |

## 2. 为什么没有框架

```js
function check(name, fn) {
  try { fn(); passed += 1; }
  catch (e) { console.error('✗ ' + name); throw e; }
}
```

三行就够，并且：

- 零依赖（`package.json` 的 devDependencies 只有 eslint）；
- `node tests/game.test.js` 直接跑，不需要 watch / config；
- 失败输出就是那一条 `assert` 的原始信息，没有框架的包装层。

`tests/run.js` 用 `spawnSync` **顺序跑五个独立进程**——一个崩了不影响另外四个的结论。

## 3. `game.test.js` —— 引擎的每个数

48 个用例分七组：

### 3.1 存档与迁移（7）

```
新档是 v10：带纪录与双货币身家，没有熟练度也没有连 S 层数
一次性礼包：发一次记账，重读不重发，读档本身不发
v1 存档可迁移到 v10
v2 存档迁移后补出空纪录表、不补回已删字段
无 version 的老存档也能兜底
存档码导出导入往返一致
非法存档码被拒绝
```

**「没有熟练度也没有连 S 层数」是一条防回归用例**：这条线整条删过，这两个字段也整条摘掉，
断言挡着它们被顺手加回来——并行进度线一旦复活，玩家又会分不清「我这门算几级」。

### 3.2 离线与打坐（6）

8 小时上限、时钟回拨、存档不许推进闭关起点、满池打坐不静默、打坐不产灵石、气海溢出如实报。

**「时钟倒退时不结算离线收益也不写入回拨值」**是防作弊与防自伤的双重断言：倒退不该给收益，但也不该把时间写坏。

**「正常离线 1 小时只结算灵力，不推进度」**守着「挂机不能替你练功」：
闭关只产灵力，一关都不推。这条一旦松，最优解立刻变成挂着不回。

### 3.3 迁移与进度（10）

这是全项目最细的一组——它是整条成长线的承重墙：

```
v5 存档升到 v10：旧 prof 摘掉，进度按旧规则折成 cleared
存档码往返带回 cleared，旧 prof / sCombo 不会复活
一局只推一关：S 与 C 都只 +1，评级不再换进度
失败、回关、目标没达成都不推进度
走通段界关当场晋段：走通第 50 关就是小成
六档门槛逐档等于段界关，段名与属性系数固定
走完 1000 关即大圆满：进度封顶，灵力照扣
一门 1000 关就是 1000 局：评级再高也缩短不了这条路
中途结束在内核里没有入口：作废靠「不进 applyPractice」保证
getSkillList 报出段位、段位色与已走通关数
```

「一局只推一关」与「一门 1000 关就是 1000 局」是**同一件事的两个角度**：
前者守判定，后者守总量。谁把评级、品阶或连击接回推进，这两条会同时红。

「六档门槛逐档等于段界关」直接对着 `data/levels.js` 的 `STAGE_GATES` 算，不写死数字——
段界关一改，这条跟着改，是它和 `verify` 8b-2 一起保证「两把尺子不会漂」。

### 3.4 推荐与连练（3）

同一门连练不减收益、旧存档的连练计数字段被丢弃、功法页排序与主页推荐同源。

### 3.5 境界与引导（3）

金丹期练得了黄阶（门槛管能不能开练，上限只管这一局多费气）、首局引导标记与技能同级存、
引导按段记（一门五格各记各的，老档的 `onboarded` 只等价第 0 段）。

### 3.6 气海、突破与特效（5）

炼气 174 起、破境补满、真元拓深、溢出如实报、特效按段位兑现（入门 25% / 圆满满额 / 未入门不给）。

### 3.7 份例、兑换与道牒（9）

份例按空位领并如实报散去多少、满池拒领且说明是满池不是次数不够、灵石兑灵力只此一向、
换不成时一个子儿不扣、兑换报价与执行同源、今日机缘、晋段日志、四属性四出口、道牒数据同源。

**「兑换面板的报价与真正执行同源」**是全项目反复吃亏的一类：
写着能换就一定换得成，反过来也一样——两处各算一遍，早晚一漂。

## 4. `store.test.js` —— 存档状态机

用**内存 wx 存储 + 可编排的假云端适配器**，不触网。

```js
global.wx = {
  getStorageSync: k => mem[k] ?? '',
  setStorageSync: (k, v) => { mem[k] = v; },
  removeStorageSync: k => { delete mem[k]; },
};
```

14 个用例走完整个状态机：

```
commit 会留下待同步标记
云端确认成功后清除待同步标记
写失败时保留标记并把错误暴露给页面
版本冲突被标记为冲突而不是静默覆盖
断网补写失败时 hydrate 保留本机进度并返回 offline
云端存档存在时 hydrate 用云端覆盖本地
云端无档时 hydrate 立刻建档
未登录时 hydrate 返回 signed-out 且不写云端
冲突时可用本机强制覆盖并清除标记
冷启动：闭关灵力在 hydrate 之后才结算，不会被云端档吃掉
登出清空本机缓存、标记与错误
commitCritical 不等待防抖窗口
```

**为什么这一组必须独立成文件**：它是唯一需要「假 wx 全局」的测试。别的测试都用真 `data` / `utils`，只有这里要模拟存储与网络。

**「版本冲突被标记为冲突而不是静默覆盖」是最重要的一条**：静默覆盖等于丢档，而且是玩家发现不了的丢档。

**「冷启动：闭关灵力在 hydrate 之后才结算」是真机上抓回来的**：玩家挂机三小时，弹窗报「灵力 +90」，关掉弹窗还是 0，下次进来又报 +90。根因在 `init()` 的结算时点与 `game.save()` 顺手推进 `lastSeen` 两处（见 `docs/specs/tasks/07-已修归档.md` A6）。这条断言按真实顺序跑 init → hydrate → settle，并守「同一段闭关不许结算两次」。

## 5. `minigames.test.js` —— 20 套玩法能走完

135 个用例，两大类。

### 5.1 注册与契约（10）

```
15 套常规玩法 + 突破专用玩法全部注册
15 门功法对应 15 套互不重复的玩法
同类功法（刀法/阵法/心法/神识）也各用各的玩法
每门玩法都给出本段 S/A/B/C 四条线，说明页与局内同源
玩法中文名与模块导出一致，功法表与注册表不漂移
参悟方式、玩法名、本门玄机三层互不撞词
15 套玩法覆盖 6 种舞台形态
每门功法的独有机制互不重复
15 门功法各有完整主题字段
所有本门玩法都有名称与说明
```

**「互不重复」「互不撞词」「各用各的」**这三条是「一门功法一套玩法内核」这个硬约束的机器版本。

### 5.2 逐门机制（66）

每门 3–8 条，从「盘面长什么样」到「边界怎么判」：

```
辨伪择真：4×3 盘面同时出现真招与虚影
顺光扫斩：刀路亮完才起寿命线，没划到就算漏
阵灯推演：五段开出来的盘都解得开，且最优步数落在该段区间
阵灯推演：步数用尽还没全亮即阵溃，按失败 F 收场
阵灯推演：用一次阵眼感应，本盘最高只到 A
记序复现：把逆诵关掉，这一门就真的不逆诵了
```

最后那条是**「开关必须真的生效」**的守门员——准备页给了开关，玩法层不读 `perks.offTwists`，玩家就会觉得「关了没用」。

### 5.3 驱动的做法

每个用例都是「建控制器 → `start()` → 按脚本喂 tap/move → 断言 vm 或 finish 的结果」。因为玩法是纯模块（不吃存档），这一步不需要任何 mock。

**`teach` 脚本也要走一遍**：目前只有阵灯推演有 `teach`，测试会驱动它走完，确认「第一次进来的人不会卡在教学里」。

## 6. `rank.test.js` —— 段位与关卡是同一把尺子

57 个用例。

### 6.1 它复算的是什么

对每一门功法，逐段算出 `buildParams` 与 `gradeLines`，然后检查：

- 至少两个玩家可见参数在变；
- 评级线随段变，或盘面规格随段变；
- 单调性（该递增的递增、该递减的递减）；
- **六档门槛逐档等于段界关**（`TIERS[i + 1].threshold === STAGE_GATES[i]`），
  且段位只由 `cleared` 读出——评级、品阶、境界都不许让它动。

### 6.2 为什么这一组必要

`audit:diff` 是**审计**（只出报告，人可以不管）；`rank.test.js` 是**断言**（红了就是红了）。

审计里那条「至少两个参数」的判断之所以不能进 CI，是因为它带量化口径、容易逼出假参数。但 `rank.test.js` 里的**单调性**是硬事实，可以断言：

> 三秀撷英诀（三连互换）的 S 线 2661 → 1800 随段**降低**，因为每手产出从 66 分掉到 50 分（S 线由 `matchSLineOf()` 按本关时辰与每手产出现算，不再是手填的五个数）。

这类「越难越低」的非单调是**故意**的，所以 `rank.test.js` 不能简单地断言「逐段递增」——它按各门的语义逐条写。

## 7. `layout.test.js` —— 109 条规范

最大的一个文件。它是「设计规范」的机器版本。

### 7.1 四类检查

| 类 | 例 |
| --- | --- |
| 结构 | 「所有 wxml 的主要标签都配平」「每个页面绑定的事件处理方法都在同名 js 里有定义」 |
| 布局 | 「所有弹窗统一次操作在左、主操作在右」「吸底条适配安全区」 |
| 规范 | 「令牌引用合法」「可点 view 统一按压反馈」「盘面无汉字」 |
| 文案 | 「规则分层：准备页一行、局内两行、整篇在说明页」「局内两行不说同一句话」「说明页每行都是给人读的话：不冒 NaN、不丢句」（真抓过 `diffLines` 的逗号 + 一元加号把整句求成 NaN） |

### 7.2 「事件处理方法都在同名 js 里有定义」这一条

它把 wxml 与 js 绑在一起：`bindtap="onFoo"` 出现但 js 里没有 `onFoo`，立刻红。

**这是最省事的一类 bug**：改名之后漏改一处，运行时只是「点了没反应」。

### 7.3 运行时探针

```js
// 真的 createGame() 起一局，扫开局那一帧的 vm.cells
```

静态读代码看不出运行时填了什么。盘面不许放汉字这条硬约束，**只有运行时探针能守住**。

代价：它只扫「开局那一帧」。若某门玩法在开局后才把汉字写进 `label`，探针看不见。

## 8. 五个文件的边界

| 想在哪儿加断言 | 该放哪 |
| --- | --- |
| 一个新的数值公式 | `game.test.js` |
| 一个新的存档迁移 | `game.test.js` |
| 一个新的同步分支 | `store.test.js` |
| 一门新玩法 / 一个边界判定 | `minigames.test.js` |
| 一条五段单调性 | `rank.test.js` |
| 一条页面规范 / 一条样式约束 | `layout.test.js` |

**没有「综合测试」**。跨层的检查（例如「说明页写的 S 线与局内一致」）放在 `minigames.test.js`，因为它的数据源在玩法模块。

## 9. 被否决的方案

这些否决围着一条线：测试要够真、够独立，但不能把项目拖进构建链。快照会天天红、一个大文件一崩全不跑、`require` 串联看不到全局——都是「省事反而误事」。而「只测能走完不测边界」那条尤其值得记：走完几乎总是能走完，真正会错的全在边界上。

| 方案 | 为什么否掉 |
| --- | --- |
| jest / vitest | 需要构建链；小程序项目保持 `node` 直接跑 |
| 一个巨大的 `test.js` | 一个崩了全不跑，看不到全局 |
| 用 `require` 串联而非 `spawnSync` | 同上：进程隔离才有独立结论 |
| 快照测试 | 样式与文案变动频繁，快照会天天红 |
| 只测「能走完」不测边界 | 「走完」几乎总是能走完，边界才是真会错的地方 |
| `layout.test.js` 也做运行时探针全盘扫描 | 每帧都扫会拖慢测试；只扫开局一帧是折衷 |

## 10. 代码指路

- `tests/run.js` —— 五文件顺序执行器

## 11. 待验

- **`layout.test.js` 是最大的单文件**，它同时承担结构、布局、规范、文案四类检查。加断言的成本越来越高（要读懂 109 条已有用例的写法），拆分的声音一直有，但没有动。
- 「盘面无汉字」的运行时探针只扫开局一帧（见上）。
- `store.test.js` 的 14 个用例覆盖了主路径，但**没有覆盖并发去重**（同一 tick 内两次 commit）与**pending 累积多条**的情况。
- `rank.test.js` 的 38 条里有相当一部分是逐门手写的语义判断，**新增玩法必须手写这一条**——漏写不会被发现（没有「每门都必须有 rank 用例」的断言）。
- 五个文件里没有一个测 **UI 事件流**（点一下按钮，页面 data 变成什么）。小程序侧没有轻量的 DOM，这一层目前完全靠真机验收。
