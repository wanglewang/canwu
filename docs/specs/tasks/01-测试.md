# 任务（Tasks）· T 测试映射

> 这份文档回答：**S 承诺的每条契约，用哪些场景去校验。**
> 它从 S 派生——S 有一条行为契约，这里就有一个或多个测试场景去验它。
> 只做「契约 → 测试文件/场景组」的映射导航，不复制断言代码；具体断言在 `tests/`。

## 一、派生关系

`tests/` 五个文件，各管一摊。下面是六份契约分别落到哪些测试场景：

| S 的契约 | 校验它的测试文件 | 覆盖的场景组 |
| --- | --- | --- |
| `spec/00-契约/01-对局.md` | `tests/game.test.js`、`tests/minigames.test.js` | 开局校验、一局一关、扣气与余额、失败结论、中途作废 |
| `spec/00-契约/02-成长.md` | `tests/rank.test.js`、`tests/game.test.js` | 进度硬顶 1000 关、段位只认关数、评级不进推进、回关 +0、六档门槛 = 段界关 |
| `spec/00-契约/03-经济.md` | `tests/game.test.js`、`tests/rank.test.js` | 兑换单向、耗气定价、气海上限、参悟不产资源 |
| `spec/00-契约/04-存档.md` | `tests/store.test.js`、`tests/game.test.js` | 存读往返、老档补值、上限夹平、读档不发钱 |
| `spec/00-契约/05-界面.md` | `tests/layout.test.js` | 首屏黑名单、按钮层级、折叠开关、返回路径 |
| `spec/00-契约/06-教学.md` | `tests/layout.test.js`、`scripts/verify.js` | 教学盘五段、输入接管、说明术语扫描 |

静态契约（结构、命名、术语、数值同步）由 `scripts/verify.js` 的断言守，不属于这五个测试文件。
完整的机器校验链见 `docs/specs/tasks/03-校验链.md`。

## 二、场景分层（按 `docs/specs/constitution/06-评审方法论.md` §2.2 的口径）

**正向主场景**：走通一局的完整流程、评级到进度的换算、段位推进、灵力兑换、存读往返。

**边界场景**：进度到硬顶、连击叠满、气海上限、老档升级、首屏字数上限。

**异常 / 坏路径**：灵力不足开局、局中退出作废、读档不发钱、重复领取、非法 id 取法门。
其中「`getMethod` 对未知 id 静默回落」这条是踩过的坑——测试取法门时必须当场验 `game`，否则拿错参数照样全绿。

## 三、未覆盖风险（强制写，不许隐瞒）

这几项当前没有机器断言，靠真机或人判断——人做风险取舍，先得知道风险在哪：

- **真机手感**：点击判定在移动端低帧率下的误差、盘面符号在部分安卓机上的显示。静态断言测不了。
- **覆盖度集合与差集告警**：R<sub>S</sub> 的 29 个场景 ID 骨架已建、R<sub>T</sub> 试挂 3 个；三份自动比对与保真度校验还没建（见 `docs/reviews/` 与 `docs/specs/constitution/06-评审方法论.md`「待验」）。
- **全方法效果**：RDD/SDD 这套流程是否真的减少审查量、有没有漏掉真实缺陷，没在全项目实测过。
- **人的三个点头点**：规格认领、盲区接受、差异裁定，目前靠对话确认，没有固化成记录。

## 四、验收通过标准

`npm run check` 四段全绿（静态校验、常驻测试、收支曲线、lint）。通过项不逐一人工复核，
人只看红的那几行。测试数量不等于质量——判据是「有没有验到 S 的关键规则」，不是断言条数。
