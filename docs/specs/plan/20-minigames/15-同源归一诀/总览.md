# 丹道·同源归一诀 → 滑格相合（总）

## 玩法概述

一张 4×4 的盘，你用手指往一个方向划，整行整列就往那边挤，两枚同数撞在一起合成双倍。合出本段的目标块就算完成。我想做的不是「手速游戏」——这一门没有时辰在追你，压力全来自「盘满堵死」。它是一门规划功课：把大块留在一角，给下一手留出推盘的通道，别把自己堵死。

评级也跟着这个性子：只看「最大那块合到多大」，不看总分。合出目标是 S，差一点是 A / B，盘满推不动是 F。五段盘面始终是 4×4，变的是「要凑多大」和「开局有多挤」——目标从 128 一路到 1024，起手块从 2 增到 4。

```text
  ┌────┬────┬────┬────┐
  │ 2  │ 4  │    │    │
  ├────┼────┼────┼────┤
  │    │ 8  │    │    │  ← 往左划：整行一起挤
  │    │    │ 16 │    │    同数相撞 → 合成双倍
  ├────┼────┼────┼────┤
  │ 4  │    │ 4  │    │
  └────┴────┴────┴────┘
  合出目标即完成 · 盘满无同数即 F
```

> 这张示意是设计意图，不是实测截图；数字直接显示、空格画成凹槽，读数就是玩法本身。

> 整行整列往一个方向挤，同数相撞就合成双倍；空出来的格子里再补一块新的。合出本段目标块就完成。
>
> 五段六篇：本篇放五段共用的骨架（盘 / 规则 / 评级 / 界面 / 依据 / 代码），
> 每段的目标块、起手块数与 fourRate 写在各段文档里，两边不互相抄。

- 功法：丹道·同源归一诀（黄阶，power +5%）｜玩法 id：`heyuan`｜无阶段新法
- 时长基准 `base = 34`

## 1. 盘面介绍

4×4 滑格。开局只有 2 块（后段 3–4 块），其余空着。

- 每块上是 2 的幂（2 / 4 / 8 / 16……）；
- 数字**直接显示**——这一门不换图案，读数是玩法核心；
- 四向操作，整行整列一起动；
- 空格画成凹槽，不是「没有」：玩家要看出还剩几个位、滑到底后一条线会停在哪儿。

盘面五段不变，都是 4×4。变的是目标块、起手块数，以及「起手给 4 的概率」。

### 操作：四向滑动

**在盘面上四向滑动**：往哪划，整盘就往哪挤（`vm.extras.swipeMove`，页面挂一层透明滑动层）。
不摆方向键——拇指本来就盖在盘上，再挪到底部去按四个箭头，等于每走一步换一次手。

判据只看起点到终点的位移（24px 起步，斜划取主轴），不跟轨迹：推盘是一步决策，不是画线。

## 2. 规则说明

| 项 | 规则 |
| --- | --- |
| 合并 | 同一行/列往一个方向挤，同数相撞合成双倍 |
| 补块 | 每次操作后，空格中随机补一块新的 |
| 结束 | 合出**本段目标块**即完成 |
| 失败（F） | 盘满且相邻无同数、再也推不动 |
| 得分 | 合并值累加，**只用于破纪录**，不参与评级 |

**评级只看「最大那一块合到多大」**，不看总分。这是「达成制」而不是「分数制」：

- 达成目标即完成，所以 S 是「完成本段任务」；
- 没达成但合到了 A 线，说明「差一点」；
- 盘满推不动 → F（无路可走，不是「打得糙」）。

A / B 线由目标往下减半：`linesOf()` 出 `[目标, 目标/2, 目标/4]`，分别对应 S / A / B，没到 B 线是 C。
各段具体线值见段篇 §3。

## 3. 五段递进

盘面不动，换的是「要凑多大」和「开局有多挤」：

| 段 | 这一段新学的一件事 | 轴 |
| --- | --- | --- |
| 一 · 未入门 | 四向推盘、同数翻倍，合到 128 就完成；起手 2 块、空格多 | 基本操作 |
| 二 · 入门 | 目标翻到 256，起手仍 2 块，但白送的 4 变少，凑同数得多推几步 | 目标 + fourRate |
| 三 · 小成 | 目标还是 256，起手增到 3 块——第一次体会「开局就被占掉一格」 | 空间 |
| 四 · 大成 | 目标 512、起手 3 块，fourRate 继续降 | 目标 + fourRate |
| 五 · 圆满 | 目标 1024、起手 4 块，fourRate 落到 0.20——几乎一半盘已被占 | 目标 + 空间 + fourRate |

`fourRate` 从 0.45 收到 0.20，三位小数——**1000 关里只有 29 关真的报得出变化**：它每关只动 0.025%，
而界面精度是 0.1%，多数关四舍五入回同一个数。这一门的密度欠账最明显，见 `04-open-issues` D11。

目标更高 → 需要更多步；起手块更多 → 开局可用空间更少，更容易被堵死。
这两个数是区分度审计补上的第二个参数：原本只有目标在变，玩家感受不到困难与极难的区别。

## 4. 设计依据

### 4.1 与三连互换、落石垒基的分工

| | 三连互换 | 落石垒基 | 滑格相合 |
| --- | --- | --- | --- |
| 格子 | 换相邻两格 | 块自己落 | 整行整列挤 |
| 消除 | 三连 | 填满整层 | 同数翻倍 |
| 节奏 | 限时 | 实时下落 | 回合制（无时限压力） |
| 结束 | 时辰到 | 时辰到 / 堆顶 | 合出目标 / 盘满 |

三者都是「格子类」，但动作完全不同：换、落、挤。

### 4.2 为什么不用时限

这一门没有时间压力——压力来自「盘满堵死」。加时限会变成「手速游戏」，而它本该是「规划游戏」。

**这也是全站唯一一个「只靠失败条件而不靠时限」的玩法**（在引入步数 / 推数预算的玩法出现之前）。

### 4.3 为什么起手块数也算难度

起手 2 块与 4 块在 4×4 上的差别极大：4 块时几乎一半空间已被占，前几步的可选路径少很多。
用它作为「第二难度旋钮」比再抬目标更有效——抬目标只是更长的重复，加起手块是真的变紧。

### 4.4 被否决的方案

这张表记着当时没走的几条路——每一行都留着诱因和收手的理由。尤其「按总分评级」和「用图案代替数字」，都差一点就把这一门做成了别的东西。

| 方案 | 为什么否掉 |
| --- | --- |
| 按总分评级 | 总分可以靠「小合并多得」堆，与「合出大块」的技术含量不符 |
| 加时限 | 见 §4.2 |
| 目标只靠抬数值 | 会变成更长的重复，不是更难 |
| 盘面放大到 5×5 | wxss 只有 `.grid--c3/4/6`，且 5×5 会让目标块需求暴涨 |
| 用图案代替数字 | 读数就是玩法，换图案等于换玩法 |
| 整盘滑动位移（界面） | 见 §5：逐格 diff 前后坐标、每格单独写 `translate`，代码量翻倍、低端机易掉帧 |
| 每一手都弹浮字（界面） | 见 §5：30 手后玩家就学会无视，改成只有真合并了才弹 |

## 5. 界面与反馈

判据看合成格的弹动与最大块金边；代价看无效推的一声闷响；操作就是四向滑动本身；
进度看 HUD「第 N 手」与「最大 X / 目标 Y」；收束是合出目标即完成、或盘满推不动判 F。

| 时机 | 玩家看到什么 | 代码 |
| --- | --- | --- |
| 静止 | 数值牌按数值换底色（米黄 → 赭红），三 / 四位数自动小一号 | `.cell--tile` / `--tile-3` / `--tile-4` |
| 合并 | 合出来的那一格缩一下再弹开，原位迸一小把粒子 | `cell--pop0/1` + `markCleared()` |
| 补块 | 新块由半大长到整格 | `cell--fresh0/1` |
| 全程 | 当前最大的一块压一圈金边 | `.cell--best` |
| 无效推 | 一声闷响 + 一行「推不动 · 换个方向」 | `C.flash(..., 'bad')` |

**为什么牌面要按数值换底色**

2048 的读法只有一条：数字多大。旧版白底黑字、只换字色，深玉台上一格一格都是白补丁——
玩家要逐格读数字才知道哪块大。底色是这条信息的第二层编码：扫一眼盘面就知道大块在哪个角，
「把大块留在一角」这条策略才有人真的执行得下去。

**被否决的方案**

- **整盘滑动位移**：要让每块从旧位置滑到新位置，得逐格 diff 前后坐标、再给每格单独写
  `translate`，代码量翻倍，低端机上还容易掉帧。改用「合并格弹 + 新块弹」表达同两件事：
  哪里合了、哪里新来了。
- **每一手都弹浮字**（旧版）：30 手之后玩家就学会无视它。现在只有真合并了才弹，且报的是
  「这一手得了多少」，不是总分——总分在 HUD，浮字报总分等于每次都弹同一个数。
