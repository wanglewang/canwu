# 玩法设计完备性自检清单

> 适用：任何一门功法对应的对局玩法（阵法·燃灯诀、心法·静心诀、刀法·开锋诀、身法·踏云步……），以及改了规则之后的老玩法。
> 用途：设计评审、开发前自检、上线前验收。**这是交付门槛，不是灵感清单**——写「这一门做完了」之前，第一节的十二个维度必须条条有答案；二期项可以空着，但要知道自己空着。
> 每一条都带三样：设计要回答什么、理论依据、现实或工程依据。最后多一列「在本仓库怎么算过」，能指到文件、能指到断言——这是它和通用模板最大的区别：**能验证的才叫清单，靠记的只是提醒。**

## 〇、先纠正七处通用口径

这份清单的骨架来自一份通用模板。模板里有七处写法与 `参悟` 已定的框架冲突，**照抄会打穿框架、还会向玩家说谎**。逐条纠正如下，写设计时以本表为准。

| 通用模板写法 | 本项目口径 | 为什么不能照抄 |
| --- | --- | --- |
| 评级 `C/B/A/S/SS/SSS` | 只有 **S / A / B / C / F** 五档，`F` 是走火（收功 / 溃败）。系数 `1.5 / 1.2 / 1.0 / 0.6 / 0.2` | 评级名在 `data/copy.js` 的 `GRADE_TITLE` 是一份真源，被结算、称号、成就、三连 S 全站共用。多两档，改动面比做一个新玩法还大 |
| 熟练度 = 基数 × 难度系数 × 评级系数 | **四连乘再封顶**：品阶 × 难度 × 评级 × 境界衰减，总倍率 ≤ `MAX_MULTIPLIER`（13.0）。上限的作用是防以后加系数失控，**不许拿来压正常组合**——压到 8.0 时天阶的困难 / 极难 / 绝境收益完全并列，最高两档就白设了 | 漏掉品阶，黄阶和天阶就同价，「品阶管收益」这条线立刻失效；漏掉境界衰减，高境界玩家会把低阶功法刷穿 |
| 难度解锁：通关当前难度才开下一档 | 难度跟**熟练度**走：0 / 400 / 1000 / 2500 / 6000，与 `TIERS` 阈值同源 | 全站只允许一套解锁语义。单门自建「通关解锁」，玩家就要记两套规则；而且限时连解类玩法根本没有「通关」这个可定义事件 |
| 圆满之后不再增加熟练度，只衰减灵石 | 圆满仍能涨，到**大圆满**封顶；境界超出功法可修上限，收益衰减到 **30%** 而不是归零 | 归零等于这门功法死了，玩家只能换门；30% 的意思是「还能练，但该换了」，和「只奖不罚」的养成基调一致 |
| 结算三按钮：再来一局 / 返回 / 下一难度 | 主按钮 **「留在本页」**（收起遮罩、按本局结果刷新准备页）；次按钮「返回」；「再来一局」降为按钮下方文字链 | 上一轮刚修掉「打完没机会看页面」：结算遮罩盖住整页、连刷直接开下一局，玩家一拍都停不下来。改回去等于撤销那次修复 |
| 对局提示、求解辅助 → 归入二期增强 | **辅助是刚需，但必须有明码代价**：燃灯诀的阵眼感应与重置本盘封顶 A、勘禁诀的勘位、太虚诀的入定 | 问题从来不是「有没有提示」，是「用了提示还宣称 S 公不公平」。辅助要么不给，要么把代价写在按钮上 |
| 分步新手引导弹窗、动画教程 → 二期 | **首局做「盘上手把手」，不做「读完再玩」的弹窗**：一门功法第一次开局，先给一盘不计步的小阵，两手之内把核心规则演完，随时可跳过，跳过或走完都记「看过」，之后永不再出现；没写教学脚本的玩法直接跳过 | 新手确实需要引导，但需要的是「带着点一次」，不是读三页字再开始——解谜类的规则，说一百遍不如让他看见点一格会翻五格。弹窗盖住盘面，恰好挡住要教的东西；它一旦成了每次开局的过场，又和「少文字、点进去展开」的基调打架 |

另外三条本项目的硬约束，通用模板里没有，必须自己补：

1. **盘面不写汉字**。方向靠箭头、形状、颜色、glyph 表达（刀路箭头、步法卷轴的 ↑↓↗⟳、燃灯诀的 `● / ○ / ✕`）。文字只出现在 HUD、按钮和说明里。
2. **恒定深色仙箓皮肤，只允许一支强调色**。页面挂 `.pg--imm`，颜色全取 `styles/tokens.wxss` 的 `var(--*)`，页面 wxss 不写裸色值。玩法盘面色板（`scene.wxss` / `practice.wxss`）是白名单例外——「盘面是纸、其余是墨」。
3. **文案不许写在 WXML 里**。状态与按钮取 `data/copy.js`，术语取 `copy.TERMS`，长解释取 `data/help.js`，玩法规则取 `data/guides.js`。

## 一、定位与叙事

| 检查项 | 依据 | 在本仓库怎么算过 |
| --- | --- | --- |
| 玩法品类明确，与已成功法机制不重复、不换皮 | 自我决定理论：多样化挑战维持内在动机 | `tests/minigames.test.js` 断言「19 门功法对应 19 套互不重复的玩法」「同类功法（刀法/剑法/阵法/心法）也各用各的玩法」「每门功法的独有机制互不重复」 |
| 叙事包装与机制同源，不是文案贴皮 | 叙事沉浸理论：机制与故事统一才有记忆点 | `data/skills.js` 的 `desc` / `flavor`、`minigames/theme.js` 的主题名与浮字，讲的是同一件事（阵灯翻转 ↔ 阵眼感应；刀路 ↔ 刀光） |
| 目标用户、适合与不适合的场景写清 | 用户分层设计：避免同时要求强记忆 + 极限手速 | 设计文档里写明「适合推演型 / 不适合竞速型」，并对应到 `DIFFICULTIES` 的档位设计（燃灯诀给足步数预算，就不该再叠倒计时） |
| 品类归属到模板大类 | 模板化复用：同类功法复用引擎 | 在 `data/practice.js` 的 `game` 字段与 `minigames/index.js` 注册表登记；文档里写清它属于点阵联动 / 记忆序列 / 滑动判定 / 走位预判 哪一类 |

**判断标准**：把这一门的文案全删掉，只看盘面和判定，玩家能不能分辨出这是另一门功课？分不出，就是换皮。

## 二、核心对局规则

| 检查项 | 依据 | 在本仓库怎么算过 |
| --- | --- | --- |
| 胜利条件一句话说得清 | 心流理论的前提：玩家知道怎么才算成功 | `minigames/*.js` 里只有一个 `finish()` 出口；`data/guides.js` 的 `goal` 一行写完 |
| 失败条件与边界明确 | 操作性条件反射：有边界的惩罚才形成闭环 | 失败必须走 `finish()` 并落 `F` 或 `C`，不许出现「无限僵持」的局；`tests/minigames.test.js` 的整局驱动会断言每门都能跑到结算 |
| 基础操作与响应规则确定 | 一致性交互原则 | 控制器只实现 `create()` 约定的接口（`tap` / `swipe` / `press` / `undo` / `hint` / `reset`）；页面事件方法必须在同名 js 里有定义（`tests/layout.test.js`） |
| 试错与重置机制 | 认知心理学：解谜的探索不该被惩罚 | 有代价的可逆操作。燃灯诀「重置阵局」回本盘开局、不限次，但本盘封顶 A——免费无限重 roll 会让步数预算失去意义 |
| 中途退出规则 | 事务一致性：未完成的局不产生收益 | 收功走二次确认（`tests/layout.test.js` 守着「参悟局内收功放在屏幕上方且带二次确认」），退出无熟练度无灵石，与全部功法一致 |
| 代价句必须常驻且只说一次 | 减少认知负荷：代价要在玩家付出之前出现 | `tests/layout.test.js` 断言「局内两行不说同一句话：tip 讲代价，inline 讲操作」「局内代价句用阿拉伯数字」 |

**判断标准**：玩家第一次输，能不能仅凭局内提示说出「我为什么输」。说不出，就是失败条件没交代。

## 三、难度系统

| 检查项 | 依据 | 在本仓库怎么算过 |
| --- | --- | --- |
| 难度控制变量全部参数化 | 认知负荷理论：可控梯度加载压力 | 变量只写在 `data/practice.js` 的 `params`，玩法层读 `buildParams(method, diffKey)` 的输出，不自己写死 |
| 递增曲线平缓，无断崖 | 最近发展区：难度略高于当前能力 | 相邻档之间的参数差要能解释（燃灯诀：盘面 3→3→4→4→5，最优步数下限 2→3→4→5→5，预算 9→22）。`tests/rank.test.js` 断言各档参数确有区分 |
| 解锁规则全站唯一 | 心流门槛管控：别让新手直接撞高难 | 难度 `need` 与 `TIERS` 阈值同源（0/400/1000/2500/6000），不新增第二套解锁 |
| 盘面尺寸不随难度档缩放 | 工程约定：尺寸是玩法身份，不是难度旋钮 | `tests/rank.test.js` 断言 `grid / cols / rows / size` 在 `buildParams` 里不被改写——**唯一例外是燃灯诀**，它把盘面规格收进 `LIGHTS_LEVELS` 并显式声明，属于「规格本身是难度」的另一种设计，需在文档里单独说明理由 |
| 默认档跟熟练度走，不记忆手选 | 心流：挑战与技能同步。门槛到了就说明能力到了，还停在半年前那一档是漏设计 | 默认 = 本门**最高已解锁档**，每次进准备页重算；手选只记在内存（`diffOverride`），跨过新门槛（`maxIdx > this.maxIdxSeen`）就清掉、回到新档。`tests/rank.test.js` 断言 0 / 399 / 400 / 999 / 1000 / 2500 / 6000 各自的默认档 |
| 退回低档有明码折减，且与连 S 是同一判定 | 激励经济学：低档不能既拿难度倍率又躲开难度本身 | **低档折减 ×0.5**（`DIFF_BELOW_CAP`），且该档 S 不计连晋：`belowCapOf()` 一个判定管两件事，玩家只需记「只有最高已解锁档才算真功夫」。折半后界线可一句话讲：黄阶简单档 S＝0.75 < 普通档 C＝0.78。熟练度 < 400 时简单档就是最高档，不折减。`npm run sim` 断言只刷简单 2551 < 逐档升 7339，退一档刷 2994 也不反超 |

## 四、激励、经济与熟练度

| 检查项 | 依据 | 在本仓库怎么算过 |
| --- | --- | --- |
| 评级判定指标明确、可解释 | 质量—奖励匹配原则 | 指标可以因门而异（燃灯诀按步数、三秀诀按总分、静心诀按轮数、踏云步按段数），但必须一句话讲清且写进 `guides.scoring`。统一的是**五档名与系数**，不是判定指标 |
| 收益公式走统一引擎 | 公平激励：付出与质量越高回报越高 | `utils/game.js` 一处算：品阶 × 难度 × 评级 × 衰减，封顶 13.0（正常最高 12.48，不误伤）；玩法层只交评级，不自己算熟练度 |
| 段位与圆满后衰减 | 动机边际递减：防止单门无限内卷 | 阈值 100/400/1000/2500/6000；到顶后仍可练但收益封顶，配合换门 ×1.15 的「触类旁通」 |
| 三种结局的收益定义 | 结果导向激励：只奖励完成参悟 | 成功 / 失败 / 中途退出三条路径各有明确产出，且藏不进漏洞：无「零成本重开刷最简盘」 |
| 横纵向收益不失衡 | 经济系统平衡：别让一门碾压全部 | `npm run sim` 的收益曲线：高档期望更高、境界衰减生效、总倍率封顶；`tests/rank.test.js` 断言品阶收益与门槛单调 |
| 刷分风险有配套规则 | 激励经济学：避免激励扭曲行为 | 每次改动都要回答「最省力的刷法是什么」。已知问题必须如实记在 README，不许装作不存在 |

## 五、页面状态与交互信息

| 检查项 | 依据 | 在本仓库怎么算过 |
| --- | --- | --- |
| 状态流转完整：准备页 → 对局页 → 结算页 | 状态机设计：路由提前理清，减少跳转 bug | 三个明确状态，且**每个状态都能停**：结算主按钮「留在本页」、准备页顶部「上局战绩」可重开结算、倒数三秒「再看看」退回准备页 |
| 局内关键状态常驻 | 信息分层：剩余资源必须随时可见 | HUD 只放三样：还要做什么、还剩多少、当前算到哪（燃灯诀「已走 X · 最优 N 步」「预算 M 步」） |
| 按钮在拇指热区、适配安全区 | 移动端人体工学 | 吸底条走安全区变量；`tests/layout.test.js` 断言「吸底条适配安全区且有高优先级底部留白」「按钮与文字链尺寸取自令牌」 |
| 置灰与不可点有解释 | 预期管理：让玩家看懂为什么点不了 | 未解锁难度显示门槛熟练度，不显示一个点不动的按钮 |
| 低频信息不占首屏 | 希克定律：减少无关信息 | 说明入口沉页尾；称号簿 / 成就 / 背包 / 设置默认折叠；`tests/layout.test.js` 断言首屏无长解释 |
| 最差那一档要分得清「没走完」与「做糙了」 | 归因清晰：玩家看到 F 要知道是这一局作废，不是自己手笨；看到 C 要明白是走完了但糙 | 有失败态的十二门（燃灯阵溃 / 勘禁心神尽 / 静心心尽 / 太虚时辰到 / 凝露没采到顶 / 并蒂引还剩对子 / 九宫时辰到还剩格 / 叠元盘满无同数 / 逐数时辰到没点完 / 让路步数走完没脱身 / 入位步数走完没归位 / 摘魁时辰到没拣完）判负一律 **走火 F**（×0.20），照常结算并断连；没有失败态的七门（刀法 / 剑法 / 身法 / 吐纳 / 灵植 / 土术 / 五行）只在时限内看产出，最低只到 C。**主动收功不进结算**，连 S 原样保留，结算卡上是「收」不是 F——它由页面的 `aborting` 标记区分，不靠玩法层猜。说明页每条 `lines().fail` 写明崩了什么、掉到哪。`tests/minigames.test.js` 断言十二门判负为 F、七门只有一处 F（收功）、有失败态必有 `fail` 线；`tests/rank.test.js` 断言 F 断连且收益是 S 的 1/7.5；`tests/layout.test.js` 断言两种 F 分流 |
| 评级标准可查，不用猜「为什么只是 B」 | 目标设定理论 + 公正感：拿不到 S 要知道差在哪，而不是被一个字母打发 | 每门玩法导出 `lines(params, gear)`，说明页按当前档列出 C/B/A/S 四条线，与局内 HUD、结算同源（`minigames.gradeLines()`）；局内只报下一条线。`tests/minigames.test.js` 断言 19 门都有 `lines()` 且四档齐全、无 `undefined/NaN`；`tests/layout.test.js` 断言说明页「怎么评级」必含「本档「困难」」与 S/A/B/C |
| 功法类别必须与玩法的动作同源 | 语义一致性：名字是玩家理解规则的第一个线索 | 反例：原「符箓·照影符」练的是数格辨禁（扫雷），符却是纸上画出来的东西。已改为「阵法·勘禁诀」，补齐阵法族黄阶；盘面术语「镇符→阵钉」、色板「符箓朱金→阵法青紫」同步。`tests/minigames.test.js` 断言同类功法的玩法内核互不复用，且阵法三档各一门 |
| 规则分层：准备页一行、局内两行、整篇在说明页 | 希克定律 + 做中学：首屏只回答「这一局做什么、打多难」 | 准备页只有 `ruleText`（取自 `guides.goal`）一行 + 难度条；整篇（步骤 / 盘上符号 / 本门机制 / 品阶与一脉）由 `data/help.js` 的 `practiceTopic()` 按功法现拼成 `topic=practice` 的说明页；局内只留 tip（代价）与 inline（操作）两行。`tests/layout.test.js` 断言准备页不再出现 `guide.steps / guide.terms`，且说明入口走 `nav.practiceHelpUrl` |
| 准备页不是唯一规则容器：局中切页即本局作废，长解释入口必须留在开局前 | 生命周期约束反过来决定信息架构 | `onHide` 会 `destroy()` 控制器并回到未开局；所以说明入口只能放在准备页右上角，打完「留在本页」→ 说明 → 返回，形成复看闭环 |
| 首局引导不遮盘面、能跳过、只出现一次 | 做中学：解谜类的第一手必须亲手点，读规则替代不了 | `pages/practice/practice.wxml` 的 `.teach` 窄条挂在局内卡片里，不是结算那种 `mask`；`minigames/lights.js` 的 `teach.create()` 给一盘两步解的小阵；完成标记落 `state.skills[id].onboarded`；`tests/layout.test.js` 守着「不在遮罩里」「跳过有入口」「文案不写死」 |
| 事件处理方法都有定义 | 工程一致性：避免点了没反应 | `tests/layout.test.js` 断言每个页面 `bindtap` / `catchtap` 的方法在 js 里存在 |

## 六、视觉与色彩

| 检查项 | 依据 | 在本仓库怎么算过 |
| --- | --- | --- |
| 每种状态有确定的色值与形态 | 格式塔区分原则 | 盘面状态至少两重编码（燃灯诀：实心 `●` + 亮底 / 空心 `○` + 暗底 / `✕` + 暗红底）；勘禁诀：数字 / `✕` / `⚑` |
| 不只靠颜色区分 | 无障碍设计：色弱与屏幕色差 | 形状、填充、发光、描边变化至少再叠一层 |
| 盘面不写汉字 | 项目硬约束：文字会破坏沉浸，也会挤爆小格 | `tests/layout.test.js` 断言「刀路用形状指方向…盘面无汉字」「步法盘面用形状指方向…不写汉字」 |
| 动画时长与强度有上限 | 视觉疲劳管控 + 低端机性能 | 动效预算在 `data/visual.js`；`tests/layout.test.js` 断言「舞台动画只动 transform / opacity，不超循环预算」 |
| 不靠高频闪烁传递信息 | 频闪合规风险 | 一次性微光（约 240–260ms）而不是持续闪；破阵金光只播一拍 |
| 颜色全取令牌 | 单一真源 | `tests/layout.test.js` 断言「全局基础层与常规页样式不写裸色值」；盘面色板是白名单例外，改动要在文档里说明 |

## 十一、风险与平衡

| 检查项 | 依据 | 在本仓库怎么算过 |

## 十五、验收口径

一道功法算「做完」，要同时过三关：

1. **设计关**：上面十二个维度条条有答案，二期项明确空着。
2. **静态关**：`npm run check` 全绿（verify + test + sim + lint），新行为有断言守着，不是靠记忆。
3. **产品关**：真机看过。**没有任何一条真机证据时，只能说「静态层完成」**——颜色在真实屏幕上是否分得开、热区在 4.7 寸上够不够、动画会不会掉帧、震动与音效是否撞手感，这些断言替不了。
