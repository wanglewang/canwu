# 称号、日志、指南、说明（四个「内容页」）

> 这四个页面不产生数值，只承担「解释」与「回顾」。它们共用同一套折叠分节（`.help-sec`），因为它们的阅读动作是一样的：**先看目录，点开一节**。

## 核心前提：讲解的页面，也要尊重读者

这四页不产出一个数字，只做两件事：解释和回顾。正因为不产出数值，它们最容易被当成「说明书仓库」——把几千字一次糊到脸上。我不想那样。

它们的共同动作是「先看目录，点开一节」，所以我给它们共用一层折叠分节。共用不只是省代码，更重要的是保证「点开的反应」在全站一模一样：读者在这页学会怎么展开，到另一页就不用重新试。

我坚持每条解释都指到具体数值，不写「较高」「大概」。也坚持术语只留一份真源，第一次出现的黑话就地可查。解释性页面最容易变成不了了之的草稿，这一篇的规矩就是防止它变成那样。

## 1. 一句话

- **称号簿**：14 个称号，解锁即落盘，可佩戴；
- **修行日志**：最近动静，倒序，一行一条；
- **修行指南**：11 节完整手册，带目录 + 展开全部；
- **说明**：按「当前页 / 当前这门功法」现拼的一册。

## 2. 目标与非目标

**目标**

- 「点进哪一节就看到那一节」，不把说明书一次糊到脸上；
- 每条解释都能指到具体数值，不写「大概」「较高」；
- 术语查询只有一份数据（`copy.TERMS`），页面上第一次出现的黑话就地可查。

**非目标**

- 不在内容页做交互式教学（那是玩法本身的 `teach`）；
- 不在页面正文里写第二层标题（原生导航栏已经有标题）；
- 不做搜索（11 节 ÷ 目录 chip 就够）。

## 3. 称号簿 `pages/titles`

```
当前称号                        5 / 14
初入仙门
全 部 称 号
初入仙门   第一趟参悟走完            [卸下]
一技大成   任意一门到大成            [佩戴]
...
丹成九转   金丹已成                 未解锁
           ▓▓▓▓░░░░  战力 96 / 170
```

| 状态 | 右侧 | 列表行 |
| --- | --- | --- |
| 已佩戴 | `.imm-btn--ghost`「卸下」 | `imm-row--on`（金边 + 名字转金） |
| 已解锁未佩戴 | `.imm-btn`「佩戴」 | 常态 |
| 未解锁 | `.imm-chip`「未解锁」 | 带迷你进度条 + `progressText` |

**称号与成就的分工**：

| | 称号 | 成就 |
| --- | --- | --- |
| 存储 | 解锁即写进存档（`state.titles`） | **实时算，不落盘** |
| 能否佩戴 | 能，只有一枚 | 不能 |
| 存在意义 | 身份与展示 | 看一眼进度 |

称号必须落盘是因为要佩戴——佩戴状态要跨设备同步。成就不需要。

## 4. 修行日志 `pages/log`

```
近期动静
◆ 于藏经阁换得《吐纳周天诀》
◆ 参悟 吐纳周天诀 获 S，熟练度 +34
◆ 突破至「筑基」，气海拓至 260
◆ 冲击「金丹」未成，布阵灵石散去 60
...
◇ 诸 界
   太初 · 参悟    进行中
   云海 · 待启    还没开放
```

- 只显示最近若干条（`state.logs`），**倒序**；
- 一条一行，`◆` 金点 + 文本；
- 空态：`.imm-empty` + `copy.emptyLog`；
- 「诸界」折叠块与人物页里的那份**同源**（`data/world.js`）。

日志的分类（`addLog` 第三参）有 `realm` / `skill` / `battle` / `practice` 等，页面上不按分类分组——**日志是流水，不是报表**。

## 5. 修行指南 `pages/guide`

### 5.1 顶部目录卡

```
目 录                                   展开全部
[一 怎么变强] [二 离线吐纳] [三 灵力与灵石] ...
轻点一节看细节，或点「展开全部」
```

- `toc-chip` 一行一个章节简称，展开中的 chip 高亮；
- 「展开全部 / 收起全部」一键；
- 点 chip 会 `scroll-into-view` 到该节。

### 5.2 十一章，按「新手要搞懂的顺序」排

| # | 章 | 一句话 |
| --- | --- | --- |
| 一 | 怎么变强 | 两条路：一条保底（挂机）一条加速（参悟） |
| 二 | 离线吐纳之规 | 最多 8 小时，超时不累计 |
| 三 | 灵力与灵石 | 一个是油，一个是钱，两条线不兑换 |
| 四 | 战力从哪来 | 一个公式，五条提升途径 |
| 五 | 熟练度与境界 | 六段、关卡怎么算、回关折减、突破门槛 |
| 六 | 参悟与盘面 | 一局怎么走、评级怎么判 |
| 七 | 连 S 叠倍率 | 只有连续的 S 才叠，10 层封顶 |
| 八 | 切磋与战力码 | 镜像战、衰减、首胜 |
| 九 | 称号与道牒 | 称号怎么拿、道号怎么立 |
| 十 | 存档与换设备 | 导出码、云端同步、游客态 |
| 十一 | 成就与榜单 | 成就不落盘、榜单只列前十 |

**顺序按「新手要搞懂的顺序」排，不按功能模块排**。章节编号写在 `title` 里（目录 chip 取 `·` 后半段），**插一节要顺延后面全部编号**——这是这套数据结构的已知成本。

### 5.3 三个「看完就能去」的动作

`action` 只给三节：给多了按钮反而把正文挤散。例：第三段末尾一个「去藏经阁」直接 `switchTab` 到功法页的 shop 分区。

`switchTab` 不能带 query，所以用 `globalData.skillsTab` 传参，读完即清——这是 tab 页唯一的传参办法。

### 5.4 名词速查

最后一节是术语表，与 `components/term` 共用 `copy.TERMS`。顶部有一个「示范：<term> 轻点即有释义」，让玩家知道那些 `?` 胶囊是能点的。

## 6. 说明 `pages/help`

### 6.1 两种来源

| `topic` | 来源 | 特点 |
| --- | --- | --- |
| `practice` | `helpData.practiceTopic({ method, game, diff })` **现拼** | 一门一册：整篇规则按这一门 + 本段难度生成 |
| 其余 | `helpData.topicOf(topic)` 静态表 | `home` / `skills` / `profile` / `battle` / `secret` / `board` / `titles` / `log` / `guide` / `charge` / `privacy` |

**参悟页的说明不是「一页一节」，是「一门一册」**。它要带 `method`（按参悟方式生成）或 `game`（冲关局没有功法，取蓄力停区的说明），还要带 `diff`（说明页要把「本段 S/A/B/C 各要多少」写成具体数字，不带段只能给笼统口径，等于没写清）。

### 6.2 默认全折叠

```js
sections: topic.sections.map(s => ({ key, title, lines, open: false }))
```

点哪节展开哪节。`.help-sec__idx` 是章节序号，`.help-sec__arrow` 是 `+ / −`。

### 6.3 标题按主题动态给

```js
wx.setNavigationBarTitle({ title: topic.navTitle || (topic.title + ' · 说明') });
```

「说明」页是共用容器，导航栏留空会把「你现在看的是哪一页」丢掉。页级说明带后缀（`人物 · 说明`）；隐私与协议本身就是完整标题（`navTitle`），不再拼后缀。

### 6.4 页尾一个总入口

```
看完整修行指南 ›
```

「说明」是「这一页」，「指南」是全部。两者分工明确，不在页面正文里互相穿插。

## 7. 四个页面共用的一层

```css
.help-sec { border: 1rpx solid var(--c-imm-line); border-radius: var(--r-md); overflow: hidden; }
.help-sec__head { min-height: var(--touch); padding: 0 var(--sp-6); }
.help-sec__body { border-top: 1rpx solid var(--c-imm-line-soft); padding: var(--sp-5) var(--sp-6) var(--sp-6); }
```

**为什么共用**：这四个页面的阅读动作完全相同（列表 → 点开 → 读几行），共用一层保证「点开的反应」在全站一致。

`.help-sec__head` 的 `min-height: var(--touch)` 保证 88rpx 的可点高度——折叠头只是文字，不撑够热区就很难点中。

## 8. 被否决的方案

这些否决的共同点是：讲解的页面最容易被「好心」毁掉——一次全展开、每页各写一套样式、给每段都配按钮、把解释分散到各页。每一条单独看都像在帮忙，合起来就是把一本清爽的手册变成一堵字墙。我把它们记下来，是为了让下一个想「再解释清楚一点」的人先停一下。

| 方案 | 为什么否掉 |
| --- | --- |
| 说明页一次全展开 | 一屏几千字，等于没写 |
| 每页各写一套折叠样式 | 点击反馈不一致 |
| 指南按功能模块排 | 新手找不到「我该先干什么」 |
| 术语解释分散写在页面里 | 改一次口径要动十几个文件 |
| 称号也实时算 | 佩戴状态必须落盘 |
| 成就也落盘 | 它不需要跨设备同步，落盘只是多一份要迁移的字段 |
| 说明页导航栏留空 | 丢掉「你现在看的是哪一页」 |
| 给每段都配 action 按钮 | 按钮把正文挤散 |

- `pages/titles/titles.wxml` / `.js` —— 三状态、`onEquip`

## 10. 待验

- **说明页的分享会丢参数**：`onShareAppMessage` 只带 `?topic=`，不带 `method` / `game` / `diff`。分享「吐纳周天诀 · 本段 S 线 26 秒」那一册出去，对方点开拿到的是**没有功法、没有段位的通用版**。这与「参悟页分享必须带 `skillId`」是同一类要求，但说明页没有做到。
- 指南 11 章的编号写在 `title` 字符串里，插一节要顺延后面全部编号——**没有断言守着编号连续**。
- 指南第四段写「身法每 30 点把切磋波动下限抬 1%」，与代码的 `shen/300`（每 3 点 +1%、30 点封顶 +10%）**差 10 倍**。这一条已记入 `10-systems/09-attributes.md` 与平衡待办，属于**玩家可见的错数字**，优先级应高于其余文档问题。
- 日志不按分类分组，也不分页：`state.logs` 有上限，但上限是多少、超出后怎么截断，页面上没有任何说明。
- 四个页面的折叠状态都不落盘（除了 `help` 的 `termsOpen` 在内存）。指南的「展开全部」在离开页面后失效。
- 称号页的「未解锁」行同时有进度条与 `progressText`，两处信息重复；若进度条已足够，文字可以只留「还差 N」。
