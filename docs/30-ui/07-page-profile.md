# 人物页（身份、属性、突破）

> 这一页只管「我是谁、我有什么本事、我能不能进下一境」。其余全部折起来。

## 1. 一句话

首屏四块：**道牒 + 属性格 + 称号入口 + 突破条件清单**。成就、背包、设置、诸界四个低频块折在下面。

## 2. 目标与非目标

**目标**

- 突破的两道门槛写成**勾叉**，一眼看出还差什么；
- 属性四项各写「这一项管什么」，不是四个孤零零的数字；
- 低频功能不占首屏，但也不用翻页找。

**非目标**

- 不在这一页编辑功法（那在功法页）；
- 不做「属性加点」这种主动分配（属性只由功法与境界决定）；
- 不接微信头像（见 `03-components.md` 的道相章节）。

## 3. 首屏四块

### 3.1 道牒 `.imm-idcard`

```
[道相]   青衫客
         筑基 · 战力 96
         称号 · 初入仙门
         立道号 ›
```

- 道相由 `components/portrait` 纯 CSS 绘（编号 0–5 换配色 / 法印，按境界加光环）；
- `variant` 与 `realmIndex` 都是存档字段，随云端同步；
- 「立道号 ›」开弹层：昵称输入（`type="nickname"`，可一键用微信昵称）+「换一尊道相」+ 预览。

**昵称输入要先过 `privacy.guard`**：未同意隐私指引时这类接口静默失败，症状是「点了没反应」。

### 3.2 属性格 `.imm-attrs`

2×2 细线格，每格三行：

| 行 | 内容 | 例 |
| --- | --- | --- |
| 名 | 属性 | 真元 |
| 值 | 数值 | 18 |
| 作用 | `world.attributes[].role` | 每点灵力上限 +2 |

四项四出口，一项一件正事：

| 属性 | 出去哪 | 效果 |
| --- | --- | --- |
| 体魄 `ti` | 战力 | 战力根基 |
| 真元 `ling` | 灵力上限 | 每点 **+2** |
| 悟性 `wu` | 参悟耗气 | `÷(1 + 悟性/200)`，封顶 ×1.6 |
| 身法 `shen` | 切磋波动下限 | `shen/300`，封顶 +10% |

**「作用」这一行不能省**：只给四个数字，玩家不知道该练谁。

### 3.3 称号入口一行

只有一行：`称号簿 · 已解锁 5 / 14 ›`。全表在 `pages/titles`。

称号本来自成一页，这里**不重复列全表**——这是「同一个功能不许在两页各有一份」的规矩。

### 3.4 突破条件清单

```
境界突破              筑基 → 金丹
✓ 战力 96 / 170
✕ 布阵灵石 23 / 120 · 去切磋或秘境挣
· 气海 174 → 200（+26）· 破境即补满
· 主修 · 吐纳诀 入门
· 主修 · 断岳诀 入门
[突破境界]  [背包]
```

三类标记：

| 标记 | 类 | 含义 |
| --- | --- | --- |
| ✓ | `imm-check__mark--on` | 条件已满足 |
| ✕ | `imm-check__mark--off` | 条件未满足，`off: true` 整行压暗 |
| · | `imm-check__mark--ref` | **参考信息，不是条件** |

**「气海」与「主修」为什么用中性点**：它们是所得与现状，不是门槛。写成条件会让人以为「勾不满不能突破」，白练。

**两道门是两件事**：`available`（战力够不够冲关）与 `stoneReady`（备得起阵材没有）。合成一个布尔就会出现「战力够了却说不能突破」的糊涂提示。

**主按钮的判定只用了 `available`**：`onBreakthrough` 只看战力，点进去到参悟页，那里再由 `canStart` 与 `costText`（「布阵灵石 60 · 余 23（不成退半）」）拦一次。这是刻意的两段式——战力是「有没有资格」，灵石是「付不付得起」，混在一处玩家分不清哪个更强。

## 4. 四个折叠块

全部用 `.help-sec`，头部 88rpx、`+ / −` 切换、默认全关。

| 块 | 头部摘要 | 展开后 |
| --- | --- | --- |
| 成就 | `成就 6 / 14` | 未解锁在前，默认 6 条 + 「全部成就」 |
| 背包 · 战力码 | — | 统计行、属性行、战力码、生成卡片图、复制战力码、复制文案、邀道友同修 |
| 设置 | — | 音效开关、术语（道号 / 战力码 / 连 S）、指南入口、当前账号、导出 / 导入存档、重置 / 退出、客服、隐私政策、版本号 |
| 诸界 | — | 世界列表（进行中 / 敬请期待） |

### 4.1 成就为什么只显示 6 条

14 条全铺会占两屏多。默认 6 条（未解锁优先），下面一个「全部成就 / 收起」。

`achievements` 实时算、不落盘——它与称号不同：称号解锁即写进存档，因为要佩戴；成就是「看一眼进度」，不需要存。

### 4.2 设置里的危险区分组

```
局内音效                      [音效 · 开]
[道号] [战力码] [连S]   修行指南 ›
──────────
当前账号：微信 · 青衫客
[登录以同步]                       ← 仅游客态
[导出存档] [导入存档]
以下操作不可撤销，动手前建议先导出存档码
[重置存档] [退出登录]              ← danger 支
──────────
[联系客服]
[隐私政策 ›]            v1.2.0
```

- 危险操作排在**导出存档之后**，并带一句明确警示；
- `.imm-btn--danger` 不是第三支按钮，是 `.imm-btn--ghost` 的修饰（金描边 + 警示红字）；
- 客服入口 `open-type="contact"` 与隐私入口是**发布必备**，位置固定在底部。

### 4.3 导出 / 导入存档

- 导出：生成 `CANWU1:...` 码 → 复制到剪贴板 → 弹层显示完整码；
- 导入：输入框 + 「从剪贴板读取」→ 校验 → 覆盖。

**剪贴板调用必须先过 `privacy.guard`**，并按「调用数 ≤ 守卫数」加断言——别只包一半。

## 5. 同步条

与主页的 `.alert-bar` 不同，这里用 `.sync-bar`（带一个小圆点）：

- `error`：另一台设备也改过 / 同步失败；
- `warn`：有改动待同步；
- `ok`：整块不渲染。

点一下 → `store.flushCloud()` → toast → 重算。

## 6. 交互细节

| 细节 | 做法 |
| --- | --- |
| 道号输入 | `type="nickname"`，`maxlength="12"`，`placeholder` 明写「点这里用微信昵称，或自己起道号」 |
| 换道相 | 「换一尊道相」按钮，循环 `variant` |
| 弹层关闭 | 点遮罩关闭，弹层内 `catchtap="noop"` 阻止冒泡 |
| 折叠记忆 | 四个折叠状态只在内存，不落盘（下次进来全关） |
| 分享 | `onShareAppMessage` / `onShareTimeline` 都在本页 |

## 7. 被否决的方案

| 方案 | 为什么否掉 |
| --- | --- |
| 首屏铺 14 条成就 | 占两屏，主角信息被挤下去 |
| 属性只写数字 | 玩家不知道该练谁 |
| 突破条件写成一个布尔 | 「战力够了却说不能突破」 |
| 气海 / 主修也打勾叉 | 它们不是门槛，会让玩家白练 |
| 称号全表放在这一页 | 与称号页重复 |
| 接微信头像 | 内容安全检测 + 域名 + 签名 URL，三份成本换一个小圆头像 |
| 折叠状态落盘 | 低频块，下次进来默认收起更干净 |

## 8. 代码指路

- `pages/profile/profile.wxml` / `.js` —— 道牒、属性格、`breakList`（三类标记）、四个折叠块
- `components/portrait/` —— 道相
- `components/term/` —— 术语
- `utils/game.js` —— `getOverview()` / `breakthroughInfo()`（`available` 与 `stoneReady` 分开）/ `getAchievements()` / `battleCode()` / `exportSaveCode()` / `importSaveCode()`
- `utils/privacy.js` —— `guard()`，昵称与剪贴板的前置
- `data/world.js` —— `attributes[].role`、四境界 `qiCap`

## 9. 待验

- 道牒里的道相在 `size="normal"` 下的尺寸与属性格之间的呼吸是否够（208 行 wxss 里没有专门给 idcard 的间距变量）。
- 突破按钮只判 `available` 不判 `stoneReady`：玩家会在「灵石不够」时点进去，虽然参悟页会拦，但**点击到被拦之间有一次无效跳转**。
- 「主修」只列 `top` 几门，具体是几门、按什么排，没有在页面上说明。
- 设置块里 12 个按钮 + 3 个折叠块挤在一屏，真机上是否需要进一步分组。
- 导出存档依赖剪贴板，剪贴板依赖隐私授权；**未授权时导出会失败但没有明确引导去开权限**——目前只靠 `privacy.guard` 的通用提示。
- 四个折叠状态不落盘：玩家如果常用「设置」里的导出，每次进来都要多点一次。
