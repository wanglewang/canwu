# 功法页与参悟页（一局的全过程）

> 功法页回答「我有什么、还缺什么」。参悟页回答「这一局怎么打」。两页之间只有一跳：点门 → 直接进静室。

## 1. 一句话

功法页 = 两个分区（已持玉简 / 藏经阁）+ 一个图鉴弹层；参悟页 = 准备态 / 局内态 / 终局态三段，**一屏之内完成一局的全过程**。

## 2. 目标与非目标

**目标**

- 点一次就到位：从功法页到开局不需要中间页；
- 一局的所有信息都在**同一屏**：印、修为、一行规则、难度、折起的「这一门」、页内换门；
- 结算必须能说清「为什么是这个评级」；
- 换门不动任何进度。

**非目标**

- 不在参悟页铺教程长文（整篇在 `topic=practice` 说明页）；
- 不做「功法详情」独立页（已删除）；
- 不在功法页就地兑换之外的购买入口（购买唯一化）。

## 3. 功法页：两个分区

```
[ 已持玉简 6 ] [ 藏经阁 13 ]
```

| 分区 | 装什么 | 排序 |
| --- | --- | --- |
| 已持玉简 | 已习得的门 | **最近练过的在前**（各门自己的 `lastAt` 倒序）→ 都没时间戳时按熟练度降序 → 再同则按正名 |
| 藏经阁 | **全部**未习得（含切磋首胜、境界前置那几门） | `rank`：换得起 → 能换但够不着 → 只能靠切磋 / 境界没到 |

### 3.1 两个排序都是设计

**已持玉简按「最近练过的在前」排**（2026-11 改）。列表回答的是「我手上有什么、昨天在练哪门」，
不是「现在该练哪门」——后者是主页「今日之课」的职责，仍由 `engine.recommendScore` 单独出。

原来这里与主页**共用** `recommendScore`（离下一段最近的在前），理由是「两处口径一致才不会打架」。
实际用下来是反的：那个分数会随进度天天变，列表也跟着天天变，玩家翻不到昨天练的那一门。
**同源的代价是把「推荐」当成了「目录」**——推荐该出现在只有一处的主页，目录要的是稳定。

时间戳由三条路写，缺一条玩家就会判定「没生效」：
① `applyPractice`（正常结算，走火也写——玩家确实练了那一局）；
② **中途收功**（`onAbandon` 的确认回调，与断连 S 同一个 `commitCritical`）；
③ **局中离开**（`onHide` 管切页 / 切后台，`onUnload` 管导航返回——返回只走后者）。
②③ 都不进 `applyPractice`，2026-11 正是漏了它们：玩家打完一局点「收功」再返回，
列表纹丝不动。**「本局作废、不计所得」管的是数值，不管顺序**——认真打了一段就该往前排。
③ 的判据是「盘面真的推进过」（`vm.progress > 0` 或得分 > 0），不是「点过开始」：
进来瞄一眼就退的不该把这一门顶到最前。

读档对旧存档兜底 0（`normalizeState`），0 表示从没练过。老存档的另一条来源是 `state.records[id].at`（本门最佳成绩的时间），
比真时间旧一点，但能让老玩家一进来就按熟悉度排上。

### 3.2 三级顺序，不是两级

```
lastAt 倒序  →  prof 降序  →  正名
```

**第二级是 2026-11 补的，起因是一次真实的翻车。** 第一版只有「时间 → 正名」两级。
上线后真机截图显示 14 门全按码点排（`4e00 4e07 4e09 4e5d 540c …` 严格递增，一眼可辨），
因为那份存档里 `lastAt` 与 `records.at` 都是 0——两级排序于是每次都落到字典序。
**字典序是最没有信息量的顺序**：玩家看到的结论是「你改了，但跟没改一样」。

熟练度是存档里唯一还带着「我投入了多少」的量，拿它兜底最差也比字典序有道理。
代价是：老存档首次打开看到的是「练得最深的在前」，不是「最近练过的在前」——
这个偏差只能靠玩一局修回来（那门的 `lastAt` 一写就跳到第一位），文案与验收都按这个说法。

比较函数在引擎里（`engine.orderLearned`），页面只写一句 `learned.sort(engine.orderLearned)`——
**放在页面里就只能做静态匹配，而这次翻车恰恰是「代码写了、数据全空」，静态断言一个字都看不出来**。
两端各守一半：`tests/layout.test.js` 静态守「页面用它、第二级还在、结算真写 `lastAt`」；
`tests/rank.test.js` 跑排序结果——复刻那份全 0 存档，断言顺序**不等于**按门名、且熟练度降序，
再练一局断言那门排到第一位（它熟练度最低，正好检验时间戳压过熟练度）。

**藏经阁按「能不能立刻换」分三段**：能换且买得起在前，能换但灵石不够其次，只能靠切磋 / 境界没到的最后。

### 3.3 一行卡片里有六样东西

```
[印]  吐纳周天诀  [黄阶]
      心法 · 节律判定 · 熟练度 1820
      连 S 2 层 · 下一局 S 51 点        ← 迷你进度条
                          [参悟]
```

- `.imm-row__mark` 印（玩法主题的 motif 单字）
- 名字 + 品阶胶囊
- `metaText`：类别 · 玩法名 · 熟练度
- 迷你进度条（`.imm-bar--thin`，`percent > 0` 才出现）
- 藏经阁分区额外一行 `costText`：能换写灵石价，不能换写获取途径
- 右侧动作按钮（`actionText` 有才有）

### 3.4 图鉴弹层：未习得也能看全本

点任意一行都开图鉴（`.modal--codex`），**锁的只有开练**。

| 段 | 内容 |
| --- | --- |
| 顶 | 类别胶囊 + 状态胶囊（已习得 / 可兑换 / 未解锁） |
| 标题 | 功法名 + 「玩法名 · 玩法 · 品阶」 |
| 正文 | `desc` 一句 + `flavor` 一句 |
| 这一局怎么打 | `previewRule` + `previewInline`，**默认折起**；展开才出 `guide.steps` / `terms` / `scoring` / `tip` |
| 这一门给什么 | `gainLines`（属性、特效、耗气…）+ 阶段新法 |
| 怎么拿到 / 练到哪 | 未习得：解锁条件 + 进度 + 境界提示；已习得：熟练度、段位、连 S 层数、最佳纪录、是否超限 |
| 底 | 次按钮「关闭」+ 主按钮（去参悟 / 兑换 / 按解锁条件跳转） |

**主按钮永远可点**：未习得不等于死路。四种去向——`practice`（已习得）/ `buy`（能换）/ `unlock.action`（切磋、攒资源、回主页）/ `home`（兜底）。

## 4. 参悟页：三段

页面根节点三态：

```html
<view class="pg pg--imm {{barMode ? 'pg--with-bar' : ''}} {{sceneOn && started && !showResult ? 'pg--scene' : ''}}">
```

| 段 | `started` | `showResult` | 盘面 | 底栏 |
| --- | --- | --- | --- | --- |
| 准备态 | false | false | 无（只有印与规则） | `start`：离开 / 代价 / 开始 |
| 局内态 | true | false | 有，可点 | `tools`：撤销 / 复位 / 提示 |
| 终局态 | true | true | **留在屏上，不可点** | `done`：上局战绩 / 返回功法 / 再来一局 |

### 4.1 准备态：只说三件事

```
[黄阶] [节律判定]                    说明 ›
吐纳周天诀                                [印]
一句风味
修为 1820 · 入门        换一门 ›
████░░░░░░  连 S ●●○○○○○○○○
下一段还差 680 · 升到小成
────────────────────────────
一行规则（guides.goal）
难度  ● 简单 7 气 ○○○○
[灵力不足 · 还差 4，去闭关或等份例]
▸ 本门新法（默认折起）
▸ 这一门（默认折起）
```

**首屏只留「标签 + 数值 + 按钮」**。眉标、说明句、hints、页脚口号、大段公式一律不上首屏——这是明确的规范，`tests/layout.test.js` 守着。

**关卡条**：中间写「第 N / 1000 关 · 已走通 X 关 · 本段 a/b 关」，两侧 `‹ ›` 逐关翻。点中间数字弹出**选关面板**：按五段分栏，先选段、再把该段已到达的关号摆成网格，直接点目标关——回打第 20 关不必从第 500 关按四百多次箭头。面板**只列已到达的关**（1–当前关），未走到的段压暗写「未至」；往上推仍只有「走通当前关」一条路，选关不改变解锁与回关折减。

### 4.2 难度条的五个胶囊

每个胶囊**各写自己的耗气**：

```
○ 简单 7 气   ● 普通 11 气   ○ 困难 17 气   ○ 极难 24 气   ○ 绝境 32 气
```

「回关便宜、当前关贵，翻关之前就看得到代价」。未解锁的段（`need` 未达）不可点。

### 4.3 三行条件提示

| 提示 | 触发 | 说清什么 |
| --- | --- | --- |
| 灵力不足 | `!canStart` | 差多少、去哪儿补、气海能装多少 |
| 回关折减 | 回打到低于当前关 | 退了几关、熟练度折到几成、S 算不算 |
| 本段收紧 | 后段 | 亮起时长 / 口诀轮数… 一一摆出来（`stageDetail`） |
| S 线 | 常态 | 本段 S/A/B/C 各要多少（`sLineText`） |

### 4.4 「本门新法」默认折起

开关要能在开局前改，但几条规则不该铺在首屏。折起态只给一行「已得的那几条长什么样」，未解锁的、被关掉的一律不列。展开后**先答一句「这是永久被动还是只有本局」**：

> 习得是永久的，效果每局从头算。

每个新法带一个开关（`stage-rule__toggle`）：想专心练基础记忆的人得有退路。关掉之后这一局就真的不触发（`perks.offTwists`）。

### 4.5 「这一门」默认折起

原「功法详情」页那几段并进来，折起。这样换门、看属性、看阶段新法都不需要离开静室。

### 4.6 关卡块下面只留三组，不堆一串同灰小字

2026-11 真机反馈：「关卡」块下面四行小字同字号、同灰度、等距堆着，分不清哪行是代价、哪行是盘面。

排法固定成三组，组间 `sp-4`、组内 `sp-1`：

| 组 | 内容 | 样式 |
| --- | --- | --- |
| 账 | `耗灵力 25` + 右端 `余 448 / 515` | `.lv-cost`，数字用 `fs-note` 加重，余额 `margin-left: auto` 推到行尾 |
| 盘面 | 整盘规格 → 这一关动了哪一处 → S 线门槛 | `.lv-spec`，组内紧排 |
| 加成 | `本局另择一门 · 触类旁通 · 耗气 ×0.92` | `.lv-note`，单独一行 |

**同一件事在这一屏只出现一次**：关号只在中间那一格，耗气只在账上，本段进度只在小节标题右侧。
`levelSub` 因此不再拼「本段 X / Y」，`levelChange` 的兜底句也不再重复本段关号——
两处都在说第三遍时，那一行就变成噪音。选关面板的竖向节奏同理：标题→副标题 8 / →段位条 32 / →网格 32 / →按钮 40。
关号网格用 `grid` 五列等宽，不用 `flex` + 固定宽（窄屏会掉成四列，整块像被啃掉一角）。

## 5. 局内态：HUD 分两套

| 套 | 条件 | 内容 |
| --- | --- | --- |
| 普通 HUD（`.hud`） | `!sceneOn` | 玩法名 + 计时 / 收功按钮 + 进度轨 |
| 舞台 HUD（`.scene-hud`） | `sceneOn` | 香炷计息、命灯、刀势刻度、局内得分 |

`sceneOn` 由 `data/visual.js` 的 `ENABLED` 决定，目前**只有刀法·开锋斩桩诀开沉浸舞台**。真机验过再逐个放开，避免一次改十套、方向错了全废。

### 5.1 局内只有两行字

```html
<view class="pr-hint">
  <text class="tiny">{{vm.hint}}</text>          ← 代价句：本门为什么难
  <view class="pr-hint__terms">
    <text class="tiny">{{guide.inline}}</text>   ← 操作句：这一手怎么点
  </view>
</view>
```

规则分三层，每层只说一次：**准备页一行 → 局内两行 → 说明页整篇**。

### 5.2 开始前有一个 3-2-1

```
凝神 · 起手
   3
轻点略过
[取消开局]
```

380ms 一跳，轻点遮罩略过（`onSkipCountdown`），点「取消开局」退出（`onCancelCountdown`）。

**为什么要有**：参悟一局十几秒，玩家从「读规则」到「手放在盘上」需要一次换气。直接开打会让前两秒全是失误。

**付不起气时不进倒计时**：`onStart` 先拦 `canStart`，`askCost()` 告诉玩家差多少。拦在起手，而不是打完再说「其实你没气」——那时盘的功夫已经白费。

### 5.3 局中离开：三条路都要问一句，账只结一次

| 出口 | 拦法 | 结果 |
| --- | --- | --- |
| 局内右上「收功」 | 自绘按钮 + `wx.showModal` | 本局作废、连 S 归零、记钟 |
| 左上角返回（导航栏 / 安卓 back 键） | `wx.enableAlertBeforeUnload` 原生询问 | 同上 |
| 切页 / 切后台 | 拦不住，`onHide` 事后结账 | 同上（不弹窗，账照结） |

**为什么要一致**：同一个页面两种脾气——带字那个会问「确定收功？」，只有箭头那个一句不问就把牌扔了，
玩家学不会哪条路要小心。2026-11 真机反馈原话是「我点返回，他不应该提示收工吗」。

**只有官方这一个口子。** 小程序 `Page` 没有 `onBackPress`，原生导航栏的返回拦不到；
`wx.enableAlertBeforeUnload`（基础库 2.12.0+）是唯一入口，导航栏返回与安卓 back 键会先弹一次询问。
它拦不住的两条必须写在这里：**iOS 侧滑手势官方明确不支持拦截**、**退出小程序也不拦**——
所以 `onUnload` / `onHide` 那两笔事后结账不能省，也不许因为「已经有弹窗了」就把它们删掉。

**撤守卫的点比挂守卫的点更危险。** 出结算（`onFinish`）、留在终局那一屏（`onStay`）、
再来一局（`onAgain`）、自己调 `navigateBack`（`onBack` / `onSecondary`）、倒数里反悔（`onCancelCountdown`）、
离开页面（`onHide` / `onUnload`）——每一处都要 `disarmLeaveGuard()`。漏一处的后果是：
玩家在「这局早打完了」的结算卡上点返回，被问一句「本局作废」。

**两处文案同源**（`abandonText()`）：收功弹窗问「确定收功？」，返回询问只放前半句（原生弹窗自带确定/取消）。
冲关局另写一句——它起手不扣灵力（布阵灵石要到结算才扣），沿用练习局那句「起手耗去的灵力不退」是假话。

**账结在 `closeAbandonedRound()`**：断连 S（`engine.breakCombo`）+ 记钟（`markTouched`）。
只在 `inRound()`（在局内、没出结算、没留在终局屏、非教学）时结，`roundClosed` 挡重入——
`onHide` 之后紧接 `onUnload` 会各调一次。**「本局作废」管的是数值，不管顺序**：
数值一笔不给，但这一门要记钟，否则玩家打一段就退，回去列表纹丝不动。

`onHide` 仍会 `controller.destroy()`，所以说明入口**只能放在开局前**，局中不提供。

## 6. 终局态：两种结算呈现

| 条件 | 呈现 |
| --- | --- |
| `sceneOn` | 五段演出 `.settle`（暗场 → 评级 → 熟练度条 → 奖励逐条 → 按钮淡入） |
| `!sceneOn` | 标准弹层 `.modal--reveal`（评级圆章 + 三行结果 + notes + 称号 + 按钮） |

### 6.1 五段演出的时间线

```js
// data/visual.js
SETTLE.full  = [0, 300, 700, 1200, 1800];   // S / A
SETTLE.short = [0, 150, 350, 600, 900];     // B / C / F
```

**S/A 满演出；B/C/F 压到 900ms**——一局才十几秒，不让人天天等演出。任意时刻点一下即跳过（`onSkipSettle`）。

### 6.2 结算卡的按钮分工

| 位置 | 文案 | 做什么 |
| --- | --- | --- |
| 底栏左 | 上局战绩 | `onOpenRecord`，把刚收起的明细叫回来重看 |
| 底栏中 | 返回功法 | `onBack`（退出本页） |
| 底栏右（金） | 再来一局 | `onAgain`——多数人打完还想连刷 |
| 卡内主按钮 | 再来一局 | 同上 |
| 卡内次按钮 | 返回 | 普通结算 `onBack`；**收功结算** `onQuitToPrep`（回本门准备屏） |
| 卡内文字链 | 留在本页 › | `onStay` |

**「留在本页」留的是刚打完那一屏**：`started: true` + `boardHeld: true`、控制器摘掉、底栏换成 `done`。不许落回准备页。

`buildGame` 与 `onAgain` 都要清 `boardHeld`。

**「返回」回的是本门静室，不是功法列表。** 2026-11 真机反馈：收功结算卡上点「返回」落回整张功法列表，
玩家要的是「这一门功法的详情」——**那一屏就是本页的准备态**（品阶、火候、连 S、本门最佳、入门规则、本局法度、
底部「暂且退去 / 开始参悟」）。所以「多退了一层」不是 `navigateBack` 退多了，是这一层本来就不该退出页面。

`onSecondary` 遇到 `result.kind === 'abandon'` 走 `onQuitToPrep()`：摘控制器、清 `aborting` 与 `roundClosed`、
`started/boardHeld/showResult` 归零后 `refresh()`。两个标记必须一起清——`aborting` 留着，下一局的正常结算
仍会被当成「收」；`roundClosed` 留着，下一局中途离开不记钟不断连 S。

出口不叠在结算卡上：想离开页面走左上角原生返回，或准备屏底部的「暂且退去」。
上一版试过「回功法页再自动弹这门的详情」，是个浮层，玩家明确不要浮层要真页面，已撤。
冲关局没有「这一门」，次按钮仍 `switchTab` 去功法页。

### 6.3 结算卡必须能说清「为什么」

`result.notes` 至少两条，由玩法模块的 `notesOf()` 生成：

> · 用时 21 秒 · S 线 18 秒、A 线 26 秒。
> · 点错 2 次，罚了 4 秒：别用手指追着数走，目光放中间、用余光扫四周找下一个数。

**第二行是「怎么改进」，不是「你差在哪」**。这是 `notesOf()` 的写法约定。

### 6.4 主动收功与走火是两个结论

- `aborting = true`（点了「收功」）→ 结算报「收」，**不进 `applyPractice`**，但要调 `engine.breakCombo()` 把连 S 归零；
- 走火（`F`）→ 正常结算，这一局没收益，连 S 归零；
- 点左上角返回 / 切页走人 → 不走结算，同样由 `closeAbandonedRound()` 断连 S（2026-11 补）。

靠页面的 `aborting` 标记区分，**不许让玩法层猜**。突破局的「气机一乱」不是参悟，不断连。

**为什么返回也要断**：收功弹窗里写着「连 S 归零」。如果只有点收功才兑现，
那「预感这把拿不到 S 就按返回」就成了一条不花钱的保连击路子——便宜的永远是绕过弹窗的那条路。
`tests/layout.test.js` 守着 `closeAbandonedRound` 里两件事都在（记钟 + `breakCombo`），
并守着 `onHide` / `onUnload` 都调它（返回只触发 `onUnload`）。

## 7. 换门

`.pr-links` 里一个「换一门 ›」，打开 `swapOpen` 弹层：一层已持功法列表，点一门就整页重开。

> 换的是这一页对着哪一门，进度一点不动。

`swapList` 带 `current` 标记。换门后 `buildGame()` 全量重建——因为玩法内核都换了。

## 8. 被否决的方案

| 方案 | 为什么否掉 |
| --- | --- |
| 「功法详情」独立页 | 多一跳；详情并进参悟页的折起区 |
| 准备页铺 `guide.steps` / `terms` | 首屏变说明书；三层规则各说一次 |
| 局中开「说明」入口 | 切页即作废，等于强制弃局 |
| 关卡行只写关号不写耗气 | 开局前看不到这一局要烧多少 |
| 结算不给 notes | 玩家不知道「差在哪、怎么改」 |
| B/C/F 也播满演出 | 一局十几秒，天天等 1.8 秒演出 |
| 「留在本页」落回准备页 | 玩家刚打完，想留着看盘 |
| 功法页默认按品阶排 | 高熟练度功法永远霸榜 |

## 10. 待验

- **两种结算呈现的维护成本**：`sceneOn` 与 `!sceneOn` 各有一整套结果 UI，字段（`result.lines` / `notes` / `titles` / `primary` / `secondary` / `canStay`）要一直保持同构。目前只有刀法走 `.settle`，其余 18 门走 `.modal--reveal`——**放开第二门舞台玩法时，这两套必须逐字段对齐**。
- 倒计时 380ms × 3 ≈ 1.14 秒，加上读规则，从点「开始」到能动手约 2 秒。在「连刷」场景下这个仪式感是否变成负担（`onAgain` 也会重新走倒计时）。
- 结算卡 `canStay` 与底栏 `done` 是两条并行的「留在本页」路径，文案一个是「留在本页 ›」一个是「上局战绩」，容易混淆。
- 功法页两个分区的排序各有一套逻辑（`lastAt` / `rank`），换分区时顺序会整体跳动，玩家可能误以为「功法变了」。
- 「本门新法」的**折起态**只汇总「已得且未关」的条目（`stageBrief` 过滤 `enabled`），展开态才列全部并带开关。这意味着：如果玩家关掉了唯一一个新法，折起那一行就没有内容可摘要——此时折叠区是否还应该出现，需要看真机上是否显得空。
- 开关状态 `twistsOff` 落进存档（按功法名存），改功法名会让旧状态失配。目前功法名是稳定的，但这是一条隐性的耦合。
- **选关面板的真机手感**：圆满段（501–1000）一次铺 500 个关号格，需确认滚动是否卡、首帧能否准确滚到当前关（`pickerScrollTo` 靠 `setTimeout` 延迟设值），以及 92rpx 的格子在小屏上会不会误触相邻关。
