# 主页（导航中枢）

> 一屏回答四件事：我现在什么境界、有多少资源、下一步该做什么、还有哪些地方可去。

## 1. 一句话

主页**不是**功能首页，是**导航中枢**：一张境界卡 + 一行提示 + 最多两条待领 + 一块六宫格 + 一个吸底主操作。

## 2. 目标与非目标

**目标**

- 冷启动 3 秒内能看懂「我在哪、还差多少」；
- 「下一步」永远只有一句，不需要读完一段；
- 六宫格每一格都进**自己的页面**，不借道别的 tab；
- 有改动待同步 / 同步出错时，在顶部一条窄带里说清，不打断操作。

**非目标**

- 不在主页铺说明文字（原理在「说明」页）；
- 不把低频功能（称号、成就、背包、设置、诸界）放首屏；
- 不在这里直接开局——开局在参悟页，那里才有难度与规则速记。

## 3. 屏幕结构（自上而下）

| 序 | 元素 | 类 | 出现条件 |
| --- | --- | --- | --- |
| 1 | 同步窄带 | `.alert-bar` | 仅 `syncTone !== 'ok'` |
| 2 | 状态占位 | `.state` | 加载 / 出错 |
| 3 | 境界卡 | `.imm-panel` | 常态 |
| 4 | 一句提示 | `.imm-hint` | 常态 |
| 5 | 打坐行 | `.imm-list > .imm-row` | `idleReady` |
| 6 | 份例行 | `.imm-list > .imm-row` | `dailyReady` |
| 7 | 六宫格 | `.imm-grid` | 常态 |
| 8 | 吸底主操作 | `.sticky-bar > .imm-btn` | 常态 |
| 9 | 闭关收获弹窗 | `.mask > .modal` | 冷启动有离线收益 |
| 10 | 页尾说明链 | `.pg__foot` | 常态 |

**「正常状态不占任何文字」**：同步窄带在 `syncTone === 'ok'` 时整块不渲染，首屏不为它留空行。

## 4. 境界卡：五个数

```
[角色名]                        [境界 2 / 4]
筑基
████████████░░░░░░   ← breakPercent
突破 战力    45 / 75
战 力 45 | 灵 力 96/174 | 灵 石 23
```

- **`breakPercent`**：`min(100, round(突破战力 / 下一境界门槛 × 100))`；已大圆满给 100；
- **进度条上方一行**：`突破 战力 45 / 75`，已满则写「突破 已至大圆满」；
- **三个数**：战力 / 灵力（带 `/上限`）/ 灵石。灵力的分母用 `.imm-stat__cap` 压成注脚。

为什么三个数而不是更多：**战力是目标、灵力是油、灵石是钱**。其余（属性、称号、熟练度）都不是「一眼要看」的。

## 5. 一句提示：优先级是设计出来的

`hintText` 有明确的挑选顺序，这个顺序本身就是设计：

| 优先 | 条件 | 文案 |
| --- | --- | --- |
| 1 | `ov.qiFull` | 灵力已满 X / Y · 去参一局，气海存不住更多了 |
| 2 | 有门功法 `percent >= 75` | 「某诀」即将升段 |
| 3 | `bt.available` | 境界已足，可去人物页突破 · 突破后战力 +N |
| 4 | 未满级 | 距「金丹」还差 N 战力 · 突破后 +M |
| 5 | 兜底 | 今日之课：某诀 |

**为什么「灵力已满」排第一**：气海满了，挂机一分钟都不再生——这是**运营层面的损失**。升段只是进度上的好消息，损失优先于好消息。

第 4 条特意带上「突破后 +N」：缺口是个冷数字，只说「还差 30」玩家算不出攒战力有什么用。

## 6. 两条待领行

| 行 | 触发 | 右侧 | 行为 |
| --- | --- | --- | --- |
| 闭关打坐 | `idleReady` | 「收下 ›」 | `engine.meditate()`，toast 回执 |
| 今日份例 | `dailyReady` | 「领取 ›」 | `engine.claimDaily()` |

这两条都用 `.imm-list` 包一层（单行成组），而不是裸按钮——它们在语义上是「有东西等你拿」，不是「操作」。

**打坐行的三种文案**：

- 有灵力可收：`已坐 12 分 · 灵力 +6 / 上限 174`
- 灵力已满：`灵力已满 174 · 只涨熟练度`（**满池不挡打坐**，它还在涨熟练度）
- 附带熟练度：`· 吐纳诀 +1`

**为什么灵力取整可能为 0**：一分钟只有 0.5 点。`qi >= 1 || prof >= 1` 才出现这一行——写「灵力 +0」比不出现更糟。

**份例相反**：份例满池时**直接拒绝领取**（它是发放的，可以等人来取），打坐满池**照收**（它还能收熟练度）。两条口径不一样，代码里是两套分支。

## 7. 六宫格

| 格 | glyph | 去向 |
| --- | --- | --- |
| 仙门切磋 | 剑 | `/pages/battle/battle` |
| 秘境探索 | 秘 | `/pages/secret/secret` |
| 战力仙榜 | 榜 | `/pages/board/board` |
| 称号簿 | 印 | `/pages/titles/titles` |
| 修行日志 | 录 | `/pages/log/log` |
| 玩法说明 | 典 | `/pages/guide/guide` |

三条规则：

1. **每一格都进自己的页面**，不许 `switchTab` 去别的 tab 借道（历史上「修炼」格是唯一违背这条的，现在已不存在）；
2. **glyph 用汉字单字**，不用 `⚔ ✦`：这类字符在部分机型会被渲染成彩色 emoji，与墨底金线拼在一起非常跳；
3. **宫格是一整块 3×2 细线格**，不是六个小盒（见 `03-components.md` 的边框数学）。

数据在 `data/navigation.js` 的 `TILES`，`verify` 核对每一条 `url` 都是已注册页面。

## 8. 吸底主操作

```html
<button class="imm-btn imm-btn--block" bindtap="onQuickPractice">{{quickLabel}}</button>
```

`quickLabel` 分两种：

- 有推荐功法：`参悟 · 吐纳诀`
- 没有：`去功法页`

**「参悟」进的是参悟页，不是开局**。难度档、规则速记、上一局评价都在那一屏——原来中间还有一层「功法详情」页，那一跳已经并掉。

推荐功法来自 `engine.recommend(state)`，与功法页默认排序**同源**。这一点很重要：两处排序算法分叉，就会出现「主页推荐 A、功法页第一是 B」。

## 9. 闭关收获弹窗

冷启动时 `store.consumeOfflineReport()` 有报告才弹：

```
闭关收获
离线 3 时 12 分 · 最多累计 8 小时
灵力   +96 / 174
气海已满，散去的 12 点未收     ← 仅溢出时
吐纳诀 熟练度  +8
```

**「坐出来的 / 装得下的 / 溢出的」三个数要分开说**。只报「+96」而不提溢出，玩家会以为算法吃了他 12 点。溢出当场散掉，这是设计而不是 bug，但必须写清。

## 10. 交互细节

| 细节 | 做法 |
| --- | --- |
| 按压反馈 | 所有可点 view 挂 `hover-class="pressable--on"`（透明度 0.86 + 缩放 0.995） |
| 定时刷新 | `onShow` 起一个 30 秒定时器，只重算打坐那一行；**先清再挂**，避免两次 `onShow` 叠出第二个定时器 |
| 退后台 | `onHide` / `onUnload` 清定时器 |
| 同步重试 | 点窄带 → `store.flushCloud()` → toast → 整页重算 |
| 分享 | `onShareAppMessage` / `onShareTimeline` 都落在本页 |

## 11. 被否决的方案

| 方案 | 为什么否掉 |
| --- | --- |
| 主页铺一段说明文字 | 首屏只留「标签 + 数值 + 按钮」，原理进说明页 |
| 六宫格改回五个 tab | 低频功能占 tab 位，最高频的「修炼」反而藏起来过 |
| 「修炼」格里放功法横滑 | 主页变成第二个功法页 |
| 提示写两句 | 两句等于没有重点 |
| 同步窄带常驻 | 正常状态不占文字 |
| 离线弹窗只报总灵力 | 溢出被当成 bug |

## 13. 待验

- 境界卡 + 提示 + 两条待领 + 六宫格，在 4.7 寸屏上是否要滚一屏才看到六宫格底部；**六宫格是导航中枢，理想情况应在一屏内完整可见**。
- `onBreakthrough` 在 `index.js` 里仍然存在，但 `index.wxml` 没有对应的按钮——**看起来是遗留方法**（六宫格没有「突破」格，突破入口在人物页）。应确认后删除或确认有动态绑定。
- 30 秒定时器在后台被系统挂起后恢复，是否会一次性补很多次回调（小程序一般不会，但低端安卓需要确认）。
- 提示第 2 条（`percent >= 75`）没有考虑「这门已经超出可修上限」的情况，会对一个练不动的门说「即将升段」。
