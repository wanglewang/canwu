# 视觉语言：墨底、旧金、青玉与「墨玉台、暖玉牌」

> 全站恒定深色。一支墨底、一支暖白、一支旧金当唯一强调、一支青玉只标进度。参悟页是唯一的例外：**盘面是一方玉局（墨玉台 + 暖玉牌），其余是墨**。

## 1. 一句话

这不是「深色主题的浅色产品」，是**一套只有四个色相的自洽皮肤**：墨（底）、暖白（字）、旧金（强调）、青玉（状态）。任何一个新页面、新组件，只能在这四支里取色。

## 2. 目标与非目标

**目标**

- 一屏之内不超过四支色相，玩家不会在配色上分心；
- 数字与主操作永远最亮，其余退成描边与字重；
- 中文排版不靠字距、不靠衬线体、不靠装饰符号撑「国风」；
- 系统切到浅色模式，**任何一页都不许翻色**。

**非目标**

- 不做「浅色版 + 深色版」两套主题；
- 不做四角金饰、大圆角气泡、发光描边这类「仙侠 UI 皮肤包」元素；
- 不用 ✦ ✿ ◆ 这类 dingbat 当装饰（部分安卓会渲染成彩色 emoji）。

## 3. 四支色相的分工

| 色 | 令牌 | 值 | 只用来做什么 |
| --- | --- | --- | --- |
| 墨 | `--c-imm-bg` | `#0c1311` | 页面底、登录页底、原生导航栏、tabBar |
| 暖白 | `--c-imm-text` | `#ece5d8` | 正文、卡片标题、面板主文字 |
| 旧金 | `--c-imm-gold` | `#cfae6d` | **唯一强调**：数字、当前项、主操作、可点的文字链 |
| 青玉 | `--c-imm-jade` | `#8fbfa9` | **只标进度与「进行中」**：进度条填充、已走通的秘境、「已首胜」标签 |

对比度（WCAG，均已实测）：正文 **13.4:1**、次文字 **6.9:1**、金色 **7.9:1**，全部高于 AA。

**上一版为什么被推翻**：米金底 + 薄荷青 + 荧光青 + 绿灰四处并发，字还偏绿，整页发浑发荧光。这一版把强调色收成一支金，青玉只留在进度上。

## 4. 层级只靠三件事

字号、字重、透明度。**不靠颜色数量，不靠装饰**。

| 层级 | 用什么 |
| --- | --- |
| 主标题 | `--fs-h1`（54rpx）+ 700 |
| 姓名 / 强调标题 | `--fs-lead`（40rpx）+ 700 |
| 卡片标题 / 数值 | `--fs-h3`（32rpx）+ 600 |
| 区块标题 | `--fs-subhead`（30rpx）+ 600 |
| 正文 | `--fs-body`（28rpx）+ 400 |
| 次要 / 密集文本 | `--fs-body-sm`（26rpx） |
| 注脚 / 角标 | `--fs-caption`（22rpx） |

**明确不做**：

- 标题不加字间空格（`letter-spacing` 只给角标与品牌字，4rpx）；
- 不挂衬线体（`app.wxss` 里 `.serif` 类还在，但页面一律不用）；
- 标题前后不加 `✦`、不加 `·` 分隔装饰。

## 5. 「墨玉台、暖玉牌」——唯一的实物质感区

参悟页的盘面是全站唯一的实物：一块深色台，上面摆一片浅色牌。

- **台（`.grid` / `.klotski` / `.scroll` / `.orbit` / `.ring-area`）取 `data/visual.js` 按功法族注入的 `--well`**：兵刃墨青、心法墨绿、丹道墨褐、阵法墨紫。同一个灰阶，四个色相。
- **牌取 `styles/tokens.wxss` 的 `--jade` 一副**（`--jade` 面 / `--jade-paper` 凹槽纸 / `--jade-dim` 暗玉）：19 门共用，换门不换棋子，像同一副棋换棋盘。
- 其余一切（HUD、底栏、结算）仍是 `--c-imm-*` 的墨。

为什么台要深：格子里要写字、要放图案、要读颜色差异。**牌必须比台亮六七倍**，牌才立得起来。旧版是「纸白底上摆纸白牌」，两者只差 1.1:1，远看就是一整块发光的白板——那正是「加了花纹还是不好看」的根。

台深了以后，「凸 / 凹」这对物理隐喻才真的成立：

- 未翻开的格子是**玉牌**：顶缘 2rpx 高光、底缘 7rpx 赭色厚度、牌下一条落影，四周留 8rpx 台色沟槽（边框取 `--well`，格子仍按百分比铺满，不必算 `calc()`）；
- `.cell--open` 吃内阴影，变成**凹槽里的旧纸**（`--jade-paper`）。

**这条比配色更有效**：玩家分得清「能点」与「点过了」，不需要靠颜色区分。

## 6. 按钮只有两支

| 支 | 类 | 高度 | 用在哪 |
| --- | --- | --- | --- |
| 金色实心（主操作） | `.imm-btn` | `--touch`（88rpx） | 一屏只能有一个：开始参悟 / 再来一局 / 微信登录 / 突破境界 |
| 细描边（次操作） | `.imm-btn--ghost` | 88rpx 或 `--sm` 64rpx | 返回、导出、撤销、复位…… |

两条硬规则：

1. **`line-height: 1`**。微信 `button` 默认行高 2.55，不锁死会让两枚并排按钮一高一低；
2. **金色按钮的底色写在 `background-color`、明暗层次单独挂 `background-image`**。写成 `background: linear-gradient(...)` 且色标是变量时，任何一次变量解析失败都会让整条 `background` 失效，按钮退化成「一行没有底色的字」——真机上极难排查。

`.imm-btn--danger` 不是第三支，它是 `.imm-btn--ghost` 的修饰：金色描边 + 警示红字，只用于「重置存档 / 退出登录」这类不可撤销操作。

## 7. 原生导航就是唯一导航

- 页面 `json` 的 `navigationBarTitleText` 与原生返回箭头承担全部导航；
- 页内**不画**标题、不画 `‹`、不画第二个返回；
- 「说明」这类低频入口沉到页尾 `.pg__foot` 一行小字；
- `navigationBarBackgroundColor` 与 tabBar 三色必须与令牌同值（`#0c1311` / `#7d8a83` / `#cfae6d`），`scripts/verify.js` 逐项核对 `theme.json`。

历史上曾有一个 `.imm-head`（右上角单字动作）和 `.pg__head`（眉标 + 标题 + 说明），两者都已删除——它们等于第二层导航。

## 8. 反例：被否决的具体做法

| 做法 | 为什么否掉 |
| --- | --- |
| 浅色 / 深色双主题 | 两套都要维护，且割裂「仙门」的沉浸；用户明确要恒定深色 |
| 强调色给三支（青 / 金 / 赭） | 上一版就是这么发浑的；一屏只能有一个「看这里」 |
| 四角金饰 + 大圆角气泡 | 皮肤包审美，与「1rpx 细描边 + 大块留白」相反 |
| 标题加字距做「古典感」 | 中文加字距只显得松散，不显得古 |
| 用 dingbat 当分隔 | 部分安卓换成彩色 emoji，与墨金撞色 |
| 盘面也做深色 | 格子里读不出数字与图案差异 |
| 发光描边做层次 | 低端机上发光靠多层 `box-shadow`，掉帧 |

## 9. 代码指路

- `styles/tokens.wxss` —— 全部颜色 / 字号 / 间距 / 圆角 / 阴影 / 层级 / 触控 / 动效令牌，**唯一真源**
- `styles/immortal.wxss:18` —— `.pg--imm` 把 `--c-*` 映射到 `--c-imm-*`
- `app.wxss` —— 全局基础层（`.pg` / `.card` / `.btn` / `.state` / `.modal` / `.sticky-bar`）
- `theme.json` —— 原生导航与 tabBar 的 `@变量`，与令牌同值
- `tests/layout.test.js` —— 守着「页面不许画第二个标题」「页面名必须等于宫格入口名」
- `scripts/verify.js` —— 核对 `theme.json` 与令牌同值、页面根节点挂 `.pg`、无裸色值

## 10. 待验

- `.pg--imm` 是**类选择器**：一旦某页根节点漏挂它，页面会退回 `tokens.wxss` 的浅米底 + 深色字，整页看着像「几行没有样式的纯文字」。登录页为此做了双保险（直接取 `--c-imm-*` 而不取映射后的 `--c-bg`）。其余页面没有这层保险，靠 verify 断言兜。
- 恒定深色下，系统「深色模式」的 `@media` 段只剩 `tokens.wxss` 的暗色令牌与 `.grade` 兜底。若以后新增页面忘了挂 `.pg--imm`，会在这段里翻成暗色而不是浅色——**症状更隐蔽**，需要断言的覆盖继续跟上。
- 旧金 `#cfae6d` 在强光下的可读性（户外场景未实测）。
