# 大成（满级后重复冲关 · 突破档位）

> 本门不进参悟序列，五篇按突破档位分，不是关号段。
>
> 元婴已是四境界的最高一境。这一档按用户拍板单列，讲规则沿用与重复挑战的成本，不编造关号或新收益。

**这一档为什么存在**：这一档是按用户拍板单列的，讲的是「满级后重复冲关」这件事——但我得先说清事实：元婴已是四境界最高一境，原文和代码都没有「满级后继续冲关」的新规则、关号或收益，当前 `applyBreakthrough()` 在 `maxed` 时直接挡回「尚未到突破之时」。所以这里不编造一个不存在的玩法，只沿用全套骨架，据实标注。

## 1. 这一档的盘与代价

下面这张表在回答什么：满级这一档的现状——规则沿用，但实际并不开启新冲关。

| 项 | 取值 | 来源 |
| --- | --- | --- |
| 突破档位 | 满级（元婴）后重复冲关 | `data/world.js` 四境界：炼气 / 筑基 / 金丹 / 元婴 |
| 境界状态 | `maxed = realmIndex >= realms.length - 1` 为真 | `breakthroughInfo()` |
| 区间宽 | 规则沿用（16 / 22 两支），不新增规格 | `zoneWidth = 16 + (perks.easy ? 6 : 0)` |
| 布阵灵石 | 准备页 `stoneCost = 0`（满级不备阵材） | `breakthroughInfo()`：`maxed ? 0 : …` |
| 实际冲关 | `applyBreakthrough()` 在 `maxed` 时返回「尚未到突破之时」，不扣灵石、不进境界 | `utils/game/realm.js`（`applyBreakthrough` 的 `maxed` 分支） |
| 失败退回 | 不适用（当前实现不开启新冲关） | 同上 |
| 落点 / S 窗 | 规则沿用：26 个落点、S 窗 1–2 格（55–110ms） | `gradeAt()` |

**据实标注**：原文与代码都没有「满级后继续冲关」的新规则、关号或收益；这一档只沿用上面全套骨架，
不编造数字。按当前实现，满级后 `available` 为 false，`applyBreakthrough()` 直接挡回（见 §6）。

## 2. 盘上长什么样

- 若重复冲关发生，盘面仍是同一条蓄力条：0 → 100 → 0 往复，tick +4、55ms 一跳，26 个落点。
- 红线区间仍每局随机：起点 42%–71%，终点 `min(96, 起点 + 区间宽)`；宽仍是 16 / 22 两支。
- HUD 仍报「距正中 N% · X 评」；状态栏「气机正盛…松手定生死」，banner「一线之间」。
- 没有为「满级后」新增任何标记、格子或第二套操作。

## 3. 评级与代价

判定与评级全套沿用总览 §2 的 `gradeAt()`，本档不新增阈值。

| 评 | 规则沿用下的结果 |
| --- | --- |
| S | 突破成功，结算卡标「破关」 |
| A / B / C | 突破成功（C 起步全算过） |
| F | 失败：退一半灵石、境界不变 |

关键仍是「只有 F 是失败、评级不换收益」——若满级后真有重复挑战，S 也只换结算卡上的一个字母，
不会变成可刷的收益梯度（依据见总览 §4.6「按评给不同突破收益」被否）。

## 4. 这一档在教什么

我这一档写的是**重复与挑战成本**。这一档按用户拍板单列，讲的是同一套「手要稳」的动作如果被反复挑战，
成本结构如何：规则不变、S 不换收益、F 退一半；而满级本身没有新境界可进。
按当前实现，`applyBreakthrough()` 在 `maxed` 时返回「尚未到突破之时」，并不真的开启重复冲关——
所以这里不描述一个原文和代码里都不存在的「满级冲关玩法」。

## 5. 会在哪失手

- **把「满级」当成还能再冲一境**：当前实现会直接挡回「尚未到突破之时」，不会扣灵石，也不会进境界。
- **若未来真的开放重复冲关**：失手口径仍按全套规则——松手落区间外 → F，退一半灵石；中途结束也是 F。
- **S 窗仍是 1–2 个落点**：想拿结算卡上的「破关」，精度门槛不会因为满级而放宽。
