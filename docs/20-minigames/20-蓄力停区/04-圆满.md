# 圆满（极限与待验 · 突破档位）

> 本门不进参悟序列，五篇按突破档位分，不是关号段。
>
> 这一档不是新境界，而是全套骨架的边界：S 窗 55–110ms、死代码、封顶不触发，以及全部待验。

**这一档为什么存在**：这一档不是新境界，是我把全套骨架推到极限处审一遍——S 窗窄到几十毫秒却只换一个字母、`hard` 分支写了却走不到、终点封顶从来不触发、宽 22 到底明不明显、长按的触控风险、中途结束也算 F。它教的不是新操作，而是诚实回答一个问题：这套突破动作究竟卡在哪。全部待验也集中在这里，一处说清。

## 2. 盘上长什么样

- 蓄力条 0 → 100 → 0 往复，tick +4、55ms 一跳；满程 25 跳 ≈ 1.375 秒，往返 ≈ 2.75 秒，26 个落点。
- 26 个落点里，宽 16 的区间内只有约 5 个落点：正中 ±1 格 = S、±4 = A、±8 = B、区间外 = F。
- HUD 每一跳都报「距正中 N% · X 评」——玩家是**看着读数瞄**的，这正是 S 窗必须窄的原因（总览 §4.2）。
- 红线区间每局随机：起点 42%–71%，终点 `min(96, 起点 + 宽)`；`min(96, …)` 这支封顶从不触发（见 §6）。

## 3. 评级与代价

判定见总览 §2 的 `gradeAt()` 全文，本档不另造阈值；只把 §2 的档位线套到极限处：正中 ±1 格 S、±4 A、±8 B、区间外 F。

| 评 | 结果 |
| --- | --- |
| S | 突破成功，结算卡标「破关」 |
| A / B / C | 突破成功 |
| F | 失败，退一半灵石，境界不变 |

**S 不换收益，是它敢做这么窄的前提**：严苛只影响结算卡上那一个字母，不影响能不能过。
若 S 窗放宽到 ±10，「看着 HUD 等它跳到 S 再松手」就是无脑操作（总览 §4.2、§4.6）。

## 5. 会在哪失手

- **手抖一下**：正中 ±1 格的 S 窗只有 55–110ms，极易掉到 A / B；落在区间外直接 F、散一半灵石。
- **等两个来回再松手**：按住时长到 4–5 秒，持续触控可能被系统手势打断（尤其全面屏机型边缘上滑）。
- **中途结束**：也是 F、也退一半——玩家可能以为「点了取消就不算数」。
- **指望 `hard` 分支或封顶生效**：这两支当前接线都取不到 / 从不触发，别拿它们当难度来源（见 §6）。

## 6. 这一档的待验

- **S 窗只有 1–2 个落点（55–110ms）**，这是全站最苛刻的一处精度要求。真机上是否有人拿到过 S；若长期无人拿到，应把 `dist <= 3` 放宽到 `<= 5`。
- `hard ? 11 : 16` 这一支**当前接线取不到**（突破局 `difficulty` 恒为 `easy` → `gear` 恒为 `normal`）。要么删掉这个分支，要么给突破局接一个真正的难度来源；现状是「写了但走不到」，属于死代码。
- 区间起点 42–71、宽 16 时终点最远到 87，`min(96, ...)` 的封顶只在起点 ≥ 80 时才生效——而起点最大 71，所以**这支封顶从来没触发过**。
- 金丹起区间宽 22（+6）是否足够明显：22 宽在 26 个落点里约 5–6 个，S 仍只有 1–2 个。
- 长按 1.375 秒只是单程；若玩家等两个来回再松手，按住时长会到 4–5 秒。持续按住期间是否有触控被系统手势打断的风险（尤其全面屏机型边缘上滑）。
- 中途结束也是 F、也退一半——玩家会不会以为「点了取消就不算数」。
