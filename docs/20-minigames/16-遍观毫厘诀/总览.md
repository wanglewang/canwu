> 数打散在盘上，从 1 顺着点到最后；点完整盘才算走完。练的是目光一路扫过去、不乱、不回头。
>
> 五段六篇：本篇放五段共用的骨架（盘 / 规则 / 扫法 / 评级 / 依据 / 界面 / 代码），

- 功法：神识·遍观毫厘诀（黄阶，variance 波动下限 +4%）｜玩法 id：`schulte`（模块 `schulte.js`，名为「顺序点格」）

## 1. 盘面骨架（五段共用）

N×N 方格，N 取 4 / 5 / 6 / 6 / 7 五段。格子里写着 1 到 N²，打乱分布。

- 数字**直接显示**——这一门的全部难度就是「读数字、扫位置」，换图案等于换玩法；
- **不标下一个在哪**：HUD 只报「下一个 7」，7 在哪得自己扫出来；
- 点过的格分两种处理，由段位定：
  - 前三段**退场**（`.cell--gone`：玉牌被取走，只留一个空位），盘面越点越空，找数时能借这个势；
  - 极难、绝境**不退场**：点过的格与没点的一模一样，盘面始终是满的，找数只能靠眼。

两种都不标「哪一格是待找的」——那是这一门的底线（见 §4.2）。退场只是缩了搜索面，
等于替「已经走过一遍」这件事记账，不是替玩家找位置。

## 2. 规则骨架（五段共用）

| 项 | 规则 |
| --- | --- |
| 完成条件 | 把 1 到 N² 全按序点完 |
| 点错 | 不换格、不扣进度，**罚时**并把错误计数 +1 |
| 计时 | 从开局第一秒起算，`用时 = 实际经过 + 累计罚时` |
| 走火（F） | **实际经过**到时辰还没点完 → F，这一局没有收益 |
| 得分 | `(B 线 − 用时) × 10 + N² × 10`，只用于破纪录 |

三件事必须分清，这是这一门最容易写错的地方：

1. **罚时进「用时」，不进「剩多少时辰」**。HUD 上的倒计时只走实际时间，错一次不会跳掉 2 秒。
2. **走火只看实际经过**。以前判据是「实际 + 罚时」，于是圆满段连错四次就能把一局
   本来打得不错的人判成 F ——「点错只是纪录变差」这句话当场变成假话，也和本门
   「只奖不罚」的调性相反。现在罚时最多把你从 S 拖到 C，不会提前收场。
3. **点完整盘才是 C 起步**；没点完一律 F。

评级口径：只看用时，含罚时。

| 评 | 判据 |
| --- | --- |
| S | 用时 ≤ S 线 |
| A | 用时 ≤ A 线 |
| B | 用时 ≤ B 线 |
| C | 点完了但超过 B 线 |
| F | 实际经过到时辰还没点完 |

**这一门最低到 C，不会给 F 除非真的没走完**——与「走火」的语义一致：F 是「一局没走完」，
C 是「走完了但糙」。

C 带（时辰 − B 线）必须始终为正：10 / 14 / 18 / 16 / 22 秒，段内收紧后也不低于 8 秒
（`C_WINDOW`）。掉到 0 的后果不是「变难」，是「过 B 线的人被判走火」，C 这一段当场消失。

### 操作与扫法

单点。点对即前进，点错即罚时。没有拖拽、没有方向键、没有长按。

扫法**必须在开局前说**：盯住盘心，用余光扫四周找下一个数；手指只负责点，
别用手指追着数走。这句话有三个落处，一层比一层晚——

- 准备页那一行（`method.desc` / `guides.schulte.goal`）；
- 说明页「诀窍」（`guides.schulte.tip`）与评级行的 `rule`（`schulte.js:lines()`）；
- 结算的 `notes`（只在这一局点错过时才出现）。

以前它只在第三处出现：玩家用「手指追着数走」的错误方法把整门功法练完，
才在结算里读到正确扫法——那正好是这一门想要避开的退化解法。

- `S + 10` 在 `S > 5.45` 后永远不生效，五段全是 `2.835 × S` —— 说白了只有一个旋钮，

- 一个固定倍数假定「用时分布的形状与段位无关」。实际不同尺寸的分布宽窄不一样：
  前段的 B 线会慢到没人掉出去（4×4 的 B 线曾给到 38 秒 = 2.4 秒/格，比公开参照的
  「一般」还慢一倍多），后段的 C 带又会窄到不存在。

## 4. 设计依据

### 4.1 为什么每段都必须换点东西

上一版是 4/5/6/6/6：后三段同一个 6×6，只有 S 线在 34 / 32 / 29 之间挪。
而同一尺寸换个随机布局，成绩本来就波动 3–5 秒（参照站自己写着「同一尺寸不同布局
的成绩差 3–5 秒属正常」），注意力状态还有 ±2–5 秒的日间波动。
**段差（2 秒、3 秒）小于单局方差**——同一个人今天在困难拿 S、改天在极难拿 A，
可能纯粹是手气。那样的三段在体感上是同一局，评级只剩「结算时乘个数」。

现在五段各换一样东西，没有哪一对只差秒表：

| 相邻两段 | 换的是什么 |
| --- | --- |
| 简单 → 普通 | 盘面 16 → 25 格 |
| 普通 → 困难 | 盘面 25 → 36 格 |
| 困难 → 极难 | **规则**：点过的格不再退场（S 线只顺手紧 1 秒） |
| 极难 → 绝境 | 盘面 36 → 49 格 |

困难 → 极难这一对同盘面、同三条线附近，难度全压在「盘面不退场」上：
前段有「越点越空」可借，后段没有。这是这一门唯一像「新法」的一段，
但它加的是规则，不是减时间——**同盘面的两段，秒表差不起作用，所以干脆不靠它**。

### 4.2 盘面为什么到 7×7 封顶

8×8 每格落在 84rpx（22rpx 字号），两位数要认得快就吃力了，而这一门一旦「认不快」
就退化成猜。7×7 每格仍有约 100×76rpx（50×38px），远在项目「每格 ≥25px」的下限之上，
两位数在 24rpx 字号下清楚可读——上一版把 7×7 否在「看不清」，是把「没排过版」
写成了「看不清」；`.grid--c7` 本来就有（推石入位在用），加一行样式的事。
代价是绝境一局 1 分半（95 秒时辰），这条记在 04-圆满 §6 的待验里。

### 4.3 段内那一根旋钮

盘面与罚时都是整数、段内不变，时辰不是参数（由模块按 B 线现推），所以段内
原本没有任何能收的数——**1000 关一线**里，关卡制在这一门上本来就是假的。
现在给一根 `lineScale`（真源 `data/levels.js` 的 `tweakParams`）：整条尺子
（S / A / B 与时辰）按关收紧，全书收 18%，第 1000 关的 S 线是本段表头的 82%。

不复用 `buildParamsAt` 那 30%：那一刀只能落在 `params.timeLimit` 上，可这一门的时辰
是「B 线 + 8」现推的，收进 B 线里 C 带就没了。18% 而不是 30%：绝境的 S 线已经压在
「优秀」段位上，再收三成就成了「没人到得了」。

### 4.4 与另一门「点数字」的分工

| | 顺序点格 | 数中取大 |
| --- | --- | --- |
| 一批数 | 固定一整盘 | 每轮换一批 |
| 目标 | 按 1→N 全走完 | 只挑最大的一个 |
| 考的是 | 目光按序扫、不回头 | 当场比大小 |
| 判定 | 对错二元 | 对错二元 |

两者的判定都是对错二元，但**认知负荷完全不同**：顺序点格靠「序」，数中取大靠「比较」。

### 4.5 为什么不标下一个在哪

这是这一门最核心的一条。舒尔特方格的全部训练价值在于「目光按序扫过整盘」，
一旦替玩家圈亮目标格，就退化成「点发亮的格子」，与练眼力毫无关系。
`scripts/verify.js` 8b-6 与测试逐手守着：盘上任何一格都不许挂 `cell--next`
或 `cell--lit`，点过一格之后也不许冒出新的标记。

「点过的格退场」与这条不冲突：退场缩的是搜索面，不是指向。它没有告诉玩家
「下一个在右下角」，只告诉玩家「这几格已经用过了」。

### 4.6 为什么罚时不扣进度，也不判走火

扣进度会让玩家在 7×7 上反复卡在同一段，一局打很久还没走完。罚时的好处是
「错了还能继续，只是纪录变差」——但这句话只有在**罚时不参与走火判定**时才成立：
罚时一旦累加进走火判据，错够次数就会把一局清零，那就不是「纪录变差」，是「白打」。

### 4.7 罚时为什么不按同一个比例走

从 S 掉到 A 还能错几次（`(A − S) ÷ 罚时`）：3.0 / 3.0 / 2.75 / 2.2 / 2.17，**逐段递减**。
上一版是 4 / 6 / 5 / 3.5 / 2.6——入门段比未入门段能多错 50%，而未入门段是五段里第二
不容错的，与「未入门段手滑不心疼」的注释正好相反。根子在于罚时按绝对秒走、盘面按平方走，
两者不同步；这一版把「还能错几次」当标定目标，反过来定罚时。

### 4.8 为什么一局一图的布局要筛

`deal()` 抽完先算「走盘长度」（1→N 一路的平均曼哈顿步距），落在期望值 ±12% 以外就重抽。
期望是 `2(N²−1)/(3N)`，纯随机时上下浮动可达 ±15%——也就是说随机布局的方差
比段差还大。筛一遍之后每段的走盘长度都被压在窄带里（4×4 2.20–2.80、7×7 4.04–5.10），
段与段之间那 1–3 秒才读得出来。

内容仍然**一局一图**，不固定：固定布局会被背下来，这一门就只剩手速。
判据是「按规格现抽 + 抽完有约束」，和入位诀「从解反向拉所以必可解」是同一套做法。

### 4.9 被否决的方案

| 方案 | 为什么否掉 |
| --- | --- |
| 8×8 甚至 9×9 | 每格 84rpx、22rpx 字号，两位数认不快就变成猜（不是「懒得排版」） |
| 标出下一格的位置 | 见 §4.5，等于取消这一门 |
| 点错扣进度 | 一局会卡很久，与「碎片时间」冲突 |
| 反向（N² → 1） | 只是换个顺序，难度没变，但要重写文案与线 |
| 数字换成汉字 / 图案 | 读数就是玩法；且盘面不许上汉字 |
| 加「连点加速」奖励 | 会变成手速游戏，与「稳扫不乱」的训练目标相反 |
| 继续用 `PER_CELL` 现算三条线 | 一个旋钮 + 固定倍数，见 §3：前段 B 线白送、后段 C 带消失 |
| 罚时继续参与走火判定 | 见 §4.6：那样「错了还能继续」就是假话 |
| 靠罚时在章内收紧（旧版做法） | 罚时是代价，乘 0.7 只会让越深的关卡手滑越便宜——方向反了 |

## 5. 界面与反馈（五项逐门过）

1. **判据**：点对的那格退场（前三段留一个空位）或点完整盘；点完浮字「点完 · 用 X 秒」，盘面不再变电。
2. **代价**：点错一声 `C.flash(..., 'bad')`，指名「该点 N · 罚 X 秒」，错误计数进结算 `notes`；罚时只进用时、不跳倒计时。
3. **操作**：扫法一句话（盯盘心、余光扫四周、手指别追数）——准备页、说明页「诀窍」、结算三处都写。
4. **进度**：HUD「已点 k / N」+「下一个 N」+「用时 X 秒」；倒计时只走实际时间（走火也只看它）。
5. **收束**：点完整盘按用时结算；实际经过到时辰还没点完 → `C.flash`「时辰到 · 还差 X 个」，判 F。

盘上任何一格都不许挂 `cell--next` / `cell--lit`（§4.5），这是这一门的界面底线。

## 7. 全门待验
