# 神识·摘星辨魁诀 → 数中取大（总）

## 核心前提：这一门在玩什么

一批数字散在盘上，你只挑最大的那一个；挑对了换下一批，一批接一批。我想做的是「一眼挑魁首」这种瞬间判断——它不需要长局，拖长了反而变成耐力测试，所以这是十五门里最短的一档。真正的变化藏在两个数之间：一批数里最大的和次大的差几。差 12 一眼就分得出，差 2 就得逐位比末位；后者才是这一门的极限。

有一件事我反复掂量：整批数字只给同一个色。按数值大小连续上色看着更直观，可数距一旦收窄，颜色会在 9/10、49/50 的临界处替玩家把答案挑出来。所以分色只助读、绝不比较——宁可少给一点方便，也不能把「比较」这件事本身外包给颜色。

```text
  ┌────┬────┬────┬────┐
  │ 38 │ 47 │ 12 │    │  ← 一批数里挑最大的
  ├────┼────┼────┼────┤     点 47 → 换下一批
  │ 25 │ 43 │    │  9 │
  ├────┼────┼────┼────┤
  │ 41 │    │ 30 │ 18 │  整批同色：只助读，不比较
  └────┴────┴────┴────┘
 数距越大越好挑；数距收到 2 时，魁首只差末位
```

## 1. 盘面骨架（五段共用）

固定 4×4 共 16 格，每轮在其中摆 `count` 个数，其余留空（`.cell--void`）。

- 数字**直接显示**，读数就是玩法；
- 数字按**这一批的数位**整批给一个色（`maxVal ≥ 50 → tone 3`、`≥ 10 → 2`、否则 `1`），同批同色。

同批同色是硬要求：数距收到 2 时最大值与次大值只差末位，若按单个数分级，颜色会在
9 / 10、49 / 50 的临界处把答案直接标出来。分色只助读，不比较（依据见 §4.2）。

`span = max(count + 2, 10 + (轮次 − 1) × 6)`：下限 `count + 2` 是硬要求，`1..10` 只有十个数，
圆满段一批要 15 个互异干扰数时旧的 `while` 去重循环会永远凑不满（已修）。
最大值不落在 `span` 里：它是「次大值 + 本批数距」，可能比 `span` 大十几。

一局之内数距还再收一次：首批数距 = `nearGap + round((轮数 − 1) × 0.25)`，末批正好是 `nearGap`。
所以不必等二十关，同一局里就能看见数字越来越贴近。

## 2. 规则骨架（五段共用）

| 项 | 规则 |
| --- | --- |
| 完成条件 | 走完本段全部 `rounds` 轮 |
| 每轮 | 盘上重排一批新数，点出其中最大的那一个 → 进下一轮 |
| 点错 | 不换轮，只罚 **2 秒**（五段同价） |
| 计时 | `用时 = 实际经过 + 累计罚时` |
| 失败（F） | 时辰到还没走完 → F |
| 得分 | `(B 线 − 用时) × 10 + 轮数 × 20`，只用于破纪录 |

单点。点对才进下一轮，点错原地不动、只记罚时。没有方向键、没有拖拽。

三条线由 `linesOf()` 现算（`depth` 是段序 0–4）：

```js
// 一轮约 2.2 秒，越往后的段每轮预算越薄
s = round(rounds × (2.2 − depth × 0.15));
S = s;  A = round(s × 1.5);  B = round(s × 2.2);
timeLimit = max(S + 10, round(B × 1.3));
```

评级是用时族、含罚时：S ≤ S 线、A ≤ A 线、B ≤ B 线、C = 全走完但超过 B 线、F = 时辰到还没走完。
最低只到 C（只要走完），F 只给「没走完」。点错罚时五段仍是 2 秒——
读数难度已经由四个旋钮抬上去，再叠罚时是同一件事收费两次（依据见 §4.3）。

**难度由四样东西一起抬**：

1. **每轮几个数**（9 → 16）：候选越多，扫一遍越费眼；
2. **轮数**（8 → 16）：总数越多，越考耐力而非爆发；
3. **数值范围**（`span` 随轮次抬）：第 1 轮是一两位数，末轮绝境能到三位数；
4. **数距 `nearGap`**（12 → 2）：一批数里最大与次大差几，这是**段内结构副轴**。

第 4 条是 D7 拍板后新加的：盘面规格挂段表、段内一律不动，旧版章内只有一条整秒时辰，
玩家打一整段（旧口径 40 关；v9 起一段为 10 / 40 / 150 / 300 / 500 关）看不出任何变化。
数距改的是**信息复杂度**，不缩时辰、不缩盘面、不改秒表：差 12 一眼分得出，差 2 得逐位比。

## 4. 设计依据

### 4.1 与顺序点格两方对比

| | 数中取大 | 顺序点格 |
| --- | --- | --- |
| 盘上是什么 | 一批数，每轮换 | 1–N，固定不动 |
| 要找什么 | 最大的一个 | 下一个该点的数 |
| 依据 | 大小关系 | 顺序 |
| 一轮的终点 | 点对即换盘 | 顺次推进 |

两者都是「在一堆东西里找到对的那一个」，但认知动作完全不同：这里是**比较**，顺序点格是**按序推进**。

### 4.2 为什么整批只给一个色

按数值连续上色（越红越大）会把答案直接送出去。旧版按单个数分位数分级，在数距宽松时没问题；
数距收到 2 之后，最大值与次大值常落在 9 / 10 或 49 / 50 两侧，颜色反而替玩家把答案挑了出来。
现在按本批最大值的数位给**整批一个色**：保留助读，绝不比较。

### 4.3 为什么点错只罚 2 秒、不随段加码

这一门的读数难度已经由三个旋钮抬上去了（个数、轮数、数值范围）。再叠罚时会让圆满段变成「一次手滑就掉到 C」，与「走完就有 C 起步」的宽容口径冲突。

对照顺序点格：那一门罚时 2 → 6 秒逐段加码，因为它的难度全在「扫」上——盘面每段都换（4/5/6/7），每格预算还逐段收，容错必须跟着收（从 S 掉到 A 只许错 3.0 → 2.17 次）；它没有别的失误代价（不扣进度、除了时辰没有失败态），罚时是唯一能让「手滑」当场兑现的旋钮。这一门不同：读数难度已经由个数与轮数抬上去，再叠罚时就变成同一件事收费两次。

### 4.4 `base = 30` 为什么最短

一轮 2.2 秒、8 轮 18 秒——这是全站最短的一局。设计意图是「一眼挑魁首」这种动作本身不需要长局：它是一件**瞬间判断**的事，拖长了就变成耐力测试。

代价是未入门段 8 轮 × 每轮约 2.2 秒，熟练玩家 15 秒能走完，**一局不足以产生「练了一趟」的实感**。这是 `base = 30` 的已知代价。

### 4.5 被否决的方案

这张表是被我否掉的路，每一行都留着诱因和收手的理由。头一条「按数值连续上色」尤其要紧——看起来是最自然的助读，恰恰会毁掉这一门。

| 方案 | 为什么否掉 |
| --- | --- |
| 按数值连续上色 | 等于把答案标出来 |
| 点错罚时逐段加码 | 与「走完就有 C」的宽容口径冲突 |
| 盘面固定 3×3 | 16 个数塞不进 9 格；且 4×4 才有「扫一遍」的量 |
| 一轮只换部分数 | 会让「记住上一轮最大的在哪」变成可行策略，与「当场比较」的训练目标相反 |
| 找最小值 | 只是换方向，难度没变，但要重写文案与三条线 |
| 用汉字数字 | 盘面不许上汉字；且一位数汉字与两位数汉字宽度差更大，反而更难扫 |
| 段内混合下一段的离散规格 | 6 列混 7 列得 6.4、取整还是 6，参数看着动了盘面没动（`mixParams` 已删） |
| 靠收时辰 / 罚时凑「每关都变」 | 20 秒那一段只有 20 格，收七成会把一段评语删掉；0.5 秒在倒计时上看不见 |

## 5. 界面与反馈（五项逐门过）

1. **判据**：盘上数字直接显示，挑出本批最大的那一个 → 换下一批；挑错不换轮，只罚 2 秒。
2. **代价**：点错罚 2 秒计入 `用时 = 实际经过 + 累计罚时`；时辰到还没走完 → F，走完就有 C 起步。
3. **操作**：单点，没有方向键、没有拖拽。
4. **进度**：走完本段全部 `rounds` 轮即结算；一局之内数距逐批收紧，每轮重排一批新数。
5. **收束**：走完按用时对照 S / A / B 线评级，超过 B 线仍走完是 C；时辰到没走完是 F。分色只助读，不比较。

## 7. 全门待验

- 一局之内数距逐批收紧，玩家是否真的感到「越到后面越难」，还是只觉得数字变大了。
