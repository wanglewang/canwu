## 1.5 逐门打磨进度

| 项 | 问什么 |
| --- | --- |
| 难度 | 这一门的主承重轴（复杂度 / 信息 / 规模 / 速度）是否真的随关卡变化，相邻档有没有断崖 |

## 2. 判重：怎么算「不重复」

四维判据，**至少三项不同**才算另一门：

| 维度 | 问什么 |
| --- | --- |
| 盘面形态 | 方形格 / 竖向河道 / 圆盘 / 灯环 / 卷轴 / 持续下落 |
| 核心动作 | 点一格 / 划一刀 / 按序输入 / 长按蓄力 / 推整行 / 换相邻两格 |
| 胜负规则 | 分数达标 / 用时 / 比值最优 / 达成即结束 / 走完段数 |
| 压力来源 | 时限 / 判定窗 / 心神 / 预算 / 堆顶 |

**判据的实操版**：把这一门的文案全删掉，只看盘面与判定，还能不能分辨出是另一门。分不出就是换皮。

几组最容易混、现已分开的：

| 组 | 分开的方式 |
| --- | --- |
| 连线 vs 三秀 | 连线是「找通路、消完变少」；三秀是「换位造形、消完补满」 |
| 阵灯 vs 五行 | 阵灯是静态翻转推演（省步数）；五行是环形限时接龙（比手速） |
| 垒石 vs 滑格 | 垒石按时间下落、填满整层；滑格四向推盘、同数翻倍 |
| 让路 vs 入位 | 让路整块滑、只求主块出去；入位走人推箱、每箱对位 |
| 记序 vs 翻牌 | 记序是「闪过的顺序」，翻牌是「翻开的位置」 |
| 记序 vs 九宫 | 记序靠记性，九宫靠排除法 |
| 逐数 vs 摘魁 | 逐数固定盘按序扫一遍；摘魁每轮换一批、只挑最大 |
| 剑法 vs 逐数 | 剑法是「真/假两态里认一个」；逐数是「按序走完整盘」 |

**守卫**：`tests/minigames.test.js` 断言「19 门对应 19 套互不重复的玩法」「同类功法也各用各的玩法」「每门功法的独有机制互不重复」。

## 3. 所有玩法共享的东西

| 项 | 内容 |
| --- | --- |
| 控制器接口 | `create(ctx)` 返回 `vm` 与 `tap` / `swipe` / `press` / `move` / `undo` / `hint` / `reset` 中的若干 |
| HUD 字段 | 进度、实时评级、连击、目标、阶段横幅、浮字、心神、副指标 |
| 评级出口 | 必须导出 `lines(params, gear)`，由 `index.js` 汇总 |
| 教学 | 可选导出 `teach.create(ctx)`；没有就跳过引导 |
| 盘面 | 不写汉字；用 `crest` / `emblem` 图案或数字 |
| 结算 | 只有一个 `finish()` 出口，落 S/A/B/C/F 之一 |
| 时长基准 | `method.base`（30–56）→ 耗气时长系数 0.85–1.30 |

详细契约见 `40-engineering/02-minigame-contract.md`。

### 3.1 首局手把手覆盖表

`index.hasTeach()` 实测：**19 门里只有 1 门自带 `teach`**。数量少是判断，不是遗漏——插一段引导有代价：它要先演一遍核心操作，而演的那一遍往往把盘面答案也演了。

判据是「这门的规则能不能在第一次操作后的 1 秒内自证」：

| 分组 | 门 | 有没有 teach | 理由 |
| --- | --- | --- | --- |
| 反直觉规则 | 阵灯推演 | **有**（两步小阵） | 「点一格翻它自己与四邻」不点不会知道；只讲「把阵点亮」又会被理解成随便点。必须让他看见连带的四格一起翻 |
| 动作类 | 顺光扫斩、辨伪择真、步法连环、节律判定 | 无 | 划一刀 / 点一下 / 按一个方向，反馈在 100ms 内到眼前。引导会提前剧透刀路与真招在哪 |
| 序列类 | 记序复现、循纹递推、五行相生 | 无 | 规则就是「按看到的顺序来」，第一遍错一次就懂了；标出「第一个该点哪」等于把这一局的序列送出去 |
| 单一目标类 | 数格辨禁、成对翻牌、灵纹连线、落石垒基、三秀同收、九宫填数、滑格相合、顺序点格、滑块让路、推石入位、数中取大 | 无 | 操作只有一种（点 / 翻 / 推 / 换 / 挪），目标写在准备页一行里。真正的门槛在「怎么规划」，而那一段教不了，只能自己走 |

**待验**：上表的分组是设计判断，没有真人数据支撑。若真机观察发现某门（优先怀疑数格辨禁——扫雷式推理对没玩过的人是全新的）前 30 秒的退出率明显偏高，再给它补 `teach`，不要一次全铺。

## 4. 五档怎么变难

各门机制不同，但都能归到四条轴。**每门只该有一个主承重轴**，其余轴只做微调——四个轴各推一点，每层都不到位，玩家反而说不出「这档到底难在哪」。

| 轴 | 例 | 上限 |
| --- | --- | --- |
| **复杂度**（规则 / 约束 / 干扰 / 分支） | 步法段数 12→39 步且键位每段重排、阵灯预算 9→22 步、勘禁禁制 5→12 | 6–8 倍 |
| **信息**（能看多久、看到多少、藏了多少） | 九宫挖洞 8→46 格、三秀亮起 0.90→0.53 秒、灵纹 1.06→0.63 秒 | 5–6 倍 |
| **规模**（盘面 / 轮数 / 目标值） | 开锋 3×3→5×5、勘禁 6×6→9×9、摘魁 8→16 轮、滑格合成 128→1024 | 4 倍 |
| **速度**（时限 / 间隔 / 判定窗） | 刀法光速 304→140ms、辨伪 1.18→0.70 秒、落石第 1 级 1.00 秒 → 绝境章末起手 43 毫秒 | 3–4 倍 |

**速度排在最后，因为它的上限最低。** 人的反应时间 200ms 是天生的，练不出来多少——把难度压在速度上，玩家只会更焦虑，而且输了不知道还能练什么；压在复杂度与信息上，他能靠「想得透、记得住」跨过去。

盘面尺寸现在有 `.grid--c3 / c4 / c5 / c6 / c7 / c8 / c9 / c10` 八种列数。放大盘面属于「显式规格表」的事（`CLICK_LEVELS` / `MINES_LEVELS` / 阵灯 / 九宫 / 逐数），通用缩放不许顺手改盘面——`scripts/verify.js` 守着这条，怕的是「调难度不小心把盘面也动了」。
