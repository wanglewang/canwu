# 玩法总览

> 15 门功法 = 15 套互不复用的玩法内核，另有 1 套只在境界突破时用。同类功法也不共用盘面、交互或胜负规则。
>
> 2026-11 退役四门：剑法·截锋断岳诀（辨伪择真）、水术·叠纹凝露诀（循纹递推）、身法·踏云连环步（步法连环）、阵法·五灯相生诀（五行相生）。本篇编号保持原序，`02 / 04 / 06 / 08` 四个号段就此空缺，不复用——复用会让旧链接指到别的玩法上。

## 这一篇在讲什么

玩家在功法列表上看到的是十五个名字。他真正撞上的，是十五种完全不同的手感：有的是把刀顺着箭头扫到靶心，有的是把光环缩到红圈的那一瞬按下，有的是在石堆落满之前给下一块留出缝。

这一篇只干一件事：**保证这十五门不是同一套玩法换了十五张皮**。判据很硬——把文案全删掉，只看盘面与判定，你还认不认得出这是另一门。

```text
  换皮与另一门的区别：判据是「删掉文案还认不认得出」

  换皮（不做）                        另一门（现在这样）
  ┌──────────────┐                 ┌──────────┐    ┌──────────┐
  │ 同一张盘      │  改个名字        │ 扫斩：划  │    │ 勘禁：推  │
  │ 同一套判定    │ ─────────▶      │ 顺箭头扫  │    │ 数字定禁  │
  │ 只换美术文案  │                 │ 一刀到底  │    │ 两数相减  │
  └──────────────┘                 └──────────┘    └──────────┘
                                     盘面不同         盘面不同
                                     动作不同         胜负也不同
```

下面这张矩阵把十五门一次摆开。想找「这门和那门到底差在哪」，看「核心动作」与「评级族」两列最快——动作决定手上在做什么，评级族决定输了算谁的账。

## 2. 判重：怎么算「不重复」

四维判据，**至少三项不同**才算另一门：

| 维度 | 问什么 |
| --- | --- |
| 盘面形态 | 方形格 / 圆盘 / 灯环 / 牌阵 / 持续下落 |
| 核心动作 | 点一格 / 划一刀 / 按序输入 / 长按蓄力 / 推整行 / 换相邻两格 |
| 胜负规则 | 分数达标 / 用时 / 比值最优 / 达成即结束 / 走完段数 |
| 压力来源 | 时限 / 判定窗 / 心神 / 预算 / 堆顶 |

**判据的实操版**：把这一门的文案全删掉，只看盘面与判定，还能不能分辨出是另一门。分不出就是换皮。

几组最容易混、现已分开的：

| 组 | 分开的方式 |
| --- | --- |
| 连线 vs 三秀 | 连线是「找通路、消完变少」；三秀是「换位造形、消完补满」 |
| 垒石 vs 滑格 | 垒石按时间下落、填满整层；滑格四向推盘、同数翻倍 |
| 让路 vs 入位 | 让路整块滑、只求主块出去；入位走人推箱、每箱对位 |
| 记序 vs 翻牌 | 记序是「闪过的顺序」，翻牌是「翻开的位置」 |
| 记序 vs 九宫 | 记序靠记性，九宫靠排除法 |
| 毫厘 vs 辨魁 | 毫厘固定盘按序扫一遍；辨魁每轮换一批、只挑最大 |

**守卫**：`tests/minigames.test.js` 断言「15 门对应 15 套互不重复的玩法」「同类功法也各用各的玩法」「每门功法的独有机制互不重复」。

## 3. 所有玩法共享的东西

| 项 | 内容 |
| --- | --- |
| 控制器接口 | `create(ctx)` 返回 `vm` 与 `tap` / `swipe` / `press` / `move` / `undo` / `hint` / `reset` 中的若干 |
| HUD 字段 | 进度、实时评级、连击、目标、阶段横幅、浮字、心神、副指标 |
| 评级出口 | 必须导出 `lines(params, gear)`，由 `index.js` 汇总 |
| 教学 | 可选导出 `teach.create(ctx)`；没有就跳过引导 |
| 盘面 | 不写汉字；用 `crest` / `emblem` 图案或数字 |
| 结算 | 只有一个 `finish()` 出口，落 S/A/B/C/F 之一 |
| 时长基准 | `method.base`（30–56）→ 耗气时长系数 0.85–1.30 |

详细契约见 `40-engineering/02-minigame-contract.md`。

不写在接口里的还有一条：**一门一条 1–1000 的关号线、五段**。段位不是玩家挑的，只是「已走通几关」的另一个说法；关号由走通推进，一局只推一关，只增不减，不设关卡锁，段位由 `cleared` 读出来（见 `10-systems/07-difficulty.md`）。各门总览与段篇里的「第 501 关」都是这个全局关号。

### 3.1 引导覆盖表：每段的第 1 关各一盘

`index.hasTeach()` 实测：**15 门参悟全部有 `teach`**。2026-11 之前只有阵灯推演一门，其余 14 门第一次开局直接 3-2-1，玩家反馈「每个游戏进入缺少新手指引」。

**现在一门五盘**：第 1 / 11 / 51 / 201 / 501 关各走一次（`engine.hasTaught(state, id, stage)`，存档在 `teachSeen[5]`）。首段回答「这门在玩什么」，段界回答「这一段变了什么」——而且段界那一盘按**本段真实规格**摆（同尺寸、同禁制数、同起点等级、同判定带），变化是看见的，不是读到的。

首段步数不一刀切，但**下限是 2 步**：一眼就会的门（成对翻牌、顺序点格、数中取大）也要让玩家在真按钮上按两下——第一手证明点得中，第二手证明规则成立。段界 1–3 步（记序复现按音数走，最多 5）。第二步必须换位置或换方向（迁移检查）。研究与规范见 `30-ui/12-teach-boards.md`，公用骨架在 `minigames/teach-kit.js`。

判据是「走完这几步，玩家能不能说清这门在玩什么 / 这一段变了什么」——不是「有没有引导」，也不是「步数够不够多」。15 门逐段教什么，见 `30-ui/12-teach-boards.md` 的 §4 逐门表。

教学盘一律不计步、不结算、不进连 S，随时可跳过；跳过或走完都记本段已看过，之后这一段不再出现（其余四段照旧）。

**待验**：段界五盘是不是真的让人看出变化，只能靠真机看。判据写在 `30-ui/12-teach-boards.md` §6——同一门连打五段有没有重复感；「只换了数字」的那几门若连续两次真机都有人点跳过，就该退回准备页用 `ruleText` 讲，而不是占一次开局。

## 4. 五段怎么变难

各门机制不同，但都能归到四条轴。**每门只该有一个主承重轴**，其余轴只做微调——四个轴各推一点，每层都不到位，玩家反而说不出「这段到底难在哪」。

| 轴 | 例 | 上限 |
| --- | --- | --- |
| **复杂度**（规则 / 约束 / 干扰 / 分支） | 阵灯余量 +7 步（段内收到 +5）、勘禁禁制 5→12、九宫挖洞 8→46 格 | 6–8 倍 |
| **信息**（能看多久、看到多少、藏了多少） | 九宫挖洞 8→46 格、三秀亮起 0.90→0.53 秒、灵纹 1.06→0.63 秒 | 5–6 倍 |
| **规模**（盘面 / 轮数 / 目标值） | 开锋 3×3→5×5、勘禁 6×6→9×9、辨魁 8→16 轮、滑格合成 128→1024 | 4 倍 |
| **速度**（时限 / 间隔 / 判定窗） | 刀法光速 304→140ms、落石第 1 级 1.00 秒 → 绝境段末起手 43 毫秒 | 3–4 倍 |

**速度排在最后，因为它的上限最低。** 人的反应时间 200ms 是天生的，练不出来多少——把难度压在速度上，玩家只会更焦虑，而且输了不知道还能练什么；压在复杂度与信息上，他能靠「想得透、记得住」跨过去。

盘面尺寸现在有 `.grid--c3 / c4 / c5 / c6 / c7 / c8 / c9 / c10` 八种列数。放大盘面属于「显式规格表」的事（`CLICK_LEVELS` / `MINES_LEVELS` / 阵灯 / 九宫 / 毫厘），通用缩放不许顺手改盘面——`scripts/verify.js` 守着这条，怕的是「调难度不小心把盘面也动了」。
