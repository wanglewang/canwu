# 灵植·三秀撷英诀 → 三秀同收（总）

## 核心前提：这一门在玩什么

一片灵畦种满灵植，你互换相邻两株，凑齐三株同色就采收；收走之后上面的苗落下来补空，补下来的新苗又可能再凑成一线——这就是连锁，一层比一层值钱。我想做一门「看一眼就懂、想拿高分却要算三步」的三消：规则一句话，深度全藏在「换哪两株能引出下一波连锁」里。

盘面五段一路从 6×6 长到 10×10，花色从 5 增到 7。但这里有个反直觉的地方：**S 线随难度反而降**（1900 → 950）。不是我手松了，是花色越多、盘越大，同样分数含金量越高——7 色大盘凑三连远难于 5 色小盘。这条我会写进准备页，免得玩家以为算错了。

```text
  ┌──┬──┬──┬──┬──┬──┐
  │花│叶│花│果│叶│花│
  ├──┼──┼──┼──┼──┼──┤
  │果│花│果│叶│果│叶│
  ├──┼──┼──┼──┼──┼──┤
  │叶│果│花│花⇄花│果│  ← 换位凑三连
  ├──┼──┼──┼──┼──┼──┤
  │花│叶│果│叶│花│叶│
  └──┴──┴──┴──┴──┴──┘
 三株同色成线 → 收走留空 → 落下补苗 → 再查连锁
```

> 这张示意是设计意图，不是实测截图；花色用汉字代指 sprite 图案，盘面按段为 6×6 到 10×10。

> 在灵畦里互换相邻两株，凑齐三株同色即采收；新苗落下还能再连锁。换不出三连就少一息。
>
> 五段六篇：本篇放五段共用的骨架（盘面 / 规则 / 依据 / 界面 / 代码），
> 每段的花色、时辰、罚息与评级线写在各段文档里，两边不互相抄。
> 这一门是唯一「一张表管全」的玩法（`MATCH_LEVELS`），整表按段逐段展开到各段篇 §1。

- 功法：灵植·三秀撷英诀（黄阶，offline +12%）｜玩法 id：`harvest`｜阶段新法：照畦 / 连收
- 时长基准 `base = 34`

**这组文档怎么读**：下面这张表在回答一个问题——五段各自换盘、换花色、收时辰与罚息之后，S 线落在哪。本文件只写五段共用的骨架；每一段的整表行与手感各有一篇，数字都在那里：

| 段 | 关 | 关数 | 盘面 | 花色 | 时辰 | S 线 | 文档 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 一 · 未入门 | 1–10 | 10 | 6×6 | 5 | 68 息 | ≥1900 | [未入门](00-未入门.md) |
| 二 · 入门 | 11–50 | 40 | 7×7 | 5 | 66 息 | ≥1750 | [入门](01-入门.md) |
| 三 · 小成 | 51–200 | 150 | 8×8 | 6 | 64 息 | ≥1400 | [小成](02-小成.md) |
| 四 · 大成 | 201–500 | 300 | 9×9 | 6 | 62 息 | ≥1300 | [大成](03-大成.md) |
| 五 · 圆满 | 501–1000 | 500 | 10×10 | 7 | 60 息 | ≥950 | [圆满](04-圆满.md) |

跨段看：盘面 6×6 → 10×10（每换一段就换一副盘，这是不用读字也看得见的台阶）、花色 5→7、
时辰 68→60 息、罚息 −1→−3。时辰没有跟着旧表继续大收：盘变大后扫一圈要更久，
每格预算从 1.89 息一路收到 0.60 息，主承重轴从「快」挪回「看得清」。
**S 线随游戏变难而降低（1900 → 950）**——7 色大盘上凑出三连的概率仍远低于 5 色小盘，
同样分数含金量不同。这条必须写进准备页与说明页，否则玩家会以为算错了（见 §5）。

**只有一套关号。** 一门一条 1–1000 的线、五段，段位不是玩家挑的，只是「已走通几关」的另一个说法
（见 `10-systems/07-difficulty.md`）。关号由走通推进，一局只推一关，段位由 `cleared` 读。
本篇与小篇里的「第 501 关」就是玩家看见的那个关号。

## 1. 盘面骨架（五段共用）

五段各一副盘：6×6 / 7×7 / 8×8 / 9×9 / 10×10，铺满灵植。盘面列与行由 `MATCH_LEVELS`
注入（玩法层读 `p.cols / p.rows`），九 / 十列在 `practice.wxss` 走满宽的 `grid--compact`，
不是落石那套 408rpx 窄槽——否则十列每格只剩 20px，果器纹挤成一团。

- 花色数按段 5 → 7（`kinds`）；
- 每次采收后上方落下、顶上补新苗，盘面**收场时永远是满的**。
  **「满」是收场，不是过程**：收走的三株会在盘上真空出 170ms（`cell--clear`，格子凹下去、
  牌撤掉），新苗再从上方按距离落下（`cell--fall`，掉几格就走几格）。这一段空是玩家
  唯一看得见「刚才收在哪儿」的窗口——前后两帧都是满的，中间不空一段，连锁三层和一层
  在屏幕上长得一模一样，只能靠浮字知道发生了事；
- 图案用 `crest` sprite（八张牌，绝境用到第 7 张）；
- **没有可行换位时自动重排**，绝不把玩家卡在死局里。

## 2. 规则骨架（五段共用）

| 项 | 规则 |
| --- | --- |
| 采收 | 点相邻两株换位，使三株同色连成一线（横或竖 ≥3） |
| 无效互换 | 换不出三连 → 少 `missCost` 息 |
| 连锁 | 落下后再次凑成一线 → 连锁 +1 层，一层比一层值钱 |
| 重排 | 花 `shuffleCost` 息，把全盘重排 |
| 照畦（提示） | 花 `hintCost` 息，指出一步能三连的换位 |
| 结束 | 时辰到 |

**没有 F**：只看时限内的总分。

## 3. 五段怎么变

每一步只收紧一到两个数，符合「递增曲线平缓，无断崖」：

| 段 | 这一段新学的一件事 | 主轴 |
| --- | --- | --- |
| 一 · 未入门 | 找三连：相邻两株换位、横或竖 ≥3 即采收 | 复杂度（5 色 · 6×6） |
| 二 · 入门 | 无效互换要罚息，「想好了再换」成为必要 | 盘面 6×6→7×7 + 代价（罚息 −1 → −2） |
| 三 · 小成 | 盘面再放大一圈、多一色（5 → 6）：同色候选被压少 | 盘面 7×7→8×8 + 花色 |
| 四 · 大成 | 罚息再收一档（−2 → −3）；解锁「照畦」少扣 1 息（仍要付） | 盘面 8×8→9×9 + 代价 + 便利 |
| 五 · 圆满 | 盘面到 10×10、再多一色（6 → 7）；解锁「连收」，S 线反降到 950 | 盘面 9×9→10×10 + 花色 + 收益 |

### 3.1 阶段新法（大成 / 大圆满）

| 段位 | 名 | 规则 | 可关 |
| --- | --- | --- | --- |
| 大成 | 照畦 | 「照畦」**少扣 1 息（仍要付）** | 否 |
| 大圆满 | 连收 | 连锁从第 3 层起额外加成；重排少扣 1 息 | 否 |

**这两条是原则第十一节的标准写法**：便利可以有，但必须有明码代价——「少扣 1 息」而不是「不扣」。
而且加成从第 3 层才给，得先打出连锁才拿得到，不是白送。
大成、圆满两段的具体体现分别见 [大成](03-大成.md) §2 / [圆满](04-圆满.md) §2。

## 4. 设计依据

### 4.1 为什么整表管理而不是公式缩放

旧版只有「S 线 620 + depth×150」在变，60 息 / 5 色 / 罚 2 息四段全写死。真控制器跑 12 局的结果：
高手五段 12/12 全 S、常人绝境 10/12 S——**等于同一局打五遍**。

现在每段只收紧一到两个数：

- 简单 → 普通：收时辰与罚息；
- 普通 → 困难：多一色；
- 困难 → 极难：收时辰与罚息；
- 极难 → 绝境：再多一色。

每一步都只动一两个数，符合「递增曲线平缓，无断崖」。

### 4.2 为什么 S 线要降

这是全站唯一「越难越低」的线。理由见 §1 表后的说明：花色越多，同样分数越难拿到。
落点目标是「高手 75–95% 拿得到、常人 5–25%」，由 `npm run audit:diff` 与 `tests/rank.test.js` 一起守。

如果按「越难越高」写，圆满段会变成「只有极少数人能拿 S」，而 S 的概率本该与段位大致相当。

### 4.3 为什么无效互换要罚息

不罚的话，玩家可以靠「狂换」试出三连——换位本身成了搜索工具。罚息让「想好了再换」成为必要。

### 4.4 被否决的方案

这张表记着我否掉的念头——每一条都留着当时的诱因。尤其「S 线随段上升」那条，是这类三消最容易踩的直觉坑，值得单独讲清楚（理由见 §4.2）。

| 方案 | 为什么否掉 |
| --- | --- |
| S 线随段上升 | 见 §4.2 |
| 无效互换不罚 | 可以靠试（见 §4.3） |
| 死局不重排 | 卡死玩家 |
| 照畦免费 | 辅助必须有代价（原则第九条） |
| 「照畦不扣息」 | 原则第十一节：便利要有明码代价，改为「少扣 1 息」 |

## 5. 界面与反馈（五项逐门过）

原文 §6「界面」与 §6.5「界面与反馈」合列如下。

- 局内代价句按本段生成：「换不出三连少 N 息」（`tipFor()` 现拼，不写死）；
- 准备页难度栏显示本段花色 / 时辰 / 罚息 / S 线；
- 无效互换有轻震反馈，与连锁的中量震动区分开。

| 项 | 落点 |
| --- | --- |
| 难度 | 主承重轴是**盘面规格 + 复杂度**：盘面 6×6→10×10、花色 5→7、时辰 68→60 息、罚息 −1→−3。7 色大盘上凑三连的概率仍远低于 5 色小盘，所以 S 线反而随段下降。 |
| 显示 | 准备页难度栏写清本段花色 / 时辰 / 罚息 / S 线；局内代价句按段现拼（`tipFor()`），不写死。 |
| 特效 | 一手分三拍演：收走（留空 170ms）→ 落下（同列同时落定，按距离 130–300ms）→ 再查一轮。无效互换轻震。详表见 §5.1。 |
| 引导 | goal 一句「换相邻两株凑三连」+ 三步 + 词条；首局有入门卡。 |
| 关卡 | 段内按 `duration` 与 `flashMs` 收紧；盘面只在换段时换副（6×6→10×10），`levelDelta` 优先报盘面，其余报时辰与亮起时长。**1000 关里 143 关真的变了**，其余据实写「与上一关规格相同」。第 1 关与第 1000 关不写那句兜底：两关都没有「上一关」可比（末关常被整秒取整抹平），改报「盘面 6×6 · 花色 5 种 · 时辰 66 秒」与「比起手关：时辰 66 秒 → 42 秒 · 盘面 6×6 → 10×10」。 |

**v9 口径修正**：原文写「段内 40 关按 `duration` 与 `flashMs` 收紧」，其中「段内 40 关」是 v8 旧口径；
v9 五段关数为 10 / 40 / 150 / 300 / 500，段内收紧按 v9 关号段理解，「143 关真的变了」是原文实测值，照抄不改。

### 5.1 一手演三拍

一手不是一个瞬间。三件事压进同一次渲染，盘面就从满的跳到满的——人眼比两帧只能比出
「位置变了」，比不出「少了三株」，连锁叠三层和一层在屏幕上没有区别。

| 拍 | 时长 | 盘面上看见什么 | 为什么必须有这一段 |
| --- | --- | --- | --- |
| 收走 | 170ms（`BEAT.clear`） | 那三株撤掉、格子凹下去（`cell--clear`，静态凹槽，不是一次性动画）、原位迸一小把粒子、HUD 浮字 | 整手唯一「看得见少了东西」的锚点。凹槽写成静态状态：减少动效关掉动画时它还在，「这里刚收走三株」照样读得出来 |
| 落下 | 130–300ms（`BEAT.fallBase + 格数 × fallPer`，封顶 `fallMax`） | 牌从上方掉进格子（`cell--fall`），掉几格走几格；新苗从盘面外进来 | 一格和十格给同一个时长会读成瞬移。**同列必须同时落定**，否则同列两株会在半空互相穿插；列与列各按自己最远那株定时长 |
| 再查一轮 | 0ms | 还有三连 → 回到「收走」，层数 +1 | 连锁是「落下来的新苗又凑成一线」。看不到落下，连锁就像凭空发生 |

无效互换另算一条：两株各抖一下（横向 ±7rpx 三次回正）。只少 2 息、不抖，玩家会以为
「没点上」，接着再点一次。

**演出期间不收输入，但表照走。** 这一门是限时计分不是步数制：把动画时间从表里扣掉，
手越快局越长，一局打不完。锁输入 + 照走表是业界限时三消的通行做法，
代价是单手演出必须压在 0.5 秒以内（三拍合计 300–470ms，三层连锁约 1.4 秒）。

抖动与下落都只动 `transform`；`cell--fall` 的 `0/1` 交替序号是为了让相邻两手各自重播一次
（同名类连挂两帧不播动画）。`cell--clear` 不需要交替——它是状态，不是一次性动作。

**被否决的方案**

- **整盘连锁脉冲**（每层连锁给全盘加一层光）：连锁本来就带金浮字与粒子，再加整盘光
  是三层叠加，玩家只看到「屏幕在闪」。
- **只给最上面八格挂落下动画**（v10 前的写法）：为了躲开「一二十格一起动等于整盘乱抖」，
  代价是玩家看不见真正移动的那些牌——他看到的「落下」全是新苗，老牌全是瞬移。
  正解是按列同步落定（同列同速，不会穿插），而不是砍掉一半的格子。
- **演出期间停表**：能让滑动更从容，但在限时计分里等于把动画时间送给玩家，
  手快的人一局能打四分钟。要停表就得改成步数制，那是另一门功课。

## 7. 全门待验

以下为全门性待验；「绝境 7 色 60 息 S 线 950」那一条段相关，落在 [圆满](04-圆满.md) §6，本文件不重复。

- 6×6（约 50px/格）到 10×10（约 35px/格）相邻两株互换在大屏 / 4.7 寸小屏的误触率，重点看第九、十段的满宽样式有没有把果器纹挤糊。
- 长按选中与点击取消的容错。
- 「无效互换轻震」在 iOS / Android 上能否与连锁的中量震动分得开，会不会反而打断观察节奏。
- **三拍的实际手感**：170ms 的空格帧在小屏上够不够看见（看不见就是白发一次渲染）；
  10×10 盘上「整列塌一截」会不会糊成一片；三层连锁连续演 1.4 秒，中间玩家是不是开始抢点。
  这三条只能真机看，代码里量不出来。
- 演出期间不收输入会不会被读成「点了没反应」——真机上抢点一次，看玩家会不会以为卡了。
