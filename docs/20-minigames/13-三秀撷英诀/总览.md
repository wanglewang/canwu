# 灵植·三秀撷英诀 → 三秀同收（总）

## 玩法概述

一片灵畦种满灵植，你互换相邻两株，凑齐三株同色就采收；收走之后上面的苗落下来补空，补下来的新苗又可能再凑成一线——这就是连锁，一层比一层值钱。我想做一门「看一眼就懂、想拿高分却要算三步」的三消：规则一句话，深度全藏在「换哪两株能引出下一波连锁」里。

盘面五段一路从 6×6 长到 10×10，花色从 5 增到 7。从第四段起，盘上开始出现**石皮封住的苗**——它不能换，只能靠落到它头上的三连把它收走解封；同时**重排开始计次**——前 3 次按原价扣 4 息，之后每次翻倍。这两条是全门唯一「看得见的规则变化」：前 200 关靠手快眼准，后 800 关还得绕开石皮、算着次数打。

S 线不是写死的绝对分，而是**按本关时辰现算**（每手 1.2 息 × 0.72 利用率，见 §4.2）。所以它在段与段之间会「抬高」：新一段的起手时辰比上一段末关更宽，S 线就跟着抬高。这是口径，不是算错。

```text
  ┌──┬──┬──┬──┬──┬──┐
  │花│叶│花│果│叶│花│
  ├──┼──┼──┼──┼──┼──┤
  │果│花│果│叶│果│叶│
  ├──┼──┼──┼──┼──┼──┤
  │叶│果│花│花⇄花│果│  ← 换位凑三连
  ├──┼──┼──┼──┼──┼──┤
  │花│叶│果│叶│花│叶│
  └──┴──┴──┴──┴──┴──┘
 三株同色成线 → 收走留空 → 落下补苗 → 再查连锁
```

> 这张示意是设计意图，不是实测截图；花色用汉字代指 sprite 图案，盘面按段为 6×6 到 10×10。

> 在灵畦里互换相邻两株，凑齐三株同色即采收；新苗落下还能再连锁。换不出三连就少一息。
>
> 五段六篇：本篇放五段共用的骨架（盘面 / 规则 / 依据 / 界面 / 代码），
> 每段的花色、时辰、罚息与评级线写在各段文档里，两边不互相抄。
> 这一门是唯一「一张表管全」的玩法（`MATCH_LEVELS`），整表按段逐段展开到各段篇 §1。

- 功法：灵植·三秀撷英诀（黄阶，offline +12%）｜玩法 id：`harvest`｜阶段新法：照畦 / 连收
- 时长基准 `base = 34`

**S 线衡量的不是「这门有多难」，而是「这一关的时辰里，按每手 1.2 息你能打多少分」**（见 §4.2）。

## 1. 盘面介绍

五段各一副盘：6×6 / 7×7 / 8×8 / 9×9 / 10×10，铺满灵植。盘面列与行由 `MATCH_LEVELS`
注入（玩法层读 `p.cols / p.rows`），九 / 十列在 `practice.wxss` 走满宽的 `grid--compact`，
不是落石那套 408rpx 窄槽——否则十列每格只剩 20px，果器纹挤成一团。

- 花色数按段 5 → 7（`kinds`）；
- **石皮封印格**（`seals`，第四段 4 格、第五段 8 格）：这些格子里的苗换不动，
  但照样能被三连一起收走——收走就解封，新落下来的苗是活的。判据是「看得见、算得清」：
  石头壳比暖玉牌压暗一档、边缘发钝（`.cell--sealed`，`scale(0.94)` + 7rpx 石壳 + 斜石纹），
  一眼扫过去就知道哪几格碰不得；
- 每次采收后上方落下、顶上补新苗，盘面**收场时永远是满的**。
  **「满」是收场，不是过程**：收走的三株会在盘上真空出 170ms（`cell--clear`，格子凹下去、
  牌撤掉），新苗再从上方按距离落下（`cell--fall`，掉几格就走几格）。这一段空是玩家
  唯一看得见「刚才收在哪儿」的窗口——前后两帧都是满的，中间不空一段，连锁三层和一层
  在屏幕上长得一模一样，只能靠浮字知道发生了事；
- 图案用 `crest` sprite（八张牌，绝境用到第 7 张）；
- **没有可行换位时自动重排**，绝不把玩家卡在死局里。前三段不限次、每次按 `shuffleCost` 扣；
  后两段每局只有前 3 次按原价扣，用完还有死局就每次双倍扣息（见 §2）。

## 2. 规则说明

| 项 | 规则 |
| --- | --- |
| 采收 | 点相邻两株换位，使三株同色连成一线（横或竖 ≥3） |
| 无效互换 | 换不出三连 → 少 `missCost` 息 |
| 连锁 | 落下后再次凑成一线 → 连锁 +1 层，一层比一层值钱 |
| 石皮封印 | 封住的苗**不能换**（点了只震一下、不扣息），但能被三连收走，收走即解封 |
| 重排 | 花 `shuffleCost` 息，把全盘重排；每局前 `shuffleCap` 次按原价扣，之后每次双倍扣息 |
| 照畦（提示） | 花 `hintCost` 息，指出一步能三连的换位 |
| 结束 | 时辰到 |

**没有 F**：只看时限内的总分。**石皮不判负、重排用尽也不判负**——这两条只会让分变少，
不许变成「这一局废了」。理由见 §4.4。

## 3. 五段递进

每一步只收紧一到两个数，符合「递增曲线平缓，无断崖」：

| 段 | 这一段新学的一件事 | 主轴 |
| --- | --- | --- |
| 一 · 未入门 | 找三连：相邻两株换位、横或竖 ≥3 即采收 | 复杂度（5 色 · 6×6） |
| 二 · 入门 | 无效互换要罚息，「想好了再换」成为必要 | 盘面 6×6→7×7 + 代价（罚息 −1 → −2） |
| 三 · 小成 | 盘面再放大一圈、多一色（5 → 6）：同色候选被压少 | 盘面 7×7→8×8 + 花色 |
| 四 · 大成 | **石皮封印 4 格** + 重排原价次数限 3；罚息再收一档（−2 → −3） | 规则（封印）+ 盘面 8×8→9×9 + 代价 |
| 五 · 圆满 | 封印加倍到 8 格、盘面到 10×10、再多一色（6 → 7） | 规则（封印 ×2）+ 盘面 + 花色 |

**为什么把新机制放在第四段而不是第一段**：前三段（200 关）要先把「找线」练成直觉；
石皮在第一天出现，玩家学到的不是「绕开石头」，而是「这门游戏有时候不让我动」。
放到大成——玩家已经能一眼看出三连——它才是纯加成难度的东西：扫盘时要多看一层「这块石头卡在哪」。

### 3.1 阶段新法（大成 / 大圆满）

| 段位 | 名 | 规则 | 可关 |
| --- | --- | --- | --- |
| 大成 | 照畦 | 「照畦」**少扣 1 息（仍要付）** | 否 |
| 大圆满 | 连收 | 连锁从第 3 层起额外加成；重排少扣 1 息 | 否 |

**这两条是原则第十一节的标准写法**：便利可以有，但必须有明码代价——「少扣 1 息」而不是「不扣」。
而且加成从第 3 层才给，得先打出连锁才拿得到，不是白送。
大成、圆满两段的具体体现分别见 [大成](03-大成.md) §2 / [圆满](04-圆满.md) §2。

## 4. 设计依据

### 4.1 为什么整表管理而不是公式缩放

旧版只有「S 线 620 + depth×150」在变，60 息 / 5 色 / 罚 2 息四段全写死。真控制器跑 12 局的结果：
高手五段 12/12 全 S、常人绝境 10/12 S——**等于同一局打五遍**。

现在每段只收紧一到两个数：

- 简单 → 普通：收时辰与罚息；
- 普通 → 困难：多一色；
- 困难 → 极难：加封印 + 限重排 + 收罚息；
- 极难 → 绝境：封印加倍 + 再多一色。

每一步都只动一两个数，符合「递增曲线平缓，无断崖」。

### 4.2 S 线为什么是「现算」而不是「按段写死」

旧版是五个手填的绝对分（1900 / 1750 / 1400 / 1300 / 950），并且配了一套「越难越低」的理由。
现在改成派生：

```text
S 线 = 每手产出 × floor(本关时辰 / 1.2 息) × 0.72
```

`MATCH_MOVE_SEC = 1.2` 是「一手从看到落定」的真实节奏（含 0.4 息动画），
`MATCH_S_UTIL = 0.72` 是 S 线要求的操作窗口利用率——**约 1.7 息必须落一手**。
`perMove`（每手产出）是实测值：五档各 40 局、假时钟推到 400 手、总得分 ÷ 总手数，
得到 66 / 66 / 56 / 56 / 50。

换掉手填值的三个理由：

1. **手填值和盘面脱钩**。旧表里「9×9 6 色 62 息」的 S 线是 1300，可这个时辰只够落 51 手，
   S 线等于要求每手 25 分——而 8×8 那档只要求 25 分/手；两档实际上一样难，表上却写着「更难」。
   现算之后，五档的**利用率全部落在 0.72**，S 线的含义在五段里是同一句话。
2. **「越难越低」这个理由站不住**。花色多了每手产出确实低（66 → 50），这一条已经由
   `perMove` 吃掉了；再手填一条下降曲线，等于把同一个方向减两遍，圆满段就变成白送。
3. **时辰一改就得同时改五个数**。段内 `duration` 逐关收紧，手填的 S 线跟不上，
   于是出现「第 10 关比第 9 关时辰少 3 息、S 线却一样」的假台阶。现算之后段内每关的 S 线都跟着时辰走。

实测标定（假时钟、每档 40 局）：**1.2 息/手时五档全部拿到 S，3 息/手时五档全部拿不到 S**，
分档落点在两者之间——落点目标是「高手 75–95% 拿得到、常人 5–25%」。
这条由 `tests/rank.test.js` 与 `tests/layout.test.js` 一起守（同源 + 利用率恒定）。

### 4.3 为什么无效互换要罚息

不罚的话，玩家可以靠「狂换」试出三连——换位本身成了搜索工具。罚息让「想好了再换」成为必要。

### 4.4 被否决的方案

这张表记着我否掉的念头——每一条都留着当时的诱因。

| 方案 | 为什么否掉 |
| --- | --- |
| S 线按段写死绝对分 | 见 §4.2：与盘面脱钩，还把一个方向减了两遍 |
| S 线随段上升 | 同上：花色变多已经被 `perMove` 吃掉，再加一条上升曲线就是双重惩罚 |
| 无效互换不罚 | 可以靠试（见 §4.3） |
| 死局不重排 | 卡死玩家 |
| 照畦免费 | 辅助必须有代价（原则第九条） |
| 「照畦不扣息」 | 原则第十一节：便利要有明码代价，改为「少扣 1 息」 |
| **重排用尽即判负** | 死局是盘面自然长出来的，不是玩家打错的。实测 35 对那一档、60 局里平均 0.4 次自然死局、最多 2 次——按「2 次原价」定价合理，但「第 3 次就判负」等于把一手运气变成废局。改为「用尽翻倍 + 不判负」：还救得回来，只是很贵 |
| **封印格连三连也收不走** | 那样死格会永久占位，盘面越打越僵，且玩家没有手段。让它「能被三连收走」把石头变成了目标而不是障碍 |
| **封印格点了扣息** | 玩家分不清「我换错了」和「这块石头不让换」。点了只震一下、浮字说明、不扣息 |
| **石皮从第一段就出现** | 见 §3：前 200 关要先立住「找线」这件事，规则加法放在大成 |

## 5. 界面与反馈

原文 §6「界面」与 §6.5「界面与反馈」合列如下。

- 局内代价句按本段生成：「换不出三连少 N 息」（`tipFor()` 现拼，不写死）；
- 准备页难度栏显示本段花色 / 时辰 / 罚息 / 石皮 / S 线（`stageDetail.brief`）；
- 换段那一关的常驻规格追加「石皮封住 N 格 · 重排原价 N 次（用尽翻倍）」——它不抢
  `levelDelta` 那三条额度，因为它不是「这一关比上一关变了什么」，而是「这一段一直是这样」；
- HUD 常驻「（原价 N）」与「· 石皮 N」，打到第 4 段以后一眼能查到还剩几次；
- 无效互换有轻震反馈，与连锁的中量震动区分开；点石皮是**另一种**震法（单次短震 + 浮字），要能与前者分开。

| 项 | 落点 |
| --- | --- |
| 难度 | 主承重轴是**盘面规格 + 复杂度 + 规则**：盘面 6×6→10×10、花色 5→7、时辰 60–66→42–48 息、罚息 −1→−3、石皮 0→8 格。S 线由本关时辰与每手产出现算（§4.2）。 |
| 显示 | 准备页难度栏写清本段花色 / 时辰 / 罚息 / 石皮 / S 线；局内代价句按段现拼（`tipFor()`），不写死。 |
| 特效 | 一手分三拍演：收走（留空 170ms）→ 落下（同列同时落定，按距离 130–300ms）→ 再查一轮。无效互换轻震。石皮是静态样式，不是动画。详表见 §5.1。 |
| 引导 | goal 一句「换相邻两株凑三连」+ 三步 + 词条；首局有入门卡，教学盘从第四段起多演示一格石皮。 |
| 关卡 | 段内按 `duration` 与 `flashMs` 收紧；盘面只在换段时换副（6×6→10×10）。**1000 关里 149 关真的变了**，其余据实写「与上一关规格相同」。第 1 关与第 1000 关不写那句兜底：两关都没有「上一关」可比（末关常被整秒取整抹平），改报本关起手规格与「比起手关累计变了什么」。 |

**v9 口径修正**：原文写「段内 40 关按 `duration` 与 `flashMs` 收紧」，其中「段内 40 关」是 v8 旧口径；
v9 五段关数为 10 / 40 / 150 / 300 / 500，段内收紧按 v9 关号段理解。

**149 关的由来**：原文实测是 143 关。S 线改成现算之后，它自己也成了一个逐关会变的数
（时辰少 2 息、S 线就低 78 分），多出 6 关「只有 S 线在动」。这不是把台阶凑多——
那 6 关盘面确实一点没变，只是评级要求跟着时辰走了。

### 5.1 一手演三拍

一手不是一个瞬间。三件事压进同一次渲染，盘面就从满的跳到满的——人眼比两帧只能比出
「位置变了」，比不出「少了三株」，连锁叠三层和一层在屏幕上没有区别。

| 拍 | 时长 | 盘面上看见什么 | 为什么必须有这一段 |
| --- | --- | --- | --- |
| 收走 | 170ms（`BEAT.clear`） | 那三株撤掉、格子凹下去（`cell--clear`，静态凹槽，不是一次性动画）、原位迸一小把粒子、HUD 浮字 | 整手唯一「看得见少了东西」的锚点。凹槽写成静态状态：减少动效关掉动画时它还在，「这里刚收走三株」照样读得出来 |
| 落下 | 130–300ms（`BEAT.fallBase + 格数 × fallPer`，封顶 `fallMax`） | 牌从上方掉进格子（`cell--fall`），掉几格走几格；新苗从盘面外进来 | 一格和十格给同一个时长会读成瞬移。**同列必须同时落定**，否则同列两株会在半空互相穿插；列与列各按自己最远那株定时长 |
| 再查一轮 | 0ms | 还有三连 → 回到「收走」，层数 +1 | 连锁是「落下来的新苗又凑成一线」。看不到落下，连锁就像凭空发生 |

无效互换另算一条：两株各抖一下（横向 ±7rpx 三次回正）。只少 2 息、不抖，玩家会以为
「没点上」，接着再点一次。点石皮也有反馈，但**只有一下短震 + 一句浮字**——抖三下会被读成
「这次换位失败了、再试试」，而它其实是「这一格根本换不了」。

**演出期间不收输入，但表照走。** 这一门是限时计分不是步数制：把动画时间从表里扣掉，
手越快局越长，一局打不完。锁输入 + 照走表是业界限时三消的通行做法，
代价是单手演出必须压在 0.5 秒以内（三拍合计 300–470ms，三层连锁约 1.4 秒）。

抖动与下落都只动 `transform`；`cell--fall` 的 `0/1` 交替序号是为了让相邻两手各自重播一次
（同名类连挂两帧不播动画）。`cell--clear` 不需要交替——它是状态，不是一次性动作。

**被否决的方案**

- **整盘连锁脉冲**（每层连锁给全盘加一层光）：连锁本来就带金浮字与粒子，再加整盘光
  是三层叠加，玩家只看到「屏幕在闪」。
- **只给最上面八格挂落下动画**（v10 前的写法）：为了躲开「一二十格一起动等于整盘乱抖」，
  代价是玩家看不见真正移动的那些牌——他看到的「落下」全是新苗，老牌全是瞬移。
  正解是按列同步落定（同列同速，不会穿插），而不是砍掉一半的格子。
- **演出期间停表**：能让滑动更从容，但在限时计分里等于把动画时间送给玩家，
  手快的人一局能打四分钟。要停表就得改成步数制，那是另一门功课。

## 7. 待验

以下为全门性待验；段相关的那几条落在各段篇 §6，本文件不重复。

- 6×6（约 50px/格）到 10×10（约 35px/格）相邻两株互换在大屏 / 4.7 寸小屏的误触率，重点看第九、十段的满宽样式有没有把果器纹挤糊。
- 长按选中与点击取消的容错。
- **石皮的可辨识度**：10×10 盘上 8 格石皮，扫一眼能不能立刻分出「这块不能动」；
  石皮与「已选中」的暖玉高亮会不会互相盖住（两者都在 `cell` 上做视觉）。
- **石皮的难度贡献**：加 4 格 / 8 格之后，五档的 `perMove` 实测值会不会掉出当前标定
  （66 / 66 / 56 / 56 / 50）。掉了就得同批重标 S 线——这是 §4.2 那个公式的唯一输入。
- **原价 3 次够不够**：`shuffleCap` 是按「自然死局平均 0.4 次 / 最多 2 次」定的，
  但那是并蒂引 35 对盘实测；三消的连锁会自己制造死局，得单独实测一轮。
- 「无效互换轻震」在 iOS / Android 上能否与连锁的中量震动、石皮的短震分得开，会不会反而打断观察节奏。
- **三拍的实际手感**：170ms 的空格帧在小屏上够不够看见（看不见就是白发一次渲染）；
  10×10 盘上「整列塌一截」会不会糊成一片；三层连锁连续演 1.4 秒，中间玩家是不是开始抢点。
  这三条只能真机看，代码里量不出来。
- 演出期间不收输入会不会被读成「点了没反应」——真机上抢点一次，看玩家会不会以为卡了。
