# 阵法·洞微勘禁诀 → 数格辨禁（总）

> 石格下埋着禁制，能看到的只有周围露出的数字。按数字把禁位一格格勘出来，钉住、再连开。
>
> 五段六篇：本篇放五段共用的骨架（盘面 / 规则 / 依据 / 界面 / 代码），
> 每段的盘面规格、禁制数、心神与评级线写在各段文档里，两边不互相抄。

- 功法：阵法·洞微勘禁诀（黄阶，qiSave −10%）｜玩法 id：`tanlei`｜阶段新法：勘位 / 洞玄
- 时长基准 `base = 50`（偏长的一门）

## 玩法概述

把它想成一片埋了禁制的石盘。你能看见的只有露出来的数字——每个数字等于它周围八格里埋了几处禁制。
你要做的，就是顺着这些数字把禁位一格格推出来、钉上 `⚑`，再点开剩下的石格。这是扫雷的骨架，
我一个字规则都没往里加；我想做的是把经典做扎实，不是往里塞新花样。

```text
   ↘ 石格下埋禁制，露出的数字是唯一的线索
   ┌───┬───┬───┬───┬───┬───┐
   │ 1 │ 2 │ ✕ │ 2 │ 1 │   │  ✕ 禁制 · ⚑ 阵钉
   ├───┼───┼───┼───┼───┼───┤  数字 = 周围八格的禁制数
   │   │   │ 3 │ ⚑ │ 2 │   │
   ├───┼───┼───┼───┼───┼───┤  读数字 → 定禁位 → 钉旗
   │   │ 1 │ 2 │ ⚑ │ 1 │   │  → 点数字格 chord 连开
   ├───┼───┼───┼───┼───┼───┤
   │   │   │ 1 │ 1 │   │   │
   └───┴───┴───┴───┴───┴───┘
   前段保证纯推理能翻完，后段才留 50/50
```

这一门真正的段差不在时间，在推理方式：前段保证「认得数字就能推完」，后段才把 50/50 留回来。
`deduce` 与 `allowGuess` 就是这条段差的开关（见 §3、§5）——盘变大只是补规模，不是主轴。

扫盘的规则五段一样：盘怎么摆、规则怎么走、界面落在哪、代码在哪、为什么这么设计。数字不一样——每段的盘面与评级各有一篇，别在这里找。

**五段的盘面、禁制、心神与推理深度各走到哪、去哪篇查细节。** 本篇只写共用的骨架：

| 段 | 关 | 关数 | 盘面 | 禁制 | 密度 | 心神 | 推理 | S 线 | 文档 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 一 · 未入门 | 1–10 | 10 | 6×6 | 5 | 14% | 3 盏 | 单格 | ≤25 秒 | [未入门](00-未入门.md) |
| 二 · 入门 | 11–50 | 40 | 6×6 | 6 | 17% | 3 盏 | 单格 | ≤25 秒 | [入门](01-入门.md) |
| 三 · 小成 | 51–200 | 150 | 8×8 | 12 | 19% | 2 盏 | 两数相减 ×1 | ≤44 秒 | [小成](02-小成.md) |
| 四 · 大成 | 201–500 | 300 | 10×10 | 18 | 18% | 1 盏 | 两数相减 ×2 · 留两难 | ≤69 秒 | [大成](03-大成.md) |
| 五 · 圆满 | 501–1000 | 500 | 12×12 | 24 | 17% | 1 盏 | 两数相减 ×3 · 留两难 | ≤100 秒 | [圆满](04-圆满.md) |

盘面 6×6→12×12（4 倍，手机每格约 28px 的上限）、禁制 5→24（4.8 倍），密度 14–19%。
换段换盘面、推理深度、容错与猜局保证；段内盘面与禁制数不动，只靠 `lineScale` 收评级线。
对照竞技扫雷（初级 9×9/10、中级 16×16/40、高级 30×16/99），原来的 9×9/12 只是初级盘——
把「圆满」说成顶峰是假的。这一版推到手机可读上限，不冒充触屏做不到的竞技高级盘。

**段差是三样一起换：推理深度、容错、猜局保证。** 旧版五段密度不变、求解器又只认最基础的单格规则，
于是每一段都是同一种推法，玩家只觉得「盘大了、时间也长了」。`deduce` 是补上的真段差：
布盘时验证这一盘「从首点纯推理能翻完」需要的两数相减次数，首两段要 0 次（保证一眼就会），
小成起分别要 1 / 2 / 3 次。两数相减不是新规则——它是经典扫雷本来就有的进阶推法：
一处数字框住的未知格若被另一处完全包住，两数之差就是外面那一圈的禁制数。

大成、圆满另换两样：`allowGuess` 让盘推到卡住时留 50/50（求解器只有单格/全局/差分三招，
卡住处玩家得读概率或用更活的约束），心神降到 1 盏（踩一次即 F）。
前 3 段仍保证纯推理能推完——「认得数字就会玩」的定位不变。

## 1. 盘面介绍

6×6 至 12×12（36 至 144 格，按段变，见 `MINES_LEVELS`）。每格要么是数字（周围 8 格里有几处禁制），
要么已翻开空白，要么未翻开。

- 面朝下的格子不显示任何东西；
- 盘面只有**数字**与两个通用符号：`✕` 禁制 / `⚑` 阵钉；
- **不落汉字**。

数字是本门唯一的信息来源，所以「盘面不写汉字」不是洁癖，是规则的一部分（见 §4 被否决方案）。

## 2. 规则说明

| 项 | 规则 |
| --- | --- |
| 首点 | 首点及其八邻**无禁制**，第一下必开出一片空白 |
| 整盘无猜 | 未入门至小成：验证从首点纯推理能翻完；大成、圆满反之，必须推到卡住 |
| 误触 | 折 **1 盏心神**，并让那处显形（不是立刻完成） |
| 钉阵钉 | 长按标 `⚑`，再点已翻开的数字格：钉数对上就自动连开其余邻格（chord） |
| 心神耗尽 | 失败 F |
| 时间到 | 失败 F（没探完） |

**前 3 段「整盘无猜」是这一门最重要的规则**：新手不该死在「两格 50/50 只能猜一个」上。
大成、圆满反过来把 50/50 留回来——那是竞技扫雷最难的一块，也是「圆满」该有的分量。

操作三件：点击翻开、长按钉阵钉 / 取消钉、点已翻开的数字格（钉数对上 → chord 连开其余邻格）。
不钉钉照样能玩，会用的人才快。这是「一看就懂，会玩才快」的典型结构。

### 2.1 时间线跟着格数走

评级线 `gradeLine(n, lineScale)` = 25 秒 × 格数 ÷ 36 × 段内系数。三条线 S / A / B 依次是基准的
**1 / 1.8 / 3 倍**：例如 6×6 是 25 / 45 / 75 秒，12×12 是 100 / 180 / 300 秒。
把 12×12 也卡在 25 秒，那不叫难，那叫不可能——**这是给足，不是压缩**：复杂度已经交给盘面与禁制数承担，
秒表只负责让一局别拖太久。

`lineScale` 是这一门在段内的唯一旋钮（盘面与禁制数只在换段时变，见 `data/levels.js` 的 `tweakParams`）。
它按全书进度线性收：第 1 关 100% → 第 1 段末 94% → 全书末 70%。所以**每段只紧 6%**（0.30 ÷ 5 段），
与段长无关——未入门段 10 关走完这 6%，圆满段 500 关也只走这 6%，摊到每关 0.012%。
不是别的门的 30%，因为这一门的参数全是离散量，没有时辰可乘。代价是后段几乎每关都报不出变化，见 §7。

## 3. 五段递进

每一段换的是**盘面规格**，不是秒表：

| 段 | 这一段新学的一件事 | 主轴 |
| --- | --- | --- |
| 一 · 未入门 | 6×6 / 5 禁制 / 3 心神：读数字、首点空白、单格推理 | 复杂度 |
| 二 · 入门 | 仍是 6×6，禁制升到 6（密度 17%）：推理链稍长，阵钉与 chord 开始值钱 | 复杂度 |
| 三 · 小成 | 换 8×8（64 格、12 禁制），心神降到 2，盘开始逼你用一次「两数相减」 | 推理方式 |
| 四 · 大成 | 换 10×10（100 格、18 禁制），心神降到 1，勘位登场；每盘至少两次两数相减，且留两难处 | 推理方式 + 容错 + 概率 |
| 五 · 圆满 | 换 12×12（144 格、24 禁制），洞玄登场；每盘至少三次两数相减，零容错且留两难处 | 推理方式 + 容错 + 概率 |

### 阶段新法（大成 / 大圆满）

| 段位 | 名 | 规则 | 可关 |
| --- | --- | --- | --- |
| 大成 | 勘位 | 每局开局勘出 3 处禁位并标出 | 否（纯便利） |
| 大圆满 | 洞玄 | 开局勘出 5 处禁位 | 否 |

**这两条是「给便利」，不是「改规则」**——所以不给开关（多一个开关只是多一处看不懂）。
洞微勘禁诀是黄阶入门功课，不该往经典扫雷里加新花样。

## 4. 设计依据

### 4.1 「把经典做扎实」，而不是「往里塞新规则」

扫雷之所以好玩，是因为「信息足够、推理可行」。所以这里的深耕是三处补齐：

1. 首点必开出空白区（不会开局被一个数字堵死）；
2. 前 3 段整盘无猜（新手不会死在 50/50），后 2 段把 50/50 留回来；
3. chord（钉+连开）真的好用。

**规则一个字没加**。变的只是布盘时按段筛盘——后段逼你用经典扫雷本来就有的两数相减，
大成起还把无猜保证反过来。这让它稳在黄阶，也让「看一眼就会玩」这个定位成立：首段依然只用单格规则，
玩家是一段段学会更深的推法，不是一进门就被新规则砸中。

### 4.2 一次误触不判负

旧版是「误触即完成」。改成「折一盏心神、那处显形」之后，玩家在前 3 段有一到两次容错、后两段零容错，而显形本身也提供了信息。

「显形」这个设计还有一层用意：误触不是纯损失，你至少知道了那里有什么。

### 4.3 盘面为什么要随段变大

旧版盘面恒 6×6，五段只有禁制数（5→8）与心神（3→2）在变，而 6×6 的扫雷本身就太浅：
36 格、8 处禁制，推理链两三步就到底，玩家摸不到「盘越大、约束传播越长」这一层真正的难。
这也是它曾经在审计里只有 1.6 倍跨度的原因。
现在推到 12×12（4 倍跨度）是补规模，但明确不是难度主轴：手机每格约 28px 已是下限，
再大就得靠横屏或缩放，那会破坏「一趟参悟」的节奏。

### 4.4 被否决的方案

这些是我否掉的路，留下来是因为它们解释了这门功法的分寸感从哪来——每一条都记着当时的诱因：

| 方案 | 为什么否掉 |
| --- | --- |
| 允许存在需要猜的局面 | 只对新手段成立：未入门到小成不猜，避免最劝退的 50/50；大成起反而要留 |
| 误触即完成 | 旧版问题（见 §4.2） |
| 首点随机（可能踩禁） | 开局就死，毫无道理 |
| 盘面写「禁 / 钉」汉字 | 盘面不写汉字 |
| 往扫雷里加本门特有机制 | 会破坏「一看就懂」，也让它配不上黄阶。现在的推理深度不是加机制：两数相减是经典扫雷本来就有的推法，首段仍是单格盘 |
| 把后段盘做成「纯靠猜」的赌局 | 后段留 50/50，但卡住前必须逼出 2/3 次两数相减——是推理之后的赌，不是不推理就赌 |

### 4.5 一处已修的 bug（值得记住）：score 方向反了

旧实现把「耗时秒数」当 `score` 传给 `finish()`。而 `applyPractice` 按 `score > prevBest` 记破纪录——
**越慢反而越容易破纪录**，方向是反的。

现在 `finish.score` 一律「越大越好」，这一门的 score 是「探完的进度 + 时间奖励」，不再是裸秒数。

### 4.6 段内旋钮曾经是「假话」

`lineScale` 曾由 `buildParamsAt` 生成、`stageDetail` 报成「S 线 94%」，但 `mines.js` 里没人读它，
盘面一关都没变。静态校验全绿，因为值确实生成了。补的是消费端（`gradeLine(n, scale)` 与 `lines()` 同源），
不是生成端；`verify` 8b-5d 现在按「每个段内旋钮都必须在对应玩法模块里被读到」守着这一类失效。

## 5. 界面与反馈

判据只有一句：**这一手做对了，盘面上该看见什么。**

| 项 | 落点 |
| --- | --- |
| 难度 | 主承重轴是**推理方式 + 容错 + 概率**：`deduce` 0/0/1/2/3 撑起推理段差，心神 3/3/2/1/1 收紧容错，`allowGuess` 后两段留 50/50；盘面 6×6→12×12、禁制 5→24 只补规模（手机上限）。段内靠 `lineScale` 收 S 线，不往速度上加码。 |
| 显示 | 常驻四样：`已探 X / Y`（进度条）、**`阵钉 X / N`**、心神灯、`S 线 N 秒`。数字按 1 / 2 / 3+ 分三段色，这是经典扫雷唯一值得照搬的辅助。三者对得上才叫「看得见」：盘面数字、盘上阵钉、剩余禁制。局内 status 在需要两数相减的段写「此盘不必猜 · 两处数字合起来看」，后两段改说「有处两难 · 先推能定的，余下再赌一把」。 |
| 特效 | 盘面反馈（只作用于 `board--mines`）：翻出一片 → 青石屑从落点向外散 + 一圈涟漪；只开一格 → 三粒小屑，不荡环；踩禁 → 朱砂冲击环；连开 → 金色扫光；钉旗 → 小金圈原地扣进石面。浮字照旧：误触「心神 −1 · 禁制显形」、开出一片「石开 N 格」、只开一格「石格无事」、chord「阵光连开 N 格」、钉数不对「阵钉未合」。 |
| 视觉 | 整盘是青灰石，不是暖褐泥：未探浅而凸（L≈37%，顶缘高光、底缘暗）、已探深而凹（L≈15%，顶缘内暗），数字是唯一亮起来的东西。极性死结不变——已探一旦做成全盘最亮，探开一片就是反光板。昼夜各一套令牌在 `styles/tokens.wxss`，夜间由 `.pg--t-night` 转接。 |
| 引导 | 一句 goal（数字＝周围八格禁制数）+ 五步 + 七个词条 + 一行 inline；首局有入门卡（`rec.introed`）。引导里**不写死秒数**——三条线随盘面与段变，写死的那版在 12×12 章起就是错的。 |
| 关卡 | 逐关靠 `lineScale` 收，`levelDelta` 报「S 线 96.4% → 96.3%」这一类。**1000 关里 232 关真的报得出变化**（其余 768 关据实写「与上一关规格相同」），越往后越稀——每段只收 6%，摊到 500 关上每关 0.012%。盘面只在换段时变（6→6→8→10→12），这是「本段换了一种盘」的明说，不是偷偷加难。 |

**「阵钉 X / N」是这次补的。** 少了它，玩家钉了七个而本段只有六个禁制时，屏幕上没有任何地方能看出来——
数字、阵钉、禁制数这三条线断了一条。钉超了照实写 `7 / 6`，不替你修正：钉多了本身就是线索。

## 6. 代码指路

- `minigames/mines.js` —— 按段筛盘（单格 / 全局 / 两数相减三族，记 `deep`；前段保证无猜、后段保证有猜）、首点安全、chord、心神、`lineScale` 与阵钉读数
- `data/practice.js` —— `MINES_LEVELS`（含 `deduce` / `allowGuess`）、`MINES_HEARTS`、`tanlei` 的 `params`
- `data/levels.js` —— `tweakParams()` 里的 `lineScale`（段内收紧的唯一旋钮）
- `data/practice.js` —— `STAGE_RULES.tanlei`（勘位 / 洞玄）
- `data/guides.js` —— 「两处数字合起来看」的推法说明
- `pages/practice/practice.js` / `.wxml` / `.wxss` —— `mineFxList` 盘面反馈层
- `styles/tokens.wxss` —— 探禁昼夜两套石盘色板
- `tests/minigames.test.js` —— 黑盒推理、首点安全、无猜、**推理深度与猜局双段差反证**
- `tests/layout.test.js` —— 盘面无汉字、`✕` / `⚑` 渲染、特效层与令牌接线

## 7. 待验

- chord 的「钉数对上」判定是否够灵敏——玩家可能钉错一个就以为功能坏了。
- 数字在深色格上的对比度（数字是本门唯一的信息来源）。
- **阵钉读数挤在心神那一行的右端**：`◆◆◆ 心神 3 / 3` 已经占了左侧，右边再挂一个 `阵钉 2 / 6` 的标签，
  320px 宽的屏上会不会折行或被裁——必须真机看。
- **后段几乎报不出变化**：`lineScale` 按全书进度线性收（每段 6%、全书 30%），未入门段 10 关走完这 6%
  （每关 0.6%），圆满段 500 关也是这 6%（每关 0.012%），而界面精度是 0.1%——后段大多数关的
  `levelDelta` 是空的。这不再影响段差（真段差已交给 `deduce`，换段必变），但逐关「这一关变了什么」
  在后段仍然是空话。要么改成按段内进度收，要么接受它只是名义变化——**待拍板**。
- **玩家能不能学会两数相减**：首段只用单格规则，小成起盘会逼你用两处数字相减。核心约束都说明写在
  `data/guides.js`，但教学盘只演示到「数字＝周围八格禁制数」，没有一步演示相减。**必须真机验**
