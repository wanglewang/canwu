## 1. 盘面骨架（五段共用）

6×6 至 9×9（36 至 81 格，按段变，见 `MINES_LEVELS`）。每格要么是数字（周围 8 格里有几处禁制），
要么已翻开空白，要么未翻开。

- 面朝下的格子不显示任何东西；
- 盘面只有**数字**与两个通用符号：`✕` 禁制 / `⚑` 阵钉；
- **不落汉字**。

数字是本门唯一的信息来源，所以「盘面不写汉字」不是洁癖，是规则的一部分（见 §4 被否决方案）。

## 2. 规则骨架（五段共用）

| 项 | 规则 |
| --- | --- |
| 首点 | 首点及其八邻**无禁制**，第一下必开出一片空白 |
| 整盘无猜 | 布完禁制后用约束传播验证：从首点纯推理能翻完，否则重布 |
| 误触 | 折 **1 盏心神**，并让那处显形（不是立刻完成） |
| 钉阵钉 | 长按标 `⚑`，再点已翻开的数字格：钉数对上就自动连开其余邻格（chord） |
| 心神耗尽 | 失败 F |
| 时间到 | 失败 F（没探完） |

**「整盘无猜」是这一门最重要的规则**：新手不该死在「两格 50/50 只能猜一个」上——那是扫雷最劝退的地方。

操作三件：点击翻开、长按钉阵钉 / 取消钉、点已翻开的数字格（钉数对上 → chord 连开其余邻格）。
不钉钉照样能玩，会用的人才快。这是「一看就懂，会玩才快」的典型结构。

### 2.1 时间线跟着格数走

评级线 `gradeLine(n, lineScale)` = 25 秒 × 格数 ÷ 36 × 段内系数。三条线 S / A / B 依次是基准的
**1 / 1.8 / 3 倍**：例如 6×6 是 25 / 45 / 75 秒，9×9 是 56 / 101 / 169 秒。
把 9×9 也卡在 25 秒，那不叫难，那叫不可能——**这是给足，不是压缩**：复杂度已经交给盘面与禁制数承担，
秒表只负责让一局别拖太久。

`lineScale` 是这一门在段内的唯一旋钮（盘面与禁制数只在换段时变，见 `data/levels.js` 的 `tweakParams`）。
它按全书进度线性收：第 1 关 100% → 第 1 段末 94% → 全书末 70%。所以**每段只紧 6%**（0.30 ÷ 5 段），
与段长无关——未入门段 10 关走完这 6%，圆满段 500 关也只走这 6%，摊到每关 0.012%。
不是别的门的 30%，因为这一门的参数全是离散量，没有时辰可乘。代价是后段几乎每关都报不出变化，见 §7。

## 3. 五段怎么变

每一段换的是**盘面规格**，不是秒表：

| 段 | 这一段新学的一件事 | 主轴 |
| --- | --- | --- |
| 一 · 未入门 | 6×6 / 5 禁制 / 3 心神：读数字、首点空白、基础推理 | 复杂度 |
| 二 · 入门 | 仍是 6×6，禁制升到 6（密度 17%，五段最高）：推理链稍长，阵钉与 chord 开始值钱 | 复杂度 |
| 三 · 小成 | 换 7×7（49 格、8 禁制）：盘变大，约束传播更长 | 复杂度 |
| 四 · 大成 | 换 8×8（64 格、10 禁制），心神降到 2：容错收紧，勘位登场 | 复杂度 |
| 五 · 圆满 | 换 9×9（81 格、12 禁制）：最大的盘，洞玄登场 | 复杂度 |

### 阶段新法（大成 / 大圆满）

| 段位 | 名 | 规则 | 可关 |
| --- | --- | --- | --- |
| 大成 | 勘位 | 每局开局勘出 3 处禁位并标出 | 否（纯便利） |
| 大圆满 | 洞玄 | 开局勘出 5 处禁位 | 否 |

**这两条是「给便利」，不是「改规则」**——所以不给开关（多一个开关只是多一处看不懂）。
洞微勘禁诀是黄阶入门功课，不该往经典扫雷里加新花样。

## 4. 设计依据

### 4.1 「把经典做扎实」，而不是「往里塞新规则」

扫雷之所以好玩，是因为「信息足够、推理可行」。所以这里的深耕是三处补齐：

1. 首点必开出空白区（不会开局被一个数字堵死）；
2. 整盘无猜（不会死在 50/50）；
3. chord（钉+连开）真的好用。

**规则一个字没加**。这让它稳在黄阶，也让「看一眼就会玩」这个定位成立。

### 4.2 一次误触不判负

旧版是「误触即完成」。改成「折一盏心神、那处显形」之后，玩家有一次到三次的容错，而显形本身也提供了信息。

「显形」这个设计还有一层用意：误触不是纯损失，你至少知道了那里有什么。

### 4.3 盘面为什么要随段变大

旧版盘面恒 6×6，五段只有禁制数（5→8）与心神（3→2）在变，而 6×6 的扫雷本身就太浅：
36 格、8 处禁制，推理链两三步就到底，玩家摸不到「盘越大、约束传播越长」这一层真正的难。
这也是它曾经在审计里只有 1.6 倍跨度的原因。

### 4.4 被否决的方案

| 方案 | 为什么否掉 |
| --- | --- |
| 允许存在需要猜的局面 | 最劝退，且与「推理」品类相悖 |
| 误触即完成 | 旧版问题（见 §4.2） |
| 首点随机（可能踩禁） | 开局就死，毫无道理 |
| 盘面写「禁 / 钉」汉字 | 盘面不写汉字 |
| 往扫雷里加本门特有机制 | 会破坏「一看就懂」，也让它配不上黄阶 |

### 4.5 一处已修的 bug（值得记住）：score 方向反了

旧实现把「耗时秒数」当 `score` 传给 `finish()`。而 `applyPractice` 按 `score > prevBest` 记破纪录——
**越慢反而越容易破纪录**，方向是反的。

现在 `finish.score` 一律「越大越好」，这一门的 score 是「探完的进度 + 时间奖励」，不再是裸秒数。

### 4.6 段内旋钮曾经是「假话」

`lineScale` 曾由 `buildParamsAt` 生成、`stageDetail` 报成「S 线 94%」，但 `mines.js` 里没人读它，
盘面一关都没变。静态校验全绿，因为值确实生成了。补的是消费端（`gradeLine(n, scale)` 与 `lines()` 同源），
不是生成端；`verify` 8b-5d 现在按「每个段内旋钮都必须在对应玩法模块里被读到」守着这一类失效。

## 5. 界面与反馈（五项逐门过）

判据只有一句：**这一手做对了，盘面上该看见什么。**

| 项 | 落点 |
| --- | --- |
| 难度 | 主承重轴是**复杂度**：盘面 6×6→9×9（2.25 倍）、禁制 5→12（2.4 倍），密度稳 14–17%；段内靠 `lineScale` 收 S 线。不往速度上加码——扫雷难在「信息拼得出来吗」，不在手快。 |
| 显示 | 常驻四样：`已探 X / Y`（进度条）、**`阵钉 X / N`**、心神灯、`S 线 N 秒`。数字按 1 / 2 / 3+ 分三段色，这是经典扫雷唯一值得照搬的辅助。三者对得上才叫「看得见」：盘面数字、盘上阵钉、剩余禁制。 |
| 特效 | 误触 → 那一格当场翻成 `✕` + 浮「心神 −1 · 禁制显形」；开出一片 → 浮「石开 N 格」（只开一格仍是「石格无事」，两种手感不该同一句话）；chord 成功 → 「阵光连开 N 格」；钉数不对去点数字格 → 「阵钉未合」。 |
| 引导 | 一句 goal（数字＝周围八格禁制数）+ 五步 + 七个词条 + 一行 inline；首局有入门卡（`rec.introed`）。引导里**不写死秒数**——三条线随盘面与段变，写死的那版在 9×9 章起就是错的。 |
| 关卡 | 逐关靠 `lineScale` 收，`levelDelta` 报「S 线 96.4% → 96.3%」这一类。**1000 关里 232 关真的报得出变化**（其余 768 关据实写「与上一关规格相同」），越往后越稀——每段只收 6%，摊到 500 关上每关 0.012%。盘面只在换段时变（6→7→8→9），这是「本段换了一种盘」的明说，不是偷偷加难。 |

**「阵钉 X / N」是这次补的。** 少了它，玩家钉了七个而本段只有六个禁制时，屏幕上没有任何地方能看出来——
数字、阵钉、禁制数这三条线断了一条。钉超了照实写 `7 / 6`，不替你修正：钉多了本身就是线索。

## 7. 全门待验

- chord 的「钉数对上」判定是否够灵敏——玩家可能钉错一个就以为功能坏了。
- 数字在深色格上的对比度（数字是本门唯一的信息来源）。
- **阵钉读数挤在心神那一行的右端**：`◆◆◆ 心神 3 / 3` 已经占了左侧，右边再挂一个 `阵钉 2 / 6` 的标签，
  320px 宽的屏上会不会折行或被裁——必须真机看。
- **后段几乎报不出变化**：`lineScale` 按全书进度线性收（每段 6%、全书 30%），未入门段 10 关走完这 6%
  （每关 0.6%），圆满段 500 关也是这 6%（每关 0.012%），而界面精度是 0.1%——后段大多数关的
  `levelDelta` 是空的。要么改成按段内进度收（但那几门的参数是离散量，段内会重置难度），
  要么接受它只是「名义上在变」——**待拍板**。
- 与盘面精度、2 盏心神、钉超提示有关的段相关问题，分别落在对应段篇的 §6；本文件不重复。
