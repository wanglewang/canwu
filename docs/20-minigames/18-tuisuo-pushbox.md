# 挪移·石箱归位诀 → 推石入位

> 人走在石格上，石箱只推不拉；每块都要推到自己的阵位，一处不落。

- 功法：挪移·石箱归位诀（黄阶，power 对战战力 +4%）｜玩法 id：`pushbox`（模块 `pushbox.js`，名为「推石入位」）
- 时长基准 `base = 36`
- 阶段新法：大成「死位」（死格压暗纹）、大圆满「临渊」（一推就进死位时描红）——只改显示，不改判定，见 §3.1
- 没有首局教导脚本
- **每局现抽一张图**：段位只给规格（盘多大、几处阵位、几道内墙、最优推数区间），
  图由生成器按规格现抽，同一段连打两局看到的是两张盘

## 1. 盘面

盘面按段给规格，图现抽。`inner` 是内盘边长，实际列数 = `inner + 2`（外面一圈石壁）。

| 段 | 盘 | 阵位 | 内墙 | 最优推数 | 生成强度 `pulls` |
| --- | --- | --- | --- | --- | --- |
| 未入门 | 4×4 内盘（6 列） | 1 | 0 | 2～3 | 5 |
| 入门 | 4×4 内盘（6 列） | 1 | 1 | 2～4 | 6 |
| 小成 | 4×4 内盘（6 列） | 2 | 1 | 3～5 | 9 |
| 大成 | 5×5 内盘（7 列） | 2 | 2 | 4～6 | 11 |
| 圆满 | 5×5 内盘（7 列） | 3 | 2 | 5～8 | 15 |

地图字符：`#` 石壁 / `.` 空地 / `b` 石箱 / `o` 阵位 / `p` 人 / `*` 箱在阵位上 / `+` 人在阵位上。

七列只出现在最后两段，样式是 `pages/practice/practice.wxss` 的 `.grid--c7`（每格 14.29% 宽、96rpx 高），
与六列共用同一副台面与玉牌。

### 1.1 图是怎么抽出来的

生成器**从解往回走**，不是先撒箱子再找解：

1. 打乱内盘格子，依次取走内墙、阵位、人；
2. 石箱先摆在阵位上——此刻这一局已经「入位」；
3. 反复挑一块箱子往回「拉」一格：箱子从 `q` 退到 `q-d`，人必须能站到 `q-2d`
   （正向推时该站的位置），且 `q-d` 不是墙、不是别的箱子、不是阵位；
4. 拉够本段的 `pulls` 步（上下一格浮动）后落盘，再用 `solve()` 算出**真实最优推数**；
5. 最优推数落在本段区间就收下；不在就重抽，最多 24 次，仍不中就交「离区间最近」的那张。

因为每一步都是正向推的可逆动作，**抽出来的图一定可解**——照反序推回去就是答案。
`tests/minigames.test.js` 的「图每局现抽，可解、落在本段区间、同段不是同一张」逐段抽 25 局真的走完一遍。

两条硬约束写在生成器里：

- **禁止反向抵消**：同一块箱子上一步往哪拉，这一步不许往反方向拉。否则净位移为零却吃掉一次机会，
  最后抽出一张「看着乱、其实两步就完」的图。
- **箱子不许停在阵位上**：那等于这一箱开局就入位，白送一处阵位。

## 2. 规则

| 项 | 规则 |
| --- | --- |
| 走动 | 方向键走一格，撞墙、撞箱都走不动 |
| 推箱 | 往前一格是石箱时，人推它往前一格；箱子后面是墙或另一只箱 → 推不动 |
| 入位 | 每个阵位都压上一块石箱即完成（箱数 = 阵位数） |
| 预算 | `capPushes = max(最优 + 4, ceil(最优 × capFactor))` |
| 走火（F） | 预算用尽还有阵位空着 → F |
| 撤销 | `undo` 只把人与箱子挪回上一步之前的位置、走步数退回，**推数照算** |
| 复位 | `reset` 回到**本局**开局图、推数清零，但**本盘最高只判 A** |
| 得分 | `(预算 − 已推) × 20 + 200`，只用于破纪录 |

## 3. 操作

四向方向键（`▲ ◀ ▼ ▶`）+ 撤销 + 复位，三个按钮同屏。

- 推不动时轻震 + 「推不动：箱子后面被挡住了」；
- 撞墙只说「那边是石壁」，不震；
- HUD 右上角显示「余 N 推」，不是秒数——这一门没有时钟。

### 3.1 盘面上的标记与阶段新法

练到段位多两处「看得更清」（`STAGE_RULES` 里不带 `hard`，准备页不给开关，判定一个字没动）：

| 段位 | 名 | 做什么 | 为什么是它 |
| --- | --- | --- | --- |
| 大成 | 死位 | 推到那里就再也推不出来的格子压一道斜纹（`cell--doom`） | 标记不替你找路：阵位在哪本来就看得见，缺的是「这一格一进就完」。这一门最先要养成的习惯正是「推之前先看退路」 |
| 大圆满 | 临渊 | 石箱与死位只差一推时，那个死格描红（`cell--doom-hit`） | 暗纹是静态地图，描红是「眼下的这一推」。两者点在不同时刻：一个在规划时看，一个在动手前看 |

**死位怎么判**：一块石箱站在某格，**只认石壁**（把别的箱子、人要怎么绕统统当成不存在），推来推去还推不推得到任何一处阵位。
宽松都推不到，真实局面就更推不到——所以暗纹**只漏标、不冤标**。冤标的代价比漏标大得多：
玩家会照着暗纹绕开一条本来走得通的路。四角必是死位（两条垂直方向都封死，一步都动不了），是这套判定的下限。

三层意思要分清：

- 死位不是禁区，是「箱子进去以后这一局就解不开了」。人照走，箱子没推进去就没事；
- 标记**不改判定**：能推的照样推得动，推错照样费推数，复位照样封顶 A；
- 箱子真被推进死位时，那一格当场描红（`cell--boxed.cell--doom-hit`）——不必等玩家复位之后再猜是哪一步推坏的。

人站在死位上时暗纹照样留着：这一格「不能进箱」与人站不站无关，人一走开它还是死位。

守卫在 `tests/minigames.test.js`：未到大成一处暗纹都不许有；大成的每一格暗纹都必须是真死位，反过来凡是死位都必须标；
四角必在死位里（语义锚点，不靠同一套算法自证）；临渊只在「某块箱子一推就进」时描红，被箱子或人自己占着的那格不描。

## 4. 五段参数

| 段 | 阵位 / 内墙 | 最优推数 | `capFactor` | 预算（按区间两端算） |
| --- | --- | --- | --- | --- |
| 未入门 | 1 / 0 | 2～3 | 2.20 | 6～7 |
| 入门 | 1 / 1 | 2～4 | 2.00 | 6～8 |
| 小成 | 2 / 1 | 3～5 | 1.90 | 7～10 |
| 大成 | 2 / 2 | 4～6 | 1.75 | 8～11 |
| 圆满 | 3 / 2 | 5～8 | 1.60 | 9～13 |

`capFactor` 从 2.2 一路收到 1.6，是**区分度审计补上的第二个参数**：它让「越难余量越薄」这句话有数。
注意 `max(最优 + 4, …)` 这一层兜底：未入门段 `ceil(2 × 2.2) = 5`，但 `2 + 4 = 6` 更大，所以走兜底值。
它保证再紧的段也至少给 4 次冗余。

**为什么最优推数写成区间不写定值**：图每局都不一样，写「S 线是 6 推」等于骗人。
准备页写本段区间，局内 HUD 报的是这一张图自己的最优（生成时就解出来了），两个数各说各的、都不假。

## 5. 评级

| 评 | 判据 |
| --- | --- |
| S | 已推次数 = 本图最优推数 |
| A | 多 2 次以内 |
| B | 不超过最优的两倍 |
| C | 超过两倍才全部入位 |
| F | 预算用尽还没入位 |
| — | **复位过本盘，S 一律降到 A**；撤销不退推数 |

比值族，分母是本图最优推数。

**用推数而不步数**，这是这一门最要紧的一条判断：走多少步不值钱——绕多远都是免费的，把箱子推到错的方向才是真的费事。用步数评级会让「站原地绕圈」变成一件有代价的事，反而惩罚正常探索。

### 反悔的两种代价

这一门有两个反悔按钮，堵法不一样，因为它们的漏洞不一样：

- **撤销**的漏洞是「退还计数」。原来 `undo` 把 `pushes` 一起回退，推错一步撤销就当没发生过。现在的做法是**只退位置、不退推数**：人回到上一步站的地方，箱子也退回去，但这一推已经算进账里。撤销仍是逃生通道（不会卡死在角落），用它是付钱的。
- **复位**的漏洞是「重置计数 + 回同一张图」。推数直接清零，所以必须**记一次痕、封顶 A**，与滑块让路、阵灯推演的复位一条规矩（阵灯的感应另走「折步数」，不靠封顶）。图现在每局都换，但复位回的是**本局**的开局，漏洞形状没变。

为什么不给撤销也封顶：撤销在推箱子里是高频操作（走错一格就要用），一封顶等于把整局 S 都封掉了，「随手撤一下」与「整盘重来」被压成同一件事，代价失去区分度。而「推数照算」既保留了 S 的可能（只要还原之后不再多推），又让每次撤销真实付账。判据见 `00-foundation/02` 第九节 9.3。

### 换图不是漏洞

玩家打崩了可以退出重开，于是拿到一张新图。这不算钻空子：重开抽到的仍是**同段**的图（下界受区间约束），
难度不会更低；而这一门本来就该「每局都是新的推演」。真正的漏洞只有「同一张图反复复位试出最优解」，
那一条由复位封顶 A 堵着。

## 6. 设计依据

### 为什么图必须每局现抽

这一门原来按段分配五张手排图（简单永远第一张）。图一固定，第三遍开始玩家记的就是答案而不是走法——
「先给谁让路」的推演退化成「把记熟的顺序按一遍」。十二原则第一条要的是玩法内核，
而这一门的内核是**推演**，不是**回忆**。所以段位保留「规格」，把「哪张图」交给生成器。

代价是**教学顺序要靠规格表达**，不能再靠手排：未入门段 1 处阵位、0 内墙，就是「绕到箱子背后」这一课；
入门段 1 道内墙，逼出「推下去再横挪」；小成段第 2 处阵位，逼出「不能拿一块顶两处」。
手排能做而现抽做不到的是「第 3 张正好是个墙角」这种具体地形，这条被接受——
换来的是每一局都要真看盘，而不是回忆上一次。

### 与滑块让路、落石垒基三方对比

| | 滑块让路 | 推石入位 | 落石垒基 |
| --- | --- | --- | --- |
| 谁动 | 整块平移，能左右挪 | 人走，箱子只推 | 块自己落 |
| 目标 | 主块到出口 | 每块到自己的阵位 | 填满整层消除 |
| 不可逆 | 可以复位重来 | 推错方向就回不来 | 堆到顶即死 |
| 评级分母 | 最优步数 | 最优推数 | 消除层数 |

三者最像的是让主出阵诀与石箱归位诀：都是「挪东西到指定位置」。分野在于**推箱只推不拉**——这使「箱子被推进角落」成为一种不可恢复的错误，而让主出阵诀的块永远能往回挪。

### 为什么最优推数必须现算

手写的数一旦与地图不符，S 线立刻失真。图现在每局都换，手写更不可能。
`solve()` 按「推一次算一步」做 BFS，人在盘上怎么绕不计，这与评级口径完全一致。
生成器调它时带 `cap = 本段上界 + 2`：只需要知道这张图有没有超界，不必跑到八十层。

### `capFactor` 为什么逐段递减

预算 = 最优 × `capFactor`。若五段都用 2.2，圆满段 6 推就能用 13 次，C 线（12 推）反而比预算更紧，C 带消失。收到 1.6 之后绝境是 9～13 次预算——**C 与 F 之间重新有了区分**。

### 被否决的方案

| 方案 | 为什么否掉 |
| --- | --- |
| 按步数评级 | 走多少步不值钱，见上 |
| 随机撒箱子 + BFS 判有没有解 | 4×4 里六成以上的随机位置箱子已经顶死在墙角（既推不动也解不开），一局要抽几十次才有一张能用；反向生成一步到位 |
| 手写最优推数 | 图每局都换，手写必然失真 |
| 八张、十二张固定图轮换 | 仍然能被背完，只是把「第三遍」推到「第十三遍」 |
| 加大盘面（8×8 起） | 手机上单格过小，且推箱在大盘上会变成长时间试错 |
| 五段都固定 `capFactor = 2.2` | 圆满段的 C 带会消失 |
| 箱子可以拉 | 一拉就没有「推错回不来」这个核心约束，与让主出阵诀重复 |

## 7. 代码指路

## 8. 待验

- ~~文案与机制不一致~~ **已修**：原来 `costText` 写「推不回来：推错方向只能重来」，而 `undo` 把 `pushes` 一起回退——既说错了，也留了刷 S 的口子。现在文案是「推错可退一步，推数照算；复位后本盘最高 A」，机制同步改成撤销不退推数 + 复位封顶。七处字面（`practice.tip`、`pushbox.js` 的 `costText` / `vm.hint` / 结算 notes / 两处注释、`guides.js` 的步骤、`skills.js` 的气韵）一并改。**注意 `guides` 里原本第 2 步说「只能复位重来」、第 4 步说「可以拉」，自相矛盾**，这一版才清掉。
- ~~撤销是无限的~~ **撤销仍然无限次，但不再是漏洞**：次数不限是对「走错一格」的必然让步（限次会让玩家不敢动），代价改为落在推数上——撤一次就多记一推，反复撤会把自己推出 S 线。与让主出阵诀的「复位无限次 + 封顶 A」是同一漏洞的两种堵法。
- **现抽的图好不好看**：反向生成的图有「箱子贴着墙、阵位在半空」的古怪构图，与前五张手排图的观感不同。
  真机上要确认这些图是「有推演感」还是「一眼看不懂」。
- **同段两张图的难度落差**：区间是 2～3、5～8 这样的跨度，圆满段内最易与最难差三推。
  玩家会不会觉得「这一局白给、下一局被坑」。
- **生成耗时**：圆满段一次生成要跑 1～5 次 BFS，Node 上十几毫秒，真机（低端安卓）可能到几十毫秒。
  开局那一帧是否会顿一下，需要真机量。
- **7×7 盘**：最后两段列数从 6 变 7，单格约 100rpx，石箱与阵位的图案是否还分得清。
- 六列宽在窄屏（iPhone SE 375pt）上是否需要 `vm.extras.compact`（当前已置 true）。
- **「推数照算」是否够直观**：玩家看到撤销后「已推」没减，可能以为按钮坏了。当前靠 `vm.status` 写「退回一步 · 这一推照算」，真机上是否读得到待验。
- **暗纹会不会糊成一片**：`cell--doom` 是底色加一道 135° 斜纹，密度 13rpx。7×7 盘上单格约 100rpx，斜纹是否还在「一眼看出与空地不同」之内；
  如果读成脏渍，就把斜纹换成四角的一道折角线。真机看。
- **描红与暗纹同时出现时会不会打架**：`cell--doom-hit` 的 3rpx 内描边压在同一格上，两层的对比度是否够。真机看。
- **死位会不会被当成「陷阱提示」而过度谨慎**：标记只在推演层，人走进去没有代价。玩家会不会以为人也进不得——说明页没写死位，只看盘面。真机看。
