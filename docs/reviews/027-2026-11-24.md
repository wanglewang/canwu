# 027 · 2026-11-24 · 删掉「熟练度」整条线（存档 v10）

## 变更声明

用户原话「统一叫入门、小成等，不要搞两套了，熟练度作废，删掉」，并在澄清中选定**「连机制一起删」**——不是只删那套名字，而是把「每门功法有一条独立的『练得多熟』累积」这件事本身拿掉。

结果是**功法只剩一条进度线**：`rec.cleared`（0–1000，一局 +1），功法的「级」就是走到第几关。六档名字统一采用关卡段位名 **未入门 / 入门 / 小成 / 大成 / 圆满 / 大圆满**，门槛 = 段界关 `0 / 10 / 50 / 200 / 500 / 1000`。存档升到 **v10**。

改的是**一个维度，不是一次改名**：`prof`（0–99999）、連 S 倍率、回关折减、`levelFactor` / `profByLevel` / `factorText`、`abandonRound` 空壳整条退役。全项目 60 余份文件同步，不留双轨。

**回关护栏变成结构性的。** 旧版靠一道连续折减（`本关 ÷ 当前关 × 段基数比`）去堵「停在低关刷」，而它从来没堵住——段成本涨四倍半，任何「停在低段反复刷」都更省（实测 6000 点灵力下只刷第 1 关 11551 点 vs 逐关进 6399 点，1.8 倍反超）。现在 `playedNo === curNo` 一个布尔把回关挡在推进之外：**回关的收益是 0，不是 1/40**。0 不需要折减曲线，也不会被省下的气盖过。

## 三、存档 v10

`SAVE_VERSION = 10`。迁移做两件事：`delete rec.prof`、`delete next.sCombo`（`next` 即 `state.sCombo`）。

**纯摘字段，一个数都不重算**：`cleared` 在 v9 已经是正确的，`prof` 那条线当时只是并排躺着没人读。凡是「删掉一条并行的记录」都该走这一步——先确认没人读，再删；别顺手重算一个可能算错的数。

老档里 `prof` 只在 v9 之前的迁移里用来反推关号（`legacyLevelFromProf()`），运行时没有任何代码按它算关。
