## 绑定

关联规格覆盖度：`10-规格覆盖.md`。关联本体：`docs/specs/tasks/01-测试.md`、`tests/` 五个文件。提取日期：2026-11-22。

## 1. 正向主场景（大类）

- 一局参悟：选门 → 扣气 → 盘面判定 → 评级 → 熟练度与段位推进 → 结算。
- 熟练度换算：评级到增量、连 S 叠倍率到上限、段位按关数推进。
- 灵力经济：灵石单向兑换、按段耗气、气海上限。
- 存档：存读往返一致、老档补值、上限夹平。
- 页面：首屏只有读数板、按钮层级、返回准备屏。

## 2. 边界场景

熟练度到硬顶（`PROF_MAX`）、连击叠满、气海上限、老档升级、首屏字数上限、段界关数。

## 3. 异常 / 坏路径

灵力不足开局、局中退出作废、读档不发钱、重复领取、非法 id 取法门（取法门当场验 `game`，否则拿错参数照样全绿）、
目标没达成时 `advanced` 不许为真。

## 4. 未覆盖风险点（强制写）

- 真机手感与符号显示：静态断言测不了，只能真机。
- 覆盖度自动比对与保真度校验：场景 ID 表、差集告警脚本均未建。
- 全方法效果未实测；人的三个点头点未产品化。
- 详细清单见 `docs/specs/tasks/01-测试.md` 第三节与本目录的 `12-运行覆盖.md`。

## 5. 覆盖两态

每个场景要分清「跑了」和「验到关键规则」——只断言没抛异常算前者，不算覆盖。
当前五个测试文件 + `verify.js` 全绿（`npm run check`），但「有没有验到 S 的关键规则」逐场景核对尚未机器化。

## 6. 验收通过标准

`npm run check` 四段全绿（静态校验、常驻测试 5 文件、收支曲线、lint）。通过项不逐一人工复核，只看红项。
