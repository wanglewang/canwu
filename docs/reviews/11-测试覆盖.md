## 绑定

## 1. 正向主场景（大类）

- 一局参悟：选门 → 报代价扣气 → 盘面判定 → 评级 → `cleared` 推进一关 → 结算。
- 进度与段位：走通 +1、回关 +0、评级不影响进度、六档门槛 = 段界关、走完 1000 关 = 1000 局。
- 灵力经济：灵石单向兑换、按段耗气、气海上限、参悟只耗不产。
- 存档：v3→v10 迁移、存读往返、读档不发钱、超上限夹平。
- 页面：首屏只有读数板、按钮层级、返回准备屏、教学盘五段摆盘。

## 2. 边界场景

进度到 1000 关硬顶（`cleared = LEVEL_MAX` 后仍照扣气）、走通段界关当场晋段、气海上限夹平、
老档升级、首屏字数上限、教学段界按本段真实规格摆盘。

## 3. 异常 / 坏路径

灵力不足开局、局中退出作废、读档不发钱、重复领取、非法 id 取法门（取法门当场验 `game`，
否则拿错参数照样全绿）、失败与回关 `advanced` 不许为真、解锁条件不满足时按钮禁用。

## 4. 未覆盖风险点（强制写，不许隐瞒）

- **真机手感**：移动端低帧率下的点击判定误差、盘面符号在部分安卓机上的显示；静态断言测不了。
- **R<sub>T</sub> 保真度只做正向**：本卡已有「测试锚点表」，`npm run audit:fidelity` 验 31 个锚点都能在测试文件精确找到，断言被改弱就报红；但反查未做（用例几百条无法逐条挂 ID），漏挂靠 `npm run audit:alerts` 的盲区间接守。R<sub>D</sub>→观测靠挂接表命中（见 `docs/specs/constitution/06-评审方法论.md`「待验」）。
- **参数注入后有没有被玩法读走**：`buildParams` 注入的参数若玩法不读，静态审计照样判过（C4）。
- **全方法效果**：RDD/SDD 这套流程是否真的减少审查量、有没有漏掉真实缺陷，没在全项目实测过。
- **人的三个点头点**：规格认领、盲区接受、差异裁定，目前靠对话确认，没有固化成记录。
- 详细清单见 `docs/specs/tasks/01-测试.md` 第三节、`tasks/05-待修欠账.md` 与本目录的 `12-运行覆盖.md`。

## 5. 覆盖两态

每个场景要分清「跑了」和「验到关键规则」——只断言没抛异常算前者，不算覆盖。
下表「状态」列用方法论 §参数的三态：`未覆盖` / `已覆盖（跑了）` / `已覆盖且验到关键规则`。
判据是**该场景真正要守的那条规则有没有被断言**，不是测试条数。

## 6. 验收通过标准

`npm run check` 四段全绿（静态校验、常驻测试 5 文件、收支曲线、lint）。通过项不逐一人工复核，只看红项。

## 差异标记（和 R<sub>S</sub> 对照）

R<sub>S</sub> 的 31 个 ID 全部在 T 侧找到落点：`SC-RUN-LEAVE-VOID`、`SC-RUN-REWARD-PARTIAL`
各跨两份契约共用 ID；`SC-SKILL-ALL-COUNT`、`SC-DECIDE-ALL-CONSUMERS` 只由 `verify` 静态守，
测试文件未单独挂——算「静态已覆盖、测试未显式挂」，不算盲区。
反向差（T 有 S 无）为 0：本表没有挂 R<sub>S</sub> 里不存在的 ID。

未覆盖风险集中在真机与保真度反查，已如实写在第 4 项。四类差集由
`npm run audit:alerts` 机器产出（跑 `npm run check` 与 `npm run audit:gap` 取真实输出，按
`12-运行覆盖.md` 的挂接表匹配），本轮实测四类告警全 0。熟练度硬顶那个旧 ID
（指向已删的 `PROF_MAX`）已随 v10 退役，不再出现在任何一份 R 里。
