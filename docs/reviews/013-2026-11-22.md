## 变更声明

1. **根因**：Unicode 下标字母只有 a/e/h/i/j/k/l/m/n/o/p/r/s/t/u/v/x，**没有 d**。
   之前 R<sub>S</sub>(U+209B)、R<sub>T</sub>(U+209C) 用的是真下标字符，
   R<sub>D</sub> 却抓了个 U+1D30「MODIFIER LETTER CAPITAL D」——那是**上标**修饰字母，
   渲染时飘在右上角，跟另两个不在一个平面。不是写错别字，是三个记号用了两套字符机制。
2. **修法**：三个统一改成 HTML 下标（R 后面跟一个小写的 sub 元素，分别装 S / T / D），
   三者落在同一个平面，也不再依赖「Unicode 恰好有没有这个字母」。
3. **范围**：方法论真源（09 文档）、规格体系（00/01/09 及覆盖度 10/11/12）、
   整体卡 OVERVIEW、001~012 里的现存轮次卡、项目长期约定 MEMORY——全文替换。
4. **反引号**：两处把记号整段包在行内代码里的地方（004 卡、01 规格总纲）去掉了反引号，
   否则 HTML 标签不会渲染，会露出 `<sub>` 字面量，反而更难看。
5. **克制**：历史工作日志（`.workbuddy/memory/2026-11-*.md`）按项目铁律保留原样不改写；
   `reviews/` 在 SKIP_DIRS 里，本卡与前述改动都不涨静态项数。

**为什么值得单开一轮**：这类「看着对、其实字体/noto 层面就错了」的记号，
靠读句子发现不了——它是你盯着渲染结果看出来的。记在这里，免得以后又用 Unicode 上标凑数。
