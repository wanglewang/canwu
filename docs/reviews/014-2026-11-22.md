## 变更声明

1. **重写 `规格/覆盖度/10-规格覆盖.md`**：保留绑定节与七项维度（09 §2.1 固定提取维度，不多加），
   新增「场景 ID 总表」一节——这是 R<sub>S</sub> 的核心，之前缺的就是它。
2. **ID 表的来源**：六份契约各一条守卫 = 一个场景 ID（对局 6 / 成长 5 / 经济 5 / 存档 4 / 界面 5 / 教学 4），
   加总纲跨契约不变量 2 条（连击上限、`SKILLS.length` 门槛），共 31 行；
   `SC-RUN-LEAVE-VOID`、`SC-RUN-REWARD-PARTIAL` 在对局与存档是同一场景，各出现两次但只算一个 ID，
   去重后 **29 个独立场景**。表中每行标了 S 出处（哪份契约第几条）和 R<sub>T</sub> 是否已挂。
3. **和 R<sub>T</sub> 对齐**：R<sub>T</sub> 试做的 3 个 ID（`SC-PROF-CAP`、`SC-STAGE-BY-CLEAR`、`SC-QI-ONE-WAY`）
   名字原样沿用，没有另起一套——差集比对认字符串，不认措辞。
4. **七项维度挂 ID**：第 3 项「不变量」每条括号里标了对应场景 ID，人看 R<sub>S</sub> 就能追到总表，
   不用在两节之间猜。写的时候自己先写错一个 `SC-QI-GATE`（表里是 `SC-RUN-QI-GATE`），
   反证扫悬空引用抓到并修正——正是这类 ID 漂移会让差集静默漏报。
5. **克制**：只动 R<sub>S</sub> 一份视图；没改 S 七份契约、没改 T/D 本体、没改任何数值与断言。
   R<sub>T</sub>/R<sub>D</sub> 的绑定补齐留到下一轮，本卡不虚报「三份已对齐」。
