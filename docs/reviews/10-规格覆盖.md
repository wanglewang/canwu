## 1. 身份

模块名《参悟》参悟系统；归属微信小程序；用途是十五门功法的一趟参悟——选门、判定、评级、推进、存档。

## 2. 核心意图

让修士每一局的钱花得明白、努力有可见回报，不被回访焦虑驱动；系统承诺的行为写死在规格里，不随实现漂移。

## 3. 不变量（最高优先级）

每条括号里是上表的场景 ID：

- 进度不为负、不越过 1000 关；一局只推一关，回关与失败一律 +0（`SC-ONE-PROGRESS-LINE`、`SC-RETREAT-NO-ADVANCE`、`SC-RUN-ONE-LEVEL`）。
- 段位只由走通关数决定，六档门槛 = 段界关；名字只有段位一套（`SC-STAGE-BY-CLEAR`、`SC-NAME-UNIQUE`）。
- 灵力只许灵石单向兑换，反向不开；参悟不产出；灵力最低 1 点，不许扣成负数（`SC-QI-ONE-WAY`、`SC-PRACTICE-NO-RESOURCE`、`SC-RUN-QI-GATE`）。
- 主动结束与失败是两个结论；「全部 / 集齐」门槛读 `SKILLS.length`；评级线唯一出处 `lines()`；有失败态必须给 `fail`（`SC-RUN-QUIT-VS-FAIL`、`SC-SKILL-ALL-COUNT`、`SC-RANK-LINE-ONE-SOURCE`）。
- 每页同步皮肤；符号一律 CSS 画；用色只认令牌真源（`SC-UI-THEME-SYNC`、`SC-UI-SYMBOL-CSS`、`SC-UI-COLOR-MEANS`）。
- 十五门内核独立；判定改一处要改所有消费端（`SC-SKILL-UNIQUE-CORE`、`SC-DECIDE-ALL-CONSUMERS`）。
- 以上不变量的数值与断言落点见各契约文件末尾的「守卫」。

## 4. 合法输入范围

节拍 / 盘面时刻的有效操作；当前关号（一局一关）；灵力余额充足时才开局；合法功法 id（未知 id 不许静默回落）。

## 5. 输出 / 反馈定义

评级（C/B/A/S + F 失败）、段位推进（走通关数）、耗气数、结算结论；开局前报代价，结算写明扣多少。

## 6. 禁止行为清单

不做签到 / 连续登录 / 体力 / 回访焦虑；不做排行榜与多人；不做内购；不把长规则铺到首屏；
不自动帮玩家判定、不凭空产出资源；AI 不自己定规格又自己验收。

## 7. 外部依赖

本地存档与云端同步；`data/*.js` 数值真源；`scripts/verify.js` 断言；系统主题（跟随 / 白天 / 夜晚）。
